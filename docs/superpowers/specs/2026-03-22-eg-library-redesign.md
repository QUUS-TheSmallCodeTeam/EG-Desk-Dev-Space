# EG-Library Redesign — Git-First Reference Management

## Summary

Reference repo 관리를 Google Drive symlink 기반에서 git-first 구조로 전환. 글로벌 registry (TSV) + 프로젝트별 manifest + git clone 직접 방식. `~/.claude` 전체를 git repo로 관리하여 기기간 sync 해결.

## Problem

기존 구조의 문제:

1. **Drive FileProvider throttle**: cloud-only 파일 접근 시 0.3 KB/s (8KB 파일에 24초)
2. **git + cloud mount = anti-pattern**: git status 76분+, rclone mount도 5분+
3. **symlink 관리 복잡**: Drive → references-local → project/references 3단 indirection
4. **rclone sync 느림**: 새 repo 추가 시 2분 (git clone은 1초)
5. **기기간 sync 어려움**: Drive 의존, 실시간 동기화 없음

## Design

### 1. Global Registry (`~/.claude/reference-registry.tsv`)

모든 프로젝트가 공유하는 마스터 목록. `~/.claude` git repo에 포함되어 기기간 자동 sync.

```tsv
# EG-Library Reference Registry
# Format: url<TAB>name<TAB>type<TAB>tags<TAB>description
# type: git | docs
# Lines starting with # are comments
https://github.com/puppeteer/puppeteer.git	puppeteer	git	browser,automation,cdp	CDP 기반 브라우저 자동화, Chromium 전용
https://github.com/GibsonAI/Memori.git	memori	git	ai,memory	LLM용 장기 메모리 엔진, Python/TS 지원
	light-system	docs	research,cognitive	LIGHT 시스템 논문/자료
```

**컬럼:**
- `url`: git clone URL. non-git 타입은 비어있음
- `name`: 고유 식별자 + 로컬 폴더명 (canonical name, 소문자 kebab-case)
- `type`: `git` (clone 가능), `docs` (수동 관리)
- `tags`: 쉼표 구분 키워드. 검색/필터용. 토픽 그룹핑 역할도 겸함
- `description`: 한 줄 설명. 사람/WM이 읽는 용도

**Canonical Name 규칙:** `name` 컬럼이 로컬 폴더명을 결정. 기존 parent_dir/repo_dir 불일치는 name으로 통일:

| 기존 parent_dir | 기존 repo_dir | 신규 name |
|----------------|--------------|-----------|
| brave | brave-browser | `brave-browser` |
| memori | Memori | `memori` |
| openmetadata | OpenMetadata | `openmetadata` |
| mirofish | MiroFish | `mirofish` |

`git clone URL references/NAME` 시 `--depth 1`과 함께 이 name으로 폴더 생성.

**삭제 정책:** 행 삭제 안 함. 프로젝트에서 안 쓰면 자연스럽게 잊혀짐 (clone 안 하면 디스크 0, 토큰은 TSV 한 줄 ~50자). 나중에 필요하면 URL 바로 사용 가능.

### 2. Reference Notes (`~/.claude/reference-notes/`)

repo별 상세 노트. 프로젝트 관련 메모 + 참고 링크. 중앙에 있으므로 모든 프로젝트에서 공유.

```markdown
# ~/.claude/reference-notes/memori.md

# Memori

## 왜 참조하는가
EG-DESK의 memory 모듈 아키텍처 참고용. 특히 augmentation 패턴.

## 주요 코드
- memori/memory/ — 핵심 메모리 로직
- memori/search/ — 검색 엔진

## 참고 링크
- https://github.com/GibsonAI/Memori
- https://docs.memori.ai/

## 노트
- 2026-03-22: Python/TS 둘 다 지원, TS 버전은 아직 초기
```

기존 `online_references.md`의 역할을 흡수하며, 프로젝트별 context도 기록.

**마이그레이션 시 주의:** 기존 `online_references.md`를 옮길 때 프로젝트 특화 내용과 일반 참조 정보를 구분하여 review. 일반 정보만 `reference-notes/`로, 프로젝트 특화 내용은 해당 프로젝트 docs에 유지.

### 3. Per-Project Manifest (`references/manifest.tsv`)

`setup.sh` 실행 시 자동 생성. 이 프로젝트가 사용하는 reference만 + 메타데이터 + 상태.

```tsv
# Auto-generated by setup.sh — do not edit manually
# Source: ~/.claude/reference-registry.tsv
# Format: name<TAB>type<TAB>tags<TAB>description<TAB>status<TAB>has_note
puppeteer	git	browser,automation,cdp	CDP 기반 브라우저 자동화	cloned	no
memori	git	ai,memory	LLM용 장기 메모리 엔진	cloned	yes
light-system	docs	research,cognitive	LIGHT 시스템 논문/자료	present	yes
xyflow	git	canvas,react	노드 기반 UI 프레임워크	not-cloned	no
```

**컬럼:**
- `name`, `type`, `tags`, `description`: registry에서 추출
- `status`: `cloned` (git clone 완료), `present` (non-git 자료 존재), `not-cloned` (아직 안 받음)
- `has_note`: `yes`/`no` — `~/.claude/reference-notes/{name}.md` 존재 여부. WM/LLM이 필요할 때만 note 로드 (lazy loading)

**특성:**
- `.gitignore`에 추가 (자동 생성물)
- URL은 생략 (registry에 있으므로 중복 불필요)
- WM/LLM은 이 파일만 읽으면 프로젝트의 reference 전체 파악 가능

### 4. setup.sh 동작

```bash
./setup.sh                  # clone/pull + manifest 생성
./setup.sh --update         # 전체 git pull
./setup.sh --check          # 상태 확인만
./setup.sh --add <name> <url> --tags <tags> --desc <desc>   # ref 추가
./setup.sh --edit <name> --tags <tags> --desc <desc>        # ref 메타 수정 (글로벌)
./setup.sh --remove <name>  # 이 프로젝트에서 제거 (registry는 유지)
```

**`--edit`는 글로벌:** registry.tsv를 수정하므로 모든 기기/프로젝트에 영향. 의도적 설계 — registry는 단일 진실 원천 (single source of truth). 프로젝트별 로컬 override는 지원하지 않음.

**프로젝트별 ref 목록** — 별도 파일 (`references/project-refs.txt`):
```
# 이 프로젝트가 사용하는 references (한 줄에 하나)
puppeteer
playwright
memori
theia
light-system
```

`setup.sh`가 이 파일을 읽어서 처리. `--add`/`--remove` 시 이 파일만 수정 (setup.sh 자체를 수정하지 않음).

**기본 실행 흐름:**
```
1. cd ~/.claude && git pull (최신 registry 가져오기)
2. project-refs.txt 읽기
3. 각 ref 순회:
   a. type=git:
      - 폴더 없음 → git clone --depth 1 URL references/NAME
      - 폴더 있음 → git pull
   b. type=docs:
      - 폴더 없음 → mkdir + 안내 메시지
      - 폴더 있음 → skip
4. manifest.tsv 자동 생성
5. 고아 폴더 경고:
   "references/old-ref/ 는 project-refs.txt에 없습니다.
    제거: ./setup.sh --remove old-ref
    유지: project-refs.txt에 old-ref 추가"
```

**--add 흐름:**
```
1. git clone --depth 1 URL references/NAME
2. project-refs.txt에 NAME 추가
3. ~/.claude/reference-registry.tsv에 행 추가 (upsert)
4. cd ~/.claude && git pull --rebase && git add reference-registry.tsv && git commit && git push
   (push 실패 시 재시도 1회. 여전히 실패 시 경고 출력 + 로컬은 정상 유지)
5. manifest.tsv 재생성
```

**--remove 흐름:**
```
1. project-refs.txt에서 NAME 제거
2. references/NAME/ 폴더 삭제 확인
3. manifest.tsv 재생성
4. registry.tsv는 변경 없음 (행 유지)
```

### 5. Sync Protocol

`~/.claude` 전체가 git repo (`eg-desk-dev-claude-code`).

**기기간 sync = git push/pull:**
```bash
# setup.sh가 자동으로:
cd ~/.claude && git pull --rebase   # 실행 시작 시
cd ~/.claude && git push            # --add/--edit 후
```

**push 충돌 처리:** `git pull --rebase` 후 push. TSV는 한 줄 = 한 repo이므로 다른 행 추가는 자동 merge. 같은 행 수정 충돌 시 push 실패 → 경고 출력 + 사용자에게 수동 해결 안내.

**새 기기 셋업:**
```bash
git clone https://github.com/QUUS-TheSmallCodeTeam/eg-desk-dev-claude-code.git ~/.claude
# → 전체 설정 복원: agents, hooks, skills, registry, notes, settings
```

**sync 대상:**
- `reference-registry.tsv`, `reference-notes/`
- `CLAUDE.md`, `wm-protocol.md`
- `agents/`, `hooks/`, `skills/`, `commands/`, `docs/`
- `settings.json`

**sync 제외 (.gitignore):**
- `history.jsonl`, `sessions/`, `debug/`, `file-history/`
- `plugins/`, `projects/`, `cache/`, `chrome/`
- `settings.local.json`, `plans/`, `backups/`
- `__pycache__/`, `.DS_Store`

### 6. 폴더 구조 (최종)

```
# 중앙 (user level, git repo)
~/.claude/
├── .git/                        # → github.com/QUUS-TheSmallCodeTeam/eg-desk-dev-claude-code
├── .gitignore
├── CLAUDE.md
├── reference-registry.tsv       # 마스터 목록
├── reference-notes/             # repo별 상세 노트
│   ├── memori.md
│   └── ...
├── wm-protocol.md
├── agents/
├── hooks/
├── skills/
├── settings.json
└── ...

# 프로젝트 (project level)
EG-Desk-Dev-Space/
├── setup.sh                     # clone/pull 로직
└── references/
    ├── project-refs.txt         # 이 프로젝트가 사용하는 ref 목록
    ├── manifest.tsv             # 자동 생성 (.gitignore)
    ├── puppeteer/               # git clone --depth 1
    ├── memori/
    ├── light-system/            # docs (수동 관리)
    └── ...                      # 플랫, 서브폴더 없음
```

### 7. 삭제 대상

이 설계로 불필요해지는 것:
- `~/.claude/references-local/` — rclone용 공유 캐시
- `~/.claude/setup-references.sh` — user-level clone 스크립트
- 프로젝트 `references/` 내 symlink 전체 (이미 제거됨)
- 프로젝트 `references/` 내 `online_references.md` → `reference-notes/`로 마이그레이션 후 제거
- `setup.bat` — Windows 스크립트. 현재 구조에 맞게 재작성 필요 (별도 task)

### 8. 마이그레이션

**원칙:** registry.tsv 포맷 변경과 setup.sh 재작성은 동시에 commit/push. 다른 기기에서 pull했을 때 구 setup.sh + 신 registry 조합이 발생하지 않도록 atomic migration.

**단계:**

1. `~/.claude` git repo 초기화 + push (완료)
2. 기존 `online_references.md` review → 일반 정보는 `~/.claude/reference-notes/`로 이동, 프로젝트 특화 내용은 프로젝트 docs에 유지
3. `reference-registry.tsv` 포맷 변경:
   - 기존: `url | parent_dir | repo_dir | name`
   - 신규: `url | name | type | tags | description`
   - Canonical name 매핑 적용 (Section 1 테이블 참조)
4. `references/project-refs.txt` 생성 (기존 setup.sh의 PROJECT_REFS 배열에서 추출)
5. `setup.sh` 재작성 (symlink → git clone, manifest 생성, project-refs.txt 읽기)
6. **Step 3 + 4 + 5를 동시 commit** (atomic migration)
7. 기존 symlink 제거 (완료)
8. 프로젝트 `.gitignore` 업데이트:
   - 추가: `references/manifest.tsv`, `references/*/` (clone된 repo 전체)
   - 제거: 기존 `references/parent/repo/` 패턴
9. `~/.claude/references-local/`, `~/.claude/setup-references.sh` 삭제
10. `setup.bat` 재작성 (별도 task)

## What Changes

| 항목 | 기존 | 신규 |
|------|------|------|
| 저장소 | Google Drive + symlink | git clone 직접 |
| 업데이트 | rclone/Drive sync | git pull |
| 새 repo 추가 | rclone (2분) | git clone (1초) |
| 기기간 sync | Drive 의존 | ~/.claude git push/pull |
| 메타데이터 | 없음 | registry (tags, desc) + notes |
| 삭제 | 복잡 (전파 문제) | 프로젝트에서만 제거, registry 유지 |
| manifest | 없음 | 자동 생성 (status + has_note) |
| 폴더 구조 | 2단 (parent_dir/repo_dir) + symlink | 플랫 (references/name/) |
| ref 목록 | setup.sh 내 배열 | project-refs.txt (별도 파일) |

## What Stays

- `setup.sh` 엔트리포인트 (동작 변경, 파일 유지)
- `references/` 디렉토리 (내용 변경, 위치 유지)
- `reference-registry.tsv` 파일명 (컬럼 변경)
