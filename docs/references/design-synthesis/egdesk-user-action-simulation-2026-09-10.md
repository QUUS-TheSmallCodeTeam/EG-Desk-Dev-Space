## 이번 범위

이전 P0·FP-02–09의 중단점·불편을 보완하고, 기존 8개 여정에 배정된 43개 trace의 연결을 점검했다. 아래는 이번 대화에 반환된 역할 결과를 요약한 중간 기록이다. 43개 trace의 모든 분기 완주를 뜻하지 않는다. 배정, 문서 대조, 독립 사용자 행동 교환, 제품 Agent의 도구 선택, 수정 후 재확인을 따로 센다.

사용자 역할은 현재 화면·자신의 목적만 보고 한 동작을 고른다. 제품 Agent 역할은 실제 전달한 요청·자료 참조·허용 도구만 받고 읽기·작업·보고를 선택한다. System 모형은 명시된 자원·권한·상태와 사건 순서로 응답한다. 다음 화면이나 답을 미리 주지 않는다. 문서 밖의 보통 입력 위젯 동작과 시험용 정상·오류 응답은 회차 조건으로 분리한다.

화면 치수·배치도는 가상 화면의 조건이다. 폭이 좁아져도 Canvas와 다른 View를 없애서 문제를 숨기지 않는다. 과거 기록의 불편을 보존하며 사용자 제안인 Chat 클릭 활성·해제 방식을 새 독립 발견으로 세지 않는다.

## 범위와 남은 일

이 절은 사용자 요청에 따라 추가 설계·시뮬레이션을 중단했던 이전 체크포인트의 범위다. 재개 후의 한정 검사는 [TRI-02 후속](#tri02-20260912)에 따로 기록하며 아래 전체 미완료 항목을 닫지 않는다. 제품 정책 16개는 기존 사용자 확인 원장에서만 관리하며 이번 작업으로 승인하지 않았다.

- 후속 전체 교환의 전사와 trace별 실제 도달·조건부 분기 커버리지 대조가 남았다.
- 마지막 수정본의 독립 최종 재검토와 검토 지문 갱신이 남았다. Q-VIEW-04/08의 `SPECIFIED`를 임의로 닫지 않았다.
- 프로그램 실행, 실제 렌더링·사용성·접근성·외부 서비스 동작 검증은 이 작업에서 수행하지 않았다.
- 사용자 결정만 남았다거나 시뮬레이션상 완벽해졌다는 완료 판정은 하지 않는다.

## 2026-09-12 후속 — TRI-02

**상태: 한정 정상 경로·별도 표시 복구·문구 비교 종료. 문구 개선 반영, 배치 변경 보류.** [TRI-01](egdesk-user-action-rehearsal-log.md#three-perspective-rehearsal)에서 남겨 둔 새 사용자 역할의 근거 발견과 원본 변경 조건을 이어 점검했다. S1–S8의 이전 집계나 전체 43개 trace 완주로 합산하지 않는다.

기준 소스는 `6da8f12`, 채택한 UX 문구의 반영 커밋은 `f777e67`이다. 직전 푸시에는 UX 문서만 포함되고 이 회차의 정식 기록이 빠져, 사용자 지적 뒤 대화의 실제 역할 반환과 로컬 재개 메모를 대조해 보완했다. 아래는 그 교환을 요약·전사한 기록이며 누락된 교환을 새로 실행하거나 없는 결과를 복원하지 않았다. Git에서 제외되는 임시 메모 없이도 범위·조건·선택·결과를 확인할 수 있도록 이 절에 남긴다.

### 근거와 역할 경계

- Main은 [현재 운영 절차](../../codex/egdesk-product-documentation-governance.md#doc-sim-improvement-loop), [원문과 전달 자료의 보존](../../../ideas/confirmed/EGDESK_INTERACTION_AND_ORCHESTRATION_CONTRACT.md#tech-observation-fidelity), [Answer·표현 계약](../../../ideas/confirmed/EGDESK_INTERACTION_AND_ORCHESTRATION_CONTRACT.md#impl-answer-revisions)을 읽고 System 모형의 상태·참조·권한·표시를 처리했다.

- 사용자 역할 `/root/sim_user_tri02`는 새 맥락에서 자신의 목적과 현재 보이는 화면만 받았다. 설계 문서·알려진 불편·예상 정답·예정된 원본 변경은 주지 않았다.
- 제품 Rio 역할 `/root/sim_product_rio_tri02`는 별도 새 맥락에서 전송된 요청·A/r1 첨부 참조·허용 도구만 받았다. B의 목적·본문과 현재 A/r2 변경은 전달하지 않았고, A 본문은 읽기 요청 뒤에만 전달했다.
- `read_attachment`, `publish_answer`, `clarify`는 문서 실험용 relay다. Main이 제품 Agent의 도구 선택·답변을 대신 쓰지 않았으며, 이 이름을 실제 제품 API로 확정하지 않았다.

> - 2월: 130만 원 — 전월보다 30만 원 증가(+30%)
> - 3월: 90만 원 — 전월보다 40만 원 감소(약 -30.8%)
>
> 매출이 가장 높은 달은 2월, 가장 낮은 달은 3월입니다.

Canvas 제목은 `매출표 A · 1~3월 매출 요약`이다. 아래 문장은 Rio가 작성했고, 근거 필드는 모두 전달받은 `obs-tri02-a-1`을 참조했다. 내부 관찰 ID는 사람용 문장에 노출하지 않았다.

| 1~3월 총매출은 320만 원(100+130+90), 월평균은 약 106.7만 원(320÷3)입니다. | 1–4행 |

사용자는 근거를 연 뒤 `요약이 전달 당시 파일을 기준으로 했다는 점은 이해했습니다`라고 반환했고, 마지막에는 `현재 r2는 3월이 120만 원이므로 이 요약은 최신 파일 기준이 아닙니다`라고 구별했다. 이미 두 자료를 동시에 관찰했으므로 `[현재 조작면]`·`[비교]` 버튼 클릭을 사후 필수조건으로 추가하지 않았다. 두 버튼 자체는 미검사다.

**확인 범위:** 사용자 입력 1회·클릭 4회·스크롤 2회·대기 1회, 완료 선언 별도. 제품 요청 접수 1회, Rio의 읽기 1회·게시 1회. 탐색으로 새 제품 요청을 만들지 않았다. Main은 5항목의 참조 범위와 Snapshot/전달 본문의 동일 hash를 검사하고, 산술도 별도로 대조했다. 이는 모형의 상태·참조 검사이며 실제 제품 저장소·렌더러의 인수시험 PASS가 아니다.

### 정상 목표 뒤 별도로 주입한 표시 복구

사용자의 정상 `done` 뒤 Canvas 보고 표현만 실패시키는 별도 조건을 시작했다. Chat 답변·현재 A/r2·B·r1 Snapshot은 유지하고 `[다시 표시] [읽기 쉬운 원문]`을 보여 줬다.

1. 사용자는 `[다시 표시]`를 스스로 선택했다.
2. Main은 미리 정한 정상 재표시 응답으로 같은 저장 Answer revision을 복구했다. 보고 스크롤 위치도 유지했다.
3. 사용자는 `[Chat 답변으로]`를 선택하고 별도 복구 목적의 `done`을 반환했다.

모형의 복구 전후 Answer, observation 본문·hash, 현재 A revision, B 상태, 빈 초안, 제품 요청 접수 수를 필드별로 대조해 모두 유지됨을 확인했다. **추가 제품 분석 요청은 0회**다. 이것은 역할 시뮬 자체가 사용한 실제 모델 추론 횟수 0을 뜻하지 않는다. 실제 오류·네트워크 복구를 실행한 것이 아니며, 재표시 성공을 외생 조건으로 정해 둔 검사다. 원문 보기·연속 재시도 실패는 검사하지 않았다.

### 사후 회고와 상태 문구의 P/Q 비교

정상·복구 목표가 끝난 뒤 비유도형 회고를 받았다. 다음 불편은 **사후 회고**이며 최초 행동 때의 자발적 flag로 소급하지 않는다.

- `검사 대상 변경됨`만으로는 현재 파일과 요약의 숫자가 왜 다른지 이해하기 어려웠고, 근거를 열어 r1 기준임을 확인했다.
- 요약의 나머지 항목을 읽으려 내부 스크롤을 두 번 해야 했다.
- 답변을 기다리며 B를 확인할 수 있고, 답변 도착에도 화면이 유지된 점, 근거와 Chat 복귀가 쉬운 점, 한 번의 재표시로 읽던 위치가 복구된 점은 편했다고 반환했다.

첫 불편에는 같은 자료·목적·1280×800 배치·보이는 컨트롤을 유지하고 상태 문구만 바꾼 두 새 사용자 맥락을 비교했다. P는 `/root/sim_copy_p`, Q의 유효 반환은 `/root/sim_copy_q_continue`다. 중단되어 반환을 받지 못한 첫 Q 실행은 성공·실패나 표본 수로 세지 않았다.

| 화면의 상태 문구 | 새 사용자 역할의 첫 해석·선택 | 후속 확인 |
|---|---|---|
| P: `검사 대상 변경됨` | r1/r2의 숫자 차이는 알지만 상태 문구의 뜻은 아직 모르겠다고 반환. r1 출처 선택 | 이 좁은 P 비교에서는 첫 해석·선택까지만 반환받음 |
| Q: `원본 변경됨 · 답변은 당시 자료 기준` | 요약이 당시 r1 기준이고 현재 r2와 다름을 이해. r1 원문 값은 아직 미확인이라고 구분하고 같은 출처 선택 | r1 네 행을 확인한 뒤 Chat 복귀를 스스로 선택. 목적 달성·이번 확인에서 남은 불편 없음 반환 |

두 역할 모두 출처를 확인하려 했다. 이 비교는 상태 설명이 명확해졌다는 문서 모형 근거이며, 클릭 감소·실제 사람의 선호율·출처 검증 생략·시각 품질 개선을 입증하지 않는다. Q에서도 출처 조회를 정답 문구로 대신하지 않았다.

### 스크롤 후보 비교와 보류 이유

`/root/sim_report_layout_options`는 모든 5항목의 원문·수치·계산식·근거와 다른 열린 View를 유지하는 두 배치 후보를 제안했다. 두 후보는 설계 비교이며 실제 렌더링이나 새 사용자 행동 재리허설을 수행하지 않았다.

| 후보 | 치수·행동 변화 | 새 부담·미확인 |
|---|---|---|
| 같은 rect에서 본문 예산 조정 | header 40 + 상태 32 + 본문 280 + 바닥 16 = 368px. 본문 +24px, 새 행동 없음. 글자·행간·근거 컨트롤 크기는 유지 | 항목 구분 여유 감소. 기존 40px에 필수 컨트롤이 있는지 확인해야 하며 스크롤 감소는 미측정 |
| 사용자가 여는 임시 검토 배치 | report `(408,364,520,368)`, Snapshot `(944,364,320,368)`. 가로 520+16+320=856px, 오른쪽 끝 1264·아래 끝 732. Chat/A/B는 그대로 | 진입·복귀 각 1행동 추가. 근거 폭이 120px 줄어 줄바꿈·가로 스크롤 부담 가능. 새 진입 컨트롤과 복귀는 후보 가정 |

**Main 처리: 두 배치 모두 채택 보류.** 처음의 report 400×368과 바닥 40px는 이 회차가 만든 조건이지 제품의 확정 치수가 아니다. 이를 바꾼 모형만으로 제품의 스크롤 문제가 해결됐다고 할 수 없고, 실제 줄바꿈·항목 경계·근거 폭 손실을 확인하지 않았다. 두 번의 스크롤은 관찰된 비용으로 남긴다. 문구 변경으로 이 비용도 해결됐다고 기록하지 않는다.

### 반영과 독립 검토, 남은 범위

채택한 상태 설명은 [답변 수정본 상세](egdesk-ux-realization-proposals.md#ux-detail-answer-revisions)에 `f777e67`로 반영했다. 변경된 자료명과 답변의 근거 시점을 함께 설명하며, 일부 자료 변경을 전체 근거 변경처럼 보이게 하지 않도록 표시 범위도 명시했다. 다중 자료의 국소 표시는 기존 참조 계약을 바탕으로 구체화한 규칙이며 이번 단일 A 자료의 P/Q 결과만으로 다중 자료 UI까지 검증했다고 하지 않는다.

독립 검토는 다음 범위에 한정했다.

- 정상 경로 검토는 처음에 이미 보이는 r2 정보를 놓쳐 미완료로 판정했으나, 실제 화면 전달과 사용자 반환을 대조한 뒤 **이 정상 경로의 문서 모형 목표 충족**으로 정정했다. 새 버튼 클릭을 숨은 완료 조건으로 붙이지 않았다.
- `/root/wm_tri02_continue`는 실제 UX diff와 Contract 1531–1537을 대조해 새 상태·권한·실행 의미의 모순을 발견하지 못했다. 버전 차이, Agent의 의미 영향 판단, 자동 갱신·새 분석을 구별하는 경계가 유지됨을 확인했다. 이 리뷰는 전체 UX·Atlas의 최종 재검토가 아니다.

이번에 보완한 정식 기록 자체의 별도 독립 재검토는 사용량 제한으로 반환을 받지 못했다. Main이 대화의 실제 반환과 기록을 대조하고 링크·자료 hash·변경 범위를 확인했으며, 이를 독립 검토 완료로 세지 않는다.

미실행 범위는 Windows/Firefox 실제 화면·글꼴·접근성·제품 API, `[현재 조작면]`/`[비교]` 자체 클릭, 늦은 조회 응답의 별도 경합, 비어 있지 않은 초안 보존, 원문 보기·연속 복구 실패, 권한 철회·삭제·보존 정책, 원본 변경의 의미 영향을 새로 분석하는 작업이다. [HUM-ANSWER-001](../../codex/egdesk-product-interaction-trace-atlas-editorial-ledger.md#hum-answer-001)과 [HUM-SNAPSHOT-001](../../codex/egdesk-product-interaction-trace-atlas-editorial-ledger.md#hum-snapshot-001)의 미결 선택을 승인하지 않았다. 앞선 전체 전사·43개 trace 분기 대조·전체 최종 재검토도 계속 남아 있다.
