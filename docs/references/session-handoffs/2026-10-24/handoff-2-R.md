화면 연결 작업자(S8·S9)에게:
- 허락 카드: SSE approval.required details { approvalId, kind:'computerElicitation', status, choices:['accept','decline'], scope:'request', serverName, appName, message, fields:[{type:'boolean', title, description, value, required} | {type:'enum', title, description, options:[{label}], choice(미리 고른 index 또는 null), required}], reason, expiresAt }. 답은 POST /chat/approval { approvalId, conversationId, runId, decision:'accept'|'decline', answers?:[{index, value:boolean}|{index, choice}] }. 필수 선택이 비어 있으면 400 INVALID_ELICITATION_ANSWER. 시간이 지나면 approval.resolved { approvalId, outcome:'expired' }.
- 활동 행 kind 'computerControl'(status declined/completed, detail에는 code/reason/tool만). SSE computer.yielded { runId, reason:'personUsing'|'personTookOver'|'stopped', bestEffort:true, at }.
- Board: POST /chat/board/send { clientThreadId(방), message, requestId?, members?(chat-store v3 멤버), leadProfileId?|profileId?, recentMessages?[{author, role:'user'|'agent', text}]≤12, cwd/model/effort… } → 202 { accepted, requestId, clientThreadId, recipients:[{profileId, memberKey, label, reason:'mentioned'|'lead', clientThreadId, status:'started'|'deferred'|'failed', requestId, conversationId, runId, code}] }. 답 귀속은 run.board { roomClientThreadId, memberKey, profileId, label, reason }이고 run.started details.board와 send 결과에도 있습니다. 멘션 토큰은 [@이름](agent://profileId) 또는 @이름. 'board-member:' 대화는 방 화면에서 합쳐 보여 주고 기록 목록에서는 숨겨야 합니다. 방 기록의 event 'board.routed'가 어디서 답하는지 알려 줍니다.
- 다시 맡기기: POST /chat/subagent/reassign { conversationId, runId, threadId } → 202(새 회차 send 결과 + handedBack). 부모가 진행 중이면 409 RUN_IN_PROGRESS + stopRequired:true이므로 '중지 후 다시 맡기기' 흐름이 필요합니다. SSE subagent.handedBack { threadId, requestId, runId }. 버튼은 행의 blocked.reason이 'approvalRequested'일 때만 보입니다.
- 메시지 보내기: POST /chat/share { fromClientThreadId, toClientThreadId, localMessageIds(1~20, 순서대로), shareId? } → 200 { shareId, messageCount, attach:'nextTurn' }. 양쪽 기록 event 'messages.shared.in'(details.link.clientThreadId = 원래 대화, messages 복사본)과 'messages.shared.out'(details.link = 받는 대화)을 '가져옴/보냄' 줄로 그리면 됩니다. 붙은 회차에는 SSE messages.shared.attached { shareIds, requestId }.
Main 개발자 / bridge 연결(2-E·2-CH)에게:
- new CodexChatRuntime({ hostLease, setTimer?, clearTimer? }), toolProviders에 { providerId:'egdesk-computer', specs(): egdesk_computer_<snake method> 함수 도구, dispatch(run, event) } 추가, 입력권 onEvent → chat.noteHostControl(event).
- provider는 adapter 결과(거절 포함)를 success:true로 돌려줘야 Agent가 안내 문장을 읽습니다. 런타임의 respond 래퍼가 success:false 본문을 일반 오류로 바꾸기 때문입니다.
- 컴퓨터 도구는 새 대화부터만 보입니다(dynamicTools는 resume으로 바꿀 수 없음).
