계약(화면 연결 작업자 / Main):
A. Desk HTTP(egdesk-desk-http.mjs, 브리지 마운트는 그대로):
 - GET /v1/boards/_search?q=<1~200자, 8낱말 이하>&limit=<1~100, 기본 20> → 200 {query, index:'fts5-trigram'|'plain', boards:[{boardId,title,headRevision,metadataVersion,lifecycle,createdAt,updatedAt, fields:['title'|'cards'|'notes'], snippet:string|null}]}; 400 INVALID_BOARD_QUERY / DESK_HTTP_INPUT. '_search'는 Board ID가 될 수 없어 /v1/boards/search Board와 겹치지 않는다.
 - POST /v1/boards/:id/merge {body, baseRevision, prefer?:'mine'|'theirs'} → 200 {boardId, baseRevision, headRevision, body, hash, conflicts:[{kind:card|shape|memo|field, id?, path?, reason:both-changed|both-added|mine-deleted|theirs-deleted, kept, mine, theirs}], clean, unchanged}. 쓰기는 없다. 화면 흐름: PUT Board가 409 BOARD_REVISION_CONFLICT → 이 창이 알던 revision을 baseRevision으로 merge 호출 → clean이면 PUT {body, expectedRevision: headRevision}, 아니면 충돌 선택 화면. 지금 EGDeskRecoveryState.sys.mjs:411 putBoard의 '내 것을 새 버전으로'를 이것으로 바꾸면 된다.
 - PUT /v1/desk/current 응답에 merged:boolean, replacedGeneration:number|null이 추가됐다. generation은 늘 새 머리이고 화면은 이미 그 값을 쓴다. 병합으로 사라진 세대를 GET하거나 복원하면 404 DESK_GENERATION_NOT_FOUND이다(가지치기된 경우와 같음).
B. chat-store v3(chat HTTP 소유자 1-R/2-R이 라우트 연결): setRoomAgent({clientThreadId, profileId|null, revision?, ts?}) → {clientThreadId, agent}. getConversation·listConversations·getConversationByNative의 thread.agent = {profileId, revision, setAt}|null. listRoomMembers(id) / setRoomMembers({clientThreadId, members, ts?}) / addRoomMember({clientThreadId, member, ts?}) → {clientThreadId, members[, added]} / removeRoomMember({clientThreadId, memberKey}) → {…, removed}. 오류: INVALID_CHAT_RECORD, ROOM_MEMBER_LIMIT(409, 64명), CONVERSATION_NOT_FOUND(404). 화면 옛 데이터 이전: roomMembersFromLegacy({participants, participantRoles, selfName:'나', resolveProfileId:name→profileId|null}) → setRoomMembers. 이름을 객체 키로 쓰는 participantRoles는 이 함수에서만 읽고 저장하지 않는다. 라우트 제안: PUT /chat/rooms/:id/agent, GET·PUT /chat/rooms/:id/members, POST /chat/rooms/:id/members, DELETE /chat/rooms/:id/members/:memberKey.
C. JSON Canvas(portable-service 1-P): 내보내기 boardToJsonCanvas(body, {title, includeAttachments:false(D-R3), includeEgdesk:true, frame:true}) → {canvas, report:{nodes, edges, omitted}} → JSON.stringify(canvas)를 '<제목>.canvas'로 저장. 가져오기 jsonCanvasToBoard(parsed, {agendaId: 새 boardId, title?, now}) → {body, title, report:{cards, shapes, dropped, truncated, approximated}} → desk.importPortable({boards:[{boardId, title, body}]}) 또는 saveBoard(boardId, {body, expectedRevision:null, title}). 4MB 초과는 store가 BOARD_BODY_TOO_LARGE로 거절한다. report 항목을 사용자 안내에 쓴다. 코드 오류: INVALID_JSON_CANVAS, JSON_CANVAS_TOO_LARGE, INVALID_BOARD_ID, INVALID_BOARD_BODY(모두 400).
