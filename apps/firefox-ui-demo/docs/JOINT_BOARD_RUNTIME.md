# 사람과 공용 Board 사용하기

**현재 코드:** Firefox용 EG-Desk 안의 Board 목록, Board 영역, 독립 Window shell과 연결된 텍스트 카드 협업. HTML 시안이나 로컬 Agent 방 초대가 아니다. 참가자마다 Firefox, 카메라, 창 위치, 로그인은 따로다. 서버가 받은 사람별로 보낼 보드와 카드를 다시 만든다.

## 처음부터 다시 들어오기까지

1. **Desk → Board 목록 → 사람과 공유**에서 협업 서비스 주소와 운영자가 별도로 준 개인 계정 키를 넣는다. Firefox 창의 메모리에만 둔다. 사이트 쿠키, SSO나 Agent 로그인은 필요하지 않다. **공용 Board 함께 만들기**에서 이름과 상대의 계정 ID를 입력한다. 개인 Board 메뉴의 **공용 Board 제안…**은 새 Board 제안이며, 원본이나 배치를 옮기는 기능이 아니다.
2. 상대가 **받은 초대 → 수락하고 열기**를 누르면 두 개설자가 같은 Board 하나에 참여한다. 둘 중 한 명이 제안만 하면 보드는 아직 없다. 이후에는 왼쪽 Board 목록에서 같은 보드를 연다. 지역에 붙은 Board 이름과 카드별 제목은 독립적이다.
3. **Board 작업 → 카드·사람 관리 → 카드 추가**에서 전표·메모·텍스트 발췌를 여러 장 추가한다. 개인 메모 본문을 선택해 가져올 수도 있다. **추가 시 제목·본문이 협업 서버에 업로드된다.** 다른 참가자에게는 자동으로 공개되지 않는다. 원본 파일·브라우저·실행 권한은 복사되지 않는다.
4. 카드의 **공개·회신 관리 → 공개할 사람 선택 → 보내기 전 확인**에서 수신자와 내용을 확인한다. 이미 참가한 사람에게 보드 안에서 공개하거나, 보드 밖의 사람에게 카드 한 장만 제안한다. 단독 초대를 수락하기 전에는 초대 표제·보낸 사람·기한만, 수락한 뒤에는 지정된 카드만 보인다. 부모 보드 이름·ID·배치·인원·이웃 카드는 단독 응답에 없다. 원문이 바뀌면 미수락 초대는 다시 보내야 한다.
5. 수신자는 **이 일 맡기 → 회신 쪽지 열기**에서 따로 작성한다. 초안이나 **회신 내용 확인**은 전송이 아니다. **이 사람에게 회신**을 눌러야 원 제공자가 결과를 본다. 보드 전체·Agent 방에는 게시하지 않는다. 초안은 메모리 전용이며 연결을 잃으면 버릴 수 있다. 개인 수첩은 기존 메모 창을 쓴다.
6. 카드를 끌면 내 위치가 바뀐다. 원 제공자가 **현재 위치를 공용 배치로 제안… → 확인하고 적용**을 눌러야 서버에 그 카드의 위치가 반영된다. 기존 개인 배치는 덮지 않는다. 좌표 변경이 원문 버전이나 이미 보낸 회신을 무효화하지 않는다. 화면을 닫아도 탈퇴하지 않는다. 다시 인증해 왼쪽 목록에서 열면 **현재 접근 가능한** 자료만 받는다.
7. **공개 회수**는 서버가 즉시 집행한다. 연결된 수신 창은 권한 응답을 다시 받으면 열린 카드·회신 편집기·행을 내린다. 클라이언트는 약 3초마다 확인하며, 네트워크 요청은 7초 후 타임아웃한다. 단절/오류 확인 시 공유 화면을 닫고 재검사한다. 오프라인 화면을 원격에서 즉시 지웠다고 하지는 않는다. 검색 재조회와 재시작이 접근권을 되살리지 않는다. 이미 본 내용·복사본·명시적으로 보낸 답은 지워졌다고 표시하지 않는다.

## 운영자 실행

필수: Node에서 `node:sqlite`를 사용할 수 있어야 한다(검증: Node 26.5). 아래 명령은 이 체크아웃의 `apps/firefox-ui-demo` 디렉터리 기준이다. 실제 서비스를 대신 개설하거나 계정을 발행한 것이 아니다.

```sh
DATA="$HOME/.egdesk-joint-demo"
(umask 077 && mkdir -p "$DATA")
node helper/egdesk-joint-board-server.mjs issue "$DATA" seoyun '서윤' "$DATA/seoyun.new-key"
node helper/egdesk-joint-board-server.mjs issue "$DATA" minjae '민재' "$DATA/minjae.new-key"
node helper/egdesk-joint-board-server.mjs serve "$DATA" 47631
```

기본 주소는 `http://127.0.0.1:47631`이며 **다른 PC는 이 주소로 연결할 수 없다**. 발급 명령은 키를 터미널에 출력하지 않고 새 0600 파일에 기록한다. 키 파일은 안전한 별도 경로로 해당 사람에게만 전달하고 관리한다. 재발급은 `rotate`와 새로운 출력 파일을 쓴다. DB에는 키 해시와 업무 자료가 저장된다. 업무 자료는 DB 안에서 암호화되지 않으므로 데이터 폴더·디스크·백업은 운영자의 보호 대상이다.

서로 다른 기기에서 쓸 때는 운영자가 DNS, 도달 가능한 네트워크, 참가자 Firefox가 신뢰하는 인증서/키를 준비한 뒤 TLS 모드를 명시한다. 예시는 `board.example.org`를 실제 주소로 바꿔야 한다. 참가자에게 HTTP 평문 주소나 인증서 경고 무시를 안내하지 않는다.

```sh
node helper/egdesk-joint-board-server.mjs serve-tls "$DATA" \
  'https://board.example.org:8443' '0.0.0.0' '/absolute/fullchain.pem' '/absolute/key.pem'
```

발급/회전은 로컬 CLI만 가능하다. HTTP에는 `GET /v1/joint/view`, `POST /v1/joint/action`이 있고, 로컬(127.0.0.1) 서비스에는 일시 접속 신호용 `POST /v1/joint/presence`가 하나 더 있다. 이 경로는 원장을 쓰지 않고 DB에 아무것도 남기지 않는다(프로세스 메모리, 10초 뒤 비활성·30초 뒤 삭제). 각 참가자가 Board별로 켠 경우에만 내용 없는 값(활성 여부, 입력 후 경과 시간 5초 단위, 보는 영역 사각형, 포커스 카드 ID)을 같은 Board의 현재 참가자에게만 보낸다. 기본값은 꺼짐이다. TLS 서비스에는 운영자가 따로 켜지 않는 한 이 경로가 없다. 쓰기는 계정별 요청 ID, 유효 참여·수신권·내용 버전을 검사하고 트랜잭션으로 처리한다. 키 자동 동기화·자동 등록은 없다. 기본 릴리스 설치기에 이 서비스를 끼워 넣거나 상시 실행시키지 않는다.

## 구현 결정과 한계

- 이 MVP에서는 두 개설자가 가입·일반 멤버 제외를 처리한다. 제공자가 자신의 카드와 공개 대상을 관리한다. 탈퇴하면 자신의 카드와 거기에 의존한 권한은 더 이상 열 수 없다. 다른 제공자의 자료는 자기 조건을 따른다. 마지막 개설자 이탈은 거부한다. 팀 소유권 이전·폐쇄·법적 보존·DB 영구 삭제는 확정하지 않았다.
- 서비스 상태와 Desk 세션은 별개다. 개인 Firefox에는 권한별 배치 수치·불투명 식별자만 별도 보관하며, 권한 목록 확인 뒤 지난 배치를 정리한다. 일반 Desk 복구 저장본에는 공용 원문·보드 제목·회신·키를 넣지 않는다. 이 구현은 OS 관리자, 사진·스크린샷이나 과거 수신자의 수동 복사를 통제하지 않는다.
- 실시간 스트리밍이 아니라 권한별 최신 상태 재조회다. 충돌은 자동 병합하지 않는다. 오류 후 상태를 확인하고 사용자가 다시 선택한다. 개인 업무 사이트, 라이브 Browser 공유/원격 입력, Agent 위임, 미니앱 설치, 종단간 암호화, 장치별 영수증, 오프라인 공동 편집은 이 기능이 아니다.
- 검증: `node --test helper/egdesk-joint-board.test.mjs helper/egdesk-board-presentation-plan.test.mjs` 및 `scripts/verify-firefox-mcp-board-two-profiles.mjs`. 후자는 신규 표시된 헤드리스 Firefox 프로필 2개·합성 사용자 3명·로컬 SQLite 서비스로 실제 chrome을 사용한다. 기존 프로필을 받지 않는다. `TMPDIR`와 그 아래 비어 있는 합성 `HOME`, `EGDESK_FIREFOX_BIN`, 6개 파일 전용 `EGDESK_QA_LOADER_SOURCE`, 설치된 Firefox MCP/Geckodriver가 필요하다. 기본 helper는 로컬 거부 응답 fixture로 격리하며 외부 모델은 쓰지 않는다. 검증 결과는 운영망·실조직 보안 인증이 아니다.

## 소속·업무 관계·도달성

Board 제목 또는 **구성 보기**를 누르면 현재 허용된 실제 구성 창만 표시한다. 번호가 붙은 이름을 누르면 그 창을 찾아간다. 이웃한 개인 메모는 목록이나 소속 표식에 들어가지 않는다. 창을 움직이면 구성원은 유지된다. 작성자는 **공개·회신 관리 → 자료 연결 편집**에서 ‘선행 자료’ 또는 ‘참조 자료’를 직접 지정한다. 양 끝이 보이는 사람에게만 관계가 보이고, 단독 전달에는 부모·이웃·관계 정보가 없다. 회신 쪽지와 받은 회신은 실제 대상 전표를 가리킨다. Board 작업의 **화면 겹침·입력 검사**는 [읽기 전용 장면 관찰](./DESK_SPATIAL_AUDIT.md)이다. 경고가 소속·업무 의미나 자동 이동을 만들지 않는다.

## 빠른 책상 정리

- **Desk 목록 → 지금 책상 빠른 정리…** 또는 **Board 작업 → 이 보드 빠른 정리…**. 현재 2D 작업면을 읽고 바로 로컬 점선 미리보기를 그린다. 사용자는 대상과 초점을 바꾸거나 취소한다. 창 하나를 찾는 카메라 보기와, 실제 위치/폭을 바꾸는 정리 명령을 구분한다.
- 직접 정리하거나, 옵션이 켜졌으면 **배치 사진으로 추천받기…**를 누른다. 허용된 요소의 화면 위치·글꼴·줄바꿈·앞뒤를 Firefox에서 측정해 재합성한 PNG와 목적, 구조화된 상태와 후보를 검토한다. **OS 화면 전체나 브라우저 탭을 찍은 스크린샷이 아니다.** 전표 본문 글자가 사진에 실릴 수 있다. 선택하지 않은 자료·계정·브라우저·채팅·터미널 화면을 자동으로 전송하지 않는다. 안전하게 그릴 수 없는 선택은 로컬로 남는다. UI는 모델 입력을 승인한 적 없는 자료를 임의로 빼고 성공한 것으로 보고하지 않는다.
- 다른 사람이 제공한 카드의 읽기·상태 변경 승인과 배치 사진으로 외부에 보낼 수 있는 권한은 별도다. 작성자가 **배치 사진에서 사용 허용…**을 그 수신자에게 주고, 수신자도 해당 1회 요청의 사진·수신처(OpenAI)·비용을 확인해야 한다. 회수하거나 자료·개인 배치가 바뀌면 이전 검토/늦은 답은 적용하지 않는다. 이미 전송한 사진을 회수한다는 뜻은 아니다.
- 모델은 좌표를 만들지 않는다. 현재 그대로, 선택 전체 보기, 한 장 집중, 비교, 필요한 한 장 앞으로, **자리를 살려 전체 정돈**, **업무 순서대로 인계 보기**, **주 작업과 참고 자료 함께 보기** 중 실제로 가능한 항목만 고른다. 인계 순서는 작성자가 명시한 `waits` 근거를 따른다. `off`는 모델 없이 로컬, `advisory`는 제안만, `on`은 개인 미리보기만. **내 화면에 적용**과 **마지막 적용 되돌리기**는 공용 게시와 별개다.

**일반 Desk의 내 메모:** 현재 선택에 포함되어 있고 사용자가 배치 사진 검토를 요청한 경우에만, 저장한 본문과 화면의 리비전·글자가 같은 메모를 검토 이미지에 담는다. 편집·IME 조합·저장 대기 중인 글, 접히거나 스크롤돼 확인할 수 없는 본문, 메모 대화·입력란은 보내지 않는다. 메모 줄바꿈은 실제 글꼴 치수로 재구성한 것으로 Gecko의 픽셀 복사는 아니다. 서로 다른 Board의 카드도 각각 유효한 사진 허가와 같은 개인 작업면이 필요하다. 최대 12개 대상, 768×512픽셀 이내다. 누락된 창까지 보여주는 전체 화면 캡처가 아니다.

**검증 경계:** 실제 키가 없는 격리 Firefox 두 프로필에서 확인했다. 네 장의 합성 작업에 대해 로컬 대역이 실행 가능한 `handoff`를 골랐고, Firefox에서 겹치는 창 쌍은 6→0, 적용 취소 시 개인 배치는 원상 복원됐다. 이 결과는 모델의 추천 품질·서비스의 입력 수락·지연·요금을 측정한 것이 아니다. `scripts/verify-firefox-mcp-board-two-profiles.mjs`는 진짜 공급자 대신 합성 응답을 주입한다. 실모델은 **설정 → 계정 → 결정 모델 · OpenAI Decisions**에서 별도로 구성하고 사진·수신처를 승인해야 한다.

## 검토된 팀 앱 두 종류

배송(집하 대기 → 집하 완료 → 배송 완료)과 검수(대기 → 통과/보류, 보류 → 통과)를 지원한다. `miniapps/joint-first-party-release.json`은 검토한 실행 파일과 배포 tarball SHA-256을 고정한다. 팀 소유자가 먼저 **서버에서 한 번** 실행한다. 클라이언트에서 패키지를 설치하거나 실행하지 않는다. 승인한 코드, 동작만 있는 계산 프로세스와 상태/권한을 가진 협업 서버를 분리한다.

```sh
# 각각 새 소유자 전용 디렉터리와 절대 경로를 쓴다. 키는 표준출력에 쓰지 않는다.
node scripts/start-verified-team-apps.mjs /absolute/private/runner/descriptor.json
# 별도 셸. 기존 두 계정·협업 서비스 준비 절차를 따른다.
EGDESK_TEAM_APPS_DESCRIPTOR=/absolute/private/runner/descriptor.json node helper/egdesk-joint-board-server.mjs serve /absolute/private/team-db 47631
```

운영자는 릴리스 기록 자체의 신뢰, 파일 소유권·디렉터리 접근, 별도 사용자/OS 격리·방화벽과 TLS를 담당한다. 위 실행기는 OS 샌드박스나 패키지 심사 서비스가 아니다. 임의 앱 실행·레지스트리 폴백·외부 배송/결제는 제공하지 않는다. 오프라인 `npx` 증명은 `node scripts/verify-joint-team-apps-offline.mjs`가 빈 캐시와 `--offline --ignore-scripts`로 재검증한다. 성패에 관계없이 패키지를 개별 참가자 브라우저에 설치하지 않는다.

**Board 작업 → 카드·사람 관리 → 팀 앱 항목 놓기**에서 항목 종류와 번호를 정한다. 카드를 공개하면 기본은 읽기 전용이다. 제공자가 보드 참가자에게 **상태 변경 허용…**을 따로 주면 그 카드에서 지원하는 변경을 확인 후 보낼 수 있다. 서버가 권한·원문 버전·앱 버전·동작을 다시 확인하고 성공한 변경만 원자적으로 저장한다. 처리 중 회수·강등·충돌·재시작은 늦은 결과를 폐기한다. 단독 수신자는 읽기 전용이다. 원격 편집이 개인 Firefox 상태나 다른 앱 항목을 바꾸지 않는다.

### 카드가 다른 창 아래에 있을 때

공용 Board를 선택하고 화면 위쪽의 **구성/자료**(또는 Board 메뉴의 같은 항목)를 연다. 카드 줄에 지금 할 수 있는 행동이 나온다. 작성자는 해당 카드의 공개·회신 관리, 참여자는 권한과 현재 상태에 따라 맡기 또는 회신 쪽지 열기를 사용한다. 다른 창을 옮길 필요가 없다. 선행/참고는 허용된 양 끝점의 이름으로 읽는다. 선 자체는 조작 대상이 아니며 완료·승인을 뜻하지 않는다. 취소하거나 Escape로 돌아갈 수 있다. 회수되면 이미 열린 행동도 갱신되며, 단독 수신에는 Board 구성·다른 사람·숨은 자료의 존재가 보이지 않는다.
