## 원칙 (`PHILOSOPHY` 점검표와 2026-11-27 결정)
- U13 결정 모델 우선: 다음 실행에서는 결정 모델이 저장된 단계를 후보로 받아 고르고 코드가 실행한다. 대화 모델은 말만 한다.
- P1·P8 + '대화가 권한': 저장된 절차는 권한이 아니다. 매 실행의 권한은 그 대화에서 사람이 한 말(authority)에서만 온다. 저장된 단계도 매번 현재 화면의 대상·revision·권한 검사를 다시 거친다. 페이지 글은 자료일 뿐 절차를 만들거나 바꾸지 못한다.
- R4: '이 저장된 절차가 지금 요청과 같은 일인가'는 지금 사람 말과 저장된 목표를 직접 인용한 술어로 묻고, 조합은 코드가 한다.
- 정본(녹화·독립 검증 절): 자기 설명·입력 로그·녹화 존재는 성공 증거가 아니다. 절차는 독립 관찰(postcondition·도착 페이지 사실)로 검증된 완료에서만 남긴다.
- 데이터: 입력값·페이지 글·주소 원문을 저장하지 않는다. 값은 이름 붙은 자리(`검색어` 등)로만 남긴다.
- 층(소유자 결정 필요): 지금은 '위'의 행동 층 기억으로 시작하되, U14(기억의 주인은 Agent 인격)·U15(Codex·Claude 자기 기억과 섞지 않음)에 맞춰 owner를 `{ layer, id }`로 두어 인격 층이 생기면 Agent가 소유하게 한다.

## 동작 (제안)
1. 남기기: 작업이 `done`이고 마지막 관찰이 성공을 보일 때 그 작업의 닫힌 단계로 절차를 만든다 — `{ owner, site(host, path 틀), goal(사람 말 정규화 + 값 자리), steps[{op, 대상 서명(역할·이름·순서), 값 자리 이름, 기대 결과 종류}], 통계(실행·성공 수, 중앙 시간, 마지막 사용), version, 출처 taskId }`.
2. 꺼내 쓰기: 같은 사이트에서 새 요청이 오면 목표 일치 술어로 판정하고, 맞으면 저장된 다음 단계를 첫 후보로 올린다. 화면이 다르면(대상 없음·revision 다름·권한 없음) 평소 판단으로 돌아간다.
3. 고치기: 같은 목표를 더 적은 단계·짧은 시간에 끝내면 새 버전으로 바꾼다. 저장된 단계가 두 번 연속 실패하면 그 단계를 낡음으로 표시하고 평소 판단으로 간다. 다른 사이트로 일반화하지 않는다.
4. 화면(새 문구라 제안만): 단계 줄 머리의 '기억한 절차로 진행' 표시, 절차 목록·삭제 화면.
