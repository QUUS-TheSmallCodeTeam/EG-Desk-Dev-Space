# 같은 Board에서 누구의 브라우저와 Agent로 일하는가

**상태: 설계 제안, 원격 기능 미구현.** ‘작업 환경’은 일상어다. 별도의 Workspace 객체를 만들거나 `[초대]`의 기본값을 정하지 않는다. 사람에게 같은 Board를 보여 주는 일, 특정 기기에 로그인된 브라우저에서 일을 시키는 일, 그 화면을 보거나 조작하는 일은 조합할 수 있지만 서로를 허가하지 않는다. 구현 전 필요한 인프라·조직 정책 결정은 기존 [조직 실행 계약](../../../ideas/confirmed/EGDESK_INTERACTION_AND_ORCHESTRATION_CONTRACT.md#tech-org-execution)을 따른다.

[사용 시나리오](../../../ideas/confirmed/EGDESK_PRODUCT_INTERACTION_TRACE_ATLAS.md#atlas-shared-card-agents) · [권한과 실행 예시](#cross-agent-requests) · [인수 사례](#collab-checks)

## 출발점: 현재 로컬 기능

- [Browser 카드 소스](../overlay/JS/eg-desk-surface.uc.js)의 `createXULElement('browser')` 경로는 카드 안에 Firefox 콘텐츠를 붙인다. 선택한 분리 환경이 있으면 `userContextId`를 검사한다. 모든 카드가 독립 로그인인 것은 아니다. Firefox의 [`remote tab`](https://firefox-source-docs.mozilla.org/dom/navigation/embedding.html)은 브라우저 내부 프로세스 간 통신이지 다른 PC에 화면을 전송한다는 뜻이 아니다. [컨테이너](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Work_with_contextual_identities)는 로그인에 쓰는 쿠키 저장소를 나눌 수 있지만 살아 있는 페이지를 복제하지 않는다.
- 같은 파일의 `serializeCardState`와 `runtimeStateForCard`는 배치, 주소·제목, 선택한 컨테이너 정보 등을 저장한다. 쿠키·로그인 토큰, 열린 메뉴, 편집 중인 페이지 메모리를 다른 PC에서 복원한다는 계약이 아니다. [JSON Canvas 내보내기](../overlay/resources/EGDeskBoardExport.sys.mjs)에서 Browser는 링크가 된다. `.egdesk`로 새 사본을 가져와도 실시간 연결은 생기지 않는다.
- [Board Thread의 현재 라우팅](./BOARD_THREAD_MULTI_AGENT.md)은 로컬 Agent를 멤버로 추가하고 지원되는 경우 지정한 프로필에 질문하는 경로다. 지정 Agent와 실행할 Browser를 함께 선택한 Board 요청은 현재 거절된다. 로컬에서 가능한 Agent 간 인용도 있다. 지원되는 Codex Board에서 한 번의 전송으로 두 Agent를 명시 지목했을 때, 확정되어 방에 게시된 최종 답변을 아직 진행 중인 상대 원래 턴에 방향별 최대 한 번 전달할 수 있다. 새 턴을 시작하거나 재시도·재생하지 않으며, 접수는 모델이 읽었다는 증거가 아니다. 이는 동료가 소유한 Agent를 직접 호출하거나 새 검토를 재위임하는 기능이 아니다. [설정 사본·일회용 질문 코드와 검토 파일](../../../ideas/confirmed/EGDESK_PRODUCT_INTERACTION_TRACE_ATLAS.md#atlas-local-share)은 이미 가능한 다른 방식이다. 어느 것도 원격 사람의 신원 확인이나 상대 Agent 직접 호출의 증거가 아니다.

## 내 보드에 초대하지 않고 공용 보드를 함께 시작하기 (제안)

기존 Board 초대는 상대가 **기존 방과 배치에 참여**하는 일이다. 공동 개설은 **두 사람이 고른 작업 구성을 중립적인 새 Board 한 곳에서 다루는 일**이다. 어느 쪽의 Desk가 상위가 되지 않고, 공용 공간을 위해 새 제품 계층이 필요한 것도 아니다. 보드 데이터를 한 사람의 PC 또는 팀 호스트가 보관할 수 있는지와 누가 보드를 관리하는지는 다른 문제다.

- **시작:** 한 사람이 목적·후보 참가자·보존 조건을 제안한다. 상대는 자기 쪽 자료를 선택해 내놓거나 아무것도 제공하지 않을 수 있다. 수락·기여 허가 전에는 비공개 제목·미리보기도 노출하지 않는다. 둘이 수락한 같은 개설 요청은 한 Board로 연결한다. 거절·만료·중복 수락은 양 개인 Board를 변경하지 않는다. 제안자·최초 접속자·호스트가 자동 영구 소유자가 되지 않는다.
- **무엇을 모을지:** 각자 카드 한 장이나 선택한 배치를 가져온다. 원본의 허용된 버전/항목에 대한 연결, 시점이 고정된 발췌 사본, 공동 작성 메모를 표시에서 구분한다. 공용 배치만 옮기며 원본을 옮기거나 덮어쓰지 않는다. 라이브 조회는 허용된 호스트에서만 한다. Agent를 목록에 보이는 것, 그 Agent에게 일을 부탁하는 것, 그 Agent가 다른 사람의 자료를 처리하는 것은 각각 허가가 다르다.
- **떠나는 경우:** 화면 닫기, 멤버에서 나가기/제외하기, 자신의 원본 연결 회수, 공용 보드에서 카드 빼기, 보드 폐쇄·자료 삭제를 구분한다. ERP 연결 회수 뒤에는 종속 조회·실행을 막고, 원본이 제한되면 수치를 담은 캐시·요약·알림도 공개 허용 범위를 다시 확인한다. 독립적으로 보존이 허용된 메모를 무조건 지우거나 과거 전달 사본을 회수했다고 하지 않는다. 호스트 단절 뒤 실제 원격 종료나 다른 호스트의 자동 승계를 약속하지 않는다.
- **미결정:** 한 번의 대조 뒤 정리할지, 팀이 이어 쓸지, 누가 제3자 가입·제외·폐쇄를 승인하고 마지막 관리자 이탈·의견 충돌을 어떻게 다룰지는 [협업 정책](../../../docs/codex/egdesk-product-interaction-trace-atlas-editorial-ledger.md#hum-collab-001)에서 결정한다. 창을 닫았다는 사실로 정하지 않는다. 공용 보드는 공개 인터넷·전 직원 열람을 뜻하지 않는다.

**공용 공간을 찾는 화면 경로:** 현재 로컬 입구와, 기본 초대 설계의 ‘수락하고 참여’ 및 받은 초대 경로, 이번 안에서 제안한 공동 개설 메뉴와 왼쪽 공용 보드 바로가기를 [입장 매뉴얼](../../../ideas/confirmed/EGDESK_PRODUCT_INTERACTION_TRACE_ATLAS.md#atlas-board-entry-doors)과 [단일 페이지 시연](../../../sketches/board-collaboration-entry/README.md)에서 비교할 수 있다. 공용 정보를 어디서 클릭하는가와, 그 사람이 어떤 자료를 실제로 받을 수 있는가는 별개다.

## 같은 사이트처럼 보여도, 무엇을 함께 쓰는지가 다르다

| 같이 하려는 일 | 원래 상태가 있는 곳 | 상대가 받는 것 / 받지 않는 것 |
| --- | --- | --- |
| 내 배치를 사본으로 건네기 | 내 로컬 Board | 허용한 자료의 특정 시점 사본. 이후 어느 쪽이 옮긴 카드도 상대에게 자동 반영되지 않는다. |
| 같은 Board를 편집하거나 발표자를 따라가기 | 공유 대상으로 승인된 Board의 객체와 배치 | 현재 허용된 배치와 이후 변경. 자기 확대율·카메라는 개인 상태다. 따라보기는 시점 표시만 연결하며 브라우저 로그인이나 입력 권한을 주지 않는다. |
| 같은 주문을 각자 열기 | 참가자별 로컬 브라우저 + 업무 서비스 | 직접 열 수 있는 주소/업무 식별자만 건넨다. 각자 로그인하고 권한을 확인한다. 상대의 입력·스크롤·메뉴는 따라가지 않는다. 주소가 세션에 묶였거나 공개할 수 없다면 공유 가능한 식별자만 쓰거나 중단한다. |
| 로그인된 호스트에 일만 맡기기 | 승인한 PC의 실제 Browser 카드와 사이트 계정 | 그 카드에서 허용한 조회 등을 한 번 수행하고 공개를 허용한 결과만 반환한다. 로그인도 옮기지 않고, 요청자에게 영상을 보여 줄 필요도 없다. |
| 로그인된 카드를 같이 보기 | 호스트의 살아 있는 페이지와 그 카드에 그려진 화면 | 허가한 참가자에게 해당 카드 화면만 보낸다. 메뉴·스크롤·저장 전 글자가 **화면에 보이면** 보일 수 있다. 개별 키 입력, DOM, 다른 카드, 비밀번호 관리자, 녹화나 모델 전송을 함께 허용한 게 아니다. |
| 그 카드에서 번갈아 조작하기 | 같은 호스트 페이지, 당시 입력을 맡은 한 사람 또는 Agent | 상대의 입력을 허용 범위 안에서 그 페이지로만 보낸다. B 기기에 A의 세션이 생기는 것이 아니다. 원 사이트에서는 A의 사이트 계정으로 처리될 수 있다. 시청·제어는 각각 회수할 수 있다. |

Figma와 닮은 부분은 [공유 문서의 변경을 여러 클라이언트에 반영하는 것](https://www.figma.com/blog/making-multiplayer-more-reliable/)과 [원할 때 다른 사람의 보드 시점을 따라가는 것](https://help.figma.com/hc/en-us/articles/5025214483351-Facilitate-meetings-with-spotlight)까지다. 임의의 제3자 사이트에서 같은 주소를 열었다는 이유로 그 사이트의 문서 모델이나 편집 세션이 EG-Desk 소유가 되지는 않는다. 사이트 자체가 공동 편집·자동 저장을 제공한다면 그 변경의 기준은 그 사이트다.

### 입장한 뒤 바뀐 상태는 누가 반영하는가

- **배치:** 입장 때 허용된 객체의 현재 버전을 받고 이후 카드 추가·이동·삭제를 순서대로 적용한다. 재접속은 놓친 변경을 메우거나 최신 허용 배치를 다시 받는다. 삭제·권한 철회와 충돌한 예전 이동으로 카드를 되살리지 않는다. 같은 카드 이동이 충돌하면 기준 버전에 먼저 반영한 변경을 유지하고 상대에게 재배치 여부를 보여 주는 것이 한 가지 안이다. 통신 기술이나 병합 알고리즘은 확정하지 않았다.
- **탭 내부:** 저장 버튼이 있는 가상 ERP에서 `8 → 21`을 입력한 시점에는 호스트 페이지가 기준이다. 보기 권한자는 그려진 `21`을 볼 수 있어도, 각자 연 페이지나 ERP 기록은 아직 `8`일 수 있다. 화면 시청은 타이핑 기록 수집이나 원격 입력이 아니다. 보드에서 카드를 따라가도 사이트 안에서 사용자의 포커스를 빼앗지 않는다.
- **업무 기록:** 외부 저장은 지정한 실행자 한 곳에서만 한다. 서버 응답·재조회 등으로 확정된 결과와 화면에 입력한 값을 구분한다. 다른 클라이언트로 전달할 것은 허가된 변경 결과이지 저장 클릭이 아니다. 재접속·재시도 때 성공 여부가 불명확하면 대조 전 중단한다. 대상 서비스에 확인 수단이 없다면 ‘결과 미확인’이지 성공이나 자동 재시도가 아니다.
- **저장 버튼 전의 효과:** 보기·입력권이나 `읽기`·`초안`이라는 이름은 외부 효과를 승인하지 않는다. 페이지 열기·포커스 이동·타이핑만으로도 읽음 처리·자동 저장·알림이 발생할 수 있다. 허용하지 않은 효과가 일어나지 않음을 보장할 수 없으면 실제 사이트에서 그 동작을 시작하지 않는다. 효과 없는 사본이나 검증된 읽기 경로를 쓰고, 둘 다 없으면 중단한다.
- **경계 변화:** 호스트·브라우저 컨테이너·페이지 대상·업무 계정이나 승인 대상자가 바뀌면 이전 화면·제어·작업 허가로 계속하지 않는다. 민감 화면, 로그인, 예상 밖의 새 창으로 이동할 때 공유 범위를 보장할 수 없으면 전송 전에 일시중지한다. 전송을 끄면 새 프레임을 보내지 않는다. 적용이 확인된 뷰어는 마지막 정지 화면도 닫으며, 단절된 기기에 실제 반영됐는지는 확인 전까지 미확인이다. 이미 본 내용이나 외부 서비스에 완료된 일을 회수했다고 표시하지 않는다.

## 서로의 Agent 사용: Agent 소유자와 업무 계정을 분리한다

‘서윤의 정산 Agent’는 서윤이 관리하는 설정의 특정 버전을 가리킨다. **서윤의 유료 계정, 서윤 개인 DM·기억, 서윤이 볼 수 있는 모든 사이트를 뜻하지 않는다.** 같은 Board에서 민재가 정산 Agent를 부르고 서윤이 동시에 민재의 검수 Agent를 불러도 두 건의 독립된 요청이다. 설정 사본을 가져와 자기 Agent로 쓰는 것, 소유자가 파일로 질문을 받아 처리하는 것, 원격에서 원 Agent에게 직접 맡기는 것도 구별한다.

| 예시 요청 (모두 목표) | 실제로 필요한 범위 | 성공해도 생기지 않는 권한 |
| --- | --- | --- |
| 민재 → **서윤의 정산**: 민재 카드의 주문 합계를 검토해 민재에게만 회신 | 민재가 해당 발췌를 정산 Agent에 제공할 권리, 서윤이 이 버전의 Agent 사용을 허용한 범위, 승인된 실행기·AI 계정·비용·결과 수신자 | 서윤 본인에게 민재의 화면이나 답이 자동 공개되지 않는다. Agent 소유자와 실제 실행 호스트가 볼 수 있는 데이터 범위를 보장할 수 없으면 그 발췌를 보내지 않는다. |
| 서윤 → **민재의 검수**: 같은 Board에서 서윤 카드의 규격을 확인 | 위와 반대 방향의 별도 요청. 서윤 카드의 조회 대상과 공개 가능한 답, 민재 Agent의 허용 범위를 확인한다. | 첫 요청의 수락은 반대쪽 허가가 아니다. 양쪽이 서로의 임시 권한이나 기억을 합치지 않는다. |
| 민재 → **서윤의 정산**: 이번에는 **서윤이 로그인한 카드**에서 조회 | Agent 사용과 별도로 호스트·카드·사이트 계정, 조회할 주문/항목, 민재에게 공개할 결과가 허용되어야 한다. **화면 없이 합계만** 회신할 수도 있다. | 민재의 사이트 로그인, 다른 주문 열람, 서윤의 화면 시청·원격 조작·저장이 생기지 않는다. |
| 민재 → **민재의 검수**: 서윤의 카드에서 정정 **초안**을 만들기 | 민재 소유 Agent여도 서윤 측의 자료 제공·카드·행동·결과 공개 허가가 필요하다. 초안은 효과 없는 사본에서 만든다. | 자동 저장 사이트에서는 입력 자체가 쓰기일 수 있다. 영향 없는 편집을 보장하지 못하면 실제 카드에 입력하지 않고 제안만 만든다. |
| 정산 → 검수: 정산 결과의 한 줄을 재검토 요청 | 새 수신자, 새 Agent 버전, 허가된 발췌·처리 위치·회신 대상에 대해 별도 위임이 필요하다. 민재/서윤의 두 요청을 합치지 않는다. | 첫 Agent에 준 도구나 재위임 권한을 상속하지 않는다. 다른 Agent가 없거나 예산이 떨어져도 개인 DM·다른 구독으로 바꾸지 않는다. |

**합계만 답하라는 문장은 공개 통제가 아니다.** 대리 조회는 허용된 최소 필드만 읽는다. 수신자에게 공개할 필드를 코드로 제한하거나 권한 있는 담당자가 검토·승인한 결과만 보낸다. 모델 요약이나 프롬프트만으로 공개 범위를 보장하지 않는다. 비공개 주문명이나 주문의 존재는 본문뿐 아니라 미리보기·알림에도 노출하지 않는다. Agent 설정도 소유자의 승인된 실행 경계에서만 사용하며 다른 사람의 실행기에 비공개 지침 원문을 몰래 보내지 않는다.

**한 요청을 실행하기 전에 답할 질문.** 누가 누구에게 무엇을 요청했나? 어느 Board의 어느 Agent 소유자/버전인가? Agent를 실행할 기기, AI 처리 서비스·계정, 실제 비용 부담 주체는 각각 어디인가? 업무 사이트를 실제로 여는 기기·카드·계정은 무엇인가? 어떤 자료를 어디까지 제공하고 조회·초안·저장 중 무엇을 허용했나? 답을 누가 볼 수 있고 언제 끝나는가? 사람 이름·표시용 Agent 이름·URL만으로 대상을 추정하지 않는다. 외부 서비스 계정을 확인하지 못했다면 ‘미확인’으로 표시하고 그 신원이 필요한 행동은 막는다.

- **요청을 받는 것 ≠ 실행 ≠ 외부 효과 ≠ 결과 게시.** 이미 승인된 범위면 매번 양측에 묻지 않는다. Board/자료 공개 권한, Agent 소유자의 사용 허가, 실행 호스트·목표 계정의 허가, 처리처·예산과 서비스 정책 중 하나라도 맞지 않으면 이유를 표시하고 해당 단계에서 멈춘다. 권한 있는 쪽만 부족한 범위를 승인할 수 있다. 사업자 약관이나 조직 정책이 금지한 계정 대여를 제품상의 승인으로 허용하지 않는다.
- **개인 자료는 보드 대화가 아니다.** 선택한 요청과 허가된 자료만 새 작업에 제공한다. 비공개 DM·MemBrain 기록·설정 원문·다른 Agent의 추론·로그인은 붙이지 않는다. 화면 시청 허가도 이미지·텍스트를 다른 모델로 보내거나 장기 기억에 넣는 허가가 아니다. 결과 공개·장기 저장·다른 방 전달은 대상과 범위를 다시 확인한다.
- **동시에 쓰기:** 두 사람이 두 Agent에 다른 검토를 병렬 요청할 수 있다. 같은 호스트 카드에서는 사람과 Agent를 합쳐 한 시점에 한 주체만 클릭·입력한다. 별도 카드라도 같은 주문을 수정하면 서비스의 버전·충돌 확인이 따로 필요하다. 이를 보장할 수 없으면 원본 저장 대신 차이를 제시한다. 불분명한 외부 쓰기를 성공할 때까지 재시도하지 않는다.
- **기록과 철회:** 요청자, 승인된 Agent 소유자·버전, 실제 실행기·업무 계정, 조작 주체, 허용한 결과 수신자와 상태를 구분해 권한 있는 사람에게만 표시한다. UI 화면의 행위자와 사이트의 감사 기록상 계정은 다를 수 있다. 원문·키 입력·화면 녹화를 감사 기록에 넣지 않는다. 시작·도구 호출·외부 효과·결과 게시 직전에 유효 범위를 다시 확인한다. 입력권만 회수하면 허가된 시청은 유지할 수 있지만 시청을 잃은 원격 조작자는 보지 못한 채 입력하지 않는다. 화면 없이 맡긴 독립된 조회는 그 작업 허가를 따로 회수할 수 있다.

### 같은 카드에서 사용자가 알아야 할 최소 표시 (문구 제안)

카드 자체에는 **누구의 사이트 화면인지**와 **내가 할 수 있는 일**을 글자로 표시한다. 예: `내 ERP로 열림` / `서윤의 ERP · 보기만` / `서윤의 ERP · 민재가 조작 중`. 눈에 보이는 시청자·공유 중지·조작권 회수를 호스트 카드에서 찾을 수 있게 한다. 따라보기와 원격 조작은 서로 다른 조작으로 노출한다. 색깔·아바타·같은 사이트 주소만으로 구분하지 않는다.

Agent 요청에는 `민재가 요청 → 서윤의 정산 → 민재 ERP 읽기 → 민재에게만 답변`과 같이 표시한다. 세부 정보에는 실제 실행 위치, 자료가 보내지는 AI 처리처·비용 부담, 만료와 바뀔 업무 계정을 나타낸다. 결과만 받는 민재에게 비공개 카드 썸네일이나 접근할 수 없는 주문명까지 보여 주지 않는다. 저장·발송·새 수신자 추가 등 범위를 바꾸는 순간에는 바뀐 부분을 그 자리에서 다시 확인한다. 이 문구·기본 선택·전송 인프라는 확정 사항이 아니다.

| C12 실행 후 한 방향만 회수 | 두 위임이 시작된 후 공개 직전 서윤이 ‘민재 → 서윤의 정산’만 회수한다. 두 기기가 재접속한다. | 민재에게는 ‘실행 시작됨 / 답변 공개 중지’만 보인다. 본문·미리보기·알림으로도 내용이 새지 않는다. 반대쪽 위임은 허용 범위에서 완료된다. 과거에 이미 받은 답까지 지웠다고 하지 않는다. |
| C13 공동 개설 | 두 사람이 서로 다른 개인 보드에서 같은 공동 개설 제안을 수락하고 한쪽이 재접속해 수락을 반복한다. 별도의 제안은 거절한다. | 수락한 한 건에는 공용 Board가 하나만 생긴다. 거절한 건에서 자료 유출·개인 배치 변경이 없고 최초 제안·호스팅을 근거로 상대 원본이나 운영 권한을 늘리지 않는다. |
| C14 원본 회수와 멤버 이탈 | 서윤이 ERP 수량 조회 허가만 철회한 뒤 민재가 자기 창을 닫는다. 별도 조건으로 다시 들어오거나 멤버에서 제외해 본다. | 새 조회와 제한된 파생 수치 노출은 차단한다. 독립적 보존이 허용된 공동 메모·발주서 사본은 해당 정책을 따른다. 창 닫기·멤버 제외·카드 제거를 하나로 처리하거나 원본 파일을 지우지 않는다. |
| C15 새 동료 합류 | 팀 보드에 제3자가 들어온다. 기존 두 사람끼리만 승인한 카드·Agent 요청이 진행 중이다. | 새 참가자에게 원본 제목·화면·답을 자동 공개하지 않는다. 상대 Agent 호출·비용·원본 재공개도 상속하지 않는다. |
