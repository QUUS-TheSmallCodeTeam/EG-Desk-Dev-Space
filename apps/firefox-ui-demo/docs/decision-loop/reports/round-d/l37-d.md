## 2차 방향 수정 반영: 캡처원 2개 (body.source)
소유자 요구 = "사람 눈에 보이는 그대로"(별도 창·대화상자·팝업 포함). drawSnapshot은 본창 문서만 찍어 Firefox 업데이트 창 같은 별도 창을 못 본다.
- **os (기본, QA·개발용, 마스크 없음)**: 브리지가 ffmpeg(avfoundation, h264_videotoolbox, 기본 10fps, 폭 최대 1280, fragmented MP4)를 자식 프로세스로 띄워 EG-Desk 창 영역을 찍는다. 영역은 시작 때 창이 `locate` 명령에 답한 screenX/Y·outerWidth/Height·dpr·screen에서 계산(점→장치 픽셀, 짝수), 주 모니터 아닌 곳·화면 밖이면 거절. sidecar에 `mask:"none"`, `maskNote`, `region`(+ "시작 때 영역 고정, 창이 움직이거나 크기가 바뀌어도 따라가지 않음, 주 모니터만" 문구), owner·runtime·node를 시작 전에 저장. 녹화 중엔 창에 글자 없는 빨간 점(`indicator` 명령; 화면에 같이 찍힘). 정지는 ffmpeg stdin에 'q'(8초 안 끝나면 SIGINT, 4초 뒤 SIGKILL=실패 표시). 최대 길이는 ffmpeg `-t`+브리지 타이머, 브리지 종료·ffmpeg 비정상 종료도 마무리·검증한다. 정지 뒤 브리지가 ffprobe로 디코드 검증(전체 파일 sha256·크기·프레임 수·길이).
- **screencapture 대신 ffmpeg인 이유(실측)**: `screencapture -v -V 60 -R…`는 SIGINT·SIGTERM·SIGHUP으로 멈추면 **파일을 안 남기고 죽는다**(node spawn 3회, 시그널 6초 후 포함, 종료 뒤 15초 감시). bash 백그라운드에선 SIGINT를 무시하고 -V 60초를 다 채웠다(60초·29MB, 2560x1440 3169프레임 = 정상 마무리는 자체 타임아웃뿐). tty에서 Ctrl-C/Enter도 시험했으나 파일 없음. 즉 중간 정지가 안 돼 채택 불가. ffmpeg avfoundation("Capture screen 0")은 같은 권한 계통에서 동작하고 'q'/SIGINT로 정상 마무리된다.
- **실측 확인**: 서비스 모듈을 실제 spawn으로 3초 돌림(영역 139,95 1280×720pt, dpr 2): start 200 → 3초 → stop 508ms에 finished, 1280×720 h264, 디코드 31프레임, 길이 3.000초, verification ok. 시험 파일은 삭제했다. (그 전 시도 중 찍힌 사용자 화면 PNG·MOV도 즉시 삭제, 내용 보존 안 함.)
- **window (대체 캡처원, 마스크 가능, 본창만)**: 아래 1차 구조 그대로. 별도 창은 못 본다.
- **제품 경로(이번 라운드 미구현, 다음 작업)**: ScreenCaptureKit(SCContentFilter를 EG-Desk Firefox 프로세스의 모든 창으로 = 별도 창·대화상자 포함, 다른 앱 창 제외) → 프레임 단위로 `screenshotMask` 좌표(창 좌표→화면 좌표 변환 + 별도 창은 전체 가림 또는 허용 목록)로 마스크 → VideoToolbox(AVAssetWriter/VTCompressionSession) 인코딩, Rust 도우미(helper-rust)에서 실행하고 브리지가 제어·검증. 필요한 것: 화면 기록 권한 요청·상태 표시, 창 이동 추적(SCStream 창 단위 프레임), 마스크가 불가한 프레임 폐기, 구간 hash/mask revision sidecar는 이미 만든 형식 재사용. 정본의 "capture→mask→encode"는 이 경로에서만 지켜진다. os 소스는 마스크가 없어 비밀번호 입력 중 녹화하지 말 것(QA 전용).

# 1차(창 내부 캡처) 구조

## 구조
- 오버레이 `overlay/resources/EGDeskScreenRecorder.sys.mjs` (새 모듈, 임시 이름): `createScreenRecorder(deps)` → start/stop/status. 순서 capture→mask→encode.
  - 캡처: `window.browsingContext.currentWindowGlobal.drawSnapshot`(Marionette 화면 캡처와 같은 합성). 기본 4fps, 축척 0.5. 틱이 겹치면 프레임을 버리고 센다.
  - 마스크: 브라우저 카드마다 기존 Browser actor의 `screenshotMask` 질의(비밀번호·일회용 코드·카드·private 표시 칸, 타 사이트 프레임, embed)를 재사용해 칸 단위로 칠한다. 질의 실패·미완성·크기 불일치(24px 초과)·비공개 창·로그인 카드(codexRole=auth)·확대 카드는 **카드 전체를 칠한다**. 크롬 쪽 `input[type=password]`, `[data-sensitive]`, `[data-private]`도 칠한다. 이전 틱의 상자도 함께 칠해(움직인 칸이 한 프레임도 안 보이게) 한다. 마스크를 못 만들면 그 프레임은 그리지 않고 버린다(fail-closed). 상자 집합이 바뀔 때마다 mask revision 증가.
  - 인코드: 캔버스 → `captureStream(rate)` → MediaRecorder(vp9→vp8→webm 중 지원 첫 형식). 지원 형식이 없으면 시작 거절(`encoder-unsupported`), 네이티브 인코더는 넣지 않았다.
  - 파일: `<데이터>/recordings/<id>.webm`에 timeslice(2초) 구간을 이어 쓰고 `<id>.json` sidecar를 구간마다 갱신. sidecar: owner·runtime·node(시작 전에 먼저 저장), 구간별 시작/끝 ms·바이트 offset/길이·sha256·mask revision 범위·그린/버린 프레임 수, 버린 이유별 수, mask revision 목록, 최종 verification.
  - 표시: 녹화 중 오른쪽 위에 글자 없는 빨간 점(10px, 클릭 통과). 정지 때 제거.
  - 종료: 최대 길이 30분 자동 중지, window unload·`quit-application-granted` 때 중지·마무리, 브리지 종료 때도 중지 명령(`closing()`).
- 브리지 `helper/egdesk-screen-recording.mjs`(새 모듈) + `codex-bridge-server.mjs` 연결 4줄(import, 서비스 생성, 라우트, shutdown 훅):
  - `POST /v1/recording/start {label?,fps?,scale?,timesliceMs?,maxMs?}` → 오버레이에 `recording.command` 이벤트(기존 SSE) → 창의 'started' 보고를 기다려 응답(10초 내 없으면 504 `no-window-ack`).
  - `POST /v1/recording/stop` → 창의 'stopped' 보고 → **브리지가 파일을 다시 읽어 독립 검증**: 구간 sha256·offset·총 크기, ffprobe(/opt/homebrew/bin) 있으면 디코드 프레임 수·크기·코덱(`playback: decodes`). 결과를 상태와 sidecar(`verification.recorder`/`.bridge`)에 기록. 검증 실패면 상태 failed.
  - `GET /v1/recording` 상태+마지막 녹화, `POST /v1/recording/report`(창 보고, loopback).
  - 플래그 `EGDESK_SCREEN_RECORDING=on`(임시 이름, 기본 끔). 끄면 모든 경로 404 `{status:'off'}`. 플래그는 모듈 안에서 읽는다(브리지 파일에 새 플래그 이름을 쓰면 real-engine-check 목록 시험이 깨져서).
- 오버레이 연결 `overlay/JS/eg-desk-surface.uc.js`: `screenRecording()`(지연 생성, start 명령 전엔 import도 안 함), `handleRecordingCommand`, 이벤트 switch에 `case 'recording.command'` 3줄. Desk 창(`#egd-canvas-layer` 있는 창)만 반응.
- QA 도구 `scripts/real-window-qa/record.mjs`(start [--fps N] [--scale S] [라벨]|stop|status, 브리지 HTTP만), `frames.sh <webm> <dir> [fps]`, README 표 2줄.

## 정본 대비
지킨 것: capture→mask→encode 순서(마스크 불가 프레임은 버림), MediaRecorder+지원 WebM 확인, 미지원이면 기록 불가, 구간별 hash·시간·mask revision·누락 저장(timeslice 정확도 가정 안 함), node·owner·runtime을 첫 프레임 전에 영속화, hidden-only 금지(빨간 점), 앱 종료 때 중지, 녹화 존재를 성공 증거로 쓰지 않음(검증은 파일 재읽기·ffprobe 디코드로 분리, 보고서·상태 어디에도 성공 판정에 쓰지 않음).
못 지킨 것/미구현: 
- "형식 지원과 **실제 재생** 검사": 브리지 ffprobe 디코드로 대체(재생이 아니라 디코드). ffprobe 없으면 `playback:'unchecked'`로 남기고 ok는 해시·크기만으로 판정.
- 관찰/앱 분리·인계 계약: v1은 분리 없음, 앱·창 닫힘 = 중지.
- OS 레벨(ScreenCaptureKit) 캡처·창 선택 동의 흐름: 안 함(자기 창 내부 합성 캡처만).
- 비밀 칸이 카드 안 스크롤로 보이는 위치는 `screenshotMask`가 viewport 기준이라 반영되지만, 크롬 쪽(대화창 입력칸 등)의 민감 판별은 password/data-sensitive/data-private뿐이다.

## 실측으로 바꾼 것 (권장안과 다름)
`captureStream(0)`+`requestFrame()`은 Firefox에서 인코더에 초당 약 1프레임만 도달(5초 4fps 애니메이션: 패킷 6개). `captureStream(30)`은 20개, `captureStream(4)`는 13개. 그래서 `captureStream(max(8, 2*fps) 상한 30)`로 바꿨다. 캔버스는 그릴 때만 바뀌므로 그리지 않는 동안 비용 0. 
같은 이유로 타임스탬프가 가변 프레임(VFR)이라 ffprobe `format.duration`은 null일 수 있다(프레임 수·sidecar 시간 사용).

## Main이 실창에서 확인할 절차
0. 소스 선택: 기본이 os(별도 창 포함, 마스크 없음). 본창만 마스크로 찍으려면 `--source window`.
1. 켜기: 개인 설정 파일 `settings/egdesk-personal-flags.json`에 `"EGDESK_SCREEN_RECORDING": "on"` 추가(또는 브리지 환경변수) 후 **브리지와 EG-Desk 재시작**(오버레이 코드 포함이라 앱도 재시작).
2. `cd apps/firefox-ui-demo/scripts/real-window-qa`
   - `node record.mjs start 채팅 스크롤 점검` (os: 기본 10fps, `--fps 20`까지; window: `--fps 10 --scale 0.75`) → id·file 출력. 창 오른쪽 위에 빨간 점이 떠야 함. os는 ffmpeg(/opt/homebrew/bin/ffmpeg)와 화면 기록 권한이 필요하고 권한이 없으면 `capture-failed`(422)로 거절된다.
   - 시험 수행
   - `node record.mjs stop` → `status:"finished"`, `recording.verification.ok:true`, `playback:"decodes"`, `decodedFrames` 확인. 상태는 `node record.mjs status`.
3. 프레임: `./frames.sh ~/Library/Application\ Support/EG-Desk/recordings/<id>.mp4 /tmp/frames 4` → f0001.png… (N번째가 (N-1)/fps초).
4. 확인 포인트: sidecar의 `framesDropped`/`dropReasons`(mask-failed 많으면 카드가 통째로 가려진 것), `maskRevisions.wholeCards`(전체 칠한 카드 수), 영상에서 비밀 칸·private 카드가 검은지.

## 남은 위험
- 브라우저 카드의 `screenshotMask` 질의는 headless에서 못 돌려봤다. actor가 안 붙는 페이지(about: 등)는 카드 통째 검정으로 나온다(안전하지만 영상이 덜 유용). 실창에서 `wholeCards` 확인 필요.
- drawSnapshot이 실창 합성에서 브라우저 카드 내용을 포함하는지는 Marionette 화면 캡처와 같은 경로라 기대하지만 이 라운드에선 직접 못 봤다.
- os 소스: 주 모니터만(보조 모니터 창이면 `not-main-display` 거절), 창 이동·크기 변경 미추적, 마스크 없음, 화면 기록 권한이 브리지를 띄운 프로세스 계통에 있어야 함(Main 확인: 이 머신은 있음). 시작 때 `locate` 응답(Desk 창)이 없으면 504.
- 인코더 한계로 timeslice 구간이 불균등(첫 구간 5초 사례). 비정상 종료 시 마지막 구간은 잃을 수 있다(sidecar는 구간마다 갱신).
- 성능: 켰을 때 비용 = 틱당 drawSnapshot + 카드 수만큼 마스크 질의(800ms 타임아웃) + 인코드. 4fps/0.5 기본. 끄면 import도 안 일어남. L38의 성능 측정에 녹화 중 CPU는 포함 안 됨.
- 창 크기 변경 시 캔버스는 고정 크기라 늘어난 비율로 그려진다(영상 해상도 불변).
- 오버레이 연결(.uc.js)은 실창 시험 전이다(구문 검사만).
