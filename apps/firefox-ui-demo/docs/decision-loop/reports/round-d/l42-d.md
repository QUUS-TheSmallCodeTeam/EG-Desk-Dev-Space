# L42-d 보고: 안 보이거나 작은 브라우저 카드 절전

브랜치 lane/d-card-throttle, 커밋 009ad51a + 29ca88bb (기준 int/d 7123f112).

## 쓴 Firefox 장치와 근거
- `browser.docShellIsActive = false`(= BrowsingContext.isActive: 타이머 조임·requestAnimationFrame 정지·문서 숨김 처리)와 `browser.renderLayers = false`(그리기 중단). Firefox 탭 전환 코드(tabbrowser)가 배경 탭에 쓰는 것과 같은 한 쌍. 깨울 때는 renderLayers → docShellIsActive 순으로 true.
- 코드로 확인한 점: 이 저장소는 docShellIsActive/renderLayers를 전혀 쓰지 않았음(grep 0건). 카드 <browser>는 XUL `browser`(remote)라 두 속성이 있고, iframe 대체 경로는 `typeof docShellIsActive !== 'boolean'`이면 건너뜀. Firefox 소스 자체는 이 환경에서 열어보지 못했고, 위 동작은 Firefox 크롬 JS의 통상 의미에 근거함(실창 확인은 Main 측정으로).

## 문턱·지연
- 카드(브라우저 영역)가 화면에 실제로 보이는 부분이 폭 560px 미만 또는 높이 350px 미만(완전히 화면 밖 포함)이면 잠재움 후보. 연속 2초 유지되어야 잠듦.
- 깨움: 보이는 부분이 폭 640 이상이고 높이 400 이상, 연속 0.3초. (560~640 / 350~400 사이는 현상 유지 = 히스테리시스.) 38% 배율 카드(1440x900 → 약 547x342)는 잠자는 쪽.
- 0.5초마다 검사(카메라 훅 없이 getBoundingClientRect). 카메라가 움직이는 중 잠깐 조건이 스치면 2초 안에 되돌아오므로 잠들지 않음.

## 제외(항상 깨어 있음, 잠자던 카드면 즉시 깨움)
활성 카드(state.activeEntityId)·전체화면 카드·포커스가 카드 안(주소창 포함)·로그인(auth) 카드·숨김/연결 끊긴 카드·화면 녹화 중·에이전트 요청 진행 중(inFlight)·사람이 잡은 상태(hold)·도구 사용 후 10초.

## Main 측정 방법
1. 설정 `egdesk.perf.sleepHiddenCards`에 `"on"`을 넣고 EG-Desk 재시작(끈 상태가 비교 기준).
2. 같은 카드 16장·배율 38%에서 창을 보이게 두고 30초 평균: 본체 firefox와 plugin-container(페이지 프로세스) CPU. 첫 3초는 제외(2초 지연 때문), 끈 상태와 켠 상태 비교.
3. 활성 카드(방금 만진 카드)는 제외되므로, 캔버스 빈 곳을 눌러 활성 카드를 비운 뒤 재는 편이 정확함. 확대해 카드 1장을 크게 보면 그 카드만 0.3초 뒤 깨는지, 에이전트 작업이 시작되면 해당 카드가 깨는지 확인. 확인용 신호: 해당 페이지에서 `document.hidden`이 true/false로 바뀜.

## 남은 위험
- 가정 하나: 카드 <browser>를 비활성으로 두는 것이 페이지 프로세스 부하를 실제로 줄이는지는 실창 측정 전까지 미확인(Firefox는 isActive=false에서 타이머를 1초로 조이고 rAF를 멈추나, 광고 iframe·워커·네트워크·오디오는 그대로일 수 있음).
- 소리 나는 페이지(음악·영상)가 작게 보이면 잠들 수 있음. 현재 오디오 예외 없음.
- 잠든 카드는 화면에 마지막 그림이 아닌 빈 그림이 될 수 있음(renderLayers=false). 작은 썸네일이 비는지 Main이 눈으로 확인 필요. 거슬리면 renderLayers는 두고 docShellIsActive만 끄도록 한 줄로 바꿀 수 있음.
- 활성 카드·포커스 카드 제외 때문에 사용자가 한 카드를 만진 직후엔 그 카드는 계속 깨어 있음(의도).
