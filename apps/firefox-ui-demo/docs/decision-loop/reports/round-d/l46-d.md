# L46-d: POST submit authority on the direct tool path + stable entry submit judgment

Commit: 17caa957 (lane/d-engine-post-submit, base int/d f84e40fe). Gate: L46-d-1 files=562 rc=0, tests 8522, pass 8481, fail 0, skipped 40.

## Cause
1. Entry (D4 defect): after the name fill, next_step ranked 'Submit order' 0.65-0.69, under the choice bar, so the step ended `uncertain` (hand-over "확신 낮음"). Reproduced with the real model on an in-memory httpbin form: 10/10 uncertain before the fix. The submit authority (R2/R4 predicate) was only asked AFTER the choice was accepted, so a shaky ranking never reached it.
2. Direct tools (confirmed in code): egdesk_card_press (helper/egdesk-page-tools.mjs `act`) classifies 'Submit order' as pay (term 'submit order') -> gate user-step -> `person_step`; other submit words go to the chat-approval path. Neither knew the person's words. (The runtime's CURRENT policy allows all classes; the block is in page-tools.)

## Fix
- helper/egdesk-browser-reflex.mjs: `authorizePostSubmit(authority, label, scope, timeout, {signal})` + `postSubmitQuestion` + `postSubmitSpent`: the single place that (a) checks the shared per-message ledger `spentPost`, (b) asks requestedGoal over the person's quote with the postSubmitQuestion, (c) rechecks current/abort, (d) consumes the message id before dispatch. Returns true / false / null(stale). The entry loop now calls it (same behavior).
- Entry stabilization: decideReflexStep asks a `post_requested` predicate in the SAME request when the page has exactly one code-proved write-submit option, no pending values, no motion/arrival (question = person's words + the form's current field values + postSubmitQuestion; "No if a field the person asked to fill is still empty or they said not to send"). A decided yes at the existing bar (max(done, choice)) names that option as the step (same mechanism as the select lists); it disagrees-guard still applies (a different accepted next_step wins). No threshold changed. The press itself still re-asks via authorizePostSubmit.
- helper/egdesk-page-tools.mjs `act` (press): before the classify/person branch, if the target is the form's one write-submit as buildReflexCandidates proves with the conversation authority (same origin, non-sensitive, no hidden field, no credential label, not opaque; httpbin 'Submit order' only on its demonstration endpoint) AND authorizePostSubmit says the person's quote of this turn (messageOf(run), conversation layer, never tool arguments) requested it, it presses once with postcondition url=form action (`via: 'person-asked'`), observes the landing; an unverified result is reported `written: 'unknown'` with "do not press again". Otherwise exactly the previous behavior (person_step / approval).
- scripts/egdesk-post-submit-real-measure.mjs: real-model measurement (in-memory httpbin form; key read from the attachment, never printed).
