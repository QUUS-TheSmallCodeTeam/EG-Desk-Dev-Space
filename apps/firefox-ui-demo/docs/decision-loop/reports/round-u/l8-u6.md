## 1. 닫힌 말로 보이게(지시 1)
`claudeBoundedInitDiagnosis(message)`가 `{ kind, count }`를 돌려줍니다: kind는 `builtin-tools | external-mcp | permission-mode | extensions`, count는 위반 항목 수(허용되지 않은 도구 수, 다른 서버 수, 1, skills+plugins+agents 개수). 이름과 CLI 문장은 넣지 않습니다. 어댑터가 `gateCode`(기존 `CLAUDE_BOUNDED_UNVERIFIED`)는 그대로 두고 `gateDetail`을 덧붙여 실행 기록 메시지가 `The Claude process ended before the turn finished (CLAUDE_BOUNDED_UNVERIFIED:builtin-tools=1)`처럼 됩니다(`run.error.code`는 기존 `TURN_FAILED`). `claudeBoundedInitViolation`은 종류만 돌려주는 기존 모양 그대로.

## 2. 공식 문서 대조(지시 2). 어떤 검사가 걸렸을까
(code.claude.com/docs: cli-reference, tools-reference, agent-sdk/typescript, 2026-11 열람)
- **builtin-tools(가장 유력, 검사 순서 1번)**: tools-reference "EndConversation tool behavior": 이 도구는 *다른 도구가 하나라도 남아 있으면* `--tools` 목록이나 deny 규칙으로 **제거할 수 없고**(의도된 예외, "세션이 끌 수 없어야 안전장치가 성립"), cli-reference `--tools` 행도 "`""`는 MCP 도구가 남아 있지 않을 때만 EndConversation을 제거"한다고 적음. EG-Desk MCP 도구가 있으므로 init `tools`에 `EndConversation`이 반드시 들어가고, 기존 검사는 `mcp__egdesk__` 접두가 아닌 도구를 모두 `builtin-tools`로 봄. 즉 **실제 CLI에서는 문서대로면 항상 걸린다**(이전 재생 시험의 init이 가짜였던 이유로 못 잡음).
- **extensions(그다음)**: SDKSystemMessage에 `skills: string[]`, `plugins: {name,path}[]`, `agents?: string[]`가 있고, 번들 스킬과 내장 에이전트까지 이름으로 나열됨(사용자 ~/.claude가 아니어도 비어 있지 않음). 기존 검사는 셋 중 하나라도 비어 있지 않으면 위반.
- 문서화된 "끄는 방법"은 이미 적용 중: 하네스 argv에 `--restricted`(사용자·프로젝트 설정 안 읽음, 관리형 설정과 `--settings`만), `--setting-sources=`(빈 목록), `--strict-mcp-config`, `--disable-slash-commands`("Disable all skills and commands"), `--tools ""`, `--no-chrome`, `--settings {"disableAllHooks":true}`. `--safe-mode`는 "MCP 서버 포함 모든 사용자 정의를 끄므로" EG-Desk의 sdk MCP 서버까지 못 쓰게 될 수 있어 **쓰지 않음**. EndConversation과 내장 에이전트 이름, 번들 스킬 이름은 문서상 끄는 플래그가 없음 -> 지시 (3)로.
- 어느 쪽이 실제로 걸렸는지는 이 창에서 직접 못 봄(CLI 실행 금지). 다음 실창에서 실행 기록 메시지의 `kind=count`가 알려 줌.

## 3. 완화(지시 3, **Main 승인 대기**): claude-browser 능력 경로에서만
- 적용 조건: 런타임이 `claudeBrowserLive()`(하네스 켜짐 + page tools 제공자 등록)일 때만 `egdeskBoundedRelaxed`를 어댑터에 보냄(`claudeBoundedThreadOverrides(policy, { relaxed })`, 두 호출 지점). 어댑터는 프로세스마다 보관하고 값이 바뀌면 새 프로세스로 재시작. **능력이 없으면 검사는 이전과 완전히 동일**(strict, 시험으로 고정).
- 완화 내용(둘뿐): ① tools에 `EndConversation`, `ToolSearch` 두 이름을 허용(`CLAUDE_BOUNDED_RELAXED_TOOLS`). EndConversation은 위 근거(제거 불가, 세션 종료 외 아무 일도 안 함). ToolSearch는 "지연된 도구를 찾아 싣는 도구"이고 `--strict-mcp-config`로 서버가 egdesk뿐이므로 싣는 대상이 EG-Desk 도구뿐(문서 근거는 설명 한 줄이라 가장 약한 부분, 승인 시 판단 부탁). ② skills, plugins, agents **목록**을 위반으로 보지 않음: 목록은 정보일 뿐이고 실행 수단(Skill 도구, Agent 도구)이 tools에 없음.
- 그대로 막는 것(시험으로 고정): 그 밖의 모든 내장 도구(Bash, Read, Write, Edit, WebFetch, Skill, Agent, Task, Workflow, SendToProjectContext 등과 다른 MCP 도구), egdesk 외 MCP 서버(플러그인이 가져온 서버 포함), `dontAsk`가 아닌 모드, 훅 이벤트 계수(기존). 플러그인이 도구·서버·훅을 가져오면 tools, mcp_servers, 훅 이벤트에서 잡힘.
- 한계: 실제 CLI 2.1.328의 init을 직접 관찰하지 못했으므로 위 문서 근거가 전부입니다. 허용 목록 밖의 내장 도구가 실제로 더 보이면(예: 문서에 없는 도구) 다음 시도가 `builtin-tools=N`으로 닫히고, 이름은 안 남기므로 그때는 도구 이름을 보려면 별도 승인된 진단(제안)이 필요: **제안(승인 대기)**: 능력 경로에서만 `tools` 중 허용 밖 이름을 로컬 로그에 남기는 진단 스위치.
