# L6 u1 — 컴퓨터 조작을 EG-Desk 도구로 제공하는 방안 (조사, 코드 변경 없음)

범위: '위'(채팅 하네스, 도구 호출, 브라우저·컴퓨터 조작). 기준 int/c14 `cf086b8`(읽기만). 사용자 `~/.codex` 는 서버 이름·실행 파일 이름·키 이름만 읽었고 값·환경 변수 값·토큰은 읽지도 적지도 않았다. 컴퓨터 조작은 한 번도 실행하지 않았다. 원칙: U10(엔진은 순수 모델, 행동·승인은 EG-Desk 자체), U11(Codex 설정 계층에 의존 안 함), U13(결정 모델은 정의된 층을 먼저), U19(Claude 대화도 EG-Desk 하네스로).
**먼저 알아 둘 것**: 이 주제는 2026-10-24 에 이미 조사·결정됐다(`docs/references/computer-use-options.md`, `rea-mechanism-adoption.md`, `reference-adoption-map.md` D-C1~C8). 결정: Q1 (다) 켜 둔 채 표시 보강, Q2 관찰 전용부터(OS 입력 보류), **Q3 EG-Desk 자체 Rust 도우미(cua-driver 를 띄우는 안은 채택 안 함)**, D-C3 허락 카드, A'(설치된 Codex Computer Use 를 동작 하나씩 호출)는 미정. 이 보고서는 그 위에 오늘 코드·설치 상태를 다시 읽고 (a)~(d)에 답한다.

## (a) 지금 EG-Desk 가 쓰는 컴퓨터 조작 도구의 실체 [설치본·코드]
- **화면 문구**: '컴퓨터 조작: 켜 둠 · 내 Codex 설정 그대로'는 정책 `inherit`(기본, 결정 Q1 (다))의 라벨이다 (`overlay/resources/EGDeskChatState.sys.mjs:2938`; 정책 `inherit|off`, `helper/codex-computer-control.mjs`). `off` 는 선택지로만 있고, 켜져 있으면 EG-Desk 는 Codex 의 설정을 **건드리지 않고** 그대로 상속시킨다.
- **'연결된 도구' 목록**은 Codex app-server 의 MCP 서버 목록(`mcpServerStatus/list`)을 이름·도구 이름으로 분류한 것(`helper/codex-inherited-mcp.mjs`: browser / desktop / repl / other; 이름 토큰 `computer`, `cua`, `desktop`, `accessibility`…, 도구 이름 `get_app_state`, `get_window_state`…, 그리고 직접 선언에서 `SKY_CUA_SERVICE_PATH`, `cua_node`, `SkyComputerUse`, `unified-computer-use`, `cua-driver` 표지가 있으면 이름이 무엇이든 desktop). 명령·URL·환경·토큰은 목록에 안 나온다.
- **이 Mac 에서 컴퓨터를 움직일 수 있는 길 세 개** (이름과 실행 파일만):
  | 서버 | 어디서 설정 | 실체 |
  |---|---|---|
  | `computer-use` | 사용자 `~/.codex/config.toml` 의 직접 `[mcp_servers.computer-use]` | 실행 파일 `SkyComputerUseClient` (OpenAI 의 Codex Computer Use 앱 안의 클라이언트) |
  | `node_repl` | 같은 파일의 직접 `[mcp_servers.node_repl]` (환경 키에 `SKY_CUA_SERVICE_PATH`) | 실행 파일 `node_repl`, 이름은 repl 이지만 같은 서비스에 연결되어 Mac 을 조작할 수 있음(표지 규칙으로 desktop 분류) |
  | `cua_repl` | 설치된 플러그인 `unified-computer-use@openai-bundled` (같은 파일의 `[plugins."…"]` 활성화) | 플러그인의 `.mcp.json`: `/bin/sh` 래퍼 → `ChatGPT.app/Contents/Resources/cua_node/bin/node` + `@oai/cua-repl`; 도구 `js`, `js_reset`, `turn_ended`; 환경 키 `CUA_REPL_ENABLED_SURFACES`(브라우저+컴퓨터 둘 다 서빙), `SKY_CUA_SERVICE_PATH`, `CODEX_CLI_PATH` 등 |
  그리고 `[plugins."computer-use@openai-bundled"]`(스킬과 에셋만, 서버 없음), `browser@openai-bundled`, `chrome@openai-bundled`, 기능 스위치 `computer_use`, `browser_use_external`.
- **실제 조작을 하는 것**: `~/.codex/computer-use/Codex Computer Use.app` — 번들 id `com.openai.sky.CUAService`, 버전 26.1116.1001980, 화면에 안 보이는 배경 앱(`LSUIElement`), 실행 파일 `SkyComputerUseService`, **alpha 채널 자동 업데이트**(`SUFeedURL`). `ChatGPT.app` 26.1117.41037 이 설치돼 있어야 `cua_node` 가 있다. 앱별 허용 기록은 OpenAI 쪽 `computer-use/sessions/*.toml`.
- **macOS 권한**: OpenAI 공식 문서상 이 앱에 **화면 기록 + 손쉬운 사용** (잠긴 화면 사용을 켜면 인증 플러그인 설치). 앱의 `Info.plist` 에는 연락처·캘린더·Apple Events 문구만 있다. EG-Desk 자신은 지금 **아무 권한도 요청하지 않는다**: 자체 Rust 도우미 `host-observe` 는 앱·창 목록, 앞 앱, 서비스 실행 여부, 권한 상태를 **읽기만**(preflight, 요청 없음) 한다(`helper-rust/src/host/`, 2,247줄).
- **EG-Desk 가 이 길 위에서 하는 것/못 하는 것**: ① 허락 질문(`mcpServer/elicitation/request`, "이 앱을 써도 될까요")은 'computerElicitation' 카드([이번만 허락]/[거절], 자동 수락 없음, 5분 만료)로 사람에게 감 (`codex-chat-runtime.mjs:4660-4715`). ② 클릭·입력 자체는 OpenAI 서비스가 직접 하고 EG-Desk 를 거치지 않는다: EG-Desk 는 사람이 Mac 을 쓰거나 긴급 중지가 눌리면 **턴을 중단시킬 뿐**(이미 보낸 입력은 못 되돌림, "best effort"라고 표시). ③ 활동 목록(`egdesk-host-activity.mjs`)은 앞 앱 변화·서비스 시작/종료·Codex 컴퓨터 호출 횟수를 메타데이터로만 기록.
- **순수 엔진 모드(`EGDESK_OWN_TOOLS_PURE`)에서 사라진다**: 사용자 MCP·플러그인을 스레드 설정으로 끈다(`mcp_servers.<이름>.enabled=false`, `plugins._default.enabled=false`, `features.plugins=false`). 실측(`pure-engine-probe-1/2/2b/3`): 기준선은 사용자 MCP 서버 14개를 알고 그중 8개가 스레드 시작에 뜨며(시작 이벤트 16건), `names` 단계는 **서버 0, 시작 이벤트 0**. 즉 컴퓨터 조작 도구도 없어지고, EG-Desk 는 아직 대신 줄 도구가 없다 → 지금 '순수 + 컴퓨터 조작'은 불가능.
- **EG-Desk 자체 쪽에 이미 있는 부품** (`int/c14`): `egdesk-computer-adapter.mjs`(CU-03: 도구 면 `capture, list_apps, list_windows, click, type_text, key, scroll, drag`, 결과 계약 effect/route/delivery/evidence, 전달 상한 view-only/background/allow-activation, 프레임 revision 재확인, 재시도 없음), `egdesk-host-lease.mjs`(CU-02: 사람/Agent/대기/불가 상태기계, epoch, 동작마다 checkpoint), `egdesk-host-input-gate.mjs`(CU-05: 닫힌 채 시작, 감시 heartbeat 1.5초, 긴급 중지 chord Ctrl+Alt+Shift+.), `egdesk-host-control.mjs`/`-activity.mjs`(HTTP `/host/activity`, `/host/control`, SSE), 런타임의 `egdesk-computer` 도구 제공자 규약(`codex-chat-runtime.mjs:522-`: 도구 이름 `egdesk_computer_<방법>`, 모든 호출이 `refuseComputerCall`을 거침). **없는 것**: 실제 provider(캡처·접근성·입력을 하는 쪽). 브리지의 `toolProviders` 는 browser, plan, annotation(+own tools)뿐이고(`codex-bridge-server.mjs:517`) Rust 도우미에는 캡처·접근성 쓰기·입력이 없다. 어댑터에는 시험용 가짜 provider 만 있다.

## (b) 사용자 Codex 설정 없이 Codex(own tools) 와 Claude Code(MCP) 양쪽에 같은 능력을 주는 방법
**핵심: 도구는 설정이 아니라 EG-Desk 의 도구 카탈로그 한 곳에서 나가고, 두 엔진이 같은 카탈로그를 본다.**
1. EG-Desk 가 `egdesk-computer` 제공자를 하나 등록한다(위 규약). 같은 도구 사양이 **Codex 에는 `thread/start` 의 `dynamicTools`**(스레드 파라미터, `~/.codex` 불필요, 도구 호출은 `item/tool/call` 로 EG-Desk 가 받음)로, **Claude Code 에는 EG-Desk 가 띄운 프로세스 안의 'sdk' MCP 서버 `egdesk`**(`egdesk-claude-mcp.mjs`: `--mcp-config` 에 `{type:'sdk'}` 만 넘기고 호출은 같은 stdin/stdout 파이프로, 별도 포트·토큰·프로세스 없음; `tools/list` 는 Codex 에 주는 것과 같은 카탈로그, `tools/call` 은 Codex 모양의 `item/tool/call` 로 바뀌어 같은 검사를 거침)로 간다. Claude 쪽 승인은 `--permission-prompt-tool stdio` 의 `can_use_tool`(`claude-engine-permissions.mjs`)이 같은 카드로 이어진다.
2. 순수 엔진 모드에서는 Codex 의 기본 컴퓨터 조작을 **끈 채** EG-Desk 도구만 준다: 순수 설정이 플러그인을 통째로 끄므로(`plugins._default.enabled=false`) `cua_repl` 은 이미 사라지고, 사용자의 직접 MCP(`computer-use`, `node_repl`)는 서버별 `enabled=false` 로 꺼진다. Codex 자신의 `computer_use` 스위치를 끄고 스레드를 다시 읽어 확인하는 장치는 별도로 이미 있다(`codex-computer-control.mjs` 의 `off` 와 `COMPUTER_CONTROL_UNVERIFIED`); 순수 설정에 그 스위치가 들어 있는지는 확인하지 못했다(읽은 키 목록에서 `computer_use` 는 "보고 안 됨"). Claude 는 격리 설정(`--settings`, 사용자 MCP 없음)으로 띄우므로 사용자 Claude 설정에도 의존하지 않는다.
3. 고쳐야 할 곳(코드 변경 아님, 위치만): ① provider 한 개와 브리지 등록(`codex-bridge-server.mjs:517` 의 목록), ② Rust 도우미의 캡처·접근성 단계, ③ **Claude 가 컴퓨터 제공자를 못 보게 막아 둔 줄**(`providerSupportsEngine`, `codex-chat-runtime.mjs:1306-1310` 의 제외 목록에 `COMPUTER_PROVIDER_ID` 가 있음)은 실제 provider 와 Claude 쪽 승인 매핑이 준비된 뒤에 푼다. 도구 이름은 `mcp__egdesk__egdesk_computer_type_text`(38자)로 64자 한도 안.
4. **U13 에 맞춘 구성(제안)**: 정의된 선택지는 코드가 만든다 — 열린 앱·창 목록, 접근성 요소 목록(역할·이름), 이전 호출의 프레임 revision. 결정 모델은 "사람의 말이 가리키는 앱·창·요소"와 "제출·삭제·결제 같은 되돌릴 수 없는 동작인가"를 고르고(질문 하나, 후보는 코드), 코드가 어댑터로 실행한다. 엔진은 추론이 필요한 순서 계획과 글만 한다. 브라우저에서 이미 쓰는 규칙("제출·결제·권한·삭제는 사람")을 그대로 쓴다.

## (c) 승인 흐름과 화면 캡처의 개인정보
**어떤 동작이 EG-Desk 승인을 거쳐야 하나 (제안, 기존 부품 기준)**
| 동작 | 분류(`classifyHostTool`) | 승인·검사 |
|---|---|---|
| 앱·창 목록, 선택 창 캡처(읽기) | other | Agent 천장이 `observe` 이상이면 허용. **앱별 첫 사용은 카드** [이번만 허락]/[거절]: 기존 'computerElicitation' 카드를 재사용(새 요소 없음, 자동 수락·'항상 허락' 없음) |
| 클릭·입력·키·스크롤·드래그(다른 앱) | direct | ① Agent 천장 `interact` 필요 ② 허가된 앱 범위 안 ③ **동작마다 lease checkpoint**: 사람이 쓰는 중, 사람이 가져감, 키·버튼 눌림, 중지, 감시 죽음이면 보내지 않고 이유를 활동 목록에 남김 ④ 같은 revision 프레임에서만 좌표 입력 ⑤ 앱별 첫 입력은 카드 |
| 앱 실행·활성화, 클립보드 쓰기, 스크립트 | possible | 균형 정책에서 lease 필요, 앞으로 가져오기(`allow-activation`)는 매번 허락(기본은 뒤에서만) |
| 제출·결제·삭제·권한 부여로 읽히는 GUI 동작 | direct + 위험 | **사람 카드 필수**(결정 모델이 후보 중 고르고, 규칙이 바닥을 깐다: 확률은 실행 권한이 아님) |
| 자동화 금지 | — | 터미널 앱, EG-Desk 자신, ChatGPT/Codex 앱, 관리자 인증, OS 보안 프롬프트, 비밀번호 칸(접근성 secure 필드) — OpenAI 도 같은 항목을 자동화 불가로 둔다 |
| 긴급 중지·감시 | — | chord Ctrl+Alt+Shift+.(입력 모니터링 권한)와 heartbeat 감시. 감시가 죽으면 입력 문이 닫힘(이미 상태기계로 구현, OS 쪽은 미구현) |
**화면 캡처의 개인정보 (제안)**
- **창 하나만** 캡처하고(전체 화면 아님), 허락된 앱의 창만. 가려지지 않은 다른 창·EG-Desk 창·거부 목록 앱은 찍히지 않거나 가린다. 비밀번호 칸·민감 표시 칸은 가림, 가리기에 실패하면 보내지 않는다(브라우저 카드 스크린샷에 대해 대표님이 정한 규칙과 같은 방식: 결정 3 "(나)").
- 픽셀은 **그 엔진 모델(OpenAI 또는 Anthropic)에게만** 간다(도구 결과). 같은 허용 설정을 따른다(U9). **결정 모델에는 픽셀을 주지 않는다**: 기본으로 닫힌 새 송출 종류 `screen_capture` 를 두고(현재 `egdesk-decision-egress.mjs` 에 화면·컴퓨터 종류 없음), 결정 모델은 코드가 만든 접근성 요소의 역할·이름 목록만 본다.
- **EG-Desk 는 픽셀을 저장하지 않는다**: 활동 행·대화 기록·원장에는 앱 이름, 번들 id, 창 id, 크기, 횟수, 해시만(현재 `egdesk-host-activity.mjs` 가 이미 "창 제목·입력 글자·키·좌표 없음"). 캡처 결과는 스트리밍·일회성으로만 엔진에 전달하고, 대화 기록 저장소가 도구 결과를 어떻게 남기는지 확인이 필요하다(미확인).
- 사람에게 보이는 표시(제안, 승인 필요): '지금 Agent 가 화면을 보는 중/조작하는 중' 표시와 중지 버튼. OpenAI 서비스는 자체 표시(`usingComputer`, Esc 취소)가 있다고 설치 파일에 적혀 있으나 실제로 뜨는지는 확인하지 않았다.

## 대표님이 정할 것
1. B 로 간다는 D-C1 을 그대로 유지하고 B1(관찰)부터 시작할지, A 를 임시 provider 로 허용할지.
2. 화면 캡처의 가림 범위와 `screen_capture` 를 결정 모델에게 닫아 두는 기본(제안).
3. 앱별 첫 허락을 기존 허락 카드로 하고, '화면을 보는 중' 표시(새 요소)를 둘지.
4. 입력 검증 보류를 푸는 시점(실제 EG-Desk 화면에서 사용자가 직접 확인).

## 한계 [미확인]
- 오늘은 어떤 컴퓨터 조작도 실행하지 않았다: B 의 캡처·접근성·입력이 실제로 어떻게 동작하는지, 권한 귀속(TCC)과 서명 정체의 영향은 측정하지 않았다.
- cua-driver 의 MCP 인터페이스와 라이선스는 10-24 문서 기준이며 이번에 다시 확인하지 않았다.
- 대화 기록 저장소가 이미지 도구 결과를 어떻게 남기는지, 순수 모드에서 EG-Desk 도구 카탈로그에 컴퓨터 도구가 들어갈 때의 Codex·Claude 호환(도구 수 한도 64 등)은 코드로 확인하지 못했다.
- 사용자 `~/.codex` 구성은 구조만 읽었고(서버·플러그인·기능 이름), 이 구성은 사람마다 다르다.
