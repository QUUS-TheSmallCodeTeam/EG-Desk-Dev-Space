- 브랜치 `lane/u1-browser-tools` (기준 int/c14 `cf086b8`), 작업 사본 `$L/wt-l8-u1`, 커밋 `a6ece20`, `6a50199`(도구 이름 충돌 수정). 작업 사본 깨끗.
- 게이트: `files=498 rc=0`, `# tests 7982 / pass 7943 / fail 0 / skipped 38`. 실제 Codex와 Claude는 실행하지 않았고 Decision도 보내지 않았습니다(모두 대역과 고정 페이지 재생).

## 1. 무엇을 만들었나
플래그 `EGDESK_PAGE_TOOLS=on`(기본 꺼짐) 뒤의 도구 제공자 `egdesk-page`: 대화 엔진이 부르는 거친 도구 네 개. 이름은 **임시**(`egdesk_card_*`; `egdesk_page_*`는 working-memory 고정 도구가 이미 쓰는 이름이라 충돌해서 바꿈).
| 도구 | 하는 일 |
|---|---|
| `egdesk_card_read` | 사람이 허용한 브라우저 카드의 제목, 주소(호스트와 경로), 보이는 줄. `mode: structure`면 컨트롤 목록(ref, role, label)과 각 컨트롤이 `auto`/`approval`/`person` 중 무엇인지 표시 |
| `egdesk_card_press` | ref로 컨트롤 누르기 |
| `egdesk_card_type` | ref로 입력창에 글자 넣기(Enter와 제출은 하지 않음, DOM fill 경로) |
| `egdesk_card_open` | 허용된 카드에서 http(s) 페이지를 새 카드로 열기 |
**기존 장치 위에 얹은 얇은 층**입니다. 모든 동작은 기존 브라우저 제공자의 `dispatch(run, ...)`를 같은 run으로 거치므로 run 바인딩 검증, 카드 허용(observe/interact), 행동 게이트, **AI 서비스 로그인 불투명(BROWSER_CARD_OPAQUE)**, 영수증, 활동 기록(`browser.tool.completed` 이벤트)이 그대로 적용됩니다. 목록, 관찰, 행동 인자(observationId, expectedRevision, expectedTarget, postcondition)는 모듈이 기억하고 채웁니다.

## 2. 자동과 승인의 경계 (코드가 정함: R3, R5; 엔진이 정하지 않음)
- **auto**: 목표 반복 장치가 쓰는 증명(`buildReflexCandidates`)이 통과한 것만: 같은 사이트 링크, 읽기 전용 GET 검색 버튼, 보기 탭, 평범한 글자 입력창. 즉시 실행(기존 규칙 유지: 코드가 읽기 전용 GET, 같은 사이트, 민감 구역 아님을 증명한 경우만).
- **approval**: 그 외 결제, 권한, 로그인, 자격증명이 아닌 것(증명 안 된 버튼, 다른 사이트 링크, 삭제와 제출 계열). **EG-Desk 승인**: 명령, 파일 도구와 같은 승인 장부(`ledger.check`)로 호출이 닫힌 노트와 함께 거절되고(`needs_person`), 사람이 채팅에서 답하면 같은 호출이 한 번 통과합니다. 효과를 증명할 수 없는 누르기는 `expectText`(누른 뒤 페이지에 보일 글)가 있어야 하고 없으면 묻기 전에 `needs_expect_text`. 장부가 없으면(`EGDESK_OWN_TOOLS` 꺼짐) 승인이 필요한 것은 아무것도 하지 않음(`PAGE_APPROVAL_UNAVAILABLE`).
- **person**: 결제, 권한 부여, 로그인, 비밀번호/카드/주민번호/인증번호 칸: 승인이 있어도 도구로는 하지 않고 `person_step`(사람이 페이지에서 직접). 기존 "사람의 단계" 규칙을 넓히지 않음.
- 판단 근거: 기존 분류기의 권장 정책(결제와 권한은 사용자 단계, 삭제와 제출은 확인). **결정 필요(승인 대기, 제안):** 삭제와 제출을 승인으로 둘지(지금) 사람 전용으로 올릴지. 지금은 "그 외는 EG-Desk 승인"이라는 과제 문구대로 승인입니다.

## 3. Claude와 Codex에게 (L5와 맞춤)
- **하나의 목록, 두 엔진**: 도구 카탈로그(`collectToolSpecs`)가 Codex에게는 `dynamicTools`로, Claude에게는 EG-Desk MCP(`mcpToolsFromSpecs`, 서버 `egdesk`)로 같은 스펙을 줍니다. Claude 쪽 이름은 `mcp__egdesk__egdesk_card_*`(64자 이내, 시험함), 허용 규칙 `--allowedTools mcp__egdesk`가 서버 전체를 덮으므로 따로 허용 줄이 필요 없음.
- **L5와의 충돌 없음**: 새 파일 두 개의 레인 모듈(`egdesk-page-tools.mjs`, `egdesk-page-tools-wiring.mjs`), 도구 이름 접두 `egdesk_card_`(명령 `egdesk_run_command`, 파일 `egdesk_read_file` 등과 겹치지 않음: 시험이 확인), 제공자 id `egdesk-page`. 등록은 기존 `toolProviders:` 줄을 건드리지 않고 `chat.registerToolProvider(provider)`(런타임에 새 메서드 하나)로 생성 후에 붙임(`own-tools-wiring` 시험이 그 줄을 고정하고 있어서).
- **카탈로그와 게이트의 핵심**: 페이지 도구는 "그것이 필요로 하는 브라우저 도구"로 정책, 카드 허용, **Agent 천장**을 검사받습니다(read=observe, press=click, type=fill, open=open_card). 일반 대화(정책 없음, 카드 없음)에는 제공하지 않고 호출도 거절. 관찰만 허용한 카드는 read만 제공, 누르기는 게이트에서 거절. 천장이 observe뿐이면 read만 제공.
- **L5가 Claude의 WebFetch와 WebSearch를 끌 때 대체 도구 목록**(카드가 허용된 대화에서):
  - `WebFetch(url)` -> `egdesk_card_open{url}` 후 `egdesk_card_read{mode:'summary'}` (읽기만, 본문은 보이는 줄 60줄, 8,000자까지)
  - `WebSearch(query)` -> `egdesk_card_open{url:'https://<검색 사이트>/?q=<질의>'}` 후 `egdesk_card_read{mode:'structure'}`로 결과 링크 목록, 그리고 `egdesk_card_press{ref}` (같은 사이트 링크는 auto)
  - 입력 폼이 있는 검색: `egdesk_card_type{ref,text}` 후 `egdesk_card_press{ref}`
  - 한계: 카드 허용이 없는 일반 대화에는 대체 도구가 없습니다(정책 null은 카드 권한이 없음). 새 카드를 열려면 허용된 카드가 하나는 있어야 하고 사이트 허용은 기존 카드 UI 흐름. 한국어와 영어 질의는 같은 방식. 제안: WebFetch 대체를 일반 대화에서도 쓰려면 "카드 없이 열기"라는 새 허용 개념이 필요하므로 승인 대기.
  - 번호 붙은 Claude 제한 방식(bounded Claude는 `--tools ''`로 내장 도구가 이미 없음)은 그대로이고, 일반 Claude 대화의 내장 WebFetch/WebSearch를 끄는 건 L5의 몫.
- Codex 쪽: own-tools 경로(`EGDESK_OWN_TOOLS=on`: 웹 검색 비활성, 빈 폴더, 순수 모델 엔진)에서 같은 제공자의 도구가 dynamicTools로 들어갑니다.

## 4. 인증 도메인 불투명 유지 (3번)
기존 서비스 층이 이미 `EGDESK_TERMINAL_OPEN_URL=on`일 때 claude.ai, claude.com, anthropic.com, auth(.openai).com, platform.openai.com, chatgpt.com 카드의 관찰, 클릭, 입력, 이동, 열기를 모두 막고(`BROWSER_CARD_OPAQUE`), send 단계에서 그런 카드는 선택에서 빠집니다. 새 도구는 거기에 **두 번째 방어**를 얹었습니다: 열려는 주소, 누를 링크의 href, 관찰된 주소가 불투명이면 서비스에 보내기 전에 거절(`BROWSER_CARD_OPAQUE`), 카드가 이미 그 페이지를 보이면 내용을 엔진에 주지 않음(서비스의 공개 오류는 검토된 코드 `BROWSER_TOOL_FAILED`로 나가므로 그 코드도 허용). 시험: 링크, 열기(claude.ai, auth.openai.com), 카드 자체가 claude.ai일 때 read, press, type 전부 거절하고 페이지에 어떤 행동도 도달하지 않음.

## 5. 시험 (재생)

## 6. 화면 검증 절차 (Main이 EG-Desk 화면에서)
준비: 브리지를 `EGDESK_PAGE_TOOLS=on EGDESK_TERMINAL_OPEN_URL=on EGDESK_OWN_TOOLS=on`으로 실행(승인 검사를 보려면 own tools도). 일반 사이트(예: 검색창이 있는 쇼핑이나 포털) 카드를 열고 **카드를 이 대화에 허용(interact)**한 새 대화를 시작. 엔진은 Claude로 한 번, Codex로 한 번.
1. "이 페이지 제목 알려줘" -> 활동 기록에 `egdesk_card_read`와 브라우저 관찰(browser.tool.completed)이 남고 답이 카드의 실제 제목과 같은가.
2. "검색창에 우산 입력" -> 카드의 검색창에 글자가 들어가고 **페이지는 이동하지 않음**(제출 안 됨). 활동 기록에 `egdesk_card_type`.
3. "검색해줘" -> 읽기 전용 GET 검색 버튼이면 바로 실행, 아니면 채팅에서 **승인 질문**("press ... on <호스트>")이 나오고 "응"이라고 하면 한 번만 실행.
4. "결제하기 눌러줘"(또는 로그인, 권한 허용) -> 엔진이 `person_step`을 받아 직접 하라고 말하고 카드는 변하지 않음. 비밀번호 칸에 "입력해줘"도 같은 결과.
5. 카드를 claude.ai 로그인 화면으로 이동한 뒤 "이 페이지 읽어줘" -> 읽지 못한다고 하고 내용이 하나도 전달되지 않음. "claude.ai 열어줘"도 거절.
6. 카드 허용 없이 새 대화에서 "이 페이지 제목 알려줘" -> 엔진에 이 도구가 없고(`egdesk_card_*` 없음) 볼 수 없다고 말함. 플래그를 끄면 어떤 대화에도 도구가 없음.
7. 관찰만 허용한 카드에서 "눌러줘" -> 거절.
