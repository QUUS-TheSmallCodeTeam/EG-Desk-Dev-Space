## 3. 알려진 한계(숨기지 않음)
- **화면 자체는 단위, 정적 시험까지**: 실제 Firefox에서 눌러 본 것이 아니고(금지), 화면 전체 전송 경로(수백 줄)는 기존 시험이 없어 모듈 + 정적 고정으로만 보장합니다. 그래서 아래 실창 확인이 필수입니다.
- 한 번 전송이 받아들여지면 Claude 초안 정리(`clearAcceptedClaudeDraft`)가 칩을 지웁니다. Codex도 같은 방식으로 칩을 지우므로(`inputSources: []`) 같은 동작이지만, 다음 턴에 카드를 다시 붙여야 할 수 있습니다(허용 자체는 ⋯ 메뉴의 대화 단위 허용).
- 실시간 전송에서는 파일, 캔버스, 브리핑 자료를 같은 메시지에 못 붙입니다(Reader가 필요하므로 거절). 필요하면 자료는 따로 보내야 합니다(제안: 사람에게 보이는 거절 문장은 기존 것이라 이 경우 "자료를 제외한 뒤 다시 보내세요"가 정확한 안내).
- Claude CLI는 2.1.248 이상이어야 바운드 실행 가능(없으면 기존 런타임이 `QA_POLICY_UNAVAILABLE`로 거절).

## 4. 실창 확인 절차(클릭 순서, Main)
준비: 브리지를 `EGDESK_OWN_TOOLS=on EGDESK_CLAUDE_HARNESS=on EGDESK_PAGE_TOOLS=on EGDESK_TERMINAL_OPEN_URL=on`으로 실행, Claude CLI 2.1.248 이상으로 로그인된 상태.
1. 대화를 만들고 엔진을 **Claude**로(설정의 대화 엔진). 대화 카드를 활성으로 둠.
2. 일반 사이트(검색창이 있는 페이지)의 브라우저 카드를 열어 페이지를 로드.
3. 그 브라우저 카드 툴바 **⋯**(Browser 더보기) -> **"Chat 조작 허용"**. 알림 "이 대화의 조작 대상으로 허용됨"과 대화 카드에 칩 "Browser · 이번 Chat 조작 허용 · 미전송" 확인.
4. 메시지 "이 페이지 제목 알려줘" 전송 -> **전송이 거절되지 않고**(예전에는 "현재 Claude 연결에서는 선택한 자료를 사용할 수 없어…"가 떴음), 활동 기록에 `egdesk_card_read`와 브라우저 관찰, 답이 실제 제목.
5. "검색창에 우산 입력" -> 카드의 입력창에 들어가고 페이지는 이동하지 않음. "검색해줘" -> 읽기 전용 검색이면 바로, 아니면 승인 질문. "결제하기 눌러줘" -> 사람 몫이라는 답.
6. 카드를 claude.ai 로그인 화면으로 옮긴 뒤 "읽어줘" -> 내용이 전달되지 않음.
7. 대조: 같은 방식으로 **플래그를 `EGDESK_PAGE_TOOLS` 없이** 띄우면 4번에서 옛 거절 문장이 그대로 나옴(능력 없음). 파일 칩을 함께 붙이면 능력이 있어도 거절.
8. 대조 2: ⋯ 메뉴에서 "Chat에 읽기 첨부"만 하면 Claude는 이전처럼 불변 캡처를 읽고 도구 조작은 없음.
