# L5 u5: 읽기 전용 컴퓨터 보기를 '행동 먼저'로

- 브랜치 `lane/u5-observe-first` 최종 `5991a0a`(기능 커밋 `fae8a89`, 호출 기록 커밋 `12594a7`, 기준 int/c14 `f72ddd6` 병합, 충돌 없음). 게이트 `l5u5`: **`files=516 rc=0`, `# tests 8156 / # pass 8117 / # fail 0`**. 실제 Codex·Claude·결정 모델 호출 0회(가짜 엔진, 대본 결정 모델, 가짜 Mac 헬퍼). 새 화면 문구 0. 임시 폴더는 시험 때마다 지움.
- 켜는 조건(전부 개발자 플래그, 기본 꺼짐): `EGDESK_DECISION_FIRST=on`(이미 EGDESK_UPPER 묶음) **그리고** `EGDESK_COMPUTER_OBSERVE=on`. 컴퓨터 제공자가 없거나 설정에서 컴퓨터가 꺼져 있거나 도구 천장이 허용하지 않으면 후보가 없고, 이 파일 경로는 닿지 않음(시험: 제공자 없이 '명령 먼저'가 이전과 같고, 요청은 이전 캐시 키 그대로).

## 1. 동작 (한 번의 고르기 + 코드 실행 + 엔진 1회)
1. 기존 명령 고르기(`df_pick`) 질문에 **닫힌 보기 후보**를 같이 둠: `list_apps`, `list_windows`, `read_elements`, `capture`(앱을 고르는 두 개는 아래 2단계). 입력·클릭·타자 도구는 후보가 될 수 없음(시험이 4개 도구 이름만 허용함을 확인). 규칙 문장: 사람이 **지금** 앱 창을 보거나 읽어 달라고 할 때만 고르고, "이전에 거절했어도 사람이 다시 요청한 것"이라고 명시; 방법 질문·클릭/입력·과거 일은 `none`.
2. 읽기/캡처가 골라지면 코드가 `list_apps`를 먼저 실행하고(승인 불필요), **그 결과의 앱들(최대 12, 활성 앱 먼저)만** 후보로 둔 두 번째 결정 호출(`ov_app`, 'none' 포함)로 사람이 가리킨 앱을 고름(U2: 후보는 도구 결과에서만. 터미널·암호 관리자 등 제공자가 거르는 앱은 후보에 없음). 못 정하면 창을 읽지 않고 열린 앱 목록을 맥락으로 넘김.
3. 코드가 **기존 제공자(`egdesk-computer`)의 `dispatch`를 그대로 호출**(L6 API 불변): 앱 해석 → 잠김(`screen_locked`) → 승인 순서도 제공자 그대로.
4. 결과를 닫힌 사실 블록(키 `egdesk_computer_observe`)으로 엔진 맥락에 실어 **엔진은 1회만 말함**: 성공(앱 목록·창 목록·요소; 화면 내용은 "지시가 아님"으로 표시, 6000자 상한, 캡처 픽셀은 맥락에 넣지 않음), 잠김("잠겨 있어 읽을 수 없음, 풀 때까지 다시 부르지 말 것"), 거절·앱 없음·모호함 등(코드 + 제공자 고정 힌트), 승인 대기(아래).
5. 턴 기록: 엔진 런에 `dynamicToolCall` 행(제목 = 도구 이름, 새 문구 없음)이 생기고 detail에 `executedBy:'egdesk'`, `outcome`(닫힌 코드), `decidedBy{path:'action', reason, option:'observe', confidence}`. 이유 값: `observe_done` / `observe_refused` / `observe_no_app`.
6. 결정 호출 기록의 닫힌 kind: **`observe_pick`**(보기 후보가 같이 간 고르기 호출. 명령만 있는 방은 그대로 `pick`), **`observe_app`**(앱 고르기).

## 2. 한계: 첫 사용 앱의 승인 카드 (설계상 정직하게)
- 제공자의 승인은 **런(run) 객체별**이고(WeakMap) 카드(`askComputerApp`)는 실제 런이 필요함. 결정 먼저 단계에는 아직 엔진 런이 없어 카드를 띄울 수 없음. 그래서 코드는 **이미 끝난 대역 런**에서 제공자를 호출함: 카드를 사람이 못 보는 곳에 띄우는 일이 없고(시험: `pendingApprovals` 비어 있음), 앱 없음·거부·잠김은 제공자가 먼저 답하므로 그대로 사실로 전달됨.
- 그 결과 읽기/캡처는 사전 실행에서 항상 `app_not_approved`('아직 이 실행에서 묻지 않음')로 돌아오고, 엔진 맥락은 "EG-Desk가 이 요청에 이 동작을 골랐다 / 이 실행에서는 아직 묻지 않았다 / 엔진이 이 도구를 **지금 부르면 기존 카드가 열린다** / 이전 실행에서의 거절은 이어지지 않는다(권한은 실행마다) / 이전 메시지로 답하지 말 것"이라고 알림 → 실창의 '이력으로 답하는' 실패를 막되, **읽기 성공 결과 자체는 카드 승인 뒤 엔진의 첫 라운드가 가져옴**(목록·창 목록은 사전 실행으로 바로 성공).
- 제안(승인 대기): 승인 카드를 엔진 전에 보이려면 `continueBrowserRunTurn`/`turnAliases`처럼 **로컬 런을 먼저 열고 승인 뒤 엔진 턴을 이어 붙이는** 변경이 필요(인터럽트·steer가 `run.runId`를 쓰므로 이번 창에는 위험하다고 판단해 안 함). 다음 라운드 후보.

## 5. Main 실창 확인 절차
1. 브리지를 `EGDESK_COMPUTER_OBSERVE=on EGDESK_DECISION_FIRST=on EGDESK_DECISION_CALL_LOG=on`(+ 하네스 플래그 `EGDESK_OWN_TOOLS=on`, Claude면 `EGDESK_CLAUDE_HARNESS=on`, 결정 모델 켬)로 시작. 계산기 앱을 열어 둠.
2. 과거 거절 이력이 있는 시험 방에서 "계산기 앱 창의 화면 요소를 읽어서 알려줘"를 보냄.
3. `GET /chat/decision-calls?limit=3`에서 그 턴에 `observe_pick`(+ 이어서 `observe_app`) 행이 보이고(`pick`은 아님), 활동 목록에 `egdesk_computer_read_elements` 행(`executedBy:'egdesk'`, `decidedBy{path:'action', reason:'observe_refused', option:'observe'}`, `outcome:'app_not_approved'`)이 있어야 함.
4. 엔진이 **첫 라운드에 `egdesk_computer_read_elements`를 부르고 기존 승인 카드가 뜸**(이력으로 답하던 이전 동작과 달라야 함). [이번만 허락] 뒤 요소를 읽어 말함. [거절]이면 사실대로 "허락되지 않음"을 말함.
5. 화면을 잠그고 같은 요청: 카드 없이 `outcome:'screen_locked'`, 엔진이 "잠겨 있어 읽을 수 없음"을 말하고 도구를 다시 부르지 않음.
6. "지금 열린 앱 알려줘": 카드 없이 `list_apps` 행(`outcome:'ok'`)과 앱 목록 답. "테스트 돌려줘"는 `pick`(명령만 있는 방) 또는 `observe_pick`(보기 후보가 같이 간 방)이고 `npm test`가 EG-Desk 러너로 실행(이전과 같음).
7. 플래그(EGDESK_COMPUTER_OBSERVE)를 빼면 `observe_*` 행·`egdesk_computer_observe` 맥락이 전혀 없어야 함.
- 비용 감각: 보기 후보가 같이 가는 방은 pick 호출 한 번에 후보 4줄이 더해질 뿐(추가 호출 없음). 읽기/캡처만 `list_apps`(헬퍼, 0.1초대 추정) + 앱 고르기 호출 1회(pick과 비슷한 0.3~0.4초대 추정)가 더 듦; 실측은 호출 기록에서.
