## 1. 자료와 방법
- 자료: 브리지 저장소 `chat-*.sqlite`(WAL 포함 **복사본**을 `$L/evidence/l5-u3/copy`에서 읽기 전용으로 열었음, 원본·프로필 무수정), 결정 모델 보정 기록 `egdesk-decision-calibration.json`, 월 예산 기록 `egdesk-decision-budget.json`. 추출 스크립트 `$L/evidence/l5-u3/{extract,classify,stages,report}.mjs`, 중간 자료 `turns.json`/`stages.json`.
- 단계 정의(이벤트 시각 기준, 보낸 시각 = `message.accepted`): ① **결정 모델 맥락** = 보낸 시각 → `run.dispatching`(맥락 활동의 `latencyMs`와 ±15ms로 일치함: 이 단계는 맥락 호출 한 번); ② **디스패치 → 엔진 시작** = `run.dispatching` → `run.started`(스레드 묶기·엔진 프로세스 준비 + 프로젝트 방에서는 명령 먼저의 고르기 호출과 EG-Desk 명령 실행이 여기에 들어감; 저장된 이벤트로는 이 안을 더 나눌 수 없음); ③ **엔진 라운드** = `run.started` → 첫 글자(`message.started`) 중 EG-Desk 도구 시간을 뺀 나머지(모델 호출과 도구 사이 대기); ④ **EG-Desk 도구** = 도구 행의 시작→완료(사람 승인 대기는 따로 표시); ⑤ **첫 글자 → 게시** = `message.started` → `message.completed`. 총 = 보낸 시각 → 게시(`message.completed`). 게시 후 `run.completed`까지는 0.01~0.03s(예외는 비고).
- '엔진 첫 출력'은 첫 글자가 아니라 첫 도구 호출일 수 있음(도구 턴). u2(ToolSearch 끔)는 03:24 이후부터 보이므로 '전/후'를 표시.

## 4. 결정 모델 호출 수와 입력 토큰
- **측정된 것(턴마다 저장된 맥락 영수증)**: 맥락 설정 호출 **1회/턴**(모델 `gpt-6-luna`), 질문 110개, 후보 108개, 입력 토큰 **19,533~20,280**(캐시 읽기 0 또는 2,938~3,057 = 최대 15%), 지연 0.40~1.07s. 14개 턴의 합 입력 **302,412 토큰**(캐시 30,185). 03:07 턴은 맥락 단계가 응답하지 않아 fallback(1.52s 기다림, 토큰 기록 없음).
- **저장되지 않은 것(추정)**: 프로젝트 방의 턴에는 명령 먼저의 **고르기 호출 1회**가 더 있다고 추정(근거: 디스패치→엔진 시작이 프로젝트 방 12턴 중앙값 0.67s(0.59~1.03s) vs 프로젝트 없는 방 3턴 0.31s(0.19~0.41s); 프로젝트가 없으면 명령 먼저가 아예 돌지 않음). 승인 빠른 경로 턴은 답 읽기 호출이 더(②가 0.97s로 평소보다 +0.3s). 열린 항목·눈치 호출 흔적은 이 구간 이벤트에 없음. 이 호출들의 입력 토큰은 **턴별로 저장되지 않음**. 월 예산 기록은 합계뿐: 이달 metered 입력 **313,308**(추정분 8,919, 미계측 1건); 이 DB의 맥락 호출 합(302,412)이 그중 약 96%로, 맥락 호출 외 모든 결정 호출의 입력 토큰은 많아야 약 1만 토큰대(11-25 시험 분이 섞였을 수 있어 상한 추정).
- 도구 쪽 판단(편집·되돌리기·명령)은 모델 호출이 없음(규칙 바닥): 해당 턴의 맥락 호출 1회가 전부.

## 5. 관찰 (사실과 추정 구분)
1. **엔진 라운드가 지배**(사실): 도구가 있는 턴은 모델 라운드를 2번 이상 돌며 라운드당 약 2~5s(ToolSearch 뒤 다음 도구까지 2.0~5.6s, 7건). 결정 모델 단계는 합쳐도 총의 3~26%.
2. **u2 효과**(부분 사실): u2 전 7턴에서 ToolSearch 왕복이 있었고 그 뒤 다음 도구 호출까지 **2.0~5.6s(중앙값 2.3s)**가 추가 라운드. u2 후 표본은 03:24 컴퓨터 조작 1건뿐이고 첫 도구까지 시작 후 2.4s(ToolSearch 없음; 전엔 5.2s에서 ToolSearch). **편집·되돌리기·명령의 u2 후 턴은 이 구간에 없음**(→ 추정 절감 약 2~5s/턴, 확인은 새 표본 필요).
3. **명령 먼저**(사실): "테스트 돌려줘"는 8.18s(엔진 라운드 1번, 도구 호출 없음). 이 구간에는 같은 요청의 엔진 경로(명령 먼저 끔) 표본이 **없어** 직접 비교는 못 함; 가장 가까운 엔진 경로 참고는 다른 요청(git 되돌리기 요청, 도구 호출 2회+ToolSearch) 19.9s. 명령 자체 0.2s로 실행 시간은 문제 아님.
4. **프로젝트 방의 고정 비용**(추정): 매 턴 ②에 +0.3~0.4s(고르기 호출). 고르기 결과가 'none'이어도 치름.
5. **프롬프트 캐시**(사실): 맥락 호출 20K 토큰 중 캐시는 0~15%. 질문 110개 틀이 거의 매 턴 그대로인데 대부분 새로 읽힘(캐시 안정화 여지는 결정 모델 쪽 확인 필요).
6. **이상치**: 03:07 맥락 fallback(+1.5s), 03:22 컴퓨터 턴은 게시 후 `run.completed`까지 9.7s, 02:54 컴퓨터 조작 도구는 사람 승인 대기 약 50s(비교에서 제외 표시).
7. 이 구간에서 가장 짧은 턴은 5.3s(짧게 정정, 도구 없음): 시작→첫 글자만 4.2s. '탁탁'의 병목은 결정 모델 단계가 아니라 Claude 라운드 수와 라운드당 지연.
