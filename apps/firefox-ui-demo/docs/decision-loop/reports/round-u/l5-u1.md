## 1. 무엇이 되나 (하네스 켠 Claude 대화)
1. **EG-Desk 도구**: 명령 실행(`egdesk_run_command`), 파일 읽기·검색·편집 미리보기·적용(undo 기록)·삭제/전체 덮어쓰기(`egdesk_*`, 도구 이름 임시)가 어댑터의 MCP 서버로 Claude에 `mcp__egdesk__egdesk_*`로 보임. 승인·정책은 **Codex와 같은 EG-Desk 경로**(규칙 바닥 → 예/아니오 술어 → 대화·턴·정확한 명령 1회 승인; 승인 대기 중 `needs_person` 결과를 Claude가 읽고 사람에게 물음). 새로 만든 정책 코드는 없음.
2. **Claude Code 기본 도구 끄기**(`--disallowedTools`, 바이너리 무수정): `Bash, Edit, Write, MultiEdit, NotebookEdit`(지시 목록) + 판단으로 추가: `Monitor, Workflow, EnterWorktree, ExitWorktree`(다른 문으로 명령·파일·git 변경), `SendMessage, SendToProject, PushNotification, RemoteTrigger, CronCreate, CronDelete, CronList, ScheduleWakeup`(대화 밖으로 새거나 무인 실행) + **내장 computer-use MCP 서버**(`mcp__computer-use`, `mcp__computer_use` 규칙). 남김: `Read, Grep, Glob, ListAgents, ToolSearch, TaskStop, 계획 모드 도구, ReportFindings, DesignSync`(읽기이거나 이 대화만 조종). WebFetch/WebSearch는 기본 유지, EG-Desk 브라우저 도구가 켜지면 끔. 컴퓨터 조작은 L6의 `egdesk_computer_*`만. computer-use 근거: CLI는 항상 `--strict-mcp-config`와 EG-Desk의 'sdk' 서버 하나만 로드하고(설정은 `{disableAllHooks:true}`뿐) 내장 서버는 설정에 없음 + 규칙으로 한 번 더 막음: 시험이 argv와 settings를 직접 읽어 검사(`egdesk-claude-harness.test.mjs`).
3. **엔진 폴더**: 하네스 대화의 Claude는 EG-Desk의 빈 엔진 폴더(`engine-folders`)에서 돌고 실제 폴더는 EG-Desk 도구만 앎. 프로젝트를 안 고르면 도구는 `no_folder`(개발 사본을 건드리지 않음; Main 01:25 관찰 (2) 해결). 같은 대화에서 같은 폴더로 이어 보내기는 통과, 다른 폴더는 거부(기존 규칙 유지). **플래그 끈 Claude는 예전 그대로 브리지 cwd에서 돎(제안 §7).**

## 3. 활동 기록(run events) 근거
- EG-Desk 도구 호출 행(`dynamicToolCall`)의 detail에 `executedBy: 'egdesk'`(닫힌 단어, 새 문구 아님).
- 명령 먼저로 EG-Desk가 미리 실행한 명령 카드(`commandExecution`) detail에 `executedBy: 'egdesk'`와 `decidedBy {path, reason, option, confidence}`(결정 모델 판단 흔적). **승인 빠른 경로로 실행된 명령도 이제 카드와 같은 흔적을 남김**(`reason: approval_ran, option: approved`; 예전엔 카드 없음, Codex도 동일하게 보강됨).

## 6. Main 화면 검증 절차 (사용자 입장)
준비: 브리지를 `EGDESK_OWN_TOOLS=on EGDESK_CLAUDE_HARNESS=on EGDESK_DECISION_FIRST=on EGDESK_DECISION_FIRST_APPROVALS=on EGDESK_OPEN_ITEMS=on`(+결정 모델 키, 필요하면 `EGDESK_DRAFT_CHECK=advisory`)로 시작, Claude 로그인 상태(API 키 로그인 권장), 프로젝트 폴더를 고르고 **새 Claude 대화** 시작.
1. "지금 쓸 수 있는 도구 이름을 전부 말해줘" → `mcp__egdesk__egdesk_run_command/read_file/search_files/edit_file/undo_edit`와 맥락 읽기 2개가 보이고, **Bash·Edit·Write·MultiEdit·NotebookEdit·Monitor·Workflow·SendMessage·Cron*·RemoteTrigger·PushNotification·EnterWorktree 및 computer-use가 없어야 함**(Read·Grep·WebSearch는 보일 수 있음).
2. "테스트 돌려줘" → 명령 먼저: 답 전에 터미널 카드가 뜨고 Claude 답은 결과를 말함. 런 활동 detail에 `executedBy: egdesk`, `decidedBy`가 있어야 함.
3. "<프로젝트 안 파일>의 문구를 고쳐줘" → 편집이 EG-Desk 도구 행(`egdesk_edit_file`)으로 보이고 diff와 undo 기록이 있어야 함; "방금 편집 되돌려줘"로 undo.
4. "마지막 커밋 되돌려줘"(`git reset --hard`) → Claude가 사람에게 물어보고 **아무것도 실행 안 됨**; "응 실행해" → 한 번 실행되고 카드가 남음.
5. 프로젝트를 고르지 않고 새 대화에서 "파일 목록 보여줘" → 도구가 폴더 없음으로 답하고 개발 사본이 보이지 않아야 함(01:25 기준선과 비교).
6. 대조: 같은 대화를 플래그 없이 → 예전 기준선(Claude 자체 도구 전부)이 그대로여야 함.

## 7. 정책 유지 조건(§4.1)과 남은 것
- 정책 조건: Claude Code **바이너리 무수정**(플래그·MCP·settings만) 유지, **사용자 본인 로그인** 유지, EG-Desk가 `~/.claude` 자격 증명을 읽거나 저장·중계하지 않음 유지, 이름·로고 새로 쓴 것 없음. **하나 걸리는 점**: `PRIVATE=on`의 비공개 턴은 실제 Claude 턴(사용량)을 더 쓰고 CLI가 자기 세션 파일을 남김(CLI 몫이지만 알림). 기본 꺼짐.
- 제안(승인 대기): ① 프로젝트를 안 고른 **하네스 꺼진** Claude 대화도 빈 폴더에서 시작(지금은 브리지 cwd). ② Main 관찰 (3)의 문구 결함(대화 카드 제목·Agent 이름이 엔진과 무관하게 'Codex 1', 'AI 설정'의 '기록 없이 시작' 설명이 Claude에서도 '코덱스에 기록을 남기지 않는') — 새 문구는 만들지 않음, 엔진별 문구 필요. ③ 하네스 켠 Claude에 내장 Read/Grep/Glob도 끄고 EG-Desk 읽기 도구만(지금은 남김). ④ 끄는 도구 이름은 이 CLI 2.1.x 기준(없는 이름은 무해): Main이 화면에서 본 목록과 대조 필요.
- 남음: 실제 Claude에서 도구 이름 `mcp__egdesk__*`가 모델에게 어떻게 보이고 호출되는지(재생은 모양만 검증), `--disallowedTools` 규칙이 이 CLI에서 `mcp__computer-use`를 실제로 막는지는 화면 검증 몫.
