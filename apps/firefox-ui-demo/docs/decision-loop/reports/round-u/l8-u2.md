# L8 u2 (D7): "카드를 이 대화에 허용(interact)"의 사용자 화면 경로

- 브랜치 `lane/u2-browser-grant` (기준 int/c14 `be45c77`), 작업 사본 `$L/wt-l8-u2`, 커밋 `ad83a05`. 작업 사본 깨끗.
- 게이트: `files=509 rc=0`, `# tests 8080 / pass 8041 / fail 0 / skipped 38`. 실제 Codex와 Claude는 실행하지 않았고, 화면은 코드를 읽어서 확인(정적 시험으로 고정)했습니다.

## 1. 답: 경로는 있다. 첨부 창이 아니라 "브라우저 카드 자신의 ⋯ 메뉴"
`browserToolPermission`을 `interact`로 바꾸는 사용자 경로는 코드에 **하나**(+에이전트가 연 카드의 자동 승계) 있습니다. L1도 같은 결론(둘뿐: ⋯ 메뉴와 첨부 패널의 읽기 첨부).
**조작 허용(interact) 클릭 순서** (`overlay/JS/eg-desk-surface.uc.js`: `showBrowserMenu` ~27800, `selectBrowserForChat` ~27765, `registerBrowserToolSelection` ~24348):
1. 허용하려는 **대화(채팅 카드)를 열어 활성**으로 둠(`state.codex.activeThreadId`가 있어야 함; 없으면 아무 일도 안 함).
2. 그 대화에 쓸 **브라우저 카드**에서 페이지를 **로드**한 상태로(빈 페이지면 `chatInputSourceForView`가 null).
3. 브라우저 카드 툴바의 **⋯**(`data-testid="browser-menu"`, 메뉴 이름 `Browser 더보기`)를 클릭.
4. 메뉴에서 **"Chat 조작 허용"**(이미 한 번 허용했다 돌려받은 뒤라면 "다시 조작 허용") 클릭. 설명: "이 Browser를 이 대화의 관찰·조작 대상으로 허용합니다…".
5. 결과: 알림 **"이 대화의 조작 대상으로 허용됨"**, 대화 카드에 칩 **"Browser · 이번 Chat 조작 허용 · 미전송"**이 붙음. 카드, 계정, 컨테이너, 주소가 달라졌으면 `Browser 조작 대상을 확인하지 못했습니다. 현재 페이지에서 다시 선택해 주세요.`
6. 메시지를 전송하면 그 카드가 `interact` 선택 자료로 Codex run에 묶입니다(`executionPolicy: browserBounded`).
- **허용은 그 대화 동안 이어짐**(BRW-11: 턴마다 새 일회용 토큰을 사람에게 다시 묻지 않고 발급). 끝내는 법: 같은 ⋯ 메뉴의 **"조작 허용 해제"**(허용이 있을 때만 보임), 또는 카드의 주소, 계정, 컨테이너가 바뀜, 또는 Browser UI 스트림이 리셋되면 읽기 전용으로 내려감.
- **읽기 전용**: 같은 메뉴의 **"Chat에 읽기 첨부"**, 또는 대화 카드의 **"+ 첨부"**에서 브라우저 카드를 체크(칩 "Browser · 미전송"). 이미 조작 허용이 있는 카드에 하면 읽기 전용으로 바뀝니다.
- **왜 Main이 못 찾았나**: 첨부 창은 `registerBrowserToolSelection(..., 'observe')`만 호출하고 "이번 Chat 조작 허용 중"은 **이미 허용된 카드에 표시만** 합니다(켜는 버튼 없음). 조작 허용은 ⋯ 메뉴에만 있고, 첨부 후 칩("Browser · 미전송")에는 그쪽으로 가라는 단서가 없습니다.
- 정적 시험(`helper/egdesk-browser-grant-path.test.mjs`)이 위 문구, 메뉴 순서(읽기 첨부, 조작 허용, 해제), 첨부 창은 observe만, `registerBrowserToolSelection`의 호출 지점이 정확히 셋(첨부 창 observe, 에이전트가 연 카드 interact, 메뉴의 permission)임을 화면 코드에 대해 고정합니다. 화면이 바뀌면 이 시험이 알려 줍니다.

## 2. 중요한 정정: Claude 대화에서는 이 화면으로 조작을 줄 수 없다 (u1 보고서와 검증 절차 수정)
u1 보고서의 화면 검증 절차는 "엔진은 Claude로 한 번, Codex로 한 번"이라고 했으나 **Claude는 이 화면에서 막혀 있습니다**:
- 전송 시 Claude 스레드에 `interact`인 브라우저 자료가 붙어 있으면 **전송이 거절**됨: `현재 Claude 연결에서는 선택한 자료를 사용할 수 없어 보내지 않았습니다. 자료를 제외한 뒤 다시 보내세요.`(`eg-desk-surface.uc.js` ~19434, `ChatState.claudeContextSendErrorText('CLAUDE_CONTEXT_UNSUPPORTED')`).
- 또 `const selectedBrowserSources = engineId === 'claude' ? [] : browserToolSelectedSources(...)`(~19623): Claude에는 **살아 있는 브라우저 자료를 아예 넘기지 않음**(Claude는 불변 캡처만 읽음, "Claude B2").
- 런타임 쪽(Claude의 browserBounded 실행, EG-Desk MCP 도구, `egdesk-claude-bounded.mjs`)은 있지만 **화면 쪽 절반이 켜져 있지 않습니다**. 그래서 u1의 `egdesk_card_*`는 Claude 화면 대화에서는 쓸 수 없고(런타임/MCP 카탈로그와 단위 시험으로만 검증), 화면 검증은 **Codex 대화로만** 가능합니다.
- **Claude를 켜는 데 필요한 것(구현하지 않음: 화면 경로를 실창 없이 맹목으로 바꾸면 위험)**: (a) 위 두 화면 게이트를 능력(capability) 뒤에서 풀기, (b) 조작 허용 카드의 불변 캡처(`captureThreadInputs`)가 Claude의 `inputReferences`와 Reader 능력(`claudeContextCapabilities`)으로 들어가는데 bounded Claude는 Reader와 같이 실행되지 않으므로(`egdesk-claude-bounded.mjs`: managed MCP, 상속 설정, Reader 금지) 그 카드는 캡처에서 빼야 함, (c) Claude CLI 2.1.248 이상과 init 검증. 이것은 제품 결정(Claude B2의 "불변 캡처만" 설계를 바꾸는 것)이라 승인 대기.

## 3. 구현한 것 (L8 영역: 권한 정책과 도구)
- `helper/egdesk-browser-grant-path.mjs`: 허용 경로를 **데이터**로(문구는 화면의 것 그대로, 새 문구 없음), `grantHint(code)`.
- 페이지 도구가 허용이 모자랄 때 엔진에게 **닫힌 힌트**를 줌: 카드가 observe만 허용(`PAGE_NO_INTERACT_GRANT`)이면 `grant: { needs: 'person_grant', how: 'browser_card_menu', item: 'Chat 조작 허용' }`, 카드가 하나도 없으면(`PAGE_NO_CARD`) `how: 'attach_browser_card'`. 엔진이 그 말을 사람에게 풀어서 안내(승인 카드를 새로 만들지 않고 기존 메뉴 항목 이름을 재사용). 도구 스펙 설명(press, type, open)도 "사람이 Browser 카드 메뉴에서 'Chat 조작 허용'으로 허용한 카드"라고 적음.
- **하지 않은 것**: 화면 코드 변경 없음(경로가 이미 있고, Claude 쪽 변경은 맹목이라 위험). 첨부 창 표시 쪽은 L1 영역이라 건드리지 않음.

## 4. 제안 (승인 대기, 새 문구)
- **발견성**: 첨부 창의 브라우저 행(L1 영역, ~1960-1971행)에 한 줄 안내: `조작까지 허용하려면 Browser 카드의 ⋯ 메뉴에서 "Chat 조작 허용"을 선택하세요.`(새 문구, 승인 필요). 또는 첨부 칩 "Browser · 미전송"의 툴팁. 가장 작은 변경이고 새 기능이 아님.
- **더 큰 안**: 첨부 창에서 직접 허용 토글. L1이 그 패널에만 붙일 수 있다고 함: 필요한 동작은 `registerBrowserToolSelection(threadId, source, 'interact')`를 부른 뒤 기존 칩을 `removeInputSource`/`addInputSources`로 교체하고 `endAgentHold()`와 `showAgentActivity('이 대화의 조작 대상으로 허용됨')`(⋯ 메뉴의 `selectBrowserForChat`와 같은 순서). 라벨은 기존 문자열 '이번 Chat 조작 허용'을 체크박스 이름으로 재사용 가능. 단 이것도 사용자 동선 변경이라 승인 대기이고 Claude 문제는 해결하지 않음.

## 5. 실창 검증 절차 (Main, Codex 대화로; u1의 6번 절차를 이것으로 대체)
준비: 브리지 `EGDESK_PAGE_TOOLS=on EGDESK_TERMINAL_OPEN_URL=on EGDESK_OWN_TOOLS=on`(승인까지 보려면), 대화 엔진은 **Codex**.
1. 위 1절의 1~5(⋯ -> Chat 조작 허용, 칩에 "이번 Chat 조작 허용" 확인).
2. "이 페이지 제목 알려줘" 전송 -> `egdesk_card_read` 호출, 활동 기록에 브라우저 관찰이 남고 답이 실제 제목.
3. "검색창에 우산 입력" -> 카드 입력창에 들어가고 페이지는 이동하지 않음. 이어서 "검색해줘" -> 읽기 전용 GET 검색이면 바로, 아니면 승인 질문.
4. "결제하기 눌러줘" -> `person_step`. 카드를 claude.ai 로그인으로 옮기고 "읽어줘" -> 아무 내용도 전달되지 않음.
5. 단서 확인: 브라우저 카드를 "+ 첨부"로 읽기 첨부만 한 새 대화에서 "검색창에 입력해줘" -> 도구 거절과 함께 엔진이 "카드 ⋯ 메뉴의 Chat 조작 허용"을 안내하는지(힌트의 `grant.item`).
6. "조작 허용 해제" 후 같은 요청 -> 거절.
7. (확인용) Claude 대화에서 허용 후 전송 -> 위 2절의 거절 문구가 나오는 것이 정상.
