# L6 u2: 컴퓨터 도구 첫 사용 승인 카드를 화면에서 '이번만 허용'할 수 없던 문제 (D2) 수정

브랜치 `lane/u2-computer-approval` (기준 int/c14 `be45c77`), 커밋 `c0d6ae3`. 게이트 결과는 맨 아래.

## 1. 증상 (Main 실창 검증, 2026-11-26 02:5x)
Claude 대화에서 "계산기 앱 창에 보이는 화면 요소를 읽어서 알려줘" → 승인 카드가 떴지만 "승인 필요 … 승인 범위: 이번 요청 — 요청 범위를 확인하지 못해 허용할 수 없습니다. 거절하거나 취소할 수 있습니다."이고 [이번만 허용]이 비활성. 허용할 방법이 없었다.

## 2. 원인 [측정]
**Claude 경로(in-process MCP)의 문제가 아니라 화면 쪽 상태 함수의 문제였다. Codex 경로도 똑같다.**
- 카드는 정상으로 만들어졌다(`approval.required` 세부: `kind:'computerElicitation'`, `scope:'request'`, `choices:['accept','decline']`, `appName`, `message`, `fields:[]`). 화면에 "승인 범위: 이번 요청" 줄이 나온 것이 `scope:'request'` 가 실려 왔다는 증거다(`eg-desk-surface.uc.js:5082`).
- 비활성의 직접 원인: `overlay/resources/EGDeskChatState.sys.mjs` 의 `approvalScopeKnown(approval)` 이 `kind` 가 `commandExecution` 또는 `fileChange` 가 아니면 무조건 `false`(원래 줄 1459-1460). `approvalRequestFor(run, id, 'accept')` 는 이것이 false 면 `null` 을 돌려주고(1455), 화면 버튼은 `disabled: approvalRequestFor(...) ? null : 'true'`(`eg-desk-surface.uc.js:5097`), 문구는 `!approvalScopeKnown` 일 때 붙는다(5087). 즉 `computerElicitation` 은 어떤 경우에도 허용 버튼이 꺼졌다.
- 왜 지금까지 안 드러났나: 10-24 인계 문서(`handoff-2-R.md`)는 이 카드를 '화면 연결 작업자(S8·S9)'에게 맡겼고 helper 쪽(런타임) 시험만 있었다. 화면 쪽에는 `computerElicitation` 처리가 한 줄도 없었다(grep: overlay 에서 0건). 기존 Codex Computer Use(cua_repl)의 허락 질문도 같은 이유로 화면에서 허용이 안 됐을 것이다(미측정: 실제 Codex 는 쓰지 않음, 재생으로만 확인).
- 두 번째 결함(재생 중 발견): 사람이 이 카드를 답한 뒤에도 카드가 `pendingApprovals` 에 남는다. 엔진 쪽 질문이면 엔진이 '해결됨' 알림을 보내 지우지만(`codex-chat-runtime.mjs:4416-4420`), EG-Desk 자체 카드에는 기다리는 엔진 요청이 없어 그 알림이 없다. 그대로면 '응답 전달됨 · 실행 상태 확인 중'이 계속 남는다.
- 세 번째(방어): `askComputerApp` 이 타이머를 만들다 예외가 나면 카드만 남고 약속이 끝나지 않을 수 있어, 타이머를 먼저 만들도록 순서를 바꿨다.

## 3. 수정
1. `EGDeskChatState.sys.mjs`: `approvalScopeKnown` 에 `computerElicitation` 분기(`computerCardScopeKnown`). 허용 조건: `scope === 'request'`(이번 요청 하나만. 세션·영구 선택은 helper 가 처음부터 안 낸다), `acceptDisabledReason` 없음, `fields` 가 배열이고 16개 이하, 모든 필드가 '화면이 답을 안 보내도 helper 가 그대로 보낼 수 있는 상태'(boolean 은 값이 있음, 필수 enum 은 목록 안에서 미리 고른 선택이 있음, 선택 사항 enum 은 비어도 됨). 그 외(알 수 없는 필드 종류, 미리 고른 답 없는 필수 선택, 세션 범위 등)는 지금처럼 거절만 가능. 이 화면은 `answers` 를 보내지 않으므로, helper 가 `INVALID_ELICITATION_ANSWER` 로 거절할 카드를 미리 막는 것이다. 새 화면 문구 없음(기존 '이번만 허용', '거절', '승인 범위: 이번 요청' 그대로).
2. `codex-chat-runtime.mjs`: 앱 확인 카드(`resolve` 가 있는 것)를 사람이 답하면 `answerComputerCard` 가 카드를 닫는다: `pendingApprovals` 에서 제거, 타이머 해제, run 의 목록에서 제거, SSE `approval.resolved { approvalId, outcome }` 방출. 만료·run 종료는 기존 호출자가 그대로 처리.
3. `askComputerApp`: 타이머 생성 순서만 변경.

## 4. 재생 시험 [측정]
`scripts/egdesk-surface-claude.test.mjs` 에 `U2:` 시험 2개, `helper/egdesk-computer-observe.test.mjs` 에 Codex 경로 확인 보강. 재생은 실제 구성품을 쓴다: Claude 어댑터의 MCP 제어 핸들러(`mcp_message` → `tools/call`), 실제 `CodexChatRuntime`, 실제 `ChatState` 리듀서, 운영 화면 코드(`surface()` 가 `eg-desk-surface.uc.js` 를 실행). 가짜는 Claude 프로세스(전송 계층), 호스트 도우미(권한 있는 척 `readElements` 결과)뿐이다.
- 수정 전에 같은 재생이 **실패**했다: `approvalRequestFor(run, id, 'accept')` 가 `null`(= Main 이 본 증상).
- 수정 후 흐름: `egdesk_computer_read_elements {app:'Calculator'}` → 카드 1장(`kind computerElicitation, scope request, appName Calculator`), 읽기는 아직 호출 0회 → 화면 렌더에 '승인 범위: 이번 요청'이 있고 '요청 범위를 확인하지 못해' 없음, 버튼 `[이번만 허용 활성, 거절 활성]` → 화면의 요청(`approvalRequestFor('accept')`)을 `/chat/approval` 로 보냄 → 도우미 `readElements:11:701` 실행 → Claude 에 결과(`AXButton` 포함, `isError` 아님) → 같은 앱 두 번째 호출은 카드 없음 → 같은 앱 `capture` 는 허락이 유지된 채 화면 기록 권한 없음이 닫힌 거절 `permission_missing` 으로 돌아옴(캡처는 이 경로가 정상인지만 보면 된다는 지시와 일치).
- 거절: 카드 [거절] → 도구는 `app_not_approved`, 도우미 호출 0회, 화면 상태에 카드 없음.
- 필수 선택이 비어 있거나 알 수 없는 필드, 세션 범위, 비활성 사유가 있는 카드는 허용 불가로 남음(단위 판정 11건 중 거절 7건).
- Codex 경로: 같은 카드를 `item/tool/call` 로 받아 화면 상태 함수가 허용하고, 답하면 `approval.resolved` 로 카드가 닫히며 이미지 결과가 돌아옴(helper 시험). 진짜 Codex·Claude 프로세스는 실행하지 않았다.

## 5. Main 이 다시 확인할 것 (실창)
1. EG-Desk 를 다시 시작(overlay 변경이라 화면 코드 재적재 필요), `EGDESK_COMPUTER_OBSERVE=on`.
2. "계산기 앱 창에 보이는 화면 요소를 읽어서 알려줘" → 카드에 **[이번만 허용]이 활성**. 누르면 읽기가 실행되어 요소 목록을 설명하고, 카드는 사라진다. 같은 대화에서 다시 물어도 카드가 없다.
3. 화면 기록 권한이 없는 상태에서 "계산기 창을 캡처해 줘" → 허용 후 `permission_missing` 안내가 정상.
