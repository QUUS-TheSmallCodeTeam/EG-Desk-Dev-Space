## 1. 원인 (v2 원본 답 분포로 확인; 영수증 04:02와 같은 증상)
v2의 8개 변경 요구 턴에서 `about`이 전부 안 읽혔고, 분포를 제품 방식으로 정규화해 보면 이유가 보입니다(`kind / about / direction`).

| 턴 (직전 메시지 없음) | about 분포 (상위) | 비고 |
|---|---|---|
| 너무 길어. 앞으로는 짧게 말해 (04:02 실창 문장) | length .49 / **no_particular .47** | 막판 두 개로 갈림. 바 .85 미달. 이 턴은 change .92, direction less .98 |
| 앞으로 답변은 세 줄 이내로 | **no_particular .70** / length .23 | |
| 좀 짧게 부탁해 | **no_particular .55** / length .40 | kind도 none .91 |
| 영어 말고 한국어로 답해줘 | language .51 / **no_particular .42** | kind도 none .81 |
| 일본어로 써줘 | **no_particular .72** / language .23 | kind none .87 |
| 그건 묻지 않아도 돼, 바로 진행해 | **no_particular .42** / repeated_question .24 / other .17 | 세 갈래 |
| 아니 파일 전체가 아니라 함수 하나만 | scope .62 / no_particular .34 | |
| 빨리 좀 해줘 | speed .84 / no_particular .13 | 유일하게 읽힘 |

세 원인이 겹쳤습니다.
1. **질문 문구**: `nk_about`는 "반응이 무엇에 대한 것인가"를 묻고, 선택지 `no_particular`는 "특별한 것에 대한 것이 아니거나, **반응이 아님**"이었습니다. Claude 경로는 직전 어시스턴트 메시지를 보내지 않으므로(유지) 모델은 "반응할 대상이 없다"고 보고 진짜 주제와 `no_particular` 사이에서 확률을 나눴습니다. 선택지 분할(길이 vs 형식 vs 범위)이 아니라 **주제 vs "반응 아님"**으로 갈린 것입니다 (길이/형식/범위 사이의 분할은 데이터에 없음: 2위가 항상 no_particular).
2. **같은 이유로 kind도 none**: 직전 메시지가 없으면 "영어 말고 한국어로 답해줘" 같은 평범한 지시가 `none`(새 요청)으로 읽혀(.81~.91) change 합이 .08~.17이 됨.
3. **세기 문(門)**: 평범한 지시는 clear .43~.75 / mild .25~.57이라 `forceful`(≥.8)이 null이고, `directiveFor`가 `forceful === true`만 통과시켰음.

04:02 영수증은 1·세 번째와 일치합니다: change .92, forceful .96이지만 about이 바 아래라 `directive` null.

## 2. 수정 (`helper/egdesk-nunchi.mjs` 중심)
1. **질문과 선택지 문구**: `nk_about`는 "턴이 어시스턴트가 **어떻게** 답하거나 일하는지에 대해 무엇을 말하는가"(주제 질문)로, `no_particular`는 "턴이 어시스턴트가 어떻게 답하거나 일하는지에 대해 아무 말도 하지 않는다"로, `none`은 "…어떻게 답할지도 말하지 않는 새 요청, 질문"으로 바꿨습니다. RULES에 "직전 메시지는 없을 수 있다. 그때도 어떻게 답하라는 말이면 그 자체로 지시"를 넣었고 `instruction_change` 설명에 "직전 메시지가 없어도 해당"을 넣었습니다. 선택지 값 이름은 그대로.
2. **새 질문 `nk_manner` (예/아니오, 6번째)**: "턴이 어시스턴트에게 어떻게 답하거나 일하는지(언어, 길이, 형식, 속도, 질문 빈도, 일의 양, 또는 말하거나 한 것이 틀렸다는 것)를 바꾸라고 말하거나 요청하는가? 감사, 승인, 새 내용, 단순 질문은 아니다." `change`는 이 질문(제품 예/아니오 바 .8/.2)과 기존 kind 합의 투표입니다: manner 예 → change; manner 아니오 → 아님(단 kind 합이 예면 불일치로 null); manner 불확실이거나 답이 없음(옛 결과) → 기존처럼 kind 합만.
3. **조건부 재판독 (change true일 때만)**: `about`이 바 미달이면 "아무 말도 안 함" 선택지(`no_particular`)를 빼고 남은 확률에서 몫을 계산: 1위 몫 ≥ .6, 2위와 차 ≥ .3, 남은 확률 ≥ .2 이면 채택(영수증 `inferred`에 'about'). `direction`은 about이 length/scope일 때(`not_applicable` 제외), `language`는 about이 language일 때(`none` 제외) 같은 규칙. 모델이 "아무 말도 안 함"에 .95를 줬으면 남은 확률 <.2라 덮어쓰지 않습니다(시험). 코드는 값을 만들지 않고 모델이 낸 확률을 다시 정규화할 뿐입니다.
4. **세기 문**: `directiveFor`는 `forceful !== false`(결정적으로 mild가 아님)를 통과시킴. 옛 모양(`forceful` 필드 없음)은 단일 strength 그대로. 부정 쪽은 영향 없음: 변경이 아닌 턴은 change가 막고, v2 부정 8개의 mild는 .62~.91.
5. 영수증(`GET /v1/user-guidance/receipts`)의 `reading`에 `mannerMass`, `inferred` 추가(닫힌 값). `merged-report` 표에 manner 질량과 `(inferred)` 표시, 채점의 forceful은 제품 문과 같이 mild로 결정된 경우만 실패.
