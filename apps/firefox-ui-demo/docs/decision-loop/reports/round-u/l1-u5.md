# L1 u5: 사람에게 답을 요구하는 카드와 사람이 한 행동 뒤에 대화창이 최신으로 내려가지 않음 (D15)

브랜치 `lane/u5-chat-scroll` (작업 사본 `$L/wt-l1-u5`, 기준 int/c14 `f72ddd6`). 실제 창에서는 확인하지 못했다(합성 로그 시험). 실제 Codex·Claude 실행 없음. 새 문구 없음, 플래그 없음(결함 수정). 임시 폴더·큰 사본 없음.

## 증상
04:06 Claude가 AskUserQuestion으로 질문 → 대화 카드에 질문이 도착했지만 질문 본문이 화면 밖(`74-claude-question.png`: '답변 대기 · 질문 1건'만 보임) → 사람이 답하자 Claude가 이어서 답했는데 대화창이 02:5x의 오래된 메시지 위치에 머물고 '새 메시지' 알약만 떴다(`75-question-answered.png`).

## 원인 (코드로 확인)
대화 카드는 그릴 때마다(`mountCodexHUD`의 `render`) 로그의 스크롤을 어떻게 할지 정한다(`eg-desk-surface.uc.js` ~15340):
- 그리기 직전에 로그가 맨 아래였으면(`atBottom`) 최신을 따라간다.
- 아니면 `preserveAnchor`로 보던 자리를 유지하고, 엔진의 새 답이 오면 '새 메시지' 알약을 띄운다.
- 이 규칙을 건너뛰는 경우는 **사람이 입력창으로 보낸 새 메시지**(`lastUserMessageId`가 바뀜) 하나뿐이었다.
질문에 답하기·승인/거절은 입력창 전송이 아니라 `lastUserMessageId`를 바꾸지 않는다. 그래서 로그가 어떤 이유로든 맨 아래가 아니었으면(질문 카드가 도착해 로그가 자랄 때, 활동 기록 창을 열었다 닫을 때 등) 사람이 한 행동 직후에도, 사람에게 답을 요구하는 카드가 도착할 때도 보던 자리에 머물렀다. 질문·승인 카드(`chat-agent-working-ask`)는 로그의 맨 끝(작업 중 줄)에 붙으므로 맨 아래로 가면 보인다. 왜 02:5x에 남아 있었는지(그 전에 로그가 맨 아래를 벗어난 계기)는 캡처만으로는 확인하지 못했다. 아래 수정은 그 계기와 무관하게, 질문·승인이 도착하거나 풀릴 때마다 위치를 바로잡는다.

## 수정
- 새 `ChatStatusView.waitingAskCount(runs)`: 방의 실행들이 기다리는 요청 수(대답하지 않은 질문 + 대기 중 승인, 낡은 것·기록으로만 읽은 것·이미 처리된 것 제외). `waitingAsk`가 읽는 기준과 같다.
- 새 `ChatHistoryView.askChanged(before, now)`: 그 수가 **알던 값에서 바뀌었을 때**만 참(처음 그린 방은 `before`를 몰라 거짓).
- 카드는 그릴 때마다 방별로 마지막 수를 기억해 비교한다. 바뀌면(요청이 도착했거나 사람이 답하거나 승인/거절해 풀렸으면) 이번 그리기에서 로그를 **맨 아래로** 보낸다(`preserveAnchor` 해제: 보던 자리를 유지하지 않고, '새 메시지' 알약도 만들지 않음). 사람이 질문에 답하면 수가 줄어 그 그리기에서 최신으로 가고, 이어지는 Claude의 답은 맨 아래에 있으니 평소처럼 따라온다.
- 그대로인 것: 사람이 위로 올려 읽는 중에 **엔진의 글**이 도착하면(요청 수 변화 없음) 지금처럼 자리 유지 + '새 메시지' 알약. 다른 방의 요청은 이 방의 로그를 움직이지 않는다. 사람이 입력창으로 보낸 경우는 기존 규칙 그대로.
- 핫스팟(`eg-desk-surface.uc.js`) 변경은 +14줄(방별 수 기억 2줄, 그릴 때 비교 한 블록, `preserveAnchor` 한 줄).

## Main이 실창에서 확인할 절차
1. 대화 카드에서 긴 대화를 위로 스크롤해 둔 채(맨 아래가 아님) Claude에게 선택지가 있는 질문을 하게 하는 요청을 보낸다(예: "npm인지 pnpm인지 물어보고 진행해 줘"). 보낸 직후 → 입력창 전송이므로 맨 아래로 간다(기존).
2. 질문이 도착할 때: 로그가 맨 아래로 내려가 '답변 대기' 줄과 질문 본문(`chat-agent-working-ask`)이 화면 안에 보여야 한다. 도착 직전에 위로 올려 둔 상태에서도 같은 결과여야 한다.
3. '답하기' → 답 선택 → '답변 보내기': 직후 로그가 맨 아래에 있고, Claude의 이어지는 답이 보이며 '새 메시지' 알약이 뜨지 않아야 한다. 승인 카드에서 승인/거절해도 같다.
4. (그대로여야 하는 것) 엔진이 길게 답하는 동안 일부러 위로 올려 읽는다. 그 상태에서 새 글이 오면 위치가 유지되고 '새 메시지' 알약이 남아야 한다. 알약을 누르면 최신으로 간다.
5. 안 되면: 질문이 도착한 시점의 로그 스크롤 위치와, 질문 카드가 로그 안에 있었는지(작업 중 줄 아래)를 알려 달라.
