# L3 u4 — Claude 턴에서 결정 모델 턴 판단과 게시 전 점검 (U19)

브랜치 `lane/u4-claude-turn-checks` (int/c14 `3b8e191` 위). 실제 Codex와 Claude 실행 없음(L5의 재생 세계: 진짜 런타임과 진짜 Claude 어댑터와 EG-Desk 도구, CLI만 녹음된 모양의 스크립트, 결정 모델은 가짜 fetch). 새 화면 문구 없음, 새 플래그 없음.

## 1. 원인 (실창 04:0x에 게시 전 점검 단계가 안 보인 이유)
- 게시 전 점검은 **Agent 방의 직접 답장**(`channelKind === 'direct'`)에서만 답을 붙잡고 점검한다. 일반 Claude 스레드는 `ineligible`이었다(Codex 일반 스레드도 같다: 엔진 차이가 아니라 방 종류 차이). u1 보고의 "Codex에서만 돈다"는 옛 기준(하네스 전)의 측정이고, 정확히는 "Agent 방에서만"이었다.
- 기록만(advisory) 점검은 `phase === 'final_answer'`인 항목에서만 도는데 Claude 번역기의 답은 `phase: null`이다(묶음 값은 `on`이라 영향 없음, 고치지 않음).

## 2. 턴 판단별 Claude 경로 (일반 스레드, 하네스 켬; 코드와 재생으로 확인)
| 기능 (EGDESK_UPPER가 채움) | 전 | 후 | 근거 |
|-|-|-|-|
| 명령 먼저 (OWN_TOOLS, TERMINAL_GATE, DECISION_FIRST) | 돎 | 돎 | L5 하네스(`CLAUDE_HARNESS`), 실창에서 npm test 196ms |
| 승인 빠른 경로 (DECISION_FIRST_APPROVALS) | 돎 | 돎 | L5 하네스 시험 `approvals fast path on Claude` |
| 열린 항목 (OPEN_ITEMS) | 돎 | 돎 | 엔진 무관 경로, L5 시험 `open items on Claude` |
| 제안 등록부 (PROPOSAL_REGISTRY) | 돎 | 돎 | 이번 재생: Claude 답의 되묻기가 `proposals` 항목으로 등록 |
| 기억 미리 넣기 (TURN_MEMORY_PREFETCH) | 돎 | 돎 | 맥락 선택 후보(일반 스레드), L5 시험 `memory prefetch on Claude` |
| **게시 전 점검 (DRAFT_CHECK=on)** | **안 돎** (일반 스레드 `ineligible`) | **돎** | 아래 3절 |
| 기억 루프, write-first (TURN_MEMORY_WRITE_FIRST) | Agent 방만 | Agent 방만 (바꾸지 않음) | 재생: 일반 스레드에서 `wiki` 호출 0, Agent 방은 호출됨. 엔진 차이가 아님 |
| 흐름 문구 (FLOW_NOTE_WORDING, STALLED_COPY) | 휴면 | 휴면 | 대화 흐름이 묶음 밖 |
| PAGE_TOOLS, TERMINAL_OPEN_URL, HUD | 판단 아님 | | 도구와 창 기능 |

**연결하지 않은 것과 이유**: 기억 루프(write-first)는 Agent의 기억에 쓰는 일이라 소유자가 있는 방(Agent 방)에서만 도는 설계이고, 일반 스레드에 쓰게 하면 어느 기억에 기록할지, 말 동의 범위는 어떻게 되는지가 정해져야 한다(소유자 결정, '아래' 쪽). 제안으로 남긴다.

## 3. 게시 전 점검을 Claude 일반 스레드로 (기존 플래그 뒤)
- `draftCheckEligibleFor(body, context)` 하나가 점검의 대상을 정한다(붙잡기와 근거 모으기 두 곳이 같은 함수를 쓴다): 설정된 `eligible`이 있으면 그것이 단독 결정, 아니면 Agent 방의 직접 답장 **또는 (새로) 하네스 아래의 Claude 스레드**. Board 전송, stateless, 확인 안 된 바인딩, 하네스 밖의 Claude는 아님. 플래그는 `EGDESK_DRAFT_CHECK=on`과 `EGDESK_CLAUDE_HARNESS=on`(둘 다 기본 꺼짐), 결정 모델 모드가 '끔'이면 아무것도 안 보냄.
- **stream-json과 맞물리는 지점**: Claude의 완성된 메시지 단위로 붙잡는다(번역기가 `item/completed agentMessage`를 만든다). 두 가지를 더했다.
  1. 도구 호출이 이어지면 앞서 붙잡힌 글은 **해설(narration)**이다. 도구가 시작될 때 그 글을 그대로 게시하고 점검하지 않는다(그 뒤의 답만 붙잡는다). 이것이 없으면 해설이 턴 끝까지 안 보인다.
  2. 도구 없이 글이 여러 개 이어지면 **마지막이 답**이다: 마지막만 점검하고 앞의 글은 쓴 대로 게시한다. 답이 보류(withheld)돼도 앞의 글은 같이 사라지지 않는다.
- **실행 근거 없는 주장**: (a) 근거 없는 구체 주장("main 브랜치에 v2.3.1을 배포했습니다.")은 게시되지 않는다(Claude에는 포크가 없어 고쳐 쓸 수 없으므로 보류, 비공개 턴을 켜면 고쳐 쓴 답이 게시: L5의 `EGDESK_CLAUDE_HARNESS_PRIVATE`). (b) 근거 있는 문장(EG-Desk가 돌린 `npm test` 결과)은 쓴 대로 게시된다.
- **04:03 사례("이번 실행에서 … 권한이 허용되지 않았습니다")**: 게시 전 점검은 구체적인 세부(숫자, 이름, 식별자)가 있는 문장만 대상으로 삼으므로 **이 문장은 원래 점검 대상이 아니었다**(근거가 없든 있든). 같은 입력이 Codex에서도 통과한다. 그래서 `claimsRunState`를 더했다: **"이번 실행/턴/요청" + 권한, 허용, 승인, 거절, 차단 낱말**이 있는 문장(질문, 계획, 이전 실행, 다른 주제는 제외)은 이 실행의 자기 상태에 대한 주장이라 점검 대상이다(`isCheckable`이 이를 포함). 재생 결과: 이번 턴에 근거가 없으면(자료가 있든 없든) 그 문장만 잘리고 나머지("계산기 화면은 읽을 수 없습니다.")는 게시된다. **도구를 부른 턴**은 도구 호출의 내용 없는 참조(opaque)가 근거가 될 수 있어 같은 문장을 자르지 않는다(과잉 차단 방지, 재생으로 확인).
- **실제 모델이 같은 판정을 내리는지는 측정하지 않았다.** 재생의 결정 모델은 문장 내용을 읽는 가짜다. Decisions만 보내는 계획 `this-run-claims-u4`: 4요청, 2,799토큰, 드라이런 통과(전송 없음, Main이 보냄): 근거 없는 "이번 실행" 문장 둘(자료만 있는 경우, 이전 거절 기록만 있는 경우)은 `sup` ≤ .2(hard), 대조 둘(이번 턴 명령 출력이 권한 거부를 말하는 문장, 평범한 지지되는 문장)은 `sup` ≥ .8(hard).

## 5. 실창 확인 절차 (Claude 대화, 하네스와 묶음 켬, 결정 모델 '사용')
1. `EGDESK_UPPER=on EGDESK_CLAUDE_HARNESS=on` (이미 쓰는 조합)으로 띄우고 일반 Claude 방(Agent 아님)을 연다.
2. 거짓 완료 확인: "배포해 줘"처럼 배포 도구가 없는 요청을 보낸다. Claude가 "main 브랜치에 v2.3.1을 배포했습니다."처럼 구체적으로 완료를 말하면 **말풍선이 게시되지 않아야** 한다(답이 통째로 보류되면 아무것도 안 보이는 것이 정상: 고쳐 쓰기는 `EGDESK_CLAUDE_HARNESS_PRIVATE=on`일 때만). 활동 기록에는 `컨텍스트 세팅 · 자료 N개`, `tool: …`만 보이고 점검은 화면에 흔적이 없다(점검 줄은 제안으로만 있음). 대신 결정 모델의 이번 달 입력 토큰(설정 > 계정)이 늘어난다.
3. 맞는 문장 통과: "npm test 돌려줘" 같은 요청 → 명령이 돌고 "테스트 N개가 통과했습니다."가 그대로 게시된다.
4. 해설: "먼저 …해 보겠습니다" 같은 앞 글은 도구가 도는 동안 바로 보여야 한다(턴 끝까지 안 보이면 이상).
5. "이번 실행" 주장: 과거에 승인 카드를 거절한 방에서 같은 도구 요청을 다시 보내 Claude가 도구를 부르지 않고 "이번 실행에서 권한이 허용되지 않았습니다"라고 말하면 그 문장이 빠진 채 게시되어야 한다. 도구를 부른 뒤 말하는 같은 문장은 그대로 게시된다.
6. 음성 대조: 결정 모델 모드 '끔'이면 어느 경우에도 말풍선이 그대로 게시되고 토큰 집계가 늘지 않는다.

## 6. 한계와 제안(승인 대기)
- 점검이 통과하거나 문장을 잘라도 화면에는 흔적이 없다: 활동 기록의 "답 점검" 줄(문구 제안)이 있어야 사람이 볼 수 있다.
- 답이 통째로 보류되면 사람은 빈 화면을 본다: 고정 문장을 쓰지 않는다는 기존 결정(option (나))을 따랐다. 일반 Claude 스레드에서는 비공개 턴(`EGDESK_CLAUDE_HARNESS_PRIVATE=on`)을 묶음에 넣을지가 소유자 결정이다(Claude 턴이 한 번 더 든다).
- `claimsRunState`의 낱말 목록은 소유자 예시에서 출발한 좁은 규칙이다. 다른 말투("이 세션에서는 …", "지금은 …")는 잡지 못한다.
- 새 파일: `helper/egdesk-claude-harness.fixture.mjs`, `helper/egdesk-claude-turn-checks.test.mjs`. 수정: `codex-chat-runtime.mjs`(대상 함수, 해설 해제, 마지막 답 점검), `egdesk-draft-run-facts.mjs`(`claimsRunState`), `egdesk-draft-check.mjs`(`isCheckable` 한 줄과 import), `egdesk-upper-bundle-claude.test.mjs`(제목).
