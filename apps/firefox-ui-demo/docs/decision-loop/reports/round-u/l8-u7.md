## 1. D20: 허용이 대화 단위가 아니라 전송 1회 단위였던 이유와 수정
- 원인: 입력창 칩은 Claude 전송이 **받아지면** `clearAcceptedClaudeDraft`가 `inputSources: []`로 비움(Claude의 캡처는 1회성이라 설계된 동작). 카드의 "조작 허용"(대화 단위 standing grant, 메뉴가 '조작 허용 해제'로 바뀜)은 그대로 살아 있는데, 다음 전송은 칩이 없어 Browser 자료를 하나도 싣지 못함 -> run 바인딩 없음 -> 도구 전부 실패. Codex 대화는 이 정리를 하지 않아서 칩이 남고, 다음 전송 때 `browserToolRefreshSelection`이 standing grant로 새 토큰을 발급해 이어짐(코드 확인).
- 수정(화면, 순수 함수는 리소스 모듈):
  1. `claudeKeptInputs(live, inputs)`(`EGDeskClaudeBrowserSend.sys.mjs`, ChatState 경유): **실시간(claude-browser 능력) 전송이 받아진 뒤** 입력창에서 "조작 허용을 받은 Browser 카드"만 남기고 나머지(파일, 읽기 전용 카드, 브리핑 자료)는 예전처럼 비움. 실시간이 아니면(능력 꺼짐, 조작 허용 없음) 아무것도 남기지 않음 = 이전 동작.
  2. 다음 전송은 남은 칩을 후보로 `browserToolSelectedSources`가 standing grant로 새 토큰을 발급(기존 BRW-11 경로, Codex와 같음) -> 같은 카드가 실시간 자료로 실리고 run 바인딩이 이어짐.
  3. 메뉴 '조작 허용 해제'를 누르면 허용이 끊기고, **Claude 대화에서는** 남은 칩도 함께 치움(만료 칩이 다음 전송을 "조작 권한이 만료됐습니다" 문장으로 막지 않게). Codex 대화는 이전 그대로(칩을 건드리지 않음).
- 유지: 허용은 대화 단위 키(`clientThreadId`, 카드)라 **다른 대화로 새지 않음**, 로그인 도메인 불투명(`withoutAuthOpaqueSources`)과 카드 변경, 계정 변경, 일시중지, 30분 유휴 해제 등 기존 standing grant 규칙은 손대지 않음. Codex 경로 불변(`clearAcceptedClaudeDraft`는 원래 Claude 전용).

## 2. D19: 구글 검색창이 person으로 분류된 이유와 수정
- 원인 1(입력): 구글 검색창은 `<textarea role="combobox" aria-label="검색">`. 자식 프로세스의 `roleFor`는 명시 role을 그대로 쓰므로 역할이 `combobox`. 입력 후보를 만드는 `buildReflexCandidates`는 `combobox`를 **지원하지 않는 역할**(`UNSUPPORTED_ROLES`, `<select>` 같은 드롭다운용)로 취급해 fill 후보에서 빼고 "사람 몫" 목록에 넣음. 페이지 도구 `egdesk_card_type`는 "목표 루프가 채우는 일반 칸만" 입력하므로 fill 후보가 없으면 `person_step(field)`.
- 원인 2(제출): "Google 검색" 버튼은 GET 폼 제출이라 `readOnlyPress`가 읽기 전용으로 증명해야 하는데, 그 증명은 폼의 칸 종류를 `SAFE_GET_FIELDS`(hidden, text, search, select, ... )로 제한하고 **`textarea`가 목록에 없어서**(구글 폼의 칸 종류는 `textarea`) 증명 실패 -> 버튼이 승인 대상이 됨.
- 수정:
  1. `buildReflexCandidates`에 옵션 `textComboboxes`(기본 꺼짐)를 추가하고 **페이지 도구만** 켬. `tag === 'textarea'`인 combobox만 일반 칸으로 봄(`<select>`와 tag가 없는 combobox는 그대로). 자격, 결제 칸은 기존 `SENSITIVE_LABEL`(후보 제외)와 페이지 도구의 `CREDENTIAL_LABEL`로 여전히 사람 몫. **목표 루프(Codex 포함)는 combobox를 이전처럼 사람 몫으로 봄**(시험으로 고정).
  2. `SAFE_GET_FIELDS`에 `textarea` 추가: **공유 규칙 변경**(목표 루프의 읽기 전용 GET 제출 증명에도 적용). GET 폼의 textarea 값은 같은 사이트 검색 URL의 질의일 뿐이고, POST 폼, 민감 폼(`sensitive`), 민감 구역, 허용되지 않은 URL, 제출 어휘 URL은 여전히 증명 실패. Main 확인 요청: 목표 루프에도 퍼지는 이 변경이 괜찮은지.
- 한계: Enter 키로 제출하는 도구는 없음(`egdesk_card_press`만). 검색은 "Google 검색" 버튼 누르기(자동)로 합니다. 결제, 로그인, 자격 칸 분류는 그대로(시험으로 고정: 로그인 링크는 person, 비밀번호 칸은 combobox로 자칭해도 person, POST 폼은 읽기 전용 아님, `<select>`는 입력 불가).

## 4. 실창 절차(갱신)
준비 u6와 같음(새 Chat, 엔진 Claude, 브리지 재시작, 환경 변수 동일).
1. 구글 첫 화면 카드 ⋯ -> "Chat 조작 허용" -> "이 페이지 제목 알려줘" -> 정답.
2. **허용을 다시 누르지 않고** 칩이 입력창에 계속 남아 있는지 확인(예전: 사라짐) -> "검색창에 우산 입력해줘" -> 검색창에 '우산'이 들어가고 페이지는 이동하지 않음, `egdesk_card_read`와 `egdesk_card_type` 성공.

4. 메뉴가 '조작 허용 해제'로 보이는 동안 3턴 이상 유지되는지 확인. 이어서 '조작 허용 해제' -> 칩이 사라지고 다음 메시지는 카드 없이 접수(카드 도구 없음).
5. 대조: 'Google 로그인'을 눌러 달라고 하면 사람 몫 안내, 다른 대화(새 Chat)에서는 카드가 실리지 않음, Codex 대화는 이전과 같음.
