## D10. 프로젝트 없는 대화에서 Claude가 "EG-Desk가 no_folder를 반환했는데…"라고 말함
- 원인: EG-Desk 자체 파일 도구(`egdesk-file-tools.mjs:187`)와 명령 도구(`egdesk-command-executor.mjs:120`)가 폴더가 없을 때 `{ status: 'no_folder', code: 'FILE_NO_FOLDER' }`(또는 `COMMAND_NO_FOLDER`)만 엔진에게 돌려준다. 엔진이 사람 말로 바꿀 재료가 없어 코드를 그대로 읽었다. 하네스(L5) 쪽 코드는 건드릴 필요가 없었다: 결과 문자열은 이 두 도구의 응답 한 곳에서 만들어진다.
- 수정: 새 `helper/egdesk-no-folder.mjs`의 `noFolderBody(code)`가 `status`와 `code`는 그대로 두고 `message`와 `hint`를 더한다. `message`는 화면의 기존 문장 `CHAT_REQUEST_PROJECT_CONNECT`(`eg-desk-surface.uc.js:2017`)의 첫 문장 그대로인 `연결된 프로젝트 폴더가 없습니다.`, `hint`는 페이지 도구의 `grantHint`와 같은 닫힌 형태 `{ needs: 'project_folder' }`(엔진이 말로 바꿈). 그림자 검사와 기존 시험이 읽는 `status`/`code`는 바뀌지 않았다.
- 시험: 두 도구의 응답 전체를 고정(`egdesk-file-tools.test.mjs`, `egdesk-command-executor.test.mjs`: 읽기·검색·명령), 문장이 화면의 기존 문장의 앞부분임을 확인, 코드만 있는 거절이 남지 않았음을 확인(`egdesk-u3-desk-small.test.mjs`). 변이 V1~V3 모두 잡힘.
- 한계: 엔진이 이 말을 실제로 쓰는지는 실제 Claude 대화에서만 확인된다. 다른 거절 코드(`FILE_NOT_FOUND`, `FILE_BINARY` 등)도 코드만 돌려주므로 같은 현상이 날 수 있다(이번 범위 밖, 제안: 같은 방식으로 한 줄씩).
- 실창 확인: 프로젝트 폴더가 없는 새 Claude 대화에서 "파일 목록 보여줘". 답이 `no_folder`/`FILE_NO_FOLDER` 대신 "연결된 프로젝트 폴더가 없습니다" 취지인가.
- **제안(승인 대기)**: 폴더를 연결하는 방법까지 말하게 하는 더 긴 문장(예: `이 대화에 프로젝트 폴더를 연결해 주세요.`). 지금은 연결 경로 이름을 정확히 알 수 없어 넣지 않았다.

## D11. '새 Agent DM'으로 만든 두 번째 Claude 방도 'Claude 1'
- 원인: 기본 방 이름의 번호는 전역 카운터(`threadNonce`)에서 나오는데 카운터는 **저장되지 않는다**. 재시작 뒤 0에서 다시 시작해 새 방이 이미 있는 이름('Codex 1' 또는 u1이 바꾼 'Claude 1')과 같은 번호를 받았다. 또 u1의 엔진 변경 이름 바꾸기는 번호를 그대로 유지해, 다른 방이 이미 그 이름이면 겹쳤다.
- 수정: 새 `ChatState.nextDefaultRoomNumber(threads, counter)`: 이미 있는 모든 기본 이름 방(Codex N, Claude N, 엔진 무관)의 최대 번호 + 1과 카운터 + 1 중 큰 값. `createThread`(DM)가 이 번호를 쓴다. 엔진 변경 이름 바꾸기(`relabelDefaultRoom`)는 바꿀 이름이 이미 다른 방에 있으면 다음 빈 번호를 쓴다. 사람이 정한 이름, 번호 없는 이름은 세지 않는다.
- 시험: 번호 계산(재시작 뒤, 엔진 섞임, 카운터 우선, 사람이 정한 이름 제외, 잘못된 입력), 이름 충돌 회피와 빈 이름 유지, 표면 연결 정규식. 변이 V4~V8 모두 잡힘. `createThread`가 `ChatState`가 없는 추출 환경에서도 도는지도 확인했다.
- 한계: 이미 겹친 두 방('Claude 1'이 둘)은 이름을 바꾸지 않는다(그 방들을 사람이 직접 바꾸거나, 엔진을 다시 고르는 경우만 위 규칙을 탄다).
- 실창 확인: 재시작 후 '새 Agent DM'을 눌러 방을 만들고 AI 설정에서 Claude를 고른다. 목록에 같은 이름이 둘 아닌가(예: `Claude 2`).

## D13. 재시작 뒤 목록에서 기록 있는 방의 미리보기가 '아직 메시지가 없습니다'
- 원인(코드 분석, 미확정): 목록 줄의 미리보기와 시간은 `thread.messages`의 **맨 마지막 메시지** 하나만 보고, 그 메시지에 글(`content`)이 없으면 방에 메시지가 하나도 없는 것처럼 빈 문구를 보였다. 방을 열면 대화는 전체 기록으로 그려지므로 증상(목록은 비어 보이고 열면 다 있음)과 맞는다. 맨 마지막 메시지가 글 없는 것(작업만 남은 답, 자리표시 메시지, 도구만 쓴 턴)이 될 수 있는 방, 특히 도구를 많이 쓴 프로젝트 방에서 두드러진다. 실제 저장소 기록을 볼 수 없어(사용자 데이터) 어느 종류의 메시지였는지는 확인하지 못했다.
- 수정: 미리보기와 시간은 **글이 있는 마지막 메시지**를 쓴다(`findLast(message => message.content)`). 글이 있는 메시지가 하나도 없는 방만 기존 빈 문구를 유지한다.
- 시험: 마지막이 비어 있을 때 앞 메시지, 사용자 메시지(`나: …`), 전부 비었을 때 기존 문구, 그룹/DM 문구, 70자 제한, 표면의 시간 줄 연결. 변이 V9~V10 모두 잡힘.
- 한계: 원인이 다른 곳(예: 기록이 아직 불러와지는 중이거나 불러오기에 실패해 메시지가 정말 비어 있음)이면 이 수정으로 나아지지 않는다. 그 경우 목록의 문구는 그대로이고 방을 열 때 불러온다.
- 실창 확인: 재시작 후 대화 목록에서 시험 프로젝트 방 줄이 마지막 말(또는 `나: …`)을 보이는가. 여전히 비어 있으면 알려 달라: 그 방을 연 직후 목록으로 돌아와 줄이 채워지는지(그렇다면 시작 때 기록 불러오기가 늦거나 그 방만 건너뛰는 것이므로 `loadLocalHistory`를 추적하겠다).
