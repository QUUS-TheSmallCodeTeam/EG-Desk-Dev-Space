## 3. 늦게 온 맥락 결과 -> 같은 턴 점검 근거 (Main 범위 조정 (a))
- 이미 있는 기능이다: turnMemory.keepLate (EGDESK_TURN_MEMORY_KEEP_LATE=on). 새로 만들지 않았다.
- **C2(엔진 입력 줄이기)와 분리 가능함, 코드로 확인**: 예산에서 `Promise.race([work, expired])`는 그대로라 턴은 맥락 없이 나간다. keepLate는 (1) 예산 시점에 요청을 abort하지 않고 예산 + LATE_CONTEXT_MS(1,500) 뒤에 abort, (2) 늦은 결과를 decision.late로만 돌려준다. decision.late의 소비자는 게시 전 점검 근거(noteLateDecisionContext / draftTurnEvidence)와 보정 기록뿐이다. 엔진에 가는 additionalContext는 같다(시험이 전체 additionalContext를 flag off 실행과 deepEqual로 비교). 그래서 NOT_IN_BUNDLE의 'engine input reduction, owner decision open (C2)'는 이 플래그에 틀린 이유였다(엔진 입력을 줄이는 것은 ONE_PACKET / PRUNE_HELD).
- 변경: helper/egdesk-upper-bundle.mjs UPPER_BUNDLE에 `EGDESK_TURN_MEMORY_KEEP_LATE: 'on'` (role turn, lane L7) 추가, NOT_IN_BUNDLE에서 삭제. 기본은 그대로 꺼짐(EGDESK_UPPER=on일 때만 채워지고 명시값 off가 이김). codex-chat-runtime.mjs의 로직 줄은 안 건드렸다(상수 두 줄 + 주석만) -> L3와 충돌 거의 없음.
- **04:47 기록의 813ms aborted**: keepLate가 꺼져 있었다는 뜻이다(켜면 예산에서 abort하지 않음). 이 묶음 변경을 쓰려면 브리지 재시작이 필요하다.
- 한계: 근거는 선택된 자료의 제목 + 요약(draftEvidence)이다. 04:45 README 사례에서 점검이 받는 것은 그 요약이고 파일 전문이 아니다. 늦은 결과가 아예 없거나(1,500+1,800 이후) guarded 항목이면 근거는 안 들어간다(기존 규칙 그대로).
