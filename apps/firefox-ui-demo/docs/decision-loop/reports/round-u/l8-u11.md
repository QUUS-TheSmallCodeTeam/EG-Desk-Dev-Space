# L8 u11: 사이트 질문 막대의 [이 대화에서 허용]을 실제 포인터로 눌러도 답이 안 들어감 (D25)

- 브랜치 `lane/u11-site-bar` (기준 int/c14 `a93232e`), 작업 사본 `$L/wt-l8-u11`, 커밋 `b4b6400`. 게이트는 3절. 새 문구 없음.

## 1. 원인 (코드에서 확정, 실창 증상과 일치)
- Main의 가설(막대 버튼이 다른 응답 경로를 쓴다)은 **아닙니다**: 막대 버튼의 `onclick`은 `finish('allowed')` 하나이고, 그 값이 카드 요청 처리기(`browserToolCardRequest`)의 `await toolAskSite()` 결과가 되어 헬퍼의 대기로 그대로 돌아갑니다. 질문 id나 run에 묶이는 별도 키가 없고 페이지 도구가 직접 던진 질문과 Claude가 던진 질문이 같은 경로입니다(u10 재생에서 진짜 전송 계층으로 확인).
- 실제 원인은 **클릭이 버튼에 닿지 않은 것**입니다. 카드 본문에는 투명한 `.egd-card-body-capture` 층이 있습니다(CSS: `position: absolute; inset: 0; z-index: 12`, **활성 카드일 때만 `display: none`**). 질문 막대는 카드의 `wrap`(축척 변환이 걸린 쌓임 맥락, 이 층의 형제) 안에서 `z-index: 6`이라 **이 층 아래**에 있습니다. 질문이 뜬 카드가 활성 카드가 아니면(대화 입력 중이라 채팅 카드가 활성) 실제 포인터 클릭은 막대 위에서도 이 층이 받아 **카드를 활성화할 뿐** 버튼의 click은 발생하지 않습니다. 스크립트의 `button.click()`은 히트 테스트를 건너뛰어 버튼에 직접 닿으므로 합성 클릭만 동작했고, 사람이 누르는 것과 달랐습니다. 이후 55초 동안 아무 답이 없어 `unanswered`로 끝납니다.
- u9에서 카드를 앞으로 가져오고 시야에 넣었지만 활성화는 하지 않아(채팅 입력을 가로채지 않으려고) 이 층은 그대로였습니다.

## 2. 수정 (3줄)
- 질문 패널이 열려 있는 동안 카드에 클래스 `egd-site-ask-open`을 달고(`toolAskSite`), CSS에서 이 클래스일 때 body-capture 층을 비활성(`display: none`, 활성 카드 규칙과 같은 줄)으로 합니다. 닫힘은 모든 끝(허용, 거절, 시간 초과)이 지나는 `finish`에서 클래스를 제거합니다. 카드를 활성화하지 않으므로 채팅 입력 포커스는 유지되고, 질문 중에 막대 밖(페이지)을 누르는 동작은 일반 카드처럼 페이지에 닿습니다(질문 동안만).
- 카드 활성화를 택하지 않은 이유: 사람이 채팅에 타이핑하는 중에 포커스를 빼앗지 않기 위해서입니다.
- 시험(`egdesk-claude-browser-site.test.mjs` 9건 중 새 1건, 정적): 층의 CSS 규칙, 질문 열릴 때 클래스 추가, 모든 끝이 `finish`를 거쳐 클래스 제거. **히트 테스트 자체는 여기서 실행할 수 없으므로 실창 확인이 필요합니다**: 비활성 카드에서 질문이 뜬 뒤 막대 버튼을 실제 포인터로 한 번 누르면 허용되고 같은 run에서 이동 1회.
