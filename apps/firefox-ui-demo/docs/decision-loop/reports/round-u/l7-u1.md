# L7 u1: 눈치 (U17), 결정 모델이 사용자 대답의 반응을 읽고 지침을 고친다

기준: int/c14 `cf086b8`, 브랜치 `lane/u1-nunchi`. 범위는 '위' (사용자와의 대화까지). '아래'(Agent 엔티티, 온톨로지)는 범위 밖이라 건드리지 않았습니다. 기본 꺼짐: 브리지 플래그 `EGDESK_NUNCHI=on`. 실제 Codex 실행 없음, 결정 모델 실호출 없음 (plan만 만들었고 Main에 전송을 요청합니다).

## 1. 판정 (단어 목록이 아니라 결정 모델)
- 사용자 메시지마다 요청 하나, 직전 어시스턴트 메시지의 끝 600자(이미 제품이 쓰는 `previousReplyFor`의 egress 게이트: Codex, 살아 있는 스레드, 엔진이 그 메시지를 이미 갖고 있을 때만; 아니면 "직전 메시지 없음"으로 판정)와 함께. 인용된 자료일 뿐 지시가 아니라는 규칙을 개발자 지시에 둠.
- **정해진 답 질문 5개로 분해** (한 질문이 여러 가지를 섞지 않음): `nk_kind` (칭찬/정정/재촉/불만/지시 변경/짧은 승인/애매/없음, 8), `nk_about` (언어/길이/형식/속도/반복 확인 질문/사실 오류/범위/기타/특정 대상 없음, 9), `nk_strength` (약함/분명/강함, 3), `nk_direction` (덜/더/유지/해당 없음, 4: 길이와 범위의 방향), `nk_language` (한국어/영어/일본어/중국어/기타/없음, 6: 말한 언어). 방향과 언어는 과제의 세 가지(종류, 대상, 세기) 위에 더한 것입니다: 방향이 없으면 "짧게"와 "길게"를, 언어가 없으면 "한국어로"를 지침으로 옮길 수 없습니다.
- 읽기: 질문마다 확신도 `(top − 1/N)/(1 − 1/N)` ≥ **.85** 그리고 1·2위 간격 ≥ .2 (발화 라벨 축의 바와 같음). 바 아래의 답은 아무것도 설치하지 않습니다 ("추측"이 아니라 "읽지 못함"). 질문마다 따로 읽음.
- 새 파일: `helper/egdesk-nunchi.mjs` (질문, 읽기, 표).

## 2. 반영
**(a) 그 대화 안 즉시 조정.** 읽은 결과를 **코드의 닫힌 표**가 한 줄로 바꿉니다. 모델이 쓴 글이나 사람의 말은 복사되지 않습니다.
- 지침을 만드는 경우: 종류가 정정, 불만, 지시 변경, 재촉 중 하나 + 세기 분명/강함 + 대상이 이름 있음(기타, 특정 대상 없음 제외) + 길이나 범위는 방향이 덜/더. 칭찬, 짧은 승인, 애매, 없음, 약한 반응은 **아무 줄도 만들지 않음**.
- 줄 (엔진용 영어 지시; 엔진이 사람의 언어로 말함): 언어 "Reply in Korean for the rest of this conversation, as the person asked." (한국어/영어/일본어/중국어; 기타는 "사람이 마지막 메시지에서 요청한 언어"), 길이 "Keep replies short…" / "Give fuller replies…", 형식, 반복 확인 질문 "Do not repeat a confirmation question that was already asked or answered; go ahead on what was agreed…", 속도 "The person is waiting: lead with the result or the current status…", 사실 오류 "check it again before relying on it…", 범위.
- 엔진 맥락 키 `egdesk_nunchi`에 "[guidance from the person: follow it in your reply; do not mention it unless asked]" + 줄들(그 사람의 적용된 사용자 지침 먼저, 이 대화의 줄은 최신 4개까지, 같은 종류는 새 줄이 옛 줄을 대체). **같은 턴**에 반영: 판정이 메모리 루프와 나란히 돌고 같은 상한(따뜻 2.5초, 차가움 4초) 안에 오면 이번 답부터, 늦으면 기다리지 않고 **다음 답부터**(영수증에 `late`).
- 새 파일: `helper/egdesk-nunchi-runtime.mjs` (런타임 쪽: begin/settle/note; `codex-chat-runtime.mjs`는 호출 3곳과 `previousReplyFor`의 옵션 하나만 바뀜).

**(b) 오래 갈 지침은 '사용자 지침 기록' 후보로.** 새 파일 `helper/egdesk-user-guidance.mjs`. 위 범위(그 사람의 모든 대화 공통), 파일 `<data>/settings/egdesk-user-guidance.json` (0600, 원자적 쓰기).
- 담는 것: 닫힌 단어(지침 종류, 값, 반응 종류, 세기)와 **출처 메시지 참조**(`chat-message:<id>`, 대화 id, 시각)와 상태 이력. **사람의 말은 저장하지 않음** (시험으로 확인). 종류가 정정, 불만, 지시 변경이고 세기가 분명 이상이며 언어/길이/형식/반복 확인 질문/범위일 때만 후보가 됨 (재촉, 속도, 사실 오류는 "이 순간"의 일이라 후보 안 됨; 한국어, 영어, 일본어, 중국어 밖의 언어는 값을 말할 수 없어 후보 안 됨). 같은 지침이 다시 나오면 출처가 추가되고 `seen`이 늘어남 (출처 5개까지).
- **후보는 스스로 적용되지 않음.** 상태: `candidate → applied | dismissed`, `applied → reverted`, `reverted → applied`, `dismissed → candidate`. 적용된 것만 모든 대화에서 엔진에게 한 줄씩 전달되고(종류마다 하나, 서로 어긋나면 나중에 적용한 것), **되돌리면 바로 빠지며 기록에는 남음** (언제 효력이 있었는지 알 수 있음).
- 사람의 행동 경로: 브리지 경로 `GET /v1/user-guidance` (기록), `POST /v1/user-guidance/<id>/apply|revert|dismiss|restore` (루프백만, 플래그가 꺼져 있으면 404). 화면은 없음 (§5, 제안).

**자동 적용 대 사용자 확인 기준 (제안, 구현 안 함).** 지금 구현은 "대화 안 줄은 자동, 오래 가는 지침은 항상 사람이 적용"입니다. 소유자가 정할 후보 기준:
1. 대화 안 줄(이번 구현): 분명/강함 + .85 바 → 자동. 되돌림은 그 대화가 끝날 때나 `dropConversationGuidance`.
2. 오래 가는 지침, 보수안(지금): 항상 사람이 적용.
3. 완화안: 서로 **다른 대화 두 곳 이상**에서 같은 지침이 후보가 됐고(`seen` ≥ 2, 출처 대화가 다름), 그중 하나가 "강함"이며, 반대 방향의 후보가 없을 때만 **적용 제안**을 사람에게 보임 (적용은 여전히 사람). 완전 자동 적용은 권하지 않음 (모든 대화에 퍼지는 지침이고 오탐의 비용이 큼).
4. 언어 지침은 가장 안전하고 흔해서 완화안의 첫 대상으로 권함.

## 5. 화면 검증 절차 (U18: EG-Desk 화면에서 사용자처럼; 스크립트는 보조)
전제 (프로필 A, 개발 플래그): `EGDESK_NUNCHI=on`, 결정 모델 `on` (키 설정), Codex로 대화. 새 화면 문구는 없으므로 아래 4단계의 "기록 보기"는 지금은 브리지 경로로 확인하고, 화면 항목은 제안(승인 대기)입니다.
1. **정정 후 다음 답부터 반영**: EG-Desk 대화에서 영어로 길게 답하게 하는 질문을 한다 (예: "오늘 할 일 정리해줘" 후 영어 답). 이어서 "야 한글로 보고해"라고 보낸다. **기대**: 이 메시지의 답부터 한국어 (판정이 상한 안에 오면 바로 이 답, 늦으면 그 다음 답부터). 이어 "그럼 다음은?"을 보내도 계속 한국어.
2. **짧게**: "너무 길어, 짧게 말해" → 이후 답이 눈에 띄게 짧아짐. 같은 확인 질문을 계속 하는 상황에서 "아 몇 번을 물어보는 거야, 그냥 해" → 같은 확인 질문을 되풀이하지 않고 진행.
3. **반응이 아닌 말은 건드리지 않음**: 새 질문("그럼 내일 일정은?"), "응 진행해", "고마워" 뒤에는 지침 줄이 늘지 않고 답이 달라지지 않음.
4. **사용자 지침 기록에 남고 되돌릴 수 있음**: `curl -s http://127.0.0.1:39218/v1/user-guidance` (로컬 브리지; 포트는 브리지 설정) → `language / korean` 후보가 `candidate`로 있고 출처가 `chat-message:…`로 보이며 **사람의 말은 없음**. 새 대화를 열어 영어로 시켜 보고 **한국어가 아님**을 확인(후보는 적용 전이라 다른 대화에 영향 없음) → `POST /v1/user-guidance/<id>/apply` → 새 대화에서 한국어로 답함 → `POST …/revert` → 다시 영어로 답함, 기록에는 `reverted`와 이력이 남음.
5. **끄면 아무 일도 없음**: 플래그를 끄고 같은 대화를 하면 지침이 반영되지 않고 라우트가 404.
- 화면 쪽 제안(승인 대기, 문구는 정하지 않음): 설정이나 대화 메뉴에 "내 지침" 목록(후보, 적용됨, 되돌림), 후보 옆의 적용/무시 버튼, 적용된 것의 되돌리기. 대화 중에는 줄이 반영됐을 때 한 번 보이는 작은 알림은 U8(완성된 메시지만)과 맞는지 먼저 결정 필요.

## 7. 위험과 한계
1. **측정 전**: 질문 세트가 실제 모델에서 어떻게 읽히는지는 아직 모름 (plan 001의 통제가 첫 확인). 바 .85는 보수적이라 놓칠 수는 있어도 틀리게 설치하는 쪽을 막도록 정했습니다. 설치를 놓치면 지침이 안 생길 뿐 대화는 그대로.
2. **직전 메시지가 없는 경우**: Claude 대화, 다시 열린 스레드, 압축 뒤 같은 경우 egress 게이트가 닫혀 있어 "직전 메시지 없음"으로 판정합니다 (사람의 말만 읽음). 정정은 말 자체로 읽히는 경우가 많지만 정확도는 낮아질 수 있음. 게이트 완화는 이전 사이클(c22, c24)의 결정이라 바꾸지 않았습니다.
3. **엔진이 지침을 따르는지**: 지침은 지시입니다. 대역 엔진으로만 확인했고 실제 Codex로는 안 돌렸습니다 (금지). 화면 검증이 필요합니다.
4. **비용**: 사용자 메시지마다 약 1,200 토큰의 호출이 하나 더. 대화가 많으면 누적. 줄이는 방법(제안, 안 함): 아주 긴 메시지는 건너뜀, 이미 `none`이 이어지면 간격을 둠.
5. **모든 대화에 퍼지는 지침**은 오탐의 비용이 커서 항상 사람이 적용하게 했습니다 (§2 제안 참고).
6. **'기타' 언어, 형식의 구체 내용**(표, 목록 등)은 값을 저장하지 않습니다: 지침은 "사람이 마지막 메시지에서 요청한 형식"으로 말하므로, 오래 가는 후보로는 형식의 구체 값이 없어 의미가 약함 (후보는 되지만 적용 시 줄이 일반적).
