항목 수: 결정 필요 35개 (A 3, B 10, C 16, D 3, E 3) + 이미 정해진 것 확인 8개.

## (A) 데이터·전송: 결정 모델로 나가는 것

### A1. 앱 이름과 앱 id를 결정 모델에 보내도 되나 (`app_names`)
- 시나리오: 사용자가 "계산기 앱 창 읽어줘"라고 하면, 지금은 모델이 어느 앱인지 고르려고 열려 있는 앱 이름과 번들 id 목록이 결정 모델로 나간다 (창 제목, 화면 요소, 화면 이미지는 안 나감). 거부하면 이 "앱 고르기"가 사라져서 읽기·캡처 후보가 빠지고 앱 목록과 창 목록만 남는다.
- 선택지: 가) 허용 (데이터 등급 `run`: 같은 목록을 엔진 모델도 이미 받음) / 나) 거부 (`app_names`를 `screen` 등급으로 바꿈)
- Main 추천: 가. 엔진 모델이 같은 목록을 이미 받고, 화면 내용은 안 나가기 때문.
- 출처: `l5-u5.md` 4절 끝 ("소유자 확인 필요")

### A2. Desk 검색창에 사람이 친 글을 결정 모델에 보내도 되나 (`hud_text`, D1)
- 시나리오: 사용자가 Desk 검색창에 글을 치면, 지금은 모든 게이트가 이 글을 거절해서 결정 모델로 아무것도 안 간다. 창 안의 코드 규칙(주소, 정확한 이름 일치)만 동작하고 카드는 안 움직인다. 허용하면 모델이 글을 읽고 어디로 보낼지(카드, 대화)를 고르게 된다. 검색창에는 아무 글이나 칠 수 있어서 민감한 글이 섞일 수 있다.
- 선택지: 가) 계속 막음 (코드 규칙만) / 나) 허용 (길이 제한 등 조건은 따로 정함)
- Main 추천: 가. 거절이 지금 기본값이고, 이 글에 무엇이 섞일지 통제할 수 없기 때문.
- 출처: `l3-u1.md` 1절 표의 `EGDESK_HUD_ROUTING` 줄과 "검색창 라우팅"

### A3. Claude 대화에서도 직전 어시스턴트 메시지를 눈치 판독에 보내나
- 시나리오: Codex 대화에서는 직전 메시지 끝 600자가 눈치 판독에 같이 가지만, Claude 대화에서는 보내지 않는다 (지금 상태, Main이 u4에서 유지). 그래서 "응", "ㅇㅇ"처럼 직전 메시지가 있어야 뜻이 정해지는 짧은 답은 Claude에서 약하다. 허용하면 Claude에서도 약한 부분이 좋아진다.
- 선택지: 가) 계속 안 보냄 / 나) 보냄 (Claude 세션도 엔진이 그 메시지를 이미 갖고 있다는 근거로 egress 게이트를 풂)
- Main 추천: 가. 직전 메시지 없이도 지시형 문장은 새 표본 16개에서 hard 12/12, soft 4/4로 읽혔고, 약한 것은 짧은 승인류뿐이기 때문.
- 출처: `l7-u2.md` ("알려진 차이"), `l7-u4.md` 10절

## (B) 화면 문구·새 UI (제안 문구 원문 포함)

### B1. 컴퓨터 보기 승인 카드의 "Agent가 …" 문구 (D8)와 컴퓨터 조작 활동 표시
- 시나리오: 사용자가 "계산기 읽어줘"라고 하면 지금 이런 카드가 뜬다: `Agent가 '계산기' 앱의 창 하나를 화면 이미지와 접근성 요소로 읽으려 합니다. 비밀번호 칸 등은 가려지고, 이번 작업에서만 허락됩니다.` 그런데 지금 말하는 쪽은 '아래'의 Agent가 아니라 대화 중인 Claude나 Codex다. 조작 중 표시(`EG-Desk Agent가 조작 중`, `Agent에게 돌려주기`, `Agent를 멈췄습니다` 등)도 같은 용어를 쓴다.
- 선택지: 가) 엔진 이름: `Claude가 '계산기' 앱의 창 하나를 … 읽으려 합니다.` / 나) 엔진 이름 없이: `이 대화의 AI가 '계산기' 앱의 창 하나를 …` / 다) 사람 관점: `'계산기' 앱의 창 하나를 화면 이미지와 접근성 요소로 읽도록 허락할까요? …` (활동 표시는 가·나 어느 쪽이든 `Agent`를 `AI`로 바꾸는 안)
- Main 추천: 카드는 가, 활동 표시는 `AI`로 치환. 근거: 엔진 이름이 이미 있고, '아래' Agent가 생기면 그 이름이 들어갈 자리라서 지금은 중립어가 안전함 (L1 의견).
- 출처: `l1-u2.md` "D8", `l6-u1b.md` 9절 1번

### B2. 첨부 창의 'Chat 조작 허용' 안내
- 시나리오: 사용자가 첨부 창에서 브라우저 카드를 붙이면 읽기만 되고, 조작을 허용하는 곳은 카드의 ⋯ 메뉴 하나뿐인데 첨부 창에는 그 안내가 없다. 사용자가 조작이 왜 안 되는지 모를 수 있다.
- 선택지: 가) 한 줄 안내만: `조작까지 허용하려면 Browser 카드의 ⋯ 메뉴에서 "Chat 조작 허용"을 선택하세요.` / 나) 첨부 창에 허용 토글 (기존 문자열 '이번 Chat 조작 허용'을 체크박스 이름으로 재사용) / 다) 그대로
- Main 추천: 가. 새 기능 없이 가장 작은 변경이고, 토글은 사용자 동선이 바뀜 (L8 의견).
- 출처: `l8-u2.md` 4절, `l1-u2.md` "D7 협조"

### B3. 프로젝트 폴더가 없을 때의 문장 (D10)
- 시나리오: 폴더가 연결되지 않은 대화에서 "파일 목록 보여줘"라고 하면, 지금은 Claude가 `연결된 프로젝트 폴더가 없습니다.` 취지로 말한다 (기존 화면 문장 재사용). 제안은 연결하는 방법까지 말하는 것: `이 대화에 프로젝트 폴더를 연결해 주세요.`
- 선택지: 가) 지금 문장 유지 / 나) 연결 안내까지 포함 / 다) 나)에 더해 다른 거절 코드(파일 없음 등)에도 같은 방식으로 사람 문장 추가
- Main 추천: 가. 화면에서 폴더를 연결하는 정확한 경로 이름을 확인하기 전에는 안내 문장을 못 쓰기 때문 (L1이 이름을 알 수 없다고 적음).
- 출처: `l1-u3.md` D10, "승인 대기 제안"

### B4. "Claude 사용 한도에 가까워졌습니다" 경고 기준 (70%)
- 시나리오: 사용량이 44%인데 경고가 떴던 것은 Claude CLI가 일찍 보내는 신호만 보고 문구를 정했기 때문이다. 지금은 사용량이 70% 이상이거나 값이 없을 때만 경고로 보이고, 그 아래면 기존 문장 `Claude 사용량을 확인했습니다. 주간 한도 · 사용량 44%…`가 나온다. 70은 L1이 고른 값이다.
- 선택지: 가) 70% / 나) 다른 값 (상수 한 곳) / 다) 제공자 신호 그대로
- Main 추천: 가. 실엔진 사용량 가드의 중단 기준 `CLAUDE_USAGE_STOP_PERCENT`와 같은 70이라 기준이 하나로 맞음.
- 출처: `l1-u1.md` 8~10절 중 10번, "승인 대기 제안 모음" 2번

### B5. Claude 방의 '기록 없이 시작' 설명
- 시나리오: 새 대화에서 AI 설정을 열고 Claude를 고르면, Claude는 기록 없이 시작을 지원하지 않는데 스위치가 켜져 있고 설명은 코덱스 문구였다. 지금은 Claude 방에서 스위치가 없어지고 설명이 `이 AI 엔진은 기록 없이 시작을 지원하지 않습니다.`로 나온다 (기존 오류문의 앞 문장을 떼어 쓴 새 문구에 가까움).
- 선택지: 가) 이 설명 문장을 보임 / 나) 스위치와 설명을 아예 숨김
- Main 추천: 가. 왜 스위치가 없는지 사용자가 알 수 있기 때문.
- 출처: `l1-u1.md` 8절

### B6. 활동 기록의 '답 점검' 줄과 '작업 메모리' 줄 문구
- 시나리오: 사용자가 보는 화면에는 게시 전 점검 흔적이 없다. 점검이 통과해도, 문장 몇 개가 잘려도 활동 기록에 아무것도 안 남아서, 답이 짧아졌거나 사라졌을 때 이유를 알 수 없다. 제안 문구 예: `답 점검 · 통과`, `답 점검 · 문장 N개 보류`. `WORKING_MEMORY`의 활동 줄 문구도 같은 상태로 승인 대기다.
- 선택지: 가) 항상 한 줄 / 나) 문장이 보류되거나 고쳐 쓰일 때만 한 줄 / 다) 지금처럼 안 보임
- Main 추천: 나. 통과 줄은 소음이고, 답이 줄어든 이유를 알려 주는 것이 목적이기 때문.
- 출처: `l3-u1.md` 4절, `l3-u4.md` 6절, `l3-u5.md` "한계와 제안"

### B7. 보내기가 막혔을 때 문장 (D1)

### B9. 컴퓨터 보기 '화면을 보는 중' 표시와 승인 카드의 앱 이름 줄

## (C) 동작 기본값

### C1. 근거 없는 주장을 잡았을 때: 전체 보류 vs 비공개 고쳐 쓰기 (`EGDESK_CLAUDE_HARNESS_PRIVATE`)
- 시나리오: Claude가 "배포했습니다"처럼 근거 없는 완료를 말하면 점검이 그 문장을 막는다. 지금 (PRIVATE 꺼짐)은 남은 문장만 게시하고, 남는 문장이 없으면 빈 화면이 된다 (고정 안내 문장은 안 씀). PRIVATE 켬이면 Claude가 한 턴을 더 써서 고쳐 쓴 답을 게시한다 (04:30 실측으로 약 +5초, Claude 턴 1개 추가라 사용량이 더 들고, CLI가 자기 세션 파일을 남김).
- 선택지: 가) 전체 보류 (빈 화면 가능) / 나) 비공개 고쳐 쓰기 (묶음에 넣음) / 다) 고정 안내 문장 (이미 안 쓰기로 정한 방향)
- Main 추천: 나. 사람이 답을 못 받는 것이 더 나쁘고, 추가 비용은 점검이 문장을 막을 때만 든다.
- 출처: `l3-u5.md` 3절 (비교표), `l3-u4.md` 6절, `l5-u1.md` 7절

### C2. 맥락이 잘린 턴에서 점검이 "근거 없음"으로 판단할지 (`EGDESK_DRAFT_CHECK_INCOMPLETE=hold`)
- 시나리오: 사용자가 "README 요약해줘"라고 했을 때 맥락 호출이 예산에 걸려 잘리면 근거가 없어서 맞는 요약도 잘려 빈 화면이 된 적이 있다 (D18). `hold`를 켜면 맥락이 잘린 턴은 근거가 불완전하다고 보고 "근거 없음" 판정을 안 한다. 대신 맥락이 잘린 틈에 지어낸 주장이 그대로 통과할 수 있다. 점검에는 이 둘을 구별하는 신호가 없다.

### E1. Claude 로그인 버튼과 터미널 URL 열기가 '로그인 제공/중개'에 해당하나
- 시나리오: 사용자가 설정에서 Claude '로그인'을 누르면, EG-Desk가 터미널에 공식 `claude` 로그인 명령을 쳐 주고, CLI가 연 로그인 주소를 EG-Desk 브라우저 카드에 열며 (`EGDESK_TERMINAL_OPEN_URL`), 로그인이 끝나면 카드를 닫는다. EG-Desk는 그 로그인 페이지를 읽지도 누르지도 않는다 (불투명 처리). 정책 검토 결과: 제3자 앱의 Claude.ai 로그인 제공, 구독 자격 중계, 토큰 수집은 금지이고, 수정 안 된 공식 CLI에 사람이 직접 로그인하는 것은 허용이다. 주소를 카드에 열어 주는 것이 '제공'인지는 최종 판단이 필요하다.
- 선택지: 가) 지금 방식 유지 / 나) 주소를 EG-Desk 카드가 아니라 기본 브라우저로 열기 (카드 열기를 끔) / 다) 로그인 버튼을 없애고 안내문만
- Main 추천: 가. EG-Desk가 자격 증명을 읽거나 저장·중계하지 않는다는 조건이 유지되고 있음. 다만 최종 해당 여부는 정책 원문을 확인한 소유자 판단이므로, 보수적 대안은 나.
- 출처: `l6-c25-owner.md` "엔진 공급" (Claude 정책 검토), `l1-u1.md` 1~2절, `l8-u1.md` 4절, `l5-u1.md` 7절

### E2. 컴퓨터 도우미의 서명 신원 (자체 서명 vs Developer ID)
- 시나리오: 컴퓨터 도우미는 지금 ad-hoc 서명이라 빌드할 때마다 신원이 바뀌어 화면 녹화·접근성 권한이 풀릴 수 있고, 유효한 서명 신원이 이 Mac에는 0개다. 자체 서명 인증서를 만들면 개발 중 권한이 유지되지만 이 Mac의 키체인을 건드린다. 배포용은 Developer ID로 서명한 번들이 필요하다.
- 선택지: 가) 개발용 자체 서명 인증서를 지금 만듦 / 나) 출시 때 Developer ID로 한 번에
- Main 추천: 가. 재빌드마다 권한이 풀리면 실창 확인이 계속 끊기기 때문 (키체인 변경은 소유자 동의가 필요).
- 출처: `l6-u1b.md` 7절 2번, 9절 5번

### E3. Claude 시작 정보에 `egdesk` 외 MCP 이름이 보이면 경고하는 검사
- 시나리오: EG-Desk가 띄우는 Claude는 설계상 `computer-use` 같은 내장 MCP가 안 보여야 하는데, 실제 CLI로는 확인하지 못했다 (`managed-mcp.json`이 있으면 `--strict-mcp-config`가 빠지는 경우도 있음). 이 검사를 넣으면 이름이 있을 때 경고 행이 남는다.
- 선택지: 가) 검사 추가 (경고 행만) / 나) 안 함
- Main 추천: 가. 정책 조건(바이너리 무수정, 본인 로그인)을 실제로 지키고 있는지를 사람이 볼 수 있게 하는 작은 검사이기 때문.
- 출처: `l6-u1b.md` 7절 5번
