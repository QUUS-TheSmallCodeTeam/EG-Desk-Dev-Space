# L28 b: 대화 모델의 카드 도구에 L19/L21 판정 적용

기준 `fac1e4b`, 브랜치 `lane/b-page-tool-choices`, 커밋 `83d9e6d`. 변경 파일은 `apps/firefox-ui-demo/helper/` 아래 `egdesk-page-tools.mjs`, `egdesk-page-tools-wiring.mjs`, `egdesk-page-tools-choices.test.mjs`. 다른 레인 파일·결정 루프·화면·도구 이름·플래그는 변경하지 않았다.

## 확인한 원인과 수정

기존 `classify`는 후보 목록의 navigate/fill/readOnly만 auto로 인식했다. radio는 L19의 choice 후보라도 승인 경로였고, select도 `isFieldElement`에서 combobox로 인정되더라도 fill 후보가 아니라서 입력할 수 없었다. 이름 버튼 후보를 만들 실제 사람 메시지도 `buildReflexCandidates`에 주지 않았다. 22:25 실창 사례는 Main 제공 증거이며 여기서 재현하지 않았다.

공개 호출 인자는 ref·text·expectText 등 **모델이 작성한 값**뿐이다. 이 값을 동의로 쓰지 않았다. 이미 같은 wiring의 task tool이 쓰던 `browserTaskMessage(run)`는 런타임이 브라우저 턴에서 실제 `body.message` 등을 requestId/runId에 저장한 값이다. 이것만 goal 및 namedButtonRequest로 전달한다. 결정 전송은 `reflexScope`의 기존 권한 검사·egress gate를 거치고, 페이지 본문 없이 기존 `withoutPageText`의 제목·컨트롤 요약만 사용한다. 구조 읽기(조작 권한 카드) 또는 대상 액션에서 후보가 있을 때 그 관찰에 대해 최대 한 번 판정하고, 실행 직전 턴 메시지와 권한의 유효성을 다시 본다. 선택되지 않은 다른 ref/다른 옵션으로는 권한이 옮겨가지 않는다.

## 소유자 확인 필요

- 자동 실행을 추가하는 경우는 `buildReflexCandidates`의 적격 후보 중 기존 `decideReflexStep`이 일반 콘텐츠 페이지에서 다음 동작으로 확정한 **한 후보**뿐이다. 선택은 L19의 `choice_requested`까지 통과해야 한다. 명시한 목표 상태에 한해 폼에 연결된 네이티브 radio 체크, 폼 checkbox 체크/명시적 해제, 단일 native select 변경(폼 밖 포함)을 허용한다. mixed·다중/잘린 목록·비활성/중복 값·민감 영역·인라인 즉시 토글·폼 밖 설정 체크는 추가 허용하지 않는다. `card_press`로 select 변경은 불가. `card_type`에는 현재 허용된 옵션의 값 또는 유일하게 그 값을 뜻하는 정확한 표시 이름만 허용한다. `target-value`를 관찰해야 성공이다.
- 이름이 유일하게 지목된 일반 native 버튼은 L21의 standalone/상위영역·form·링크·어휘 검사와 동일한 판정을 통과한 뒤 `card_press`로 **run당 최대 1회** 자동 시도한다. 시도 직전에 권한을 소비하며 결과를 확인 못 해도 해당 run에서는 자동 재클릭하지 않는다. L21 내부 후조건(같은 문서·같은 URL에서 새 변화 관찰)을 그대로 쓴다.
- POST 폼의 선택 상태 편집은 허용하지만 POST 제출은 이 예외에 해당하지 않는다. 권한·결제·로그인·자격증명은 이전처럼 `person`(승인해도 도구가 실행하지 않음); 삭제·증명 없는 제출은 기존 approval 등 이전 경계를 유지한다. 기존 사이트 승인/인증 페이지 보호 및 하위 카드 권한·리비전 검사는 그대로다.
- 이 권한은 브라우저에서의 한 편집/클릭에 대한 동의다. DOM에서 보이지 않는 JS 이벤트 리스너에 의한 자동 저장·서버 쓰기 등 외부 무부작용을 보증하지 않는다. 판정 호출 추가 비용·지연도 동반한다.

## 검증과 남은 문제

공개 도구에서 wiring을 거친 오프라인 회귀 시험: Medium·Bacon·표시 이름과 값이 다른 select의 올바른 후조건, 다른 값/잘못된 동사 거절, 결제·로그인 person/삭제·POST·설정 approval, 명시성 부족·사람 메시지 없음·민감 페이지·권한 만료의 조작 없음, Start 결과 미확인 시 재시도 없음. 3개 파일 단독 시험 15/15 통과. 가짜 결정·브라우저로 확인한 결과이며 번역·의도 판정 품질이나 실창 시간은 대변하지 않는다. 진입 비활성 등으로 사람 메시지가 없거나 결정 서비스/권한이 없으면 승인을 추측하지 않는다. 진입 분류 자체는 변경하지 않았다.

## Main 실창 확인

소유자 승인 후 통합 빌드에서 Claude가 직접 카드 도구를 쓰는 회차를 분리해 확인한다. 새 `https://httpbin.org/forms/post` 카드에 “피자 크기 중간으로 골라줘, 제출하지 마”: `card_read(structure)`의 Medium만 해당 선택 중 auto, `card_press` 1회, 재관찰에서 checked·POST/주소 변경 없음·재승인 질문 없음. 새 상태에서 Bacon/Onion을 명시해 두 번의 신선한 관찰 및 체크를 확인한다. `/dropdown`에서 Option 2는 `card_type` 후 실제 값 2. `/dynamic_loading/2`에서 Start 1회 후 Hello World!가 보이고 자동 재클릭 없는지 확인. 로컬 무해한 결제·로그인·삭제/POST fixture에서 자동 조작 0회. 같은 조건의 Codex 직접 도구/결정 루프와 결과·호출 경로·승인 질문·소요시간을 따로 기록한다. 이 레인에서는 운영 Firefox·포트·실제 엔진을 사용하지 않았다.
