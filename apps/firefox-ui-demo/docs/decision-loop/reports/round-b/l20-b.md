## 원인과 수정
- **기록**: 기존 Decisions 선택지에는 기록 이동이 없었다(확인). 21:19 진입이 세 번의 결정 뒤 빠져나온 개별 predicate 값은 확인하지 않았다. 단일 interact 카드에서 일치하는 단독 이동 명령은 카드 식별 질문이 불필요하다. 일반 웹 요청 여부·권한·페이지 상태 검사는 유지한다. 결정이 선택하면 기존 `egdesk_browser_history` → `browserToolHistory` → `goBrowserBack/Forward` 경로만 사용한다. chrome이 보관하는 대상 주소는 발송 전 기존 허용 사이트 검사, redirect commit guard 유지. 발송 영수증만으로 성공하지 않고 다른 fresh observation에서 기대 주소와 실제 착지를 대조한다. 첫 관찰이 이전 문서면 재발송 없이 제한적으로 다시 읽는다.
- **스크롤**: 기존 `scroll_more`는 `down/page`만 발송하고 도착 여부는 `goal_met` 재판정에 맡겼다(확인). 종전 실창의 마지막 실패가 특정 confidence 탓인지는 미확인. 명시적 맨 위·아래 요청은 기존 top/bottom API, 조금·한 화면은 기존 up/down page API 한 번. 정적 문서에서는 한 결정과 한 동작 뒤 새 관찰 좌표로 종료한다. 이미 끝이면 관찰만으로 완료. 무한 목록이 바로 늘어나면 각 새 revision으로 최대 3회까지, 끝을 입증하지 못하면 `step_limit`로 handoff. 민감 페이지 판정과 일반 탐색 중의 `scroll_more`는 그대로다.
