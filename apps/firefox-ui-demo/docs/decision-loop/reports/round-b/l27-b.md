## 확인된 원인과 수정

BRW-13은 hold 상태에서 UI 요청을 `status: rejected` 및 고정 사유로 거절한다. 기존 helper의 관찰 처리에서는 거절 응답과 손상된 관찰을 모두 `BROWSER_OBSERVATION_UNAVAILABLE`로 만들었다. 페이지 읽기 도구도 관찰 오류의 코드만 전달했고, raw 도구가 이미 `staleBy`를 붙인 경우조차 최종 native 오류 필터는 코드만 재분류했다. 증상과 일치하는 코드 경로와 합성 재현은 확인했다. 22:22~22:23 실창에서 각 호출이 정확히 어느 시점에 카드에 도달했는지는 재측정하지 않았다.

- 기존 `BROWSER_OBSERVATION_STALE / user-hold`를 공통 도구 결과, `browser.tool.failed`, 페이지 도구, 최종 네이티브 오류에 보존한다. 브라우저 제공자에 한해 두 값이 모두 일치할 때만 고정 메시지를 허용하며 진단 문자열을 노출하지 않는다.
- BRW-13은 현재 카드의 권한을 철회하므로 기존 실행의 해당 카드에만 거절을 기억한다. 모델이 다시 도구를 불러도 UI 재요청을 보내지 않는다. 다른 카드·새 바인딩으로 전파하지 않는다. 연결/손상 오류는 이 상태를 설정하지 않는다. 물리 동작의 미전송 판정은 기존 증거 조건을 그대로 요구한다.
- 결정 루프·직접 진입·안내·사이트/이동 확인 단계에서 hold를 사람에게 넘기는 결과로 보존한다. 기존 `RULE_CANNOT`를 유지하고, 일반 도구 결과에도 사람이 제어권을 가져갔음을 말하고 재시도하지 않도록 명시한다. 화면 문구·플래그·도구명 변경은 없다.
