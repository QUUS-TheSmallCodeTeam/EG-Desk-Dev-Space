## 원인과 변경
- **확인**: 원래 루프는 외부 링크를 옵션에서 제거하고 guidance에만 보냈다. 교대 진입/채팅 작업에서는 안전 분류를 통과한 실제 HTTP(S) `<a>` 최대 6개를 페이지 순서대로 **카드의 허용 질문을 전제로** 고를 수 있다. 다른 루프와 페이지 도구는 기존 후보 그대로다. 정책은 `outside-site`일 때만, label/href/disabled 검사 뒤에 질문한다. HTTPS 강등·인증정보 주소는 해당하지 않는다.
- `request_site`는 기존 카드의 55초 한도를 그대로 기다린다. 질문 중에는 페이지 조작 없음. `site-allowed`일 때만 같은 주소/문서의 새 관찰에서 같은 label/href가 여전히 안전한지 확인 후 그 관찰 ID/리비전으로 한 번 navigate. 중단, 거절, 미응답, 링크 소실 시 이동하지 않는다. 거절/미응답을 공급자가 일반 TOOL_FAILED로 버리던 부분도 해당 도구의 두 상태에 한해 분리했다. `site_not_allowed` / `site_pending`을 대화 모델 메모로 전달한다. 기존 카드 질문/카드 활동 표시를 사용하며 대기 전용 단계 줄 추가는 하지 않았다.
- **확인**: 루프는 GET 제출 뒤 사이트가 붙인 `ia=web` 등을 인정하지만 도구 런타임의 정확 URL 잠금은 풀리지 않았다. 때문에 다음 이동이 `BROWSER_OUTCOME_UNKNOWN`으로 4ms 안에 차단될 수 있다. 실제 서비스 + 가짜 카드로 잠금과 복구를 재현했다. **추정**: 20:10 단계 8도 이 경로였을 가능성이 높지만 원본 전송/영수증의 구간 대응은 확인하지 않았다. UNKNOWN은 사이트 질문을 뜻하는 코드가 아니다. 일반 UNKNOWN을 재시도하거나 임의로 잠금을 풀지 않았다.
- 복구 근거: 같은 문서에서 실제로 채운 필드의 현재값 = 채운 값 = GET의 매개변수 값, 관찰된 GET submitter의 주소 = 이동 요청 및 postcondition, 같은 사이트 출발. 이어서 **새 문서가 interactive/complete**, 원래 조건이 이미 참이 아니며 origin/path 및 제출한 모든 비어 있지 않은 값이 유지된 경우에만 복구한다. POST/다른 검색어의 잠금은 유지한다.
- **검색 완료 원인 확인**: `typedSearch`는 제출 전의 약한 선택만 보강하고 결과 페이지에서는 일반 `goal_met`만 물었다. 이제 실제 친 값이 실린 GET 도착을 다음 관찰에서 증명하면 같은 결정 호출에서 검색 결과 표시가 요청의 유일한 브라우저 목표인지 별도 이진 판단한다. 보통 페이지 + 확실한 yes만 코드가 `search_arrived`/done으로 판정한다. 링크도 허용 후 도착 확인 + 마지막 브라우저 조작이면 `link_arrived`. 로그인/인증/오류/모달 상태를 먼저 처리한다. 추상 목표를 문자열 정규식으로 해석하거나 마지막 판정을 무조건 done으로 바꾸지 않는다. 입력/도착 근거는 task segment 경계를 넘길 수 있다.
