## 수정

- 연결된 HTML label(감싸기·for)을 name보다 먼저, select/textarea 내용 자체는 이름으로 사용하지 않는다. checkbox/radio의 value 사후조건을 `checked`/`unchecked`로 비교하고 원래 속성값은 `choiceValue`, 체크 여부는 `checked`에 분리. mixed는 조작하지 않는다. select는 실제 value, 현재 표시 이름, 옵션 이름·값 목록(최대 32)을 제공한다.
- ordinary content에서 현재 바꿀 수 있는 선택만 제시한다. 한 결정 요청 안에서 `next_step`뿐 아니라 `choice_requested`가 명시적 목표·상태 일치를 확인해야 한다. 체크박스의 체크·해제, 라디오 선택, 네이티브 단일 select 값 설정을 기존 click/fill로 실행한다. `target-value`가 새 관찰에서 확인된 뒤 다음 목표를 새 observe로 결정하며 페이지 load를 기다리지 않는다. 결과 미확인은 중지. 필드 입력에 시간·날짜 추가(숫자는 기존부터 지원). 선택된 time 필드의 한 가지 명시 시각은 `저녁 7시 반` → `19:30`으로 값만 정규화, 카드의 사후조건으로 확인한다.
- 선택 없는 페이지의 모델 요청 바이트를 바꾸지 않는다. 페이지 본문은 기존 비전송 설정 그대로이며 선택 후보는 컨트롤 이름·값·상태만 제공. 새 화면 문구·도구·플래그 없다.

## 소유자 확인 필요

1. 일반 페이지에서 사용자가 정확한 선택과 상태를 명시할 때, **폼에 연결된 네이티브** radio/checkbox의 편집을 텍스트 입력과 같은 권한으로 자동 실행한다. 단일 네이티브 select는 요청 사례인 폼 밖 `/dropdown`도 포함한다. 32개 초과, 다중 select, 비활성·중복 값, mixed, 인라인 즉시동작 속성 및 민감 영역은 이 새 경로에서 제외한다. checkbox 해제는 명시 요청만, radio 단독 해제는 제공하지 않는다.
2. 로그인·결제·권한·민감 흐름과 제출은 승인 확대 대상이 아니다. POST 폼 안의 편집은 허용하지만 POST 제출은 하지 않는다. 폼 밖 switch/checkbox와 ARIA 상태 버튼을 새 선택으로 승격하지 않는다. 타 사이트는 기존 카드 질문 그대로다.
3. 사이트가 `addEventListener`/위임 이벤트로 자동 저장하면 HTML 구조만으로 서버 부작용 부재를 증명할 수 없다. 이 자동 편집 권한은 **브라우저 입력 상태**의 변경을 허용하는 것이며 서버 변경 부재 보증은 아니다. 강한 무부작용 보증이 필요하면 이 규칙을 그대로 채택하면 안 된다.
