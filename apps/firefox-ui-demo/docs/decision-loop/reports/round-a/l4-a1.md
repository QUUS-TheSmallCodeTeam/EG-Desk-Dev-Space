# L4 a1: Codex 0.171.0-alpha.13 계약 열기 (새 Codex 대화 "전송 거절됨" 원인)

브랜치 `lane/a1-codex-0171` (기준 c37ab23), 커밋 `b7b38bc`, `478ae13`. 게이트 `files=530 rc=0`, `# fail 0` (8,210 통과, 38 건너뜀).

## 원인 [확인]
ChatGPT.app 안의 Codex CLI가 0.171.0-alpha.13으로 자동 업데이트됐다. 이 버전은 `CONTEXT_CONTRACT_VERSIONS`에도 `QA_POLICY_CONTRACT_VERSIONS`에도 없어서 브리지가 `schemaMatch/dynamicTools/readerReadOnly/qaReadOnly = false`로 판정했다. 맥락 런타임의 `schemaReady`가 `nativeCapabilities.schemaMatch`를 보므로 첫 메시지가 맥락 접근 거절("Context access was rejected or unavailable")로 막혔다. 브라우저 묶음 실행(browserBounded)도 `qaReady`가 거짓이라 `QA_POLICY_UNAVAILABLE`로 막혔을 것이다.

## 이전 버전을 넣을 때 쓴 절차 [확인: 원 저장소 b9a98d9 문서, 1999381, 67b3824]
- 그 버전이 생성한 experimental 스키마가 프로브(context, QA 모양)를 통과하고, 실행 파일 지문이 잡혀야 한다. 모델 턴은 돌리지 않는다.
- 실제 엔진에서 기능을 확인한다(Windows 0.163.0-alpha.10.2: 실제 모델이 로컬 고정 페이지에서 observe/click/fill 완료).
- QA 목록은 "모양만으로는 실제 격리를 증명하지 못한다"는 원칙에 따라 따로 연다. 0.162.1은 context만 열고 QA는 닫았던 선례가 있다.

### 실제 격리 점검 (`scripts/real-engine/codex-qa-isolation-check.mjs`)
- 방식: 실행 중인 EG-Desk와 별개의 임시 app-server 1개(stdio), 사람의 Codex 로그인 그대로(`--person-home`: CODEX_HOME 설정 안 함, 그 폴더를 읽지 않음), 작은 환경 변수, memories 끔, effort low, ephemeral 스레드 1개(기록 안 남음). 자격 증명 파일은 읽지도 복사하지도 않음.
- 1단계 증명(런타임과 같은 함수, 같은 순서): `loadQaThreadOverrides` → `thread/start` → `verifyQaNativeThread` → `verifyQaMcpIsolation`. 결과는 read-only, 오프라인, never 승인 확인, 사람의 MCP 서버 10개 모두 이 스레드에서 도구 0, 컴퓨터 조작 기능 꺼짐, ephemeral 확인.
- 2단계 샌드박스(모델 없이, `command/exec`에 read-only + 오프라인 정책):

  | 명령 | 결과 |
  |---|---|
  | 폴더 안 쓰기 | `Operation not permitted`(exit 1), 파일 없음 |
  | 폴더 밖 쓰기 | `Operation not permitted`(exit 1), 파일 없음 |
  | 네트워크 | `Could not resolve host`(exit 6) |

  대조로 workspace-write에서는 같은 쓰기가 성공했고, 네트워크를 허용하면 HTTP 200이었다. 즉 명령은 정상이고, 막은 것은 샌드박스다.
- 3단계 모델 턴(QA_TURN_OVERRIDES, effort low, 11초): 모델이 실행한 curl은 차단됐고(exit 6), 승인 요청 0, 턴 뒤 파일 없음. 모델은 쓰기 명령은 시도하지 않았다(2단계가 덮음).
- 판정: pass. 기록 `$L/evidence/l4-a1-qa-isolation/qa-isolation.json`.
- 1차 실행 기록(`qa-isolation-run1-with-workspace-write-probe.json`)에는 범위 밖 관찰이 하나 있다. workspace-write(writableRoots=[inside], tmp 제외)에서 상위 임시 폴더(app-server의 작업 폴더) 쓰기가 성공했다. 묶음 실행은 workspace-write를 쓰지 않으므로 판정에서 뺐다. 원인은 확인하지 않았다(세션 작업 폴더가 쓰기 허용되는 것으로 추정).

- `helper/egdesk-turn-steer-contract.test.mjs`: "고정 안 된 버전" 예시를 0.171.0-alpha.14로 변경. 0.171.0-alpha.13은 이제 고정돼서 steer를 한 번의 프로브에서 읽는다. 기대값은 그대로.
- `helper/egdesk-native-launcher.test.mjs`: 가짜 0.171 CLI가 실제 바이너리처럼 프로브가 읽는 실제 스키마 파일도 쓰도록 변경. 기대값은 그대로.
- `scripts/real-engine/codex-qa-isolation-check.mjs` (+시험, 새 파일): 위 점검. 기본은 DRY이고 `--run`일 때만 실행.
- `scripts/real-engine/fixtures/native-schema-0.171.0-alpha.13/`: 13개 스키마 파일.

소유 범위 밖 파일: `egdesk-native-reader.mjs`는 맡은 "맥락 읽기 계약"을 열려면 필요한 최소 수정이었다. launcher, steer 시험은 capabilities와 probe의 시험이다.

## 남은 위험
- 정확한 버전 고정이라, 다음 자동 업데이트(예: alpha.14)가 오면 다시 닫힌다. 그때 할 일은 세 가지다.
  - `node scripts/real-engine/codex-qa-isolation-check.mjs --codex-bin <bin> --person-home --out <dir> --run`
  - 스키마 고정본을 다시 생성
  - 버전 추가
- 사람의 전역 지침 파일(~/.codex)이 엔진에 들어가는 문제와, 사람 MCP 서버 10개가 프로세스 수준에서 시작되는 문제(11/25 관찰)는 이 계약 밖이다. 스레드 수준에서는 MCP가 꺼진 것을 확인했다.
- `capabilitiesOf().ephemeral`이 이제 참이라 Codex에도 '기록 없이 시작'이 열린다. 0.171의 ephemeral fork 거부는 c24·c25에서 대응돼 있다.
- Reader 수정은 실제 엔진에서 전체 흐름으로 돌려 보지 않았다.
- 점검 1회에 약 3분이 걸린다(대부분 app-server와 MCP 시작).
