## 확인과 추정 구분

- 실제 빈 첫 화면의 관찰에는 요소 80개, 진짜 입력칸은 `<textarea role="combobox">` 하나. `nav.type=submit/image`인 요소는 0개였다. 후보 41개와 루프 제어 5개로 기록의 46개와 일치한다.
- `person_target_1`은 GET 제출 버튼이 아니라 `검색`이라는 **모드 선택 라디오**다. 후속 질문의 후보는 순서대로 라디오 그룹, 검색 모드 라디오, 다른 모드 라디오. 진짜 제출 버튼을 기다리는 동안 동명 요소를 누르라고 사람에게 넘긴 셈이다. 관찰에 라디오의 선택값은 없어 현재 선택 여부를 이용할 수 없다.
- 기준 빌드에 가짜 카드와 실제 첫 관찰, 측정값 형태의 결정 답(첫 단계 `needs_free_text` .68, 칸 .25, 해당 라디오 .97)을 넣어 `createDirectBrowserEntry → runBrowserReflex`로 재생: `paused/human_step`, 입력·이동 모두 0회, `field_text` 호출 0회. 확률의 모양은 실측, 상위 두 후보의 구체적 배치는 재생 가정이다. 원인은 코드로 확인: 후속 질문이 `human_step`으로 먼저 반환하여 바깥 진입의 `uncertain → undecidedField → pickFieldText`에 도달하지 못한다.
- 2a: 기존 코드에서 **증명된 일반 GET 제출 버튼은 이미** `options[].item.readOnly=get_form`이며 `withheld`나 `personOnly`에 들어가지 않는다. POST·위험 어휘는 그 증명을 얻지 않는다. 빈 첫 화면에 제출 버튼을 추측해 만들거나 모든 모드 라디오를 목록에서 지우지 않았다. 동명 라디오가 실제 요청의 목표일 수 있기 때문이다.

## 2c: 권한을 넓히지 않음

- `egdesk-page-tools.mjs`의 `egdesk_card_type`은 가드된 채우기를 한 뒤 캐시된 관찰을 무효화한다. 이후 작업 루프에 전달하는 동일 턴·문서·칸별 성공 영수증은 없다. `typedTexts`는 현 `runBrowserReflex` 호출 안에서 fill이 성공할 때만 누적되며, 제출 주소의 파라미터 **값**과 비교한다.
- Firefox 자식의 `lastGuardedFill`은 액터 안에서 후속 키 입력을 제한하는 ref/node 쌍이지 작업 루프의 제출 권한이 아니다. `navigationFacts`도 GET 주소와 필드 **종류**만 반환하며 쿼리 파라미터와 입력 ref의 대응, 마지막 편집 주체는 전달하지 않는다. 따라서 페이지 현재값 또는 텍스트 일치만으로 직전 대화도구의 글이라고 단정할 수 없다. 자동승인 범위를 넓히지 않았다. 실제 32.7초 Claude 턴의 정확한 중단 사유는 추정이다.
- 소유자 검토 항목: 턴·카드·문서·칸에 묶인 성공 영수증, 사람/페이지 편집 후 무효화, 해당 GET 폼 파라미터와 관찰 ref의 대응을 새로 증명할지. 별도 설계 전에는 `card_type`으로 친 텍스트를 `typed_search`의 근거로 쓰지 않는다.
