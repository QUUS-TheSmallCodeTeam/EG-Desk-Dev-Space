## 19:44 실창 사례의 5번 [코드로 확인]

`reflex-5`의 숫자는 결정 횟수가 아니라 `codex-browser-tool-provider.mjs`의 `reflexScope.callTool` 호출 순번이다. 1 observe, 2 fill, 3 observe, 4 navigate. 4의 `postcondition-unverified`는 `SUCCESS_STATUSES`에 없으므로 provider가 성공=false를 반환하고 `callTool`이 예외를 던진다. `runBrowserReflex`의 `act`는 navigate의 `meta.landed()`로 들어간다.

- **5 = `egdesk_browser_wait({cardId, for:'load', timeoutMs:5000})`**. 결정 모델이 고르는 단계가 아니다. 닫힌 타임라인에서 이름이 `tool`로 나와도 실행 경로로 특정된다. 6은 `landed`의 fresh observe, 7은 결과 URL을 확인한 뒤의 보통 `load` wait(10000ms), 8은 다음 반복의 observe다. 5번 실패 뒤에도 `landed`가 관찰할 수 있는 까닭은 5의 예외만 잡기 때문이다.
- 헬퍼 `waitForCondition`은 `kind:'observe', options.wait`로 카드에 요청한다. 미확인 navigate의 `pendingTransition.priorDocumentId`를 `notDocumentId`로 보낸다. `sendToUi`와 카드 바인딩 확인을 거쳐 `toolObserve`가 그때 카드의 **top browsingContext.currentWindowGlobal.getActor('EGDeskBrowserAgentRuntime').sendQuery('snapshot', …)**를 호출한다. `EGDeskBrowserAgentRuntimeChild.waitThenSnapshot`은 `this.document`를 고정하며 `notDocumentId`와 같으면 `load` 성공을 허용하지 않는다. 이 액터는 다른 WindowGlobal의 새 문서를 뒤따라가지 않는다.
- 기존 카드의 `whenToolWindowGlobalReady`는 닫히지 않은 *현재* 전역이면 충분했다. navigate가 반환된 뒤 아직 새 문서가 커밋되지 않은 구간에는 떠나는 전역도 해당한다. `AbortError`가 오면 관찰은 한 번 재시도하지만, 응답·거절 모두 오지 않으면 헬퍼가 15초 뒤 `BROWSER_UI_TIMEOUT`을 낸다. 5000ms는 문서 안의 조건 시간, 15000ms는 UI 응답 시간으로 서로 다르다.
- **추정**: 19:44의 15004ms는 옛 문서 쿼리의 응답 또는 거절이 헬퍼까지 돌아오지 않은 경우와 일치한다. 제공된 이벤트에 당시 WindowGlobal ID, 액터 수신·종료 시각이 없어 어느 홉에서 응답이 사라졌는지는 확인 불가하다. 전체 시간이 단축되었다는 실창 측정값도 아직 없다.

## 변경과 검증

- `helper/egdesk-browser-tool-runtime.mjs`: 미확인 navigate 때 관찰에 이미 있는 Gecko `innerWindowId`도 기억한다. 이 이동 뒤 `load` wait에만 보낸다. 일반 observe, idle, 선택자, 입력은 그대로다.
- `overlay/JS/eg-desk-surface.uc.js`: 카드의 기존 공유 20ms 폴러에서 그 전역만 제외한다. 대체 전역이 이미 있으면 즉시 진행한다. 새 전역에서 본래 `notDocumentId` 조건을 유지한 채 남은 시간만 기다리고 경과시간에 교체 대기분을 포함한다. 전역이 끝내 안 바뀌면 남은 0ms로 현 문서를 검증해 timeout으로 끝낸다. 전역 자체가 없거나 응답이 유실된 경우의 거절·상한도 유지한다. 권한, lease, 사이트·사후조건 및 최종 snapshot 검증은 그대로다. 이동이나 입력을 재전송하지 않는다.
- `scripts/egdesk-browser-tool-transport.test.mjs`: 가짜 카드와 시계에서 400ms에 교체될 때 옛 액터 요청 0회, 새 액터 1회, 10초 중 9600ms만 전달, 전체 경과 400ms. 미교체 대조군은 10000ms가 지나서만 옛 문서를 즉시 한 번 샘플링해 timeout. 400ms는 **합성 시험값**이다.
- `helper/egdesk-browser-tool-runtime.test.mjs`: 이전 UUID와 Gecko 전역 ID 모두 wait에 전달, 새 문서 확인 뒤에만 후속 입력 성공. `helper/egdesk-browser-task-tool.test.mjs`: 가짜 결정 답과 GET 검색 카드로 원래 8개 호출 순서 및 5번의 `load/5000`을 고정했다.
- 단독: 런타임·전송·reflex 162/162, 태스크 도구 18/18. 게이트 원본 `$L/evidence/gate-l11a2/full.tap`.

## Main 실창 확인

1. 통합 코드가 로드된 뒤 기존 Codex 대화 방식에서 DuckDuckGo 검색 결과 카드에 종전과 다른 검색어로 “덕덕고 카드에서 슈렉 검색해줘” 요청. 제출 1회와 실제 결과 표시를 확인한다. 결과 페이지에서 다른 검색어로 한 번 더 반복한다.
2. 해당 턴에 `node scripts/egdesk-turn-timeline.mjs --browser --engine codex --last 2 --rows` 실행. 4가 `postcondition-unverified`인 턴에서 5가 `wait-condition-met`, 보통 페이지면 1초 안팎이고 15초 `BROWSER_UI_TIMEOUT`이 없는지 확인한다. `done`만으로 통과 처리하지 않는다. 4에서 이미 검증되면 별도 복구 경로를 거치지 않으므로 구분한다.
3. 남은 제한: 실제 제3자 페이지의 로드 완료가 늦으면 조건 시간까지 갈 수 있다. Gecko ID가 없는 스냅샷은 기존 경로, 새 문서 관찰 없이 조작 성공으로 승격하지 않는다. 15초가 재발하면 5번의 전역 ID와 카드 응답 시각부터 분리해서 확인한다.
