# L1 a1: 브라우저 작업 단계 줄(채팅)과 카드 강조·설명 (플래그 뒤, 표시 전용)

브랜치 `lane/a1-steps-ui` (기준 c37ab23), 커밋 `4d3e469`. 작업 사본 `$L/wt-l1-a1`.

## 한 일
1. **채팅 단계 줄**: 한 대화 안에서 브라우저 작업 단계가 생긴 시점에 맞춰 메시지 사이에 끼워 넣는다. 보통은 사용자 메시지와 답 사이다. 블록은 작업(taskId)별로 하나이고, 5줄 이상이면 요약 줄과 마지막 줄만 보이게 접힌다. 접힘은 이 화면에서만 기억한다.
   - 배치는 기존 '사용자가 Browser를 직접 조작 중' 알림(`appendControlNotices`)과 같은 시간 기준 방식이다. 함수 끝에 `appendBrowserSteps(until)` 한 줄을 붙였다.
   - 그래서 응답 중일 때는 '작업 중' 말풍선 바로 위에 쌓인다.
   - 기존 스크롤 동작(L1 u5)은 건드리지 않았다. 맨 아래에 있으면 계속 따라가고, 위를 읽는 중이면 위치를 지킨다. 단계 줄은 `chat-message`가 아니라서 기준점(anchor)이 되지 않는다.
2. **카드 강조·설명**: 카드가 실행한 Agent 요청마다 카드 본문 왼쪽 아래에 짧은 설명을 약 2.6초 띄운다. 페이지가 그대로면 대상 요소 둘레에 테두리를 약 1.4초 그린다.
   - 결정 모델의 반사 단계와 대화 모델의 도구 호출이 같은 표시를 쓴다.
   - 받는 쪽: 카드의 기존 기록 이벤트 `egdesk:browser-agent-action`에 리스너를 달았다. `source: 'model-tool'`만 표시한다.
   - 대상 위치: 요청의 관찰 bounds(`guard.target.bounds`)를 먼저 쓴다. 없으면 같은 문서에 대한 직전 관찰(observe 응답 snapshot)의 같은 ref bounds를 쓴다.
   - 테두리를 그리지 않는 경우: 행동 뒤 문서가 바뀌었거나 이동(navigate)이었거나 거부된 경우. 이때는 설명만 띄운다.
   - 좌표: 관찰 viewport 기준 퍼센트로 잡아 기존 대상 점(`.egd-browser-agent-target`)과 같은 축척을 쓴다.
   - 누가 했는지: 결정 모델과 대화 모델은 요청의 callId로 가른다. Browser provider가 반사 단계에 `<call>.reflex-<n>-<uuid>`를 붙이기 때문이다(codex-browser-tool-provider.mjs reflexScope). 대화 모델 이름은 그 요청 방의 엔진(Claude/Codex)이다.
   - 입력한 글자와 필드 값은 쓰지 않는다. 라벨과 동작 종류만 쓴다.
3. **브리지의 받는 자리**: `helper/egdesk-browser-steps-channel.mjs`(새 파일).
   - 런타임 쪽: `decisionContext.browserSteps.publish(step)`을 제공한다. 플래그가 꺼져 있으면 아무것도 보내지 않고 false를 돌려준다.
   - 같은 모양의 원시 프레임(`type: 'browser.task.step'`)을 런타임이 emit으로 직접 보내도 `broadcast()` 첫 줄에서 다시 거른다. 플래그가 꺼져 있으면 버리고, 켜져 있으면 다시 정리한다.
   - 번호 붙은 chat.event(`browserTask.step`)는 절대 버리지 않는다. 버리면 seq에 빈칸이 생기기 때문이다. 오버레이 reducer가 run.browserSteps로 읽는다.
   - `/v1/state`의 capabilities에는 켜져 있을 때만 `browserSteps: true`가 붙는다. 오버레이는 이 값이 있을 때만 단계 줄과 카드 표시를 그린다.
4. **새 플래그**: `EGDESK_BROWSER_STEPS_UI=on`(기본 꺼짐). 꺼져 있으면 화면과 송신 모두 이전과 같다.

## 런타임(L5)이 쓸 계약
```
this.decisionContext?.browserSteps?.publish({
  threadId | clientThreadId,   // 방(run.clientThreadId와 같은 값)
  taskId, seq,                 // 작업과 단계 순서(정수 ≥ 0). 같은 taskId+seq는 덮어씀
  cardId?, op,                 // op: fill|click|press|select|scroll|navigate|observe|wait|submit|done|blocked|handoff
                               //     (egdesk_browser_* 이름, TYPE_TEXT/CLICK 같은 대문자도 받음)
  target?,                     // 대상 라벨(문자열 또는 {label}), 60자로 자름
  valueName?,                  // 값의 '이름'(예: '검색어'). 값 자체는 보내지 말 것(보내도 버림)
  key?, direction?,            // press의 키, scroll의 방향(down|up|bottom|top)
  ok?, ms?, by: 'decision'|'model',
  status?, reason?,            // 이어받기: op 'handoff' 또는 status needs_value|low_confidence|needs_user|human_step|handoff
  ts?                          // 없으면 브리지 시각
})
```
- 또는 run이 있을 때 `this.emit(run, 'browserTask.step', 같은 필드)`도 된다. 이 경우 저장되고 기록 재생에도 나온다. 시작 전 단계(preRun)는 conversationId가 없어서 reducer가 받지 못하므로 publish 쪽을 권한다.
- 배치는 시간(ts)으로 한다. 단계 ts가 답 메시지의 시작 시각보다 앞서면 답 위에 놓인다.

## 남은 문제
- 런타임 발행(L5)이 아직 없다. 채팅 단계 줄은 L5가 `decisionContext.browserSteps.publish`(또는 chat.event)를 보내야 나온다. 카드 강조·설명은 L5 없이도 플래그만 켜면 모든 Agent 도구 요청에 나온다.
- 결정 모델과 대화 모델은 callId 형식으로 구분한다. L8이 반사 단계 callId 형식을 바꾸면 모두 대화 모델로 보인다. 오래 쓰려면 요청에 명시 필드(예: `actor: 'decision'`)를 두는 게 맞다(L8 몫).
- 원시 프레임 단계는 화면 메모리에만 남는다. 다시 불러오면 사라진다. 기록에 남기려면 L5가 run이 있을 때 chat.event로도 보내야 한다.
- 카드 테두리는 행동이 끝난 뒤(기록 시점)에 그려진다. 같은 페이지에서 입력하거나 누른 경우에만 의미가 있다. 이동하는 클릭은 설명만 뜬다. 행동 직전에 미리 보여 주려면 권한·리스 경로(`browserToolDispatchOnce`)를 손대야 해서 하지 않았다.
- 채팅 블록의 '누가'는 색만 다르고 아이콘은 하나다. 결정 모델 전용 표시(아이콘이나 배지)는 디자인 결정이 필요하다.
- `EGDESK_UPPER` 묶음에는 넣지 않았다. 켜는 방법은 지금 개별 플래그뿐이다.

## Main이 실제 창에서 확인할 절차
1. 통합하고 브리지를 `EGDESK_BROWSER_STEPS_UI=on`(+ L5·L8 플래그)으로 다시 띄운다. 오버레이 resources를 프로필에 다시 복사한다(새 모듈 `EGDeskBrowserStepsView.sys.mjs`).
2. `curl -s http://127.0.0.1:39218/v1/state | jq .capabilities.browserSteps` 결과가 `true`인지 본다.
3. 카드: 브라우저 카드에 이번 대화 조작 허용을 켜고, Claude에게 "이 카드 검색칸에 우산 입력해줘"처럼 시킨다. 카드 왼쪽 아래에 `Claude · 검색에 입력`이 뜨고 검색칸에 테두리가 잠깐 생기는지 본다. 결정 모델 경로로 돌면 `결정 모델 · …`이 뜬다.
4. 채팅(L5 연결 뒤): 같은 요청에서 사용자 메시지와 답 사이에 `브라우저 작업 · 결정 모델 N단계 …` 블록이 생기는지 본다. 응답 중에는 '작업 중' 말풍선 위에 한 줄씩 쌓이는지 본다. 5단계 이상이면 접히고 `N단계 더 보기`로 펼쳐지는지 본다.
5. 대화를 위로 올려 읽는 중에 단계가 와도 화면이 튀지 않는지, 맨 아래에 있으면 계속 따라 내려가는지 본다.
6. 플래그를 끄고 다시 띄우면 단계 블록, 카드 설명, 테두리가 하나도 없는지 본다.
