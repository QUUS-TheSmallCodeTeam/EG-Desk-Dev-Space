## Runner API
`runProcedure({procedure, cardId, values, fromStep, confirmed, tools, decide, signal, onStep, run, clock}) -> {status, stepId?, index?, code?, done, ...}`
- tools = `{callTool(name,args)}` (실제로는 reflexScope(run,event,cardId).callTool: 가드 도구 그대로).
- decide({step, goal, snapshot, elements, candidates, change}) -> ref | null. 기본 구현(도구 쪽)은 buildReflexCandidates + decideReflexStep, 정답이 act일 때만 ref.
- onStep(run, event): taskStepEvent 형태 + activity start/stop 프레임(withBrowserTaskActivity). 끝 프레임 status는 done/needs_confirm/needs_value/human_step/cannot_proceed, code는 confirm_needed/needs_value/person_only_controls 등 (browserStepFor가 handoff/blocked로 매핑).
- 흐름: bindProcedureParams -> 남은 단계의 누락 값은 동작 전에 needs_value(params 목록) -> fromStep 없고 카드 host가 start.host와 다르면 가드 navigate(거절 코드 그대로 cannot_proceed) -> 단계별: person이면 human_step, confirm이고 confirmed에 없으면 needs_confirm(동작 전), 그다음 새로 observe, 라벨(trim/공백/대소문자)+role 정확히 1개면 코드 매치, 아니면 decide 1회, 그래도 없으면 cannot_proceed target_not_found.
- 검증: fill/select = target-value, navigate = url, 링크 클릭 = reflexActionArgs navigate, expect url/visible-text/target-value 클릭은 그 postcondition, 나머지 클릭은 NAMED_CHANGE(c20 named press 취급). press는 Enter/Space에 postcondition(expect 또는 현재 값).
- STALE(BROWSER_OBSERVATION_STALE/TARGET_STALE)이면 다시 observe 후 재매칭, 최대 3회 재관찰(CHANGE_LOOKS) 후 cannot_proceed page_changing. 재관찰 시 summarizeChange 결과를 decide에 change로 전달. user-hold는 human_step user_hold.
- 사람 몫 예외: 라벨이 비밀번호/OTP/카드번호/로그인 어휘이거나 classifyAction이 grant면 human_step. confirm 표시 없는 pay/delete 분류 클릭은 needs_confirm(결제/삭제)로 막음.

## 채팅 도구 (EGDESK_BROWSER_PROCEDURES=on 이고 procedures 호스트가 있을 때만 제공)
- `egdesk_browser_procedure_list {}` -> {status:'ok', procedures:[{id,name,host,stepCount,paramNames}]}
- `_run {procedureId, cardId?, values?, fromStep?, confirmed?}` -> runner 결과 + procedureId, name, cardId
- `_save {name?, cardId?}` -> captureDraft({clientThreadId, cardId, name}) 후 save. 결과 {status:'saved', id, name, stepCount, paramNames, personSteps, confirmSteps}; 초안 없으면 code nothing_to_save
- `_update {procedureId, name?, removeSteps?, setDefaults?, setConfirm?}` -> {status:'updated',...}. 민감 param 기본값 설정 거부(param_sensitive), 쓰이지 않게 된 param 제거, 단계가 0개가 되면 거부.
- Codex/Claude는 같은 page tools provider specs()를 읽으므로 둘에 동일하게 제공됨. 모든 spec description과 모든 응답 forYouOnly에 같은 규칙문을 넣음.
- 규칙문(제안 문구, PROCEDURE_RULE 한 곳): "Procedure run rules. needs_confirm: ask the person to confirm that step, then call egdesk_browser_procedure_run again with fromStep = that stepId and confirmed = [that stepId]. needs_value: ask the person for the missing value (params), or infer it from the conversation, then call run again with values. human_step: tell the person what is left for them on the page; do not retry. cannot_proceed: say which step stopped (stepId, index) and why (code) in everyday words. Never claim a step ran when it did not: only the steps in done ran."

## 위험, 미완
- 플래그 off일 때 도구는 제공되지 않지만, pageToolBrowserEquivalent는 env를 모르므로 4개 이름을 항상 navigate 동등으로 매핑함(제공 안 된 이름은 호출되지 않아 영향 없음).
- 사람 몫 판별용 정규식은 reflex의 SENSITIVE_LABEL(비공개 const)과 같은 어휘 + 로그인 어휘를 runner에 로컬 복제함. reflex의 export는 L59와 충돌 우려로 수정하지 않음.
- L55 changed-page 결정 모델 경로(changeEvidence 질문)는 직접 호출하지 않고, 재관찰 + 라벨 재매칭 + summarizeChange를 decide에 전달하는 방식으로 대체.
- press(Enter)는 saved expect가 changed면 현재 값 target-value를 postcondition으로 쓰므로 Enter가 페이지를 이동시키면 unverified로 실패할 수 있음(URL expect로 저장 권장).
- 실제 창, 실제 모델 검증은 하지 않음(fake 도구/관찰만).
