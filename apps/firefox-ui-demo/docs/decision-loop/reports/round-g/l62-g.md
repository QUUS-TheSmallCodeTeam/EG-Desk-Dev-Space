## 위험 / 가정
- 실제 앱에는 아무것도 실행하지 않았다(구조 테스트만). 러너 본체는 미실행 상태.
- 시드 절차의 target(role textbox/button)과 응답 형태(`{procedure}` 또는 본체 직접, `{procedures}` 또는 배열, `{draft}`)는 계약에서 추정. L59 실제 응답과 다르면 run-proc.mjs의 http 파싱 몇 줄만 고치면 된다.
- clientThreadId 탐색은 /v1/state chat.runs 또는 /chat/history/threads 추정. 실패 시 EGDESK_QA_THREAD로 지정. capture의 cardId는 DOM id(egd-browser-card-N)를 그대로 보낸다. 다르면 조정 필요.
- P6는 사람이 비밀번호를 입력하는 캡처 경로 대신 시드로 sensitive 단계를 만든다(에이전트 journal에는 사람의 입력이 안 남음). 정규화가 raw 비밀번호 값을 걸러내는지는 별도 확인 대상.
- P1~P3, P7은 채팅 모델 의존이라 문구 정규식(answerRe)은 첫 실행 후 조정될 수 있다.
- 케이스가 만든 절차는 종료 시 DELETE(사용자 저장소 보호). 보존하려면 EGDESK_QA_KEEP=1.
