## 컨트롤 위치
- 게이트: `bridgeProceduresField` -> `state.codex.proceduresUi` (`/v1/state` capabilities.browserProcedures === true). 꺼지면 툴바 버튼은 DOM에서 제거, 패널 제거, 저장 버튼 미생성, 브리지 메서드는 요청 전에 return.
- "절차로 저장": 채팅의 브라우저 단계 블록 헤더 (접기 토글 왼쪽). 조건: 작업 중이 아님 + 성공한 act 단계 1개 이상 + cardId 존재 (`procedureSaveOffer`). 누르면 POST /v1/procedures/capture {clientThreadId, cardId} -> 편집기(초안). 저장은 POST.
- "절차": 채팅 카드 창(캔버스) 헤더 우측 액션 영역 맨 앞. 누르면 목록 패널(GET /v1/procedures): 실행, 편집, 삭제(인라인 확인).
- 편집기: 이름, 시작 주소(읽기 전용), 단계(번호, op, 대상, 기본값 입력, 실행 때 확인, 위/아래/삭제), 민감 값은 "실행 중 직접 입력"만 표시. 저장은 기존 절차면 PUT, 초안이면 POST. 이름/단계 검증 실패 시 저장 비활성.
- 실행 폼: 기본값 편집 가능. "실행"은 활성 DM에 `setDraft` + `sendMessage()`(기존 전송 경로)로 메시지 전송. 채팅이 작업 중이거나 입력창에 글이 있으면 보내지 않고 안내.
- 패널은 화면 고정(우상단) 하나를 공유. 편집 중 입력 포커스는 재렌더로 끊기지 않게 입력은 제자리 갱신.

## 가정, 위험
- L59 라우트 응답 모양은 계약 문구만 보고 관대하게 읽음: 목록은 배열 또는 {procedures|items}, 단건은 procedure 또는 {procedure}, capture는 {draft}. 실제 응답과 다르면 `procedureOpenList/Load/Capture`의 한 줄만 고치면 됨. lane/g-proc-store는 merge하지 않음.
- 실제 창에서 렌더링/클릭은 확인하지 못함 (라이브 앱을 건드리지 않는 규칙). fake DOM이 아니라 소스 수준 테스트 + 순수 모듈 단위 테스트만 있음.
- 실행 메시지의 값에 ", "가 있으면 모델 해석이 애매할 수 있음 (개행은 공백으로 정리).
- 파라미터 값 편집은 이름으로 연결되므로, 같은 param을 쓰는 단계가 둘이면 두 필드가 같은 값을 공유.
- 도킹된 오른쪽 패널(HUD) 채팅에는 "절차" 툴바 버튼이 없음 (캔버스 채팅 카드 헤더에만). 저장 버튼과 패널은 HUD에서도 동작.
- 단계 블록의 "마무리됨" 판정은 작업 중이 아님 + 성공 act 존재로 근사.

## 추가 수정 (통합 게이트 회귀)
원인 3가지, 모두 내 커밋에서 생김:
1. `emit()`에 `renderProcedurePanel()` 한 줄을 넣어 하네스(함수만 추출해 돌림)에서 ReferenceError, 그리고 agent-identity 테스트가 요구하는 `renderCodexActivityPanel();` 바로 다음 줄 형태가 깨짐. 수정: emit 원복, 대신 브리지 설치 직후 `state.codexBridge.subscribe(() => renderProcedurePanel())`로 연결 (게이트가 꺼지면 아무것도 그리지 않음).
2. CSS에 하드코딩 색(var 폴백의 #fff, rgba 그림자 등) 26개. 수정: 폴백 제거, 토큰만 사용(`--egd-surface-elevated`, `--egd-outline`, `--egd-chrome-shadow`, `--egd-primary`, `--egd-on-primary`), z-index는 store panel 다음(100116).
3. disabled 불투명도 `.4` 하드코딩. 수정: `var(--egd-opacity-disabled)`.
(중간에 정규식 치환이 파일 전체의 outline-variant를 건드린 사고가 있었으나 base에서 CSS를 다시 만들어 내 블록만 삽입, 기존 규칙 변경 없음.) 기존 테스트는 수정/완화하지 않음.
