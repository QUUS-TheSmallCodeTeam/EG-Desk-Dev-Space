# L48 (e) 카드 sleep v2 보고

커밋: a24be764 (브랜치 lane/e-card-sleep-v2). 기능은 기본 OFF 유지 (egdesk.perf.sleepHiddenCards = "on").

## 규칙 (EGDeskCardSleep.sys.mjs)
뷰포트 대비 보이는 면적 비율(area)과 유효 줌(scale = 화면 폭 / 레이아웃 폭)을 추가.
- sleep: scale < 0.45 (글자 못 읽는 줌, 크기 무관) 또는 (보이는 폭<560 또는 높이<350) 그리고 area < 20%.
- wake: (scale 모름 또는 >= 0.55) 그리고 ((폭>=640 and 높이>=400) 또는 area >= 25%).
- 히스테리시스: 면적 20/25%, 줌 0.45/0.55, 크기 560x350/640x400 유지. 도구 grace 10s, sleep 2s, wake 0.3s 그대로.
- 근거: c12 (1070x398)는 뷰포트 1440x900 기준 약 33%라 면적 규칙으로 wake. 오버뷰(줌 0.376)는 scale<0.45라 sleep (CPU 절감 유지) 하되 마지막 프레임을 보여줌. 첫 번째 질문(전체가 보이지만 작게 그려진 카드): sleep하되 프레임이 있으므로 시각적 손실이 적음. 줌을 모르면(null) scale 규칙은 무시.

## 스냅샷
- sleep 직전 prepareSleep(비동기): browser.browsingContext.currentWindowGlobal.drawSnapshot({0,0,clientWidth,clientHeight}, scale, 'white') -> ImageBitmap -> canvas에 그려 browser 위(같은 parent, absolute, pointer-events none)에 올린 뒤 docShellIsActive/renderLayers=false.
- scale = min(1, 화면폭*dpr/레이아웃폭), 픽셀 예산 150만 px 상한. 그린 직후 bitmap.close().
- wake: 활성화 후 150ms 뒤 canvas 제거(width=0으로 백킹스토어 즉시 해제). 재페인트 전 흰 깜빡임 방지.
- 실패(드로우 없음/예외/null) -> 프레임 없이 기존처럼 sleep. 캡처 중 도구가 오거나 카드가 닫히면 토큰으로 취소(sleep 안 함). 잠든 채 닫히면 onForget으로 해제(DOM과 함께 제거됨).
- UI 문구 추가 없음.

## 진단 (d)

## Main 실창 검증
1. 기본값 확인: pref 없이 cardSleepReport() 의 enabled=false.
2. pref을 "on"으로 설정 후 (재시작 필요, installCardSleep은 시작 시 1회) 브라우저 카드 8개.
3. 오버뷰 줌 0.376: 약 3초 뒤 cardSleepReport() 에서 대부분 asleep:true, framed:true, 화면에는 흰 상자 대신 마지막 화면이 보여야 함. CPU 약 2%대.
4. 줌 1.148로 확대: c12 같은 주 카드(area>=25%, scale>=0.55)는 0.3~1s 후 asleep:false, framed:false, 라이브로 움직여야 함. 작아서 화면 가장자리에 남은 카드는 계속 sleep+프레임.
5. 카드 하나 sleep 중 에이전트 도구 호출 -> 즉시 wake. 잠든 카드 닫기 -> 오류/잔상 없음.
## 위험
- drawSnapshot 실제 동작/비용(Firefox 161, 대형 카드, 크로스 프로세스 iframe)은 실창 미검증. 8장 동시 캡처 순간 부하 가능(sleep 시점은 카드별로 2s 지연이라 분산됨).
- 프레임 canvas 위치는 browser.offsetLeft/Top 기준(부모가 positioned 아니면 어긋날 수 있음). 어긋나면 부모 구조 확인 필요.
- scale은 offsetWidth 대비 getBoundingClientRect 비율이라 카드 transform이 캔버스 줌인지 확인 필요(줌 1.148에서 scale≈1.148이어야 함).
- 프레임은 정지 이미지라 sleep 카드의 영상/애니메이션은 멈춘 화면으로 보임.

# 2차 수정 (Main 실창 피드백 반영), 커밋 c099a617

## 문제 1: 프레임이 안 그려짐
- 원인: drawSnapshot 첫 인자가 DOMRect 인터페이스인데 일반 객체 {x,y,w,h} 를 넘겨 TypeError 가 삼켜짐.
- 수정: rect 에 null 을 전달 (저장소의 EGDeskBrowserAgentRuntimeParent 주석 기준: null = 현재 보이는 top 문서 viewport, CSS px x scale). scale 은 화면 폭*dpr/clientWidth (상한 1, 150만 px 예산). 캔버스 크기는 반환된 bitmap 의 width/height 사용. (Gecko 소스 직접 확인은 못 함. 저장소 주석과 기존 호출 `drawSnapshot(null, 1, "white")`에 근거.)
- 첫 페인트 전 sleep: 문서가 로딩 중(webProgress.isLoadingDocument)이거나 캡처 실패면 sleep 하지 않고 다음 틱(0.5s)마다 재시도, CAPTURE_GRACE_MS=6s 가 지나면 프레임 없이 sleep(v1 동작).
- 진단: cardSleepReport() 항목에 lastCaptureError (문자열, 예: 'loading', 'no-window-global', 'TypeError: ...') 추가. 성공하면 빈 문자열.

## 문제 2: scale 이 캔버스 줌이 아님
- scale 을 state.zoom (캔버스 줌)으로 교체. 임계값: sleep < 0.5, wake >= 0.58 (히스테리시스; 0.6 에서 mostly visible 카드는 깨어남, 오버뷰 0.376 은 잠). 면적/크기 규칙은 그대로.
- report 의 scale = 캔버스 줌, innerRatio = 기존 element 비율(참고용, 판정에 사용 안 함).

## 테스트
egdesk-card-sleep.test.mjs 17개 중 17 통과 (줌 0.376/0.6/1.0/1.148 + 히스테리시스 0.48/0.52/0.55, 재시도/상한, 로딩 중 스킵, DOMRect 대신 null). uc.js 구문 OK. 전체 스위트 미실행.

## Main 검증
pref on 재시작 후: 시작 직후 6s 내 cardSleepReport() 에서 framed:true 로 바뀌는지, 안 되면 lastCaptureError 확인. 줌 0.6/1.0 에서 면적 큰 카드가 awake, 0.376 에서 전부 sleep + 프레임.
위험: null rect 는 페이지 줌(Ctrl+/-) 시 viewport CSS 크기가 clientWidth 와 달라 비트맵 해상도만 약간 달라질 수 있음(무해). 캔버스 오버레이 위치(offsetLeft/Top)는 여전히 실창 미검증.
