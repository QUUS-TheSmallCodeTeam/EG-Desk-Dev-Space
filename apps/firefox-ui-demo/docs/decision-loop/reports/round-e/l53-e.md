# L53-e 보고: Gemini 키 파일 대소문자 경로 문제

- 원인: 브리지가 기본 keyFile을 `path.join(dataDir,'settings',...)`로 비정규(대소문자 다른) 경로로 넘김. `isOwnedAndPrivate`가 `realpath.native(target) === target`을 요구해 실패하고, 오류는 `readKeyFileLine`의 catch에서 삼켜져 키가 없는 것으로 처리됨. JSON 스토어는 dataDir을 `realpathSync.native`로 정규화한 dir에서 파일 경로를 만들어서 문제가 없었음.
- 수정:
  - `helper/egdesk-decision-credential.mjs`: 새 옵션 `keyFileName`. keyFile이 없으면 스토어가 이미 정규화한 `dir`(realpath) 아래 파일명으로 기본 keyFile을 만듦. 파일명은 `[A-Za-z0-9._-]+`만 허용(경로 구분자 불가).
  - `helper/codex-bridge-server.mjs`: `keyFile: env || null, keyFileName: 'gemini-decision-key.txt'`.
  - 보호는 그대로: 심볼릭 링크 키 파일은 거부(O_NOFOLLOW+lstat). 스토어와 동일하게 심볼릭 dir 경로는 realpath로 허용(스토어와 같은 동작). 사용자가 env로 준 비정규 keyFile은 기존대로 거부.
- 다른 영향 위치: 비정규 dataDir이 `isOwnedAndPrivate`로 직접 가는 곳을 grep으로 확인함. 대부분(bridge-settings, budget, calibration, engine-profiles, briefing, private-json, chat/desk/profile/ontology/workflow, memory-evidence)은 dir을 realpath로 정규화한 뒤 사용해서 같은 증상 없음. `egdesk-engine-profiles.mjs:178`(target realpath 비교)과 `egdesk-board-agent-draft-config.mjs:16`은 코드 정독까지는 못 했음. 후자는 getDecisionApiKey를 받는 설정 읽기라 이번 버그와 무관해 보이지만 미확인. 수정은 하지 않음.
- 테스트(apps/firefox-ui-demo, 가드 포함): egdesk-decision-credential.test.mjs + egdesk-bridge-settings.test.mjs = 31 tests, 31 pass, 0 fail, 0 skipped. 새 테스트: `Data/settings` 생성 후 `data/settings`로 열기(기본 키 파일 발견), 심볼릭 키 파일 거부, 비정규 명시 keyFile 거부. 대소문자 구분 볼륨이면 case 부분만 건너뜀. 이 볼륨은 대소문자 비구분이라 실제 실행됨.
