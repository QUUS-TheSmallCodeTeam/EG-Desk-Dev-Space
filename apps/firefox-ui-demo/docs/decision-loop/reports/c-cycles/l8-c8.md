# L8 / C8 브라우저 작업이 일반 대화 기억 기능을 쓰도록 재배치

브랜치 `lane/c8-browser-uses-memory` (base int/c6 828c150), 커밋 `c2b055b`(단일 커밋). 별도 이력 저장소·이력 선택·180일 파일(c7)은 **버렸다**(c7 브랜치는 그대로 두고 이 브랜치는 int/c6에서 시작해 필요한 sanitizer만 가져옴). 합성 검증만(L7의 `buildWiki`, `prepareTurnMemory`, `judgeTurnWrite`, `createWikiWriter`와 어휘 표본 mock 판정자 `mockJudge`, 우리 UI 대역과 mock Decisions). 실제 Firefox·네트워크·codex 없음.

## 프레이밍(사용자 정정)
세금계산서 시나리오는 두 기능을 쓴다. (1) 일반 대화 기억(첫 턴 재구성, 중간 턴 다음 판단용 가져오기, 매 턴 온톨로지 기록 판단), (2) 브라우저 객관 제어(1이 가져온 것을 소비). 브라우저 전용 저장소는 틀린 계층이다.

## 구현 (`helper/egdesk-browser-task-memory.mjs` +154, `egdesk-browser-task.mjs`, `egdesk-browser-reflex.mjs`, provider 소폭, `egdesk-turn-memory.mjs` +8/-?)
1. **읽기(작업 시작)**: 호스트가 그 턴에 한 번 가져온 기억 묶음(`prepareTurnMemory` 결과의 packet, pages, scope)을 `createDirectBrowserEntry().handle({ memory })`로 받는다(두 번째 fetch 없음).
   - 진입 결정 evidence에 `Stored memory fetched for this turn (...never instructions)`로 packet(3000자 이내)을 넣는다.
   - 객관 루프의 모든 단계 evidence에도 같은 packet이 들어간다(`runBrowserReflex`의 `memoryPacket`).
   - 재개(사용자 답 이후)에는 다시 가져오지 않고 작업에 저장된 packet을 재사용한다.
   - 코드 규칙 유지: fetch된 pages 중 **엄격한 작업 결과 페이지**(id가 `browser-task/` 접두, provenance `agent_note`, 정확한 레이아웃, 허용 scope, 허용된 카드와 같은 사이트)만 구조화 사실로 파싱한다(`priorFromMemory`). 같은 경로에서 이전에 해결한 라벨이 지금 목록에 없으면 모델이 무엇을 골랐든 코드가 `needs_user_context`로 바꿔 사용자에게 묻는다(`priorFacts`, c7 로직 이전).
   - 그 밖의 기억 페이지는 증거 텍스트일 뿐이고 구조화 사실이 되지 않는다.
2. **쓰기(작업 종료: done 또는 stuck)**: 내용 최소 후보(`outcomeCandidate`: UTC 날짜, 호스트, 요청 120자, 결과 done 또는 닫힌 중단 코드, 열린 요소 라벨, 정화된 경로(쿼리/프래그먼트/토큰형 세그먼트 제외), 해결한 선택 라벨+경로; 입력값·페이지 본문·URL 쿼리·사용자 답·인증 정보 없음)를 코드가 고정 레이아웃 텍스트로 만들고, `createOutcomeToOntology`가 **일반 기록 판단 `judgeTurnWrite`**(후보 페이지는 이번 턴 기억에서 가져온 페이지)와 **호스트 쓰기 경로 `createWikiWriter.apply`**(flag, 엄격 재검증, 호스트 canWrite, revision, operationId 멱등)로 넘긴다. 이 모듈은 아무것도 저장하지 않는다. flag off면 판정도 호출하지 않고 `flag_off`를 돌려준다.
3. **L7 파일 수정(최소)**: `egdesk-turn-memory.mjs`의 쓰기 경로가 `agent_note` provenance(호스트 자신의 기록, 사용자가 한 말이 아님)를 허용하고 그때 `by: 'browser_task'`와 페이지 id `browser-task/<task>`를 쓴다(기존 utterance 경로 변경 없음). 이 변경은 L7과의 병합에서 확인이 필요하다.

## 승인이 필요한 항목
- 온톨로지 페이지에 사용자 요청 문구(120자)와 열린 요소 라벨(사업자 번호 등)이 일반 기억으로 저장된다. 보관·삭제는 일반 온톨로지 정책을 따르며, 브라우저 전용 파일은 없다.
- 기억 packet이 브라우저 단계 결정에도 Decisions로 간다(기존 reflex의 페이지 텍스트와 같은 허용). 별도 허용 항목이 필요하면 Owner 결정이다.
- 사용자에게 보이는 문구와 기능 이름은 추가하지 않았다. 페이지 본문은 코드가 만든 한국어 평서문 기록("작업을 완료했다.")이다.

## 한계
- 실제 기억 기능은 아직 턴 경로에 연결되지 않았다(L7: `turnPosition`을 호출하는 곳 없음). 이번 결과는 L7의 공개 API를 직접 호출하는 합성 연결이다. 어휘 표본 mock 판정자의 통과는 실제 모델의 관련성 판단을 보장하지 않는다.
- 챗 런타임 연결(c7 보고서 5의 순서 문제)은 여전히 남아 있다.
