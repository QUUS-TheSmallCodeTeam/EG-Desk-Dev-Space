## 기억 층
**M1. 읽을 파일 미리 읽기 (`TURN_MEMORY_PREFETCH=files`) — 켜도 됨**
- 느끼는 것: "예산이 얼마야?" 같은 폴더 질문에 엔진이 파일을 읽으러 다니는 시간이 사라짐. 3쌍 평균 **−5.8초** (17.0→7.9, 13.3→9.6, 11.8→7.0), 엔진 도구 호출 1→0, 답 정확.
- 비용: 턴당 결정 호출 +1(0.3~0.45초), +1.2k~1.4k 토큰. 위험: 고른 파일이 틀리면 엔진이 지금처럼 직접 읽음. 결정 모델은 파일 **이름·크기·날짜**만 보고 내용은 엔진에게만 감.
- 모자란 것: 큰·무관한 폴더에서의 측정 1회(지금은 합성 폴더 3개). **당신이 정할 것: 켤지 (권고: 켠다).**

**M2. 기억 먼저 (`TURN_MEMORY_WRITE_FIRST` 묶음) — 실제 엔진 1회 뒤**
- 느끼는 것: 엔진이 "확정됐군요"라고 말하는데 기록은 확인 전인 어긋남이 사라지고, 말이 기록과 충돌·모순이면 그 상태가 엔진에게 먼저 전달됨. 새 화면·문구 없음.
- 실측: 결정 모델 부분은 **재생 11/11** (hard 실패 0, 요청 205~353ms, 10,523토큰). 턴당 +0.3~1.3초(제품 안에서는 재생의 약 2배, 최악 2.1초 대 예산 2.5초: 여유 얇음, 넘으면 오늘과 같이 진행). 실제 엔진: 추측·전달된 말·대조는 통과, **핵심 장면(자기 진술 → "응 맞아")은 엔진 정지로 한 번도 못 봄**.
- 모자란 것: 실제 엔진 `memory-first-v2` 1회(대화 8개). **정할 것: 그 1회 뒤에 켤지(권고), v4 문구를 기본으로 승격할지, 확인 문구 v2 대 v3(권고 v2).**

## 열린 항목 (기억과 행동 사이)
**O1. 열린 항목 해소기 (`OPEN_ITEMS`) — 정하면 켜짐**
- 느끼는 것: 대기 중인 승인·진행 중 작업·확인 대기 기록에 대해 "그냥 해", "음… 글쎄", 무관한 말을 코드와 결정 모델이 먼저 정리. 실측: 승인을 409ms 에 정리하고 "그냥 해"가 6.9초(끔 8.2초); 모호한 말은 아무것도 정리 안 함; 무관한 말을 해도 대기 질문이 유지된 뒤 실행됨. 기대 실패 1은 엔진이 `ls -la`(읽기)를 돌린 것(기대가 너무 엄격).
- 모자란 것: 같은 실행에서 엔진 정지 3건이 가린 장면, 실제 엔진 재확인. **정할 것: 정리 기준 0.85 와 "결정된 아니오" 상한 0.25(되돌리기 쉬운 값 하나)를 정책으로 받아들일지.**

**O2. 제안 등록부 (`PROPOSAL_REGISTRY`) — 실제 엔진 1회 뒤**
- 느끼는 것: 엔진이 "…할까요?"라고 한 제안과 "이 행동은 보류하고 먼저 보고"가 열린 항목으로 남아 "ㅇㅇ" 같은 짧은 답이 올바른 제안에 붙음. 문구 A 9/9 (두 말투 모두 1.0, 처리 후 0; 예전 문구는 .56/.82로 취약).
- 모자란 것: 보류 행동이 목록 삭제 한 종류뿐, 다른 종류는 합성조차 안 잼. 새 문구 없음.

**O3. 브라우저 열린 항목 (`BROWSER_OPEN_ITEMS`) — 실제 엔진 1회 뒤**
- 느끼는 것: 로그인 벽에서 멈춘 작업에 "했어", "다시 해줘", "그만해", "그 페이지에 뭐 있어?"가 올바르게 이어짐. 실측(12개 답변): 정답 8, 허용 2, 안전 미스 2, **틀림 0**, 중앙값 317ms.
- 모자란 것: 해소기와 옵션을 합친 측정(약 15k 토큰, 결정 모델만), 실제 엔진(abandon·ask-page는 엔진 정지로 확인 못 함). **정할 것: 위 두 측정을 먼저 할지.**

## 행동 층
**A1. 행동 먼저 (`DECISION_FIRST`) — 설정 토글만 정하면 켜짐**
- 느끼는 것: "테스트 돌려줘 / 빌드해 봐 / git 상태"에 엔진이 폴더를 훑으며 도구를 여러 번 쓰던 것이, 결정 모델이 명령을 고르고 EG-Desk 가 바로 돌린 뒤 엔진이 한 번 말하는 것으로 바뀜. 실측 3쌍 모두 빨라짐: **빌드 19.8→6.5초, 실패 시험 21.6→8.2초, 통과 21.1→6.5초** (결정 호출 16→7, 엔진 라운드 16→3). 3/3 기대 통과. 위험 낮음(안전한 스크립트 이름만 후보, 승인·위험 규칙 그대로, 바깥 파일 안 건드림).
- 모자란 것: git 머지(`git merge <브랜치>`)는 합성만. **정할 것: ① 설정 토글의 이름과 설명 문구(승인 필요; "폴더에서 만든 고정 설명이 결정 모델로 간다"는 안내 포함) ② `card` 모드(말 없이 카드만)는 대화 층 지름길이라 승인 필요 — 쓰지 않을지.**

**A2. 승인 빠르게 (`DECISION_FIRST_APPROVALS`) — 정책 승인 후 켜짐**
- 느끼는 것: 질문에 "그냥 해"라고 하면 엔진이 새로 해석하지 않고 코드가 대기 중이던 그 명령을 실행: **8.5→4.8초**. "아니 잠깐"(취소)은 3.3→3.7초로 차이 없음. 2/2 통과. 새 문구 없음.
- 모자란 것: 질문 단계 시간은 그대로(변동 안). **정할 것: 결정 모델이 읽은 짧은 승인(기존 `reply_runs_command`)으로 코드가 위험 명령까지 실행해도 되는지(승인 규칙·위험 바닥은 그대로 통과해야 함).**

**A3. 엔진 정지 감시 (`ENGINE_STALL_FIRST_EVENT_MS`) — 상한만 작동**
- 사실: 하루 동안 주 대화 정지(180초) 9건 + 고쳐 쓰기 정지 15건. 감시를 "첫 진행" 기준으로 고친 뒤 실제로 **30초에 잡았으나 재시도도 정지** → `ENGINE_STALLED` **65.8초**(다른 실행 71~74초 3건). 정지는 몇 분씩 에피소드로 옴.
- 모자란 것: 구제. 고쳐 쓰기 쪽은 11초(9초로 당기는 제안) 뒤 새 스레드를 같이 시작해 6건 중 5건을 구했음. 주 턴에도 비슷한 구제가 가능한지는 L5 c36 이 보는 중. 새 문구 없음.

**A4. 브라우저 루프 v2 — 거의 켜도 됨**: 5개 시나리오 5/5 (7.7~17.3초, 양식 제출 수정 확인), 제출 같은 되돌릴 수 없는 행동은 한 번도 안 함. 모자란 것: 같은 5개 한 번 더(표본 작음).
**A5. 브리핑 층 — 아직**: 판단 층 재생: 위치 0 실패, 적합 12/12, 커버리지 hard 2/6인데 원인은 **기대가 틀림**(표의 설명 칸이 줄 제한으로 보드에서 줄어 심판이 "미정"으로 읽음; 결정된 아니오 0). 모자란 것: 기대 수정 뒤 재생, 실제 브리핑 엔진 턴(오늘 1/2 통과, 분 단위 시간).
