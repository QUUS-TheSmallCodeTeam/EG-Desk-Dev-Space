## 2. Do v8's one-packet checks need a real send? No
The four expectations (`s1`/`s3b` `no-duplicate-bodies`, `no-memory-key`) read the engine's turn input (`seen.packets`: keys and body copies), which is built by code (`mergeTurnMemory` / `onePacketSelection` in the runtime). They depend on the Decision model only through (a) the context selection being attached (`decision.mode === 'on'`, a selection key present) and (b) the memory packet attaching. L7 c29 showed the Decision requests are byte-identical with the switch on and off, so the real model's answers for s1/s3b are the ones already recorded in v7b.
Checked by replay (no send): v8 plan, switch on, answers replayed from the real v7b run (`evidence/l2-c23/replay-v8-on.json`; only s10, s13, s14 are scripted). s1 and s3b use the real recorded answers (s1 relevance .99/1/.99 -> selection attached; s3b rel_0 1 -> attached; both runs had both keys). Result: all four pass with the switch on; with it off they are "not run" (judged only under the switch). Hard 79/80 on, 75/80 off; the others are s13/s14 (scripted, "not a model result") and one s13 miss below.
What is NOT measurable without the real engine: whether the engine follows the single packet's reference line (that is what the real-engine memory script held-v3/scale measures). Not a v8 check.
Condition: `no-memory-key` fails if a real answer ever left the selection unattached (no relevance, so no selection key) while a memory packet still attaches (then the memory key rides alone: product behaviour by design). That is determined by the recorded answers of s1 and s3b, which attach.

## 3. Finding in the replay (plan, not product)
`s13.fetched` (scripted answers, replay) fails: with real earlier steps replayed the scripted s13 fetch picks `sqlite-schema` and `quote/a-request` besides `pg-plan`. The expectation (`pg-plan` fetched, no quote page) depends on the scripted judge's choice in a changed state; with the real Decision the step's page set is decided by its answers and by what earlier turns already hold (receipts). This expectation is therefore only meaningful in a real send (and was already marked "not a model result" in the replay). v8 is pinned, so it stays; if the real run shows the page was already held (no re-send), that is a v9 expectation change, not a product defect.
