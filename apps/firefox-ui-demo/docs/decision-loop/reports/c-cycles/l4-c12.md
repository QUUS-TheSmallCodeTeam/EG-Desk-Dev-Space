### Decision model이 보는 것
- 멤버 `M1..`, 옵션 `P1..`(배치) / `A1..`(주의) 별칭, 그리고 닫힌 단어만: 옵션 종류, 거리(`in_view|near|far|very_far`), 방향, 누구 view 안인지, task 상태, requester/waiting, `ownerMustAct`, 카드 creator(`agent|user|shared|unknown`).
- 제목·본문·id·좌표는 나가지 않음 (테스트에서 wire 문자열로 확인).
- 답은 쓰기가 아님: chrome이 별칭을 풀고 **현재 장면에 대해 하드 규칙을 다시 확인**(`settle`)한 뒤에만 사용.

### 옵션 종류
- 배치: `reuse`, `in_requester_view`(requester가 대기 중 + idle일 때만 존재), `near_requester`, `beside_related`, `quiet`, `adjacent_area`
- 주의 재판단: `leave`, `point`(포인터 사실), `surface_near_requester`(Agent가 만든 movable 카드 + requester 대기·idle일 때만 존재)
- 판단이 없거나 확신 부족일 때 코드 기본값: `reuse → beside_related → near_requester → quiet → adjacent_area`. 기본값은 **어떤 view 안으로도 들어가지 않고, 카드를 옮기지 않음**.

## 5. 정직하게 남기는 한계

1. **오늘 제품에 "에이전트가 스스로 여는" 파일/결과 카드 경로가 없음.** `openVerifiedRunFile`(아티팩트 칩)과 `spawnResultCard` 둘 다 사용자 클릭으로 열림. 그래서 이번 소비자는 "에이전트 산출물을 사용자가 여는 순간"의 배치를 기록함. 요구사항의 "agent file work가 viewer로 열린다"를 실제로 만들려면 자동 열기 경로가 먼저 필요 (별도 결정).
2. **실행이 끝나면 heartbeat가 멈춤** → 사용자가 완료 후에 칩을 누르면 bridge는 `no-heartbeat`로 답하고 판단을 묻지 않음(창 쪽 기록만 남음). 완료 후 포인터 메시지도 같은 이유로 도착 경로가 없음. L3와 협의 필요.
3. **주의 재판단(`attentionRequest`)은 runtime·bridge·시뮬레이션까지만.** 제품에서 이를 호출하는 트리거(완료·승인 대기·idle 전환)는 아직 연결 안 함.
4. **포인터 사실의 소비자 없음.** heartbeat facts에 실리고 `pointerWriterPrompt`도 있지만 `egdesk-conversation-flow.mjs`를 수정하지 않았으므로 실제 메시지는 아직 안 나감.
5. **`on` 모드 없음.** advisory만. 실제로 다른 자리에 여는 것은 미구현.
6. **다중 사용자는 mock.** 실제 앱에는 `state.presence`가 없어 항상 단일 사용자 provider. L1의 실제 `presence.snapshot()` 형태와 필드명이 다르면 `normalizePresence`만 맞추면 됨(현재 가정: `{member, self, active, viewport{x,y,width,height}, focusCard, lastInputAgeMs}`).
7. **calibration**: whitelist에 배치 feature가 없어 `board_arrangement`로 기록함(L7 모듈 미수정). 배치 전용 feature가 필요하면 L7 결정.
8. 단일 사용자 provider는 입력 시각을 모르면 "활성·idle 아님"으로 봄. 입력 감지 리스너는 flag가 켜진 뒤 첫 호출에서만 붙음.
