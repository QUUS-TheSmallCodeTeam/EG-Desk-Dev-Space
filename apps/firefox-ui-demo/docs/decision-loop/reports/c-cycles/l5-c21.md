## 1. 판정기 `helper/egdesk-run-conditions.mjs`
**build/test health** (`judgeHealth`)
- exit ≠ 0 → `unhealthy`(`exit_status`). 요약 줄이 전부 통과라고 해도 그 모순은 `summary_says_passed`로 남김.
- exit 0이고 **러너 자신의 요약 줄**(node --test TAP/spec, jest, vitest, pytest, cargo, mocha)에 실패가 있으면 → `unhealthy`(`summary_failed`).
- exit 0이고 요약 줄이 전부 통과면 → `healthy`(`summary_passed`). 이때 술어는 **묻지 않음**.
- exit 0인데 요약이 없음(구조화 사실이 부족함)이면 **그때만** 술어 `output_reports_problem`을 꼬리에 물음:
  - yes(≥.8) → `unknown`(`output_reports_problem`)
  - 사이 값 → `unknown`(`output_unsure`)
  - no(≤.2), 판단 불가, 오류 → `healthy`(`exit_ok`. 이 경우 근거는 exit 상태이고, P2에 따라 기존 동작을 따름)
- 끝나지 않은 명령(시간 초과 등)은 `unknown`(`no_exit_status`)이고 healthy가 되지 않음.
- 요약 줄은 원문 그대로 보관함(300자).

**dev server ready** (`judgeServerReady`)
- 프로세스가 끝났으면 → `not_ready`.
- 포트가 주어지면 loopback probe(주입)로 판정함: 받으면 `ready`, 거절하면 `not_ready`. 출력이 "listening"이라고 해도 probe가 거절하면 not_ready이고 술어는 묻지 않음.
- 포트가 없으면 출력의 **loopback URL과 포트만** 후보로 뽑아 probe함(`example.test:8080` 같은 외부 주소는 제외).
- probe할 수 없으면 술어 `output_says_listening`은 **힌트로만** 남기고 `unknown`을 유지함(ready가 되지 않음).

**git conflict / 미커밋 작업** (`judgeWorktree`)
- `git status --porcelain=v1`을 파싱함: 병합되지 않은 코드(UU, AA, DD, AU, UA, DU, UD)는 conflict, 추적 중인 변경은 uncommitted, `??`는 untracked로 셈.
- 결과는 `conflict` / `uncommitted_work` / `clean` 중 하나임.
- git status가 없으면 술어 `output_reports_conflict`는 힌트로만 쓰고 `unknown`을 유지함.

**술어 공통**: yes/no이고, 출력 꼬리 3000자를 따옴표로 한 번만 넣으며, 요청 하나에 조건 하나임(R1, R2, R4). 결합은 코드가 함(R3). 묶음 질문 lint를 통과함.

## 2. 연결
- **실행기**(`egdesk-command-executor.mjs`): 명령이 끝나면 `judgeHealth`를 실행하고, git status가 주입되어 있으면 `judgeWorktree`도 실행함.
  - 도구 결과에 `health`, `healthReasons`, `tests{runner, passed, failed, total, line}`, `worktree{state, conflicts, uncommitted, untracked}`를 넣음.
  - `onConditions`로 런타임에 넘김.
- **wiring**(`EGDESK_OWN_TOOLS=on`):
  - `ask`는 사람의 Decision 모드가 on이나 advisory이고 키가 있으며 그 Run의 egress가 `command_output`을 허용할 때만 묻고, 1.5 s 안에 끝냄.
  - `gitStatus`는 실행 폴더에서 `git status --porcelain=v1`을 실행함(최소 환경, 1.5 s. 저장소가 아니거나 오류면 null).
  - egress 등록: `egdesk-own-tools-wiring.mjs: command_output`.
- **heartbeat**: 런타임 `noteOwnCommand`가 대화의 heartbeat에 facts 전용 provider `own_commands`를 붙임. 평평한 숫자와 닫힌 단어만 들어감(`exit_code`, `duration_ms`, `health`, `test_summary`, `tests_passed`, `tests_failed`, `tests_total`, `worktree`, `conflicts`, `uncommitted`). 텍스트는 없음(heartbeat 계약).
- **메시지 근거**(heartbeat의 판정과 draft check가 쓰는 `workLines`/`messageEvidence`):
  - "The last command EG-Desk ran ended with exit code 0; its test runner's own summary line reads "# tests 40 / # pass 40 / # fail 0" (40 passed, 0 failed, 40 in total); …"
  - **"테스트가 모두 통과했다"는 러너의 요약 줄로 뒷받침됨**(L3 c19의 실측 결과: 그 주장을 지지하는 것은 통과 줄 자체였음). 줄을 따옴표로 넣는 것은 그 Run이 `command_output`을 보낼 수 있을 때만이고, 그렇지 않으면 숫자만 넣음.
  - health가 `unknown`이면 "whether it fully worked is not confirmed"라고 씀. conflict와 미커밋 변경도 한 줄로 씀.
  - 자체 명령이 없으면 줄이 추가되지 않으므로 기존 근거 문장은 그대로임.
- **테스트**:
  - `egdesk-run-conditions.test.mjs`(6개): 요약 줄 표 8종과 없는 경우 4종, health 규칙(요약이 있으면 묻지 않고, 술어는 낮추기만 하며, 실패나 미종료는 healthy가 되지 않음), 서버(probe 우선, loopback만, 힌트), worktree, 요청 모양과 lint, heartbeat facts와 근거 문장.
  - c19 시나리오에 git status를 주입하고 health(`summary_passed`, mocha `2 passing (12ms)`)와 worktree(`uncommitted_work` 2)를 단언으로 추가함.
