## 5. 도구 (c22) 에 더한 것 [측정]
`egdesk-journey-diff` 출력에 `draws:` 줄과 JSON 의 `draws` 를 더했다 (`drawsOf`, 결과 파일의 `sha256` 과 `answers` 만 읽어서 재생이 필요 없다): 새 실행의 요청 중 이전 실행과 본문이 같은 수, 그 같은 본문의 답이 같은지, 새 표본이 있는 계열. v6 → v7b 에서 `draws: 32 of 50 request bodies are byte-identical to the old run (answers identical in all of them)` 로 이 보고서의 1절 숫자와 같다. 테스트 2개.

[해석] 요청 본문을 결과 파일에 저장하면 재생 없이 diff 가 된다 (Main: 싸면 나중에). 이번에는 v7b 50/50 이 재생으로 모두 재현돼서 필요가 없었다. 결과 파일에 `sha256` 만 있어도 이 보고서의 "같은 본문 → 같은 답" 확인은 됐다.

## 6. 한계 [한계]
- "같은 본문은 같은 답" 은 70쌍에서 예외가 없었지만 서버가 항상 결정적이라는 증명은 아니다. 시간 줄만 다른 본문에서는 답이 움직였다 (s9).
- 여정 v7b 는 단계 검사다. 질문 단위 정답이 없어서 정확도 칸에 들어가지 않는다.
- browser-live 의 본문 비교는 같은 작업군의 이전 통과 실행과만 했다. 작업군이 다르면 본문이 같을 수 없어서 새 표본으로 셌다.
- 플래그를 켠 채 돌았는지는 하네스의 `allOnWorld` 와 결과의 `world` 로 정했다. c16, c17, c19 여정은 결과에 `world` 가 비어 있어서 기본 all-on 플래그만 켠 것으로 읽었다.
- 실제 엔진 점검은 점검마다 켠 플래그와 점검 기대가 달라서 같은 조건의 반복이 아니다 (3절).
