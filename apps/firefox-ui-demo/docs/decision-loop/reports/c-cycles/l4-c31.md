## 1. hook (별도 모듈 + 등록 지점)
- `helper/egdesk-real-engine-briefing-hook.mjs`: 브리핑 hook 본체. `helper/egdesk-real-engine-hooks.mjs`: 등록 배열(`CHECK_HOOKS`, 한 줄씩). 체크 파일에는 import 1개와 호출 지점만 추가(플래그 목록 2곳, hook 부착 1곳, send 인자 병합 1곳, 턴 후 호출 1곳, 기록 1곳). L7 메모리 hook과 나란히 존재.
- `EGDESK_BRIEFING_FLOW=on`인 대화에서만 활성. 이 플래그는 decision-dependent 목록에 올라가 `--decisions` 없이는 preflight가 거부. `EGDESK_BRIEFING_FLOW`는 notReproduced에서 reproduced로 옮겼고 `EGDESK_BRIEFING_OUTPUT_SCHEMA` 추가.
- 하는 일: (a) chrome과 같은 `contextCapabilities { read, reader, publishBriefing }`를 chat.send에 실음, (b) 스크립트 턴에 `expect.briefing`이 있으면 답변이 게시된 뒤 제품의 `BriefingHost.observeRequest`와 제품의 Board/Decisions 핸들러(`/decision/briefing-observe`)를 호출, 주관 모델은 체크 자신의 런타임이 만드는 실제 엔진의 비공개 fork 턴, Decision 모델은 체크의 fetch, (c) 기록(포크 턴 수, 스키마 실린 포크 수, 게시된 카드, 제안된 단계, Decision 호출)과 `expect.briefing` 검사.
- 자료: 런타임이 memory 행을 주면 그것을(L7 시딩), 없으면 대화 폴더의 `MM-DD.md` 노트를 코드로 읽음(연도는 선언된 상수 2026, 상태는 노트 문구에서 `statedStatus`).
- 제외: 캔버스(후보 `[]`), chrome 타이머, 사용자 보드. 이 때문에 재사용/기존 카드 경로는 이 hook으로 검증하지 않음.
