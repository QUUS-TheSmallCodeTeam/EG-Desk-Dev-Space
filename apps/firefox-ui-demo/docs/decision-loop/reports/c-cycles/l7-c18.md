## 2a. 기록 규칙 확장 (Main 결정 반영)

`RECORDING_RULE` 이 이제 **쓰기 판정이 답 뒤에 돌 수 있는 모든 턴**에 붙는다. 자기 키 `egdesk_recording` 을 쓴다.
- **첫 턴**: 기록 판정 triage 가 디스패치 전에 이미 "기록할 가치 없음" 을 답한 경우만 빼고 붙는다. 묶음이 없는 첫 턴(새 사실)에도 붙는다.
- **중간 턴**: triage 가 "기록할 가치 있음" 으로 정했을 때만 붙는다. 그때만 쓰기 판정이 준비된다.
- **쓰기 경로가 없으면**: 붙지 않는다.

키를 따로 둔 이유:
- 기억 내용이 아니고, 기억 묶음이 없는 턴에도 실린다.
- 기억 묶음이 없다는 기존 단언들(상한·egress·권한 철회 테스트)을 바꾸지 않아도 된다.

`record-state` 근거 항목도 같은 조건을 따른다. 이 키는 초안 점검의 내용 없는 참조로 넘기지 않는다 (그러면 점검이 관대해진다).

테스트 변경: c17 의 규칙 테스트는 위치와 조건을 새 기준으로 다시 썼다. 추가로 확인하는 것은 묶음 없는 첫 턴의 새 사실, triage 가 아직 안 끝난 첫 턴, 쓰기 경로 없음이다. L2 여정은 d1(s9 모양)에 `egdesk_recording` 이 정확한 키 목록으로 들어가고, a1 은 그대로다.

## 2b. 날짜·상태를 쓰기·확정 시점에 기록 (Main 결정 반영)

본문에서 읽지 않는다.

| 시점 | 기록 | 자료 행 필드 |
|-|-|-|
| writer 가 페이지를 만들 때 | 생성 시각 (`spokenAt`, 이미 저장되던 값) | `recordedAt` |
| 브라우저 작업 기록 | 작업이 돈 날 = 사건 날짜. 코드가 안다 | `time.at` (+ `recordedAt`) |
| 사용자가 읽기를 확정할 때 | 확정 시각 (`confirmedAt`) 과 상태 | `status`, `statusAt` |

- writer 는 제안자가 준 사건 날짜(`time.at`)를 코드가 아는 경우에만 보존한다. 어댑터의 저장소도 이를 영속한다.
- 발언 페이지의 사건 날짜는 계산하지 않는다 ("어제" 같은 말에서 날짜를 만들지 않음).
- 테스트: 어댑터와 쓰기 저장소를 거쳐 생성일, 작업 날짜, 확정 상태·날짜가 자료 행에 실리는 것을 확인한다.
- L4 의 sequence 규칙은 `time.at`(사건 날짜)만 읽는다. `recordedAt`(기록 날짜)을 대신 쓸지는 L4 결정이라 알리기만 했다.
