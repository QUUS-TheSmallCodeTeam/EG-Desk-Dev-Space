## 0. 범위와 한계 (먼저)
- **합성 하네스 관찰**: mock Decisions fetch → 실제 `createDecisionClient` → 실제 `CodexChatRuntime.chatChoice` → 실제 `createChatHttpHandler(/chat/choice)` → 실제 Surface `mountChatChoiceComposer`(가짜 DOM에서 실제 핸들러 실행). 키는 `egd-synthetic-not-a-key-0002`, 네트워크 없음, native 작업은 호출 시 즉시 실패하도록 막고 `nativeOps===0`을 모든 결과에서 단언.
- **설치된 앱 검증 아님**: Firefox/EG-Desk/실제 bridge 미실행. 실제 앱에서 필요한 확인: 실제 DOM의 포커스 이동·스크린리더 낭독(role=status), 실제 OpenAI 응답 형태(특히 429 본문 코드, abstain 확률분포), `openChatChoiceSettings` 카드 실제 열림.
- 만들어 넣은 가짜 권한/바인딩 없음. 합성 DM 바인딩은 runtime 테스트와 같은 방식(저장소에 direct 바인딩·이전 run 기록)으로 제품이 만드는 상태를 모사.

## 1. Sim 여정 (정확한 단계)
같은 DM에서: ① 작성창 질문 "이번 주 발표 자료는 어느 쪽으로 정리할까요?" ② `[보기 추천]` 열기 ③ 보기 2개 입력("슬라이드 10장 요약본" / "표 중심 상세본") ④ `[질문과 보기 검토]` ⑤ `[질문과 보기만 보내기]` 확인 → `POST /chat/choice` → mock Decisions가 13개 결과 중 하나를 반환.
결과: confident, abstain(abstain 0.90), near_tie(0.46/0.44/0.10), low_confidence(0.62/0.28/0.10), out_of_list(`c9`), no_credit(429 insufficient_quota), rate_limited(429), timeout(응답 보류→1.5s), budget_exceeded(client budget.canSpend=false), invalid_key(401), unreachable(fetch throw), server_error(500), model_unavailable(404).
각 결과마다 3회 실행: A) 관찰 + `[닫기]` 후 재오픈, B) 복구 버튼 `수정` 누르기, C) `재시도` 누르기. 테스트 파일: `scripts/egdesk-chat-choice-outcomes.test.mjs`.

## 2. 문제 (패치 전 실측)
패치 전 12개 비추천 결과가 **전부 동일**:
- 화면: `추천을 표시할 수 없습니다. 직접 판단해 주세요. 작성 중인 메시지는 그대로입니다. 닫기` (`eg-desk-surface.uc.js:12708` manualText, 렌더 12900)
- 버튼: `[닫기]` 하나뿐. 포커스: null (confirm 버튼이 사라지며 포커스 유실; `useManual` 12763에 포커스 처리 없음).
- bridge 응답: `{"status":"manual"}` — 원인이 UI 이전에 소거됨: `egdesk-chat-choice.mjs:66`(abstain/약한 확신/동률 모두 같은 MANUAL), `:127-128`(`catch {return MANUAL}`로 DecisionError 코드 폐기), `codex-chat-runtime.mjs:4344,4349,4350`(timeout·실패 모두 `manual`).
- `[닫기]` 후 재오픈하면 보기가 `["",""]`로 소실. 수정 경로 없음, 재시도 없음, 이유/다음 단계 없음.
구체 문제:
1. P1 abstain·near-tie·낮은 확신이 "시스템 오류"와 같은 문장 — 사용자는 *질문이 모호*한 건지 *키/크레딧 문제*인지 구분 불가(HAX G10/G2, PAIR low confidence).
2. P2 재시도 가능(rate_limited/timeout/unreachable/server_error)과 불가(no_credit/invalid_key/budget/model_unavailable)가 같은 화면. 재시도 버튼 자체가 없어 처음부터 다시 입력(검토된 보기 소실).
3. P3 키/계정 문제인데 설정으로 가는 길이 없음(`no_credit`·`invalid_key`).
4. P4 모델이 고르지 못한 경우 다음 추천/에이전트 질문 경로 없음(`[이유 묻기]`는 추천이 있을 때만 의미).
5. P5 포커스 유실(WCAG 2.4.3, VA/GOV.UK 오류 시 포커스 이동). 추천 성공 시에도 `[이유 묻기]`로 포커스 안 감.
확률은 UI에 노출되지 않음(오히려 올바름): 보정되지 않은 수치를 보이면 확신으로 읽힘.

## 6. 철학 점검
원칙: **모델 제안과 승인된 실행의 분리 + 사용자의 선택/이력 보존.** 모든 비추천 결과에서 아무것도 실행·전송되지 않고(`nativeOps=0`), 다음 행동은 전부 사용자의 명시 클릭이다: 재시도는 비용 고지·확인 버튼이 있는 review로만 복귀(자동 재전송 없음), Agent 질문은 편집 가능한 초안일 뿐 `[보내기]`가 따로 필요, 설정 이동은 사용자가 누를 때만. 검토한 보기는 `수정`으로 보존된다(전엔 소실). reason은 닫힌 enum이라 질문·키 같은 사용자 데이터가 bridge 응답을 통해 새로 노출되지 않는다. "화면에서 발견 가능·완결 가능" 측면에서 각 결과가 화면 안에 다음 단계 버튼과 포커스를 갖는다.

## 7. 한계/미해결 및 다음 sim
