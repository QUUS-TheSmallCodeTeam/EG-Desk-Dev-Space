# L3 사이클 38 — 보류 행동(pw) 질문을 여섯 상황으로 넓히는 계획

브랜치 `lane/c38-pw-broaden` (int/c14 `21caac8` + c37 병합, 후보 A 문구 포함). 증거 `evidence/l3-c38/`. Decisions만, 전송 없음(Main이 보냄).

## 계획 `pw-broaden-c38`: 17요청, 4,720토큰 (보정 후 5,556, ceiling 5,900), 드라이런 통과
| 상황 | 보류 응답(양성) | 근접 음성 (보류를 요청하지 않았고 다른 이유로 안 됨) |
|-|-|-|
| 메일 발송 | "메일은 아직 발송하지 않았습니다." / "발송은 하지 않고 초안만 준비해 두었습니다." | 받는 사람 주소를 못 찾아 발송하지 못함 |
| 푸시 (배포) | "푸시는 실행하지 않고 대기 중입니다." | 원격 저장소 인증이 없어 푸시하지 못함 |
| 덮어쓰기 | "파일은 아직 덮어쓰지 않았습니다." | 읽기 전용이라 덮어쓰지 못함 |
| 결제 성격의 단계 | "결제는 진행하지 않았습니다." / "결제 버튼은 누르지 않고 여기서 멈췄습니다." | 카드 본인인증이 필요해 결제를 완료하지 못함 |
| 일정 변경 | "일정은 아직 변경하지 않았습니다." | 캘린더 권한이 없어 변경하지 못함 |
| 일괄 이름 변경 | "파일 이름은 아직 바꾸지 않았습니다." / "이름 변경은 적용하지 않았습니다." | 폴더에 파일이 없어 바꿀 이름이 없음 |
| 대조(행동이 **됨**) | 메일을 발송했습니다 / "응 진행해"에 푸시했습니다 | |

- 양성 9, 근접 음성 6, 대조 2. 모든 기대는 **hard**, 제품 기준(`PROPOSAL_YES` .8)으로 **코드가 만든다**: 양성 ≥.8, 음성과 대조 ≤.2.
- 양성은 사람이 "아직 하지 말고 알려 줘"라고 한 요청에 대한 엔진 스타일 답(짧은 목록 + 마지막 한 줄, 기록된 check-2b, 31pr, conditional-yes의 형식)이다. **합성**이다: 이 상황들의 실제 엔진 답 기록은 없다.
- **근접 음성이 이 계획의 핵심**이다. 문구 A는 "문단이 행동이 안 됐다고 말하는가"를 묻는데, 사람이 보류를 요청하지 않았고 권한·인증 때문에 못 한 경우에도 "안 됐다"는 참이다. 그런 답에서 yes가 나오면 `waiting_action`이 잘못 등록된다(다음 "응"이 그 항목을 가리키게 됨). 이 경우 yes가 나오면 문구를 고쳐야 하는 발견이다(기준은 낮추지 않는다).
- 코드 쪽: 17개 응답 모두 질문 문장이 없어 문단 경로를 타고, 인용되는 것은 정확히 마지막 한 줄이며 목록은 인용되지 않음을 테스트로 고정했다(`egdesk-open-proposals.test.mjs`, 상황 데이터는 `egdesk-open-proposals.situations.mjs`). 변이 3건이 잡혔다.
