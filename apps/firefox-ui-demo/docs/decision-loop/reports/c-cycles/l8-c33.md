## 수정
- **모순이 신호입니다**: "페이지 없이는 답할 수 없다"(`browser_entry_answer` ≤ .25)인데 "열린 페이지가 그것을 가진 게 아니다"(`browser_entry` ≤ .25 또는 미결정)이고 어떤 카드도 yes가 아닐 때, 후속("이 열린 페이지는 오류, 로그인, 확인 단계인가?")을 묻습니다. 카드가 결정된 no일 때뿐 아니라 **미결정**(.52)일 때도 묻습니다. 기존 경로(웹 작업이 결정됨, 카드 결정된 no)는 그대로입니다.
- 후속이 정확히 한 카드에 yes이고 다른 카드가 모두 no면 그 카드로 들어갑니다(단계가 `ps_error`로 `error_page`를 넘김). "답변이 아니면서"의 판정(`readBrowserEntry`)이 조기 "답변" 읽기보다 앞에 있습니다.
- 후속의 병합에서 `browser_entry_answer`가 빠져 있었습니다(후속의 결과를 다시 읽을 때 전제가 사라졌음). 같이 넘깁니다.
- **통제는 막혀 있습니다**: 페이지 없이 답할 수 있는 요청("광합성이 뭐야?")은 `browser_entry_answer`가 yes라서 후속에 닿지 않고, 오류 페이지가 열려 있고 후속이 yes여도 진입하지 않습니다. 오류가 아닌 평범한 페이지는 후속이 no라서 들어가지 않습니다(요청 하나 더 쓸 뿐).
- 테스트(`egdesk-browser-entry-two-predicates.test.mjs` 2건 추가): 실제 숫자(.14, 0, .52)로 후속이 물어지고, 오류 yes는 진입, 오류 no와 미결정은 비진입, 통제 둘, 줄이 없는 카드와 yes 카드는 안 물음, 카드 둘에서 정확히 하나일 때만, 그리고 진입 전체가 후속 한 번 뒤 `error_page` 노트로 끝나고 후속이 페이지 줄을 인용함. 기존 더블 둘을 새 질문 모양에 맞췄습니다("아무것도 web이라 하지 않음"의 답변 predicate를 높게). 설정 stand-in이 실제 모델처럼 .14, .52로 답합니다.
