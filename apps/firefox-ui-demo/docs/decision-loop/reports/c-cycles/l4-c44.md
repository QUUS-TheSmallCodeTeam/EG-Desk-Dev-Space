## 3. U13 정정: 브리핑의 자기 층 점검

재료 / 주제·순서 / 카드 종류는 이미 채움 전에 Decision이 코드가 만든 선택지에서 정한다(재료 `about`, 주제는 코드가 만든 로그 묶음과 `before` 순서, 카드 종류는 `fit` 질문, 가이드는 "decided; do not change it"로 엔진에 전달). 엔진이 맡는 것은 글뿐이다. 점검에서 실제로 약했던 곳은 두 곳:
1. 재료 층이 항목당 한 번의 표본이라 흔들렸다 (위 1번, 로그 투표로 수정).
2. 엔진 문구(단계 설명 한 문장)가 이미 정해진 층을 다시 열고 채움 턴 하나를 쓰게 했다.

플래그 `EGDESK_BRIEFING_LAYERS=on` (기본 꺼짐, `codex-bridge-server`, `briefingDeps`, http 경로, 점검 훅까지 연결): 카드의 모든 조각이 확실(예)인데 단계 설명 한 문장만 미결정(아니오 아님)이면 그대로 둔다(`stats.stepKept`). 기록된 29br schema-off에서 이것이 29.5초 채움 턴 한 번을 없앤다(시험: 끄면 `[전체, P2]` 두 번, 켜면 한 번, 결정된 아니오나 확실하지 않은 조각이 있으면 둘 다 다시 씀).

한계를 분명히: 층 판단을 Decision으로 더 옮겨도 초는 거의 줄지 않는다(판단은 이미 2~4초). 초를 줄이는 큰 지렛대는 구조에 있다. 채움은 답 본문을 쓰지 않고 요청과 재료만 쓰는데(coverage의 사실 목록만 답을 인용한다) 지금은 답 턴이 끝난 뒤에야 시작한다. 재료와 층 판단(약 3초)과 채움(25~39초)을 답 턴(34~63초)과 **동시에** 돌리면 62/93/160초가 대략 max(답, 3 + 채움) = 40~63초가 된다. 이것은 런타임(L5 소유 `codex-internal-turn`, 답이 게시되기 전에 브리핑을 시작하는 훅)을 건드려야 해서 이번에는 만들지 않았고 c45 후보로 제안한다. 추정이며 측정이 아니다.
