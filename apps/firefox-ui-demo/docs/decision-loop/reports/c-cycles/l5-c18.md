**동작**
- **읽기**:
  - 줄 번호를 붙여 페이지로 줌(기본 400줄, 최대 2000줄, 응답 256 KB, 파일 8 MB 상한).
  - binary는 내용을 쏟지 않고 크기, sha256, 앞부분 3 KB base64만 줌.
  - 결과에 sha256을 넣어서, 편집할 때 `expectedSha256`로 그 사이에 바뀌었는지 확인할 수 있음.
- **검색**:
  - 문자열(정규식은 선택, 200자 이하)로 찾음.
  - 상한: 파일 2000개, 파일당 1 MB, 결과 200개, 2초. 멈추면 `stoppedBy`로 알림.
  - `.git`, `node_modules`, 비밀 저장소는 건너뛰고, 링크는 따라가지 않음.
- **편집**:
  - 방식: `replace`(정확한 문자열), `diff`(이 파일 하나의 unified diff. hunk의 옛 줄이 정확히 한 곳에만 있어야 하고, 하나라도 안 맞으면 아무것도 쓰지 않음), `write`(전체 내용), `delete`.
  - `dryRun`은 diff 미리보기만 하고 아무것도 쓰지 않음.
  - 쓰기는 같은 폴더의 임시 파일에 쓴 뒤 rename함(원자적). 원래 권한 비트를 유지함.
- **거부하는 것**:
  - 실행 폴더 밖(절대 경로나 `..` 포함).
  - 실제 경로(realpath)가 밖으로 나가는 symlink. 쓰기는 안쪽을 가리키는 링크라도 링크를 통해서는 하지 않음.
  - 편집에서만: `.git`, `.codex`, `.agents`, `.egdesk`.
  - 읽기와 편집 모두: `.ssh`, `.aws`, `.gnupg`.
  - QA나 bounded Run의 편집.
- **사람에게 묻는 것(R5, 코드로 판단, R3)**: 사람이 관리하는(생성물이 아닌) 파일을 **삭제**하거나 **통째로 바꾸는** 편집.
  - 생성물 = git이 무시하고(ignored) 추적하지 않는 파일. 판단은 터미널 게이트와 같은 `inspect` 인터페이스로 함.
  - 사실을 모르면 생성물이 아닌 것으로 봄(`unresolved_target`). 추적 중이면 `tracked_files`, 추적하지 않는데 무시되지도 않으면 `deletes_untracked`.
  - 묻는 경로는 명령 도구와 **같은 승인 장부**임. 장부는 그 사유를 받고, 정체성은 `kind:sha256(새 내용)`, 사람의 답과 비교할 문장은 `overwrite file notes.md` 같은 짧은 설명임(`check({ floor, identity })`는 c18에서 추가했고 기존 명령 판정은 그대로임).
  - 사람이 yes라고 답하면 **그 정확한 내용의 편집만** 한 번 실행됨. 내용이 다르면 다시 물음.
- **묻지 않는 것**: 새 파일 만들기, 기존 파일의 일부 편집(정확한 문자열이나 diff hunk), 읽기, 검색. 모두 diff로 보여줌.
- **정체성**: 명령 도구와 같음. 장부 키는 대화, 턴, 정확한 대상(경로와 내용 hash)이고, 엔진 프로필, 계정, CODEX_HOME, 화면은 쓰지 않음(테스트로 확인). 폴더는 `workspaceOf(run)`(= 런타임의 `runFolder(run)`)로만 정함.
- 테스트(`egdesk-file-tools.test.mjs`, 6개, 임시 폴더):
  - 읽기의 페이지, 긴 줄, binary, 밖, 링크 탈출, `.ssh`, `.git` 읽기 허용, 안쪽 링크 읽기.
  - 검색의 건너뛰기와 상한.
  - 편집의 고유 일치, replaceAll, 이전 내용 확인(stale), dryRun, 보호 경로와 링크 거부, 임시 파일이 남지 않음.
  - diff 검증, 생성, 모호한 hunk.
  - 통째로 바꾸기와 삭제가 묻고, yes 다음에 정확한 내용만 한 번 쓰이며, 생성물은 묻지 않음.
  - 정체성과 플래그.

## 2. 순수 엔진 모드 연결 (플래그 `ownTools = { mode(), neutralFolder() }`, `CodexChatRuntime` 생성자. 기본 없음 = off)
- on이면 Codex 스레드에 대해 다음을 함:
  - thread/start(새로 시작할 때와 재개할 때 모두)에 `pureEngineThreadOverrides()`를 합침: `sandbox:'read-only'`, `approvalPolicy:'never'`, `features.shell_tool/unified_exec/view_image=false`, `web_search:'disabled'`, `project_doc_max_bytes:0`.
  - turn/start마다 `approvalPolicy:'never'`와 `sandboxPolicy:{readOnly, networkAccess:false}`를 붙임.
  - **cwd는 EG-Desk 소유의 빈 폴더(`neutralFolder`)**로 함.
  - 실제 폴더(Board/프로젝트 binding 또는 요청의 cwd)는 `run.ownFolder`와 대화별 `ownFolders`에만 둠. EG-Desk 도구는 `runFolder(run)`로 이 폴더를 씀.
  - Codex의 native `item/commandExecution/requestApproval`과 `item/fileChange/requestApproval`은 **즉시 decline**함(카드 없음, accept 없음).
  - 중립 폴더가 준비되지 않았으면 메시지를 보내지 않고 `OWN_TOOLS_UNAVAILABLE`(조용히 Codex 셸로 돌아가지 않음).
- bounded/QA와 Claude는 이 모드에서 제외함(기존 정책을 유지).
- **증명**(`egdesk-own-tools-runtime.test.mjs`, 실제 런타임 + 모의 app-server):
  - on이면 thread/start의 cwd가 빈 폴더이고 위의 overrides가 모두 들어가며, dynamicTools에 명령, 읽기, 검색, 편집 도구가 있음. turn/start도 빈 폴더와 never/readOnly임. **실제 폴더 경로는 app-server로 가는 어떤 호출에도 나타나지 않음.**
  - 편집 도구는 실제 폴더의 파일을 바꾸고 빈 폴더에는 아무것도 생기지 않음. 명령은 실제 폴더에서 실행됨.
  - native 명령과 파일 변경 요청은 decline되고 카드가 0개임.
  - 다음 턴에도 엔진 폴더는 빈 폴더, 도구 폴더는 실제 폴더임.
  - off이면 지금과 똑같이 실제 폴더를 쓰고 overrides와 도구가 없음. on인데 중립 폴더가 없으면 thread/start와 turn/start가 0회임.
- **"모든 파일 변경과 명령이 EG-Desk 도구로만 간다"의 근거**:
  1. Codex 셸과 unified exec 도구 자체가 등록되지 않음(c17 출처: `spec_plan.rs:1194-1230`).
  2. apply_patch는 read-only + never이므로 쓰지 못하고 묻지도 못함.
  3. 그래도 요청이 오면 EG-Desk가 decline함.
  4. Codex에게 보이는 폴더는 비어 있음.

  1과 2는 실제 Codex로 확인하지 않았음(미확인).

## 3. 실제 runner `helper/egdesk-command-runner.mjs` (spawn 인터페이스, 가짜 spawn으로 테스트)
- 실행: `spawn('/bin/sh', ['-c', command], { cwd: 실행 폴더, env, stdio: ['ignore','pipe','pipe'], detached: true })`. 로그인 셸이 아니므로 profile이나 rc 파일이 변수를 추가하지 않음. stdin은 닫혀 있음. 실행기의 승인 장부를 통과한 명령만 옴.
- **환경 변수 허용 목록(처음부터 새로 만듦. 브리지 환경을 물려주지 않음)**:
  - 물려받는 것:
    - `PATH`: 사람이 설치한 도구를 찾기 위함.
    - `HOME`: 도구가 git config, npm cache 같은 자기 설정을 읽기 위함.
    - `USER`, `LOGNAME`: 로컬 사용자 식별.
    - `LANG`, `LC_ALL`, `LC_CTYPE`: 출력 인코딩.
    - `TMPDIR`: macOS의 사용자별 임시 폴더.
    - `TZ`: 출력의 날짜.
  - 고정값:
    - `TERM=dumb`, `NO_COLOR=1`, `CI=1`: 대화형이 아닌 출력.
    - `PAGER=cat`, `GIT_PAGER=cat`: 페이저가 키를 영원히 기다리지 않게 함.
    - `GIT_TERMINAL_PROMPT=0`: 아무도 입력할 수 없는 비밀번호를 기다리는 대신 실패하게 함.
  - **넘기지 않는 것(테스트로 확인)**: API 키, 토큰(`OPENAI_API_KEY`, `GITHUB_TOKEN`, `EGDESK_GATE_HOOK_TOKEN`), `CODEX_HOME`, `SSH_AUTH_SOCK`, `AWS_*`, 프록시, `NODE_OPTIONS`, `BASH_ENV` 등 그 밖의 전부.
- **시간**:
  - soft notice(기본 30 s, 시간 제한보다 짧으면 그 값): facts에 `softNotice`를 기록하고 실행기가 running row를 갱신함.
  - hard limit(기본 120 s, 실행기 상한 600 s): 프로세스 그룹에 SIGTERM을 보내고 grace(2 s) 뒤 SIGKILL을 보냄. abort 신호도 같은 처리를 함.
  - 끝나면 모든 타이머를 해제하므로 끝난 뒤에는 kill하지 않음.
- **출력**: 도구 결과용으로 head 4 KB와 tail 16 KB를 남기고, 넘치면 `…`와 `truncated`를 붙임. 전체 stdout과 stderr는 **기존 RunOutputStore**로 흘려보냄(`appendCommandOutput`/`completeCommand`. 화면의 "command output" 보기가 쓰는 곳이고, store가 자기 head와 tail을 따로 유지함).
- **facts**: 시작 `{running:true, runningMs:0}`, soft notice, 끝 `{running:false, runningMs:duration, exitCode}`.
  - 실행기는 c10 row(`terminalFactRow`)를 **kind 'engine'**으로 바꿈. 엔진이 요청한 명령이므로 row에 exitCode가 들어감. gate 단계는 `asking:true`이므로 `terminal:'gate', waitingOnUser:true`.
  - 끝 row에는 `durationMs`를 추가 필드로 붙임(c10 함수의 모양은 그대로임. c10은 runningMs를 실행 중에만 남기기 때문).
  - c17 실행기 테스트의 row 기대값은 이 변경에 맞춰 바꿨음(필드가 늘어났고 약화한 것은 없음).
- 테스트(`egdesk-command-runner.test.mjs`, 4개, 가짜 spawn과 가짜 타이머): 허용 목록이 정확한지와 비밀이 빠지는지, spawn 인자, cwd, detached, head와 tail, store로 흘려보내기, soft notice, SIGTERM→SIGKILL(그룹), 끝난 뒤 kill이 없는지, 실행기와 결합했을 때 exit code와 duration, 위험한 명령은 spawn 0회인지.

## 4. 미확인
- 실제 Codex에서 `features.shell_tool=false` 등의 overrides가 이 버전에서 받아들여지고 도구 목록에서 사라지는지(소스 근거만 있음).
- read-only + never에서 apply_patch 시도가 모델에게 어떻게 보고되는지.
- 빈 엔진 폴더에서 모델의 행동 품질. 모델은 실제 경로를 모르고 EG-Desk 도구만 씀. 폴더를 설명하는 문맥을 따로 줘야 할 수 있음.
- `killGroup`의 기본값은 `child.kill`임. 그룹 전체를 죽이려면 브리지가 `process.kill(-pid, sig)`를 주입해야 함(브리지 연결은 이번 범위가 아님).
- 하드링크로 폴더 밖 파일을 가리키는 경우는 realpath로 잡히지 않음(OpenCode도 따로 다루지 않음).
- 브리지에는 아직 연결하지 않았음(환경 플래그, 데이터 폴더 아래 중립 폴더 생성, 실제 spawn 주입). 런타임 수준까지만 연결함.

## 5. 결정 필요
1. **일부 편집은 묻지 않음**: 기존 파일의 정확한 문자열이나 diff hunk 편집은 묻지 않고 diff로만 보여줌. OpenCode는 모든 편집에 묻음. 모든 편집을 물으면 코드 작업이 사실상 멈춤. 이 범위로 둘지, 아니면 편집 전 내용을 보관하는 undo 기록을 추가할지.
2. **runner 환경**: `SSH_AUTH_SOCK`을 넘기지 않으므로 ssh 방식의 `git push`는 실패함(https+credential helper는 HOME 아래 설정으로 될 수 있음). 넘길지. `HOME` 자체를 넘기는 것도 결정 사항임(넘기지 않으면 git과 npm 설정이 없어짐).
3. **브리지 연결**: `EGDESK_OWN_TOOLS=on` 같은 개발 플래그, EG-Desk 데이터 폴더 아래 빈 엔진 폴더, 실제 `child_process.spawn`과 그룹 kill 주입. 다음 사이클에서 할지.
4. 도구 이름(`egdesk_read_file` 등 4개)은 임시(Main이 소유자에게 묻는 중).
