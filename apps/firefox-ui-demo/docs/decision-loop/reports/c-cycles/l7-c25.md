## 2. resume 때 연속성 확인 (`checkContinuity`)

- 근거: 실제 엔진 스모크에서 비-ephemeral thread는 사람의 Codex home에 있고, 다른 Codex 클라이언트(ChatGPT 앱 등)가 이어 갈 수 있습니다. 그래서 resume한 thread에는 EG-Desk가 보지 못한 턴이 있을 수 있습니다.
- 동작 (`restoreThread` 안, Codex 엔진만):
  1. 엔진 쪽 턴 id를 모읍니다. resume 응답의 `thread.turns`에 더해, `turnsBackwardsCursor`가 있으면 `thread/turns/list`(`itemsView: 'notLoaded'`, limit 100, desc)를 끝까지 페이지로 읽습니다. 스키마 0.171에 있는 필드와 요청입니다.
  2. EG-Desk 쪽은 이 대화의 store run들(`listRuns`)의 `runId`(= 엔진 턴 id)를 읽습니다.
  3. 엔진에 있고 EG-Desk에 run이 없는 턴이 하나라도 있으면 **foreign**입니다.
  4. 비교할 수 없어도 foreign입니다. `thread/turns/list`가 실패하거나, 20페이지(턴 2,000개)를 넘거나, store 기록이 없는 경우입니다.
- foreign이면:
  - turn memory 영수증, shadow 영수증, 컨텍스트 영수증을 지웁니다.
  - `turnPosition`이 `first / foreign_turns`를 돌려줍니다. 그러면 previous_reply, 영수증, held 가지치기가 모두 닫힙니다.
  - 다음 턴이 first-turn 경로로 필요한 기억을 다시 보내고, 그 loop가 끝까지 돌면 표시가 풀립니다 (compaction 표시와 같은 방식).
  - **resume된 바로 그 턴은 표시를 소진하지 못합니다.** 그 턴의 turn memory loop는 resume 전 위치(mid)로 이미 시작됐기 때문입니다. 표시가 풀리는 조건은 `turn.position.reason === 'foreign_turns'`로 돌았던 loop뿐입니다.
- 엔진 쪽 턴이 EG-Desk 기록보다 적은 경우(revert 등)는 foreign이 아닙니다. 그건 `thread/reverted` 신호(c24)로 따로 닫습니다.
- fork는 새 thread라 live가 아니고, 엔진이 복사한 턴 id가 store와 다를 수 있습니다. 어느 쪽이든 foreign으로 가서 안전한 쪽입니다.

## 3. L3 scenarios-v2의 tn_recall .13

**결론: 제품은 가져옵니다. 틀린 것은 제품이 아니라 L3의 기대값입니다.**

- 기록된 실제 답 (c27, `triage_recall-985c1f528cd9c757`, "오전 6시에 작업 중지 예약 걸었지?"): courtesy 0, **need .99**, recall .13, record .01. held 없음, 저장 페이지 12개 목록.
- 제품의 fetch 건너뛰기 규칙은 `triageSkipsFetch`입니다. 건너뛰는 경우는 둘뿐입니다.
  - courtesy가 decided yes일 때
  - need가 decided **no**이고, held 페이지가 보였고, 저장 목록이 완전할 때
- need가 yes라서 이 요청은 건너뛰지 않습니다. 제품 triage를 기록된 답으로 실제로 돌려 확인했습니다 (`recall-13.txt`).
  - held 0개와 3개, `heldExcerpts` 켬/끔, c11의 legacy 규칙까지 모든 조합에서 `skips = false`입니다.
  - 같은 recall .13이어도 need가 no(.02)이고 held 3개일 때만 true가 됩니다. recall은 건너뛰기를 일으키는 값이 아닙니다.
- L6가 "would skip the fetch"라고 표시한 것은 recall이 decided no인 것을 건너뛰기로 읽은 것으로 보입니다. L3의 기대값은 "recall ≥ .8 (hard): 사람이 앞의 것을 가리킨다"인데, 이 질문의 문구는 "앞의 것을 다시 불러내거나 요약하거나 재정리해 달라고 하는가, **하나의 새 사실이나 하나의 좁은 세부를 묻는 것이 아니라**"입니다. "예약 걸었지?"는 한 가지 세부를 묻는 질문이라, no(.13)가 문구에 오히려 맞습니다. 그러니 이 사례는 모델이 틀린 것이 아닙니다.
