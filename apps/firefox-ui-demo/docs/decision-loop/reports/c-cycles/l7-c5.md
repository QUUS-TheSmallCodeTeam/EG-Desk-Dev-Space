## 1. 스키마 변경 (egdesk-decision-calibration-log.mjs)

- 버전 1 → 2. 추가 필드는 전부 선택적. v1 파일은 그대로 읽고 다음 쓰기 때 v2로 올림. 더 새로운 버전(>2)의 파일은 읽지도 쓰지도 않고 그대로 둔다(status `unsupported`, 기록은 메모리에서만 동작; 바이트 동일 시험).
- 판단(judgment) 필드: `confidence`(API의 우연 보정 confidence), `options`(N, 2..255: 질문의 허용값 수 = 보정 기준), `margin`, `noPick`(닫힌 어휘 abstain / unclear / low_confidence).
- 항목 필드: feature에 `board_reply` 추가, `fallback`에 `timeout_unsent` 추가(챗 선택지는 이제 `timeout`으로 뭉개지 않고 그대로 기록).
- 라벨 `outcome.next`(기능별 닫힌 어휘, 다른 기능의 값은 버림): dm_chooser = asked_why / asked_agent / edited / retried / closed / sent_ordinary, board_arrangement = applied / undone / rejected / kept_own / timed_out. Board 답장은 `keptN` / `removedN`(0..99 정수만). turn_context는 기존 `run`/`toolActivities` 유지.
- 라벨 병합: 이미 있는 필드는 덮어쓰지 않는다(첫 명시적 다음 행동이 유지됨).
- 핸들: `record()`는 불투명한 동결 객체를 돌려준다(프로세스 로컬 WeakMap 키, 파일에 어떤 식별자도 쓰지 않음; 이전의 `c1` 문자열 id 대체). `attachLabel(log, handle, outcome)`: log/handle이 없거나 틀려도 던지지 않고 false. 기존 호출자는 `log.complete(handle, …)`를 그대로 사용.
- 반올림은 문턱의 같은 쪽을 유지(side-preserving): `0.7999999999999999`를 0.8 문턱에 대해 기록하면 0.7999로 남는다. 이 처리가 없을 때 재생 시험에서 실제 불일치 1건이 발생해 추가(N=4, top .85, second .1, confidence 0.7999999999999999 → 제품은 low_confidence, 4자리 반올림 0.8은 accept).
- 재생 도우미: `chanceCorrected(top, N)`, `replayGate(feature, judgment)` (confidence ≥ threshold 및 margin ≥ minMargin; DM 선택지는 top ≥ threshold 추가. 숫자가 부족하면 null).
- 내용 없음/제한/권한은 불변: 화이트리스트 재구성(텍스트·id 필드 없음), 100건·192 KiB·30일, 0600, 설정 디렉터리, `.egdesk` 비포함.

## 2. 호출자 갱신 (이미 가진 값만 채움)

- DM 선택지(codex-chat-runtime `recordChoiceCalibration`): `confidence`, `options`(제시한 선택지 + abstain 행 = N), `margin`, `noPick`(결과 reason이 abstain/unclear/low_confidence일 때), `timeout_unsent` 보존.
- Board 배치(egdesk-board-presentation-http `calibrate`): `confidence`, `options`(질문 선택지 수), `margin`.
- Board 답장 선별(egdesk-board-agent-ask): feature `turn_context`+`kind:board` → `board_reply`. (술어이므로 confidence/N 없음.)
- 라벨 연결(UI 이벤트)은 다음 사이클에 각 레인이 `attachLabel`로 연결한다. 이번에는 API만.
- 기존 시험 갱신(의도 유지, 새 숫자 추가): chat-choice-calibration 기대값 4건(confidence/options/margin/noPick), board-presentation-calibration 1건, board-agent-calibration의 feature 이름 1건.

## 5. 철학 점검
"Decision Model의 동의·높은 점수는 사실 증명이나 쓰기 권한이 아니다": 기록은 점수가 문턱을 넘었는지를 나중에 재현할 수 있게 할 뿐, 어떤 동작도 이 파일을 읽지 않는다. 라벨은 사용자의 명시적 다음 행동만(닫힌 어휘), 내용·id는 저장하지 않는다.
