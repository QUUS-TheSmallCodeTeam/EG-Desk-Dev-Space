## 1. 오배제 수정 (`4fce587`)

**(a) 읽기 전용 GET 버튼은 라벨로 막지 않는다.** `buildReflexCandidates`가 버튼마다 `readOnlyPress`를 먼저 계산하고, 라벨 판정이 `submit`(이유 `submit-vocabulary`)일 때만 코드가 증명한 GET 폼 검색 앞에서 물러납니다. 증명의 조건은 그대로입니다(GET, 같은 사이트, 자격증명과 결제 필드 없음, 민감 영역 아님, 주소 단어 분류 통과). 선택하면 c20과 같이 그 주소로의 이동으로 실행됩니다.
- 물러나지 않는 것: `pay`, `grant`, `delete` 판정(`결제 확인`, `삭제`, `권한 허용`을 GET 증명이 있어도 막음), POST, 증명이 없는 버튼(옛 런타임), 민감 폼과 필드 종류, 민감 영역, 다른 사이트, 위험한 주소(`/delete`, `/login`), 보기 전용 버튼에 붙은 submit 라벨.

**(b) `등록` 좁히기.** 분류기의 `SUBMIT_WORDS`에서 `등록`을 빼고 `REGISTER_SUBMIT`을 추가했습니다: `등록`이 한 단어로 있을 때("등록", "댓글 등록") 또는 등록 구절일 때("등록하기", "등록 완료", "등록하세요", 회원, 신규, 상품, 게시물, 리뷰, 후기, 댓글, 글, 사진, 파일 뒤의 "등록")만 submit입니다. 한글이 앞이나 뒤에 붙으면(주민등록, 사업자등록증, 등록번호, 등록한) 아닙니다.
- 같은 사이트 링크의 라벨 판정이 `등록` 구절 때문의 submit이면 막지 않습니다(페이지 이동입니다). 주소 단어 분류는 그대로이고, 다른 사이트 링크는 이전처럼 막힙니다.
- 이 변경은 분류기 전체에 적용됩니다(런타임의 클릭 가드도 같은 분류기): `주민등록표 …` 라벨의 버튼도 더는 submit이 아닙니다(그 라벨에 `신청`, `확인` 등이 있으면 여전히 submit).

**테스트** (`egdesk-browser-false-exclusions.test.mjs` 4건):
