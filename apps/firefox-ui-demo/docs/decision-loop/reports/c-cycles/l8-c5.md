## 2. 재현된 문제와 수정
- **P1 오해 소지 reason (J1 전 `journey-before.tap`)**: 일반(content) 페이지에서 Decisions가 컨트롤 `blocked`("어떤 요소도 목표에 가깝지 않음")를 고르면 결과가 `escalated / reason: "content"`였다(`egdesk-browser-reflex.mjs` 종료 switch가 `decision.pageState`를 reason으로 사용). 추론 모델은 "content"를 받아 무슨 뜻인지 알 수 없다. 수정: 차단 페이지 상태(access_denied/error_page/modal_blocking)면 그 이름, 아니면 `blocked`. 공개 코드만, 페이지 텍스트 없음.
- **P2 콜드 연결 영구 fallback (J8 전)**: reflex는 `timeoutMs`를 넘기지 않아 매 결정이 기본 1500 ms(`DEFAULT_DECISION_TIMEOUT_MS`)다. `egdesk-decision-client.mjs` 주석이 기록한 콜드 호출 1.4-2.2 s(만료 시 소켓이 abort되어 다음 호출도 콜드)를 합성 지연으로 모델링하면 콜드 2.0 s / 웜 0.4 s에서 reflex 두 번 호출 모두 `fallback/timeout`, 동작 0이었다. 수정: reflex 실행의 첫 결정만 `FOREGROUND_DECISION_TIMEOUT_MS`(4000 ms)를 쓰고 이후 결정은 기본값을 쓴다(호출자가 `timeoutMs`를 주면 그대로). 이후 같은 모델에서 첫 결정 2.0 s 성공 → 연결이 따뜻해져 나머지 결정 0.4 s. hang이면 4 s 안에 `fallback/timeout`으로 깨끗하게 종료(J8b: 결정 요청 1, 동작 0, 추론 모델이 기존 방식으로 진행). 한계: 콜드 지연 수치는 코드 주석의 기록값을 쓴 합성 모델이며 실제 소켓/TLS 실측이 아니다. hang 시 대기가 1.5 s에서 4 s로 늘지만 run당 한 번이다.
- 범위 밖 관찰: reflex 경로에서는 `timeout_unsent`가 생기지 않는다(마감 타이머가 키 조회 이후 POST 직전에 시작되고 거부는 `evidence_unavailable`). 이 구분은 chat-choice(`egdesk-chat-choice.mjs`)에만 있다. reflex 결과의 `reason: timeout`은 POST 시작 여부(`error.dispatched`)를 모델에 알리지 않는다(데이터 없는 값이라 가능하지만 필요가 재현되지 않아 변경 안 함).
- **Owner 결정 항목(수정 안 함)**: reflex가 `blocked`/`escalated`로 돌려준 뒤 추론 모델이 직접 `egdesk_browser_click`으로 제출 버튼을 누르는 경로는 전역 게이트 정책(`CURRENT_ACTION_GATE_POLICY`: pay/grant/delete/submit 모두 allow, runtime `egdesk-browser-tool-runtime.mjs:435`)을 따른다. canon §3.3은 reflex 필터가 "다른 일반 Browser 도구의 전역 승인 정책이 아니다"라고 명시하므로 "submit은 항상 사람" 보장은 reflex 범위에서만 성립한다. 추천 프리셋(`RECOMMENDED_ACTION_GATE_POLICY`: pay/grant=user-step, delete/submit=confirm)을 켤지는 Owner 결정이다. 이번 사이클에서 정책을 바꾸지 않았다.
- 참고: 문서 교체(페이지 새로고침)로 입력값이 사라져도 reflex는 이미 소비한 값을 다시 채우지 않는다(J5는 첫 fill이 거절되어 해당 없음, 성공한 fill 후 교체되는 경우는 별도 케이스). 안전 문제는 없고 목표 판정(goal_met)은 Decisions가 한다.
