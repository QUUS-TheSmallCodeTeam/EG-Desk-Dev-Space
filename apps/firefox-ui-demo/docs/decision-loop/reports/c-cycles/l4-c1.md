## 2. 발견한 문제 (패치 전 실제 관찰값, `evidence/l4-c1/matrix-before.jsonl`, `sim-before.tap`)
통과해야 맞는 동작 중 이미 맞던 것(패치 전 9/15): J1~J4 좌표/z/카메라, J6a(`run` POST 0, provider 0, commit 0), J6b, J7(3종 모두 commit 0, 선택이 keep으로 복귀), J8, J11.
- J1: A (40,60)→(274,320), B (300,140)→(598,320), C·D·카메라·z 불변, undo로 정확히 복원. J2(front): A rect 불변, z 3→5(=topZ 4+1), 복원 OK. J3(tidy): B만 (300,140)→(364,60), A·C·D 불변. J4: 카메라 {0,0,1}→{-25.71,-8.57,2.143}, commit targets `[]`, 복원 OK.
- **P1 (J10) 적용 뒤 화면을 팬/줌만 해도 되돌리기가 사라진다.** 관찰: `undoOffered:false, undoResult:false`. 원인 `EGDeskJointPresentation.sys.mjs:~143` `sameLayout`이 카메라·뷰포트·모든 카드·revision 전체를 비교하고 `sync()`(:~172)가 `undo=null` 처리, `undoOnce`(:~362)도 같은 비교.
- **P2 (J9) 무관한 카드 C를 31px 옮겨도 되돌리기가 사라진다.** 관찰: `undoOffered:false`, commits 1. 같은 원인. 적용으로 건드린 카드만 복원해도 안전한데 전체 장면 일치를 요구한다.
- **P3 (J12) 모델 미리보기 적용 시한이 prepare 시점부터 60초.** 원인 `confirm()` 안 `a.modelChoice.expires = job.expires`(prepare 때 정해진 티켓 만료). 재현: prepare t=0, 패킷 읽다가 t=50s에 전송, 결과 도착, t=61s에 적용 → `ok:false, commits:0`, 미리보기가 사용자 선택으로 되돌아가며 '검토 시간이 끝났습니다.' 결과를 볼 시간이 10초 남짓.
- **P4 (J5-keep) 모델이 `keep`을 답하면 사용자가 고른 `pair` 미리보기가 `keep`으로 덮어써지고** 메시지는 '제안한 구성을 미리 보는 중입니다'(미리볼 것이 없음). 관찰: choice `keep`.
- **P5 (J13) 모델 답이 이미 고른 구성과 같을 때** (`pair→pair`, 이전 실화면 기록과 같은 경우) 화면 문구가 '제안한 구성을 미리 보는 중'이라 아무것도 바뀌지 않았음을 알 수 없다.
- **P6 (J14) 적용 성공 후 알림 0건.** 패널이 조용히 닫히고(`applyPlan`) 되돌리기 위치(패널 재오픈 후 '마지막 적용 되돌리기', :~490)를 알려주지 않는다. 적용이 막혀 `false`일 때도 패널만 닫히고 무음.
- 코드 읽기만으로 얻은 관찰(하네스 미검증, 실제 앱 필요): 적용은 `h.apply`/`record`(`eg-desk-surface.uc.js:41`)로 직접 들어가며 전역 `history.record`(⌘Z, :30352-30360, 메뉴 '배치 되돌리기' :30684)를 거치지 않는다. 즉 적용 직후 ⌘Z는 배치 추천이 아니라 그 이전 수동 이동을 되돌릴 수 있다. 이번 패치 범위 밖.
- 인접 작업 공간: `worksitePlans`(EGDeskAdjacentWorkbench.sys.mjs)는 이 장면에서 쓰이지 않았다(tidy/workbench가 로컬 평면에서 가능). 막힌 평면에서 인접 공간 안이 카메라 이동으로 적용되는 경로는 이번에 시험하지 못함(다음 시뮬 제안 참고).

## 3. 개선 근거
내부 canon: `EGDESK_VISION_GAP_LEDGER.md:1363`(UX-05 '실수로 옮긴 배치를 되돌리고'), `:1503`(배치 되돌리기가 없던 갭), `EGDESK_PRODUCT_INTERACTION_TRACE_ATLAS.md:97`(이동은 '미리보기, 취소·되돌리기' 제공), 사용자 소유 배치 보존·모델은 제안만(DM 이전 ledger의 '모델 제안 ≠ 승인된 실행').
외부 출처와 결정:
- Microsoft HAX Pattern 9C 'Undo automated actions' (https://www.microsoft.com/en-us/haxtoolkit/pattern/g9-c-undo-automated-actions/): '시스템이 사용자 입력을 바꿨음을 알리고, 되돌릴 방법을 제공' → **P6 적용 알림 추가**를 결정.
- Microsoft HAX G9 Support efficient correction (https://www.microsoft.com/en-us/haxtoolkit/guideline/support-efficient-correction) 및 G8 dismissal: 모델이 틀리거나 쓸모없을 때 사용자 원본을 쉽게 유지/복구 → **P4: keep 답은 사용자 선택을 덮지 않음**.
- Apple HIG Undo and redo (https://developer.apple.com/design/human-interface-guidelines/undo-and-redo): 되돌리기 결과를 예측·강조, 사용자가 '무엇이 되돌려지는지' 모르면 의도치 않은 변경 → 적용 알림 문구에 되돌릴 대상과 위치를 명시, 카메라가 사용자가 이동한 뒤에는 되돌리기를 막아 시점이 튀지 않게 함(J11 유지). 같은 문서는 다단계 undo/redo를 권한다 → 이번엔 단일 단계 유지, 다단계/redo는 다음 sim으로 이월(미구현을 명시).
- tldraw History (https://tldraw.dev/sdk-features/history): 되돌리기 항목은 레코드별 diff 묶음 하나로 쌓이고, 해당 레코드가 아닌 변경은 되돌리기를 막지 않는다 → **P1·P2: 적용이 건드린 카드·카메라만 검증**하도록 결정(Figma/Miro/Excalidraw 문서는 이번에 확인하지 못해 근거로 쓰지 않음).
- 결정을 바꾼 출처: HAX 9C(알림), tldraw(범위 한정 undo 유효성), HAX G9(keep 처리). P3의 시한은 외부 출처가 아니라 코드 분석: 티켓 TTL은 전송 동의의 신선도이고 적용 시점 안전은 `sync()`(장면 동일) + `checkDecision`(모드·키·권한)이 따로 보장한다.

## 4. 패치 요약
`overlay/resources/EGDeskJointPresentation.sys.mjs` (+23/-6), `scripts/egdesk-board-arrangement-apply.test.mjs` (+276 신규).
- `sameLayout` 제거, `undoStillValid(u, now)` 추가: 되돌릴 카드들의 rect·z가 적용 직후와 같고, 적용이 카메라를 옮겼다면 카메라도 같을 때만 유효. `sync()`·`undoOnce()`가 사용.
- `RESULT_TTL_MS=60000`: 모델 미리보기 적용 시한을 결과 도착 시점(`now()`)부터 계산. 전송 티켓 `job.expires` 검사는 그대로(보안 가드 약화 없음, 기간 동일, 시작점만 이동).
- `confirm()`: 모델이 `keep`이고 내 선택이 keep이 아니면 선택·`modelChoice`를 건드리지 않고 안내 문구만 표시. 모델 답이 이미 고른 구성과 같으면 '이미 고른 구성과 같습니다' 문구.
- `applyPlan()`: 성공 시 `h.notice`로 적용·되돌리기 위치 안내, 실패 시 '화면이 바뀌어 적용하지 않았습니다' 안내. 기존 보안 동작(적용 직전 `checkDecision`, `sync()`, `commit` 검증)은 변경 없음.

## 6. 철학 점검
원칙: **모델은 제안하고 사용자가 승인한 실행만 적용되며, 사용자 자신의 배치를 보존하고 언제나 되돌릴 수 있다.** 변경은 이를 강화한다. (a) 모델 `keep`/무효 답은 사용자의 수동 선택과 배치를 건드리지 않고 commit 0, (b) 적용 직전 권한·모드·장면 재확인(J7, 응답 시점 J6b)은 그대로 유지, 시한도 같은 60초이되 사용자가 결과를 볼 수 있는 시점부터, (c) 되돌리기는 '적용이 건드린 것만, 아직 적용 직후 그대로일 때만' 허용해 사용자 이후 작업을 덮어쓰지 않으면서(J8/J11 차단) 이후 무관한 작업 때문에 사라지지는 않음, (d) 적용했다는 사실과 되돌리기 위치를 화면에 알림(발견 가능성). 한계: 되돌리기는 여전히 패널 재오픈이 필요하고 알림은 텍스트만 있다.
