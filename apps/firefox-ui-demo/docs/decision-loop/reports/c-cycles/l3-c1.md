## 3. 개선 근거
**내부 canon**
- `apps/firefox-ui-demo/docs/DECISION_MODEL_CONTEXT_SETUP.md:35` 클라이언트 설명에 "월 입력 토큰 로컬 상한"이 구현 모듈 기능으로 명시, `:148` §5 Owner 결정 4번 "로컬 월 토큰 상한 **기본값**"은 미결. 코드 주석 `codex-bridge-server.mjs:226`의 "§5.4"는 이 소유자 결정 항목을 가리킨다(Atlas §5.4는 provider/model/fallback이라 다른 주제이며, 상한/사용량 canon은 위 두 줄이 전부였다; ATLAS:2910 §5.6은 budget이 "실제 Run 제한을 자동 확정하지 않는다"고만 규정).
- 결론: canon은 **상한 기본값을 소유자가 정한다**(없으면 상한 없음)와 **UI/설정 경로는 정의하지 않는다**. 따라서 "기본 상한 없음" 의미론은 유지하고, 상한 설정 UI는 구현하지 않으며 gap으로 보고한다. 단, 상한이 한 번 선택되면 그것이 재시작으로 사라지거나 우회되는 것은 안전 구멍이므로 사용량+상한 저장만 구현.
- 키 파일 규약(`egdesk-decision-credential.mjs` 헤더: 0600, 0700 디렉터리, 임시파일→fsync→rename)과 `egdesk-bridge-settings.mjs`(손상 파일 `.corrupt-` 보관, 새 버전 미덮어쓰기)를 그대로 따랐다.

**외부 출처**
- OpenAI Spend limits https://developers.openai.com/api/docs/guides/spend-limits : 제공자 쪽 "hard spend limit"만이 실제 청구 상한(429, 즉시는 아님)이고 alert는 차단하지 않는다. → **결정 변경**: 로컬 토큰 합계는 청구액이 아니라 "보조 가드"로 표기/설계하고(파일에 `inputTokens`만, 금액 필드 없음), 상한 파일에 금액·잔액을 넣지 않았다. 또 hard limit 오류 코드(`project_spend_limit_exceeded` 등, https://help.openai.com/en/articles/6614457-troubleshooting-api-usage-and-spend-limits)가 `rate_limited`로 분류되는 문제를 발견해 follow-up으로 기록(범위 밖, 다른 레인 테스트 영향 가능).
- OWASP Secrets Management / POSIX atomic rename(임시파일 fsync→rename→디렉터리 fsync)은 새로 가져온 것이 아니라 기존 writer 패턴 재사용이 맞다는 확인용이다. 이번 조사에서 새로 fetch한 문서는 OpenAI 두 건뿐이며 OWASP/SQLite 문서는 열람하지 않았다(기존 코드 주석에 근거 이미 있음). 결정을 바꾼 출처는 OpenAI spend-limits뿐.
- 월 경계는 기존 코드의 UTC 기준을 유지(OpenAI 청구 월도 UTC 기준으로 알려져 있으나 이번에 1차 출처로 확인하지는 않았음).

## 6. 철학 점검
원칙: **사용자가 지출을 통제한다 / 선택은 재시작을 넘어 보존된다.** 소유자가 한 번 고른 상한이 재시작 한 번으로 사라지거나 우회되면 통제가 아니다. 변경은 기본값(상한 없음)을 소유자 결정으로 남기고 임의 기본값을 만들지 않으며, 모델 추천과 승인 실행의 분리(`no_credit` 후 자동 재시도 없음, 새 승인 요청에서만 복구)는 그대로다. 키는 새 파일에 절대 쓰지 않아 삭제 시 잔존물이 없다.
