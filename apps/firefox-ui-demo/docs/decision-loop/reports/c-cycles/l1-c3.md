# L1 cycle 3: Board 일회 질문의 발췌 선별 (Decision model)

브랜치 `lane/c3-board-reply-screening` (base `int/c1` 1dc3a84). 모든 관찰은 **synthetic harness**: 임시 SQLite desk store, 실제 `createBoardAgentAskService`, 실제 `selectBoardAgentContext`, 실제 Decisions client(mock fetch), 실제 `createReviewFlow`/`beginAgentReply`(소유자가 보는 문구). 실제 앱, 실제 OpenAI, 설치된 Firefox는 쓰지 않았다. 암호화 번들 의존성이 이 환경에 없어 `egdesk-board-agent-ask-roundtrip.test.mjs`는 skip된다(수정한 기대값은 실행 검증 못 함).

## 1. 여정 (신규 `helper/egdesk-board-agent-screening-journey.test.mjs`, 25 tests)
소유자가 승인 발췌 3개 저장(E1 "Friday visitors park behind the gym.", E2 "Meet in the atrium on Friday.", E3 "Catering invoice totals seventy credits.") -> 일회용 코드 발행 -> 질문 "Where do visitors park on Friday?" -> `prepare` -> `run` -> 소유자 회신 작성창 문구.
모드 off/advisory/on x Decisions 응답 {확신, 저확신, 기권(전부 0), 범위 밖 alias(c99 포함), 429 insufficient_quota, 429 spend_limit_reached, timeout(1s)} = 21 + 추가 4(off 거부, 철회/재저장/재발행, 진행 중 철회, draft 경로 off).

관찰표 (패치 전 / 후 비교는 5절). 사용된 발췌 번호:
| 모드 | 응답 | Decisions 요청 | 최종 답에 쓰인 발췌 | 패치 전 소유자 문구 |
|---|---|---|---|---|
| off | 모두 | 0 | 1,2 (로컬 단어 일치) | 로컬 문구 |
| advisory | 확신 / 저확신 / 기권 / 범위밖 | 1 (질문+승인 후보 3개 전체) | 1,2 (선택 불변) | **Decisions 언급 없음** |
| advisory | 429 x2 / timeout | 1 | 1,2 | **언급 없음** |
| on | 확신 | 1 | 2 (Decisions 선택) | "관련성 판단에 별도 Decisions API를 사용했습니다." |
| on | 저확신(0.5/0.55), 기권 | 1 | 없음(빈 답, source=decision) | "관련 공개 발췌문을 찾지 못했습니다..." |
| on | 범위 밖 alias c99 | 1 | 1,2,3 (c99 무시: client가 요청 이름만 채택, 승인 세트 밖 항목은 불가) | Decisions 사용 문구 |
| on | 429 x2 / timeout | 1 | 1,2 (로컬 폴백) | **로컬과 동일 문구, 실패 언급 없음** |

확인된 불변식(모든 모드, 패치 전부터 성립): 답에는 승인 발췌 원문만 들어간다(범위 밖 id는 `allowed` 맵에서 걸러짐). Decisions 요청 본문은 `{question, candidates[alias,text]}`만이다. off에서는 `prepare`가 `DECISION_OFF`로 거부하고 요청 0. 승인 후 철회, 다른 발췌로 재저장, 코드 재발행이면 `STALE`이고 Decisions 요청 0. Decisions 응답 대기 중 철회하면 늦은 응답은 버려진다. Responses draft 경로: 설정 파일이 없으면 availability.draft=false, `prepare(draft)`는 `DRAFT_OFF`, 실제 config reader는 파일 없음 -> null, 키가 Decisions 키와 같으면 null(대체 키로 쓰지 않음). 초안 요청 0.
질문자(asker)가 보는 것: 소유자가 편집해 돌려준 답 텍스트뿐이며 선별 메타데이터는 없다. 이 점은 의도된 설계로 두었다.

## 2. 문제 (재현, 패치 전 출력 `evidence/l1-c3/before-patch.tap`: 25 중 14 실패)
1. **advisory 침묵 송신.** advisory에서도 질문과 승인 발췌 전체가 Decisions로 전송되지만(요청 1회), 결과는 선택에 반영되지 않는다. prepare 응답에는 모드가 없고(`previewDecisionMode:null`) 소유자 회신 문구에는 Decisions가 전혀 언급되지 않는다(`answerSource`는 `decisionEgress && source !== 'local'`일 때만 언급, advisory의 source는 'local'). 소유자는 데이터가 나갔고 비용이 났다는 사실도, 결과에 영향이 없었다는 사실도 모른다.
2. **실패 은닉.** on 모드에서 429(insufficient_quota, spend_limit_reached)나 timeout이면 selector가 `local_fallback`으로 로컬 선택(E1,E2)을 돌려주지만 서비스는 이를 `source:'local'`로 뭉개고, 소유자 문구는 요청 없이 로컬로 고른 경우와 동일하다. 사용자가 외부 선별에 동의했는데 실패했다는 신호가 없고, 선택 결과가 Decisions 결과(E2만)와 다르다는 것도 보이지 않는다. 코드 위치: `egdesk-board-agent-ask.mjs` run()의 `source`, `EGDeskReviewHandoff.sys.mjs` `beginAgentReply`의 `answerSource`.

## 3. 개선 근거
- 코드 canon: `DECISION_MODEL_CONTEXT_SETUP.md` Board 일회 질문 절("외부 선별 ... `advisory`에서는 외부 판단이 로컬 선택을 바꾸지 않는다"), Contract:2621("Decision Model은 이 집합 안에서만 자료를 고르며 모델의 판단이 권한을 넓히지는 않는다"). 선택 세트 자체는 이미 canon을 지킨다. 빠진 것은 그 세트를 고른 방식에 대한 투명성이다.
- OWASP Authorization Cheat Sheet, Least Privilege / Deny by Default (https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html): 실패 시 더 넓게 열지 않고 좁은 쪽으로 닫는다. 현 폴백(승인 세트의 로컬 부분집합)은 이미 맞아서 **선택 로직은 바꾸지 않기로** 결정했다.
- GDPR Art.5(1)(c) / ICO data minimisation (https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/data-protection-principles/a-guide-to-the-data-protection-principles/data-minimisation): 목적에 필요한 것만 처리한다. advisory는 결과를 쓰지 않으면서 전체 후보를 보내므로 최소화 관점의 비용이 있다. 이 출처가 **advisory 송신을 막지 않고 투명하게 공시**하되(canon이 advisory 평가를 허용), 소유자가 알고 고르게 하는 쪽으로 결정했다. advisory 송신 자체를 끄는 변경은 canon 변경이라 하지 않았다(대안으로 보고).
- Microsoft HAX G11 "why the system did what it did"(https://www.microsoft.com/en-us/haxtoolkit/guideline/make-clear-why-the-system-did-what-it-did): 어떤 경로가 결과를 만들었는지 접근 가능해야 한다. 소유자 문구에 반영.

## 4. 패치 (3 제품 파일 +16/-7, 테스트 3개 기대값 확장)
- `helper/egdesk-board-agent-ask.mjs`: `prepare`가 `decisionMode` 반환. `run`이 외부 선별을 요청한 경우 `screening`(`decision`|`advisory`|`fallback`)을 결과에 추가(extract, draft 모두). 발췌 선택 로직과 `source`는 불변.
- `overlay/resources/EGDeskBoardAgentAsk.sys.mjs`: 미리보기에 advisory 한 문장("기록만 모드라 그 판단은 선택에 반영되지 않고 ... 그래도 전송되며 API 비용이 생길 수 있습니다"), 결과의 `screening`을 검증해 `onAnswer`로 전달(없으면 키 생략).

- 기대값 확장: `egdesk-decision-quota-board-extract.acceptance.test.mjs`(429 -> `screening:'fallback'`, 200 -> `'decision'`), `egdesk-board-agent-ask-roundtrip.test.mjs`(draft + Decisions -> `screening:'decision'`, 번들 의존성 부재로 skip되어 미실행).
