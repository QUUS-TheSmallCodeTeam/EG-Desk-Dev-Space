### 제안 (플래그 뒤, 구현은 advisory까지)
1. **S1 사전 분류**: 메시지가 도착하면 기존 컨텍스트 선별 요청과 **병렬**로 시작, 같은 800 ms 예산을 공유. 시간 안에 답이 없으면 이번 턴은 기억 없이 진행하고 사유를 기록(`withinBudget=false`).
2. **S2 가져오기/재구성**: 
   - 첫 턴: 네이티브 스레드 준비(`thread/start`)와 **겹쳐서** 실행한다. 지금은 판정 요청을 먼저 기다린 뒤 스레드를 만든다(codex-chat-runtime의 준비 순서). 겹칠 수 있는 시간은 실측이 필요하므로 advisory가 `prepMs`(판정 준비부터 turn/start까지)를 기록한다.
   - 세션 중간: 겹칠 작업이 없다. 사전 분류가 need=yes일 때만 가져오며, 선택지는 (A) 예산과 별도의 상한(예: 2 s)까지 턴 시작을 기다림 — 필요한 질문에만 지연이 생김, (B) 상한을 넘기면 늦은 패킷을 **다음 턴 시작에 이월**(오래됐다고 표시), (C) 턴 도중 steer로 주입(동작 변경이 커서 보류). 권장은 (A)+(B). 상한은 소유자 결정이고 advisory 측정으로 정한다.
   - links-first를 mid 기본값으로 두면 토큰이 절반 이하(5.2k vs 9.9k, 3.0k vs 8.3k, 추정)지만 호출 수는 같아 지연 단축은 작다(스캔 한 번이 가벼워짐).
3. **S3 쓰기 판정**: 응답에 영향이 없으므로 **응답 후**(turn/start 이후 백그라운드)에 실행. 제안은 호스트 쓰기 경로(`createWikiWriter`, 기본 꺼짐)가 권한·리비전 검사 뒤에만 저장.
4. 비용: advisory도 실제 토큰을 쓴다(첫 턴 약 12k, 세션 중간 5–10k, 작은 말 0.7k 추정). 그래서 플래그는 기본 꺼짐이며 `budget`으로 links-first를 줄 수 있다.

### 구현된 advisory 배선 (`codex-chat-runtime.mjs`, 플래그 기본 꺼짐)
- 설정: `decisionContext.turnMemory = { mode(), wiki({body,context}), scope?, live?, eligible?, budget?, ontologyWrite?, deadlineMs? }`. `mode()`가 `'advisory'`일 때만 동작하고 다른 모든 값('on' 포함, 아직 미구현)은 꺼짐. 설정이 없으면 코드는 아무것도 하지 않는다. 브리지 서버는 이 설정을 만들지 않는다(위키 어댑터가 없음; L8/후속 사이클이 공급).
- 턴 위치는 스레드 준비 전에 `turnPosition(context)`로 읽고(준비 시간 측정 시작), `turn/start`가 수락된 뒤 **백그라운드**로 `prepareTurnMemory`를 돌린다: 보내는 쪽(`send`)은 기다리지 않고 오류를 삼킨다. 답변 모델이 받는 것은 바뀌지 않는다(시험: turn/start 입력이 플래그 유무와 바이트 단위로 동일).
- 세션 중간을 현실처럼 측정하기 위해 **그림자 영수증**(실제로 전달했다면 모델이 가졌을 페이지)을 스레드별로 메모리에만 보관(최대 50개). 실제 영수증이 아니므로 어떤 전달에도 쓰이지 않는다.
- 기록: 보정 로그에 `turn_memory` 항목(내용 없음): 위치(first/mid), 가져오기 결과(ran/skipped/partial/fallback/empty), 사전 분류 세 술어의 p·문턱·`would`, 쓰기 대상 선택의 top/second/confidence/margin/N, 단계별 지연(`prepMs, triageMs, fetchMs, writeMs, totalMs`, 호출 수, 사전 분류가 800 ms 안에 끝났는지 `withinBudget`; 10 ms 단위 반올림), 런 종료 라벨(run 상태, 도구 활동 수). 쓰기는 하지 않는다(advisory는 판정 제안까지만).
- 시험 6개(`egdesk-turn-memory-wiring.test.mjs`): 꺼짐(미설정/off/on) 무호출, 입력 바이트 동일·호출이 dispatch 이후, 멈춘 호출이 턴을 지연시키지 않음·실패해도 무영향, 위키 없음/부적격 무동작, 첫 턴→세션 중간→작은 말(위치·그림자 영수증·타이밍·내용 없음 확인·라벨), 가져오기 실패의 닫힌 fallback 기록.
- 스키마(보정 로그, 같은 v2 안의 선택 필드): feature `turn_memory`, q `triage_courtesy|triage_need|triage_record|write_target`, would `fetch`, `position`, `memory`, `timing`.
