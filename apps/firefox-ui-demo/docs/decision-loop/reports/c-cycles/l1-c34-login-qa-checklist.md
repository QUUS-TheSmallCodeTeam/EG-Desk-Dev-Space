# Claude 로그인 화면 라이브 QA 체크리스트 (EG-Desk 안에서 로그인)

대상: 소유자의 기존 프로필 (`egtc3irr`), 브리지 환경 `EGDESK_TERMINAL_OPEN_URL=on`. 준수 원칙: **로그인의 모든 단계는 사람이 직접 한다.** 자동화(드라이버, 에이전트, EG-Desk 코드)는 claude.com / claude.ai / platform.claude.com 페이지를 누르지도, 입력하지도, 읽지도, 캡처하지도 않는다. 인증 코드는 화면에 보이는 그대로 사람이 터미널에 직접 붙여 넣는다.

시작 전: 프로필의 `chrome/`과 `user.js`는 Main이 이미 백업. Claude CLI가 로그아웃 상태여야 로그인 버튼이 보인다 (이미 로그인 상태면 `로그인` 대신 `다시 확인`만 보인다).

드라이버 (선택, 단계 1~3만 대신 해 줌, 4단계부터는 사람):
```
node scripts/egdesk-claude-login-live-qa.mjs --out <dir>                   # 1~3단계, 끝나면 "waiting for the person" 출력 후 멈춤
node scripts/egdesk-claude-login-live-qa.mjs --resume-after-signin         # 사람이 "끝났다"고 한 뒤: /engines/claude/refresh 결과만 읽음
node scripts/egdesk-claude-login-live-qa.mjs --dry-run                     # 계획만 출력
```
드라이버가 하는 클릭은 설정 열기 / 계정 탭 / `로그인` 버튼뿐이다. 스크린샷은 EG-Desk 자신의 요소 둘 (계정 설정의 Claude 행, 터미널 카드 제목줄)뿐이고 창 전체는 찍지 않는다. 브라우저 카드가 겹치면 그 스크린샷은 건너뛴다.

| # | 사람이 해야 할 일 / 하는 일 | 화면에서 보여야 하는 것 | 이상하면 |
|---|---|---|---|
| 0 | 설정 → 계정 → Claude 행을 연다 | 행에 `로그인 필요` 계열 상태, 버튼 `로그인`(활성), 버튼 `다시 확인`. 안내 문구는 평문뿐이고 Claude/Anthropic 로고나 그림은 없다 | 버튼이 없으면 이미 로그인된 상태이거나 Claude CLI가 설치되지 않음 (행의 힌트가 이유를 말한다) |
| 1 | `로그인` 클릭 | 버튼이 잠깐 `터미널 여는 중…`, 곧 **터미널 카드**가 같은 Desk에 새로 생김 (설정 창을 가리지 않는 빈 자리). 터미널에 `claude auth login --claudeai` 한 줄이 입력되고 실행됨. 행 아래에 결과 문구(`터미널에서 Anthropic 공식 로그인을 마친 뒤 다시 확인을 눌러 주세요 …`) | 터미널이 안 뜨면 문구가 `터미널 카드를 열지 못했습니다` 또는 `터미널 준비를 확인하지 못했습니다`로 바뀐다 (이 경우 플래그와 무관: 오늘도 같은 동작) |
| 2 | (자동) CLI가 로그인 주소를 연다 | 시스템 기본 브라우저가 **아무것도 열리지 않는다.** 대신 **EG-Desk 브라우저 카드가 새로 생긴다** (터미널 카드 옆 빈 자리, 카메라가 움직이지 않고, 지금 쓰던 카드가 바뀌지 않음, 터미널에 입력 포커스 유지). 터미널에는 CLI 안내 줄(브라우저가 안 열렸다면 이 주소로 가라는 줄)이 같이 보일 수 있다 | **시스템 브라우저가 열리면**: CLI가 `BROWSER`/`open`을 쓰지 않는 경우다. 플래그의 한계를 기록하고(어떤 CLI 버전인지) Main에게 알린다. 카드가 안 뜨면 `settings`가 아닌 `bridge` 로그에 `[terminal] open-url opener could not be installed`가 있는지 본다 |
| 3 | (자동 확인, 드라이버 1~3단계) | 터미널 카드와 브라우저 카드가 모두 존재하고, 터미널 제목줄 스크린샷이 저장됨 | 드라이버가 `CHECK FAILED`를 내면 위 2단계 확인 |
| 4 | **사람이** 브라우저 카드 안에서 로그인한다 (Google / Apple / 이메일 중 사람이 선택, 입력, 승인) | 카드 안에 Anthropic의 로그인 페이지. EG-Desk는 페이지에 아무것도 하지 않는다. (에이전트가 이 카드를 선택해 관찰/조작하려 하면 `BROWSER_CARD_OPAQUE`로 거절됨: 로그인 중 에이전트에게 이 카드를 선택해 주지 말 것) | 페이지가 로드되지 않으면 일반 브라우저 카드 문제 (플래그와 무관) |
| 5 | **사람이** 동의(권한 허용) 화면에서 직접 승인한다 | Anthropic의 동의 화면 | |
| 6 | 승인 뒤 카드에 **코드 페이지**(`platform.claude.com/oauth/code/callback`)가 뜨고 인증 코드가 보인다 | 코드가 카드에 표시됨. 이 화면은 **스크린샷으로 찍지 않는다** (코드는 자격 증명) | 코드 페이지 대신 오류면 CLI의 안내(터미널)를 읽는다 |
| 7 | **사람이** 코드를 복사해 **터미널 카드**의 `Paste code here if prompted >` 에 직접 붙여 넣고 Enter | 터미널에 로그인 성공 메시지. EG-Desk는 코드를 읽지도 저장하지도 전달하지도 않는다 (터미널 입력은 사람의 키 입력) | 붙여 넣기가 안 되면 터미널 카드를 클릭해 포커스를 준 뒤 다시 |
| 8 | "끝났다"고 알린다. 사람이 설정의 `다시 확인`을 누르거나, 드라이버 `--resume-after-signin` | Claude 행이 `로그인됨` 계열로 바뀌고 방식/요금제 배지가 보인다 (계정 라벨은 화면에만, 드라이버 출력에는 단어만) | 오래 걸리면 다시 확인을 한 번 더. 여전히 `로그인 필요`면 7단계의 코드가 맞는지 터미널 메시지를 본다 |
| 9 | 정리: 로그인 카드를 닫는다 (사람이) | 브라우저 카드를 닫아도 터미널과 로그인 상태에 영향 없음 | |

플래그 꺼짐 확인 (같은 프로필, 브리지 환경에서 `EGDESK_TERMINAL_OPEN_URL` 제거, 브리지 재시작): 1단계까지 같고, 2단계에서 **시스템 기본 브라우저가 열린다** (오늘의 동작). 터미널 카드의 `echo $BROWSER`는 비어 있거나 기존 값이다.

플래그 켬 확인용 터미널 명령 (사람이 터미널 카드에서 입력, 부작용 없음): `echo $BROWSER` → `<데이터 폴더>/terminal-opener/egdesk-open-url`, `which open` → `<데이터 폴더>/terminal-opener/bin/open`, `open .` → 원래대로 파인더가 열림 (http(s)가 아닌 인자는 시스템 `open`).

기록할 것: CLI 버전 (`claude --version`), 2단계에서 `$BROWSER`로 열렸는지 `open`으로 열렸는지 (이 저장소에서는 구분 못 함: 열린 경로는 둘 중 아무거나), 브라우저 카드의 위치/포커스 변화 여부, 막힌 단계.
