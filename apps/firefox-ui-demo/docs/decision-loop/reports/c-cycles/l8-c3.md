# L8 / C3 브라우저 반사 후속 보고

브랜치 `lane/c3-browser-reflex-followups` (base int/c1 1dc3a84), 커밋 `e8770bc Browser reflex: no fill before a decided link; max_steps carries the last public failure code`. 합성 검증만(실제 provider/service/runBrowserReflex + UI·Decisions 대역). 실제 Firefox 검증 없음.

## 1. 대기 값 매핑이 link 결정에도 실행됨
- 재현(수정 전, `matrix-before.tap` C3-1): 필드 Nickname + 링크 Pricing, values={nickname}, next_step=[L1] 0.97 → 요청 1건 **fill**, navigate 0, Decisions 요청 2건(next_step + field_0 매핑). 다음 스텝에서야 navigate. 즉 떠날 페이지에 값을 입력하고 매핑용 외부 호출도 한 번 더 썼다.
- 판단: canon §3.3(`DECISION_MODEL_CONTEXT_SETUP.md` "받은 값으로 입력", 정확 지정 필드는 예약, 일반 화면에서만 매핑)은 값을 입력하는 단계 자체를 허용하지만, 시스템 규칙(`egdesk-browser-reflex.mjs` REFLEX_RULES "Pick a text field only when typing into it moves toward the goal")과 §5.2(받은 값 입력 = 목표를 위한 자동 범위)는 결정된 다음 단계가 이 페이지를 떠나는 이동일 때 입력을 요구하지 않는다. 이동 직전 입력은 (1) 낭비, (2) 페이지 스크립트(자동저장/라이브 검색)가 값을 볼 수 있는 불필요한 노출, (3) 불필요한 외부 판단 1회다. 같은 페이지의 버튼(검색 실행 등) 결정에는 기존 테스트가 요구하는 대로 계속 먼저 입력한다.
- 패치: `runBrowserReflex`에서 `decision.option.item.kind !== 'navigate'`일 때만 매핑/입력 블록 실행. 값은 pending으로 남아 다음 페이지에서 쓰인다. 적용 후: 요청 1건 navigate, fill 0, field_0 요청 0. 대조군: next_step=[F1] fill 1, [B1] 버튼 + 값 → fill 1 유지.

## 2. 거절된 마지막 스텝의 코드가 모델에 안 감
- 재현(수정 전): UI가 not-dispatched로 거절 → 결과 `{"outcome":"max_steps"}`뿐, code 없음.
- canon 허용 범위: `reflexResultForModel`은 이미 `outcome, reason, code, url, ...`만 내보낸다(`tool_failed`에 `code` 포함). 코드는 provider의 `reflexStepError`가 도구 오류 JSON의 `error.code`(고정 BROWSER_* 식별자)만 읽는다. 페이지 텍스트는 코드에 들어가지 않는다.
- 패치: `finish('max_steps')` 직전에 마지막 도구 호출이 실패였고 코드가 `/^[A-Z][A-Z0-9_]{2,63}$/`이면 `reason:'step_rejected', code`를 담는다(방어적 정규식으로 자유 텍스트 차단). 성공 호출이 있었으면 `lastFailure`가 지워져 기존 형태 유지.
- 검증: 결과 키는 정확히 `code, decisions, outcome, reason, steps`; `example.test|pricing|Synthetic shop` 문자열 0건. 결과 예: `{"outcome":"max_steps","reason":"step_rejected","code":"BROWSER_OBSERVATION_STALE","steps":1,"decisions":1}`.
- 부수 확인: 초기 mock이 navigate 뒤 wait를 지원하지 않아 `BROWSER_WAIT_OUTCOME_UNKNOWN`이 나왔다. mock을 고쳐 성공 경로가 코드 없이 끝남을 확인(테스트 대역 문제, 제품 결함 아님).

- 이 비율은 트리거 단어 위주로 만든 표본이라 실사용 비율이 아니다. 단어가 들어간 문서/블로그 링크는 reflex가 아니라 추론 모델 경로로 넘어간다.
- 놓침 5: /order/place, /grant/allow, /logout, /account/close, /subscriptions/cancel. 라벨 판정도 같은 분류기를 쓰므로 `classifyAction` 자체의 범위이며 href 필터의 문제가 아니다(분류기를 이 사이클에서 넓히지 않음). GET 로그아웃/탈퇴 류는 URL 규칙을 새로 만들지 않고 분류기 개선 항목으로 남긴다.
- 완화하지 않음: 마지막 세그먼트만 보는 좁은 규칙도 /docs/api/delete-endpoint, /tag/delete를 막으므로 이득이 작고, canon(§5.2 삭제·결제는 사람, §3.3 분류기 재판정)은 더 좁은 규칙을 명시하지 않는다. 전후 측정 결과 동일(`href-measure-before/after.json` cmp 동일).
