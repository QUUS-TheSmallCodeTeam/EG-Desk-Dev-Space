## 바꾼 것 (테스트만)
1. 장치의 배치 런타임을 브리지와 같은 모양으로: `enabled`는 advisory·on 모두, `live`는 on일 때만. 시계와 타이머는 런타임의 가상 시계에 연결(L4 자체 테스트와 같은 방식).
2. 기존 포인터 기대 두 건은 **live(on)** 아래로 옮겼고, 의도는 그대로입니다.
   - 소유자가 할 일 없음: 사실은 `requester / review`로 올라오고 기록은 `raised`. 요청자는 소유자 Desk에 대화가 없어 경로 없음, 소유자 대화 메시지 0건.
   - 소유자가 결정해야 함: 사실 `owner / owner_action`, 소유자 대화에 포인터 **정확히 1건**, 확인 후 사실 회수.
3. **advisory 사례 추가** (소유자 결정 필요 / 불필요 두 경우 모두):
   - 요청자는 여전히 B이고 뷰어 옵션은 여전히 B 근처입니다(식별은 모드와 무관).
   - 판정은 "point"로 내려지고 `would: point`, `pointer: 'advisory'`로 **기록만** 됩니다.
   - 포인터 사실 없음(런타임과 heartbeat 양쪽), 소유자 대화 메시지 0건, 메시지 이벤트 0건, 포인터 작성 요청 0건, 확인 콜백 0건.
4. 장치가 heartbeat를 직접 nudge하던 줄을 뺐습니다. 이제 배치 런타임이 스스로 nudge하는 제품 동작(요청 후 0.5초 안에 판정, 한 박자 뒤 재시도)에 의존하므로 단언이 더 엄격해졌습니다. "판정한 박자에는 아무것도 게시되지 않는다"도 추가했습니다.
5. 브리지 소스 단언 2줄 추가: `enabled`가 advisory·on, `live`가 on일 때만인지. 장치의 두 모드가 브리지의 실제 설정과 같다는 근거입니다.
