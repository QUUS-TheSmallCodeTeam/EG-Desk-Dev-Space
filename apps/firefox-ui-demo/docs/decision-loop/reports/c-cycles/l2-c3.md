# L2 / c3 — 복구 경로와 오래된 결과의 안전성

브랜치 `lane/c3-chooser-recovery` (base `int/c1` a17c4e4). 증거: `$L/evidence/l2-c3/` (`table-before.json`, `table-after.json`, `recovery-before.tap`, `recovery-after.tap`, `gate-after.tap`, `base.txt`).

## 0. 범위와 한계
- 합성 하네스 관찰(실제 client/runtime/HTTP/Surface chooser, 가짜 DOM). 설정 변경은 제품이 하는 방식으로 모사: **이 창의 Decisions 저장은 scope `key`만 바꾸고 `editKey`는 유지**(`chatChoiceScope`: `[editKey, canvasSelectionRevision, choiceSettingsGeneration]`), **다른 창의 변경은 status의 `boardRevision`만 바뀌고 scope key는 불변**, 계정 변경은 scope가 null.
- 실제 앱 필요 확인: 실제 DOM 포커스(`:focus-visible`), 스크린리더, 설정 카드와의 상호작용 타이밍. L1 `chatChoiceScope` 게이트, L3 예산, L5 timeout 렌더링은 미변경.

## 2. 무엇이 기록(history)으로 남고 무엇이 비활성이 되는가 (정의)
canon: 추천은 "이 화면에만 표시되는 추천… 실행하지 않음"의 일시적 조언(c1 문구), 제안/수락은 실행·저장이 아님(Contract `EGDESK_INTERACTION_AND_ORCHESTRATION_CONTRACT.md:2308`), 재시도·재전송은 현재 권한을 먼저 대조(`:1091`). 정의:
- 설정(키·모드)이 **이 창에서** 바뀌면 chooser 패널 전체가 닫힘: 추천 문구·`[이유 묻기]`·`[다시 검토]` 등 모델 유래·권한 유래 요소는 **기록으로도 남기지 않고 즉시 비활성**(이미 L1 동작, 유지).
- 사용자가 직접 입력한 보기(raw text)는 사용자의 선택이므로, 결과가 *전달되지 않은* 상태(대기 중·no-pick)에서는 보존. *전달된 추천* 이후에는 L1 sim D 정책("a delivered recommendation leaves no reusable options")대로 보존하지 않음 → **의도적으로 유지**(테스트가 명시한 정책이며 L1 소유).
- **다른 창**에서 바뀌면 화면의 추천은 그대로 보이되, 그 추천에 기대는 유일한 행동 `[이유 묻기]`는 클릭 시점에 현재 상태를 재확인하여 거절(기존 동작이 올바름).
- 일반 전송으로 나가는 초안은 chooser와 완전히 분리된 일반 메시지.

## 3. 패치 (`eg-desk-surface.uc.js` 만, +7/-2)
1. `sync()`: scope 불일치로 패널이 닫힐 때 패널이 포커스를 갖고 있었다면 `[보기 추천]`(보이면) 또는 작성창으로 포커스를 돌려줌.
2. `rawEditsOf`: `pending`, `manual` 단계도 사용자의 raw 보기를 보존(결과·재시도 권한은 버림).
- 출처 반영: VA.gov focus-management(https://design.va.gov/accessibility/focus-management — 콘텐츠 제거 시 "logical location" 복원)과 GOV.UK error-message(https://design-system.service.gov.uk/components/error-message — 오류 시 입력 유지)가 위 두 수정을 정했고, **recommended 단계 보존은 L1 정책을 존중해 하지 않기로 결정**(내부 테스트 `egdesk-chat-choice-settings-return.test.mjs` sim D가 처음 시도(전부 보존)를 막아 되돌림).
- 카피 변경: **없음**(신규 라벨/문구 0).

## 5. 철학 점검
원칙: **권한이 철회되면 모델 유래 요소는 즉시 비활성이고, 사용자의 입력과 작업 위치는 보존.** 키 삭제/모드 변경 뒤 추천·`[이유 묻기]`는 남지 않고(다른 창이면 클릭 시 재확인 거절), 일반 전송은 chooser와 분리되어 Decisions 호출을 만들지 않는다. 동시에 사용자는 포커스를 잃지 않고, 아직 추천이 전달되지 않은 입력은 되살릴 수 있다.

## 6. 한계 / 다음 sim
- 전달된 추천 이후 설정 저장 시 보기를 지우는 L1 정책은 유지(제안만: 사용자가 방금 입력한 보기를 지우는 것이 맞는지 L1/Main 판단).
- 다른 창에서 키만 삭제된 경우도 추천은 클릭 전까지 화면에 남는다(동작상 안전하나 시각적으로는 최신이 아님; 알림 문구가 필요하면 신규 카피라 사용자 승인 필요).
- 다음 sim 제안: 다른 창에서 변경됐을 때 화면의 추천에 "오래됨" 표시가 필요한지(카피 승인 전제), 그리고 설치 앱에서 실제 포커스 링 확인.
