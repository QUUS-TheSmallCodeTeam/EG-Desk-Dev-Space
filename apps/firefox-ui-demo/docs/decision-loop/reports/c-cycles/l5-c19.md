## 1. 구현
**(1) undo 기록** (`egdesk-file-tools.mjs`)
- 무언가를 쓴 편집마다 기록을 하나 남김(편집 전 내용, 편집 후 hash, editId, runKey). 기록은 그 Run과 대화에 묶임.
- 상한: 대화당 50개, 8 MB. 오래된 것부터 버리고, 혼자 상한을 넘는 기록은 남기지 않음.
- 한 기록이 한 편집을 되돌림: 기본은 가장 최근 것이고, editId를 주면 그 편집.
- **파일이 그 편집이 남긴 상태 그대로일 때만** 되돌림. 그 뒤에 바뀌었으면 `undo_conflict`를 돌려주고 나중 변경을 덮어쓰지 않음.
- 만든 파일은 지우고, 바꾼 파일이나 (승인받아) 지운 파일은 이전 내용으로 되돌림. 쓰기는 원자적임.
- undo는 묻지 않음. EG-Desk가 바꾼 것을 되돌리는 것이기 때문임.
- 경로: 같은 대화의 다음 턴에서는 도구 `egdesk_undo_edit`, 화면과 사람은 provider의 `undoRecords(run)`/`undo(run, editId)`. QA Run에서는 금지함.
- 편집 결과에 `editId`가 들어감.

**(2) ssh agent** (`egdesk-command-runner.mjs`, `egdesk-command-executor.mjs`)
- `COMMAND_ENV_APPROVED_ONLY = ['SSH_AUTH_SOCK']`.
- 실행기는 장부가 `allow`(사람이 한 번 승인함)라고 답한 명령에만 `approved: true`를 runner에 넘기고, 그 명령만 ssh agent를 받음. 승인으로 다른 변수가 추가되지는 않음(테스트로 확인).
- push처럼 바닥이 승인으로 보내는 명령이 이 경우임. `git status` 같은 승인 없는 명령은 받지 못함.

**(3) 브리지 연결** (`egdesk-own-tools-wiring.mjs`, `codex-bridge-server.mjs`)
- 개발 플래그 **`EGDESK_OWN_TOOLS=on`**. 다른 값이나 없음은 off이고, 이때 `createOwnToolsWiring`은 `null`을 돌려주며 브리지는 아무것도 추가하지 않음.
- on이면:
  - 명령, 파일 provider와 하나의 승인 장부를 만듦.
  - runtime의 `ownTools`를 켜고, 중립 폴더는 `<EG-Desk 데이터 폴더>/engine-folders/empty`(0700). 비어 있지 않으면 쓰지 않음(→ OWN_TOOLS_UNAVAILABLE).
  - 실제 `child_process.spawn`을 쓰고, 명령은 detached로 실행함. **프로세스 그룹 kill**은 `process.kill(-pid, sig)`이고, 실패하면 자식만 kill함.
  - 출력은 runtime의 RunOutputStore로 보냄. git 사실은 기존 `createGitTargetInspector()`로 얻음.
  - terminalGate: 사람이 설정한 `EGDESK_TERMINAL_GATE`가 있으면 그 설정(mode, inspect, method)을 그대로 쓰고, 없으면 'on'으로 함. 거기에 장부를 `hookBroker`로 붙임(답 읽기와 턴 수명주기).
- **off일 때 기존 경로가 그대로임**:
  - provider 목록의 리터럴 `[browserProvider, planProvider, annotationProvider]`는 그대로이고 뒤에 `.concat(…)`만 붙임. 이 리터럴을 검사하는 기존 테스트도 수정 없이 통과함.
  - terminalGate는 off일 때 c11 설정과 같은 객체임.
  - 브리지 소스를 읽거나 불러오는 테스트 34개 파일 중 게이트에 포함된 파일은 **445 tests / 0 fail**.
  - 게이트에 포함되지 않은 5개 파일(spawn을 쓰므로 안전 프리로드가 막음)은 기점 트리와 c19 트리에서 **똑같이 26 pass / 15 fail**임(`evidence/l5-c19/non-gate-*.txt`). 바뀐 것이 없음.
  - 전체 게이트는 0 fail.

## 2. 사람 관점 시나리오 (`helper/egdesk-own-tools-scenario.test.mjs`)
조건: 브리지의 실제 wiring + 모의 app-server + 가짜 spawn + 임시 폴더. 사람의 첫 요청은 "덧셈 버그 고치고 인사말 바꾼 다음 테스트 돌리고 강제로 올려줘"임.

**"응"**
- 턴 1:
  - 정확한 문자열 편집과 diff 편집 두 개가 묻지 않고 실행되고 diff로 보임.
  - `npm test`가 실행 폴더에서 실행됨(그룹, ssh agent 없음, API 키 없음). 결과는 "2 passing"임.
  - `git push --force origin main`은 `needs_person`(remote_irreversible)이고 실행되지 않음.
  - 모델이 대화에서 묻고 턴을 끝냄.
- 턴 2: 사람의 "응"을 yes/no로 **한 번** 읽고, 같은 push가 **한 번만** ssh agent와 함께 실행됨(approvedOnce).
- Codex 쪽:
  - app-server로 간 어떤 호출에도 실제 폴더(demo-app)가 없음.
  - thread/start는 빈 엔진 폴더, read-only, never, 셸 off임.
- 나중에:
  - 기록은 add.js, greet.js 두 개임.
  - 끝난 Run에서 도구를 부르면 거부됨. 그래서 같은 대화의 다음 턴("인사말 바꾼 것만 되돌려줘")에서 `egdesk_undo_edit`로 greet.js를 되돌림.
  - 화면 경로(`undo`)로 add.js를 되돌림. 두 파일 모두 처음 내용으로 돌아감.

**"아니"**
- 같은 흐름에서 push는 다시 `needs_person`이고 실행되지 않음. spawn에 닿은 것은 `npm test`뿐임.

## 3. 결정 필요
1. **화면의 undo 진입점**: provider에 `undoRecords`와 `undo`가 있지만, 사람이 누를 버튼이나 HTTP 경로는 없음. 만들면 사람에게 보이는 문구가 생기므로 승인이 필요함.
2. **모델의 undo 범위**: 지금은 같은 대화라면 이전 Run의 편집도 모델이 되돌릴 수 있음(파일이 그대로일 때만). 그 Run 안으로 좁힐지.
3. **실제 사용 전 확인**: 플래그를 켠 실제 사용은 실제 Codex와 실제 셸을 씀. 이번 사이클은 모두 가짜로 검증했음. 처음 켜는 시점과 방법(사람이 지켜보는 로컬 실행)은 소유자가 정해야 함. 남은 미확인은 c18과 같음(실제 Codex가 셸 off 설정을 받아들이는지, 빈 폴더에서 모델이 어떻게 행동하는지).
4. 기본 Codex 홈 이전(c17의 결정 2)은 여전히 소유자에게 묻는 중임. 공유 app-server는 플래그를 켜도 사람의 `~/.codex` 설정 레이어를 읽음.
