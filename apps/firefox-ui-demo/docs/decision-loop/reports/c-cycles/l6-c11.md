[측정, 등록 규칙 밖에서 본 것] 같은 사안 yes-O 에서 대상은 버텼지만 (.95) **"아니오" 형제 둘도 .95** 로 끌려갔다. 같은 사안의 O 요청 두 개는 세 답이 모두 같았다 (.95 ×3, .92 ×3). 등록 규칙은 대상만 보기 때문에 판정은 바뀌지 않는다.

**L1 c13 이 더하는 것.** 같은 패밀리에서 구성만 고친 것이다. 카드를 각 질문 **안에** 인용했더니 묶은 답이 .99/0/0, .04/.94/.02 였고, 카드 하나씩 따로 물은 요청 6개와 **숫자까지 같았다**. 그래서 같은 사안의 오염은 "묶음" 때문이 아니라 c12 구성 때문이다. c12 는 질문 문구가 모두 같고, 카드는 질문 밖의 입력 메시지에만 있었다.

**"형제가 다를 때만 분리" 규칙이 아직 필요한가: 아니다.** 근거:
1. 각 질문이 자기 항목을 담는 구성 세 가지에서 모두 묶음과 단독이 같았다: 질문 안 인용(c13, 채우기 줄), 입력에 있는 라벨 지목(발췌 `c1`).
2. 아래 묶음 검사를 증거표 전체에 적용하면, 검사를 통과하는 요청의 술어는 결정-정답 91.7% (inline) / 92.3% (reference) 로 형제 없는 술어 (87.6%) 보다 낮지 않다. 실패하는 요청은 50% 다 (아래 표).

제품에는 재질문 규칙 대신 **구성 검사를 둔다**. "답이 0.1 안에 모임" 신호는 정답 없이 볼 수 있어 계속 기록할 가치가 있지만, 이것으로 다시 묻게 할 근거는 지금 없다.

## 2. 작업 기억 게이트 (`5cf3277`)

- **안전장치 1, 다시 읽을 수 있는 줄만 뺀다.** `predicateAction` 은 "불필요"(≤ .2) 를 스필 저장소가 있을 때만 스필로 바꾼다. 저장소가 없으면 프로세스 출력도 원문 유지다. 접기(collapse)는 되돌릴 수 없고, 반복되는 진행 줄은 판정이 아니라 코드 규칙이 접는다. 테스트: 저장소 없음 → 원문 그대로, 저장소 있음 → 스필된 줄이 정확히 다시 읽힌다.
- **안전장치 2, 전부 "불필요"면 아무것도 적용하지 않는다.** 물은 블록이 모두 ≤ .2 이면 판정 실패로 보고 오늘의 동작으로 돌아간다 (코드 규칙 플래그가 켜져 있으면 규칙, 아니면 원문). 보정 기록에는 `fallback: 'all_not_needed'` 를 남긴다 (닫힌 어휘에 추가). 테스트: 기사 전부 0 → 원문, 규칙이 켜져 있으면 판정 없는 규칙 결과와 같은 바이트, 빌드 로그 전부 .01 → 원문.
- **스필된 블록 다시 읽기 카운터** (`createSpillRereadCounter`):
  - 코드 규칙이 실제로 스필하면 (플래그 `on`) 스필된 줄 범위를 기억한다.
  - 같은 범위에 대해 advisory 판정이 뭐라고 했는지 판정이 끝날 때 붙인다.
  - 모델이 그 스필을 `egdesk_read_source` 로 다시 읽으면 다음을 기록한다: 다시 읽힌 블록 수, 판정이 "불필요"라 했던 수 (`rereadJudgedNotNeeded`, 판정이 숨겼다면 틀렸을 블록), "필요"라 했던 수, 판정 없음, 범위 없는 읽기 여부.
  - 숫자만 남기고 id, 글, 도구 이름은 남기지 않는다. run 은 request id 로 찾는다.
  - context runtime 의 `onSpillRead` 훅은 게이트 플래그가 켜진 run 에서만 걸린다. 기본 제품에서는 훅 자체가 없다 (테스트가 확인한다).
  - [한계] 플래그 `advisory` 에서는 실제로 스필된 것이 없어서 다시 읽기가 생기지 않는다. 이 카운터가 판정의 "불필요" 정확도를 재는 곳은 플래그 `on` (규칙 스필) + advisory 판정 조합이다.
- **기본 설계 전환:** `buildGateRequest` / `gateToolOutput` 기본값과 배선의 `judgeDesign` 기본값을 `predicates` 로 바꿨다. `choice` 는 `judgeDesign: 'choice'` 일 때만 쓴다. 판정은 여전히 advisory 만이고 게이트는 플래그 없이는 꺼져 있다.
- 기존 choice 설계 테스트의 호출 21곳 (`gateToolOutput` 16, `buildGateRequest` 1, `gateToolResponse` 4) 에는 `design: 'choice'` 를 명시해서 같은 내용을 계속 검사한다. 단언은 약화하지 않았다. 이전 동작을 고정하던 두 단언(저장소 없이 접기, 전부 0 일 때 앵커 외 전부 스필)은 안전장치 동작을 고정하는 단언으로 바꿨다.
