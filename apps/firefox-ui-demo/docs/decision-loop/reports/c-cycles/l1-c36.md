# L1 c36: 남은 로그인 카드가 인증 코드를 주소창에 남기는 문제

브랜치 `lane/c36-stale-signin-cards` (base `int/c14` `21caac8`). 새 문구 없음. 테스트는 합성 DOM과 소스 수준이며 **실제 창에서 확인하지 못했다**.

## 일어난 일 (Main의 보고)
이전 로그인에서 남은 브라우저 카드(그 CLI는 창/브리지 재시작으로 사라짐)에서 소유자가 로그인을 끝냈다. 제공자가 CLI의 loopback 수신기 `http://localhost:50430/callback?code=…`로 리다이렉트했고, 듣는 이가 없어 Firefox가 "연결할 수 없음"을 보였으며 **인증 코드가 주소창에 그대로** 남았다. 코드는 자격 증명이다.

## 세 가지 수정

| # | 요청 | 구현 |
|---|---|---|
| 1 | 터미널 open-url 경로로 열린 카드를 그 터미널 세션에 묶고, 세션이 끝나면 닫는다 | `EGDeskSurfaceTerminal.mjs`: `openRequestedUrls`가 연 카드에 `_signinSessionId`(= 세션 id)와 `data-egd-signin-session`을 달고 연결 목록에 넣는다. 터미널 호스트가 `terminal-exit-confirmed`, `terminal-no-session`, `terminal-disconnected` (브리지 재시작은 연결 끊김으로 나타남)를 알리거나 **터미널 카드가 닫히면** (`cleanupCard`) 목록의 카드를 그 창의 `requestClose`로 닫는다. 사람이 직접 연 카드는 건드리지 않는다. 위조된 메시지(인증 안 된 프레임)는 기존 검사로 걸러진다 |
| 2 | 세션 복원은 이런 카드를 복원하지 않고, `code=`/`state=`가 붙은 loopback 콜백 주소는 복원하지 않는다 | (a) `serializeCardState`: 연결된 카드(`_signinSessionId`)는 **저장하지 않는다.** (b) 저장 기록은 `scrubBrowserRecord`를 거친다: 주소, 홈, 기록(history), 제목에 loopback 자격 증명 주소가 있으면 빈 페이지로 바꾸고 제목을 지운다. (c) 복원(`restoreCardFromState`와 Desk 복원)은 `restorableBrowserUri`를 거친다: loopback 자격 증명 주소(그리고 그 실패 오류 페이지 `about:neterror?u=…`)는 **항상** `about:blank`, 브리지가 `terminal-open-url` 능력을 알리면(플래그 켬) **옛 로그인 페이지**(claude.ai, claude.com, anthropic.com, OpenAI 인증 도메인의 `/oauth`, `/login`, `/authorize` 경로)도 `about:blank`로 복원 (이미 저장된 옛 세션을 위한 것) |
| 3 | loopback 콜백이 카드에서 실패하면 코드를 카드의 기록과 제목에 남기지 않는다 | 카드의 위치 리스너가 loopback 자격 증명 주소 또는 Firefox 오류 페이지(`about:neterror?u=<원래 주소>`, 이 `u`에 코드가 들어 있다)를 보면 `scrubCredentialPage`: 카드의 history 배열에서 그 주소를 `about:blank`로, Firefox 세션 기록을 비우고(`purgeHistory`), 카드를 `about:blank`로 바꾸고(기록 교체) 제목을 지운다. 브리지는 능력 `terminal-open-url`을 알려 오버레이가 이 가드를 켠다 (`/v1/state`의 `chatCapabilities`, `codex-bridge-server.mjs`) |

## 플래그에 대한 결정 (정직하게)
Main은 세 항목 모두 "같은 플래그 뒤"를 요청했다. 두 곳은 의도적으로 **플래그와 무관하게** 둔다: loopback 주소의 `code=`/`state=`/토큰을 저장하고 복원하지 않는 것(2-c의 첫 줄과 2-b), 그리고 3번의 카드 가드는 `_signinSessionId`가 있는 카드이거나 능력이 켜졌을 때만 돈다. 이유: 코드가 주소창과 저장된 세션에 남는 것은 플래그와 무관한 자격 증명 유출이다. 다만 일반 개발 서버(`localhost:3000/cb?code=…`)를 쓰는 사람의 카드가 **복원 때 빈 페이지가 된다**는 부작용이 있다 (저장된 주소가 콜백 자체일 때만; 일반 로컬 페이지는 그대로). 플래그 꺼짐에서는 3번의 카드 가드(실시간 비우기)는 돌지 않는다. 소유자가 이 선택을 바꾸고 싶으면 `restorableBrowserUri`/`scrubBrowserRecord`의 첫 줄을 `guard`에 묶으면 된다.

## 한계와 확인 안 됨
1. 실제 창에서 확인하지 못했다: (a) Firefox가 실패한 로드를 `about:neterror?u=` 형태로 보이는지 (주소 형태는 Firefox 표준 동작에 대한 지식이고 이 저장소에서 실행하지 않았다), (b) `purgeHistory`가 이 카드의 browser에서 동작하는지 (실패하면 try/catch로 넘어가고 카드는 blank로 바뀐다), (c) 카드가 닫힐 때 `requestClose` 경로.
2. 이미 열려 있는 오염된 카드 한 장은 코드가 그 카드의 주소창에 이미 있다. 이 변경은 다음 위치 변경(리스너)과 다음 저장/복원에서 지운다. 지금 떠 있는 카드를 즉시 정리하려면 소유자가 카드를 닫으면 된다.
3. `terminal-disconnected`는 일시적인 연결 끊김에도 온다. 그때도 연결된 로그인 카드를 닫는다 (CLI가 살아 있어도 카드를 다시 열려면 로그인을 다시 시작해야 한다: 보수적 선택).
4. 옛 세션에 저장된 로그인 페이지 카드의 복원 비움은 능력이 이미 알려진 뒤에만 켜진다 (복원이 `/v1/state`보다 먼저면 그 카드는 이전처럼 복원될 수 있다. 코드가 든 loopback 주소는 이 순서와 무관하게 비운다).

## 추가: 로그인 흐름의 빠른 진행과 실패 (Main 요청, 플래그 `EGDESK_TERMINAL_OPEN_URL`)
사람이 "4.5분 안에 로그인이 안 되면 그 자체가 문제"라고 했다. 이제 무음 구간은 길어야 5초 / 10초 / 3초 단위다. 능력(`terminal-open-url`)이 꺼져 있으면 모두 이전 동작 그대로다 (터미널 대기 15초, 확인은 다시 확인 버튼).

| 단계 | 값 | 넘으면 | 근거 / 위치 |
|---|---|---|---|
| 터미널 세션이 시작되어 입력 가능해질 때까지 | **5초** (전: 15초) | 기존 오류 `터미널 준비를 확인하지 못했습니다. 터미널에서 <명령> 을 직접 실행해 주세요.` | CLI와 셸 시작은 1~2초로 관찰됨(Main 실측). `CLAUDE_LOGIN_WATCH.terminalReadyMs` |
| 입력한 줄 뒤 로그인 카드가 열릴 때까지 | **10초** | 같은 기존 오류 | CLI가 `$BROWSER`로 열기까지 1~2초 관찰. 5배 여유. `signinCardMs`, 100ms마다 카드 수 확인 (`_linkedSigninCount`) |
| 기다리는 동안 엔진 확인 | **3초마다**, 최대 **5분** | 5분이 지나면 감시만 멈추고 화면은 "started" 안내 그대로, 다시 확인 버튼은 그대로 | `watchClaudeLogin`: `refreshClaudeEngine` (없으면 `refreshAuthStatus`). 확인이 실패하면 다음 3초에 다시 시도. 로그인 성공이 보이면 `claudeAction`을 비워 바로 로그인됨 상태가 표시됨 |
| 로그인 터미널이 성공 없이 끝남 | 즉시 (다음 3초 확인 때) | 오류 표시 + 연결 카드 닫기 (위 1번 수정) | 터미널 `terminal-exit-confirmed`, 또는 연결된 뒤의 `terminal-disconnected`, 또는 터미널 카드가 사라짐 (`_sessionEnded`). 처음부터 연결 안 된 경우는 "끝남"이 아니라 시작 실패로 5초 규칙이 다룸. 끝나는 순간 이미 로그인됐다면 성공이 우선 |

- 터미널이 준비된 뒤 셸이 조용해질 때까지 기다리는 시간(400ms 조용함, 최대 8초)은 c35 그대로이며 위 5초와 별개다. 이 대기를 포함하면 최악 경우 입력까지 5초 + 8초일 수 있다 (정상은 약 1초).
- 문구는 새로 만들지 않았다: 위 오류는 기존 문장, "끝남" 오류는 기존 형식 `Claude 상태를 바꾸지 못했습니다: 연결 프로그램 오류`. 이 문장은 정확하지 않으므로 **승인 필요 제안**: `로그인 터미널이 끝났습니다. 다시 로그인을 눌러 주세요.` (`CLAUDE_LOGIN_ENDED_TEXT` 한 곳만 바꾸면 됨). 또 "기다리는 중" 표시도 기존 `started` 안내문을 그대로 쓴다. 그 문장은 "마친 뒤 다시 확인을 눌러 주세요"라고 하므로 자동 확인과 어긋난다. 제안: `브라우저 카드에서 로그인을 마치면 이 화면이 자동으로 바뀝니다.` (승인 필요, 미적용).
- 한계: (1) CLI가 카드를 열기 전에 실패하면 10초 뒤에 오류가 뜬다 (그 전에 끝난 세션은 3초 확인 시점의 "끝남"으로 더 빨리 잡힌다). (2) 사람이 로그인을 천천히 하면 5분 감시가 끝난 뒤에는 자동 갱신이 멈춘다 (다시 확인 버튼 사용). (3) 시간 값은 합성 시계 테스트로만 확인했고 실제 창에서 재지 않았다.
- 테스트: 감시(3초 간격, 100회=5분, 성공/끝남/바뀜/시간초과, 실패한 확인 재시도), 카드 대기(10초 안에 열림/안 열림/옵션 꺼짐/카운트 없는 터미널), 터미널 카드의 카드 수와 끝남 판정(종료, 세션 없음, 연결 안 됐던 끊김), 표면 연결 정규식. 변이 12개 더 (C13~C24) 모두 잡힘.
