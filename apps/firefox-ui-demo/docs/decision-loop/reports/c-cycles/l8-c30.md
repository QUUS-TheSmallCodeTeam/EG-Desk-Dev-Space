## 1. 발견: 멤버십 작업이 진입해도 날짜가 답에 닿지 않았을 것
Main이 요구한 "끝까지 가고, 답에 날짜가 실린다"를 코드에서 따라가 보니, 끝난 작업의 노트(`subjectiveNote`)는 상태 줄(`found`)을 **식별자(주문번호, 사업자번호)가 있을 때만** 페이지 텍스트에서 찾아 담았습니다. "다음 결제일이 언제야?"처럼 답이 페이지의 사실인 요청에는 식별자가 없어서, 작업이 `done`으로 끝나도 노트에는 `{"status":"done", ... "next":"report_to_user"}`만 있었고 답변을 쓰는 모델은 날짜를 모릅니다. c31 병원 작업도 같은 이유로 `done` 노트에 날짜가 없었습니다(실측 노트 확인).

수정(`6000082`): 끝난 작업이고 페이지 텍스트를 받아도 되는 실행(`pageTextInNote`, 기존 `found`와 같은 게이트)이며 식별자로 찾은 상태 줄이 **없을 때**, 노트에 그 작업이 끝난 페이지의 첫 줄들을 `page`로 담습니다(최대 8줄, 총 480자, 줄당 120자, 빈 줄과 비텍스트 건너뜀). 어느 줄이 답인지는 코드가 추측하지 않고(R3: 의미 판단은 코드의 몫이 아님) 답변을 쓰는 모델이 읽습니다. `found`가 있으면 `page`는 붙지 않고, 끝나지 않은 작업의 노트에는 없고, 게이트가 꺼져 있으면 이전과 같습니다. 요청 바이트는 하나도 바뀌지 않습니다.
- 테스트(`egdesk-browser-answer-page.test.mjs` 4건): 멤버십 페이지에서 끝난 노트가 네 줄을 담음(날짜 포함), 게이트 꺼짐은 이전과 같음, 줄 수와 글자 수 상한과 빈 줄 처리, `found`가 있으면 `page` 없음과 미완료 노트에 없음.
- 한계: 노트가 페이지의 앞 8줄만 담으므로 날짜가 그보다 뒤에 있으면 닿지 않습니다(줄을 고르는 판단을 코드가 하지 않기 위한 선택).
