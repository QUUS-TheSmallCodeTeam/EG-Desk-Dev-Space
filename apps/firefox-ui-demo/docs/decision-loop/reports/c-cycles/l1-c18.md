## 2. 제거한 결합 (A1·A2, 플래그 없음: 분명히 잘못된 동작)
`EGDeskChatState.sys.mjs`:
- **`codexSlotAccountKey(profileId, context)`**: bridge가 나열한 **기본이 아닌** Codex profile 행이 로그인 상태일 때 `codex:slot:<profileId>:<email>`을 돌려준다. 모르는 profile이거나 로그아웃이면 null이다.
- **`codexRoomAccountKey(thread, authStatus, context)`**: 방의 Engine Profile이 창이 아는 기본 외 profile이면 그 profile의 키, 아니면 지금과 같은 기본 로그인 키다.
- `nativeBindingForRun(thread, run, context)`: 기본 외 profile에서 돈 run은 그 profile의 계정으로 바인딩한다. 그 계정을 모르면 `live-unverified`이고, 기본 계정을 빌리지 않는다.
- `canResumeNativeThread`와 `reconcileNativeThread(…, context)`: 방 키와 비교한다.
- `chatThreadReadiness`: 기본 외 profile 방은 그 profile의 로그인 상태로 판단한다(기존 문구 재사용).
- 창: `nativeBindingForRun(current, run, state.codex)`, `update()` 후 reconcile, 스냅샷 복원, 기록 복원에 `state.codex`(engine 행)를 넘긴다.
- 기본 로그인이 바뀌면 여전히 모든 Codex 방이 detach되지만, B 방은 이어지는 reconcile에서 자기 계정(변하지 않음)과 맞으므로 **곧바로 다시 붙는다**. 대화, 기록, `engineProfileId`가 유지된다.
- 창이 모르는 profile id(행 없음)는 지금 규칙을 그대로 쓴다. 기존 L6 고정 테스트(`slot-a` 등)도 그대로 통과한다.
- 이것은 소유권 부여가 아니다. helper가 resume마다 그 profile의 owner를 확인하는 것은 그대로다.

## 3. 테스트 (`scripts/egdesk-u11-independence.test.mjs`, 6개: 축을 하나씩 세션 중간에 바꿈)
1. **계정(기본 로그인) A→C**: 기본 방은 보류(`identity-mismatch`, 기존 규칙). B profile 방은 보류되지 않고 `verified`로 이어진다. resume 가능, ready, `engineProfileId` 유지.
2. **B profile의 계정 B→D**: B 방은 resume 불가, detach·reconcile 뒤 보류. 기본 방은 그대로다.
3. **기본 로그아웃**: B 방은 ready·resume 가능, 기본 방은 불가. 반대로 B 로그아웃이면 B 방만 "Codex 연결 후 전송할 수 있습니다"(기존 문구)이고 기본 방은 ready다.
4. **모르는 profile**은 지금 규칙을 따른다. 아는 profile이 로그아웃이면 바인딩은 `null/live-unverified`이고 기본 계정을 빌리지 않는다. 계정 이름이 남은 로그아웃 행은 키를 주지 않는다.
5. **folder와 screen**: 같은 B 방을 다른 폴더나 다른 창 상태에서 보아도 바인딩과 readiness가 같다.
6. 창 호출 지점 4곳이 engine 행을 넘기는지 소스로 고정한다.

## 4. 소유자 결정이 필요한 것 (추천 기본값)
1. **A4, Agent Profile의 계정 지정과 대화의 고정 계정이 다를 때**. 추천: 대화의 고정 계정이 이긴다. Agent의 계정은 새 대화의 기본값일 뿐이고, 충돌 오류 대신 그 계정으로 계속한다. 다른 계정으로 바꾸는 것은 사람의 명시적 전환만 허용하고, 그때 Atlas OBJ-056처럼 "같은 업무 유지 + 연결된 새 Run"으로 한다. HUM-ENGINE-001의 범위 질문과 함께 정해야 한다.
2. **A4 후속, 계정 전환 뒤 같은 방을 이어 갈 때 무엇이 따라가는지**(대화 기록 맥락, 초안, 요청자, 승인 대기 질문, 메모리). 추천: 사람과 대화의 것(요청자, 승인 대기, 초안, EG-Desk 메모리)은 따라간다. 엔진 쪽 기록(native thread)은 옛 계정에 남는다. 이것이 정해지면 A9(승인 broker 키를 로컬 대화로)를 구현한다.
3. **A5, 기본 계정 변경 시 작업 그래프 초기화**. 추천: 초기화하지 않는다. 각 작업을 다시 시작할 때 그 Run의 바인딩만 다시 확인한다.
4. **A8, Claude 대화의 폴더 고정**. 추천: Codex처럼 EG-Desk 도구와 중립 폴더 방식을 Claude에도 적용하는 것을 검토한다. 그 전까지는 지금처럼 "새 대화" 안내를 유지한다.
5. **A10, 다중 Desk 창**. 추천: 지원한다면 요청자를 bridge registry에서 읽는 경로를 둔다. 지금은 창 하나를 가정한다.
