## 1. 무엇을 연결했나 (플래그 기본 OFF, 답변은 보류·변경·지연 없음)
- 플래그: `decisionContext.draftCheck = { mode(): 'off'|'advisory', eligible?, internalVocabulary?, deadlineMs? }`. 없거나 `advisory`가 아니면 off. 브리지는 **개발자 환경변수 `EGDESK_DRAFT_CHECK=advisory`일 때만** 이 설정을 넘긴다(`codex-bridge-server.mjs` +2줄, 설정 화면·저장 설정 없음, 기본 off).
- 흐름(`codex-chat-runtime.mjs` +82): 턴 시작 시 `noteDraftCheckTurn`이 이번 턴에 모델이 받은 근거를 기록 → 최종 답변의 `message.completed`가 **이미 emit된 뒤** `startDraftCheckAdvisory`가 분리된 작업(`draftCheckRuns`, 아무도 await하지 않음)을 띄움 → `checkDraft(mode:'advisory')` → 내용 없는 보정 항목 1개 기록. 수정 턴 없음, UI 없음, 활동 행·이벤트 추가 없음.
- 게이트(모두 충족해야 실행): 플래그 advisory + Decision 모드 advisory/on + 저장된 키 + 직접·비무상태·비Board·비제한 DM 턴 + 보호(guarded) 근거 없음. 보호 근거(`mayRead`)나 개인 이력 묶음, 근거 목록을 알 수 없는 결과는 **요청 없이** `fallback: evidence_unavailable`만 기록.
- 근거(모델이 실제로 가진 자료): 컨텍스트 패킷이 **실제로 붙은 경우(Decision 모드 on)**의 항목(시점·출처 태그 + 카탈로그 텍스트=제목·요약. 로드된 본문은 보내지 않음, 이미 Decisions에 갔던 텍스트만). Decision 모드가 advisory면 패킷이 붙지 않았으므로 근거 없음. 턴에 함께 간 애플리케이션 블록(공유 메시지 등)과 **도구 출력은 내용 없는 참조**(`opaque`: id·종류·상태만)로만 전달. 참조만 있으면 "근거에 없음"을 결론내릴 수 없어 `unverified`를 만들지 않고, 참조뿐이고 용어 후보도 없으면 호출 자체를 하지 않는다.
- 밖으로 나가는 것(advisory 실행 시): 게시된 답변 문장, 위 카탈로그 텍스트, 내부 용어 후보. 사용자 질문 원문, 도구 출력, 본문, 키는 나가지 않는다(시험으로 본문·도구 출력 비전송 확인). 답변 문장이 Decisions로 가는 것은 **새로운 외부 전송**이므로 플래그를 켜는 것은 소유자 결정이다.
- 보정 기록(내용 없음, `egdesk-decision-calibration-log.mjs` +8): 기존 `draft_check` 항목에 닫힌 어휘 `check`/`ifUnrevised` ∈ {would_pass, would_revise, would_trim, would_ask}와 `evidence` 개수 {items, opaque, sentences, terms}, `timing` {totalMs, calls, withinBudget}만 추가. `check`는 발견 사항이 없으면 would_pass, 있으면 would_revise이고 `ifUnrevised`는 수정이 실패할 때의 대체(확실한 문장이 남으면 would_trim, 없으면 would_ask). 문장·용어·근거 본문 필드는 없다.

## 2. 증명 (`helper/egdesk-draft-check-advisory.test.mjs`, 4 tests + 모듈 12 tests 통과)
- **바이트 동일**: 플래그 없음 / off / advisory 세 실행의 게시 답변 시퀀스(`message.*` 텍스트·단계)와 **전체 이벤트 스트림**(UUID·시각만 정규화)이 같다. 해시: `event stream sha256[:16] none=56e2ac59d47c154d off=56e2ac59d47c154d advisory=56e2ac59d47c154d; posted answer none=6b57e8bf0f6449b1 advisory=6b57e8bf0f6449b1`. 네이티브 호출 목록과 `turn/start` 파라미터도 같다. none/off는 검사 요청 0, advisory는 정확히 1, advisory의 추가물은 보정 항목 1개뿐.
- **보정 항목 예**: `{"feature":"draft_check","mode":"advisory",…,"check":"would_revise","ifUnrevised":"would_ask","evidence":{"items":1,…},"timing":{…}}`; 답변·근거 문구가 항목에 없음을 시험.
- **멈추거나 실패하는 검사**: 신호를 무시하고 영원히 멈추는 판정(`deadlineMs: 60`)은 런을 늦추지 않고(2.5 s 안에 끝남) 게시·이벤트는 변하지 않으며 항목은 `fallback: timeout`; 던지는 판정은 `unreachable`; 두 경우 `draftCheckRuns`는 비워진다.
- 게이트 확인: 모드 off, 보호/미상 근거, 비직접·무상태·Board·제한 턴은 요청 0. Decision 모드 advisory면 근거 비어 있음. 도구 사용 시 참조 1개만 전달되고 판정 호출 0, `would_pass`, 도구 출력 문자열은 어디에도 없음.

## 3. `on` 모드 설계 (구현·활성화하지 않음)
위치: 기존 보류 지점 `startTopicAnswerGuard`(:5008) ~ `holdTopicAnswer`(:5068) ~ `settleTopicAnswer`(:5085). 가드는 `context.topicAnswerGuard === true`일 때만 만들어진다(:1554), 턴 종료 시 `finish` 경로에서 `settleTopicAnswer`가 호출된다(:5332, applyItem :5158). 보류 중 `messageDelta`는 가드가 있으면 반환(:5098)해 델타가 UI·저장소에 가지 않는다.
1. **보류 켜기**: 플래그 `draftCheck.mode() === 'on'`(별도 값)이고 위 advisory 게이트를 모두 통과한 턴은 `context.draftCheckHold = true`; :1554에서 `startTopicAnswerGuard(run)`을 호출하되 가드에 `kind: 'draft'`를 둔다. 상한은 `min(TOPIC_ANSWER_HOLD_MS=120 s, DRAFT_CHECK_LIMITS.holdMs=45 s)`.
2. **만료·넘침은 원문 게시(fail-open)**: topic 가드의 만료/넘침은 `rejectTopicAnswer`(안내 "EG-Desk가 답변을 표시하지 않았습니다")인데, draft 가드는 그 안내를 쓰면 안 된다. `kind==='draft'`면 만료·`overflow`·검사 실패 모두 보류 항목을 **그대로 `applyItem(..., approved=true)`로 게시**한다. 모순 검사(`topicAnswerContradiction`)는 draft 가드에 적용하지 않는다.
3. **검사 삽입**: `settleTopicAnswer`에서 상태 확인 뒤, `discardTopicAnswer('released')` 직전에 `const posted = await this.checkHeldDraft(run, items)`. 항목이 1개일 때만 검사(여러 개면 `unchecked`). `checkHeldDraft`는 advisory와 같은 근거(턴 기록 + 도구 참조)로 `checkDraft({ mode: 'on', revise, client, signal })`을 호출하며 시간은 가드 `until`과 `holdMs`로 제한. 결과가 `revised`/`certain_part`/`ask_user`면 그 텍스트로 `item.text`를 바꿔 `applyItem`; `passed`/`unchecked`면 원문.
4. **수정 1회(`revise`)**: 가장 위험한 부분이며 **실제 엔진 검증이 필요**. 턴이 이미 끝난 뒤이므로 (A) 같은 네이티브 스레드에 숨은 `turn/start`(수정 지시를 애플리케이션 블록으로): 네이티브 기록에 초안·수정 한 쌍이 남아 이후 기억·재개를 오염. (B, 권장) 스레드를 **임시 포크**(`thread/fork`, 상태 없는 임시 실행의 기존 패턴)해 수정 지시와 함께 한 턴만 돌리고 최종 텍스트만 가져온 뒤 폐기. 두 경우 도구는 끄고(읽기 전용 제한) 승인 요구를 거절하며, 결과 텍스트는 다시 보류(UI 비노출). 이번 검증 불가: mock 엔진 제약.
5. **그 사이 설정 변경**: c4 규칙대로 게시 직전에 Decision 모드·키·설정 세대를 다시 읽어, advisory/on 또는 키가 사라졌으면 **검사 결과로 바꾸지 않고 원문 게시**(소유자가 끈 뒤 결과를 따르지 않음).
6. **저장**: 바꾼 텍스트만 저장·표시되고 초안 원문은 어디에도 남지 않는다(보정 숫자 제외). 가드는 체크포인트하지 않으므로(`restoreTopicAnswerGuard`가 `restart`로 거절) draft 가드는 `restore` 때 `restart`가 아니라 일반 복원(네이티브 기록에서 원문)으로 돌려야 한다. `collectArtifacts`, 주제 기억 추가, `noteBoardPeerSpeech`는 게시되는 최종 텍스트를 쓴다.
7. **UI 영향**: 보류 구간(첫 검사 0.3-1.5 s + 수정 시 수 초 + 재검사 ≤1.2 s)에는 최종 답변 스트리밍이 없다. 작업 메모(commentary)는 흐른다. 소유자의 답이 없는 상태(스트리밍 상실 허용 여부).
8. **켜기 전 필수**: 가짜 app-server로 보류→검사→해제 경로 시험(델타 미노출, 수정, 만료 시 원문, 설정 변경 시 원문), 수정 턴 실엔진 검증, 문구 2종 승인(c7 `DRAFT_CHECK_COPY`), advisory 보정 기록으로 `unverified` 오탐률 확인.

## 4. 한계
- 근거 텍스트가 카탈로그 요약뿐이라 본문에만 있는 사실은 `not_mentioned`로 보일 수 있음(보정 기록으로 측정; 본문 사용은 별도 전송 허용 결정이 필요).
- 도구 출력은 내용 없는 참조라 도구로 확인한 사실은 `unverified`로 만들지 않음(대신 놓칠 수 있음).
- advisory의 외부 전송(답변 문장)은 새 범위: 플래그를 사용자에게 노출하기 전에 소유자 동의 문구가 필요.

## 6. 철학 점검
