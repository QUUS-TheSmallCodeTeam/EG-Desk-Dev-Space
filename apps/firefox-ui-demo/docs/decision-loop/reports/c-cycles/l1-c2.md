모든 관찰은 **synthetic harness**다. 설치된 앱 검증은 하지 않았다.

## 1. Sim 구성 (새 파일 `scripts/egdesk-chat-choice-settings-return.test.mjs`)
- 제품 코드 그대로 사용: `mountChatChoiceComposer`, `chatChoiceScope`, **`decisionRequest`**(설정 쓰기 구간: `choiceSettingsGeneration++/choiceSettingsWriting++` 후 `emit`), **실제 HUD 전송 버튼 슬라이스**(`sendButton`, `submitComposer`, `sendMessage`, `ensureNativeReadyForSend`), ChatState restore/reconcile, `/chat/send`, `/chat/resume`, `/chat/choice` HTTP handler + runtime + SQLite.
- Fixture(제품이 만드는 상태가 아니라 모사): 설정 HTTP 응답(키 저장 -> `mode:on`, boardRevision a->b, generation 증가), 설정 카드(active entity지만 file/browser/shape 아님, 열 때 `canvasSelectionRevision++`), `emit -> choice.sync()`(HUD는 매 render마다 sync 호출), `refreshConversation`이 `/chat/resume`을 호출.
- 한계: 런타임 프로세스 재시작 없음, 설정 카드의 실제 DOM 없음, 이 harness의 project default는 "none 확인" fixture.

## 3. 문제 (sim B에서 재현)
패널이 **edit 단계로 열려 있는 채** 설정에서 키를 저장하면(setup 버튼을 거치지 않고) `eg-desk-surface.uc.js` `sync()`가 `entry && !current(entry)`에서 `reset()`만 호출해 입력한 보기가 사라진다. 원래 실패 출력(`before-patch.tap`):
`B before={"panel_hidden":false,"options":["상단 알림","일정 공지"],...} after={"trigger_hidden":false,"panel_hidden":true,"options":[],...}`, 재오픈 `options=["",""]`. 이유: 설정 쓰기가 `scope.key`(settings generation 포함)를 바꾸고 write 중 scope가 null이 되지만, 저장 경로(`savedEdits`)는 [계정 설정 열기] 클릭에만 있다. 검토/확정 대기 단계(review, checking)도 같다.
- 정상으로 확인된 것: 키 저장 후 성공 경로 전체(sim A), 재복원의 pair 보존(sim C), composer가 바뀌면 불추종(sim A2).

## 4. Canon 대비 (무엇이 살아남아야 하나)
- Atlas:305: 검토는 외부 전송이 없고, 전송은 `[질문과 보기만 보내기]` 확정에서만, 추천/취소/권한 변경만으로 구독 호출 금지. 코드의 setup 문구도 "설정에서 변경한 뒤 돌아와 질문과 보기를 다시 검토해 주세요. 작성 중인 메시지는 그대로입니다."
  -> 살아남을 것: 사용자가 입력한 raw 문장(질문 composer, 보기). 사라질 것: 검토 결과, confirm 권한, 결과/추천, 요청 중 상태.
- 이미 코드에 있는 같은 원칙: `savedEdits`(setup 닫기, statusUnavailable)가 `editKey`(방/소유자/binding/draft revision/question)에 묶인 raw 옵션만 보관. 목록 이동용 `listEdits`는 settings 변경을 따라가지 않도록 테스트가 고정(composer test 'settings' boundary)하므로 건드리지 않았다.
- 외부: NN/g 오류 방지/사용자 입력 보존, GOV.UK "입력 유지" 원칙과 같은 방향이나, 이번 결정은 내부 일관성(`savedEdits`와 같은 규칙으로 확장)에 근거했다. 별도 외부 조사는 하지 않았다.

## 5. 패치 (`eg-desk-surface.uc.js` +5/-1)
`sync()`: entry가 더 이상 current가 아니고 단계가 `edit/checking/review/checkingConfirm`이면 `{key: editKey, question, options}`만 `savedEdits`에 남기고 reset. 재오픈 시 기존 검증(`savedEdits.key === scope.editKey && question 일치`)과 sync의 불일치 시 폐기가 그대로 적용된다. `pending`/`recommended`/`manual`/`setup` 등은 보관하지 않는다.

## 7. Task 2 결과 (stale `awaiting-identity` 재복원)
Desk 세션 저장은 thread를 retained pair와 함께 저장하고, 재시작마다 `detachNativeThread -> reconcileNativeThread`가 다시 돈다(`eg-desk-surface.uc.js:7118`). verified 직후 저장 / 보류 상태에서 저장 두 경우, 재시작 1~3회 모두 `retained={conversationId, clientThreadId:'qa-dm-restored', accountKey}`가 보존되고(`sameRetainedPair` 분기), 재인증 뒤 `bindingState=verified`, 원래 native client binding 복구, 추천 게이트 열림. stale `reason: 'awaiting-identity'`는 남지만 어떤 게이트도 `reason`을 읽지 않는다(표시는 `nativeBindingHeld`일 때만). 패치 불필요.

## 8. 철학 점검
"사용자가 입력한 것을 보존하되 승인 권한은 보존하지 않는다": 설정을 다녀와도 사용자가 친 보기는 남지만, 검토/확정 권한과 결과는 폐기되고 새 검토와 명시적 확정이 필요하다. 모델 제안과 승인된 실행의 분리는 그대로다.
