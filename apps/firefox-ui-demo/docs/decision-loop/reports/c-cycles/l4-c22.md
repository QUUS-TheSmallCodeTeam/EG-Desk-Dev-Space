## 1. 장면별 감사

### 장면 A: 답이 끝나고 브리핑이 `presented`가 되었을 때 (사람이 아무것도 누르지 않음)
1. 크롬이 답이 끝난 run을 관찰합니다. `observeBriefing`, S:4380. 플래그 `egdesk.briefingFlow`가 "on"일 때만 동작합니다.
2. 브리지는 새 파트마다 결과물을 발행합니다. `publishOutput` → `output.published` 이벤트이고, 본문 없이 메타데이터만 갑니다(`egdesk-context-runtime.mjs:999-1030`). 이어서 `proposeBriefing`이 같은 검증을 거친 `briefing.published` 이벤트를 냅니다(:875, :984).
3. 사람에게 보이는 것: 답 말풍선의 결과 칩 줄입니다.
   - 새 파트마다 결과 칩 하나(S:14460 `outputChips`).
   - **"브리핑 보기"** 칩(S:14477).
   - 캔버스에는 아무것도 생기지 않습니다. 카드 생성, 카드 이동, 카메라 이동이 모두 없습니다.
   - 접기 제안이 있으면 boardNotice 한 줄이 나옵니다(S:4377, 승인 대기 문구). 미리보기는 사람이 책상 빠른 정리를 열 때만 나옵니다.
4. **U7**(다른 사람의 화면에 넣지 않음, 내 카드를 옮기지 않음, 카메라를 건드리지 않음): 이 단계에서는 구조적으로 지켜집니다. 결과물은 칩일 뿐이고, 공유 Board 쓰기도 없습니다.
5. **차이 1** (`EGDeskBriefingHost`, `egdesk-context-runtime.mjs:984`): 브리지가 기록하는 `presentationStatus: 'proposed'`를 크롬 어디에서도 읽지 않습니다(overlay 전체 grep 0건). 그래서 호스트가 제안한 브리핑과 Agent가 직접 게시한 브리핑이 똑같은 "브리핑 보기"로 보입니다. → 문구와 소유자 결정 필요(2장).

### 장면 B: 사람이 "브리핑 보기"를 누름
1. 패널이 열리고, **모든 단계 대상이 '당시 입력 · 읽기 전용' 근거 카드로 열립니다**(S:3609-3628 준비 루프, `openInputEvidence(..., reveal:false)`).
   - 위치: `resolveCanvasCardPlacement('input-evidence')`(S:4318). 사람의 안전 뷰포트 안 빈자리이고, `.egd-board-region`은 피합니다(S:9375).
   - 처음 열 때는 카메라가 대상에 맞춰집니다(`fitBriefingTargets`, S:3059). 사람이 연 경우이므로 계약 :962의 허용 범위입니다.
   - 닫으면 이전 카메라로 돌아갑니다(S:3125 `previousView`). 열린 근거 카드는 남습니다.
2. 단계 설명은 패널에 `step.text`로 나옵니다. 대상을 열 수 없으면 `fallback`과 사유가 나옵니다(`EGDeskBriefingState` resolve).
3. **차이 2** (S:2918, `EGDeskBriefingState.sys.mjs:221-224`): 단계의 "보기"로 인정되는 것은 `.egd-input-evidence-card`뿐입니다. 결과 카드(`.egd-result-card`)는 인정되지 않습니다. 그 결과:
   - (a) **재사용된** 카드도 단계 대상이 되지 못합니다. 예: 캔버스에 이미 있는 A사 견적서 v1 카드. 같은 내용의 읽기 전용 근거 카드가 하나 더 열려 **중복**이 됩니다(재사용 우선 원칙과 어긋남).
   - (b) 새 파트(비교, 순서, 남은 일)는 카탈로그 렌더러가 만든 마크다운이 근거 카드의 **원문 스냅숏**(InputContext.inputSnapshotView)으로 보입니다. 렌더된 결과 카드가 아닙니다.
   - 원인: "browser viewId is only a Live-link hint, never a substitute for evidence"(CNV-07 근거 인증 규칙). → 소유자 결정 필요(2장).

### 장면 C: 사람이 결과 칩을 누름
1. `openPublishedOutput`(S:17611) → `spawnResultCard`(S:4405)가 결과 카드를 엽니다.
2. 위치: `resolveCanvasCardPlacement('result', { workSurface })` → L1의 배치 훅입니다(S:9381). `EGDESK_WORK_PLACEMENT`/pref "on"이면 quiet 배치(카메라 이동 없음, 활성화 없음)이고, 아니면 사람의 클릭으로 열려 그쪽으로 이동합니다.
3. 렌더링은 결과 카드의 기존 마크다운 렌더러입니다. 표, 목록, 체크박스는 지원하지 않습니다(C13부터 알려진 항목). 비교 카드는 `**라벨** v1 → v2` 줄로 보입니다.
4. 이 카드는 출처(provenance, outputId/outputKey/version)를 가지므로(`EGDeskChatState.sys.mjs:3822`) 다음 브리핑이 재사용할 수 있습니다. 다만 차이 2 때문에 이 브리핑의 단계 대상으로는 인정되지 않습니다.

### 장면 D: 같은 일의 두 번째 브리핑 ("내가 만든 오래된 결과물을 회수한다")
1. 같은 자료라면 첫 브리핑이 만든 카드를 출처로 알아보고 재사용합니다(c16, 테스트 "mounted, the next answer"). 새로 발행하는 것은 없습니다.
2. **차이 3 (닫음)**: 자료가 바뀌어 파트를 다시 만들 때의 문제였습니다.
   - 이전에는 결과물 키가 매번 무작위(`briefing-<random>`)였습니다. 그래서 첫 카드가 버전 체인에 들어가지 않았고, `supersededBy`가 붙지 않았으며, 회수 대상(`retrievable` = agent-earlier && (superseded || stale))도 되지 않았습니다. 또 `canvasBriefingCandidates`는 `stale: false`로 고정되어 있습니다(`EGDeskBriefingHost.sys.mjs:29`). 결국 낡은 첫 카드가 접기 제안 없이 그대로 남았습니다.
   - 수정: 2장 앞의 "닫은 차이" 참고.
3. 실측(모의, 마운트): v2 페이지가 11/11 날짜와 새 수치로 바뀐 경우입니다.
   - 세 파트가 모두 다시 만들어졌고, 각자 **자기 이전 결과물의 다음 버전**이 되었습니다(version 2, previousId 일치).
   - 접기 제안 `retrievals`는 `res-new-1..3`입니다(`second-briefing.txt`).
   - 화면에서는 기존 `supersedeResultRecord`가 첫 카드에 `supersededBy`를 기록합니다.

### 장면 E: 사람이 할 수 있는 것 (유지, 무시)
- **접기**: 미리보기 → 적용, 또는 그대로 두기. 되돌리기와 Cmd+Z가 됩니다(기존 테스트). 공유 Board에는 쓰지 않습니다.
- **결과 칩**: 눌러서 카드로 남길 수 있습니다(유지). 칩을 치우는 동작은 없습니다.
- **제안된 브리핑**: 열기와 종료만 있습니다. 유지하거나 무시하는 동작이 없고, 칩은 계속 남습니다(차이 1과 같은 결정).
- **차이 4 (닫음)**: 접기 제안 답장은 최대 150초 늦게 옵니다(S:4399 timeout). 그 사이 사람이 플래그를 끄거나, 카드를 공유 Board로 옮기거나, 이미 접었거나, 카드가 사라졌을 수 있는데 이를 다시 확인하지 않았습니다.

## 2. 닫은 차이 (새 문구 없음, 소유자 결정 불필요, 기존 플래그 뒤)
1. **이전 결과물 버전 이어가기와 같은 답장 안에서의 회수**:
   - `helper/egdesk-briefing-flow.mjs`에 `continuedBriefingOutput`를 추가했습니다. 같은 대화, 같은 trait와 component, 자료 키가 하나 이상 겹치면 가장 최근에 일치한 결과물의 outputKey를 씁니다. 한 브리핑 안의 두 파트가 같은 키를 쓰는 일은 없습니다. design-first 컴포넌트(자료 키 없음)는 늘 새 결과물입니다.
   - 브리지(`egdesk-board-presentation-http.mjs`): 바인딩에 outputKey와 conversationId를 기억합니다. 교체된 이전 버전을 아직 보여주는 보드 위 카드는 이번 답장의 `retrievals`에 더합니다. 조건은 Agent 자신의 카드일 것, 접혀 있지 않을 것, 이번 브리핑이 가리키지 않을 것입니다. 접기는 여전히 사람이 적용하는 제안일 뿐입니다.
2. **늦은 접기 제안을 지금 화면 기준으로 다시 확인**: `offerBriefingRetrieval`(S:4367)은 플래그가 아직 "on"일 때만 제안합니다. 대상은 연결되어 있고, `egd-result-card`이며, 공유 Board 카드(`jointManaged`)가 아니고, 아직 접히지 않았고, 출처의 creator가 'agent'인 카드뿐입니다.
3. 테스트 3개를 추가했습니다:
   - 단위 테스트: 이어가기 규칙과 반례(다른 방, 다른 종류, 겹침 없음, 한 브리핑 내 중복, design-first).
   - 마운트 테스트: 두 번째 브리핑.
   - 합성 DOM 테스트: `offerBriefingRetrieval`의 실제 소스를 컴파일해 씁니다. 플래그가 바뀐 경우, 공유 Board 카드, 출처 없는 카드, 없는 카드, 이미 접힌 카드를 확인합니다.
   - 기존 테스트 2곳(publish, engine)은 컴파일 시 새로 쓰는 전역(`BriefingHost`, `readSurfacePref`)을 주입하도록만 바꿨습니다. 단언은 바꾸지 않았습니다.

## 3. 소유자 결정 또는 문구가 필요한 차이
1. **결과 카드를 단계의 "보기"로 인정할지** (차이 2, CNV-07 근거 규칙): outputId와 내용 해시가 단계의 board 캡처와 같은 결과 카드를 근거 보기로 쓸지 정해야 합니다. 쓰면 재사용 카드의 중복 근거 카드가 사라지고, 새 파트가 렌더된 카드로 보입니다. 지금은 "viewId는 힌트일 뿐"이라는 규칙 때문에 막혀 있습니다. 근거 인증의 소유자가 결정할 일입니다.
2. **제안 상태 표시** (차이 1): 호스트가 제안한 브리핑임을 보여줄지, 그리고 "유지 / 치우기" 동작을 둘지. 둘 다 새 문구가 필요합니다.
3. **표·체크리스트 렌더러 없음**: 결과 카드 마크다운 렌더러에 표, 목록, 체크박스가 없습니다. 비교와 남은 일은 줄 형식입니다. `→` 화살표와 굵은 라벨 줄 형식은 C13/C14부터 승인 대기입니다.
4. **근거 카드의 마크다운**: 근거 카드는 원문 스냅숏을 보여줍니다. 새 파트를 렌더해서 보여줄지는 1번과 묶어서 결정할 일입니다.
5. **결과 칩 치우기**: 쓰지 않을 새 파트의 칩을 치우는 동작이 없습니다(새 문구 필요).
6. **이어가기 기준 "같은 일"** = 같은 trait·component + 자료 키 1개 이상 겹침(코드 규칙). 겹침이 우연인 경우, 예를 들어 같은 결정 메모를 공유하는 다른 일이면 엉뚱한 카드에 접기가 제안될 수 있습니다. 제안일 뿐이지만 기준을 소유자가 확인해야 합니다.
7. **바인딩은 브리지 메모리에만 있음**(500개 상한): 브리지를 다시 시작하면 이어가기가 끊기고 새 결과물이 됩니다. 영속화할지는 별도 결정입니다.
8. 승인 대기 문구(이번에 바꾸지 않음): 접기 알림 "오래된 결과 카드를 접는 정리 제안이 있습니다. 책상 빠른 정리를 열면 미리 볼 수 있습니다.", 미리보기 "오래된 결과 접기", 적용 "내 화면에 적용".

## 4. 확인하지 않은 것
- 실제 크롬에서 끝난 run의 이벤트 스트림이 나중에 오는 `output.published` / `briefing.published`를 받는지는 확인하지 않았습니다. 마운트 하네스와 all-on 여정에서만 확인했습니다. 설치된 앱은 검증하지 않았습니다.
- L1의 다중 사용자 presence(`state.presence`)와 결과 카드 배치 훅이 다른 사람의 화면을 피하는 동작은 L1 소관입니다. 이번에 바꾸지 않았습니다.
