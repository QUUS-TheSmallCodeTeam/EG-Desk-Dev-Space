## 2. fill 출력 축소 (실제 check-9 응답으로 측정)
- 요청이 최소만 요구: (a) 단계의 `fallback` 문장을 요청하지 않음(검증기는 응답에 없으면 단계 `text`를 씀; 명시적 빈 값은 여전히 빈 슬롯, 모델이 쓴 값은 유지), (b) sequence 카드 줄의 `label`과 `text`는 null 가능: null이면 코드가 인용한 자료의 날짜와 줄에 들어가는 문장들(통째 문장만, 길면 비움)을 그대로 복사, (c) 단계 `text`는 80자 이내 짧은 구, 그 외 슬롯은 그대로. 스키마(strict)도 같은 요청에서 만들어져 fallback이 빠지고 copy 필드는 `anyOf null`. 검증기가 스키마가 허용한 것을 거부하지 않도록 시드 고정 차분 테스트(압축 스키마, null 포함).
- 측정(`$L/evidence/l4-c35/size-measurement.txt`): 실제 P1 응답 644자 -> 291자(-55%, 같은 보드 줄: 복사로 실제 모델이 입력한 줄과 정확히 같음), P2 342 -> 288자(-16%; open_items 줄은 모델이 써야 함이라 줄지 않음). 프롬프트는 3,256 -> 3,486자(+230자: 복사 규칙), 스키마 1,586 -> 1,562자. 프롬프트는 시간 원인이 아님(입력 대부분 캐시).

- 결과적으로 예상 시간: 줄 복사와 fallback 제거로 P1 출력 토큰 약 절반, 추론도 결정할 것이 줄어 감소 예상. 실제 시간은 재실행에서 확인해야 함(예측일 뿐).
