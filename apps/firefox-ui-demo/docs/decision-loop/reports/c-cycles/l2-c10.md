## 1. 통합 여정을 int/c14에 맞춤

실패 원인은 Main의 진단대로였습니다. 포인터 단계(c4)가 `EGDESK_WORK_PLACEMENT=advisory`로 돌고 있었고, int/c14에서는 `on`일 때만 포인터 사실이 생깁니다. 원래 실패 출력은 `journey-before.tap`에 있습니다.

한 일:
- 하네스의 "전부 켬" 값을 `EGDESK_WORK_PLACEMENT=on`으로 바꾸고, 브리지와 같이 `enabled`는 advisory|on, `live`는 on만으로 배선했습니다. 프레즌스가 켜져 있을 때의 요청자 청중 규칙(`runRequesters.audience`)도 브리지대로 연결했습니다.
- 숫자는 손으로 고치지 않았습니다. 새로 돌린 원장을 c9 원장과 단계별로 비교했고, **11개 단계 모두 Decision 요청(기능별), 주관 모델 턴, 활동 행, 이벤트가 c9와 같았습니다.** 합계도 같습니다: Decision 요청 38건, 본 턴 6회, 포크 턴 5회. 그래서 여정 테스트의 단정은 그대로 두었습니다.
- 새 테스트: advisory에서는 같은 포인터 판단이 기록만 되고(`would: point`), 포인터 사실이 생기지 않으며, 하트비트 질문 0건, 포크 턴 0회, 이벤트 0건, 채팅 기록 변화 없음.

여정 파일은 이제 테스트 5개이고 모두 통과합니다 (`journey-after.tap`).

## 3. onePacket (A3)

- `createTurnMemoryConfig`는 이제 `onePacket`을 런타임에 넘깁니다. 그러나 **브리지(`codex-bridge-server.mjs` 437행)는 이 옵션을 넘기지 않습니다.** 환경변수도 설정도 없어 제품에서는 여전히 켤 수 없습니다. L7 c15의 `writeTarget: 'about'`, `confirmInConversation`도 같은 상태입니다.
- 스위치 이름을 새로 짓는 일은 승인이 필요하다고 보아 브리지에는 손대지 않았습니다. 하네스에 `allOnWorld(t, { onePacket: true })` 옵션으로만 열었습니다(기본은 브리지처럼 꺼짐).
- 옵션을 켠 결과: 묶음이 하나(`egdesk_decision_context`)로 합쳐지고 같은 페이지 본문이 1번만 들어갑니다. Decision 요청과 활동 행은 끈 경우와 같습니다. 끈 경우(브리지 현재 동작)는 묶음 둘, 본문 2번입니다. 증거: `journey-ledger-one-packet.json`.

## 4. 표면: 대화 닫힘 신호 (제품 변경)

**규칙** (`ChatState.openConversationChange`, 순수 함수):
- 채팅이 보이고 대화 화면이면 그 방이 "열린 대화"입니다. 채팅이 보이고 방 목록이면 열린 대화가 없습니다.
- 채팅이 보이지 않으면(숨김) 값을 바꾸지 않습니다. 숨기는 것은 나가는 것이 아닙니다.
- 열린 대화가 다른 값으로 바뀌면, 이전 대화에 대해 `POST /chat/session/close { clientThreadId }`를 한 번 보냅니다.

**거는 곳**: `emit()`이 `normalizeThreads()` 직후 이 규칙을 적용합니다. 방을 바꾸는 실제 지점들(`selectThread`, `setHudView('list')`, `openHudHome`, `deleteThread`, `createThread`)이 모두 `emit()`을 거치므로 한 곳에서 잡았습니다.

| 사용자 동작 | 신호 |
|-|-|
| 다른 방을 엶 | 이전 방 1회 |
| 방 목록으로 돌아감 | 그 방 1회 |
| 열려 있는 방을 삭제 | 그 방 1회 |
| 새 방을 만들어 그 자리에 엶 | 이전 방 1회 |
| 방의 클라이언트 바인딩이 교체됨(계정 변경 등) | 옛 바인딩 1회 |
| 방을 처음 엶, 같은 방을 다시 엶, 다시 그리기(새 메시지·스크롤·메뉴) | 없음 |
| 채팅 패널을 숨김 / 같은 대화로 다시 보임 | 없음 |
| 채팅을 캔버스 카드로 옮김 | 없음 |
| 숨겼던 채팅을 다시 열어 방 목록이 뜸 (제품의 기본 동작) | 그때 1회 |
| 시작 직후 한 번도 화면에 뜬 적 없는 방 | 없음 |

요청이 실패해도 화면은 바뀌지 않고 다시 시도하지 않습니다. 브리지는 창이 사라지면 idle 세션을 따로 정리합니다.

**실제 라우트까지 이어서 확인한 것** (통합 하네스, `session-close.tap` 8개 통과):
- 실행이 끝난 대화에서 목록으로 나가면 응답 `{ accepted: true, closed: true }`, 세션 하트비트가 끝납니다. 그 뒤 포인터 판단이 나와도 하트비트 질문 0건, 그 대화에 게시되는 메시지 없음. 다시 열어 새 메시지를 보내면 세션이 다시 살아납니다.
- 실행 중에 다른 방으로 가면 응답 `{ accepted: true, closed: false, afterRun: true }`. 실행은 계속되고 답은 저장되며, 실행이 끝날 때 세션도 끝납니다.
- 채팅을 숨기기만 하면 신호가 없고, 포인터 메시지는 그 대화에 1개 도착합니다.

**게이트가 한 번 빨갛게 됐던 일**: 첫 구현은 `emit()` 안에서 `syncOpenConversation?.()`로 불렀습니다. `scripts/egdesk-surface-state.test.mjs`는 `emit()` 본문만 잘라 실행하므로 선언이 범위 밖이라 113개 테스트가 `ReferenceError`로 실패했습니다(`gate-l2c10-first-run-red.tap`). 그 테스트 파일은 건드리지 않고, `emit()`이 이미 `refreshFileCardAgentBadges`에 쓰는 `typeof` 가드로 바꿔 해결했습니다 (`2a2bb6c`).

**한계와 판단이 필요한 점**
- `toggleHUD`는 Desk DOM 전체가 필요해 테스트에서 직접 실행하지 못했습니다. 그 함수가 쓰는 상태 값을 테스트가 그대로 쓰고, 소스 정규식으로 그 대입문이 있는지만 확인했습니다. 실제 패널 열기/닫기에서의 동작은 설치된 앱에서 확인이 필요합니다.
- **캔버스의 채팅 카드를 닫는 것**은 지금 "숨김"과 같게 처리합니다(신호 없음, 다음에 목록이 뜰 때 신호). 카드 닫기를 "대화를 닫음"으로 볼지는 정해 주셔야 합니다. 정본(Interaction Trace Atlas)에서 이 구분을 찾지 못했습니다.
- Board 스레드의 구성원별 대화는 브리지에서 다른 ID를 씁니다. 이번 신호는 화면에 열린 방의 ID만 보냅니다. 구성원 대화의 세션은 닫지 않습니다.

## 5. 스위치 목록에서 바뀐 것 (c9 표 대비)

- `EGDESK_WORK_PLACEMENT`: 값이 advisory | on으로 늘었습니다. advisory는 기록만, on은 포인터 사실까지.
- 새 불일치: 창 pref `egdesk.workPlacement`는 여전히 `advisory`만 인정합니다. 환경변수를 `on`으로 해도 pref는 `advisory`여야 하고, pref를 `on`으로 쓰면 꺼진 것으로 읽힙니다 (L4).
- 켤 방법이 없는 턴 기억 옵션이 셋이 됐습니다: `onePacket`, `writeTarget: 'about'`, `confirmInConversation` (L7).
- 새 라우트 `POST /chat/session/close`는 스위치가 없고 항상 받습니다. 하트비트가 꺼져 있으면 `closed: false`로 답하고 아무 일도 하지 않습니다.
