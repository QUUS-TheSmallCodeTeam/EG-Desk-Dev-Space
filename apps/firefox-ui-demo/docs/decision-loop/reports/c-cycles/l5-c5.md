브랜치 `lane/c5-terminal-states` (기준 `int/c4`), 커밋 `537b26d`(기능), `6c4ab2c`(int/c4 회귀 수정). 증거 `evidence/l5-c5/` (`matrix.json`, `gate.out`). 합성 transcript와 가짜 프로세스만 사용. 실제 셸·PTY·codex 바이너리·네트워크 없음. 패러다임: Decision 모델은 사용자에게 추천을 보여 주는 도구가 아니라 **시스템 판정자**이며, 선택지는 **런타임이 먼저 만든다**(JEV_INTEGRATION_SUGGESTIONS §2 Pillar 2·3, §4, §9.4 JEV-RUN-01).

## 2. 구현 (신규 모듈 2개 + 어휘 2줄)
- `helper/egdesk-terminal-judge.mjs`
  - **상태 선택지(런타임 열거):** 프로세스 사실로만 결정. 살아 있음 → running_output / waiting_yn_input / waiting_password / stuck_in_pager / need_user_context / cannot_proceed. 종료 코드 ≠ 0 → completed_error / need_user_context / cannot_proceed(**"성공"은 후보에서 제거**). 종료 코드 0 → completed_ok / completed_error(숨은 테스트 실패) / … 
  - **규칙 우선:** 비밀번호/패스프레이즈 프롬프트는 규칙으로 인식하고 그 tail은 모델로 보내지 않는다. 조용한 시간이 충분하지 않거나 tail이 없으면 판정하지 않는다(`running_output`, 요청 0). 같은 tail은 캐시로 재요청 없음.
  - **전송 내용 최소화:** ANSI 제거·최근 30줄/2400자·줄당 200자·비밀 패턴 마스킹(`redactTail`). 터미널 텍스트는 `consent()`가 true일 때만 나간다(기본 false).
  - **상태별 시스템 응답(`stateResponse`):** wait / 사람에게 yes-no 전달 / 사람에게 비밀 입력 전달(값은 추적에 남지 않음) / 에이전트 소유 세션이면 `q` 전송(사람 소유면 사람에게) / 보고 / 수리 / 주관 모델에 제어 이관(need_user_context, cannot_proceed).
  - **오류 → 맥락 재구성:** 런타임이 로그를 블록으로 열거(`enumerateLogBlocks`) → 블록당 predicate 1문항을 **요청 1건**으로 묶어 Decision이 관련 블록 선택(최대 4개/4000자) → 주관 모델에 전달 → 수정 적용 → **같은 명령을 다시 실행**(객관 루프로 복귀). 수리 상한(기본 2) 후엔 cannot_proceed로 챗에 이관.
  - **모드/예산/기한/보정:** off = 요청 0·오늘의 동작. advisory = 묻고 보정 기록만 하고 시스템은 결정론적 폴백으로 행동. on = 수락된 선택으로 행동. 실패(기한 1.5 s, 예산 소진, 낮은 확신, 동의 없음)는 폴백: 종료 코드로 판단, 살아 있으면 대기, 30 s 이상 침묵이면 주관 모델에 이관.
- `helper/egdesk-terminal-command-gate.mjs`
  - **규칙(바닥)이 항상 이긴다:** 해석 불가 대상(`$VAR`, 백틱), 보호 대상(`/`, `~`, `.`/`..`, 루트 근처, 맨 `*`), cwd 밖, git 추적 파일이 있는 대상, dirty 워크트리의 `git reset --hard/clean/checkout --/restore`, 원격 비가역(`git push --force`), `sudo`, `curl|sh` → 점수와 무관하게 승인 필요.
  - **모델은 파괴적 동사가 있고 규칙이 승인을 요구하지 않은 명령만** 점수화(0~4 단계 `Destructive/Irreversible Risk`, 막대 2.5, 낮은 확신이면 승인). 입력은 런타임이 만든 맥락(cwd 이름, 대상별 추적 파일 수·ignored·cwd 내부 여부, 말한 의도, git dirty). 평범한 명령(`npm test`)은 **요청 0**.
  - **점수는 승인을 더할 뿐 빼지 못한다.** off/advisory/동의 없음/예산 소진/기한 초과/오류 → 규칙만으로 판단(오늘의 동작). 엔진의 기존 승인 정책은 이 게이트가 통과시킨 명령에도 그대로 적용.
- `egdesk-decision-calibration-log.mjs`: 어휘에 feature `terminal_state`·`terminal_gate`, question `terminal_state`·`terminal_risk`·`log_block` 추가(내용 없는 숫자/닫힌 단어 기록 규칙 그대로; 테스트로 터미널 텍스트가 기록에 없음을 확인).
- 별도 수정: `eg-desk-surface.uc.js` 한 줄 — int/c4(`ef82022`)에서 설정 포커스 복구가 하네스에서 정의되지 않은 `card`를 읽어 `scripts/egdesk-first-run-journey.test.mjs` 4건이 **int/c4 자체에서 실패**하고 있었다(내 변경과 무관, 직접 확인). `typeof card` 가드로 해결(Main 확인 필요).

## 5. 사용자 노출 문구 (승인 대기, 이번 패치에는 UI 문구 없음)
새 기능 이름과 화면 문구는 추가하지 않았다. 연결 단계에서 필요해질 후보(미구현, 승인 필요): ① 승인 카드의 위험 이유 한 줄(예: "추적 중인 파일이 있는 폴더를 지웁니다", "위험 점수가 높아 확인이 필요합니다"), ② 사람 핸드오프 문구("프로그램이 예/아니오 입력을 기다립니다", "비밀번호 입력이 필요합니다. 입력한 값은 기록·전송되지 않습니다"), ③ 터미널 출력이 결정 모델로 전송될 수 있다는 동의 안내(`consent()`에 연결되는 설정). ③은 새 데이터 이그레스(터미널 출력 tail과 로그 블록, 비밀 마스킹 후)라 **사용자 결정이 필요**하다.

## 6. 철학 점검
P2(실패하면 지금 방식으로): 모든 실패는 오늘의 동작(종료 코드, 대기, 엔진 승인)으로 돌아간다. 시스템 판정 원칙: 선택지는 런타임이 열거하고 모델은 고르기만 하며, 응답은 시스템이 정해진 표대로 수행한다. 규칙은 그대로 남고 점수는 승인을 더할 뿐이다. 비밀번호는 모델에도 로그에도 가지 않는다.
