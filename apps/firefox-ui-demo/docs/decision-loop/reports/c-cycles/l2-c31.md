## What was built
- `helper/egdesk-real-engine-timing.mjs` (pure) + `scripts/egdesk-real-engine-timing.mjs` (CLI, in-process `main()`), tests `helper/egdesk-real-engine-timing.test.mjs` (10).
- Per scripted turn: `turnMs`, `firstVisibleMs` (first posted message, approval question or visible activity row; the runtime's own bookkeeping rows are not counted), `finalAnswerMs` (last posted message, so it includes the draft check's hold), Decision calls (count, ms added, wall ms with overlaps counted once, each call's start), engine rounds (count, ms per round: a round ends with a tool call or the final text and runs from the previous round's end), tool ms (EG-Desk's own tool calls, request to result; native tool items only when they are not the same call), posting outcome (c23 word, else posted / none).
- The check (small, additive, tested) now records, per sub-turn, `timing`: offsets in ms from the turn start of the visible runtime events (with the activity kind), every engine item's start and end, each own tool call's request and result, plus `sendMs` and `doneMs`; and each Decision call row gets `atMs` (its start). Nothing else of the record changes (one existing test pinned the exact Decision-row keys: `atMs` added to it).
- Compare: the SAME script run twice. Turns are matched by set, conversation id and turn index; `--normalize '-off|-on'` drops a suffix so an `-off` and an `-on` copy of a script (flags are set per conversation in a script) match. Per turn: seconds saved (off minus on: turn, first visible, final answer, Decision wall, engine, tools), Decision calls and rounds off/on, outcome off/on, and CHANGED answer facts: numbers with units only on one side, a different posting outcome, a different number of messages, every expectation whose verdict flipped. Summary: seconds saved over the turns answered on both sides, median per turn, faster/slower counts, totals of Decision calls and engine rounds, turns with changed facts.
- An older record (all of today's) has no timing: the measure derives only what it can (turn and answer time from the sub-turn latency, rounds from the tool-call count, marked `*`) and leaves first visible, Decision wall, engine ms and tool ms empty (never guessed). Records from the next real run on carry all of it.

## Commands for lanes
```

node scripts/egdesk-real-engine-check.mjs --codex-bin $BIN --person-home --decisions … --script …-on-v1.json  --out $L/…/<name>-on  --run
node scripts/egdesk-real-engine-timing.mjs compare $L/…/<name>-off/records $L/…/<name>-on/records --normalize '-off|-on'      # add --json for the data
node scripts/egdesk-real-engine-timing.mjs table <records dir…> [--set <script prefix>]                                        # the per-turn table and the top-line numbers
```
Run each side at least twice when a difference matters (one turn is one draw: the same request bytes give the same Decision answers, the engine is not deterministic).
