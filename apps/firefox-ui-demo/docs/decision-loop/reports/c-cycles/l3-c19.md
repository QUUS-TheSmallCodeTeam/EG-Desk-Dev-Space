## A. s6 sup .37의 원인과 수정

### A.1 본문을 읽은 결과

heartbeat-c18의 s6 본문 E1:

```
In this turn the assistant ran `npm test -- --suite=payroll-secret`; it finished with exit code 0. The command check read its output as:
The command finished and its output shows success. Last lines of its output: running 40 tests
```

"테스트가 모두 통과했습니다"를 뒷받침하지 못한 이유는 셋이다.

1. **마지막 줄에 통과 요약이 없다.** "running 40 tests"는 시작 줄이다. 원인은 L2 여정 fixture다.
   - fixture는 스트림으로 `running 40 tests\n`(17 B)을 보낸 뒤, 완료 때 `aggregatedOutput: 'all passed\n'`(11 B)를 준다.
   - 제품(`completeCommand`)은 더 긴 쪽을 보존하므로 "all passed"가 버려졌다.
   - 실제 Codex의 aggregatedOutput은 전체 출력이라 이 일은 생기지 않는다. 제품 버그가 아니라 fixture 불일치다. L2에 알릴 사항이다.
2. **종료 코드 0이 숫자로만 있고 뜻이 말로 없었다.**
3. L5 판정 문구("output shows success")는 보이는 마지막 줄과 맞지 않아 근거로 약했다.

참고로 제품은 이 문장을 막지 않았다.
- 미확인 판정은 sup ≤ .2에서만 낸다. .37은 '판정 없음'이다.
- 이 문장은 구체 정보가 없다.
- 실패한 것은 우리가 사전 등록한 "근거가 이 문장을 지지한다(≥ .8)" 기대다.

### A.2 수정 (기준값은 그대로)

- `answerFactsEvidence`가 종료 코드의 뜻을 말로 쓴다.
  - 0: "finished [after N seconds] with exit code 0, which means the command itself reported success"
  - 0이 아님: "... reported a failure"
  - 프로세스 관례라서 코드 규칙으로 둔다(R3).
- 재생(`replay-words/`, `replay-full-output/`)으로 c19 제품이 만드는 E1을 확인했다.
