# L4-c8 보고서: 캔버스 출처(provenance) 기록, 플래그 뒤의 브리핑 흐름 호스트 연결(advisory), 접힘 상태 지속

브랜치 `lane/c8-canvas-provenance` (기준 `int/c7` 0020b10). 커밋 `2692904`(시험), `850fc44`(구현), `19603e1`(훅 위치 수정), `76fc32a`(회수 대상 제한). 합성 하네스 결과이며 설치된 앱 검증이 아니다.

## 1. 출처 기록 (어디서 Agent 출력이 캔버스 카드가 되는가)
- 경로 확인: Agent 출력이 카드가 되는 곳은 사용자 동작이다. 답변의 '결과 카드로 남기기'(`openAnswerResultCard` → `ChatState.resultCardRecord`)와 게시한 결과 칩 누르기(`openPublishedOutputChip` → `openPublishedOutput` → `ChatState.publishedOutputCardRecord`). 두 경로 모두 `spawnResultCard`로 카드를 만들고 `card._resultRecord`가 카드의 `runtimeState`로 저장된다(`serializeCardState`, 위치와 같은 Desk 세션 저장). `egdesk_publish_briefing_*`는 카드가 아니라 제안(`proposed`)만 만든다. 같은 outputKey는 한 카드로 다시 그려진다(칩을 누르면 새 버전으로 redraw).
- 기록: 카드 생성 시점에 `record.provenance`를 **내용 없이**(id·종류 단어·시각만) 넣는다: `{version, creator:'agent', agentId(방의 Agent 프로필 id), engineId, runId, answerId, outputId/outputKey/outputVersion(게시 결과일 때), createdAt, supersededBy:null}`. 제목·본문·방 이름·작성자명은 들어가지 않는다(시험이 확인). 카드는 사용자가 만들지만 내용은 Agent의 것이라 creator는 `agent`.
- 대체됨(`supersededBy`): 같은 방의 같은 outputKey의 더 새 버전 `output.published` 이벤트가 오면, 열려 있는 이전 버전 카드의 provenance에 `{outputId, version, at}`를 기록하고 dirty 표시한다(카드는 다시 그리지 않고 접지도 않음). 새 버전을 칩으로 열면 카드가 새 record로 다시 그려져 현행이 된다.
- 지속: 카드 record 안에 있으므로 위치처럼 개인 Desk 세션에 저장되고 복원된다(저장 → 복원 시험). 공유 Board 원장은 쓰지 않는다(Board 공동 카드는 일반 Desk 세션에 저장되지 않음, `serializeCardState`가 null 반환). 이 변경은 개인 상태에만 쓴다.
- **출처 없음 = unknown**: 이전에 만든 카드, 출처가 불명한 카드, 잘못된 provenance(creator 값 위조, 버전 불일치)는 복원 시 버려지고 `provenance` 키가 없다. 호스트 어댑터가 이를 owner 없음으로 넘기고 흐름은 사용자 것으로 취급하므로 **회수 대상이 될 수 없다**(시험). 메모는 호스트 어댑터가 `user`로 표시(메모 레코드의 작성자가 사용자), Board 공동 카드는 후보에 넣지 않는다.
- 바이트 동일성: `restoreResultCardRecord`는 provenance가 없는 기록을 이전(int/c7) 모듈과 바이트 단위로 같게 복원한다. 증거 `evidence/l4-c8/equivalence.txt`: int/c7의 `EGDeskChatState`와 새 모듈을 11개 비교(레거시 기록 6종 복원, `resultCardKey`, `resultCardSourceView`, `upsertPublishedOutput`, export 목록, 새 레코드에서 provenance만 뺀 값) **11/11 동일**.

## 2. 브리핑 흐름 호스트 연결 (플래그 기본 OFF, advisory 먼저)
- 플래그: Firefox pref `egdesk.briefingFlow`, 값이 정확히 `"advisory"`일 때만 켜짐(그 외 모두 off). 브리지는 이중으로 Decisions 모드가 `advisory`일 때만 동작하고 `on`/`off`에서는 `{status:'skipped',reason:'mode'}`로 아무것도 하지 않는다.
- 연결: 서피스 `chat.event`의 `run.completed`에서 `state.observeBriefing?.(run)`(기존 `noteChatAttention?.`과 같은 state 훅 방식, 케이스 끝에 추가). 첫 문장이 플래그 검사이므로 **기본 경로에서는 pref 한 번 읽는 것 외에 아무 일도 안 한다**(시험: pref 외 DOM 조회 0, 기하 조회 0, POST 0, state 변화 0).
- 켜졌을 때: 방금 끝난 답변이 캔버스 카드(결과 카드·메모) **둘 이상을 이름으로 언급**할 때만(로컬 검사) `POST /decision/briefing-observe`(본문: 답변, answerId, 카드 후보와 출처 사실; 로컬 loopback 브리지). 답변당 1회. 브리지는 placement 판정, 판정이 board일 때만 reuse/retrieve 판정을 물어 **보정 로그에 기록만** 한다(advisory 행 2개, `attached:false`, 내용 없음). 설계 요청·발행·변경 없음(`observeOnly`, 주관 모델 호출 없음). 응답은 내용 없는 요약(`stages`, `outcome`, `judgeRequests`)뿐이다.
- 후보 생성: `EGDeskBriefingHost.canvasBriefingCandidates`(순수). 결과 카드 → 라벨(카드 제목), 짧은 요약(본문 앞 100자), owner/createdForAnswer/superseded는 provenance에서, visibility는 접힘·화면 안 여부에서. 메모 → `메모 N`(본문 없음), owner user. 보내도 되는 것만.
- 기본 경로 증명 요약: (a) 플래그 off에서 observeBriefing 부작용 0, (b) 훅은 케이스 끝에서 호출되어 기존 줄 인접 계약을 깨지 않음(처음 두 위치에 넣었더니 `egdesk-surface-attention`, `egdesk-surface-state`, `egdesk-annotation-memo`의 소스 형태 시험이 실패해 위치를 옮김), (c) provenance가 없는 레코드 복원 바이트 동일.
- 흐름 변경: advisory에서 placement 판정이 board이면 reuse 판정까지 기록하도록 `runBriefingFlow`를 확장하고 `observeOnly`를 추가했다. 기존 c6/c7 시험은 그대로 통과.

## 3. 접힘 상태가 Desk 세션 저장/재로드에서 살아남는가 (하네스 측정)
실제 `serializeDeskSnapshot`/`serializeCardState`/`runtimeStateForCard`와 `restoreDeskSession`의 접힘 복원 블록을 서피스 소스에서 컴파일해 측정(DOM만 가짜):
- **결과 카드와 메모의 접힘은 살아남는다**: 저장 `desk.collapsedViewIds = ['result-1','memo-1']`, 재로드 후 둘 다 접힌 상태, 접지 않은 카드는 열린 채.
- **Board 공동 카드의 접힘은 저장되지 않는다**(기존 설계): `scrubJointSession`이 세션의 접힘 id에서 공동 뷰를 제거하고 `serializeCardState`는 공동 카드를 저장하지 않는다. 그래서 회수 대상은 결과 카드여야 한다.
- **고친 것(깨져 있던 것)**: c7의 회수 적용 경로는 `WorkbenchArrange`의 `sources`(Board 카드와 메모)만 대상이라, 실제 캔버스의 결과 카드는 회수 대상이 될 수 없었다(c7 시험은 Board 카드를 결과 카드처럼 모델링해 가려져 있었음). 수정: 데스크 범위(`@desk`)에서 provenance가 기록된 `.egd-result-card`를 **접기 대상(`folds`)**으로 열거(배치·사진 대상은 아님), 컨트롤러 스냅샷에 `folds`, `offerRetrieval`은 **fold 대상만** 허용(Board 카드·배치 카드·메모는 거절), 대상만 있어도 패널이 열림. c7 시험의 모델을 결과 카드로 바꿨다. 마운트 시험: provenance 있는 결과 카드 접기 미리보기→적용→⌘Z→다시 실행→⌘Z, provenance 없는 결과 카드와 Board 카드는 거절.

## 5. 열린 점
- **동의 정책**: advisory 관찰은 라벨·짧은 요약(결과 카드 본문 앞 100자)이 외부로 나간다. 플래그를 켠 것을 동의로 보는지, 설정 화면의 명시 동의가 필요한지는 사용자 결정(코드는 `allow` 콜백 지점이 있음). 메모는 라벨 `메모 N`만 나가고 본문은 나가지 않는다.
- 결과 카드를 브리핑 **target**으로 쓰려면 기존 도구가 요구하는 바인딩된 sourceId/artifactId가 필요하다(게시 출력은 별도 id). 이번 advisory 관찰은 target을 해석하지 않으므로 영향 없음. 설계 단계(on 모드)로 가기 전에 출력→artifact 바인딩 어댑터가 필요하다.
- `stale`(원본이 바뀜) 신호는 아직 어디서도 만들지 않는다. 현재 회수 가능 조건은 "이전 답변의 Agent 출력 + 더 새 버전으로 대체됨 + 아직 보임"이다.
- `outcome.next`, 보정 로그의 판정 종류 구분 필드(`feature` 닫힌 어휘)는 여전히 없음.
- 실제 앱에서의 확인 필요: `output.published` 이벤트가 카드 dirty→저장까지 이어지는지, pref 값 형식(JSON 문자열 `"advisory"`), 열린 카드가 여러 방에 걸칠 때의 방 비교.

## 7. 철학 점검
출처는 내용 없이 만들 때 한 번 기록하고 위치처럼 개인 상태로 둔다. 모르면 unknown이라 회수할 수 없고, 회수는 접기뿐이며 내 화면에서만 되돌릴 수 있다. 기본은 꺼져 있고, 켜도 기록만 하며, 공유 원장은 건드리지 않는다.
