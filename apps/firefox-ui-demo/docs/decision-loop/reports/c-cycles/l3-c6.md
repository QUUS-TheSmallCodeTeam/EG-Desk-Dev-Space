## 1. 키 저장 결과별 포커스와 입력창 (before-surface.log)
| 결과 | 저장 전 포커스 | 저장 후 포커스(원본) | 입력창 값 | 결과 문구 영역 |
|---|---|---|---|---|
| verified | 키 입력창 | **없음(body)** | 비워짐 | role=status |
| invalid_key | 키 입력창 | **없음** | 비워짐 | role=alert |
| rate_limited | 키 입력창 | **없음** | 비워짐 | role=status |
| unreachable | 키 입력창 | **없음** | 비워짐 | role=alert |
| key-not-replaced | 키 입력창 | **없음** | 비워짐 | role=alert |
| bridge 연결 실패 | 키 입력창 | **없음** | 비워짐 | role=alert |
모든 분기에서: 입력창은 POST 전에 비워지고, 설정 구역을 `redrawDecision()`이 저장 시작과 끝에 다시 만들어 기존 입력창이 사라지며 **포커스가 페이지로 떨어짐**. 모드는 모든 경우 불변.

### 결정
- **포커스(재현된 문제)**: WCAG 2.2 2.4.3 Focus Order와 2.4.11 Focus Not Obscured의 취지에 따라, 상호작용 중 포커스가 사라지면 키보드·스크린리더 사용자가 처음부터 다시 찾아야 한다. 수정: `runDecision`이 시작 때 포커스가 설정 구역 안에 있었고, 끝났을 때 포커스가 body/분리 상태라면 새로 그려진 키 입력창으로 되돌린다. 사용자가 그동안 다른 곳(예: composer)으로 옮겼다면 가져오지 않는다(시험으로 확인).
- **오류 식별**: 결과 문구는 이미 `role=alert`(오류) / `role=status`(확인·경고)였다. 3.3.1 Error Identification에 맞게 오류일 때 입력창에 `aria-describedby`로 그 문구(`egd-settings-decision-result`)를 연결했다. `aria-invalid`는 `unreachable`·브리지 오류처럼 키가 잘못된 것이 아닌 경우가 있어 붙이지 않았다.
- **비밀값을 실패 시에도 비우는 것은 유지**: 거절·미검증·연결 실패에서도 키 문자열을 DOM 필드에 남기지 않는다(DOM 값은 세션 복원·자동완성·화면 읽기·확장 접근에 노출될 수 있고, 실패한 키를 더 오래 들고 있을 이유가 없음; 키 보관은 별도 0600 저장소가 맡는다). 비용은 재시도 때 다시 붙여넣기. 이는 OWASP 비밀 관리 취지와도 맞다. 코드 변경 없음, 시험으로 고정.
- 저장 성공/경고에서 포커스를 입력창에 두는 것은 결과를 읽은 뒤 다음 입력이나 모드 라디오로 자연스럽게 이동할 수 있게 하는 최소 선택이다(결과 문구는 live region이라 이동 없이 전달).

### 이후 (after-surface.log)
모든 분기에서 저장 후 포커스 = 키 입력창, 값 비어 있음, 결과 role 유지, 오류 시 `aria-describedby`가 결과 문구 id를 가리킴, 모드 불변.

## 2. DM composer 추천 상태 (마운트된 코드)
추천이 표시된 상태(추천 문구 + `[이유 묻기]`, 포커스는 `[이유 묻기]`)에서:
| 변경 | 변경 뒤 | 판정 |
|---|---|---|
| 설정에서 on→off | 패널 숨김, 추천 문구·`[이유 묻기]` 없음, 입력창 질문 그대로, 새 제공자 요청 0 | 비활성 확인 |
| 설정에서 on→advisory | 동일 | 확인 |
| 설정에서 키 삭제 | 동일 | 확인 |
| 다른 창에서 모드를 off로 바꾼 뒤 `[이유 묻기]` 클릭 | 클릭 시 모드를 다시 읽어(`checkMode`) 불일치 → 수동 상태 `추천을 표시할 수 없습니다. 직접 판단해 주세요. 작성 중인 메시지는 그대로입니다.`, 추천 문구·버튼 제거, 질문 그대로, 제공자 요청 증가 없음, 초안 교체 없음 | 확인 |
메커니즘: 설정 쓰기마다 `choiceSettingsWriting`/`choiceSettingsGeneration`이 오르고 `emit`이 composer `sync()`를 불러 추천 범위 키가 바뀌므로 `current()`가 거짓이 되어 패널이 초기화된다(`rawEditsOf`는 추천이 이미 전달된 단계의 옵션을 보존하지 않음). 이번 변경 없음.
수정 필요 사항 없음. 시험으로 고정만 했다.
