### 1.1 요청이 만들어지는 두 경로

| 경로 | 뜻 | 개수 |
|-|-|-|
| runtime | 런타임·세션 하트비트·provider·egress 관문·판단기·클라이언트를 전부 거친, 그 순간 제품이 실제로 만드는 요청 | 11 |

요청한 패턴 중 넷은 제품이 애초에 묻지 않는 순간이었다 (3초, 12초 생각 중, 방금 보낸 뒤 8초, 아무도 없음). 이 넷은 "모델 혼자서도 참는가"를 보는 용도로 넣었고, 빗나가도 코드 규칙이 그대로 막는다.

요청 시각은 제품의 실제 질문 일정에 맞췄다. 답이 계속 "없음"이면 제품은 10·30·70초 또는 20·40·80초에 묻는다. 그래서 "45초 명령 실행 중"은 40초 요청으로, "12초 생각 중"은 반사실(12초)과 실제 첫 질문(20초) 둘로 나눴다.

### 1.3 빗나가면 무엇이 바뀌나

| 빗나감 | 바뀌는 것 |
|-|-|
| 행동해야 할 때 none (`need-command-40s`, `need-objective-40s`, `pointer-*` hard) | **문구.** 판단 규칙의 "하지 않는 쪽 우선"이 40초 침묵보다 세게 읽힌다는 뜻. 포인터는 "배치 쪽이 이미 가리키기로 정했고 지금이 그 순간인지만 묻는다"를 질문에 넣는다 |
| 종류가 틀림 (`need-missing-10s` 에서 explain_wait, `need-silence-25s` 에서 explain_wait) | **선택지.** 코드가 내놓는 선택지를 줄인다 (열린 질문이 있으면 대기 메시지를 빼고, 침묵 기준을 넘으면 stalled 만) |

| `need-quick-3s` hard 가 빗나감 | **판단 규칙 문구**를 먼저 고친다. 나머지 결과는 그 전제로 읽는다 |
| `pointer-in-view` 가 빗나감 | 시야 안의 것은 판단기에 맡기지 않고 코드에서 뺀다 |

### 1.4 등록된 바이트를 지키는 테스트

`helper/egdesk-heartbeat-real-plan.snapshot.json` 에 등록본(id, sha256, 토큰, 기대)을 커밋했다. `egdesk-heartbeat-real-plan.test.mjs` 가 매번 다시 빌드해 등록본과 같은지 본다. 판단 규칙·선택지 문구·사실 줄이 바뀌면 이 테스트가 실패한다. 그때는 `node scripts/egdesk-heartbeat-real-plan.mjs --snapshot` 으로 다시 등록해야 하고, 이전 바이트로 잰 결과는 더 이상 제품을 설명하지 않는다.

이 결합은 의도한 것이지만 통합 때 걸릴 수 있다. 다른 레인이 provider 행이나 모델 이름을 바꾸면 이 테스트가 실패한다.

### 1.5 L6 러너에 전달할 점

- 두 패턴(`need-silence-25s`, `need-reasoning-70s`)은 같은 `name` 에 expect 가 둘이다 (hard `oneOf` + soft `equals`).
- `minConfidence` 는 `equals` 항목에만 넣었다. `oneOf` 항목에는 넣지 않았다.
- 제품의 수락 기준에는 차이 0.2 이상(1위와 2위 확률)도 있다. 형식에 자리가 없어 넣지 못했다. 결과를 읽을 때 확률도 같이 봐야 한다.

## 2. c13 열린 끝

### 2.1 대화 닫힘 신호

브리지가 이미 받는 신호 중 "대화가 닫혔다 / 방을 나갔다"는 **없었다.** 찾은 것과 한 일:

| 신호 | 상태 | 연결 |
|-|-|-|
| 대화 하나가 닫힘 / 방을 나감 | 없음 → 추가 | `POST /chat/session/close` `{ clientThreadId }` → `closeSession` |
| 창 전체가 사라짐 (`/events` 스트림이 모두 끊김) | 이미 있음 | 10초 동안 스트림이 없으면 idle 세션을 모두 끝냄 |

- **`/chat/session/close` 는 L2 가 불러야 한다.** 표면이 대화를 닫거나 방을 나갈 때 한 번. 지금은 부르는 곳이 없다. 엔진 계정 확인을 거치지 않고, 메모리만 바꾼다.
- idle 세션은 즉시 끝난다. run 이 도는 중이면 그 run 의 하트비트는 유지하고 run 이 끝날 때 idle 로 가지 않고 끝난다. 응답은 `{ accepted, closed, afterRun? }`.
- 닫은 뒤 새 메시지가 오면 다시 열린 것으로 본다.
- 창 신호의 10초는 presence 미러의 만료 기준과 같다. 창 새로고침은 약 1초 안에 다시 붙으므로 영향이 없다. 도는 run 의 하트비트는 건드리지 않는다.

### 2.2 갈 곳 없는 포인터

소유자 본인 대화가 살아 있지 않거나 소유자가 자리에 없으면, 그 사실을 **그 사람 앞으로 보관**한다. 그 사람만 참여하는 대화에서 다음 run 이 시작되면 그 run 의 포인터 선택지로 나온다.

| 규칙 | 값 | 이유 |
|-|-|-|
| 보관하는 것 | 누구, 무엇 (result / approval / question) | 방향은 보관하지 않는다. "왼쪽"은 그때 보던 화면 기준이라 나중에는 틀린다. 작성 지시문은 "책상의 다른 곳"이 된다 |
| 보관 시간 | 15분 | 세션의 하드 스톱(사람 없이 15분이면 포기)과 같은 기준 |
| 개수 | 최대 8, 원본 사실당 1 | 메모리 한도 |
| 전달 | 그 사람만 있는 대화의 다음 run, 1번 | 대상 규칙 그대로. 다른 사람이 있는 대화에는 요청조차 하지 않는다 |
| 전달 후 | 보관분 삭제, 원본 provider 에 알림 (`acknowledgePointer`) | 중복 방지 |

**L4 의 120초가 아니라 15분으로 잡은 이유.** L4 의 120초는 "방향이 붙은 포인터 사실"의 수명이다. 그 안에 소유자가 대화를 열 가능성은 낮아서, 120초를 따르면 이 대체 경로는 거의 쓰이지 않는다. 결과물 자체는 120초 뒤에도 책상에 있다. 그래서 방향을 버리고 15분 보관한다.

위험: 소유자가 그 사이 결과를 이미 봤을 수 있다. 이를 아는 신호가 없다. 판단 요청에 `attention_waiting_seconds` 를 넣어 판단기가 "없음"을 고를 수 있게 했고, 계획의 `pointer-held-3min` 이 이를 잰다.

보관분은 메모리에만 있고 브리지 재시작 시 사라진다. 멤버 id 는 런타임 밖으로 나가지 않는다.

### 2.3 nudge() 사용법

`egdesk-heartbeat.mjs` 계약 머리말에 provider 용 사용법을 적었다. L4 는 `submit` 이 장면을 대기열에 넣은 직후와 포인터 사실을 세운 직후에 `heartbeat.nudge?.()` 를 부르면 된다. idle 에서 최대 20초이던 대기가 0.5초가 된다. 거절되면 false 를 돌려주고 아무 일도 하지 않는다. L4 모듈은 고치지 않았다.

### 2.4 계획을 만들다 찾아 고친 것

- **시야 안 포인터의 문구.** L4 는 시야 안이면 방향 `none`, 거리 `in_view` 로 보낸다. c13 은 이를 "책상의 다른 곳"으로 읽었다. 이제 `in_view` 로 읽는다.
- **브라우저 작업 라벨.** L8 이 c13 에서 행의 `task` 값을 `waiting_user / handing_off / running` 으로 바꿨는데 내 요약은 옛 값을 읽고 있었다. 새 값을 읽고, "질문을 준비 중" 라벨을 하나 더했다 (라벨 8종).

## 5. 남은 것

- 실측은 하지 않았다. 계획만 있다. 보내는 것은 L6 러너와 승인의 몫이다.
- `/chat/session/close` 를 부르는 곳이 없다 (L2).
- L4 가 `nudge()` 를 아직 부르지 않는다.
- `steps_known_to_remain: 21` 은 계획이 아니라 예산(24단계 한도의 남은 수)이다. 판단기가 이를 "21단계나 남았다"로 읽을 수 있다. `need-objective-40s` 결과로 확인된다.
- 브라우저 작업 루프 동안 엔진 표시가 움직이지 않아 `seconds_since_anything_came_from_the_work` 가 커진다 (`need-objective-40s` 에서 40). 단계가 `objective_step` 이라 stalled 는 나오지 않지만, 판단기에 주는 인상은 실측으로 봐야 한다.
- 승인이 필요한 새 사용자 노출 문구는 없다. 이전 대기 건은 그대로다 (`FLOW_COPY.stalled` 등).
