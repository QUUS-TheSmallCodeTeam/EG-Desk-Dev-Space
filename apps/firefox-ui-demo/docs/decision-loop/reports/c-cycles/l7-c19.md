## 2. 코드가 먼저 줄이기 (R3): `helper/egdesk-context-pruning.mjs`

### 규칙: `held` 하나만 둡니다

이 대화에서 답변 모델이 이미 받았고, 그 뒤로 내용이 바뀌지 않은 기록은 다시 묻지도, 다시 보내지도 않습니다. "받았다"는 두 영수증 중 하나로 판단합니다.

- **선택 자신의 영수증**: `contextDeliveryKey()`는 보낸 블록(header+text)의 해시입니다. `prepareTurnContext`의 ready 결과에 enumerable이 아닌 `deliveredKeys`로 붙습니다. 런타임은 턴이 수락된 뒤 `contextDelivered`에 기록합니다. 텍스트는 다시 읽지 않습니다.
- **turn memory의 영수증**: revision과 content key가 지금 페이지와 같을 때입니다.

적용 조건은 Codex 스레드일 것 (compaction 시 `contextDelivered`도 지워짐), mode `on`일 것, 플래그 `EGDESK_TURN_MEMORY_PRUNE_HELD=on`입니다 (`turnMemory.pruneHeld`, 기본 off). receipt에는 `pruned: { held: n }` 개수만 남깁니다.

### 빼지 않는 것

- `mayRead`가 있는 guarded 후보: 선택이 all-or-nothing으로 처리하고 dispatch 때 다시 확인합니다.
- mandatory 후보, `memory-lookup:0`, `conversation:recent`
- 모델만 판단할 수 있는 나머지 전부

### 시도했다가 뺀 규칙

- **"onePacket에서 turn memory 페이지와 중복"**: 코드 사실이 아니라서 뺐습니다. turn memory는 선택과 **나란히** 돌기 때문에, 선택이 물을 시점에는 이번 턴에 turn memory가 무엇을 붙일지 모릅니다. 온톨로지 후보를 통째로 빼면 yes가 빠집니다. 같은 턴 안의 중복은 c14 `mergeIntoSelection` dedupe가 이미 막습니다.
- **"읽을 수 없는 guarded 후보 제외"**: 뺐습니다. 기존 W3 QA 테스트들이 guarded 행의 all-or-nothing 동작을 고정하고 있습니다.

### 절감: 재생한 본문 (v3, 제품 코드로 재생)

방법은 `measure-pruning.mjs`입니다. 바뀌지 않은 본문은 sha로, 짧아진 turn_context는 같은 카탈로그 제목에 기록된 실제 확률로 답합니다.

## 3. HARD `s2.no-repeat` 원인 (Main 가설 정정)

Main은 "referential rule이 held 페이지 본문을 다시 보낸다"고 추정했는데, **원인은 turn memory가 아니라 컨텍스트 선택**입니다.

- v3를 26c5b9f에서 재생해서 s2의 native additionalContext를 dump했습니다 (`evidence/l7-c19/v3-s2-ctx.json`). 키는 `egdesk_context`, `egdesk_decision_context`, `egdesk_channel` 세 개뿐이고, `egdesk_turn_memory`는 없습니다.
- `egdesk_decision_context` 안에 `[item id=ontology:quote/a-decision …]` 본문이 들어 있습니다. 선택이 12개를 모두 다시 물었고, rel_4를 0.57 (기준 0.5)로 받아 붙였습니다.
- turn memory 쪽은 s2에서 fetch를 건너뛰었습니다 (c18 규칙대로).
- 수정은 2절의 held 가지치기입니다. 테스트 `scripts/egdesk-context-pruning-journey.test.mjs`는 실제 v3의 rel 확률을 제목별로 넣어서 확인합니다. 플래그 off면 재현되고 (12개, a-decision 재전송, `s2.no-repeat` false), on이면 s2에서 7개만 묻고 s1 페이지는 하나도 보내지 않습니다 (`s2.no-repeat` true).
- 참고로 L2 harness의 `pageIds`는 turn memory의 **참조 줄** (`[page id=… already delivered earlier in this thread, unchanged; content not re-sent]`)도 셉니다. 예를 들어 s4의 `pg-design`은 다시 보낸 것이 아니라 참조만 한 것입니다. 이 줄과 본문을 구분하는 건 L2의 선택입니다.

## 6. 늦은 turn_context 결과: 플래그 `EGDESK_TURN_MEMORY_KEEP_LATE=on` (`turnMemory.keepLate`, 기본 off)

- 예산 시점에 이미 날아간 요청을 abort하지 않고, 예산 뒤 **`LATE_CONTEXT_MS` = 1500 ms** (`helper/codex-chat-runtime.mjs`)까지 답을 기다립니다. 예산이 지난 뒤에는 새 요청을 시작하지 않습니다.
- 턴의 race는 그대로입니다. 그래서 **답변 모델이 받는 것은 바뀌지 않습니다** (테스트에서 키 목록이 같음을 확인).
- 늦게 온 결과는 `decision.late`로 같은 턴의 뒤쪽 단계에만 쓰입니다.
  - **draft check 증거** (mode on): guarded가 아닌 항목을 `draftCheckTurns` entry의 `evidence` 앞에 넣고, `entry.lateEvidence = n`으로 표시합니다. L3 코드는 건드리지 않았고, 넘기는 증거로만 맞췄습니다. guarded 항목과 private topic batch는 버립니다.
  - **calibration 기록**: 늦게 온 판단을 `attached: false, late: true, lateMs`로 남깁니다. calibration log v2에 선택 필드 `late`/`lateMs`를 추가했습니다 (turn_context만).
- 테스트 `scripts/egdesk-context-late.test.mjs` (1.1 s mock, 800 ms 예산): 플래그 off면 entry에 선택 증거가 없고 timeout 한 건만 남습니다. on이면 native turn은 같고, 늦은 항목이 증거로 들어가고 (`lateEvidence`), late calibration 항목이 생깁니다.

## 7. turn_context 예산 (owner 결정 "일단 늘려")

| 값 | 위치 |
|---|---|
| warm 800 ms | `helper/codex-chat-runtime.mjs` `TURN_CONTEXT_BUDGET_MS` |
| cold 1500 ms | `helper/codex-chat-runtime.mjs` `TURN_CONTEXT_COLD_BUDGET_MS` |
| 늦은 결과 창 1500 ms (예산 뒤) | `helper/codex-chat-runtime.mjs` `LATE_CONTEXT_MS` |
| 연결 warm 여부 | `helper/egdesk-decision-transport.mjs` `warm()`: keep-alive pool에 살아 있는 free socket이 있는지 |
| idle 창 55 s (서버 Keep-Alive 힌트 − 1 s가 더 짧으면 그 값) | `helper/egdesk-decision-transport.mjs` `DECISION_IDLE_MS`, `DECISION_HINT_MARGIN_MS` (기존 값) |
| 브리지가 명시적으로 전달 | `helper/codex-bridge-server.mjs` decisionContext의 `budgetMs: TURN_CONTEXT_BUDGET_MS, coldBudgetMs: TURN_CONTEXT_COLD_BUDGET_MS, warm: () => decisionTransport.warm()` |
| 선택 로직 | `codex-chat-runtime.mjs` `turnContextBudget()` |

- `turnContextBudget()` 규칙
  - **cold(1500)**: 대화의 첫 턴 (`turnPosition` reason이 `no_native_thread`, `fresh_native_thread`, `no_prior_turns` 중 하나), 또는 `warm()`이 true가 아닐 때 (cold 프로세스, idle 창이 지남, 모든 소켓이 사용 중)
  - **warm(800)**: 그 밖의 경우
  - `coldBudgetMs`가 없는 setup은 예전처럼 예산 하나만 씁니다.
- warm 여부는 `prepareDecisionContext`가 시작할 때 읽습니다. turn memory가 먼저 free socket을 가져가면 이번 요청은 실제로 새 소켓을 열게 되므로 cold로 보는 것이 맞습니다.
- 테스트 `scripts/egdesk-context-budget.test.mjs`
  - cold 첫 턴 1.1 s → 예산 안이라 붙음
  - warm 중간 턴 0.3 s → 붙음, 1.1 s → fallback (800 ms 경로가 그대로임)
  - cold 중간 턴 1.1 s → 붙음
  - cold 1.7 s → deadline 지나 붙지 않음, keepLate on이면 늦은 결과가 draft check 증거가 됨
  - 브리지 소스가 값을 명시적으로 넘기는지 확인
- `helper/egdesk-decision-transport.test.mjs`에 `warm()` 테스트를 추가했습니다: cold면 false, 응답 뒤 true, idle cap이 지나면 false.
