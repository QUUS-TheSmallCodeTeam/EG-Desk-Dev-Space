- **scale-v2** (`real-engine-memory-scale-v2.json`): 같은 일곱 페이지, 1턴은 긴 두 페이지(데이터베이스 1,395자와 스토리지 864자)에서 사실 하나씩("야간 덤프 시각, 스토리지 증설 규모") 묻도록 줄였고 (키가 약 3.9k자, 한도 아래), attached/merged 1/noDuplicates/minKeyChars 3000. 2턴은 "본 전환은 이미 끝났어? **언제로 계획돼 있는지**, 문제가 생기면…"으로 날짜를 묻도록 고쳤습니다.

## 3. 제품 수정: selection이 전달한 페이지를 메모리 loop의 held로 (c30의 내 발견)
- 문제: 1턴에 selection 항목으로만 전달된 페이지(데이터베이스, 스토리지)가 2턴 메모리 scan의 "Held in the answering model's context" 목록에 없고 후보로 나와서(`turn2-scan-request-held-and-pages.json`), loop가 다시 골라 본문이 한 번 더 갈 수 있었습니다.
- 수정 (`codex-chat-runtime.mjs`): 전송 직전 `selectionHeldPages()`가, 보내는 selection 텍스트에 **페이지 본문이 글자 그대로** 들어 있는 페이지를 모아(`{ revision, hash }` 영수증 형태, 메모리 영수증과 같은 키) `turn.selectionHeld`로 두고, 턴이 받아들여진 뒤 `noteTurnMemoryOn`이 `turnMemoryDelivered`에 합칩니다 (메모리 쪽 항목이 있으면 그쪽이 이김; 메모리 패킷이 안 붙은 턴에도 selection 몫은 기록). **새 개발자 플래그 `EGDESK_TURN_MEMORY_SELECTION_HELD=on`, 기본 꺼짐** (처음에는 `PRUNE_HELD`에 묶었다가 게이트에서 이미 보낸 plan memory-action-v2의 요청 본문과 c17 저니의 동작이 바뀌어 별도 플래그로 분리했습니다: 보낸 plan은 그대로 재현되어야 하므로). scale-v2 스크립트가 이 플래그를 켭니다; scale-v1 JSON(이미 실행됨)은 그대로입니다. 본문이 달라졌거나 잘렸으면(글자 그대로가 아니면) 합치지 않습니다.
- 효과: held 목록(triage와 scan이 보는)에 들어가고 `heldSame`이 되어 재전송 안 됨. 테스트: 가짜 엔진에서 어휘 scan이 스토리지를 고르는 상황으로 플래그 없이는 재전송이 일어나고 (현재 동작), 플래그를 켜면 2턴 `resent` 0, held 목록에 네 페이지가 있고 후보 목록에는 없음. 변이 확인: 호출을 끄면 같은 테스트가 실패 (`mutation-check.txt`).
