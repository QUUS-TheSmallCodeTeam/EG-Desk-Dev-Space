# L7 c35: own-confirm이 실패한 이유 (check-20mw)와 고친 것

기준: int/c14 = bdece02. 근거는 기록(`evidence/main-real/real-engine/check-20mw/`)의 Decision 값과 거기서 다시 만든 요청 본문(`evidence/l7-c35/rc-body.txt`)입니다. 실제 전송은 하지 않았습니다 (Main 승인 후).

## 1. (a) 출처 라벨이 own으로 안 선 이유
- 기록 2턴: `speech_source_0 = unspecified`, `speech_form_0 = assertion`, `speech_time_0 = future_anchored`. 문장 라벨 요청(axes)이 **"unspecified"** ("화자가 근거를 분명히 주지 않음")를 바에 넘게 골랐고, reading의 basis가 그대로 `unspecified`가 되었습니다 (`pending:done:unspecified`).
- 원인은 hybrid 두 단계 설계입니다: 두 번째 요청(split 술어 own/other/record/guess)은 axes가 **설치하지 못한** 축만 묻는데, "unspecified"는 설치된 값으로 취급되어 own 술어가 한 번도 물어지지 않았습니다. 질문 문구나 임계값의 문제가 아닙니다 (axes는 결정이 근거를 대지 않는다는 점에서 틀리지 않게 읽음; split의 own v3는 "personally … did"를 묻는데 그 질문이 안 나간 것).
- 수정: 설계 `hybrid-two-step-ask` (플래그 값 `EGDESK_TURN_MEMORY_SPEECH_DESIGN=hybrid-ask`, 기본은 그대로): axes가 source를 "unspecified"로 설치하면 그 축의 split 술어를 설치 안 된 축처럼 묻고, 술어가 **구체적 출처**(own/other/record/guess)를 정하면 그 라벨, 정하지 못하면(미정/모두 no) axes의 "unspecified"를 그대로 둡니다 (아무것도 추측하지 않음). 다른 값으로 설치된 source(attributed_report, inference 등)는 다시 묻지 않으므로 **relayed, hedged는 그대로**입니다 (테스트). 다른 설계와 보낸 plan의 본문은 바이트 그대로입니다.
- own 기대값은 엄격하게 둡니다 (`self_reported_observation`); 완화하지 않았고 hedged/relayed 기대값도 v1과 같습니다 (테스트: v2 대본의 턴 기대값이 v1과 같음).

## 2. (b) "응 맞아"가 확인하지 못한 이유
- 기록 4턴: `rc_stated_0 = .09`, `rc_confirms_0 = .01`, `rc_rejects_0 = .01`. 3턴의 답은 "…방금 말씀하신 ‘다음 주 화요일 확정’은 아직 확인 전인 보고로 덧붙어 있어요." (모델이 노트를 자기 말로 **말했음**: 노트 전달은 성공).
- 판정 요청 본문을 기록의 값으로 다시 만들면 (`rc-body.txt`) 질문이 인용하는 노트가 **`"신제품 리뷰 회의 일정 (noted as done)"`** 입니다. 기록 제목과 상태 낱말뿐이라서, 판정자는 이것을 "일정 자체가 완료로 적힘"으로 읽고, 답이 말한 "다음 주 화요일 확정은 확인 전 보고"와 같은 것으로 보지 못했습니다 (stated .09, 그 노트를 확인하는 말이 아니므로 confirms .01). 즉 인용에 **사람이 보고한 내용**이 없는 것이 원인입니다 (완료 보고처럼 제목이 곧 사건인 경우에는 통했고, c15 시뮬레이션과 c1~c9의 plan이 그 경우).
- 수정: 노트 항목이 사람의 원래 말(`said`, 세션 메모리에만 두며 200자)을 같이 들고, 질문은 `"아 그거 다음 주 화요일로 확정했어 [the person's earlier message, kept as a report on 신제품 리뷰 회의 일정, noted as done]"`를 인용합니다. `said`가 없으면 인용은 예전 그대로이고 (보낸 plan record-confirmation-predicates-v1의 본문은 바이트 동일), 요청의 `input`(답과 메시지)은 바뀌지 않고 질문 인용만 바뀝니다 (테스트). 데이터 경로는 이전과 같습니다: 사람의 발화는 확인 판정 요청에서 이미 `speech_history`와 `memory_page` 허용을 요구합니다.
- 이것이 실제 모델에서 통하는지는 plan으로 확인해야 합니다 (아래).
