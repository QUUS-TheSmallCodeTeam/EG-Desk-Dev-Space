# L1 c26: 계획 단계의 새 방 계정, /tasks 와 /task-sources 의 방 계정

브랜치 `lane/c26-plan-steps-account` (base `int/c14` `d21a298`). 전부 mock, 아무것도 보내지 않음. 플래그(`EGDESK_ROOM_ACCOUNT` 브리지, 런타임 `roomAccount`) 뒤에 있고, 꺼져 있으면 동작이 그대로다. 새 문구 없음.

## 1. (a) 프로필 방 계획의 newThread 단계는 방의 계정으로 새 방을 연다 (`1ed1014`)
결정: 채팅 `send` 본문은 `engineProfileId`에 닫혀 있고, 계획 실행기의 내부 경로만 정할 수 있다.
- 계획 해결기(`egdesk-task-plans` `resolveTaskInput`): newThread 단계의 입력에 계획을 제안한 방의 slot을 `engineProfileId`로 넣는다 (slot이 없으면, 즉 기본 방이나 플래그 off면 넣지 않음).
- 작업 어댑터(`egdesk-task-native`): `engineProfileId`는 입력 허용 키이고(대화를 이름으로 지정하는 단계와는 함께 올 수 없음), `chat.send` 본문에서는 빼서 신뢰된 내부 인자 `{ newRoomProfile }`로만 보낸다. `sameThreadChat` 래퍼가 그 인자를 전달한다.
- 런타임(`requestEngineRoute`, `send(body, internal)`): 새 방이면서(`boundCid`도 저장된 slot도 없음) codex이고 `roomAccountOn()`일 때만 `newRoomProfile`을 쓰고, 알 수 없는 계정은 `assertEngineProfile`이 거절한다. 기존 방은 고정된 계정이 이긴다. 공개 본문의 `engineProfileId`/`newRoomProfile`은 읽지 않으며, HTTP는 `chat.send(body)`로 한 인자만 넘긴다.
- 테스트: `helper/egdesk-plan-step-account.test.mjs` 3개(신뢰 인자로 새 방이 그 계정에서 시작, Agent 저장 계정보다 우선, 이후 메시지도 같은 계정, 위조 본문 무시, 플래그 off와 기존 방, 알 수 없는 계정 거절), `helper/egdesk-plan-room-account.test.mjs` +2(프로필 방 계획의 newThread 단계는 기본 로그아웃/남의 계정에서도 본문 밖 신뢰 인자로 보냄, 기본 방 계획·sameThread 단계·플래그 off는 그대로).

## 2. /tasks/* 와 /task-sources 를 방 계정으로 (`288f7cc`)
- 계획 서비스: `hintsOfGraph(graphId)`, `hintsOfBoard(boardId)` (c25의 계획 힌트와 같은 방 대화 쌍). 다른 그래프나 Board는 `undefined`(기본 로그인, 이전과 같음).
- `GET /tasks/state`, `POST /tasks/{activate,retry,resume,approval,continue}`는 `ensureAuth(hintsOfGraph(graphId))`, `POST /task-sources`는 `ensureAuth(hintsOfBoard(boardId))`. 정답 기록(`recordAnswer`)과 원문 등록은 c25에서 이미 Board의 계획 방 계정으로 저장된다.
- `POST /tasks/cancel`은 계정 확인이 원래 없다(`adapter.assertScope`만). 사람이 자기 작업을 언제나 멈출 수 있어야 하므로 그대로 두었고 테스트가 고정한다. `submit`은 그래프가 아직 없어 기본 로그인(계획이 아닌 제출).
- 테스트(같은 파일 +2): 프로필 방 계획의 상태/게이트/원문이 방의 대화 쌍으로 인증되고 기본이 로그아웃이어도 등록됨, 다른 그래프/Board는 기본, 취소는 인증 없음, 플래그 off는 힌트 없음.
