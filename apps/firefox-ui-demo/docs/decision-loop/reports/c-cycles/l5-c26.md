## 1. 멈춘 명령의 사실을 다음 턴에 준다
- 원인(check-7w): 인터럽트로 턴이 끝난 뒤라서 `stopped` 도구 결과가 엔진에 전달되지 않고(`dispatchToolProvider`가 진행 중이 아닌 run의 응답을 버림), 다음 턴의 모델은 명령이 끝났는지 잘렸는지 알 수 없었음.
- 새 모듈 `helper/egdesk-stopped-command.mjs`: `stoppedCommandFact`(멈춘 명령이고 명령줄이 있을 때만; 명령 300자, 출력 끝 800자, 신호는 `SIG…` 단어만), `stoppedCommandBlock`, `stoppedCommandEvidence`, 키 `egdesk_stopped_command`.
- 실행기가 `onConditions` 기록에 `command`, `signal`, `outputTail`(멈춘 경우에만)을 더함. 런타임 `noteOwnCommand`가 대화(clientThreadId)별로 하나 기억하고, **다음 턴의 `additionalContext`에 한 번만** `egdesk_stopped_command`(kind application)로 실음(`postedInstead`와 같은 방식, 사람의 메시지와 채팅은 그대로). 그 뒤에 멈추지 않고 끝난 명령이 기록되면 오래된 것은 지워짐. 대화 삭제 시 함께 지워짐. 한정(bounded) 전송에는 실리지 않음.
- 모델이 받는 글(사실만, 지시 없음): "EG-Desk fact about the last command you started in this conversation: The command `sleep 15 && echo build-finished` was stopped at the person's request after 4.6 s (signal SIGTERM). It did not complete: it has no exit code; whether it would have succeeded is not known, and it is no longer running. Output printed before it was stopped (last part): …" (출력이 없으면 "It had printed no output before it was stopped.").
- 초안 점검: 이 블록은 불투명 참조로 세지 않고 **아는 텍스트 증거**로 줌(출력은 `terminal_output`이 허용될 때만). 그러지 않으면 "중간에 멈췄습니다"라는 올바른 답이 근거 없는 주장으로 거절될 수 있음(check-6의 시제 오탐과 같은 종류).
- 테스트 `helper/egdesk-stopped-command.test.mjs`(4): 사실/블록/증거 형식과 한계; 종단(명령 실행 → 인터럽트 → 다음 턴에 블록이 있고 사람의 입력에는 없고 세 번째 턴엔 없음); 끝난 명령은 알리지 않음, 나중 명령이 대체, 다른 대화에는 안 감; 초안 점검 증거.
- 새 실제 스크립트 `real-engine-stopped-fact-v1`(pause와 같은 흐름): 1턴 `engine.commandStopped`, 3턴 "끝까지 실행된 거야, 중간에 멈춘 거야?"에서 `answerExcludes ['cleanup-finished', '확인할 수 없']`, `posted`. Decision 키와 같은 플래그 필요(`--decisions`).
- 남은 한계(발견): 인터럽트 직후 (SIGKILL 유예 2초 안에) 바로 다음 메시지를 보내면 실행기가 기록하기 전이라 사실이 빠질 수 있음. 실측의 흐름(4.6초 뒤)에서는 해당 없음. 필요하면 다음 전송이 진행 중인 정지를 잠깐(유예+α) 기다리게 할 수 있음.
