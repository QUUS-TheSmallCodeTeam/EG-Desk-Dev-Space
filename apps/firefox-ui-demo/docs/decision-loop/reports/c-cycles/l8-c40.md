## 3. 고친 것 (문구, 근거는 위 표)
- **change**: "요청을 바꾸는가(다른 대상이나 요청)" -> "이 작업이 페이지에서 찾는 것을 바꾸는가(같은 종류의 요청의 다른 항목, 기간, 세부)? 관련 없는 질문이나 요청, 인정(응), 중단 요청은 아니다." 
- **ask_page**: 페이지 앵커 + "계속, 중단, 다시, 변경 요청, 인정, 그리고 다른 것에 대한 질문은 아니다."
- **retry**: "작업을 다시 실행해 달라는 요청인가? 사람이 자기 단계를 했다고만 말하는 것이나 다른 것을 말하거나 묻는 것은 아니다."
- **겹침 규칙 추가**: retry와 change만 yes(나머지 결정 no)면 change(더 구체적: 새 요청을 적용하고 이어감). 근거: `change` 답변이 retry .93, change .89였음. continue+retry는 c39의 것. 위쪽 두 규칙 외 쌍과 셋 이상은 그대로 미결정.
- 계획 v2(`scripts/egdesk-browser-open-item-plan-v2.json`): 같은 12개 답변과 기대, **새 문구에 대한 예측을 문구를 바꾸기 전에 커밋**(`3d6d155`): 정답 8/12(6~10), wrong 0일 확률 .80. 문구가 길어져 요청당 약 90토큰 증가: 12개 전체 추정 **13,439**(v1 12,348), 그래서 상한을 14000으로 올림(기본 4000은 그대로, 3개).
- 테스트: c57 녹화 12개의 확률을 규칙에 통과시키는 테스트(ack는 continue, change 답변은 change, 나머지 미결정이고 wrong 없음, 단일 change는 규칙상 settled이므로 방어는 문구라는 점을 명시), 문구 문장 확인, v2 계획이 v1과 같은 답변인지.
