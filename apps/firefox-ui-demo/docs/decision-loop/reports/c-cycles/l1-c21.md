## 1. 구현

### (1) 방이 자기 계정을 유지한다 (Agent에 저장한 계정은 새 방의 기본값일 뿐)
- `requestEngineRoute`: 플래그가 켜져 있고 방이 이미 있으면(네이티브 대화가 있거나 저장소 방에 계정이 기록돼 있으면) `ENGINE_PROFILE_CONFLICT`를 내지 않는다. 방의 계정이 이긴다. 새 방은 지금처럼 Agent에 저장한 계정을 쓴다. 엔진이 다른 경우의 충돌은 그대로다.
- 꺼짐이면 오늘 동작(충돌 오류)이다. 테스트가 확인한다.

### (2) 방의 계정을 명시적으로 바꾸면 같은 방이 이어진다
- 런타임 `switchRoomAccount({clientThreadId, engineProfileId})`:
  - 플래그가 꺼져 있으면 `ROOM_ACCOUNT_OFF`다.
  - 일 중인 방(`conversationBusy`)이면 `RUN_IN_PROGRESS`로 거부한다. 실행 중인 Run은 옮겨지지 않는다(Contract §14.1).
  - Board 방, 일회성 방, 분기된 방은 거부한다. 없는 방은 `CONVERSATION_NOT_FOUND`, 없거나 쓸 수 없는 계정은 `ENGINE_PROFILE_UNAVAILABLE`이다.
  - 같은 계정이면 `unchanged`다.
- 저장소 `switchRoomAccount`:
  - 지금까지의 네이티브 대화를 `room_account_segments`(처음 쓸 때 만드는 새 표)에 이전 구간으로 남긴다.
  - 방을 새 계정에 다시 고정하고 네이티브 대화는 비운다.
  - 이전 구간의 기록은 방의 기록에 그대로 있고(run 목록에 두 계정의 run이 모두 나온다), 엔진 쪽 대화만 옛 계정에 남는다.
  - `bind`가 방의 **현재** 네이티브 대화에 해당하는 바인딩 이벤트를 읽도록 조회를 좁혔다. 바뀐 적이 없는 방은 결과가 같다.
- 다음 메시지: 새 계정에서 새 엔진 대화를 시작한다. 새 대화가 시작되면(`continueSwitchedRoom`) 방에 속하고 옛 네이티브 id에 걸려 있던 것이 따라온다.
  - **답하지 않은 승인 질문**: 대기 중인 질문, 사람이 아직 답하지 않은 명령 대기열, 아직 턴에 묶이지 않은 승인이 새 대화 키로 옮겨진다(`broker.rekey`). 그래서 사람이 "네 실행하세요"라고 하면 새 대화에서 읽혀 그 명령 하나만 한 번 허용된다.
  - 방의 실제 폴더 기록(`ownFolders`)도 따라온다.
- **EG-Desk 메모리**: 메모리 범위의 소유자 키는 방이 **처음 쓴 계정**의 키로 유지된다(`memoryOwnerKeyFor`, 저장소 `roomMemoryOwnerKey`). 두 번째 전환 이후에도 처음 키다. 꺼짐이면 지금처럼 현재 계정 키다.
- **창**:
  - `ChatState.continueRoomOnAccount(thread, profileId)`: 같은 방, 메시지, 제목, 방 바인딩은 그대로 두고 네이티브 대화와 바인딩 상태만 비운다(`fresh`, 보류 아님). 다음 run이 방을 새 계정 키로 묶는다(c18 울타리). 초안은 `threadDrafts`에 있어 건드리지 않는다.
  - 브리지 API `switchRoomAccount(threadId, engineProfileId)`: pref가 꺼짐이면 `off`다. 일 중인 방은 묻지도 않는다. 거부는 닫힌 코드로 돌려주며 아무것도 바꾸지 않는다.
  - **이 전환을 부르는 화면 컨트롤은 아직 없다.** Atlas의 `[이 Chat에서 사용]` 컨트롤은 승인된 문구가 필요하다. 지금은 API와 규칙만 있다.
- 라우트 `POST /chat/room-account`(loopback JSON, `EGDESK_ROOM_ACCOUNT=on`이 아니면 404, 닫힌 응답).

### (3) 기본 계정이 바뀌어도 작업 목록을 유지하고, 각 작업의 계정은 재개할 때 확인
- pref `egdesk.roomAccount`가 `on`이면 `update()`의 기본 계정 변경 처리에서 작업 목록(`taskBoard`, 계속하기·승인·재개 상태, 제안된 계획)을 되돌려 놓는다(`keptTasksOnDefaultSwitch`). 꺼짐이면 지금처럼 비운다. L6이 고정한 줄 모양(`resetThreadConversations();` 뒤 주석과 비우는 줄)은 그대로다.
- "각 작업의 계정은 재개할 때 확인한다"는 지금 구조가 이미 한다. `/tasks/resume`은 작업 그래프가 자기 묶인 대화로 재개되고, 그 길이 방의 계정과 소유자를 확인하며, 맞지 않으면 거부한다. 거부는 `taskResumeErrorText`로 그 작업에만 표시된다. 새 확인 코드는 만들지 않았다.

### (5) 두 번째 Desk 창이 요청자를 브리지에서 읽는다
- 브리지 `POST /presence/requester/read {clientThreadId, conversationId}` → `{requester: alias | null}`. presence 플래그가 꺼져 있으면 404다. 반환은 **지금 presence 피드에 있는** 멤버 alias만이다(heartbeat의 audience 규칙과 같다). 쓰는 것은 없다.
- 창 `state.noteRunRequester`: run이 시작될 때(`run.started`):
  - 그 run의 요청자를 이 창이 이미 들고 있으면 브리지에 **다시 알린다**. 브리지의 registry는 메모리뿐이라 재시작하면 비기 때문이다.
  - 모르면 브리지에서 읽어 `adopt`로 기억한다. adopt는 `board: null`이라 이 창이 다시 알리지 않는다(브리지가 보증한 값).
- `createRunRequesters`에 `held`, `retell`, `adopt`를 더했다. 기존 `set`, `for`, `wrap`은 그대로다.

## 4. (4) Claude 방의 폴더 변경: 설계 메모만 (구현 없음, 오늘의 안내 유지)
- **오늘**: Claude 방은 시작한 폴더로만 이어진다(`CWD_CHANGE_UNSUPPORTED`, "A Claude conversation keeps the folder it started in; start a new conversation for another folder", 런타임 ~2390·~2955). 이유는 엔진 쪽이다. Claude CLI의 세션은 시작 cwd로 resume되기 때문이다.
- **Codex는 이미 분리돼 있다(ownTools, c18)**: 엔진 대화는 EG-Desk가 준비한 **빈 중립 폴더**에서 돌고, 실제 폴더는 EG-Desk 도구(명령 실행기, 파일 도구)만 안다(`ownFolders`: 대화 id → 실제 폴더). 폴더를 바꿔도 엔진 대화는 그대로다.
- **Claude에 같은 길을 적용한다면**(own-tools 경로):
  1. Claude 엔진 대화도 중립 폴더에서 시작한다. 새로 시작하는 방부터만 적용하고, 이미 있는 방(옛 폴더로 시작)은 그대로 둔다.
  2. 방의 실제 폴더는 `ownFolders`에 있고, 사람이 폴더를 바꾸면 그 값만 바꾼다. 엔진 대화의 cwd는 바뀌지 않는다.
  3. Claude 쪽 자체 도구(명령, 파일)는 꺼서 폴더 접근이 EG-Desk 도구를 거치게 한다. 이것이 중립 폴더가 안전하려면 필요한 조건이다.
  4. 같은 `ownTools` 플래그 아래에 두고(기본 꺼짐), `CWD_CHANGE_UNSUPPORTED`는 own-tools 방에는 적용하지 않는다.
- **먼저 확인할 것**: Claude 어댑터가 자체 도구를 끌 수 있는지와 중립 폴더로 시작한 세션이 resume되는지(Claude CLI 문서와 실제 확인). 확인 전에는 구현하지 않는다.
- **새 문구**: 폴더를 바꿨을 때 방이 이어진다는 안내가 필요하면 승인이 필요하다. 오늘 문구는 바뀌지 않는다.
