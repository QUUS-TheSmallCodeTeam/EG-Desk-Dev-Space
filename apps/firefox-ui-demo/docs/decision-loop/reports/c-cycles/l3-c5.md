## 원인
`helper/egdesk-native-audience.test.mjs`는 `chat.prepareDecisionContext`를 직접 대체해 `{ mode: 'on', result: { ..., mayDispatch } }`를 돌려주고, **`CodexChatRuntime`에 `decisionContext`(결정 설정)를 아예 주입하지 않는다**(`fixture`, 시험 :20-31, 36). 내가 c4에서 넣은 제출 직전 재검사(`codex-chat-runtime.mjs` `narrowDecision`, 수정 전 :2485-2491)는 `this.decisionContext.mode()`를 호출하는데 설정이 없어 TypeError → `catch`가 `current = false`(실패 시 닫힘)로 처리 → 결정 결과를 "오래됨"으로 보고 `decision.mode = 'advisory'`로 내리고 붙일 문장을 삭제. 이어지는 `reserve` 계산(`decision?.mode === 'on' && mayDispatch && additionalContext?.[DECISION_CONTEXT_KEY]`, :2496 부근)이 거짓이 되어 **native audience 예약(`context.checkAudience(cid, reserve)`)이 일어나지 않았고** 첫 grounding 배제·재개 시 대상 변경 거절도 사라짐. 시험 4건(`expected 'first-agent', actual undefined`, `Missing expected rejection`)이 정확히 그 증상. "Decision off에서도" 부분은 off 이후 재시작에서 저장된 audience 잠금이 필요한데 처음 예약이 없었기 때문에 연쇄 실패.

## 수정 (`a6a8bbc`, `codex-chat-runtime.mjs` +3/-1)
재검사는 비교할 **살아 있는 결정 설정**(`this.decisionContext.mode`가 함수)이 있을 때만 수행. 설정이 없으면 바뀔 수 있는 것이 없으므로 결과를 버리지 않는다(`current = typeof setup?.mode !== 'function' || (...)`). 설정이 있는데 `mode()`가 던지면 기존대로 닫힘. 내 모드 의미 보장(on→off/advisory/키 삭제 시 모델 선별 자료 미첨부, 핀 고정 자료만 유지)은 그대로이고, native-audience 불변식은 그대로(시험 수정 없음).

추가 발견: 이번 게이트에서 내 c1 시험 `egdesk-decision-budget-store.test.mjs`의 "a damaged file is set aside…"가 1회 실패. 로그에 `-5`가 없어야 한다는 검사가 세트-어사이드 파일명의 무작위 hex(`.corrupt-<time>-<hex>`)에 우연히 `-5`가 들어가면 깨지는 **불안정 시험**이었음(제품 문제 아님). 검사를 "파일 내용 문자열(`inputTokens`, `2026-11`)이 로그에 없다"로 바꿔 의도는 유지(`e1a6b59`), 6회 반복 통과.
