## 2. 재현된 교차 레인 버그 3건과 수정 (패치 전 원 출력: `crosslane-before.tap`)
| # | 증상 (패치 전) | 원인 레인 상호작용 | 수정 |
|---|---|---|---|
| B1 | 요청을 보낸 뒤 모드/키가 바뀌어 중단된 요청이 보정 기록에 **0건**(`2 !== 3`) | L2 c4(기록은 모드가 아직 `on`일 때만) × L3/L1(모드·키 변경이 요청을 폐기) | 요청은 항상 `on`에서 시작하므로 기록은 `on`으로 하고, 이미 전송된 요청이 설정 변경으로 끝나면 모듈의 닫힌 단어 `mode_changed`로 1건 기록 |
| B1b | `timeout_unsent`(보내지 않음)가 보정 기록에 **provider `timeout`으로** 기록(`1 !== 0`) | L2 c4 × L5(dispatch-aware timeout) | 전송되지 않은 timeout은 기록하지 않음(L7이 `timeout_unsent` 어휘를 추가하면 그때 연결) |
| B2 | bridge가 꺼져 확인이 실패하면 **`[닫기]`만** 표시 → 닫으면 입력한 보기 소실(`buttons: cancel`) | L2 c1(이유 없는 manual) × bridge 재시작(L5 transport/연결) | 이유 없는 manual에도 기존 `[질문·보기 수정]`을 표시(신규 라벨 없음, 문구 변경 없음) |
| B3 | bridge 재시작 뒤 **이미 쓴 요청 ID를 다시 보내면 유료 요청이 한 번 더** 나감(재현: provider 요청 2건). 일회 영수증이 메모리에만 있어 재시작에 사라짐 | 기존 `choiceRequests`(영수증 메모리) × 재시작 | 프로세스 시작 시각 이전에 만들어진 요청 ID는 거절(`createdAt < choiceEpoch` → manual). UI는 확인마다 새 ID를 만들므로 정상 경로 영향 없음 |
- B3은 제품 UI가 같은 ID를 재전송하는 경로는 없다(재현은 API 수준). 그래도 "의도당 유료 요청 1건" 원칙의 구멍이라 최소 가드로 막았다. 영구 영수증은 더 큰 설계이므로 하지 않음.
- 수정 파일: `helper/codex-chat-runtime.mjs`(+14/-5 안팎), `overlay/JS/eg-desk-surface.uc.js`(+2/-1). 신규 테스트 `scripts/egdesk-chat-choice-crosslane.test.mjs`.

## 4. 철학 점검
원칙: **한 번의 명시적 확인 = 최대 한 번의 유료 요청, 그리고 어떤 레인의 변경이 겹쳐도 사용자의 입력은 보존.** 더블클릭·재시도·모드/키 변경·bridge 재시작을 하나의 여정으로 이어 측정한 결과 요청은 확인 수와 일치했고(경계가 열려 있던 재시작 뒤 ID 재사용만 닫음), 보정 기록은 요청당 한 건이며 내용이 없다.
