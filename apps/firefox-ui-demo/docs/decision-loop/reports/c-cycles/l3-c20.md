- **hard:** recall yes, 정정 courtesy no, 기다림 note yes, 재질문 answer, 말하지 않은 메모 stated no
- **soft:** 승인 courtesy no, 칭찬 courtesy yes, 확인 confirms no

**시나리오가 드러낸 제품 사실** (시뮬레이션으로 꾸미지 않고 기록만 했다):
1. **턴 메모리 판정은 직전 Assistant 메시지를 보지 않는다.** 이 설정에서 "ㅇㅇ"는 "ㅇㅇ"만으로 판정된다. 판정 규칙에는 "any live conversation shown"이 있지만, all-on world에는 대화 기록 허용이 없어서 보이지 않는다. 승인·모호·정정처럼 직전 메시지에 의미가 달린 턴에 영향을 준다. **L7에 전달할 사항.**
2. **턴 맥락(answer_type, rel)도 직전 Assistant 메시지를 인용하지 않는다** (context_reask 본문에 없음).
3. **run 도중 보낸 메시지는 거부된다**(RUN_IN_PROGRESS). 진행 중인 run에 답을 받는 건 브라우저 작업의 열린 질문뿐이다. 그래서 "왜 멈췄니?"는 다음 run의 요청으로만 heartbeat에 닿는다. run 중 재촉을 heartbeat가 듣게 할지는 제품 결정이다(L2/L3).
4. **001 라벨의 정합성:** ex-2bb18a("테스트해보니… 괜찮을라나")는 topic_return .97을 받았다. 실제로는 직전 Assistant 답에 대한 결과 보고에 가깝다. 그래서 recall 시나리오에 쓰지 않았고, recall은 'referential' 라벨만 쓴다. 표본 라벨이 오면 휴리스틱으로 고른 예시가 라벨로 고른 예시로 바뀐다.
