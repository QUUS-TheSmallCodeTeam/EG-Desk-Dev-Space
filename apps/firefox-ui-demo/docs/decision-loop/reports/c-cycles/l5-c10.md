## 2. 계획을 제품 코드로 만들다 드러난 결함 (재현 후 수정)
1. **오류 블록이 정작 오류 메시지를 잃고 있었다.** 블록은 머리 700자로 자른 뒤 다시 "마지막 12줄"만 남겨, `not ok 137` 다음의 AssertionError·스택이 사라지고 뒤따르는 `ok 151…` 줄만 모델에 갔다. 수정: 블록은 **머리**를 유지(첫 12줄), 실패 줄과 들여쓴 상세는 한 블록, 실패 표식 블록은 12개 상한에서 먼저 보존. 기존 내 시험 4곳의 기대값이 이에 따라 바뀌었다(실패+상세가 한 블록: 열거 4→3, 선택 `b2,b3`→`b2`).
2. **`npm publish`·`docker system prune`은 규칙에도 점수에도 걸리지 않고 통과하고 있었다**(삭제 동사가 아니라서). 수정: 게시(`npm/pnpm/yarn/cargo publish`)와 컨테이너 데이터 제거(`docker/podman … prune`, `rm`, `rmi`)는 점수 대상.
3. 한 줄에 파괴적 명령과 평범한 `chmod`가 같이 있으면 뒤의 `chmod`가 "파괴적" 표시를 지웠다(`rm -rf dist && chmod 644 x` → 미채점). 수정.
4. 같은 조용한 tail은 한 번만 판정해서 "긴 침묵"을 물을 수 없었다. 수정: 30 s 이상 침묵이면 박동 시점에 **한 번 더**(명령당 상한 안). 박동이 없으면(대화 흐름 꺼짐) 두 번째 판정은 없다.
- 확인만 한 것: 출력 보관소의 기존 가림이 `tsc -p .`의 `-p .`을 비밀번호 인자로 보고 `[REDACTED]`로 바꾼다(화면과 같은 동작, 과잉 가림). `git clean`은 지워질 파일 수 같은 맥락이 본문에 없다(런타임이 주지 않음).
