## 1. Shadow 모드 (`EGDESK_OWN_TOOLS=shadow`, 기본 off)
- **Codex는 지금과 똑같이** 자기 셸과 파일 변경을 씀(순수 엔진 overrides 없음, EG-Desk 도구 없음, 장부 없음, spawn 없음, 엔진 폴더 없음). 승인 카드도 지금처럼 나타나고 decline하지 않음.
- Codex가 시작하는(`item/started`) **명령과 파일 변경마다 한 번씩**(같은 item은 한 번만), EG-Desk 자체 도구라면 어떻게 했을지 판정해 기록함(`helper/egdesk-own-tools-shadow.mjs`, 런타임의 `observeOwnToolsShadow`).
  - **명령**:
    - 바닥 → `would_ask`(사유 포함).
    - 판단할 수 없는, 무언가를 바꾸는 명령 → `would_ask`(`risk_unsure`).
    - `EGDESK_TERMINAL_GATE`가 켜져 있으면 술어로 판정함. 해로운 쪽이면 `would_ask`, 무해하면 `would_run`.
    - 실행 폴더 밖의 cwd → `would_refuse`(`outside_folder`).
  - **파일 변경**:
    - 만들기나 diff(update) → `would_run`(diff로 보이고 undo 가능).
    - 사람이 관리하는 파일을 지우기 → `would_ask`(`kept_file_delete`). 생성물이면 `would_run`.
    - `.git`이나 엔진 내부 → `would_refuse`(`protected_path`). 폴더 밖 → `outside_folder`. 밖으로 나가는 링크 → `symlink_escape`.
- **기록**: 보정 로그에 `feature: own_tools_shadow`, `shadow: { subject: command|file_change, would, fileKind?, reasons?, engine }`. 닫힌 어휘이고 **명령 문자열, 경로, 내용은 없음**(테스트로 확인). QA Run은 제외함.
- **브리지**: shadow 값이면 wiring이 `{ shadow: true, toolProviders: [], ownTools: { mode: 'shadow' } }`를 돌려줌. terminalGate는 사람이 설정한 그대로 둠(own-tools 병합은 'on'일 때만). c19 wiring 테스트의 정규식은 이 조건에 맞춰 바꿨음(off일 때 c11 설정을 그대로 쓴다는 단언의 뜻은 유지함).
- **증명**(`egdesk-own-tools-shadow.test.mjs`, 4개):
  - 명령 판정과 파일 판정 표.
  - 실제 런타임: shadow와 off에서 app-server 호출, 응답, 승인 카드, 이벤트가 같음.
  - shadow에서만 기록 5개(`git clean -fdx`=would_ask deletes_untracked, `npm test`=would_run, update=would_run, 관리 파일 삭제=would_ask, `.git/HEAD`=would_refuse). 반복된 이벤트는 한 번만 셈.
  - 기록에 명령 문자열이나 경로가 없음.
  - wiring이 아무것도 추가하지 않음.

## 2. 첫 실행 체크리스트 (`scripts/egdesk-own-tools-first-run.mjs`, 로직은 `helper/egdesk-own-tools-first-run.mjs`)
**아무것도 실행하지 않음**: 프로세스, 네트워크, 설치, 로그인, 파일 쓰기, 파일 내용 읽기가 모두 없음(소스 스캔 테스트). 단계를 출력하고 존재 여부만으로 전제를 확인함.

**출처(공식)**
- 설치: https://github.com/openai/codex README. 설치 스크립트, `npm install -g @openai/codex`, `brew install --cask codex`, 또는 최신 GitHub Release의 플랫폼 archive(예: `codex-aarch64-apple-darwin.tar.gz`).
- 로그인: https://developers.openai.com/codex/auth
  - "Sign in with ChatGPT … the sign-in flow opens a browser window. After you sign in, the browser returns your credentials to Codex."
  - `cli_auth_credentials_store = "file"`이면 "auth.json under CODEX_HOME".
  - "treat … auth.json like a password".

**확인 항목**: node 버전, EG-Desk 데이터 폴더, 설치 폴더, `EGDESK_CODEX_BIN`, `CODEX_HOME`, 로그인 여부, 엔진 폴더, 현재 플래그.
- `EGDESK_CODEX_BIN`: 소유 설치 폴더 아래에 있고 실행 가능한지 봄.
- `CODEX_HOME`: 소유 홈과 같은지 봄. `~/.codex`이면 "사람의 홈"이라고 표시함.
- 로그인 여부: 소유 홈에 `auth.json`이 **있는지만** 봄(읽지 않음).
- 엔진 폴더: 비어 있는지 봄.

**단계 요약**
1. **설치**(사람이 함): 공식 Release archive를 `<EG-Desk 데이터 폴더>/engines/codex/<version>/codex`에 풂. 저장소의 Codex 바이너리는 쓰지 않음. 사실 확인이 끝난 버전(0.170.0–0.174.0-alpha.1)을 권장함. 다른 버전도 동작하지만 세션당 한 번 `unverified_engine_version`이 기록됨.
2. **연결**: `<데이터 폴더>/engine-homes/codex-default`를 만들고, 브리지를 `EGDESK_CODEX_BIN=<위 경로>`와 `CODEX_HOME=<그 홈>`으로 시작함. 공유 app-server는 브리지 환경을 그대로 받으므로(`codex-bridge-server.mjs` spawnAppServer `env: process.env`) 이 두 변수로 바뀜. **`~/.codex`의 어떤 파일도 복사하지 않음.**
3. **로그인 한 번**: EG-Desk의 AI 엔진 연결(app-server를 통한 Codex 자체 브라우저 로그인)로 Sign in with ChatGPT를 함. 자격증명은 소유 홈에 남음.
4. **Shadow**: `EGDESK_OWN_TOOLS=shadow`(+ `EGDESK_TERMINAL_GATE=advisory`로 술어 판정도 받음)로 평소처럼 씀.
   - 볼 것: `<데이터 폴더>/settings/egdesk-decision-calibration.json`의 `own_tools_shadow` 기록 분포, `unverified_engine_version`.
   - 기대: 평소 명령은 would_run, 파괴적인 명령은 would_ask, 프로젝트 안에서는 would_refuse가 없음.
5. **버릴 폴더에서 own tools**: 실제 프로젝트 밖에 버릴 git 저장소를 만들고 Board를 묶음. `EGDESK_OWN_TOOLS=on`으로 켜고 읽기, 검색, 정확한 편집, diff 편집, undo, 테스트, 파괴적 명령(예: `git push --force`)을 시켜 봄.
   - 볼 것: 파괴적 명령이 멈추고 대화에서 물음. "응"이면 한 번 실행되고 "아니"면 실행 0회. 엔진 폴더가 비어 있음. native 승인 카드가 없음. 출력이 실행 출력 보기에 나옴.
6. **실제 폴더**: 실제 프로젝트를 묶고 같은 신호를 첫 세션들 동안 계속 봄.
7. **되돌리기(언제든)**:
   - `EGDESK_OWN_TOOLS`를 지우고 재시작하면 지금과 똑같음.
   - `EGDESK_CODEX_BIN`과 `CODEX_HOME`을 지우면 이전의 Codex와 홈으로 돌아감(`~/.codex`는 한 번도 건드리지 않았음).
   - 편집은 undo 기록으로 되돌림.
   - 소유 폴더(engines, engine-homes, engine-folders)는 지워도 됨.

- 이 트리에서 실제로 출력한 결과는 `evidence/l5-c20/first-run-print.txt`(증거 HOME, 임시 데이터 폴더)에 있음.
- 테스트(`egdesk-own-tools-first-run.test.mjs`, 3개): 처음 상태(모든 단계가 남아 있고 `~/.codex` 아래를 하나도 보지 않음), 단계를 마친 상태(모두 ok), 잘못된 설정 표시, 단계 순서(shadow → 버릴 폴더 → 실제 폴더 → 되돌리기)와 출처 인용, 스크립트에 실행이나 네트워크 코드가 없음.

## 3. 남은 것
- 실제 Codex로 한 번도 실행하지 않았음(금지). 첫 실행 자체는 소유자 결정임.
- 체크리스트의 3단계는 EG-Desk의 기존 엔진 로그인 화면(app-server `account/login/start`)을 전제로 함. 그 화면이 `CODEX_HOME`을 바꾼 공유 app-server에서 그대로 동작하는지는 실제 실행 전에는 확인할 수 없음. 대안은 그 `CODEX_HOME`으로 공식 CLI를 실행해 "Sign in with ChatGPT"를 고르는 것임(README: "Run codex and select Sign in with ChatGPT"). 이것도 사람이 할 일임.
