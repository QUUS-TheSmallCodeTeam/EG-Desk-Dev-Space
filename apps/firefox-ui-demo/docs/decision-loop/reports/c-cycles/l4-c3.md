## 2. Board 배치 추천 보정 기록 (canon §5.3)
기존 `helper/egdesk-decision-calibration-log.mjs`의 API만 사용했고 화이트리스트는 바꾸지 않았다(`feature:'board_arrangement'`는 이미 허용).
- `egdesk-board-presentation-http.mjs`: 선택적 `calibrationLog` 의존성 추가, `run()`에서 `calibrate()` 호출. `codex-bridge-server.mjs` 한 줄: 핸들러에 `decisionCalibrationLog` 전달. 기록 실패는 삼키고 응답은 불변.
- 기록되는 항목(예, `sample-calibration-entry.json`): `{"feature":"board_arrangement","mode":"on","day":"…","judgments":[{"q":"choice","would":"accept","top":0.94,"second":0.06,"p":0.94,"threshold":0.75,"minMargin":0.2}],"candidates":4,"attached":true}`.
  - top-two 확률: `top`, `second`. bar: `threshold`=0.75(확신도), `minMargin`=0.2(1·2위 차). bar의 판단: `would` = `accept`(통과) / `reject`. advisory도 같은 bar를 적용해 기록(`attached:false`). `on`에서 미리보기가 실제 제안되면 `attached:true`.
  - 실패·무효 경로: 응답 도착 뒤 모드/키가 바뀜 → `fallback:'mode_changed'`, 시한 경과 → `timeout`, 공급자 실패 코드(timeout/unreachable/…)는 어휘 안의 것만. 모두 `judgments:[]`.
  - 담지 않는 것: 제목, slot, 목적 문장, 옵션 이름, id, 좌표, 이미지, 텍스트. 시험이 기록 파일에 목적 문장·옵션 이름·키·`data:image`·`slot`이 없음을 확인.
- **빠진 필드(보고만, 수정 안 함):** '사용자가 다음에 한 일' 라벨(적용함 / 되돌림 / 거절 / 내 선택 유지 / 시간 초과)을 담을 자리가 없다. `complete(id, outcome)`의 `outcome`은 `run`(completed/failed/interrupted/cancelled)과 `toolActivities`만 받고, 엔트리의 `attached`(boolean)와 `fallback` 어휘도 이 의미가 아니다. 의미를 오용하지 않으려고 라벨은 기록하지 않았다. 제안: `outcome.next ∈ {applied, undone, rejected, kept_own, timed_out}` 닫힌 어휘 한 개 추가(L7 소유 모듈 변경이므로 승인 후). 추가되면 컨트롤러가 `apply`/`undo`/`choose` 시점에 브리지로 라벨을 보내는 얇은 POST만 더하면 된다. 라벨 없이도 "bar가 accept였는지 + 확률"은 쌓이지만, 임계값 보정에는 라벨이 필요하다. 또 `would`는 어휘상 `accept/reject`만 쓸 수 있어 `keep`을 고른 경우도 `accept`(= bar 통과)로 기록된다는 점에 주의.
- 시험 `helper/egdesk-board-presentation-calibration.test.mjs`(5개): on 통과·bar 미만·advisory·모드 변경 fallback·기록 실패 시 응답 불변. 패치 전 0/5(기록 없음), 후 5/5.
