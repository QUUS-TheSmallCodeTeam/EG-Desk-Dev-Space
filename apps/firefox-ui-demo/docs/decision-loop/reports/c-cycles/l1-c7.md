# L1 cycle 7: Board 답변 발췌 선별을 공통 egress 게이트로 통일 (요청별 체크박스 제거)

브랜치 `lane/c7-board-reply-unify` (base `int/c10` f57b0cd), 커밋 `46d6c2e`.
모든 관찰은 **synthetic harness**다(임시 SQLite desk, 실제 ask 서비스/selector/Decisions client/게이트/패널 흐름/검토 흐름, mock fetch). 설치 앱, 실제 OpenAI, Firefox는 쓰지 않았다. 암호화 번들 의존성이 없는 이 환경에서 `egdesk-board-agent-ask-roundtrip.test.mjs`는 계속 skip이라 그 파일의 수정은 구문 검사만 했다.

## 1. 결정: 발췌가 Decisions로 갈 수 있는 조건
D2(결정 모델은 다른 모델과 같은 데이터 공유 권한을 따른다, 별도 동의 없음)를 Board 질문에 그대로 적용했다.
- **초안(draft) 실행**: 소유자가 고르고 확인한 실행이 승인된 공개 발췌를 이미 초안 모델(전용 OpenAI Responses)로 보낸다. 이때만 게이트의 `board_excerpt`가 열린다. 저장된 결정 모델 모드가 `on`/`advisory`이고 키가 있으면 선별 요청 1건이 나간다.
- **발췌(extract) 실행**: 발췌를 어떤 모델에도 보내지 않는다("이 기기에서 처리"). 그래서 Decisions에도 보내지 않는다. 저장 모드가 `on`이어도 요청 0.
- 모드 `off` 또는 키 없음: 어느 실행에서도 요청 0.
이 규칙은 L5 c6 보고서 2.4절의 제안과 같다. 요청 본문의 어떤 필드도 선별을 켤 수 없다.

**동작이 달라지는 점(확인 필요):** 예전에는 발췌 실행 + 체크박스로 Decisions 선별이 가능했다. 이제는 불가능하다. 초안 서비스는 기본 꺼짐(전용 설정 파일과 별도 키 필요)이므로, 초안 서비스를 설정하지 않은 기기에서는 Board 답변 선별이 Decisions를 전혀 쓰지 않는다. 반대로 초안 서비스가 있고 저장 모드가 `on`/`advisory`이면 초안 실행은 요청별 선택 없이 항상 선별을 거친다(확인 화면에 표시됨). 발췌 실행의 "외부 API로 보내지 않습니다" 약속을 깨지 않으려면 이 해석이 유일하게 안전하다고 판단했다. 다른 해석(발췌 실행에서도 모드만 켜져 있으면 전송)을 원하면 게이트의 한 줄(`boardExcerptsToModel`)만 바꾸면 되지만, 그 경우 발췌 실행의 화면 문구도 바꿔야 한다.

## 2. 변경 (제품 파일 5개 + 문서 1개)
- `helper/egdesk-decision-egress.mjs`: kind `board_excerpt`(class `board`) 추가, `modelDataPermissions({ boardExcerptsToModel })`, `EGRESS_SITES['egdesk-board-agent-context.mjs'] = ['board_excerpt']`("NOT yet unified" 표시 삭제).
- `helper/egdesk-board-agent-context.mjs`(selector): 입력의 `decisionEgress` 플래그 삭제. 옵션의 `egress` 게이트에 `allows('board_excerpt')`를 묻고, 아니면 키 조회·요청 없이 로컬 선택을 돌려준다(기존 폴백 그대로). 게이트가 아닌 값(true, 문자열, 프록시, 던지는 객체)은 닫힌 것으로 본다.
- `helper/egdesk-board-agent-ask.mjs`(서비스): `prepare` 입력에서 `decisionEgress` 제거(보내면 `INPUT` 400). 선별 여부는 게이트 + 저장 모드에서 파생한다. Board 질문의 게이트는 도구 상한을 모두 none으로 넣어 **`board_excerpt` 외의 kind는 전부 닫힌다**. `prepare` 응답에서 `decisionEgress` 제거, `decisionModel`/`decisionMode`는 선별이 실제로 적용될 때만 값이 있다. `DECISION_OFF` 오류는 더 이상 없다. client는 `guardClient(['board_excerpt'])`로 한 번 더 감싼다.
- 승인의 범위: 미리보기 뒤 결정 모델 설정이 바뀌면(꺼짐→켜짐, on→advisory, 키 교체) 초안 실행 승인은 `STALE`이 된다. 발췌 실행은 설정 변화의 영향을 받지 않는다. 한 번의 승인 = 한 번의 처리는 그대로다.
- `overlay/resources/EGDeskBoardAgentAsk.sys.mjs`(패널): 체크박스, `chooseDecision`, 요청/응답의 `decisionEgress` 제거. 호스트 응답이 발췌 실행에 Decision 모델을 지정하거나, 모드 없이 지정하면 실행 전에 거부(stale 안내 + 취소).
- `overlay/resources/EGDeskReviewHandoff.sys.mjs`(소유자 회신 안내): 실행이 보고한 `screening`만 따른다. 예전의 호환 분기(`screening` 없음 + source가 local이 아님 → "Decisions 사용")는 삭제했다. 그대로 두면 선별 없는 초안이 Decisions를 썼다고 잘못 말하게 된다.
- `docs/DECISION_MODEL_CONTEXT_SETUP.md` "외부 선별" 항목을 새 규칙으로 고쳤다.
- 유지: 선택은 승인된 발췌 집합 안에서만(c3), advisory는 기록만(선택 불변), 소유자 안내는 실제로 일어난 일을 말함(c3), 보정 기록(c4, `board_reply`), 일회용 코드.

## 4. 시험
| 요구 | 결과 |
|---|---|
| 허용 → 선별 요청 1건 | 초안 실행 x 모드 on/advisory: Decisions 요청 정확히 1건, 본문은 질문 + 승인 발췌 별칭뿐(`screening-journey` 14건, `calibration` 12건, `draft-host` 2건, `egress` 1건, `quota` 1건) |
| 불허 → 요청 0 + 로컬 폴백 | 발췌 실행 x off/advisory/on, 초안 실행 x off, 게이트 없음/닫힘/가짜 게이트: 요청 0, 로컬 단어 일치 결과 그대로 |
| 렌더된 패널에 체크박스 없음 | 선택 화면의 input은 라디오 2개뿐, 확인 화면은 input 0개, `chooseDecision` 없음(`scripts/egdesk-board-agent-ask.test.mjs`) |
| 요청 필드로 선별을 켤 수 없음 | `decisionEgress` true/false 모두 `INPUT`, 요청 0 |
| 선택이 승인 집합 밖으로 나가지 않음 | 범위 밖 별칭(c99) 무시, 초안이 받은 발췌는 항상 승인 발췌 |
| advisory 기록만 | 초안이 받는 발췌 = 로컬 선택, 보정 기록 1건 |
| 승인 뒤 설정 변경 | 꺼짐→켜짐, on→advisory 모두 `STALE`, selector 미도달 |
| 철회/재저장/재발행, 진행 중 철회 | `STALE`, Decisions 0 또는 늦은 응답 폐기, 초안 요청 0 |

초안 실행 여정(모드 x 응답, `after.tap`의 ROW): off는 요청 0에 로컬 [1,2]. advisory는 요청 1에 [1,2](실패 시 fallback 표시). on은 확신 [2], 저확신·기권은 빈 선택(초안 요청 없음), 범위 밖 별칭 [1,2,3], 429·timeout은 fallback으로 [1,2].

## 6. 철학 점검
결정 모델은 시스템 수준 판정자이고, 그 입력은 다른 모델이 받을 수 있는 것과 같다. 발췌는 소유자가 확인한 실행이 모델로 보내는 경우에만 Decisions로 가고, 그 사실은 확인 화면과 회신 안내에 그대로 나온다. 요청별 스위치가 없어졌지만 승인 범위는 넓어지지 않았다(발췌 실행은 오히려 완전히 닫혔다).
