## 1. check-7 원인 (records/…/briefing-schema-{on,off}.json)
- `forkReplies`는 둘 다 `[null, null]`: 검증기(`validateFill`)까지 가지도 못함. 따라서 "어느 규칙, 어느 슬롯"이 아니라 응답 자체가 없었음.
- 시간이 말해줌: `engineStats.elapsedMs` 60,780 / 60,831 ms에 `turns: 2` = 한 턴당 30.4 s, 엔진의 `turnMs` 30,000 + 오버헤드. `forkRequests`는 thread/start + turn/start가 각각 2번(턴 시작 2 ms로 즉시 수락), `forkErrors: []`, `schemaInvalid 0`(null은 스키마 위반으로 세지 않음). 결론: 새 스레드의 fill 턴이 30초 안에 답하지 못해 두 번 타임아웃(직접 관찰한 것은 아님: 당시 레코드에 턴별 종료 사유가 없었음. 시간 일치로 추론).
- check-5(카드 3장, 12~13 s에 성공)와 달리 c33의 설계(sequence + open_items)로 바뀐 뒤 같은 fill이 더 오래 걸린 이유는 레코드에 없어 모름. 지연 원인 자체(모델 지연인지 멈춤인지)는 이번에도 확인되지 않았고, 아래 관측이 다음 실행에서 알려줌.
- 스키마 대 검증기: 스키마는 길이/행 수/빈 문자열/좌우 동일을 표현할 수 없음(strict 부분집합). 검증기가 응답 전체를 거부하는 경우는 틀 이외에 하나뿐이었음: 제목이 한도(80자)를 넘으면 `no-title`로 응답 전체 거부(스키마는 허용). 수정: 제목은 단어 경계에서 잘라 수용(빈 제목만 거부). 차분 테스트(시드 고정 600개 무작위 스키마-유효 응답): 전체 거부는 빈 제목 외 없음, 나머지는 `empty`/`mismatch` 슬롯 이슈로만 나타나고 기존 흐름이 처리.

## 2. 수정
- 재시도 규칙(엔진): `engine.lastFailure()` 추가(`timeout` | `no-reply` | `refused` | `unusable` | null; 시간 한도에 도달해서 null이면 timeout). `stats()` 키는 그대로.
- U5 fill-invalid: 전체 fill이 타임아웃이면 같은 요청을 다시 보내지 않음(같은 일이 다시 일어남). 응답이 없거나 쓸 수 없으면 한 번 재시도(이전과 동일), 그래도 안 되면 한 라운드만 항목을 하나씩 요청(`fillInPieces`: 항목당 한 요청이라 응답이 짧고 각자 자기 시간 안에서 끝남; 제목은 첫 조각의 것; 항목 1개이거나 4개 초과이면 안 함; 조각 하나가 쓸 수 없으면 라운드 종료, `detail`은 전체 fill의 사유 유지, 조각의 사유는 `stats.pieces`). fillTurns에는 1턴으로 계산.
- U5 not-covered: 놓친 사실이 있고 추가할 미결정 part가 없으면 (종전에는 곧바로 채팅) 그 사실을 인용한 자료를 가진 카드들만 한 번 다시 씀(`rewriteCovering`). 요청에는 닫힌 `cover` 목록(자료 별칭만, 답변 글은 절대 안 보냄)과 `only`. 규칙 검사(넘침, 슬롯 이슈), 지원 질문, 놓친 사실만 다시 질문. 그래도 놓치면, 또는 재작성이 쓸 수 없으면 채팅. 추가 요청: 최대 7개로 `maxRequests` 8 이내.
- hook 관측: `forkTrace`(비공개 턴별 걸린 시간, 종료 코드 예 `INTERNAL_TURN_TIMEOUT`, via, 상태, 생성된 item 종류, 마지막 토큰 사용량), `engineCalls`(요청별 kind, only, cover, ok, 실패 사유).

## 3. 기존 테스트 기댓값 변경 (의도된 동작 변경, 약화 아님)
- fill이 두 번 쓸모 없을 때 fillTurns 2 -> 3(한 조각 라운드가 추가되고 첫 조각에서 멈춤), 마운트된 경로의 fork 프롬프트 2 -> 3. 놓친 사실에 대해 종전의 "추가 part 없음 -> 즉시 채팅, 두 번째 fill 없음"이 "해당 카드 재작성 1회 후 채팅"으로 바뀌어 세 곳의 `coverage.redesign: null`이 `{ from: 'rewrite', parts: [], items, cover }`로 바뀜. 모두 코멘트로 U5 변경 사유를 남김.

## 4. 새 테스트
- 스킬레톤: 타임아웃이면 같은 요청 재전송 없음(요청 순서 pin), unusable이면 종전처럼 한 번 재시도 후 조각 라운드, 조각 실패 시 중단과 사유 유지, 놓친 사실 재작성(성공/여전히 놓침/재작성이 지원 안 됨/재작성 응답 불량)과 요청 수 7, `cover`는 별칭만, 프롬프트의 닫힌 단어, 제목 자르기.
- 엔진: `lastFailure` 5가지 분류와 stats 키 불변. 스키마: 차분 테스트.
- hook(실제 0.171 모양의 fake): check-7 재현. 전체 fill 요청은 시간 안에 답하지 않고(한도 400 ms) 항목 단위 요청은 답함: 두 대화 모두 presented, 모든 사실, `engineCalls`가 `[전체: timeout]` 후 `[P1]`, `[P2]`, `forkTrace[0].code INTERNAL_TURN_TIMEOUT`, 타임아웃은 스키마 위반으로 세지 않음.
