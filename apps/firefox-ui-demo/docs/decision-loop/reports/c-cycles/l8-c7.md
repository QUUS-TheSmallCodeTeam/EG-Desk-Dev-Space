## 2. 구현
- `createBrowserTaskHistory({ dataDir?, now })`: 선택적 영속(0600, 0700 디렉터리, 원자적 쓰기, 손상 시 격리, 최대 100건·180일). `candidates` 와 `fetch` 모두 권한 검사: **같은 계정(ownerKey), 이 실행에 허용된 카드와 같은 사이트, 만료 전**.
- 이력 단계(`egdesk-browser-task.mjs` lookupPrior): 코드가 후보 열거(후보 0이면 Decisions 요청 0) -> Decisions가 `[H1..]` 중 하나 또는 `no_prior_record` 선택(`decideHistory`, 임계값 choice 0.75/margin 0.2, authorizeDispatch 포함, 4 s foreground) -> 호스트가 권한 확인하며 다시 fetch -> `task.prior`.
- 진입 결정에도 이력 사용: 카드마다 최근 요청 한 줄(80자)을 진입 evidence에 `Earlier browser tasks on these cards`로 추가(기록이 있을 때만).
- 객관 루프(`runBrowserReflex` `priorRun`): 이전 실행 요약 줄을 `History (earlier run ...; may be outdated)`로 각 결정에 제공. 코드가 현재 페이지와 대조한 사실도 제공: 같은 경로에서 이전에 해결한 라벨이 지금 목록에 있으면 `it is listed now as [L2] ...`, 없으면 `NOT listed now`. **없으면(충돌) 모델이 무엇을 골랐든 코드가 `needs_user_context`로 바꿔 사용자에게 묻는다.** 현재 사용자 요청·맥락이 이력보다 우선한다고 규칙에 명시.
- 기록 시점: 작업 완료(done) 또는 cannot_proceed 일시정지(`stuck` + 닫힌 코드)에 id로 upsert. 질문(need_context)만으로는 기록하지 않는다. `choice_needed`로 멈춘 뒤 다음에 연 요소가 그 질문의 해결 라벨이 된다.

## 4. 승인이 필요한 데이터 결정
- 이력 파일에 **사용자 요청 문구(120자)** 와 **열린 요소 라벨(예: 사업자 번호)** 이 로컬 0600 파일에 180일 보관된다. 대화 저장소가 이미 사용자 메시지를 보관하지만 별도 복제본이다. 요청 문구 대신 대화 메시지 참조만 저장하는 대안도 가능하지만 이력 선택에 문구가 필요하다.
- 이력 선택·단계 결정 요청에 기록 내용(요청 문구, 라벨, 정화된 경로)이 Decisions로 간다. 기존 reflex가 페이지 텍스트를 보내는 것과 같은 허용(authorizeDispatch, 같은 recipient)을 쓰며 별도의 허용 UI는 만들지 않았다. 필요하면 "이력을 외부 판정에 보낼지" 별도 허용 항목이 필요하다.
- 사용자에게 보이는 문구, 기능 이름은 추가하지 않았다. 이력 삭제 UI도 없다(`clear(ownerKey)` API만 있음).

## 5. 챗 런타임 연결(4번): 하지 않았다, 이유
`codex-chat-runtime.mjs`의 send 경로에서 run(및 `browserBinding`)은 `engine.startTurn`(`:2538` 부근) 뒤에 만들어지고 `provider.bindRun`이 그 뒤(`:2606`)에 호출된다. 직접 진입은 **주관 턴이 시작되기 전에** 바인딩된 run으로 객관 루프를 돌려야 하므로, 연결하려면 (a) 턴 전 임시 run 바인딩 또는 bindRun/startTurn 순서 변경, (b) 제한된 브라우저 턴이 추가 컨텍스트를 받지 않는 불변식(`:2276` `bounded ? {}`)에 예외를 만들어 노트를 주입, (c) 턴 시작 실패/취소 시 바인딩 정리 경로가 필요하다. 이는 L7(턴 기억)이 만지는 `extraContext`/`additionalContext` 조립부와 L3 초안 검사 경로와 겹치고, 순서 변경은 단순한 플래그로 감쌀 수 없다. 플래그 기본 off로 모양만 넣으면 검증 불가한 죽은 코드가 된다. 안전한 순서로 제안: 별도 라운드에서 (1) 턴 전 경량 바인딩 API(`provider.bindPreRun`)와 그 해제, (2) 노트 주입은 새 키로 주관 입력에만 추가하고 `bounded ? {}` 테스트를 새 예외 한 곳으로 갱신, (3) 이후 이 모듈을 연결.
