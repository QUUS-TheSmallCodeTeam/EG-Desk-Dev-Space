## 항목 1. 지금 브리핑이 답한 모델에게 보드 설계를 부탁하는 방식 (장면 형태)

## 항목 2. outputSchema (EGDESK_BRIEFING_OUTPUT_SCHEMA=on, 기본 꺼짐)
- 공식 Codex 0.171 `TurnStartParams.outputSchema`("이 턴의 최종 메시지를 제한하는 선택적 JSON Schema"). 포크 턴의 `turn/start`에 그 스키마를 붙입니다.
- **스키마는 기존 렌더 컴포넌트의 받아들이는 모양에서 만듭니다**(`H/egdesk-briefing-output-schema.mjs`). 새로 만든 것이 없습니다.
  - fill: guide의 항목 id마다, 그 컴포넌트가 나열하는 칸만(text는 문자열, material은 **그 항목의 재료 별칭 중 하나**, list는 정확히 그 필드를 가진 행). `unfillable`의 `item`은 항목 id 중 하나입니다.
  - design: 요청이 나열한 대상 별칭과 "new:<part>", emphasis는 닫힌 단어 또는 null.
- **엄격 모드 호환**(가정): 모든 객체에 `additionalProperties:false`, 모든 속성이 required, `type/properties/required/items/enum/anyOf`만 사용하고 `minLength`, `maxLength`, `pattern`, `minItems` 등은 쓰지 않습니다(글자 수와 개수 상한은 코드의 `validateFill`이 그대로 지킵니다). 엄격 스키마는 칸을 뺄 수 없어서 칸을 못 채우면 `null`을 쓰게 하고, `stripNulls`가 null을 "칸을 뺌(unfillable)"로 되돌려 기존 검사가 읽습니다. 테스트가 스키마가 이 부분집합 안에 있는지(`schemaProblems`) 확인합니다.
- 엔진은 스키마가 있을 때 최종 메시지가 **JSON 객체 그 자체**(앞뒤 설명, 코드 펜스 없음)이고 스키마에 맞는지 **자기가 다시 확인**합니다(`violation`). 엔진의 제약을 믿지 않습니다. 모의, 구버전 엔진, 거절이 어길 수 있기 때문입니다. 맞지 않으면 null이고 `stats.schemaInvalid`로 셉니다.
- **꺼짐일 때 바이트까지 같음**(테스트로 고정):
  - 프롬프트는 켜짐일 때와 같고(스키마가 제약을 나릅니다), `runText`는 정확히 `{ timeoutMs }`만 받습니다.
  - 포크 `turn/start`의 params 키는 `threadId`, `input`, `clientUserMessageId`뿐입니다.
  - `stats()`에 `schemaInvalid` 키가 없습니다.
- **가짜 app-server 테스트**(포크 턴 params를 기록하도록 하네스에 한 줄 추가):
  - 유효: 포크 `turn/start`에 guide에서 만든 스키마가 붙고, 보드가 제안됩니다.
  - 무효, 거절, 실패: 추가 필드, JSON 앞뒤 설명, 다른 자료의 별칭, 거절 문장, 실패한 턴 → 모두 `fallback-chat / fill-invalid`, 아무것도 게시되지 않고, 각 포크 턴에 스키마가 붙었습니다.
  - 엔진 단위: 추가 필드, 앞뒤 설명, 코드 펜스, 다른 별칭, 거절, 빈 메시지 7가지 모두 null이고 `schemaInvalid` 7로 셉니다.
- 확인하지 못한 것(실엔진 필요): 0.171이 **임시 포크 스레드의 턴**에서 `outputSchema`를 지키는지, `anyOf`+null 합집합과 별칭 열거(`enum`)를 엄격 모드가 받아들이는지, 거절 시의 모양.
