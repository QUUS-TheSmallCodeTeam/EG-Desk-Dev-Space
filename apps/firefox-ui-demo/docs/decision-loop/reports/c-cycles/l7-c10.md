### 1.2 최소 권한 Board 범위 (사용자 결정)
- Board 항목 페이지는 scope `board:<id>`를 가진다. `adapter.scopeFor(context, body)`는 이 DM scope와, 메시지가 그 Board에서 보내졌을 때(`body.boardId`)만 `board:<그 id>`(그리고 `board:current`)를 허용한다. 다른 Board, 다른 DM, Board가 아닌 DM에서는 읽을 수 없다. 사용자가 이 메시지에 선택한 자료(`selected:*`)는 그 DM scope로만. 온톨로지 그래프는 기존처럼 전역(결정 카탈로그에 이미 제공되던 범위).
- 시험: 아답터 매핑 수준(DM/다른 Board/그 Board)과 `reconstructMemory`까지의 종단 확인: 자기 DM에서는 선택 자료만, Board 항목은 보이지 않음; 그 Board에서 보냈을 때만 Board 본문이 판정자에게 간다; 다른 Board에서는 안 간다; 저장소 자체의 `mayRead` 철회가 위에 겹쳐 적용된다.
- 데이터 공유 설정(D2): 별도 동의를 추가하지 않았다. 판정 모델의 송신을 하나의 헬퍼로 합치는 L5 작업은 아직 이 브랜치(int/c8)에 들어오지 않았다(egress 헬퍼 없음). 들어오면 어댑터·런타임의 Decisions 호출 경로를 그 헬퍼로 옮긴다(열린 항목).

### 1.3 자동 승격 금지 (사용자 결정)
- 판독(pending)은 어떤 경로로도 스스로 status가 되지 않는다. `createWikiWriter`는 `acceptStatus`를 받지만 **무시**한다(호출자 호환용). `adapter.writerFor`는 더 이상 받지 않는다. 모델의 점수·판정자·다른 Agent·정책 콜백은 승격할 수 없다.
- 유일한 승격 규칙(호스트 규칙, 문서화): `writer.promote(pageId, { scope, confirmation: { by: 'user', at: ISO }, operationId })` — **사용자 본인의 이후 명시적 확인**. 조건: 쓰기 플래그, `by`가 정확히 문자열 `'user'`와 일치, 확인 시각이 판독의 말한 시각보다 **나중**(같은 순간의 말은 확인이 아님), `canWrite({op:'promote'})`, 존재하는 pending 판독(가장 최근 것). 사용자가 실제 UI 동작으로 확인했음을 호스트가 보장해야 하며 이 함수는 `by:'user'`가 아닌 것을 거부할 뿐 그것을 증명하지는 못한다. 승격되면 accepted 판독이 pending을 대체하고(`confirmedAt` 기록) 리비전이 오른다. 멱등(operationId), 영속 저장소에는 accepted 판독이 같은 소스 리비전에 저장되며 다음 턴의 오버레이에서 같은 상태·시각의 pending을 대체해 중복이 생기지 않는다.
- 시험: 잘못된 확인 8종(null, 빈 객체, agent, policy, 시각 없음/잘못됨, 대소문자 다른 USER, 문자열) 거부, 판독보다 이르거나 같은 확인 거부, 쓰기 권한 없음·플래그 꺼짐 거부, 그 모든 시도 뒤에도 status 불변, 성공 시 리비전·상태·판독 교체, 재생(replay), pending 없음 거부, 영속·오버레이(저장소 기반 페이지) 확인, `acceptStatus: () => true`가 여전히 `recorded_pending`.
- L8에 변경 통지함(브라우저 경로가 acceptStatus에 의존했다면 이제 pending으로 남는다).
