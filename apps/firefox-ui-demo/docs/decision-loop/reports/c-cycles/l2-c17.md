## 1. run 도중 메시지 (표면 + 브리지)

**플래그가 켜졌을 때**
- 브리지가 capability `in-run-messages`를 알립니다.
- 표면: DM에 run이 하나 일하고 있고(멈추는 중이 아님) 열린 이른 질문이 없으면, 작성창이 글 메시지를 받습니다. 요청은 `/chat/send`에 `inRunMessageTo: <runId>`를 붙여 보냅니다.
  - 이른 질문이 열려 있으면 지금처럼 그 답(`inRunReplyTo`)이 우선입니다.
  - 첨부·프로젝트 선택이 있으면 지금처럼 턴을 기다립니다.
- 런타임(`acceptInRunMessage`): 그 run의 사람 메시지로 저장합니다.
  - 순서대로 저장하고 `message.completed`로 한 번 보여 줍니다(보낸 상태).
  - 같은 requestId가 다시 오면 메시지 하나로 처리합니다.
  - pending 큐에 넣고 하트비트에 바로 알립니다: `mark('user')`와 `nudge()`(다음 beat가 nudgeMs 안에 옴).
- **엔진에는 저절로 아무것도 가지 않습니다.**

**L3와의 계약** (런타임 주석 "Messages while a run works"에 적었습니다)
1. 읽기: `pendingInRunMessages(run)`는 `[{ requestId, text, at }]`를 오래된 순으로 돌려줍니다. text는 사람의 말 그대로입니다(judge용).
2. 결정: `settleInRunMessage(run, requestId, 'reply' | 'steer' | 'interrupt')`, 메시지마다 한 번.
   - `reply`: 하트비트가 직접 진행 답을 올렸습니다. 엔진에는 아무것도 가지 않습니다.
   - `steer`: 같은 native turn에 `turn/steer`(검증된 계약, `clientUserMessageId` = requestId)로 넣습니다.
   - `interrupt`: `interrupt()`, 즉 `turn/interrupt`로 멈춥니다. 멈춤 버튼과 같은 경로입니다.
   - 돌려주는 값: 결정한 값, `'failed'`(메시지는 pending으로 남음), 또는 `null`(모르는 메시지, 이미 결정됨, run이 끝남).
3. 잃지 않음: run이 끝날 때까지 pending이면, 그 대화의 다음 턴 입력 맨 앞에 사람의 말 그대로 들어갑니다(`turn/start` input, 순서대로, 한 번만). 대화를 삭제하면 버립니다.
- 하트비트의 facts/질문에 무엇을 어떻게 넣을지(진행 답 vs run에 넘김 판단)는 L3의 몫입니다. 저는 source facts를 바꾸지 않았습니다.

**플래그가 꺼졌을 때** (오늘과 같음)
- capability가 없으므로 작성창은 기다리고 아무것도 보내지 않습니다.
- `inRunMessageTo`가 붙은 요청은 저장 전에 409 `INRUN_MESSAGE_UNAVAILABLE`로 거부합니다. 필드가 없는 요청은 지금과 똑같습니다(일반 send는 `RUN_IN_PROGRESS`).
- 증거: 기존 스위트 1490개(surface-state, completed-messages, chat-choice, all-on journey의 all-flags-off byte identity, browser-task roundtrip, heartbeat session/flow, run-codex-bridge)가 0 실패입니다.

**테스트** (`scripts/egdesk-chat-completed-messages.test.mjs`, c17 7개. 실제 표면 코드를 vm에서 돌리고, 실제 런타임·HTTP·SQLite를 씁니다)
- 플래그 꺼짐: 작성창이 막히고 보낸 것이 없습니다. 이름 붙은 메시지는 409, 저장 없음, 엔진 호출 없음.
- 표면만 capability를 보고 브리지에는 플래그가 없을 때: 거부되고, 저장되지 않고, 말은 작성창으로 돌아갑니다(기존 문구).
- 켜짐: 메시지 두 개가 순서대로 저장되고 각각 한 번 보입니다. nudge가 2번 불리고, steer·interrupt·turn은 0입니다. 같은 요청은 하나, 다른 run 이름은 409입니다.
- 결정: reply는 엔진 호출 0입니다. steer는 정확한 `turn/steer` 파라미터로 갑니다. interrupt는 `turn/interrupt`이고 stopRequested가 섭니다. 메시지마다 한 번만 결정됩니다. 거부된 steer는 pending으로 남습니다.
- 잃지 않음: 다음 턴 input이 `[nudge, 새 메시지]`이고 그다음 턴은 `[새 메시지]`만입니다. 삭제하면 carried가 0이 됩니다.
- 이른 질문이 열려 있으면 여전히 `inRunReplyTo`로 답이 갑니다.
