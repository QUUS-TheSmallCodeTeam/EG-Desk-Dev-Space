## 1. 우선: 엔진이 편집을 "읽기 전용이라 못 한다"고 거절한 문제 (Main check-1: edit-undo, terse-yes)
- 원인 두 가지(가설이 아니라 설정 타입으로 확인한 것은 키의 존재와 의미, 실제 바이너리에서의 효과는 Main의 재실행이 확인함):
  1. Codex는 `<permissions instructions>` 개발자 블록을 넣어 읽기 전용 샌드박스와 승인 안 함 정책을 모델에게 설명함. 설정 키 `include_permissions_instructions`("Whether to inject the `<permissions instructions>` developer block", 0.171 `config.schema.json`). 이 블록은 Codex 자신의 도구에는 맞지만 `egdesk_*`에는 맞지 않음 → 스레드에서 **끔**.
  2. 모델에게 `egdesk_*`가 EG-Desk의 권한으로 동작한다고 알려 준 곳이 없었음. 0.171 `ThreadStartParams.developerInstructions`(string|null, 프로필 지침과 같은 필드)에 짧은 사실 블록을 넣음. 도구 설명을 고치지 않은 이유: 설명은 도구별이고 "엔진 자신의 도구가 꺼져 있다"는 스레드 수준의 사실이며, 도구 설명은 여러 계획과 테스트가 고정하고 있음. 지침은 `TurnStartParams`에 없어서 **스레드 시작과 모든 resume**에 넣음.
- 문장(모델용, `OWN_TOOLS_INSTRUCTIONS`, 약 800자): 자신의 shell/patch 도구는 꺼져 있고 이 세션의 읽기 전용 파일시스템 설정은 egdesk_* 도구에 적용되지 않음 / EG-Desk가 자신의 권한으로 사람의 프로젝트 폴더에서 파일과 명령 작업을 수행함: read와 search는 읽고, `egdesk_edit_file`은 바꾸고(문자열 교체, diff, 전체 쓰기, 삭제) **바로 적용하며** diff를 돌려주고 `egdesk_undo_edit`용 기록을 남기고, `dryRun`이면 미리보기만 함; `egdesk_run_command`는 명령을 실행함 / 도구 결과가 `needs_person`이면(위험한 명령, 파일 전체 삭제나 덮어쓰기) 자신의 말로 사람에게 묻고 턴을 끝내며 답이 올 때까지 같은 호출을 되풀이하지 않음.
- 프로필(Agent)이 있으면 그 지침이 먼저이고 이 블록이 뒤에 붙음. 프로필을 끈 경우(`profileEnabled:false`)에도 own tools에서는 **사람의 config.toml의 `developer_instructions`를 읽어 싣지 않음**(U11).
- **찾은 실제 결함(같이 고침)**: 저장된 own-tools 대화를 다시 열 때(`thread/resume`) 첫 resume에는 순수 엔진 스위치도, 격리도, 지침도 실리지 않았음(c18부터). 새 스레드와 모든 resume이 같은 `ownToolsThreadOverrides`를 쓰게 함. L7 c26이 첫 resume을 건너뛰는 최적화(`skipFirstResume`)를 넣은 것과 합쳐서, 건너뛰지 않는 경우에만 내 오버라이드를 싣도록 정리함.
- 테스트(가짜 app-server): `refuseEditsUnlessInstructed`로 Main이 본 거동을 모델링함(권한 블록이 켜져 있거나 지침이 없으면 편집을 "읽기 전용"이라며 거절하고 도구 호출 0회). 제품의 `thread/start`로 edit-undo 시작 스크립트가 통과하고(와이어 로그에 지침과 `include_permissions_instructions:false`), 같은 가짜와 스크립트에 c23 이전 `thread/start`(`downgrade`)를 쓰면 거절되어 점검이 실패한 턴으로 보고하고 파일은 그대로임(대조). 런타임 테스트: 새 스레드, Agent 지침 순서, 플래그 off, resume.
- 한계: 가짜는 가설일 뿐이므로 **실제 0.171에서 이 두 가지가 거절을 없애는지는 Main의 재실행이 확인함**. 안 없어지면 다음 후보는 `developerInstructions` 대신 `baseInstructions`(모델 기본 지침 자체를 교체)나 도구 설명 보강이고, 그때의 근거는 기록의 `posted`와 `thread/start` 응답의 `instructionSources`가 됨.

## 2. 0.171의 steer 계약: 버전 고정이 아니라 스키마 능력으로
- 현황: 제품의 steer 증명은 `boardPeerContract`였고, 코드는 그것을 `version === '0.162.1'`에만 인정함. 0.171.0-alpha.13의 실제 `TurnSteerParams`/`TurnSteerResponse`는 이미 `verifyBoardPeerSchema`를 통과함(스키마가 장애물이 아니고 고정이 장애물이었음, 테스트로 확인).
- 구현: `verifyTurnSteerSchema`(요청 합집합에 `turn/steer`가 있고, params 필수 항목이 `threadId, expectedTurnId, input`을 넘지 않으며(그 안에서만), 타입과 text 변형 `{type:'text', text, text_elements}`, 응답 필수 `turnId`)와 `optionalTurnSteerFingerprint`, `probeTurnSteerSchema`. `inspectNativeCapabilities`가 **그 바이너리 자신의 생성 스키마**로 `steerContract = sha256('steer', 버전, 바이너리 지문, 스키마 지문)`을 만듦(버전이 식별되는 어떤 바이너리든, 버전 목록과 무관, 삭제 능력과 같은 방식). 고정된 버전은 같은 probe에서 읽어 스키마를 두 번 만들지 않음. 프로필 앱서버는 자기 바이너리의 값을 가짐(`capabilitiesOf`에 `steer`, `steerContract`).
- 어댑터: `steerContract(slot)`와, `steerTurn`은 **평문 steer(`additionalContext` 없음)만** steer 증명을 받고, `additionalContext`가 있으면 기존 board peer 증명만 받음(보드의 신뢰 안 되는 문맥 계약은 그대로, 이번에 넓히지 않음). 어떤 증명이든 불일치면 `BOARD_PEER_UNSUPPORTED`.
- 런타임: 사람 메시지의 steer(`settleInRunMessage`)와 열린 질문에 대한 답(`answerEarlyQuestion`)이 `steerContract ?? boardPeerContract`를 씀(L4의 held 작업 분기에도 반영). 브리지: `getSteerContract: () => appServerReady ? nativeCapabilities.steerContract : null`. 효과는 `EGDESK_INRUN_MESSAGES`/conversationFlow 플래그 뒤에서만 나타남.
- 테스트(`egdesk-turn-steer-contract.test.mjs`, 실제 0.171 스키마 파일을 고정물로 둠): 검증기의 거절 15가지(필수 항목 추가, expectedTurnId 비필수, 타입 변경, text 변형 없음 등), 지문 변화, 버전/바이너리/스키마가 다르면 증명이 달라짐, probe 실패·예외·버전 불명·지문 불가면 증명 없음, 어댑터의 허용/거절 조합. 점검 도구의 `steer` 액션이 가짜 app-server에 대해 증명이 있으면 `turn/steer`를 보내 같은 턴 id를 받고, 없으면 `no_steer_contract`로 아무것도 보내지 않음(아래 5번).
- 한계: 스키마가 같다고 거동이 같다는 보장은 아님. 거동(같은 turnId, 진행 중인 턴의 userMessage로 보임, 모델이 따름)은 Main의 smoke-3이 증명한 것에 기대고 있고, 이 능력은 그 증거와 스키마 일치를 연결할 뿐임. 바이너리가 바뀌면(버전, 지문, 스키마) 증명이 바뀌어 다시 검증됨.

## 4. EG-Desk 자신의 모델과 effort (Main의 (a), U11)
- 규칙: 요청이 정한 것 > Agent 프로필의 모델 > **EG-Desk 자신의 설정** > (아무것도 없으면) 엔진 기본. own tools가 켜진 Codex 스레드에서만, 보호된(QA) 전송은 건드리지 않음. 사람의 `config.toml`의 model/effort는 쓰이지 않음(설정이 있을 때).
- EG-Desk 설정의 출처: 이미 있는 `EGDESK_CODEX_MODEL`/`EGDESK_CODEX_EFFORT`(실행 시작 인자 빌더와 같은 이름, 같은 검증 `egdeskCodexSelectionFromEnv`; 잘못된 값이면 배선이 실패함). 배선이 `ownTools.profile()`로 내놓고 런타임의 `modelSelection`이 쓰며 `thread/start`의 `model`과 `turn/start`의 `model`/`effort`로 나감(요청 모델 검증 `assertModelSelection`을 그대로 지남).
- 테스트: 우선순위 4단계, effort만 있는 경우, 플래그 off면 변화 없음, 아무것도 없으면 엔진 기본(공백을 숨기지 않고 보고), 환경변수 검증.
- **한계/결정**: 프로필 모델이 없는 사용자에게 줄 EG-Desk의 기본 모델/effort를 **어디서 정하는가**(화면 설정?)는 새 사용자 문구와 설정이 필요한 일이라 만들지 않았음. 지금은 개발 환경변수가 그 자리임. 안 정하면 사람의 Codex 기본(예: effort "ultra")이 그대로 쓰임.

## 5. 스크립트 형식: 액션 턴(L3와 합의), 확장 지점
- L3(QxHtYOPXD8yZaaW0)와 합의한 필드: 턴은 메시지 턴(`say`…) **또는** 액션 턴 `{ action: "interrupt" | "steer" | "delete", afterMs?, say?, expect? }`.
  - `interrupt`: 사람이 이전 턴의 실행에 정지를 누름(`chat.interrupt`), 이전 턴 시작 후 `afterMs`. 이전 턴의 expect에 `turnStatus: "interrupted"`, `posted: false`(완료된 에이전트 메시지만 게시되므로 부분 텍스트는 게시되지 않음, Main 실측).
  - `steer`: 이전 턴의 실행에 평문 `turn/steer`를 **제품의 어댑터와 이 바이너리의 steer 증명**으로 보냄(증명이 없으면 `no_steer_contract`, 아무것도 안 보냄). 사람 메시지 경로는 `whileRunning`이고 별개임.
  - `delete`: 이전 턴이 끝난 뒤 사람이 대화를 삭제(`chat.forgetConversation`), `expect.conversationGone`. 이후 메시지 턴은 **새 대화**(새 스레드, 기억 없음). 기록에 저장소 상태와 엔진 기록 처리(`engineHistory` state/reason)를 남김.
  - 규칙(검증기): 첫 턴 불가, interrupt/steer는 평문 메시지 턴 뒤에만(메시지 턴의 후속은 하나), steer는 say 필수, interrupt/delete는 say 불가, 액션 턴에 approve와 whileRunning 불가, afterMs는 interrupt/steer에만(0..120000), 암묵 검사 `action_taken`.
  - 같이 추가(L3 요청): `expect.commandsRanIncludes`/`commandsRanExcludes`(부분 문자열, 모델이 명령을 합칠 수 있어서). L3의 새 스크립트 `real-engine-pause-v1`(whileRunning, 이전 턴 상태 `interrupted`)은 이전 턴의 상태를 기록하는 기존 동작으로 충분함. 모든 스크립트(내 것, L3, L4, L7)가 최종 검증기를 통과함.
- 확장 지점 `deps.extensions = [{ name, setup(ctx) → { afterTurn?(record, info), finish?() } }]`: 런타임이 조립된 뒤 한 번 `setup`, 모든 턴 기록 뒤 `afterTurn`, 대화 끝에 `finish`(값은 `rec.extensions[name]`). 던지는 확장은 `{error}`로 기록될 뿐 점검과 판정을 바꾸지 않음. L4(briefing hook)와 L7(memory seeding)은 자기 모듈에서 이것만 쓰면 됨. 이번에 그들의 코드를 건드리지 않았고, 병합 때 L7이 이미 내 파일에 직접 넣은 memory hook은 그대로 둠.
- 가짜 app-server: `turn/interrupt`(진행 중인 턴을 `interrupted`로 끝냄), `turn/steer`(같은 turnId, 진행 중인 턴에 userMessage 항목), 턴 시작 시점에 진행 상태를 등록(점검의 interrupt와 경합하던 것을 고침). 프로토콜 부분집합에 `turn/steer` 추가. 간헐적으로 실패하던 타이밍 두 군데(위 경합, whileRunning의 400 ms 작업 시간)를 고쳐 5회 연속 통과함.
