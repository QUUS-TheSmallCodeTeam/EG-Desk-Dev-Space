## 1. heartbeat 판정이 작업이 실제로 하는 일을 보게 함 (R1)

**이전 상태.** 작업 중에는 엔진이 조용하므로 note 질문이 20초에 나옵니다. 그런데 judge가 받는 것은 closed label뿐이었습니다. "a task in the browser is still going", 끝난 step 수, 마지막 step 이후 경과 시간이 전부여서, 사실에 맞는 대기 메시지인지 막연한 메시지인지 judge가 구분할 근거가 없었습니다. 사이트를 언급하는 문장은 check에서 근거가 없다고 막혔을 것입니다.

**변경.**
- task store에 `brief(key)`를 추가했습니다(읽기 전용). 내용은 goal(사람이 쓴 그대로, 160자 제한), 카드 host, step 수, 마지막 closed 결과입니다.
  - 마지막 결과 값: started, opened_link, scrolled, filled_field. 멈춘 경우에는 그 pause code(choice_needed, confirm_needed, login_required, page_unclear 등)입니다.
  - 기존 `facts()`에는 여전히 내용이 없습니다(테스트로 확인).
- `egdesk-conversation-flow.mjs`의 `browserTaskLines(brief, allows)`가 줄을 만듭니다. 각 줄은 run의 egress gate를 통과할 때만 들어갑니다.
  - 항상 들어가는 줄(closed): `The task in the browser: N page steps so far; <TASK_LAST 문구>.`
  - `browser_task_record`가 허용될 때만: `The browser task's goal, as the person asked it: "…"`
  - `page_text`가 허용될 때만: `It works on the site <host>.` 형식이 맞지 않는 host는 넣지 않습니다.
  - 요소 라벨, 경로, URL, 페이지에서 읽은 텍스트는 절대 들어가지 않습니다.
- 같은 줄이 세 곳에 들어갑니다.
  - judge 문맥(`runContext`). 선언 kinds에 `browser_task_record`와 `page_text`가 추가되고, heartbeat judge가 run의 gate로 다시 검사합니다.
  - check의 근거(`messageEvidence`). 그래서 "포털에서 사업자 선택 화면을 보고 있습니다" 같은 사실 문장이 통과할 수 있습니다.
  - writer 프롬프트(`writerPrompt`의 `task`): "이 사실로 작업이 무엇을 하는지 말해도 되고, 없는 것은 덧붙이지 말 것"이라고 지시합니다.
- 비용: beat 요청 하나에 약 275 bytes, 약 55 토큰이 늘어납니다(`evidence/l8-c18/brief-size.json`).

**제품 경로 테스트** (`codex-chat-browser-task-roundtrip.test.mjs`): Main의 all-on 페이지에서 s10/s11 실제 답을 그대로 재생했습니다.
- **B1**: s10(.70 분포)에서 코드가 두 사업자로 `choice_needed`를 냅니다. 20초 beat의 judge 문맥에는 "1 page step so far; it stopped to ask the person which of several options they mean", goal, host가 들어갑니다. writer 프롬프트에도 같은 줄이 들어갑니다. 주소, 경로, 사업자번호는 들어가지 않습니다.
- **B2**: s10에서 질문하고, 런 안에서 "두 번째 사업자로"로 답하면, s11([L2] 1.0, 다운로드 .99)을 거쳐 done이 됩니다. 루프 중간의 beat 문맥에도 goal이 있습니다.
  - 작업 하나당 Decision 요청 수(실측 아님, 스크립트 기준):

    | 구간 | entry | step | resume | heartbeat beat | 합계 |
    |---|---|---|---|---|---|
    | 질문 전 | 1 | 1 | – | 1 | 3 |
    | 작업 전체 | 1 | 4 | 1 | 1 | 7 |

  - check 요청은 0건입니다. 대기 문장에 구체적 주장이 없어서입니다. writer는 엔진의 private fork 1회이고 Decision 요청이 아닙니다.

## 2. step 단위 보정 기록 (결정 5)

- step마다 기록 하나를 남깁니다(`feature: browser_reflex`).
  - `next_step`: 물었을 때만 남깁니다. 기록으로 코드가 정한 step은 묻지 않으므로 없습니다. 값은 would, top, second, confidence, margin, options 수, threshold .75, minMargin .2입니다.
  - page-state predicate 6개: p, threshold .7, would(act / none / hold)
  - `goal_met`: p, threshold .85
- 모두 closed 단어와 숫자입니다. raw 기록에 페이지 텍스트, 라벨, 주소가 없음을 테스트로 확인했습니다. Main이 추가한 `ps_*` 어휘가 실제로 기록되는 것도 확인했습니다.
- same-thing predicate(`same_N`)는 보정 어휘에 없어서 기록하지 않습니다. 필요하면 어휘 추가가 필요합니다.
- 기존 S8 테스트는 entry 기록 1개를 셌습니다. 이제 entry와 step 기록 2개를 세고, step 기록의 내용 없음도 확인합니다.

## 3. 사람에게 질문한 뒤에는 대기 메시지를 얹지 않음

- 기존에도 질문이 게시되면(`asked`) heartbeat는 아무것도 묻거나 말하지 않았습니다(`waiting_user`).
- 빈틈이 하나 있었습니다. 질문을 작성하는 동안(handing_off) beat가 대기 메시지 작성을 시작하고, 그 사이 질문이 먼저 게시되면 대기 메시지가 질문 **위에** 붙을 수 있었습니다.
- 수정: `postIntermediate`에서 게시 직전에 다시 확인합니다. 작업이 멈춰 있고 질문이 이미 게시됐으면 게시하지 않습니다.
- 테스트 **B3** (choice_needed, confirm_needed, login_required, page_unclear 각각):
  - writer를 붙잡아 둔 채 질문을 먼저 게시하고, 그다음 writer를 풀어 줍니다. 게시된 것은 질문 하나뿐이고, 이후 60초 동안 판정도 메시지도 0건입니다.
  - 게시 직전 확인을 끄면 네 경우 모두 실패합니다. 이 확인이 규칙을 지키는 것임을 확인했습니다.
- 해석과 결정 사항: 질문이 게시되기 **전**의 대기 메시지는 지금처럼 허용합니다. H1의 "작성이 느린 경우 설명 한 번"입니다. 이것까지 막을지는 결정이 필요합니다.

## 4. 다른 레인 영역에 닿은 것

- **L3 c15 규칙 정밀화** (H1, N1 테스트): 기존 assertion은 "heartbeat 질문에 페이지 내용이 없음 (`/portal|example|https?:|\d{3}-\d{2}-\d{5}/`)"이었습니다. Main의 이번 지시로 host가 `page_text`로 들어가게 되어, 다음과 같이 바꿨습니다.
  - 주소, 경로, 페이지 숫자는 계속 금지합니다(`/https?:|\/invoices|\/biz\/|\/download|\d{3}-\d{2}-\d{5}/`).
  - host는 자기 `page_text` 줄에서만 허용합니다. 그 줄 밖에서 host가 나오면 실패합니다.
  - `page_text`가 허용되지 않는 run에서는 host가 나오지 않음을 단위 테스트로 확인했습니다. L3에 알려야 합니다.
- **`egdesk-conversation-flow.mjs`(L3 영역)**: 추가만 했습니다. `browserTaskLines`, `TASK_LAST`, 그리고 `workLines`, `runContext`, `messageEvidence`, `writerPrompt`에 선택 인자를 더했습니다. brief가 없으면 동작은 이전과 같습니다.

## 5. 결정이 필요한 것

1. 질문이 게시되기 전(작성 중)의 대기 메시지를 계속 허용할지, 막을지.
2. 사용자 문구는 추가하지 않았습니다. 문장은 주관 모델이 씁니다. `TASK_LAST`의 영어 문구는 judge, writer, check에만 쓰고 사람에게 보이지 않습니다. 확인만 필요합니다.
3. same-thing predicate(`same_N`)를 보정 어휘에 추가할지.
4. beat 요청당 약 55 토큰 증가를 받아들일지.
