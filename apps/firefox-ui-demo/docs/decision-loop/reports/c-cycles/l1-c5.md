## 3. 막힐 수 있는 지점
- **S1 (DM에 단서 없음):** 키가 없고 모드가 끔이면 DM 어디에도 결정 모델의 존재나 미설정 상태가 보이지 않는다. 유일한 진입점은 설정 > 계정 > 결정 모델이다. `[보기 추천]`이 빠지면 키가 없다는 안내를 DM에서 받을 길이 없다. (제품 결정 필요, 수정 안 함)
- **S2 (후보가 없으면 요청도 없음):** 모드 사용 + 키 저장 후에도 **선택할 후보(선택한 자료, 허용된 이전 발언, Board, 온톨로지 항목)가 하나도 없으면 turn-start Decisions 요청은 나가지 않는다**(`NOCANDIDATES`: provider key_check 1 그대로, 구독 turn은 정상, 활동 행도 없음). 사용자는 "모드를 켰는데 아무 일도 안 일어난다"고 느낄 수 있고 화면에서 그 이유를 볼 수 없다. 이 테스트의 주 여정은 온톨로지 항목 1개가 있는 사용자를 가정한다. (설계상 의도로 보이며 안내 문구만 부족. 수정 안 함)
- **S3 (모드 켜기 발견성 - 수정함):** 키 저장 후 결과가 "확인됨"뿐이고 모드는 계속 끔이라 쓰이지 않는데 어디서 켜는지 안내가 없었다. 키 저장 직후 같은 섹션의 `끔/기록만/사용`으로 이어지는 단서가 필요했다. 아래 5절 패치.
- **S4 (첫 열기 때 입력칸 비활성):** 설정을 처음 열면 상태 GET이 끝날 때까지 키 입력칸이 비활성이고 안내 문구가 "확인할 수 없음 · 브리지 연결이 준비되면 다시 확인합니다."다. 몇 ms 뒤 활성화된다. 막히지는 않는다.
- **S5 (모드 설명과 실제 동작의 간격):** 모드 `사용` 문구는 "선별에 성공하면 허용된 선택 자료를 답변 입력에 붙입니다."라 후보가 있는 요청에만 해당한다는 점은 S2와 같다.
- 막히지 않음을 확인: 잘못된 키는 저장되지 않고("키가 올바르지 않습니다 · 키를 저장하지 않았습니다.") 입력칸이 비워진다. 크레딧 없는 키는 저장되고 경고 문구가 나온다. 켜 둔 상태에서 공급자 429가 나도 구독 turn은 그대로 진행되고 활동 행이 "컨텍스트 세팅 · 결정 모델 응답 없음"(reason no_credit)로 남는다. 재시작 뒤 키/모드는 디스크에서 복원된다.
