## 1. A6: 기본 로그인이 바뀌어도 다른 Engine Profile 방의 진행 중 작업은 끊기지 않음
- 창의 `resetThreadConversations`(기본 계정 변경과 기본 로그아웃이 모두 부름)는 먼저 `ChatState.codexDefaultSwitchKeeps(threads, state.codex)`로 창이 아는 **기본 외 Codex profile**의 방을 고른다.
  - 그런 방이 있으면 기존의 부분 초기화 경로(Claude 방을 남기던 경로)를 쓴다.
  - 남는 방은 요청(`protocol.requests`), run, 사용자 입력 초안, 바인딩, 방 자체가 그대로다(detach하지 않음).
  - epoch는 `reset('codex', 'codex-default')`만 한다. 기본 profile과 기록되지 않은(legacy) token만 끝나고, profile B의 token은 유효하며 abort되지 않는다(`createChatEpochScope`의 profile 단위 세대를 그대로 씀).
  - 기본 방은 지금처럼 요청과 run이 지워지고 detach·보류된다.
  - 다른 profile 방이 없으면 지금과 똑같은 전체 초기화다(테스트로 고정).
- 이벤트 스트림 재연결은 Claude 방이 이미 겪는 것과 같다. 스트림을 닫고 다시 연결해도 남는 방의 요청·run 기록은 유지된다.
- 창이 모르는 profile id의 방은 지금 규칙을 따른다(지워지고 보류됨).
- run 단위 조작 중 profile 없이 시작하는 token(`epochScope.begin('codex')`: 중단·조정 요청 등 일부)은 legacy로 취급돼 지금처럼 끝난다. 진행 중 B run 자체와 그 요청은 남는다.

## 2. A7: 분기와 Briefing 의견은 방 자신의 profile 계정으로 확인
- `chatForkAvailability(thread, { …, engines })`: 기본 외 profile 방은 그 profile의 로그인과 계정으로 판단한다. `canResumeNativeThread`에 문맥을 넘긴다. 창은 `engines: state.codex.engines`를 넘긴다. 문구는 기존 그대로다.
- `createBriefingCommentScope`: 계정 울타리를 `ChatState.codexRoomAccountCurrent(thread, authStatus, cachedDefault, context)`로 바꿨다.
  - 기본 외 profile 방은 그 profile 계정 키를 쓴다.
  - 기본 방은 지금처럼 현재 기본 로그인 키이면서 창이 캐시한 기본 키와 같아야 한다.
  - 생성 시점과 `current()` 양쪽에 적용했다.
  - B 계정이 바뀌면 범위가 끝나고, 요청은 "브리핑 연결이 바뀌었습니다"로 거부된다.

## 4. Main에게: 소유자 결정 5건 (쉬운 시나리오)

**결정 1. Agent에 지정한 계정과 방의 계정이 다를 때**
- 하는 일: '분석 담당' Agent는 계정 B를 쓰도록 저장돼 있다. 사람이 계정 A로 시작한 방에서 이 Agent를 골라 메시지를 보낸다.
- 지금: 보내지지 않고 "다른 계정을 지정한 Agent이니 Agent 선택을 바꾸거나 새 대화를 시작하라"는 오류가 난다.
- 추천대로라면: 그 방은 계속 계정 A로 답한다. Agent에 저장한 계정 B는 그 Agent로 **새 방을 시작할 때만** 쓴다. 사람이 이 방을 B로 바꾸겠다고 직접 고르면, 같은 방에서 일이 이어지고 다음 실행부터 B로 돈다.

**결정 2. 방의 계정을 바꾼 뒤 무엇이 따라가는가**
- 하는 일: 사람이 계정 A의 방에서 일하는 중이다. 동료가 부탁한 일이고, Agent가 "이 명령을 실행해도 될까요?"라고 물었는데 아직 답하지 않았고, 입력창에 쓰던 글이 있다. 이때 이 방을 계정 B로 바꾼다.
- 지금: 방이 멈춘다("이 방을 시작한 계정과 현재 계정이 달라 이어서 보낼 수 없습니다"). 새 방을 만들어야 하고, 새 방에는 대화도 쓰던 글도 가져가지 않는다.
- 추천대로라면: 같은 방에서 이어 간다. 사람과 대화에 속한 것(누가 부탁했는지, 아직 답하지 않은 질문, 쓰던 글, EG-Desk가 기억하는 내용)은 따라온다. 계정 A 쪽에 남은 엔진 자체의 대화 기록은 A에 그대로 두고, B의 첫 실행은 EG-Desk가 가진 맥락으로 시작한다.

**결정 3. 기본 계정을 바꾸면 작업 목록이 지워지는 문제**
- 하는 일: 사람이 여러 단계의 작업 계획을 진행하는 중이다. 다른 일 때문에 기본 로그인을 다른 계정으로 바꾼다.
- 지금: 작업 목록, 제안된 계획, 이어 하기·승인 대기 상태가 모두 사라진다.
- 추천대로라면: 작업 목록은 남는다. 어떤 작업을 다시 시작할 때 그 작업이 돌던 계정이 아직 로그인돼 있는지만 확인하고, 아니면 그 작업만 그렇다고 알린다.

**결정 4. Claude 방에서 폴더를 바꿀 때**
- 하는 일: 사람이 Claude와 폴더 X에서 일하다가, 같은 방에서 폴더 Y를 고르고 계속 말한다.
- 지금: "Claude 대화는 시작한 폴더를 유지하니 다른 폴더는 새 대화를 시작하라"는 오류가 난다.
- 추천대로라면: Codex처럼 파일·명령 작업을 EG-Desk 자체 기능이 고른 폴더에서 하게 해서, 같은 방에서 폴더를 바꿔도 이어 가게 하는 것을 검토한다. 결정 전까지는 지금 안내를 유지한다.

**결정 5. Desk 창을 두 개 열었을 때**
- 하는 일: 동료가 부탁한 일을 사람의 Agent가 하는 중이다. 사람이 Desk 창을 하나 더 열어 같은 방을 이어서 본다.
- 지금: 두 번째 창은 누가 부탁했는지 모른다. 그 창에서 새 작업 화면이 열리면 동료 쪽이 아니라 그 사람이 부탁한 것처럼 그 사람 근처에 놓인다. 알림 메시지 쪽은 bridge가 알고 있어 그대로다.
- 추천대로라면: 두 번째 창도 bridge에서 누가 부탁했는지 읽어, 두 창이 같은 자리에 놓는다. 창을 하나만 쓰기로 하면 지금 그대로 둔다.
