## 1. "ㅇㅇ"의 courtesy가 .66으로 나온 이유

- 본문을 보면 직전 답은 "…다음은 **7번(효과 미리보기)** — 코일 before→after로 payoff 선지급. **계속 갈까요?**"로 끝납니다. **예/아니오로 답하는 질문**입니다. 그러니 "ㅇㅇ"는 이 질문에 대한 답입니다.
- 그런데 courtesy 질문의 문구는 "thanks, a greeting, **an acknowledgement** or other social small talk, with no question, request, report or decision in it?" 입니다. 질문에 대한 "예"를 acknowledgement로 읽을 여지를 남깁니다. 직전 메시지를 보여주자 .99에서 .66으로 내려가긴 했지만, 문구가 그 해석을 막지 않았습니다.
- **수정 (R4, bar는 그대로)**: 직전 메시지가 함께 들어갈 때만 courtesy 질문 끝에 한 문장을 붙입니다.
  > A short yes, no or go-ahead that answers a question or a proposal in the assistant's message (for example "ㅇㅇ" or "네" after "계속 갈까요?") is an answer that decides something, not a courtesy.

## 2. "좋다. 다음 진행"의 record가 .95로 나온 이유

- 직전 답은 "…이 버전 어떠세요? **OK면 이 완성 수준을 기준으로 8번 갑니다.**"로 끝납니다. 사람은 승인만 했습니다.
- record 질문("a new fact, **a decision**, a plan…")은 판단 대상을 사람의 진술로 한정하지 않습니다. 그래서 모델이 assistant가 설명한 버전 내용까지 사람이 내린 결정으로 기록할 만하다고 읽은 것으로 보입니다. 직전 메시지의 내용이 사람의 진술처럼 섞여 들어간 셈입니다.
- **수정**: 직전 메시지가 함께 들어갈 때만 record 질문 끝에 한 문장을 붙입니다.
  > Judge only what the person's own message states: the assistant's message is context for what the person answers, never part of the person's statement. Agreeing to, approving or saying go ahead to what the assistant proposed ("좋다", "ㅇㅇ", "다음 진행") is not a record by itself.
- 직전 메시지가 없으면 두 질문 모두 바이트 단위로 예전과 같습니다. 공백만 있는 메시지도 "없음"으로 처리합니다. 둘 다 테스트로 확인했습니다.
- 다시 만든 두 본문을 c26에서 보낸 본문과 비교했습니다. input은 같고, courtesy와 record 두 질문의 끝에 붙인 문장만 다릅니다 (`evidence/l7-c23/terse-ab.txt`).

## 3. 문구를 predicate별로 고르기 (v1/v2)

### 수치 (c23의 v1 답, c26의 v2 답; `per-predicate.txt`)

조합 32가지를 모두 계산했습니다.

| predicate | 요청별 v1 → v2 |
|---|---|
| other | c22 .73 → 0 |
| own | c22 .62 → 0, c12 .68 → .19, c02 .23 → 0, c10 .58 → .16 |
| guess | c01 .66 → 0, c10 .71 → .01 |
| before | c01 .56 → .98, c26 .75 → .96 |
| now | c32 .35 → .13, c37 .77 → .39, c30 .65 → .30 |

- 모든 predicate에서 **v2가 v1보다 같거나 낫습니다**.
- v2를 하나라도 v1로 바꾸면 결과가 나빠집니다. 예를 들어 own을 v1으로 되돌리면 c02를 잃습니다 (.23은 undecided).
- **c10은 v1에서도 split 판정으로는 설치되지 않았습니다** (own .58, guess .71). 그러니 "c10을 잃게 만든 predicate"는 v1에 없습니다.
- 실제 제품에서는 c10이 2단계의 첫 단계인 axes 질문에서 record_based .93으로 이미 설치됩니다 (c24). 두 번째 요청까지 가지 않습니다.
- 그래서 Main의 규칙("guard를 잃지 않은 곳에서만 v2")을 수치대로 적용하면 **다섯 predicate 모두 v2**입니다.

### 구현

- `SPLIT_WORDING_CHOICE = { other: v2, own: v2, guess: v2, before: v2, now: v2 }`.
- `splitWording`에 객체를 넘기면 predicate마다 버전을 고를 수 있습니다. 객체에 이름이 없는 key는 v1입니다.
- `'v2'`는 이 선택표를 가리키며, 지금은 모든 predicate를 v2로 고릅니다. 기본값은 계속 v1입니다.
- 이미 보낸 split-wording-v2 플랜의 본문은 지금도 같은 바이트로 다시 만들어집니다 (테스트).

### own v3 후보 (측정 전용)

- v2에서 c12는 .19, c10은 .16으로 no bar(.15)를 아주 조금 넘었습니다.
- v3는 두 가지 제외 사항을 그 표현을 실어 나른 한국어 형태로 명시합니다.
  - 읽어서 안 것: "메일 보니까", "주문 내역을 보니", "기록상"
  - 결론: "~걸 보니 ~것 같아"라면 문장이 주로 말하는 것은 결론이고, 화자가 그 결론을 직접 본 것은 아님
- 객체 선택(`{ own: 'v3', ... }`)으로만 쓸 수 있고, 아래 플랜으로 측정합니다.
