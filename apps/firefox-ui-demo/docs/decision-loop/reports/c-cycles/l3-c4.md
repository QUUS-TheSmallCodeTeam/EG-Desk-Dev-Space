## 4. 캐논 불일치와 조치
1. **턴 시작 맥락이 on에서 시작해 off/advisory/키 삭제로 바뀐 뒤에도 결과를 붙임**(재현: `before-ctx.log` `mid-flight on->off`, `on->advisory`, `on, key deleted` 모두 `attachedInTurn:true`). 원인: `prepareDecisionContext`가 시작 시점의 모드를 캡처(`codex-chat-runtime.mjs:4002`)하고, 이후 `decision?.mode === 'on'`(:2274)로 그대로 붙이며 제출 직전(`narrowDecision`, :2478)은 개인 이력 묶음(grant) 경로만 재검사했다. "on은 허용된 자료를 붙인다 / off는 아님 / advisory는 기록만"이 진행 중 변경에서 깨짐(P4: 소유자가 끈 뒤에도 결과를 따름).
   - 수정(`codex-chat-runtime.mjs` +27, `egdesk-context-setup.mjs` +12): 결정 결과에 설정 세대를 같이 저장하고, 제출 직전 `on`+키+세대가 그대로인지 확인. 아니면 **모델이 고른(scored) 자료는 붙이지 않고**, 사용자가 직접 지정하거나 앱이 핀 고정한 로컬 자료(`mandatory`/`locallyForced`, 모델 판단이 아님)만 `localOnly()`로 남기며, 그것도 없으면 기록만으로 내림(활동 행 `기록만`). 개인 이력 묶음이 있는 결과는 기존 grant 가드를 그대로 따름(기존 W3 시험 계약 유지; 처음 시도에서 이를 깨뜨려 `egdesk-memory-evidence-wiring.test.mjs` 1건이 실패해 범위를 좁힘).
   - 이후(`after-ctx.log`): on→off, on→advisory, 키 삭제 모두 `attachedInTurn:false`, 기록만 행. advisory→on도 기록만 유지.
   - 한계: 제공자 호출은 이미 일어났으므로 되돌릴 수 없고(비용·전송), 활동 행은 그 호출을 기록만으로 남긴다.
2. DM 선택은 advisory에서 호출하지 않는다(off와 동일). 캐논이 선택 추천의 advisory를 정의하지 않고, 추천 자체가 화면 결과라 "기록만"으로 남길 대상이 없음. 불일치로 보지 않고 **문서 공백**으로 표시(설정 화면 advisory 설명은 "지원되는 요청에서 ... 보낼 수 있습니다"라서 DM 선택은 해당하지 않음). 수정 안 함.
3. 반사의 on→advisory 진행 중 변경이 시험에 없었음 → `codex-browser-reflex-dispatch.test.mjs`에 `advisory`, `late-advisory` 케이스 추가(+8 시험 항목, 모두 통과). 제품 코드 변경 없음.
- Board, 반사: 재현된 불일치 없음.
