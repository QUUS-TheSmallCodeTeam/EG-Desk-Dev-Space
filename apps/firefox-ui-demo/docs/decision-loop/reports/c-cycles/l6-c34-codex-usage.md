## 1. 어떻게 셌나 (기준)
1. 단위는 기록 파일 하나 = 대화 하나 = 앱서버 한 번 실행(재시작이 있으면 +1). 스레드·fork·턴 수는 기록의 `requests`(엔진 요청 목록)에서 셉니다.
2. **모델 호출 수** = 엔진이 보낸 `thread/tokenUsage/updated` 알림 수(호출마다 한 번; smoke 로 검증: 도구 라운드 2번 + 최종 답 = 3). 이 값이 기록된 서브턴은 138개(40%). 나머지는 기록된 것에서 구한 평균으로 추정: 도구 0개 1.31호출, 1개 2.03, 4~5개 4.3~4.7, 12개 이상 4(여러 도구를 한 라운드에 부름), 내부 턴은 1호출씩 더함.
3. **입력 토큰** = 모델 호출 수 × 그 서브턴 기록의 마지막 호출 입력 토큰(`usage.input`; 기록된 `usage`는 마지막 호출 값입니다). 한 턴 안에서 문맥은 조금씩 커지므로 이 추정은 몇 % 높게 나옵니다. 캐시 입력도 같은 방식. 기록 없는 턴(시간 초과)은 평균 12.6k 입력.
4. 시각은 대화 시작 시각(UTC → KST).
5. 셀 수 없는 것: Codex 홈에 쌓인 사람의 별도 사용, 다른 도구의 사용, 한도 계산에 쓰이는 모델별 가중치. Codex 홈은 읽지 않았습니다(개인 대화가 있을 수 있어서).

## 4. 한도를 몇 % 썼나: 말할 수 있는 것과 없는 것
- **없는 것**: 사용률 값. 계획은 "prolite", 주간 창 11-23 15:32 ~ 11-30 15:32(KST), 100% 확인 시각 19:30 (Main). 공개 자료에는 주간 한도의 절대 크기가 없습니다. 모델은 `gpt-6-astra`(내부 턴 기록)로, OpenAI 도움말상 Plus 에서 5시간 창당 5~45개 로컬 메시지가 추정치입니다(Pro 100 은 제3자 자료로 Plus 의 약 10배, 주간 한도 크기는 비공개).
- **범위만**: 루프는 6.1시간 동안 사람 메시지 328 + 내부 턴 34 = 약 360개를 보냈고 시간당 약 59개, 5시간당 약 300개입니다. Plus 의 5시간 창 추정(5~45)에 Pro 100 배율(약 10배)을 곱한 50~450개/5시간 안에 있습니다. 즉 루프의 속도는 이 계획이 한 번에 쓸 수 있는 크기 근처이고, 그 속도를 6시간 유지했습니다. 주간 한도가 5시간 창의 몇 배인지는 비공개라 점유율은 계산하지 않습니다. 사용자 본인의 다른 사용량은 이 기록에 없습니다.

## 6. 앞으로의 실제 실행 예산 규칙 (권장)
1. **배치 전후로 사용률을 읽는다**(Main 이 `account/rateLimits/read`): 주간 사용률, 5시간 창(있으면), 크레딧 잔액을 배치 기록에 적는다. 이제 점검 도구가 대화마다 같은 값을 기록하므로(7절) 전후 차이가 곧 배치 비용입니다.
2. **배치 상한을 호출 수로 정한다**: 시작 전 "대화 수 × 대화당 모델 호출(참고: 평균 3.0) "을 선언한다. 지금까지의 배치는 시간당 40~50대화(약 120모델 호출, 입력 190만)까지 갔습니다. 보정 전까지 **배치당 20대화 / 60 모델 호출 / 비캐시 40만 이하**로 시작한다.
3. **주간 사용률로 닫는다**: 보정(첫 배치의 사용률 증가분 ÷ 호출 수)이 나오면 배치당 **주간의 2% 이하**, 하루 **10% 이하**. 주간 **70%** 에서 실제 엔진 실행은 사용자 확인 뒤에만, **85%** 에서 중지(남은 15%는 사용자의 몫).
4. **정지를 경보로 쓴다**: 한 배치에서 180초 정지나 fork 정지가 **2건** 나오면 그 즉시 배치를 멈추고 사용률을 읽는다(오늘은 정지가 0건 → 24건으로 갑자기 늘었고 16:47 이후 3시간을 더 돌았습니다).
5. **같은 세트 반복 금지**: 같은 입력의 반복은 증거가 아니라는 c23 규칙과 같습니다. 재실행은 코드나 입력이 바뀐 뒤에만. (심은 초안은 이미 두 번.)
6. **무거운 세트는 따로 선언**: fork·새 스레드를 쓰는 세트(심은 초안, 고쳐 쓰기)는 비캐시가 큽니다. 한 배치에 하나만.
7. **한 대화에 턴을 모은다**: 앱서버 실행·스레드 시작 자체는 토큰이 없지만, 턴마다 문맥(약 12.6k)을 다시 보냅니다(캐시 80%). 같은 방에서 이어 보낼 수 있는 시나리오는 한 대화로.
8. **효과 있는 순서로 돌린다**: 결정 모델 호출(별도 과금, 한도와 무관)로 먼저 확인하고, 엔진 실행은 그 뒤 필요한 것만.
9. **크레딧을 기록한다**: 한도에 닿은 뒤 실행은 크레딧을 쓸 수 있으니, 100% 이후에는 실행 전 사용자 승인 필수.
