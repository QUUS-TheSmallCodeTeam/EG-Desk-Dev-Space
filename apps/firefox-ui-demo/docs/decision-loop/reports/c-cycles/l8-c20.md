## 2. 버튼: 코드가 읽기 전용임을 증명할 때만 누름 (결정 1)

- **Firefox 자식** (`EGDeskBrowserAgentRuntimeChild.navigationFacts`)은 판단 없이 사실만 보고합니다.
  - 버튼의 type
  - 민감 영역 여부(`[data-sensitive]` / `[data-private]` 안인지)
  - 가장 가까운 영역의 이름
  - form 제출 버튼이면: method, 필드 종류, 민감 필드 여부, **GET 제출이 실제로 불러올 URL**(이름 있는 필드 중 활성이고 체크된 것과 제출 버튼 자신의 name/value를 브라우저 순서대로 넣은 값)
  - form 밖 버튼이면: `aria-controls`가 가리키는 패널의 텍스트
- **증명** (`readOnlyPress`):
  - (a) 같은 사이트로 가는 GET form 제출: 안전한 필드만 있고, 민감 필드가 없고, 목적지의 단어 분류가 none이어야 합니다. 실행은 **그 URL로 navigate**합니다. GET 링크와 같은 위험 등급입니다. 문서가 바뀌는 click은 runtime readback이 확인할 수 없어 카드가 uncertain 상태로 잠기기 때문에 click을 쓰지 않습니다.
  - (b) 보기만 바꾸는 버튼(`type=button`이나 `role=tab`, 패널 텍스트 있음): visible-text 사후조건이 붙은 click입니다.
  - 공통 조건: 민감 영역이 아니어야 합니다. 영역 이름이 결제/청구/권한/동의/개인정보/비밀번호/인증/보안/로그인 어휘이면 제외합니다(fail-closed).
- **look-alike, 모두 사람에게 남음**(표 테스트 16행):
  - POST "조회" form
  - 비밀번호 필드가 있는 form, 이메일 필드가 있는 form
  - 외부 사이트로 가는 action, delete 어휘 목적지, 목적지 미계산
  - 결제 정보 / Billing / 권한 설정 / 보안 설정 영역 안의 버튼, data-sensitive 영역 안의 버튼
  - form 안의 `type=button`, form 밖의 submit 버튼
  - 사실을 보고하지 않는 이전 runtime의 버튼
  - 빈 패널 탭, reset 버튼
  - "결제하기"는 form 종류와 상관없이 제시되지 않습니다.
- task 기록: 누른 버튼은 `actions.press`로 셉니다. GET 이동은 trail에 남습니다.

## 3. 기록에 링크 주소의 숫자 (결정 2)

- 기록 줄에 고른 링크 주소(경로와 쿼리)의 식별번호(8~20자리 숫자, 최대 3개)를 덧붙입니다: `선택: 배송 조회 @ /orders [choice_needed] #202611190042`. 옛 형식의 줄도 그대로 읽힙니다.
- `sameByCode`: 양쪽 모두 식별번호가 있으면 **라벨이 같아도 식별번호로 판정**합니다. 그래서 "배송 조회"가 두 줄 있어도 주소 번호로 구분되고 코드가 맞는 줄을 고릅니다. 번호가 없으면 지금처럼 어느 줄인지 묻습니다.

## 4. 노트에 상태 문장 (결정 3)

- 작업이 끝나면 코드가 마지막 페이지의 보이는 텍스트에서 작업의 식별번호를 찾습니다. 식별번호는 정해진 선택, 기록, 이번에 연 링크 주소에서 가져옵니다.
- 찾은 텍스트 조각과 그 뒤 두 조각(합계 240자 이내)을 노트의 `found`에 넣습니다. 예: `["주문 2026-1119-0042", "휴대폰 케이스", "배송 상태: 배송 중 (…)"]`
- 식별번호가 없으면 넣지 않습니다. 코드는 추측하지 않습니다.
- run의 egress가 `page_text`를 허용할 때만 넣고, 기본은 꺼져 있습니다(`pageTextInNote`).
