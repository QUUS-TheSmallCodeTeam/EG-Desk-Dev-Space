## 1. 행동 먼저 (소유자 정정 U13: 결정 모델의 자리는 행동 층)
- `EGDESK_DECISION_FIRST=on` (기본값) = 결정 모델이 명령을 고름 → 코드가 EG-Desk 러너로 실행 → **엔진 한 번**(결과 블록 `egdesk_command_result`가 문맥, 도구 호출 불필요, "말은 엔진이") + 그 명령의 터미널 카드가 엔진 런에 표시. 건강/실패/충돌 모두 이 길(reason `healthy` | `result_for_engine`, path `action`). 승인이 필요한 명령(`needs_person`)·고르지 못함·임계값 미달 등은 예전처럼 엔진 길.
- `EGDESK_DECISION_FIRST=card` = c32의 "카드만, 말 없음"(건강하면 로컬 턴 종료). **[제안, 승인 필요]**: 코드가 게시한 결과는 대화 층 지름길. 그 외 값은 꺼짐(`ON`, `yes` 등).
- 구현 메모: 카드 알림은 디스패치 중 `pending.buffer`에 쌓이므로 버퍼 비우기 **앞**에서 낸다(뒤에서 내면 카드가 사라졌음: 시험이 잡음).

## 4. 정지 감시 수정 (check-29st 실제 정지)
- check-29st `watchdog-armed` turns[1]: `thread/status` 2 + `turn/started` + user message 항목 시작/완료가 **2 ms 안에** 오고 그 뒤 180초 침묵(`firstEventMs` 2) → 첫 이벤트 규칙이 서문으로 만족되어 감시가 안 울림.
- 수정: **진행(progress)** = 그 턴의 이벤트 중 `turn/started`와 사용자 메시지 항목 이벤트를 뺀 모든 것(어시스턴트·추론 항목, 델타, 도구 호출, 승인, 완료). 서문만 보인 채 N초면 인터럽트 후 한 번 재시작(그때까지 아무것도 실행되지 않았으므로), 진행이 한 번이라도 있으면(도구 호출 포함) 건드리지 않음. 부작용: 인터럽트된 턴의 사용자 메시지 항목이 엔진 스레드 이력에 한 번 더 남음.
- 점검 도구: 턴 기록에 `firstProgressMs`, `expect.engineStall.maxFirstProgressMs`, 가짜 엔진 `silentPreamble`(실제 정지 모양 재현). 시험: 서문 뒤 침묵 → 재시도 성공, 두 번이면 `ENGINE_STALLED`, 한도 안의 추론/도구 호출은 건드리지 않음.
- **N**: 서문 시간(0~8 ms)은 쓸모없음. 건강한 7턴의 전체 지연 p99(최대) 7.06 s → 진행 시간의 상한으로 보고 `N = max(15, ceil((3×7.06+5)/5)×5) = 30 s`. 스크립트 무장값을 30초로. 한계: 높은 effort에서 조용히 30초 넘게 생각하면 오탐 재시도 → EG-Desk가 쓰는 effort로 `first-event-times`를 다시 돌려 `firstProgressMs` p99로 확정.
