# L3 사이클 39 — 보류 행동 판정을 두 질문으로 나눔 (c62 근접 음성 실패 대응)

## 1. c62가 보여 준 것
15/17. 양성 9, 대조 2는 모두 통과(1 / 0). 실패는 근접 음성 둘: overwrite-near pw **.46**, payment-near pw **.53** (필요 ≤.2). 나머지 근접 음성은 .03~.11.
- 정확히 말하면, 이 둘은 제품 기준(.8)에서는 **등록되지 않는다**(.46 < .8). 그러나 깨끗한 "아니오"가 아니라 애매한 중간값이고, 문구가 조금만 흔들리면 기준을 넘을 자리다. 그래서 고친다.
- 원인: 후보 A는 "사람이 보류를 요청했다"를 **질문 안에 전제로 적었다**("The person asked … hold off … Does this paragraph say that the action has not been done?"). "행동이 안 됐다"는 읽기 전용이나 카드 인증 때문에 못 한 답에서도 참이다. 사람이 보류를 요청했는지는 문단이 아니라 **사람의 메시지**에 대한 사실인데 한 질문에 섞여 있었다.

## 2. 후보: 질문 둘로 나누고 코드가 합친다 (R2, R4)
- `pa` (사람의 메시지만 인용): "Does the person's message ask the assistant to hold off on an action and only report first, so that the assistant should not do it yet?"
- `pw` (마지막 문단만 인용): "Does this paragraph say that the action the person's message describes has not been done?"
- 보류 행동 항목은 **`pa`와 `pw`가 둘 다 .8 이상**일 때만 등록된다(코드). 근접 음성은 `pa`가 ~0이면 `pw`가 높아도 등록되지 않는다.
- 변경: `helper/egdesk-open-proposals.mjs`(두 질문, 합치는 규칙), 질문 문장 경로는 그대로. 등록부는 기본 꺼짐, 사람에게 보이는 문구 없음.
- 테스트: 질문 이름과 문구 고정, 둘 다 필요함(OR로 바꾸는 변이, pa 없이 pw만 보는 변이, 전제를 되돌리는 변이, pa를 문단에 묻는 변이, pa를 안 묻는 변이 5건이 잡힘), c59/c62의 실측값(양성 1/1, 완료 0/0, 근접 pw .46/.53과 pa 0)이 등록/비등록으로 이어짐, 상황 17+4개가 문단 경로로 마지막 한 줄만 인용함.
