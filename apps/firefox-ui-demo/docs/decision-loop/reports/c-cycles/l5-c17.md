**Codex 자체 실행 도구 끄기**

- **apply_patch는 설정으로 끌 수 없음(a0d5b0a6 기준)**: `spec_plan.rs:1390`은 `model_info.apply_patch_tool_type.is_some()`일 때 등록함. 이 값은 모델 메타데이터(`protocol/src/openai_models.rs:462`)이고, `models-manager/src/model_info.rs:19` `with_config_overrides`는 context window, 압축, 출력 한도, 지침만 덮어씀. 그래서 순수 엔진 모드에서는 **read-only 샌드박스 + `approvalPolicy: never`**로 apply_patch가 쓰지도 묻지도 못하게 해야 함(`pureEngineThreadOverrides()`. 아직 연결하지 않음).

**그 모드에서도 Codex가 스스로 하는 일(정직하게)**
- 선택한 구독 계정으로 모델을 호출하고, 그 계정의 인증을 갱신함(CODEX_HOME = 계정의 자격증명 저장소. 소유자 원칙에 맞게 "계정 plane"으로만 씀. canon §14.1 "각 구독 account가 격리된 App Server runtime/config/credential store").
- 대화 기록(rollout)을 CODEX_HOME에 저장하고, 문맥 압축, memories(EG-Desk는 이미 `features.memories=false`)를 함.
- 설정 레이어를 읽음: System(`/etc/codex`), User(CODEX_HOME), 신뢰된 Project `.codex`, 관리형 requirements(c16, discovery.rs:157). EG-Desk 소유 홈에는 사용자 `mcp_servers`나 훅이 없음. 하지만 **공유 기본 app-server는 사람의 `~/.codex`를 씀**(`egdesk-native-capabilities.mjs:64-67` 주석). 그래서 원칙을 지키려면 기본 Codex도 EG-Desk 소유 홈으로 옮겨야 함(결정 2).
- thread `cwd`: 셸이 꺼져도 Codex는 cwd를 환경 문맥으로 모델에 보내고, 그 경로에서 `.codex` 프로젝트 레이어와 AGENTS.md를 찾음. 폴더와의 결합을 끊으려면 Codex에는 EG-Desk 소유의 **중립 폴더**를 cwd로 주고, 실제 폴더는 EG-Desk 도구만 알게 하는 방법이 있음(결정 3. 프로토타입 실행기는 이미 Codex cwd를 쓰지 않음).
- apply_patch 시도는 모델 메타데이터에 있으면 남음(위). read-only + never이면 실패로 끝남.

**미확인**: dynamic tools의 안정성(실험적 API), `project_doc_max_bytes=0`의 정확한 의미, 신뢰되지 않은 폴더의 `.codex` 설정 레이어를 Codex가 읽는지(문서는 신뢰된 레이어만이라고 하지만 설정(훅 아님) 쪽의 코드 줄은 확인하지 않음), 읽기 전용 + never에서 apply_patch가 모델에게 어떻게 보고되는지. 모두 실제 실행 없이 소스만 읽고 내린 판단임.

**canon이 이미 정한 것(인용)**

## 3. 설계(시나리오)와 프로토타입 `helper/egdesk-command-executor.mjs`
**시나리오**
1. 사람: "고친 거 강제로 올려줘."
2. 엔진(모델)이 `egdesk_run_command`(임시 이름, 승인 필요)를 `{command: "git push --force origin main"}`으로 부름.
3. EG-Desk 실행기가 **실행 전에** 승인 장부에 물음 → 바닥(remote_irreversible)에 해당 → 실행하지 않고 도구 결과로 `{status:"needs_person", reasons, options:["run","cancel","give_context"], next:"ask_user_in_chat", retry:"same_command_after_yes", executed:false}`를 돌려줌.
4. 모델이 대화에서 사람에게 자기 말로 물음(U4).
5. 사람이 "응, 해"라고 답함 → 다음 턴 시작 전에 런타임이 그 답을 yes/no 술어 둘로 읽음 → 그 턴에 **그 정확한 명령만** 한 번 승인함.
6. 모델이 같은 명령으로 다시 부름 → 실행기가 **EG-Desk가 이 Run에 정한 폴더**에서 runner로 실행 → 결과(exit code, stdout/stderr 꼬리, 잘림 여부)를 모델에게 돌려줌.
7. 그동안 terminal facts(c10 row, kind `objective`)가 `gate/waiting_user` → `running/objective_step` → `idle`로 나감.
8. `npm test` 같은 무해한 명령은 묻지 않고 바로 실행함.

**규칙**
- 판단 순서: 바닥(R5) → 술어(그 Run의 게이트와 egress, `gateHookAssess`) → 그 턴의 한 번만 쓰는 승인 → 한 번에 하나씩(c14, c15 규칙).
- **샌드박스가 없으므로 더 엄격하게**: 무언가를 바꾸거나 보내는 명령인데 판단할 수 없으면(키 없음, Decision off, 모델 오류) 실행하지 않고 사람에게 물음(`risk_unsure`). 승인 카드 경로에서는 Codex 샌드박스가 그런 명령을 제한했지만 여기서는 그렇지 않음. 읽기만 하는 명령은 판단 없이도 실행함.
- **정체성**: 장부는 대화와 턴, 그리고 정확한 명령과 폴더로 키를 만듦. 실행기는 엔진 프로필, 구독 계정, CODEX_HOME, 화면을 읽지 않음. 폴더는 `workspaceOf(run)`(EG-Desk의 Board와 프로젝트 binding)으로만 정하고, Codex thread cwd를 쓰지 않음. 폴더 밖 cwd와 폴더 없음은 거부함. bounded/QA Run은 실행하지 않음.
- 같은 native 호출이 두 번 와도 한 번만 실행함(callId 기준).
- `pureEngineThreadOverrides()`: `{ sandbox:'read-only', approvalPolicy:'never', config:{ features:{ shell_tool:false, unified_exec:false, view_image:false }, web_search:'disabled', project_doc_max_bytes:0 } }`. **연결하지 않음.** 연결하면 Codex가 파일을 수정할 수 없게 되므로, EG-Desk 자체 편집 도구(OpenCode의 edit, write, patch에 해당)가 먼저 있어야 함(결정 1).

**테스트** `helper/egdesk-command-executor.test.mjs`(10개, 모의 runner):
- off이면 도구를 제공하지 않고 실행 0회.
- 표: 바닥 10개와 술어 위험 3개는 needs_person이고 runner에 닿지 않음. 무해한 명령과 유사 명령 8개(`rm -rf node_modules`, `rm -rf build/`, `npm test`, `npm publish --dry-run`, `git clean -n`, `git reset --soft`, `docker ps`, `git status`)만 실행됨.
- 대화의 yes → 다음 턴에 그 정확한 명령이 한 번 실행됨. 명령을 바꾸거나 재사용하면 다시 물음. no이면 실행 0회.
- 판단할 수 없는 상황: 바꾸는 명령은 사람에게 묻고, 읽는 명령은 실행함. 오류도 같음.
- 정체성: 프로필, 화면, Codex cwd가 달라도, CODEX_HOME이 이상한 값이어도 결과가 같음. 폴더 밖, 폴더 없음, QA는 거부함.
- facts 세 단계의 row.
- 순수 엔진 overrides의 형태.
- **실제 런타임**: on일 때만 thread/start `dynamicTools`에 포함됨. `item/tool/call`이 실행기에 닿음. 위험 명령은 needs_person, `npm test`는 실행됨. 턴이 끝나고 사람이 "yes, force push it"이라고 보내면 다음 턴의 같은 호출이 실행됨(approvedOnce). 실행 폴더는 EG-Desk 폴더이고 엔진이 보고한 cwd가 아님.
- **off일 때 기존 경로가 그대로임**: provider가 있든 없든 thread/start와 RPC 호출이 바이트 단위로 같고, 엔진의 승인 요청은 지금처럼 카드가 됨.

## 4. 기존 경로에 생기는 변화
- **플래그 off(기본)**: 바뀌는 것이 없음(위 동등성 테스트). Codex 자체 셸 명령, 엔진 명령 감시(c8, c10, 기록만), 승인 카드와 게이트(c11, c12, c13 결정 3), 묻지 않고 실행된 명령의 기록(c12)이 모두 지금과 같음.
- **플래그 on(실행기만)**: 엔진에 EG-Desk 명령 도구가 추가됨. Codex 자체 셸은 아직 켜져 있으므로 모델이 둘 다 쓸 수 있음. 이 상태에서는 기존 카드와 감시 경로가 Codex 셸 명령에 대해 그대로 동작함. 완전한 전환은 `pureEngineThreadOverrides`를 연결해야 끝남(결정 1). 그때 엔진 명령 감시와 승인 카드는 Codex 명령이 없으므로 할 일이 없어짐. 대신 실행기의 facts와 결과가 그 자리를 채움.
- c8 엔진 명령 감시(상태 판정)를 실행기 출력에도 붙이려면, 실행기가 출력을 RunOutputStore에 넣고 같은 감시를 `engine:'egdesk'`로 먹이면 됨(미구현. 닫힌 어휘에 'egdesk'를 추가해야 함).

## 5. 결정 필요
1. **완전한 순수 엔진 전환**(`pureEngineThreadOverrides` 연결): 그 전에 EG-Desk 자체 파일 읽기와 편집 도구가 필요함(Codex의 apply_patch는 설정으로 끌 수 없어서 read-only + never로만 막을 수 있음). 순서와 범위.
2. **기본 Codex도 EG-Desk 소유 CODEX_HOME으로**: 지금은 공유 app-server가 사람의 `~/.codex`(설정, mcp_servers, 훅, 신뢰한 프로젝트)를 씀. 원칙을 지키려면 계정 로그인을 소유 홈으로 옮겨야 함.
