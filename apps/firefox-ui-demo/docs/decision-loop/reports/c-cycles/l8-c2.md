## 2. 문제 (정확한 값과 위치)
- **P1 (실제 결함)**: `egdesk-browser-reflex.mjs:127`(수정 전) `classify({ label: element.label ... })`가 링크의 label만 판정한다. `egdesk_browser_navigate`는 runtime의 `GATED_TOOLS`(`egdesk-browser-tool-runtime.mjs:339`: click, pointer_click, type)에 없어 runtime도 거르지 않는다. 그래서 label이 "Continue"(분류 none)이고 href가 `https://example.test/account/delete?id=7`인 동일 사이트 링크가 후보가 되어 confidence 0.99면 navigate 1회가 실행됐다. 분류기는 "account delete"는 delete, "checkout pay"는 pay로 판정한다(합성 프로브). 정책 §5.2는 동일 사이트 링크 자동 이동을 허용하지만 삭제/결제 경로의 GET까지 허용한 것은 아니다.
- 관찰(수정 안 함): (c)에서 navigate가 stale로 거부되면 결과가 `max_steps`로 나와 마지막 실패 코드가 모델에 전달되지 않는다. 다음 스텝에서 새 관측으로 다시 판단하므로 안전하며 같은 코드 2회 연속이면 중단된다. next_step이 임의의 act일 때 대기 중 값의 필드 매핑이 실행되는 설계(`runBrowserReflex` 매핑 블록)는 별도 검토 대상으로 남긴다.

## 3. 근거
- 캐논: `DECISION_MODEL_CONTEXT_SETUP.md:18` "확률은 실행 권한이 아니다. 실행 가능 여부는 기존 classifyAction·URL 정책…", `:19` 실패 시 기존 방식으로 복귀, §3.3(:125) 브라우저 반사. 확신도 0.99도 href가 삭제 경로면 권한이 아니므로 후보 단계에서 classifyAction이 다시 판정해야 한다.
- 외부: OWASP LLM06 Excessive Agency의 "Complete mediation: 하위 시스템에서 모든 요청을 정책으로 검증, LLM 판단에 의존 금지"와 "Require user approval" — https://genai.owasp.org/llmrisk/LLM06:2025-Excessive-Agency . OWASP AISVS C9.2.1 비가역 행동은 사람 승인 전 차단 — https://github.com/OWASP/AISVS/blob/main/1.01/en/0x10-C09-Orchestration-and-Agentic-Action.md . Chrome agent 보안 가이드의 "도구는 상태를 바꾼다고 가정" — https://developer.chrome.com/docs/agents/security .
- 결정에 미친 영향: LLM06 complete mediation이 "label뿐 아니라 실제 이동 목적지(href)를 분류기에 통과시킨다"는 수정 방향을 정했다. 같은 출처가 오탐 시 fail-closed(후보 제외, 추론 모델이 처리)를 택하게 했다. 나머지 (a)(b)(c)(e)(f)는 기존 가드가 충족해 외부 자료가 코드 변경을 만들지 않았다.
