# L8 C44: 순서 응답("두번째")을 기록된 후보에 코드로 해석 + 단계 측정 계획

- 브랜치 `lane/c44-ordinal-step` (기준 int/c14 `21caac8`). 커밋 `18f4c5f`(해석기, 후보 기록, 엔트리 연결, 테스트, 측정 사전 등록), 이어서 측정 모듈 커밋. 작업트리 깨끗. 게이트는 최종 답에 기록.
## 1. 원인과 수정 (행동 층, U13 정정: 코드가 계산할 수 있는 것은 코드에서)
V4(c63): "두번째"가 재개를 올바르게 읽었지만(`task_resume`), 다음 단계 요청에는 가공 없는 "두번째"와 페이지 텍스트만 있고 **무엇을 물었는지와 후보 순서**가 없어서, 올바른 요소 `[L2] 사업자 987-65-43210`을 0.60(기준 0.75 미만)에 골랐고 루프는 같은 질문을 다시 했습니다(안전한 결과이지만 사람이 한 말이 소용없어짐). 같은 페이지에서 "두 번째 사업자로 해 줘"는 0.98.
수정(제품):
1. 일시정지가 `choice_needed`일 때 질문한 후보를 **노트의 순서 그대로** 작업에 기록(`task.askedCandidates`, 최대 3개, 라벨에서 `[L1]` 접두 제거).
2. 응답이 **순서 표현 하나뿐**이고 목록에 있으면 코드가 해석(`helper/egdesk-browser-choice-reply.mjs`, `resolveChoiceReply`): 첫번째/첫 번째/첫째/1번/1번째/1/처음, 두번째/둘째/2번/2, 세번째/셋째/3번, 마지막/맨 마지막. 명사(사업자, 거, 항목...), 조사(로, 요...), 정중한 동사(해 줘, 할게요...)가 뒤따라도 됨. 단계의 사용자 맥락 줄: `Chose "사업자 987-65-43210" (option 2 of the options the person was asked to choose between, in this order: 1. ... / 2. ...); the person said: 두번째`.
3. 코드가 풀 수 없으면(위/아래 거, "2번 말고", "두번째 말고 첫번째", 다른 말이 섞임, 목록 밖 순서, "이번", 빈 문자열, 후보 1개) **아무것도 추측하지 않고** 단계에 질문한 목록을 순서대로 붙여 모델이 판단: `<응답>\n(The person had been asked to choose between, in this order: 1. ... / 2. ...)`. 확인(후보 하나)과 자유 입력 등 다른 일시정지는 이전 그대로.
- 테스트(`egdesk-browser-choice-reply.test.mjs` 5건): 흔한 표현 전부, 추측하지 않아야 하는 표현 20가지(null), 맥락 줄, 엔트리 흐름(후보 기록, "두번째"가 이름으로 단계에 도달, 사용 후 비움, 풀 수 없는 응답은 목록과 함께, 확인과 자유 입력은 그대로).
## 2. 측정 (먼저 재기: Decisions만, 보내는 것은 Main)
`scripts/egdesk-ordinal-step-plan.json`(사전 등록 `18f4c5f`, 측정 모듈 전): 제품의 실제 단계 요청(포털 고정 페이지 /invoices 위의 objective step, 대역 클라이언트로 포착해 그대로 전송; **줄만 다름**, 줄은 제품 함수가 만듦) 네 가지: bare(옛 줄, V4의 0.60 확인용), code(제품이 지금 "두번째"에 보내는 해석된 줄), list(코드가 못 풀 때 모델이 보는 질문 목록과 "두번째"), below("아래 거" + 목록). 판정은 코드(`readChoice`, 제품 기준 확신 0.75, 마진 0.2): 원하는 사업자 수락 = correct, **다른 사업자 수락 = wrong**(다른 사업자 송장을 엶), 기준 미만 = safe_miss.
- 사전 예측: 정답 3/4(2~4), wrong 0일 확률 .90; bare 0.35 correct, code 0.93, list 0.80, below 0.55. 결정 규칙: list가 correct이고 bare가 아니면 부족했던 것은 질문 목록이고 코드 해석은 안전한 지름길; bare도 correct면 c63은 변동이고 수정은 무해; code가 correct가 아니면 해석된 줄의 문구를 바꿈.
- 예산: 요청당 단계 요청이 약 1.65~1.69k 토큰(choice + predicate 7개 + 페이지 텍스트)이라 4개는 6.7k로 5k 상한 초과. 사전 등록 삭제 순서(below, bare): 기본은 **code와 list 두 개**(추정 3,356, 실제 약 3.5k). bare 값은 V4가 이미 측정(0.60). 4개 전부는 `--budget 6800`이 필요하나 하드 상한은 5000(올리려면 소유자 비용 승인).
