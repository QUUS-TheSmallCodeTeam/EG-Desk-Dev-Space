## 2. 설계 (리뷰 그대로: 명시 대상 우선, 추천 도착만으로 실행·포커스 전환 없음)
- **무엇을 정하나**: 실행이 아니라 **목록에서 어느 행이 강조되는가**뿐이다(U1: 시스템 결정; 행 자체는 런타임이 이미 만든 것, U2). 사람은 지금처럼 Enter로 확정한다(UX-01 키보드 경로).
- **1단계, 코드(R3)**: 모델 호출 없음.
  - 주소는 웹 행(지금 규칙 그대로).
  - 열린 카드·방·Board 하나와 **이름이 정확히 같으면** 그 행.
  - `/`로 시작하거나 명령 줄 모양(프롬프트 기호, `./`, 흔한 CLI 첫 단어, `&&`/`|`, 플래그)이면 **인식만** 하고 오늘 그대로 둔다(이 칸에는 slash 명령도 터미널 행도 없다. 소유자 결정 §6).
- **2단계, 후보는 지금 있는 행에서(U2)**: 말을 내보내도 되는 열린 카드(배치와 같은 maySend 규칙: 게시된 결과 카드의 제목과 첫 글), 웹 행, 요청 행. 최대 카드 4개.
- **3단계, 판단(R1/R2/R4)**: 입력을 한 번 인용하고 후보마다 예/아니오 하나를 묻는다.
  - `goes_to_I#`: "이 항목을 열거나 그리로 가라는 입력인가?" 항목은 그 질문 안에 인용한다(묶음 lint 통과).
  - `web_search`: 웹 검색인가.
  - `assistant_request`: 어시스턴트에게 하는 질문이나 요청인가.
- **4단계, 코드가 순위(R2)**: 카드 하나만 예이고 나머지 카드가 모두 아니오면 그 카드다. 아니면 요청 행과 웹 행 중 정확히 하나만 예이고 다른 하나가 아니오일 때 그 행이다. 그 밖(둘 다, 미결정, 실패)은 오늘 강조를 유지한다. 막대는 .8/.2이다.
- **안전 규칙**: 어떤 행도 실행·열기·전송·포커스 이동을 하지 않는다.
  - "on"이면 강조만 옮긴다. 조건은 세 가지다: 입력 글자가 그대로이고, 사람이 ↑/↓·마우스로 강조를 직접 옮기지 않았고, 목록이 열려 있을 것. 그렇지 않으면 답을 버린다.
  - 강조가 옮겨진 뒤 **300 ms(반응 시간) 안의 Enter는 사람이 보던 행**을 실행한다.
  - "advisory"는 기록만 한다(내용 없는 기록: 규칙, 행 종류, 적용 여부).

## 3. 데이터가 나가는 문제 (중요, U9)
- 칸에 친 글자는 **아직 어디에도 보내지 않은 글**이다. 범위 칩도 "이 기기에서 먼저 찾습니다…"라고 약속한다. 지금 어떤 구조도 어떤 모델에게 이 글을 보여 주도록 허용하지 않는다. U9(결정 모델은 다른 모델과 같은 허용, 별도 동의 없음)와 egress 테스트("nothing here can be opened for Decisions alone")가 결정 모델 전용 허용을 금한다.
- 처음엔 전용 스위치를 넣었다가 이 불변식에 걸려 **되돌렸다**. 그래서:
  - egress kind `hud_text`를 등록했다(`EGRESS_SITES['egdesk-hud-routing.mjs'] = ['hud_text', 'canvas_text']`). 그 class는 모델 data class가 아니라서 **모든 게이트가 거부**한다.
  - 제품에서 "on"이어도 bridge는 `not_allowed`를 돌려주고 요청은 0, 창은 오늘 강조를 유지한다(테스트로 고정). **코드 규칙(주소, 정확한 이름)은 지금 동작한다.**
  - 모델 단계는 구현하고 테스트했다(`FUTURE_PERMISSION` 게이트를 주입해 미래의 허용을 가정). 소유자가 "모든 모델에 적용되는" 허용을 정하면 켜진다.
- 실측(Main 전송)은 합성 글을 보내는 측정이라 이 제품 허용과는 별개다.

## 8. 소유자 결정
1. **칸에 친 글을 모델에 보내도 되는가**(모든 모델에 같은 허용, U9). 지금 칩 문구는 "이 기기에서 먼저 찾습니다"라고 약속한다. 허용하지 않으면 코드 규칙만 동작한다. 추천: 칸에서 Enter 전에 보내지 않는 지금 약속을 유지하고, 허용한다면 Decisions만이 아니라 Agent 요청 행과 같은 범위로 정한다.
2. **명령 줄 모양 입력의 목적지**: 터미널 행을 새로 둘지, 요청 행(Agent가 EG-Desk 명령 도구로 실행)으로 보낼지, 지금처럼 둘지. 추천: 터미널 행을 두되 실행은 터미널에서 사람이 한다. 문구 승인이 필요하다.
3. **"허용 command"의 범위**: 이 칸에 등록할 EG-Desk 액션(slash 명령, 팔레트)이 있는가. 지금은 없다.
4. **강조가 제안으로 옮겨졌을 때 비시각 안내 여부**(UX-01).
5. **말을 내보내도 되는 카드 범위**: 지금은 게시된 결과 카드만(maySend). Browser 탭 제목이나 파일 이름 같은 다른 카드 이름도 묻게 할지.
