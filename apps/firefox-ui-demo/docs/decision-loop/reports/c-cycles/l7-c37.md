# L7 c37: prefetch (U13 R-B: 결정 모델이 읽을 것을 고르고 코드가 읽어 엔진 턴에 같이 준다)

기준: int/c14 = 07d8cec (c36은 아직 합쳐지지 않음: 합치면 `TURN_MEMORY_FLAGS` 줄과 그 테스트 두 곳이 겹칠 수 있고, 둘 다 그대로 남기면 됨). 실제 전송과 실제 엔진은 돌리지 않았습니다 (Main 실행).

## 1. 만든 것 (기본 꺼짐: `EGDESK_TURN_MEMORY_PREFETCH=files`)
- 턴 시작에 **코드**가 엔진이 일하는 폴더의 읽기 후보를 만듭니다 (`helper/egdesk-prefetch.mjs`): 텍스트 계열 확장자만, 최근 변경 순 최대 60개, 폴더 3단계, 파일당 100 KB 이하, 점 폴더·node_modules·dist 등 제외, 심볼릭 링크와 빈 파일 제외. 각 파일이 선택(selection) 후보가 됩니다 (id `workspace:<경로>`, 카탈로그 줄은 **경로 + 크기 + 날짜만**).
- **결정 모델**이 기존 관련도 기계(turn_context, 바 .5)로 고릅니다. 바 아래는 아무것도 붙지 않고 엔진은 지금처럼 읽습니다.
- 고른 파일은 **코드가 읽어** (실경로가 폴더 안, 목록 뒤 바뀌지 않음, NUL 바이트 없음, 24 KB까지) 엔진 턴 컨텍스트의 선택 항목으로 줍니다 (항목당 6,000자 한도; `EGDESK_TURN_MEMORY_ENGINE_CONTEXT=split`이면 4,000바이트 이하 항목들로 나뉘어 한 항목이 엔진 한도에 잘리지 않음: c32/c33). `PRUNE_HELD`가 켜져 있으면 이미 이 대화에 준 파일은 바뀌지 않는 한 다시 묻지 않습니다 (선택 후보에 delivery key가 있는 무보호 문서).
- **데이터 규칙**: 결정 모델이 보는 것은 파일 이름·크기·날짜 목록뿐이고 파일 **내용은 엔진에게만** 갑니다. 이 목록은 새 egress 종류 `workspace_names` (데이터 클래스 `files`)로, 엔진이 읽는 폴더가 묶인 실행에만 열립니다 (Agent 천장이 terminal과 files를 둘 다 `none`으로 닫았으면 열지 않음). 결정 모델은 엔진과 같은 데이터 공유 권한을 따른다는 규칙 그대로입니다. 새 권한이나 설정은 없습니다.
- 하지 않은 것: 테스트·명령 실행(R-B의 `npm test`)은 승인 정책이 걸린 일이라 이번에는 파일 읽기만 했습니다. 폴더 목록 자체를 답으로 게시하는 직접 응답형(S3 t1)도 새 문구 문제가 있어 하지 않았습니다.

## 2. 테스트
- `helper/egdesk-prefetch.test.mjs` (5개): 목록의 범위(확장자, 제외, 링크, 크기, 단계, 60개, 최근순), 읽기의 안전(바뀐 파일, 폴더 밖 링크, 이진, 없는 파일, 24 KB 상한), 후보의 모양(무보호, 카탈로그에 내용 없음), **런타임 통과** (결정 모델 대역이 경로를 말한 파일만 고름: 고른 파일의 내용이 엔진 턴에 있고, 다른 파일은 카탈로그 줄로만 결정 모델에 가며 내용은 가지 않음; 플래그 끔: 후보가 없음), egress 규칙 (닫힌 천장, 열린 천장, 폴더 없음, 플래그 끔).
