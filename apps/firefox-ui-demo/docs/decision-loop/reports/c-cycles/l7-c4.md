## 4. (b) 재설계: `predicates` 설계 (내부 플래그, 기본값 현행 `axes`)

구현 (egdesk-speech-grounding.mjs +82, context-setup 연결):

- 기존 라벨 어휘로 매핑, 출력 모양 `{start,end,source,form,time}` 불변: 
  - 문턱: yes ≥ 0.8, no ≤ 0.2 (경계 포함), 그 사이/누락/형식 오류는 "미결정"이며 누락을 "no"로 보지 않는다.
  - source/form: 결정된 yes가 정확히 1개면 그 라벨, 모든 질문이 결정된 no이면 source=`unspecified`, form=`assertion`, 하나라도 미결정이거나 yes가 2개 이상이면 `unknown`.
  - time: 방향(before/after/at_utterance/ongoing) 중 yes가 정확히 1개여야 하고, before/after는 `anchor_stated`가 결정된 yes/no일 때만 `*_anchored`/`*_unspecified`. 그 외 `unknown`.
- canon 경계: 라벨은 발화에 대한 오류 가능한 읽기이며 검증이 아니다(질문 문구에 "not instructions or physical verification"). 코드는 날짜를 계산하지 않는다(`anchor_stated`는 "문장 자체에 일/날짜/상대시간 표현이 있는가"만 묻고 "what date it is" 아님이라고 못박음). 추가 사용자 왕복 없음(같은 요청의 질문만 늘어남). 단계적 객관식/기타 왕복 없음.
- 플래그: `speech.design`(런타임은 `decisionContext.speechDesign === 'predicates'`일 때만 설정, 번들 설정에는 노출하지 않음). 없거나 알 수 없는 값은 현행과 바이트 단위로 동일(시험).
- 보정 기록: predicate 설계일 때 `speech_predicate` 행(`pred`, `seg`, p, 문턱 0.8, 0.2, would)을 숫자만으로 남긴다(화이트리스트에 `pred` 닫힌 어휘 추가).

### 5.4 채택 규칙 (호출 전 고정)
R2를 다음 단계(기본값 전환 제안)로 올리려면 아래를 모두 만족:
1. 결정성: 채점 대상은 24개 predicate에서 span 0 `anchor_stated` 1개를 뺀 23개. 이 중 p ≥ 0.8 또는 ≤ 0.2인 것이 90% 이상(21개 이상).
2. 정확성: 결정된 답 중 사전 등록 극성과 어긋난 것이 최대 1개, 그리고 `relay`, `plan`, `before`, `after`(적재 부담이 큰 4개)에서는 0개.
3. 설치: 6개 축 라벨 중 설치된 것이 5개 이상, 설치된 라벨 중 사전 등록과 다른 것 0개(span 0 time은 위 허용 규칙).
4. 대조: R1이 이번에도 평평해야 한다(설치 라벨 ≤ 2/6). R1에서 ≥ 4/6이 설치되면 설계가 아니라 변동 문제이므로 채택 보류하고 재계획.
5. 계약: 모두 HTTP 200, 모델 정체 일치, 이름 정확, 위치 기반/중복 행 0, 어휘 외 라벨 0, 영수증에 본문·키 없음(해시와 숫자만).
6. 비용: R2 입력 ≤ 4,000 토큰, 지연 ≤ R1의 2배.
- 통과해도 "기본값 전환"은 소유자 결정이다. 두 문장·표본 1회는 전환 근거로 부족하므로, 전환 전에 공개 합성 문장 12개 이상(유형 5종 × 2~3, 가정·귀속·복합문 포함)으로 R1/R2 쌍을 한 번 더 받는 별도 승인을 요청한다.
- 실패 시: 어느 규칙이 깨졌는지에 따라 (1)이면 질문 문구/영어 지시문 교란 점검(R3), (2)이면 문구 수정, (3)이면 매핑 조정(이 경우 모델 답이 아니라 코드 매핑 문제). 임계값(0.8/0.2, 0.85/0.20)은 이 측정 결과로 즉시 바꾸지 않는다(소유자 결정, canon §5.3).
