## 2. 더 큰 발견: check-31pr의 "2/2 PASS"는 제안 등록을 검사하지 않았다
- 31pr의 턴 기록에는 `proposals` 기대도 `proposals` 기록도 없다. 스크립트는 `expect.proposals`를 선언했는데 평가되지 않았고 결과는 ok였다.
- 원인(내 c33 버그): 훅을 **async `finishTurn`**으로 썼다. 체크는 `finishTurn`을 동기로 읽으므로 기록과 기대가 Promise였고 아무도 읽지 않았다. 비동기 대기는 `afterTurn`이 맡는다.
- 고침: `afterTurn`으로 옮김, 기대가 선언됐는데 평가할 수 없으면 `proposals.evaluated`가 **실패**한다, 디스패처가 Promise를 돌려주는 `finishTurn`을 **거부**한다(다른 훅의 같은 실수도 막는다).
- 테스트: 디스패처를 통과하는 훅 테스트 6건(플래그 없고 기대 없는 대화는 훅이 아무것도 더하지 않음 포함), 그리고 체크 전체를 가짜 app-server로 돌려 실제 스크립트의 terse-yes 대화에서 `turn.proposals`가 기록되고 `proposals.kinds`, `proposals.stepsAtLeast`, `proposals.none`이 **평가되는지** 보는 end-to-end 2건(결정 모델이 "아니오"면 대화가 실패함도 확인). 변이 11건이 잡혔다(옛 버그를 되살리는 변이 포함).
- 31pr에서 등록 자체가 동작했는지는 **확인된 바 없다**(기록이 없다). 다만 c56의 pw .56과 31pr 엔진의 "아직 수정하지 않았습니다" 사이에 같은 상황의 말투 차이가 있다는 것은 확인된다.

## 3. 보류 행동(pw) 문구의 증거 계획 `pw-wording-c36` (Main이 전송)
현재 문구 "…Does this paragraph report that and leave the action itself waiting, not done, for the person's go-ahead?"는 한 질문에 세 가지(보고했다, 행동이 안 됐다, 승인을 기다린다)를 묻고, 인용된 문단("파일은 변경하지 않았습니다.")에는 마지막이 없다. 후보 두 개:
- **A** (조건 하나, 인용은 그대로): "The person asked the assistant to hold off on an action and only report first. Does this paragraph say that the action has not been done?"
- **B** (A와 같은 취지, 목록까지 답 전체를 인용): "…Does this answer report what the action would do and say that it has not been done?"
- 각 변형을 **엔진이 실제로 쓴 두 말투**("변경하지 않았습니다"(2b), "아직 수정하지 않았습니다"(31pr))와 **실제 음성 두 개**(2b의 처리 후 답, 31pr의 "…`일정 확인`은 남겨 두었습니다")에서 잰다. 통과 기준: 양성 둘 ≥.8 그리고 음성 둘 ≤.2. A가 통과하면 A(인용 변경 없음), 아니면 B.
- 9요청, 2,588토큰(ceiling 3,235), 드라이런 통과, 전송 0. 현재 문구는 31pr 말투에서 한 번만 잰다(기준선).
- 문구는 증거가 나올 때까지 바꾸지 않았다. 통과하는 변형이 생기면 코드는 작다(`PROPOSAL_PREDICATES.waiting`과, B라면 인용 span).
