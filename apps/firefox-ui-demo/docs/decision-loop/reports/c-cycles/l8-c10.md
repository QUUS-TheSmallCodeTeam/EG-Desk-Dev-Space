## 1. 연결 (`egdesk-browser-entry-wiring.mjs` 신규 37줄, bridge +6, runtime/task 소폭, `egdesk-turn-memory-wiring.mjs` +2)
- **flag**: 브리지 개발자 flag `EGDESK_BROWSER_ENTRY=advisory|on`, 기본 off(draft check와 같은 방식, 설정 화면 항목 없음). off이면 런타임이 `memory`/`outcomeSink`를 호출하지 않아 읽기·구축·전송·파일 열기가 전혀 없다. 브리지 코드가 flag를 스스로 켜지 않음을 정적 테스트가 확인한다.
- **어댑터 공유**: `createTurnMemoryConfig`가 같은 지연 어댑터를 `getAdapter()`로 노출(추가만). 브라우저 진입은 같은 어댑터·같은 쓰기 저장소를 쓴다(어댑터 생성은 브리지에 1곳).
- **outcomeSink**: 작업 결과 후보를 일반 기록 판단(`judgeTurnWrite`)과 `adapter.writerFor(wiki, …)`(= `createWikiWriter` + `openWikiWrites` 영속화)로 넘긴다. 허용: 이 DM(`dm:`) 쓰기 범위의 새 페이지뿐. 다른 페이지의 상태 변경은 하지 않는다(판정이 update를 제안하면 링크 없는 새 페이지로 바꿈). 페이지 본문은 **agent_note 결과 텍스트 그대로**(`messageRef` 없음), 내용 제한은 c8과 동일(날짜, 호스트, 요청 120자, 결과 코드, 라벨, 정화 경로, 해결한 선택; 값·쿼리·토큰·사용자 답 없음).
- **memory 훅**: 브라우저 소비자는 아무것도 들고 있지 않으므로 주관 모델의 턴 위치·영수증과 무관하게 **첫 턴식 재구성**(`position: first`, 영수증 없음)으로 packet을 만든다. 주관 모델에는 닫힌 노트만 가므로 전달 영수증은 커밋하지 않는다. 일시정지된 작업의 재개(사용자 답)에는 훅을 다시 부르지 않는다.
- 런타임 훅 인자에 `client`, `askedAt`, `position`을 추가(추가만). 작업에 `memory`를 보관해 sink가 같은 스냅샷에 쓴다.
- D2(Decisions도 다른 모델과 같은 데이터 공유 설정을 따름, 공용 egress helper는 L5가 작업 중): 별도 동의를 추가하지 않았다. 훅과 sink는 L7 advisory와 같은 `decisionContext.client`를 쓰며, 공용 helper가 들어오면 그 클라이언트 경로를 바꾸는 것만 남는다(이 브랜치에는 아직 helper가 없다).

## 2. mid-session 재실행 (W3, L7의 기본값 변경 후)
L7 변경: mid-session fetch는 "결정된 courtesy yes"에서만 건너뛴다(`skipOnNeed`는 호스트 opt-in). 확인한 것:
1. 대조(일반 mid fetch): 주관 모델이 이미 들고 있는 결과 페이지는 영수증으로 건너뛰므로 picks에 없다. 이 fetch로 브라우저 루프를 먹이면 이전 기록을 놓친다.
2. 대조(`skipOnNeed: true` + 잘못된 need "no"): 전체 fetch가 `skipped`가 되어 기록이 없다.
3. 훅: 두 경우 모두 무시하고 첫 턴식 재구성을 해서 이전 기록 페이지가 picks와 packet(`사업자 987-65-43210`)에 포함된다. 따라서 L7이 이후 held excerpts + skip-on-need를 켜도 브라우저 작업은 이전 기록을 받는다.
