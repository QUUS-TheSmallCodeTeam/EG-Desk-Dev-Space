# L5 / C7 — 터미널 모듈 실경로 연결 (플래그 기본 OFF, advisory 우선)

브랜치 `lane/c7-terminal-wiring` (기준 `int/c10`), 커밋 `496d9fd`, `8445352` (12 파일, +985/−13). 증거 `evidence/l5-c7/` (`state-watch-matrix.json`, `gate-wiring-matrix.json`, `gate.out`). 합성 transcript·가짜 프로세스·가짜 엔진 transport·mock 모델만 사용. 실제 셸/PTY/git/codex 바이너리/네트워크 실행 없음. 브리지 서버는 띄우지 않았다(서버 배선은 구문 검사와 소스 순서 시험으로만 확인).

## 0. 연결하면서 드러난 사실 3가지 (결정 필요)
1. **이 제품에는 "에이전트 소유 터미널 세션"이 없다.** `TerminalSessionRegistry`의 세션은 전부 사용자가 연 Terminal 카드(사용자 자신의 셸)다. 에이전트의 명령은 엔진(Codex/Claude) 내부에서 실행되고 EG-Desk에는 승인 요청으로만 온다. 따라서 on 효과 (a) "에이전트 소유 세션의 pager 종료"는 구현·시험했지만 **오늘 제품에서는 발동할 대상이 없다**(서버 배선: `isAgentOwned: () => false`).
2. **사용자 Terminal 카드의 출력은 어떤 모델에도 상시 공유되지 않는다**(사용자가 결과를 직접 보낼 때만). D2(Decision도 같은 공유 권한) 그대로 적용하면 그 출력은 Decisions로도 가지 않는다. 그래서 서버 배선은 `egressFor: () => null`: Terminal 카드에서는 **Decision 요청 0건**이고, 규칙(비밀번호 프롬프트)·프로세스 사실(종료 코드)·run watch의 파싱 결과만 기록된다. 모델 판정까지 가는 전체 경로는 "run에 묶인 세션"을 가정한 시험으로 증명했다. → 결정: Terminal 카드 출력을 모델(따라서 Decisions)에 공유하는 설정을 만들 것인가, 아니면 판정 대상을 엔진의 명령 실행 출력(이미 그 run의 모델이 받는 데이터)으로 옮길 것인가. 후자를 권한다.
3. **승인을 "추가"할 수 있는 지점은 세션 전체 허용뿐이다.** EG-Desk에 도달하는 명령 승인 요청은 이미 전부 사람 승인 카드가 되고 자동 승인은 없다. 엔진이 자체 샌드박스 정책으로 묻지 않고 실행하는 명령은 실행 전에 EG-Desk가 볼 수 없다. 그래서 on 효과 (b)는 "고위험 명령은 `세션 동안 허용`(acceptForSession)으로 승인할 수 없다(매번 묻는다)"로 구현했다. 이 선택지는 현재 Claude 스레드에서만 제공되므로 Codex에서는 on이어도 화면 변화가 없다.

## 1. 상태 판정기: run watch 옆 (`helper/egdesk-terminal-state-watch.mjs`)
- run watch를 감싸 레지스트리에 대신 전달한다. 모든 호출·반환값을 그대로 통과시킨다. **플래그 off면 그 외에는 아무것도 하지 않는다**(tail 보관·시계 읽기 없음).
- 플래그: 개발자 플래그 `EGDESK_TERMINAL_JUDGE=advisory|on`, 기본 off. 사용자의 Decision 모드와 키가 상한이다(키 없음/모드 off → 요청 0, 모드 advisory면 플래그 on이어도 advisory).
- 체크 포인트(자체 폴링 루프 없음): 화면의 `/terminal/read`(take), 확정된 프로세스 종료(`noteExit`), 외부 박동(`beat(sessionId)`: L3 heartbeat가 나중에 호출 가능). 체크는 호출자를 기다리게 하지 않는다.
- `terminalFacts()`: 읽기 전용·내용 없는 사실 제공자. `{ sessionId, alive, exitCode, quietMs, lastOutputAt, lastInputAt, tailChars, agentOwned, runBound, judged: { state, source, would, at } }`. 출력·입력·명령 텍스트 없음(시험으로 확인). `lane/c11-heartbeat`는 아직 커밋이 없어 인터페이스를 맞출 대상이 없었다. 이 형태를 제안한다.
- 기록(보정 로그 `terminal_state`, 닫힌 단어·불리언만): 판정 상태, 출처(runtime/rule/decision/fallback), **했을 일**(`wait / hand_yes_no / hand_secret / quit_pager / hand_close_pager / report / repair / hand_subjective`), 실제 실행 여부, 체크 종류. 오류면 넘겼을 로그 블록 수(열거 수/선택 수).
- 비용 상한: 같은 조용한 tail은 한 번만 판정, 명령당 최대 4회(스피너처럼 계속 바뀌는 출력 대비), Enter가 새 명령 창을 연다. 비밀번호 프롬프트는 규칙으로 인식하며 전송하지 않는다.
- **발견한 설계 공백:** Terminal 카드는 오래 사는 셸이라 "명령 완료"가 프로세스 종료가 아니다. 살아 있는 프로세스의 선택지에는 completed_*가 없다. 그래서 run watch가 이미 파싱한 테스트/빌드 결과(passed/failed)를 런타임 사실로 써서 질문 없이 `report`/`repair`를 기록한다. 일반 명령의 완료(프롬프트 복귀)는 명령 경계 사실이 없어 판정하지 못한다(다음 단계).

### 시험 결과 (`egdesk-terminal-state-watch.test.mjs`, 실제 레지스트리 + run watch + 판정기 + Decision 클라이언트)
- **바이트 동일:** 같은 스크립트 세션(읽기 16회, 입력 5회, 실행 결과 포함)을 래퍼 없음 / 플래그 off / advisory로 돌려 `read()`·`write()`·`snapshot()` 결과 JSON과 프로세스에 쓰인 입력을 비교 → 전부 동일. off는 요청 0·기록 0·facts 빈 배열. advisory는 요청 5·기록 6이면서도 동일.
- advisory 기록(run에 묶인 세션 가정): `running_output→wait`, `completed_error(runtime)→repair`, `stuck_in_pager→hand_close_pager`(사람 터미널), `waiting_yn_input→hand_yes_no`, `completed_ok(runtime)→report`, 종료 시 `completed_ok→report`. 프로세스에 간 것은 사람이 친 입력뿐.
- 비밀번호: `rule → hand_secret`, 요청 0, 프롬프트·입력 값이 요청/기록/facts 어디에도 없음.
- egress: run에 묶이지 않은 세션 또는 도구 상한 terminal=none → 요청 0, `evidence_unavailable` 폴백(종료 코드로 판단).
- on: 에이전트 소유 + Decision on + 수락된 선택 → `q` 정확히 1회. 사람 터미널 → 없음. 판정 후 화면이 바뀜 → 없음. Decision 모드 advisory → 없음. 다른 상태(yes/no, 오류, 완료) → 기록만.

## 2. 명령 게이트: 엔진 승인 카드 직전 (`codex-chat-runtime.mjs` `receiveApproval` / `replyApproval`)
- Codex `item/commandExecution/requestApproval`과 Claude `can_use_tool`(어댑터의 `routePermissionRequest`가 같은 요청으로 변환)이 모두 도달하는 한 지점에 연결했다. 두 경로 모두 실제 어댑터를 통해 시험했다.
- 플래그: `EGDESK_TERMINAL_GATE=advisory|on`, 기본 off. 게이트는 요청에 **절대 답하지 않는다**(자동 승인 없음). `[거절]`·`[이번만 허락]`은 어떤 모드에서도 제거되지 않는다.
- advisory: 카드는 즉시 그대로 만들어지고, 백그라운드에서 규칙 결과·Decision 점수·"승인이 필요했을 것인가"를 기록한다(보정 로그 `terminal_gate`: rule/would/scored/reasons(닫힌 단어)/score(0~4, 소수 1자리)/engine/gitFacts). 명령·경로·의도 텍스트는 기록에 없다.
- on: 추가로 (1) 조회 없이 알 수 있는 규칙(해석 불가 대상, 보호 대상, cwd 밖, sudo, curl|sh, force push)이면 카드에 `세션 동안 허용` 선택지를 내지 않는다. (2) git 사실이 필요한 규칙(추적 파일, dirty 워크트리)이나 점수는 사용자가 `세션 동안 허용`을 누른 시점에 확인해 고위험이면 `COMMAND_RISK_SESSION_FORBIDDEN`(403)으로 거절한다. 한 번 승인은 그대로 가능하다. 모델이 답하지 않으면 게이트 기한(최대 4 s)까지만 기다린 뒤 오늘 방식대로 허용한다.
- git 사실(`helper/egdesk-terminal-git-facts.mjs`): `git -C cwd rev-parse / ls-files / check-ignore / status`를 셸 없이·읽기 전용·시간 제한으로 실행. 실패나 저장소 아님은 "모름"으로 남고 점수에 "모름"으로 전달된다. **실제 git 실행은 시험하지 않았다**(가짜 execFile로 인자·파싱만 확인).
- egress: 점수 요청은 그 run의 공용 게이트(`terminal_command`)를 거친다. 도구 상한 terminal=none이면 기존대로 카드 전에 거절되고 게이트는 돌지 않는다.
