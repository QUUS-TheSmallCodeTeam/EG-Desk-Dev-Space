## 1. same_matter: 왜 한 요청의 카드가 전부 같은 답을 받았나
본문을 읽어 보니 원인은 하나였다.
- v2의 질문 세 개는 **instructions 문자열이 글자 하나까지 같았다**("…as the card quoted under this question…").
- 카드는 공유 input에만 "Question same_matter_R1:" 머리말을 달고 있었다. 질문 자체에는 어느 카드인지 말해 주는 것이 없었다. 그래서 모델은 사실상 같은 질문 하나에 세 번 답했다(견적: 하나가 맞으니 1/1/1, 보고서: .03/.03/.03).
- 대조군: 같은 실측의 Board 관련성 질문은 instructions가 "excerpt labeled c4"처럼 자기 항목을 이름 대고 있었고, 답이 1 / .95 / 0으로 갈렸다.

고친 것(R4, "공유 자료에 답이 되는 것 없음"):
- **기본값 'question'**: 카드마다 자기 질문 안에 그 카드 인용을 넣는다. 공유 input은 요청문뿐이다. 두 질문이 같은 문자열인 일은 없다(테스트).
- **대안 'request'**: 카드마다 요청 하나. 함께 보내고, 코드가 합치고, 하나라도 실패하면 규칙 자리를 쓴다. 요청 하나하나가 heartbeat 상한에 들어간다.
- 토큰 비용(제품이 만든 바이트, 러너의 추정식): 질문당 카드 **1,441** vs 요청당 카드 **1,853**(+412, +29%). 지연은 병렬이라 늘지 않지만 요청 수는 2 → 6.
- R6(요청 안 오염)은 L6 c10 실험으로 정하기로 돼 있다. 그래서 재측정 계획에 두 방식을 모두 넣었다. 기본값은 싼 쪽('question')이다.

## 2. in_effect: 문구, 날짜, 관련 있는 것만
- **문구**: "Does the arrangement this excerpt describes (excerpt cN) still apply on <date>?" (Main 제안 그대로에 항목 이름만 붙임).
- **날짜는 코드 규칙**(`questionDate`): 질문이 날짜를 말하면 그 날, 아니면 오늘.
  - 읽는 순서: `2026-11-27` / `2026년 11월 27일` → `11월 27일`(반년 넘게 지났으면 내년) → `2026년 12월` → `이번 주/다음 주 X요일` → `오늘/내일/모레` → `12월`.
  - 없는 날(2월 30일)은 무시한다.
  - 결과: 주차 질문은 2026-11-27, 워크숍은 2026-12, 요금은 오늘.
- **관련 있는 것만(R3)**: 첫 요청은 관련성만 묻는다. 관련으로 판정된 발췌문만 두 번째, 더 작은 요청에서 시점을 묻는다. 아무것도 관련 없으면 두 번째 요청은 없다.
  - 아낀 양: v3 전체 계획 기준 시점 질문이 14 → 7개, 추정 5,184 → **4,691 토큰(−493, −9.5%)**. 요청 머리말이 3번 더 붙은 것을 감안한 값이다.
  - 무관한 발췌문에 대한 미결정 답(.54/.60/.51)은 이제 묻지 않는다.
- 결합 규칙은 그대로다: 관련 그리고 적용 → 제공, 관련인데 비적용 → dated(현재 답으로 절대 안 나감), 답이 없거나 잘못됨 → 응답 전체 무효(기존 단어 일치).
- **비용 변화(알림)**: 관련 발췌가 있는 Board ask 한 번은 이제 Decisions 요청 **2건**이다(전에는 1건). 두 번째 요청은 따로 1초 상한을 받는다. 재시도는 없다. 이 계약을 박아 둔 다른 레인 테스트(crosslane L2, quota acceptance, draft-host)의 요청 수와 토큰 합계를 그에 맞게 고쳤다. draft-host의 mock은 "물은 질문에만 답하는" provider로 고쳤다(고정 답 객체가 묻지 않은 키를 돌려주면 제품이 거절한다. 그 거절이 맞다).

## 3. 창 `on` (U7)
`egdesk.workPlacement` = `on`이면 Agent의 **새** 작업 화면(실행 파일 뷰어, 결과 카드)을 규칙 자리에 연다. 기본값은 꺼짐이다.
- **카메라 이동 없음**: 훅이 돌려주는 자리에 `quiet: true`가 붙고, `revealPlacedCanvasCard`는 quiet면 즉시 돌아간다. 같은 자리라도 quiet가 없으면 reveal 타이머가 잡히는 것을 대조로 확인했다.
- **입력 포커스 없음**: 결과 카드는 `activate: false`. 파일 뷰어는 `activate: … && !placement.quiet`.
- **남의 활성 뷰 안 금지**: 하드 규칙 1. 요청자가 다른 멤버이거나 모르는 사람이면 소유자 뷰도 보호한다.
- **아무 카드도 옮기지 않음**: 새 카드 하나를 여는 것뿐이다.
- **공유 원장에 안 씀**: 규칙 자리는 Board 영역과 24px 간격을 두고 겹치지 않는다(기존 obstacle 규칙). 훅에는 Board 저장·카메라·포커스 호출이 없다(소스 검사).
- 실패하면(presence 오류 등) 오늘 자리 그대로 연다. 재사용(reuse)이면 새로 열 것이 없으니 오늘 그대로다.
- `advisory`는 바이트 단위로 이전과 같다(훅이 `null`을 돌려줌).
- 테스트는 합성 DOM이다. 표면 소스의 `resolveCanvasCardPlacement`, 훅, `workPresence`, `revealPlacedCanvasCard` 본문을 그대로 꺼내 실제 SurfaceState·배치 런타임과 카메라/포커스 spy 위에서 돌렸다. Firefox는 쓰지 않았다.

## 4. 제안: Board 발췌문의 선택적 시점 필드 (형식 변경 없음, 승인 필요)
지금 발췌문은 문자열뿐이라 시점을 본문 해석에 맡긴다. 소유자가 원할 때만 적는 선택 필드를 두면 시점은 코드 규칙이 된다(R3). 저장 형식은 바꾸지 않았다.

```
excerpts: [ "문자열"                                   // 지금 형식, 그대로 유효
          | { text, validFrom?, validUntil?, version?, supersededBy? } ]
  validFrom / validUntil : "YYYY-MM-DD" (포함), 없으면 제한 없음
  version                : 짧은 문자열 (예: "2026 개정")
  supersededBy           : 같은 정책 안의 다른 발췌문 번호(1부터) — 그 발췌문으로 대체됨
```
코드 규칙(질문 날짜 D = `questionDate`):
1. `validUntil < D` 또는 `validFrom > D` → dated. 묻지 않는다.
2. `supersededBy`가 가리키는 발췌문이 D에 유효 → dated. 묻지 않는다.
3. 같은 `version` 계열에서 둘 다 관련이면 가장 최근 유효 것만 제공한다.
4. 필드가 없는 발췌문만 지금처럼 arrangement 술어로 묻는다.

호환·경계:
- 읽기는 문자열과 객체 둘 다 받는다. `validateExcerpts`의 바이트 상한은 `text`에 적용하고, 필드 값은 닫힌 형식만 허용한다.
- Decisions로 가는 것은 지금처럼 `text`뿐이다. 날짜는 코드가 쓴다.
- 저장은 문자열 JSON 배열이 객체를 섞은 배열이 된다. 이전 버전 bridge는 객체를 거절하므로 내려가기가 막힌다.
- UI에 날짜 입력 칸이 필요하다(새 문구).
- 이 세 가지는 모두 결정 사항이다.
