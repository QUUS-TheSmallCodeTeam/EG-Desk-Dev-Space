## 1. 전역 ⌘Z 시뮬레이션
시험: `apps/firefox-ui-demo/scripts/egdesk-board-arrangement-history.test.mjs` (신규, 8 케이스).
- 진짜인 것: `eg-desk-surface.uc.js`의 `installCanvasPlacementOps` 원문(real `history`, `applyHistoryStep`, `undoLayout`, `redoLayout`, 캡처 keydown 리스너)과 arrange 배선 줄(`let jointDesk…arrangeUI`, `const arrange=…createWorkbenchArrange({…})`)을 **같은 스코프로 소스에서 잘라 컴파일**해 실제 `arrangeUI` 바인딩을 공유. 실제 `EGDeskWorkbenchArrange`/`EGDeskJointPresentation`(패널 DOM 버튼 클릭으로 pair/front/overview 적용, 패널의 '마지막 적용 되돌리기' 클릭), 실제 `EGDeskCanvasLayout.createLayoutHistory`.
- 가짜인 것: DOM 노드·카메라·지오메트리 저장소. 수동 이동은 실제 제스처 종료와 같은 호출(`history.record` + 지오메트리 쓰기)로 모델링. ⌘Z는 캡처된 keydown 핸들러에 `{metaKey,key:'z'}`를 직접 전달.
- 장면: 메모 A(40,60,300x200,z3), B(300,140,300x200,z4), 브라우저 카드 C(900,500, 장애물/비대상).

### 패치 전(int/c1) 실제 관찰 (`evidence/l4-c2/hist-before.tap`, `matrix-hist-before.jsonl`; 8중 1 pass)
H1 수동이동 A(+21) → Apply(pair) → ⌘Z → ⌘Z → Shift+⌘Z:
- s0 A(40,60) B(300,140) → 수동 이동 후 A(61,60) → pair 적용 후 A(188,250) B(512,250).
- ⌘Z #1: `handled:true`인데 **아무것도 안 바뀜** A(188,250) B(512,250). 알림 `되돌릴 배치가 그 뒤에 바뀌어서 건너뛰었습니다.` 원인: 기록의 맨 위가 수동 이동(A만)이고 A가 Apply로 이미 옮겨져 있어 stale로 판정, **그 수동 이동 단계는 버려짐**.
- ⌘Z #2: `handled:false`, 변화 없음(기록 비어 있음). Shift+⌘Z도 변화 없음.
→ 내 코드 읽기 가설("⌘Z가 이전 수동 이동을 되돌린다")은 **부분적으로만 맞았다**: 이 순서에서는 되돌리기는커녕 수동 이동 기록이 소실되고, 배치 추천 Apply는 ⌘Z로 되돌릴 방법이 아예 없었다(패널 버튼만).
H2 Apply 후 수동 이동(B가 아니라 A +13): ⌘Z → 수동 이동만 되돌려짐(옳음), ⌘Z #2 변화 없음(Apply는 되돌릴 수 없음).
H3 Apply 후 패널 Undo → ⌘Z: 이전 수동 이동 되돌림 정상(기록이 따로라 이중 되돌리기는 없었지만 Redo 불가). H4: ⌘Z로 Apply 못 되돌리고 패널 Undo는 계속 제안(두 기록이 따로). H5(front): ⌘Z가 z를 못 되돌림(z는 기록 밖). H6(overview): 카메라 못 되돌림. H3b: 패널 Undo 후 Shift+⌘Z 변화 없음.

### 패치와 패치 후 (`hist-after.tap`, `matrix-hist-after.jsonl`; 8/8)
설계: **기록은 하나(`createLayoutHistory`).** 배치 추천 Apply가 그 기록의 한 단계(`label:'arrange'`)가 된다.
- `EGDeskCanvasLayout.sys.mjs`: `record()`가 선택적 `extra`({before,after}: 호스트 소유 JSON, 여기서는 z와 카메라), `token`, `guard(expect)`를 받는다. 기록은 해석하지 않는다. `step()`은 rect 검사 후 `guard`가 거짓이면 기존 stale 규칙대로 건너뛰고(기존 알림 재사용), 아니면 `extra`·`token`을 돌려준다. `top()`, `drop(token)` 추가. 기존 호출은 인자 없이 동작이 같다.
- `EGDeskWorkbenchArrange.sys.mjs`: `commit(key,plan,{kind:'apply',token})`에서 적용 직전·직후 rect·z, 적용 카메라를 읽어 `history().record(...)`. guard는 대상 카드의 z와(카메라를 옮긴 단계면) 카메라가 단계가 남긴 그대로일 때만 참. `restore(extra,ids)`: ⌘Z/Shift+⌘Z가 되돌린/재적용한 z·카메라를 같은 경로(`h.apply`, Board 카드는 `record`, 그 외 `dirty`, `refresh`)로 반영. `forgetUndo` 노출.
- `EGDeskJointPresentation.sys.mjs`: 적용마다 `token`을 만들어 commit에 전달·undo 레코드에 보관. 패널 '마지막 적용 되돌리기'는 `undoApplied(token)`으로 기록의 **같은 단계**를 되돌린다(맨 위가 아니면 그 단계를 기록에서 `drop`한 뒤 c1의 직접 복원 사용: 이중 되돌리기 불가). `forgetUndo(token)`: ⌘Z가 이 Apply를 되돌리거나 다시 적용하면 패널 쪽 되돌리기를 폐기.
- `eg-desk-surface.uc.js`: arrange 배선에 `history`, `undoApplied` 추가, `applyHistoryStep`이 `result.token`이 있으면 `arrangeUI.restore(extra,…)`, `arrangeUI.forgetUndo(token)` 호출.
패치 후 관찰(모두 통과):
- H1: ⌘Z #1 → A(61,60) B(300,140) (Apply만 취소), ⌘Z #2 → A(40,60) (수동 이동 취소), Shift+⌘Z → A(61,60) (수동 이동 재적용).
- H2 Apply 후 수동 이동: 패널 Undo는 미제공(`panelUndoOfferedAfterMove:false`), ⌘Z #1이 수동 이동, #2가 Apply를 되돌림.
- H3 패널 Undo 후 기록 `{undo:1,redo:1}`: ⌘Z는 이전 수동 이동만 되돌림(Apply를 두 번 되돌리지 않음). H3b: 패널 Undo 후 Shift+⌘Z가 같은 Apply를 재적용.
- H4: ⌘Z 후 패널 Undo 폐기(`false`), Shift+⌘Z 재적용, ⌘Z 재되돌림. H5 front: ⌘Z가 z 5→3, Shift+⌘Z가 3→5. H6 overview: ⌘Z가 카메라 복원, 이후 사용자가 팬하면 ⌘Z는 `건너뛰었습니다` 알림과 함께 건너뜀(시점이 튀지 않음).
- H7 가드 유지: 기록 없이 배치된 카드가 바뀌었다면(기록 밖 경로) Apply 단계는 stale로 건너뛰고 사용자 위치를 덮지 않음.
기존 가드 유지: 사용자가 Apply된 카드를 옮겼고 그것이 최신 단계가 아니면 되돌리기는 기존 stale 규칙으로 막힘(H7), c1의 `undoStillValid`와 일치.

## 2. 카드가 로컬 평면에 안 들어갈 때 tidy는 인접 작업 공간을 쓰는가
측정: `evidence/l4-c2/measure-adjacent.mjs` / `.out`(합성 장면, 1320x840, 실제 컨트롤러 `open`+`choose`).

- canon: `docs/JOINT_BOARD_RUNTIME.md:51-56` '빠른 책상 정리': "창 하나를 찾는 카메라 보기와, 실제 위치/폭을 바꾸는 정리 명령을 구분한다", "안전하게 그릴 수 없는 선택은 로컬로 남는다", 적용은 '내 화면에'만, 선택하지 않은 자료는 건드리지 않음. `DECISION_MODEL_CONTEXT_SETUP.md:262`: 정돈/인계/주 작업 배치, 로컬 미리보기/적용/되돌리기, 불확실하면 수동. **인접 작업 공간 허용/금지를 명시한 문장은 canon에서 찾지 못했다**(저장소 전체 grep 포함). 코드 주석(`AdjacentWorkbench`: "Never move private blockers")만 있다. 재현된 canon 위반은 없다(비대상 카드는 이동하지 않고, 카메라 이동은 미리보기 지도 '옆 작업 공간의 제안'으로 표시되며 되돌리기로 복원됨). 다만 인접 계획 적용 1회가 카메라 이동과 위치 변경을 함께 한다는 점은 위 '구분한다' 문장과 긴장이 있을 수 있어, 제품 판단 항목으로만 남긴다(수정 안 함).

## 4. 철학 점검
"가장 최근에 사용자가 본 변화가 ⌘Z가 되돌리는 것이고, 되돌리기는 사용자의 이후 작업을 덮어쓰지 않는다(모델 제안 ≠ 승인된 실행, 사용자 배치 보존)". 한 기록으로 합쳐 ⌘Z, 패널 Undo, Redo가 같은 사실을 가리킨다. 가드(rect·z·카메라가 단계 직후 그대로일 때만)는 유지되어 사용자의 이후 이동이 덮이지 않는다.
