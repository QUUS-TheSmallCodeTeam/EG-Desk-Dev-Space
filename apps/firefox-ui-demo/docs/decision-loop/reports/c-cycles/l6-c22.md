## 2. 동작 방식 [측정]
- 결과 파일에는 요청 본문이 없고 `sha256`, `bytes`, 질문 이름, 답만 있다. 그래서 각 SHA의 `apps/firefox-ui-demo`를 `git archive`로 임시 폴더에 풀고, 기록된 답으로 여정 하네스를 재생한다 (본문 수집 줄은 임시 사본에만 붙임; 사본은 끝에 삭제, 워크트리는 깨끗함).
- 재생한 본문의 sha256이 기록과 같으면 "정확히 재현"으로 표시한다. 재현 못한 본문은 diff 옆에 "코드의 본문이지 보낸 본문이 아님"이라고 적는다.
- 단계별 출력: 새로 실패/통과한 확인, 계획에 새로 생긴 확인, 바뀐 본문(바뀐 줄만, 앞의 안 바뀐 줄 1개와 함께), 0.2 이상 움직인 답, 게시된 메시지 수.
- 바뀐 본문의 계열마다 두 SHA 사이의 커밋을 세 가지로 찾는다: (a) 그 계열 builder 파일을 건드린 커밋, (b) 계열의 핵심 함수 정의를 바꾼 커밋 (`git log -L`; `FAMILY_SYMBOLS`), (c) 바뀐 줄의 문장을 파일에서 더하거나 뺀 커밋 (pickaxe). wiring 파일(codex-chat-runtime.mjs 등)은 14개 커밋이 걸려 너무 넓어서, 함수 단위 (b)를 따로 둔다.
- 맵 검증 [측정]: 계열 → 파일 맵의 모든 파일 존재, 각 계열의 질문 이름 조각이 맵 파일 어딘가에 있음, 각 핵심 함수가 말한 파일에 정의되어 있음을 테스트가 고정한다. 하네스의 본문 수집 anchor가 정확히 한 번 나오는지도 테스트한다 (옮겨지면 테스트가 실패하고 고칠 위치를 알려준다).
