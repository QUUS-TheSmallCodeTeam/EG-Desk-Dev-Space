## 1. 바인딩 영속화 (버전 체인)
- 새 모듈 `helper/egdesk-briefing-bindings.mjs`: `openBriefingBindings({ dataDir })`는 **Map**을 돌려줍니다. 핸들러와 스켈레톤이 쓰는 get/set/delete/entries/keys/size가 그대로이고, set과 delete가 저장합니다.
- 위치는 `<브리지 데이터 디렉터리>/briefing/briefing-bindings.json`입니다(`codex-bridge-server.mjs`).
  - 캘리브레이션 로그와 같은 비공개 파일 규칙: 디렉터리 0700, 파일 0600, 소유자 검사, O_NOFOLLOW, 원자적 쓰기(tmp → rename, fsync).
- **저장하는 것**: outputId, conversationId, outputKey, trait, component(닫힌 단어), 자료 키(`[a-f0-9]{16,64}` 또는 `t:`+해시), version, 내용 해시(sha256), 시각.
  - 제목, 자료 본문, 카드 본문은 없습니다. 그런 필드가 있거나, 키가 텍스트이거나, 모르는 종류이거나, id가 잘못된 행은 받지 않습니다(테스트).
- **상한**: 전체 500개, 대화당 60개, 180일, 256 KiB. 오래된 것부터 버립니다.
- **정리**:
  - `forgetConversation(id)`: 메모리와 디스크 모두에서 지웁니다.
  - 이어가려던 출력이 저장소에서 사라졌으면(새 출력이 version 1, previousId 없음) 그 바인딩을 지우고 새 출력을 기억합니다.
- **고장 처리**:
  - 깨진 파일은 옆으로 보관하고 새로 시작합니다.
  - 더 새로운 버전의 파일은 그대로 둡니다(메모리만 사용).
  - 다른 사람이 읽을 수 있는 권한의 파일은 신뢰하지 않습니다.
  - 심링크 디렉터리나 상대 경로면 메모리 Map으로만 동작합니다(이전과 같음).
- 핸들러는 `briefingBindings` 옵션을 받습니다. 기본값은 이전처럼 메모리 Map이라 기존 테스트가 바뀌지 않습니다. 바인딩마다 version과 hash도 남깁니다.
- **재시작 테스트 (마운트)**:
  - 첫 브리핑 → 같은 디렉터리로 저장소를 다시 열고 새 핸들러를 만듦(브리지 재시작) → v2 페이지가 바뀐 두 번째 브리핑.
  - 결과: 다시 만든 모든 파트가 **자기 이전 출력의 다음 버전**이 되었고(previousId 일치), 옛 카드는 접기 제안에 들어갔습니다.
  - 같은 여정을 이전의 메모리 Map으로 돌리면 모두 version 1이 되고 회수할 것이 없습니다(대조군).

## 2. 채우기 실패 후 사람이 보는 것 (s3, `nothing-left`)
- 브리지는 `{ status: 'observed', outcome: 'fallback-chat', reason: 'nothing-left' }`를 돌려줍니다(`egdesk-board-presentation-http.mjs`, `if (!live || out.status !== 'presented') return summary`). 아무것도 발행하거나 제안하지 않습니다.
- 크롬의 `offerBriefingRetrieval`는 첫 줄(`outcome !== 'presented'`)에서 끝납니다. **알림, 칩, 카드, 카메라 변화가 모두 없습니다.** 사람에게 남는 것은 대화의 답 그대로입니다.
- 답에 브리핑이 없으므로 기존 CHAT-05 **"브리핑 요청"** 칩이 그대로 보입니다(`EGDeskBriefingState.sys.mjs:88`, Codex 방이면서 컨텍스트 도구가 있을 때). 이 칩은 Agent에게 브리핑을 부탁하는 초안만 입력칸에 넣습니다. 그래서 사람은 원하면 직접 브리핑을 요청할 수 있습니다.
- 브리핑을 **버렸다는 표시는 없습니다**. 표시하려면 새 문구가 필요합니다. 승인 대기 중인 "보드 브리핑을 만들지 못해 대화로 답합니다."가 그 후보이며 소유자 결정입니다.

## 2b. 부분 보드가 아무것도 없는 것보다 나은가
- **이미 그렇게 동작합니다.** 채우기 검사 루프는 실패한 파트를 한 번 다시 쓰고, 두 번째에도 실패하면 그 파트만 빼고 나머지로 진행합니다. 그다음 사실 단위 커버리지 규칙이 적용됩니다.
  - 답이 말하는 사실이 보드에 모두 보이면 → 남은 파트로 이루어진 보드를 **제안**합니다.
  - 빠진 파트만 보여주던 사실이 있으면 → 누락입니다. 빠진 파트는 재설계 후보가 아니므로 → 대화 답(`not-covered`). 커버리지 규칙이 그대로 지켜집니다.
- s3 실측에서는 P1, P2, P3이 **모두** 실패했습니다(P1 r1_right 0, r2_left 0 / P2 r2 .62, r4 .44 / step_P3 .28 두 번). 남은 파트가 없어 `nothing-left`였습니다. 즉 s3에서 부분 보드는 만들 것이 없었습니다.
- 이 동작을 고정하는 테스트를 추가했습니다(코드 변경 없음):
  - (a) P3만 두 번 실패하고 답에 남은 일이 없음 → P1, P2 보드 제안. rejections는 rewrite → drop, dropped는 P3, unsupported.
  - (b) 답의 남은 일(F3)을 P3만 보여줌 → not-covered, 재설계 없음.
  - (c) 모든 파트 실패 → nothing-left.
- s3의 실패가 L2 하네스의 스크립트 fill 때문인지 검사 결함인지는 L2가 확인 중입니다. 결함이면 받은 body로 다시 보겠습니다.
