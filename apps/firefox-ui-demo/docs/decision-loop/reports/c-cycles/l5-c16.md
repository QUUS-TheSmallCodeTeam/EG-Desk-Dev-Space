## 1. 소스 확인을 반복하는 정확한 절차 (Main용)
저장소 스크립트 `apps/firefox-ui-demo/scripts/codex-hooks/source-facts-check.sh`를 씀. 이 스크립트는 curl로 openai/codex의 원본 텍스트 7개를 받고 사실 11개를 grep함. Codex를 실행하지 않고 설정도 읽지 않으며, 이 점을 테스트로 확인함.
1. **버전 확인**: 알림 `unverified_engine_version`이 기록되었거나 새 릴리스를 채택하려는 경우, 그 빌드의 user agent 버전 `X.Y.Z`(InitializeResponse.userAgent의 `<originator>/X.Y.Z`)에 해당하는 태그는 `rust-vX.Y.Z`임.
   - 기록에는 버전이 남지 않음(닫힌 어휘). 버전이 필요하면 브리지 로그 대신 채택하려는 릴리스 번호를 쓰면 됨.
2. **실행**(cwd = `apps/firefox-ui-demo`):
   `bash scripts/codex-hooks/source-facts-check.sh rust-vX.Y.Z "$L/evidence/<lane>/facts-rust-vX.Y.Z" > "$L/evidence/<lane>/facts-rust-vX.Y.Z.out"; echo $?`
3. **결과 해석**:
   - `exit 0`(`result=all-facts-hold`): `helper/egdesk-codex-version-pin.mjs`의 `CODEX_HOOK_SOURCE_CHECK.versions`에 `'X.Y.Z'`를 **추가**함(기존 항목은 지우지 않음). 그다음 `helper/egdesk-codex-version-pin.test.mjs`가 그대로 통과하는지 보고 브로드 게이트를 돌림. 커밋 메시지에 태그와 `.out` 경로를 적음.
   - `exit 1`(`MISS …`): 목록에 **추가하지 않음**. 빠진 사실의 파일(MISS 줄 괄호 안)을 그 태그에서 직접 읽고, c14 보고서의 해당 결론(환경 상속, `*TOKEN*` 제외, session_id/turn_id 출처, userAgent)이 아직 맞는지 다시 판단함. 맞지 않으면 훅 설계(egdesk-gate-hook-core.mjs, egdesk-gate-hook-broker.mjs)를 먼저 고침. 사실이 위치만 옮겨졌다면 스크립트의 grep을 고치고(이유를 커밋 메시지에 남김) 다시 돌림.
   - `exit 2`(다운로드 실패, 404 등): 태그 이름이나 네트워크 문제임. 목록은 바꾸지 않음.
4. 확인은 "사실이 grep으로 보인다"는 수준임. 바이트 동일성은 보장하지 않음(c15에서 릴리스마다 파일이 달랐지만 사실은 성립했음). 확인 후에도 c14의 미확인 1~5는 그대로임.

## 2. 프로필 app-server에서 훅이 돌 수 있는가 → **돌 수 있음(코드 근거)**
- **Codex 쪽**(openai/codex a0d5b0a6, `hooks/src/engine/discovery.rs`):
  - `discover_handlers`(119행~)는 관리형 요구 사항 훅을 먼저 붙이고, 157행 `for layer in config_layer_stack.layers_low_to_high()`로 **모든 설정 레이어**에서 `hooks.json`과 `[hooks]`를 읽음.
  - 레이어 종류는 1067-1081행의 System(`/etc/codex`, CODEX_HOME과 무관), User(`$CODEX_HOME`), Project(신뢰된 `.codex`), SessionFlags(`-c`), MDM/Enterprise/Legacy managed임.
  - 훅 문서 "Turn hooks off": "Hooks are enabled by default", 끄려면 `[features] hooks = false`.
- **EG-Desk 쪽**(`codex-profile-app-servers.mjs` `launch`):
  - 인자는 `app-server --listen stdio:// -c cli_auth_credentials_store=file`이고 **훅을 끄는 스위치가 없음**.
  - `CODEX_HOME`은 EG-Desk가 소유한 프로필 홈(User 레이어)이고 `cwd`는 프로젝트(Project 레이어)임.
  - 따라서 System, User(프로필 홈), 신뢰된 Project, 관리형 훅이 그 프로세스에서 돌 수 있음.
- **중요한 발견**: 그 프로세스의 환경은 격리되어 있음(`isolatedCodexEnv`: PATH/HOME 등 OS 변수와 `CODEX_HOME`만 남음). 그래서 **EG-Desk의 게이트 훅은 거기서 침묵함**. 주소가 오지 않으므로 "EG-Desk가 띄운 엔진이 아님"으로 판단하고, fail closed가 아니라 침묵함. 테스트로 확인함.
  - 프로필에서 훅 경로를 쓰려면 격리 환경에 `EGDESK_GATE_HOOK_URL`과 `EGDESK_GATE_HOOK_TOKEN`을 **명시적으로** 추가해야 함. 이는 격리 정책을 바꾸는 일이라 이번에는 하지 않았음(결정 1).
- 그래도 버전 고정은 연결함(Main 결정 2). 프로필 프로세스에서 사람이나 관리형 훅이 돌 수 있고, 훅 경로를 나중에 켜면 그대로 의미가 있기 때문임.

## 3. 구현
- `codex-profile-app-servers.mjs`: 새 옵션 `onVersion(id, { userAgent })`. 프로필 프로세스마다 `initialize` 직후 한 번 부르고(현재 프로세스일 때만), `codexHome` 경로는 넘기지 않음. 프로세스가 교체되면 다시 부름.
- `codex-bridge-server.mjs`: `onVersion → chat.setEngineVersion({ engineId: 'codex', engineProfileId: id, userAgent })`.
- `codex-chat-runtime.mjs`: 버전 확인을 **app-server 세션마다** 따로 가짐(`engineVersionChecks`: 공유 `codex-default`, 그리고 프로필 id. 최대 64개).
  - 알림은 세션마다 한 번 기록하고 `engineScope: 'shared' | 'profile'`(닫힌 어휘)을 붙임. 프로필 id와 버전은 쓰지 않음.
  - 게이트 활동(카드, 묻지 않고 실행된 명령, 훅 check)은 그 대화의 프로필 세션만 확인함. 브로커 `onCheck`는 `{ conversationId }`를 넘김.
  - c15의 `engineVersionCheck` 속성은 공유 세션을 가리키도록 유지해서, c15 테스트는 수정 없이 통과함.
- 보정 로그: `GATE_ENGINE_SCOPES = ['shared', 'profile']`.
- 버전 고정 모듈의 주석이 저장소 스크립트를 가리키게 바꿈.
- 테스트(`helper/egdesk-codex-profile-version.test.mjs`, 4개):
  - 프로필 실행에 훅 스위치가 없고, 소유한 CODEX_HOME과 cwd를 쓰며, 격리 환경 때문에 게이트 훅이 침묵함(fetch 0회).
  - 프로필마다 initialize의 userAgent를 한 번 보고하고, 경로는 넘기지 않으며, 교체되면 다시 보고하고, 브리지 연결은 소스 스캔으로 확인함.
  - 공유와 프로필 세션이 각각 한 번씩 기록하고, 활동은 자기 세션만 확인하며, 새 프로세스면 다시 기록하고, 기록에 id와 버전이 없음.
  - 스크립트가 저장소에 있고, 사실이 11개이며, Codex 실행이나 설정 참조가 없음.
