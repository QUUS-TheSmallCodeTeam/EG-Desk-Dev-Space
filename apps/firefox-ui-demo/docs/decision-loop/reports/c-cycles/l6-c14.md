## 1. 초안 검사 과잉 개입 계획 (`proofs/decision-real-measure/draft-overcorrection/`)

`node scripts/egdesk-draft-overcorrection-plan.mjs [--write | analyze <results>]`, 모듈 `helper/egdesk-draft-overcorrection-plan.mjs`, 테스트 3개.

- **본문:** 제품 `checkDraft` (`design: 'predicates'`, 기본값, `on`) 가 기록용 클라이언트로 만든 그대로다. 초안 하나에 요청 하나이고, 문장마다 `sup_i` (근거가 그 문장을 말하는가) 와 `tense_i` (계획·과거를 지금 일로 말하는가) 를 묻는다. 공개용 합성 한국어, 가상 회사를 썼다.
- **등록 (본문을 만들기 전):** 초안 9개, 문장 19개.

  | 구분 | 종류 | 수 |
  |-|-|-|
  | 맞는 문장 14 | 과거 사실 (숫자·날짜 정확) | 5 |
  | | 계획을 계획으로 | 3 |
  | | 전해 들은 말을 전해 들은 말로 | 4 |
  | | 현재 사실 | 1 |
  | | 구체 주장 없음 ("더 확인할 내용이 있으면 말씀해 주세요.") | 1 |
  | 틀린 문장 5 | 계획을 했다고 말함 ("v2 … A사에 보냈습니다") | 1 |
  | | 틀린 숫자 (8% → 18%) | 1 |
  | | 전해 들은 말을 사실로 (구체 있음: "납품일은 12월 2일로 변경되었습니다") | 1 |
  | | 전해 들은 말을 사실로 (구체 없음: "A사는 계약을 연장하기로 했습니다") | 1 |
  | | 지난 기록을 지금 일로 ("디스크 사용률은 지금 92%") | 1 |

  - 제품이 문장을 정확히 이 19개로 나누는지 빌더가 확인한다.
  - 틀린 초안에는 다른 곳에서 재는 맞는 문장을 복사해 넣지 않았다. 같은 근거 위의 같은 문장은 새 입력이 아니기 때문이다.
- **"지우거나 고친다"의 정의:** 제품이 그 문장에 finding 을 내는 것이고, 기준은 제품의 `readPredicateFindings` 와 같다.
  - unverified: `sup ≤ 1 − finding (.3)` 이고 그 문장에 구체 내용(숫자, 라틴 이름·식별자)이 있을 때.
  - present_tense: `tense ≥ finding (.7)`.
  - finding 이 난 문장은 제품이 쓴 사람에게 돌려 고치게 하거나, 잘라 내거나(`certain_part`), 질문으로 바꾼다(`ask_user`).
- **hard 검사:**
  - 맞는 문장: 구체 내용이 있으면 `sup ≥ .301`, 언제나 `tense ≤ .699`.
  - 틀린 문장: 제품이 잡을 수 있는 질문에서 잡혀야 한다. 숫자·구체 있는 전언은 `sup ≤ .3`. 계획을 완료로, 과거를 현재로, 구체 없는 전언은 `tense ≥ .7` (구체가 없으면 `sup` 이 낮아도 제품은 행동하지 않으므로 tense 가 유일한 길이다).
- **productBars:** `DRAFT_CHECK_THRESHOLDS.finding` 에서 계산한다 (`sup_#` 예 .301 / 아니오 .3, `tense_#` 예 .7 / 아니오 .699). 러너 검사와 묶음 검사(lint) 모두 통과한다 (문장은 `S1`, `S2` 로 입력에 인용된다).
- **분석:** `analyze` 가 실제 답을 제품 `checkDraft` (`on`, 다시 쓰는 사람 없음) 에 되돌려 넣는다. 맞는 문장 중 지워지거나 고쳐지는 비율, 틀린 문장 중 통과하는 비율, 종류별 수, 초안별 결과(`passed` / `certain_part` / `ask_user`) 를 낸다.
- **크기:** 추정 **8,386 토큰 / 상한 10,000**, 한 묶음. 한국어 본문은 실측이 추정보다 5~10% 높았는데, 10% 를 더해도 상한 안이다.
- **이 계획으로 할 수 있는 말과 없는 말:**
  - 할 수 있는 말: 맞는 문장 14개 중 0개가 걸리면 이 문장 분포에서 과잉 개입률 상한은 19% (단측 95%).
  - 없는 말: 정밀한 비율. multiuser 의 R0/F0 처럼 안내문이 덧붙는 것 자체는 이 계획이 재지 않는다. 그것은 finding 이 났을 때 제품이 붙이는 대체 문구이고, L3 가 고치는 중이다. 이 계획은 finding 이 나는 빈도를 잰다.

## 2. 첫 턴 cold/warm 지연 probe (`proofs/decision-real-measure/turn-context-latency/`)

`node scripts/egdesk-turn-context-latency-plan.mjs [--write | analyze <rep-1> <rep-2>]`, 모듈 `helper/egdesk-turn-context-latency-plan.mjs`, 테스트 2개.

**러너 기능 추가 (`7ebdabd`, 테스트 2개):**
- 요청별 `waitBeforeMs` (0~120,000 ms, 합계 ≤ 600,000 ms). 보내기 전의 멈춤이고 재시도가 아니다. 실패하면 그 뒤 요청은 기다리지도 보내지도 않는다. dry run 은 기다리지 않는다.
- 계획 단위 `transport: "product"`. 브리지가 쓰는 제품 Decisions transport (`createDecisionTransport`: keep-alive pool, 55 s idle 창, 재시도 없음, 리다이렉트 거부) 로 보낸다. 전송할 때만 만들고 끝나면 닫는다.
- 요청마다 보내기 직전에 제품의 `warm()` 값(`warmBefore`) 을 기록한다. 이것이 제품이 쓸 예산(800/1,500 ms) 을 정한다.
- transport 의 데이터 없는 trace 에서 소켓 재사용과 dns / connect / tls / 응답 시점을 ms 로 기록한다. 숫자만 남긴다.
- 기존 보장은 그대로다: 고정 엔드포인트, `--send` + 환경변수 키만, 바이트 그대로 + 재해시, 재시도 없음, 첫 실패에서 정지, 토큰 상한.

**probe:**
- 조건은 네 가지다:
  - a: 새 프로세스의 첫 요청
  - b: 바로 다음
  - c: 20 s 뒤 (55 s idle 창 안)
  - d: 70 s 뒤 (idle 창 밖)
- 2회 반복이다. a 는 새 프로세스여야 하므로 반복마다 따로 실행한다 (`rep-1/plan.json`, `rep-2/plan.json`, 각 4요청, 대기 90 s).
- 본문은 제품 `prepareTurnContext` 가 만든 turn_context (`answer_type`, `time_intent`, `rel_0`) 다. 카탈로그는 같고(제품처럼 캐시되는 앞부분) 메시지는 8개가 모두 다르다. 같은 본문은 하나도 없다.
- 기록만 한다 (`recordOnly`). `analyze` 는 요청마다 elapsedMs, warmBefore, 소켓 재사용, connect/tls, 서버 처리 ms, 캐시 토큰을 내고, 800 / 1,500 / 제품이 고를 예산 안에 들었는지를 판정한다.
- **크기:** 추정 **5,252 토큰** (반복마다 약 2,630, 상한 각 3,000). 10% 를 더해도 6k 안이다.
- **한계:**
  - 본문은 카탈로그 1개짜리 최소 turn_context 다. c20/c21 의 첫 턴은 약 2.5k 토큰 본문이었다. 이 probe 는 연결 비용(cold vs warm) 을 재지, 본문 크기 효과는 재지 않는다. 서버 처리 시간은 지금까지 크기와 거의 무관하게 170~260 ms 였다.
  - 반복은 2회뿐이라 분포가 아니라 조건 간 차이(수백 ms 단위) 만 보인다.
- **보내는 법 (Main):** 반복마다 따로 실행한다.
  ```
  node scripts/egdesk-decision-real-measure.mjs proofs/decision-real-measure/turn-context-latency/rep-1/plan.json --send --out <rep-1.json>
  node scripts/egdesk-decision-real-measure.mjs proofs/decision-real-measure/turn-context-latency/rep-2/plan.json --send --out <rep-2.json>
  ```
