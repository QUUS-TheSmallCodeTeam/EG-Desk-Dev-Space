# L1 cycle 8: 다중 사용자 presence (공용 Board)

브랜치 `lane/c8-presence` (base `int/c11` edbec8b), 커밋 `b0022f8`.
모든 관찰은 **loopback + 합성 참가자**다: 실제 joint store(SQLite 파일), 127.0.0.1 소켓 위의 실제 HTTP 핸들러, 실제 presence 허브, 실제 joint client와 presence 모듈. 사람·Desk(오프셋, 화면 영역, 포커스)·시계는 합성이다. 설치 앱, 외부 네트워크, 원격 인프라는 쓰지 않았다.

## 1. canon에서 읽은 것
- Contract 12.2 데이터 범위 2항: "개인 카드 배치·카메라, 미전송 초안과 사이트 쿠키는 공용 상태에 넣지 않는다."
- 같은 절 3항: "선택적 일시 신호(설계 후보): 접속 표시나 커서는 권한 범위 안에서 일시적으로 보낼 수 있다. 저장되는 Board 상태나 업무 완료 증거가 아니며 없어도 공동 작업은 가능하다."
- Atlas `atlas-org-workspace-data`: "각자의 화면 배치·카메라 … 는 공유하지 않는다." 접속 표시·커서는 아직 제공하지 않는 항목으로 적혀 있다.
- 협업 설계 문서: "자기 확대율·카메라는 개인 상태다. 따라보기는 시점 표시만 연결한다."
- 12절: 원격 협업 인프라 선택은 명시적 사용자 승인 대상.
- **canon은 "내 보는 영역 공유"의 기본값을 말하지 않는다.** 그래서 기본값은 꺼짐으로 두었고 아래 5절에 소유자 결정으로 올린다.

## 2. 만든 것
**서비스 (`helper/egdesk-joint-presence.mjs`, 경로 `POST /v1/joint/presence`)**
- 프로세스 메모리만 쓴다. 허브가 받는 것은 읽기 전용 좌석 확인 함수 하나(`store.presenceAccess`, SELECT만)뿐이라 원장·카드 위치·배치·DB를 쓸 방법이 없다.
- 공유 수준은 참가자·Board별로 매 요청에 실린다: `off`(기본, 아무것도 저장하지 않고 기존 기록을 즉시 철회) / `active`(여기 있음 + 입력 후 경과 시간만) / `region`(보는 영역 사각형 + 포커스 카드 추가).
- 닫힌 필드만 받는다(`board, share, inputAgeMs, viewport{x,y,width,height}, focusCard`). 그 밖의 키는 400이라 제목·본문·URL·포인터 좌표가 들어갈 자리가 없다. 본문 한도 2KB.
- 사각형은 Board가 카드 위치에 쓰는 공용 좌표(내 캔버스 좌표 − 내 Board 오프셋)이고 40 단위 격자로 **바깥쪽** 반올림한다(실제 영역을 항상 덮고, 격자보다 가는 움직임은 나가지 않는다). 입력 경과 시간은 5초 단위, 상한 5분.
- 권한: 계정 키 인증(기존) + 해당 Board 좌석. 읽을 때마다 발행자의 좌석 epoch을 다시 확인해 탈퇴·제외된 참가자는 만료를 기다리지 않고 즉시 사라진다. 비참가자와 모르는 Board는 같은 404를 받는다.
- 포커스 카드는 발행자가 그 Board에서 볼 수 있는 카드만 보관하고, **읽는 사람도 그 카드를 볼 수 있을 때만** 전달한다.
- 참가자 별칭은 `m-`+16자리 hex(Board·프로세스별 HMAC). 계정 ID가 아니고, Board 사이에서 대조할 수 없고, 재시작하면 바뀐다.
- 속도 제한: 참가자·Board당 1초에 한 번(429). 철회(`off`)만은 제한 중에도 기록을 지운다.
- loopback 서비스에는 기본으로 붙고, TLS(망에서 닿는 주소) 서비스에는 운영자가 `presence: true`를 줘야만 붙는다(CLI에는 없음).

**클라이언트 (`overlay/resources/EGDeskJointPresence.sys.mjs`)**
- `presence.snapshot()` → `[{ member, self, active, viewport, focusCard, lastInputAgeMs }]` (키와 순서 그대로).
- 첫 행은 본인이며 단일 사용자 provider의 행을 그대로 쓴다(네트워크에 의존하지 않음). 나머지는 이 Desk에 열린 공용 Board들의 참가자 중 공유를 켠 사람이다. 사각형은 내 Board 오프셋을 더해 **내 캔버스 좌표**로 바꾸고, 포커스 카드는 내 Desk의 별칭(기본: view id)으로 바꾼다.
- 내 영역은 내 화면이 그 Board의 영역과 겹칠 때만 나간다. 내 Desk의 다른 곳을 보고 있으면 `region`이어도 사각형·카드 없이 "활성"만 나간다.
- `EGDeskJointBoardClient`에 `presence(body)` 호출을 추가했다. Board 액션이 아니다(요청 ID 없음, view 적용 없음, 재시도 없음). 실패해도 공용 Board를 닫거나 초기화하지 않는다.
- `EGDeskJointBoardView.createUI`가 `jointDesk.presence { snapshot, share, setShare }`를 내놓는다. 호스트가 본인 행(`h.selfPresence`)을 주기 전에는 요청을 하나도 보내지 않는다.

## 3. 오래된 기록 처리와 근거
| 경계 | 값 | 근거 |
|---|---|---|
| 발행 주기 | 3초 | 공용 Board의 기존 재조회 주기와 같다(추가 타이머 없음) |
| 비활성 전환 | 10초 | 주기 3초 + 기존 요청 타임아웃 7초. 느리거나 한 번 놓친 발행으로는 뒤집히지 않는다 |
| 삭제 | 30초 | 비활성 뒤 마지막 영역을 잠시 알려 주되 서비스 메모리에서 지운다 |
| 입력 기준 활성 | 60초 미만 | 발행은 계속하지만 손을 뗀 사람은 "있지만 비활성"으로 나온다 |
- 읽는 쪽도 같은 경계를 자기 시계로 적용한다. 연결이 끊긴 사람의 화면에서 다른 참가자가 계속 활성으로 남지 않는다(10초 뒤 비활성, 30초 뒤 사라짐).

## 4. 공유를 끈 참가자는 어떻게 보이나 (결정)
- 보는 영역 공유가 꺼진 상태는 둘로 나뉜다. **`off`(기본): 다른 참가자에게 전혀 보이지 않는다.** `active`: 활성으로 보이되 사각형과 카드는 없다(`viewport: null, focusCard: null`).
- 기본을 "전혀 보이지 않음"으로 둔 이유: canon이 접속 표시 자체를 선택적 일시 신호 후보로 두고 있고, 현재 제품에서 개설자가 아닌 참가자는 참가자 명단도 받지 않는다. 동의 없이 "지금 접속해 활동 중"을 알리면 지금 서로 아는 것보다 더 많이 알리게 된다.
- **인터페이스 주의(L4):** 다른 참가자의 `viewport`는 `null`일 수 있다(active 수준, 또는 그 Board를 보고 있지 않을 때). 본인 행의 `viewport`는 항상 사각형이다.

## 5. 소유자 결정이 필요한 것
1. **기본 공유 수준.** 지금은 `off`. 이 상태에서는 다중 사용자 provider가 본인 행만 돌려준다. `active`를 기본으로 하면 heartbeat가 "다른 활성 참가자가 있다"는 것까지는 기본으로 알 수 있다.
2. **설정 화면과 문구.** 켜는 UI를 만들지 않았다(새 사용자 문구 없음). 지금은 코드에서 `jointDesk.presence.setShare(boardId, level)`로만 켤 수 있어 제품에서는 아무것도 나가지 않는다.
3. **설정 보관 위치.** 지금은 창 메모리뿐이라 재시작하면 `off`로 돌아간다. Desk 개인 설정에 저장할지 결정이 필요하다(훅 `initialShare`/`onShareChange`는 있다).
4. **망에서 닿는(TLS) 서비스에서 presence를 켤지.** 원격 인프라 승인 대상이라 꺼 두었다.
5. **포커스 카드의 전달 형식.** 서비스가 보내는 값은 카드 ID다(읽는 사람이 이미 가진 ID만 전달). 화면에 나오는 `focusCard`는 각자의 로컬 별칭이다.

## 6. L4에 넘기는 연결점
- 단일 사용자 provider의 본인 행을 `h.selfPresence = () => single.snapshot().find(r => r.self)`로 넘기면 3초 주기 교환이 시작된다. surface는 건드리지 않았다(L4 영역).
- 카드 별칭이 view id가 아니면 `h.presenceCardAlias(boardId, cardId)` / `h.presenceCardId(alias)`로 바꿀 수 있다.
- 한계 하나: 공용 좌표는 같아도 **카드 배치는 사람마다 개인 포즈**다. 다른 참가자의 사각형이 내 Desk에서 같은 카드를 가리키는 것은 공용 위치에 놓인 카드에 한해서다. 사람을 넘어 믿을 수 있는 신호는 `focusCard`다.
- 한 사람이 두 Board에 있으면 별칭이 Board마다 달라 두 행으로 보인다(대조 불가가 의도).

## 9. 철학 점검
"초대받은 사람이 내 작업 영역을 방해하지 않고 내 공간의 다른 곳에서 일한다"를 판단하려면 누가 활성이고 어디를 보는지가 필요하다. 이번 변경은 그 사실을 각자가 켠 만큼만, 내용 없이, 잠깐만 알린다. 개인 카메라와 배치는 여전히 개인 상태이고 공용 원장은 한 글자도 바뀌지 않는다.
