## 1. 실제 엔진 대화 스크립트 4개 (L5 하네스용)

위치: `scripts/real-engine/scripts/real-engine-{correction,why-stopped,terse-yes,topic-return}-v1.json`

- **형식:** L5의 형식(`lane/c22-real-engine-check`의 `validateEngineScript`)이다.
- **내용:** 사람의 실제 턴 패턴에서 가져와 마스킹하고 다시 쓴 것이다. 폴더 내용은 합성이다. 기대는 코드로만 확인한다.
- **L5 검증기:** 세 개는 그대로 통과한다. `why-stopped`는 새 필드 `whileRunning` 하나만 거부된다. 그 필드를 뺀 나머지는 유효하다.

| 스크립트 | 패턴 | 흐름과 코드 기대 |
|-|-|-|
| `correction` | 작업 도중 정정 | 단가표를 읽고 "모듈 이름만" → 이름 3개가 답에 있음. "아니, 이름이 아니라 단가를 말한 거야" → 답에 12,000 / 8,500 / 4,200이 있음 |
| `why-stopped` | 긴 명령 도중 "왜 멈췄니?" | `sleep 15 && echo build-finished` 실행(egdesk_run_command, commandsRan, 답에 build-finished, turnStatus completed). 4초 뒤 "아니 지금 왜 멈췄니?"를 run 도중에 보냄 → 답이 게시되고 네이티브 도구는 쓰이지 않음. 명령이 중단되지 않고 끝나는지로 "질문이 run을 멈추지 않는다"를 확인한다. |
| `terse-yes` | 제안 뒤 "ㅇㅇ" | 완료된 항목을 지울 후보만 먼저 알려 달라고 함 → 파일이 그대로이고 undo 기록 0. 그다음 "ㅇㅇ" → 편집 도구 사용, 파일이 `- [ ] 일정 확인`만 남고 undo 기록 1 |
| `topic-return` | "아까 그거 다시" | 첫 파일을 읽고(납기 12월 20일) 둘째 파일로 넘어갔다가(출하 1월 15일), "아까 그거 다시. 첫 번째 파일에서 납기가 언제라고 했지?" → 답에 12월 20일이 있고 1월 15일은 없음 |

**`whileRunning` (새 선택 필드)**
- **형태:** `"whileRunning": { "afterMs": 4000 }`
- **의미:** 이 턴의 `say`는 **앞 턴이 아직 일하는 동안** 보낸다. 시점은 앞 턴이 시작한 뒤 afterMs가 지난 때이고, 앞 턴이 끝난 뒤가 아니다.
- **전제:** L2의 플래그 `EGDESK_INRUN_MESSAGES=on`이 필요하다. 보낼 때는 `inRunMessageTo`에 그 run의 runId를 넣는다.
- **L5에 전한 것:** L5(task `xby7Po4HEq1Vd3Kb`)에 메시지로 보냈다.
  - 제안한 의미는 위와 같다.
  - 첫 턴에는 쓸 수 없다.
  - 대화 플래그에 `EGDESK_INRUN_MESSAGES=on`이 없으면 검증기가 거부하도록 제안했다.
  - 두 턴이 모두 끝나기를 기다리라고 제안했다.
- **why-stopped의 추가 조건:** 플래그 `EGDESK_CONVERSATION_FLOW=on`과 `EGDESK_DRAFT_CHECK=on`이 필요하다(답이 held로 게시된 heartbeat 메시지이기 때문). 그래서 이 스크립트는 `--decisions`와 키가 필요하다.

**테스트** (`helper/egdesk-real-engine-conversation-scripts.test.mjs`): 변이 5건이 모두 잡혔다.
- L5의 검증기는 아직 병합 전이라 import하지 않고 형식 규칙을 다시 적었다.
- 확인하는 것: 형식, whileRunning의 규칙(뒤쪽 턴만, afterMs 범위, 플래그 필요), 세 패턴의 핵심 기대, 스크립트 안에 비밀값 없음.
- 변이: 플래그 제거, 명령이 nudge보다 먼저 끝남, "ㅇㅇ" 전에 편집, 둘째 파일 허용, 이메일 삽입. 마지막 변이는 처음에 문자열이 맞지 않아 적용되지 않았고, 다시 적용해서 잡혔다.
