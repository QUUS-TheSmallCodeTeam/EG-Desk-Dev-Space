### 요청 자체로 확인한 것(모델 답과 무관)
- 해지 링크 + 제출 버튼만 있는 페이지, 2단계 인증 페이지: 요청의 `next_step` 선택지는 고정 옵션 5개뿐이고 요소는 0개다. `step-only-human-controls` 본문에는 `구독 해지`, `제출`, 해지 주소가 **문자열로도 없다**.
- 두 사업자 페이지는 기록 유무와 상관없이 질문·선택지가 바이트까지 같고, 기록은 evidence만 더한다(`it is listed now as [L2] …`).
- 재개 요청은 닫힌 일시정지 코드와 답장만 담는다(페이지·사이트 없음). 본문에 키·이미지 없음, 호스트는 합성 두 개뿐.

### 계획을 만들며 드러난 점(실측 전)
1. 재개 요청은 "무엇을 물었는지"를 싣지 않는다(`Paused because: need_context (choice_needed)` + 답장). "두 번째 사업자로"가 질문 없이 판정된다. resume-answer가 이 설계를 시험한다.
2. 기억 packet에는 L7의 시계 줄이 들어가며 거기에 **이 기기의 UTC offset(540분)** 이 포함된다(`entry-with-prior`, `step-two-businesses-prior`). 제품의 평소 동작이지만 실측 본문에도 실린다. 다른 시간대의 기기에서 다시 만들면 그 두 본문의 sha가 달라진다.
3. "요청에 위험 라벨이 없다"는 이 합성 페이지에서는 문자열 수준으로 성립한다. 제품이 보장하는 것은 **선택지에 없다**는 것이고, 실제 페이지의 보이는 본문에 같은 글자가 있으면 evidence 본문에는 들어갈 수 있다(선택은 불가).
4. 단계 evidence에서 기억 packet은 한 줄로 접힌다(`compactText`). 읽을 수는 있으나 줄 구조가 사라진다. step-two-businesses-prior가 이 형식을 시험한다.

`node scripts/egdesk-decision-real-measure.mjs <plan.json>`은 dry run(검증·표 출력, 전송 0). 실제 전송은 `--send` + 환경변수 키가 있어야 하며 이번 사이클에서는 하지 않았다. 계획 재생성: `node evidence/l8-c14/build-plan.mjs`.

## 3. 병합된 기억 코드 재확인 (onePacket, at-page)
- 두 스위치는 일반(제한되지 않은) 턴의 경로에만 걸린다: `memoryTurn = !bounded && …`, at-page는 turn memory `on` + 쓰기 경로가 있을 때만. 브라우저 `on` 턴은 제한된 턴이고, 내 훅은 `prepareTurnMemory`를 직접 부르며 결과 기록은 `adapter.writerFor`로 간다.
- 새 테스트 C14(실제 `CodexChatRuntime.send`, turn memory `on` + `onePacket: true` + `speechDesign: 'at-page'`, 같은 저장소에 참조만 가진 발화 페이지 1개): 1개월차 결과 페이지가 본문을 가진 `agent_note`로 저장(참조로 바뀌지 않음), 새 런타임의 2개월차에서 훅이 그 페이지를 본문과 함께 받고 질문 없이 완료(브라우저 Decisions 4건, 이동 2), 제한된 턴의 입력에는 작업 노트만 있고 기억 packet 키·합쳐진 packet 없음.
- 새 테스트 W7(배선 수준): 참조만 가진 발화 페이지와 같은 파일에 있어도 훅은 결과 페이지만(본문 포함) 돌려주고, 풀리지 않은 참조의 글은 packet에 없다.
- 관찰(내 레인 밖, 수정하지 않음): `createTurnMemoryConfig({ onePacket })`은 인자를 받지만 돌려주는 설정에 `onePacket`을 넣지 않는다(해당 파일에 그 이름이 서명에만 한 번 나옴). 런타임은 `decisionContext.turnMemory.onePacket`을 읽으므로 이 인자로는 켜지지 않는다. 테스트에서는 런타임이 읽는 자리에 직접 넣었다. L7 확인 필요.
