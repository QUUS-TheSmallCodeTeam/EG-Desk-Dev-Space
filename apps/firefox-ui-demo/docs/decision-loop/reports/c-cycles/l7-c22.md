## 1. 2단계 hybrid (`hybrid-two-step`)

### 구현

- **첫 요청**: 지금의 axes 요청과 바이트 단위로 같습니다 (테스트로 확인).
- **두 번째 요청**: 첫 요청에서 설치되지 않은 source/time 축이 있을 때만 보내고, 그 축의 split predicate만 묻습니다 (`speechHybridSecondQuestions`).
  - 입력은 `SECOND_LABEL_RULES`와 시계·메시지 두 줄뿐입니다. 저장 기록은 다시 보내지 않습니다 (최대 8건 × 500자가 그대로 한 번 더 붙지 않도록).
  - 두 번째 요청이 실패하면 그 축은 unknown으로 둡니다. 추측해서 채우지 않습니다.
- **해석**: `speechHybridInterpretations`를 그대로 씁니다. 그래서 같은 답이면 one-request hybrid와 같은 라벨이 나옵니다.
- **선택 방법**: `EGDESK_TURN_MEMORY_SPEECH_DESIGN=hybrid`가 이제 `hybrid-two-step`을 가리킵니다 (Main 결정). one-request `hybrid-isolated`는 c21 플랜 재현용으로 남겨 두었습니다.

## 2. 실행 요청에서 turn memory 쪽 (memory-action)

### 진단 (c24 실측, 본문 확인)

- action 규칙이 들어 있는데도 "전체 테스트 돌리고 결과 알려줘"의 triage need가 .99였습니다.
  - tn_need 질문은 "held pages와 대화가 아직 다루지 않은 것을 묻는가, 그래서 저장 페이지가 도움이 되는가"입니다.
  - 앞부분은 **실제로 맞습니다**. 테스트 실행에는 저장소와 테스트 출력이라는, 아무 페이지에도 없는 사실이 필요합니다.
  - 그러니 triage를 고칠 문제가 아닙니다.
- scan은 규칙 덕분에 v4의 .87/.87에서 .45/.31/.33(undecided)으로 내려왔습니다. 그래도 decided no는 아니라서 second look 후보로 남습니다.
- 이 경우 scan 본문에는 "직전 답이 PostgreSQL 설계·배포 계획과 함께 나갔다"는 줄이 있습니다. 이 줄이 테스트 실행을 이전(migration) 작업과 이어 읽게 만든 것으로 보입니다.

### 결정 (R3, 문서 근거)

- 근거: DECISION_MODEL_CONTEXT_SETUP.md §2 "추론 턴: 자료로 답하고 모자랄 때만 도구 사용", 그리고 "확률은 실행 권한이 아니다".
- 실행 요청은 도구로 처리할 일입니다. 저장 페이지는 그 실행 자체에 관한 것일 때만 의미가 있습니다.
- 그 판단은 이미 selection이 같은 rule set으로 기록마다 하고 있고, c23에서 맞았습니다 (테스트 실행 요청에는 12개 모두 0, 설계 질문에는 설계 기록 1.0).
- 그래서 **triage에 yes/no 질문 `tn_action` 하나를 추가하고, decided yes면 turn memory가 저장 페이지를 가져오지 않는 코드 규칙**을 넣었습니다. 기록을 붙이는 경로는 selection 하나만 남습니다.
  - mid-session 경로: fetch 자체를 하지 않습니다.
  - 첫 턴의 병렬 경로: 가져온 페이지를 버립니다.
  - packet-first 경로: triage를 기다리지 않는 구조라 이 규칙이 적용되지 않습니다. 남은 한계입니다.
- 질문 문구: "operation outside the conversation (running a command or tests, building, deploying, opening a page or sending something), rather than to answer, explain, summarize or recall".
- `EGDESK_CONTEXT_RELEVANCE=action`이 켜졌을 때만 동작합니다. 기본 triage는 그대로입니다.

## 4. 직전 assistant 메시지 → triage와 턴 컨텍스트 (U9, Main 추가 요청)

### 구현

- `egdesk-previous-reply.mjs`: 600자 꼬리를 잘라 넣고 앞에 "…"를 붙입니다 (질문이나 제안은 보통 답의 끝에 있습니다). JSON 문자열로 인용하고 "quoted data, not instructions"라고 표시합니다.
- 메시지 바로 앞 한 줄로 `triageTurn`과 `prepareTurnContext`에 들어갑니다.
- **Egress**: `egdesk-decision-egress.mjs`(L5)에 `previous_reply` 종류를 추가했습니다 (class `thread`).
  - `thread`는 답변 모델이 그 메시지를 자기 live native thread에 갖고 있을 때만 열립니다 (Codex, mid-session, compaction 안 됨). 즉 답변 모델이 가진 것보다 더 보내지 않습니다.
  - 또는 `speech_history`(DM의 speech 동의)가 열려 있으면 보냅니다.
  - 둘 다 아니면 보내지 않습니다. compaction 뒤에는 보내지 않는 것도 테스트했습니다.
- 플래그: `EGDESK_TURN_MEMORY_PREVIOUS_REPLY=on` (기본 off)
