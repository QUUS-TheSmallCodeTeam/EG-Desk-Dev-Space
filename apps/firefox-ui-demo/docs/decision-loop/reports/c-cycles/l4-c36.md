## 2. 수정
- 같은 coverage 요청 안에서, 코드 앵커가 없는 사실(`cites null`)마다 `stated_F#` 질문을 하나 더 함: "이 문장이 위에 인용된 자료가 말하는 것을 다시 말하는가? (어시스턴트가 한 일, 답변의 구성, 하지 않은 일만 설명하는 문장은 아님)". 자료는 요청에 한 번만 인용(`The materials, each quoted as JSON`), 새 규칙 문구 `coverage_stated`(onboard만 있는 요청의 기존 문구는 그대로). 새 요청 없음, 이미 쓰는 자료 클래스(memory_page)만 사용.
- 결정: onboard가 "아니오"여도 stated가 확정 "아니오"(<= .3)이면 `unshowable`(기록만, 차단 아님), stated가 "예"이거나 불확실이면 지금처럼 강제(`missing` -> 한 번의 재작성 -> 채팅). 방향은 보수적: 판정기가 확신할 때만 면제. 둘째 질문(재확인)은 놓친 사실만 묻고 stated는 다시 묻지 않음.
- 사실 레코드에 `stated` 확률이 남음(hook의 `decisions[].p`에 `stated_F#`로도 보임; 입력 기록 상한은 자료가 들어가서 3,000 -> 6,000자).
