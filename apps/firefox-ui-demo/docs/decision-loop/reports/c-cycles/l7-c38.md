# L7 c38: 기억 층을 엔진보다 먼저 확정 (memory first)

기준: int/c14 = `cbad751` (c36, c37 병합 포함). 플래그 `EGDESK_TURN_MEMORY_WRITE_FIRST=on`, 기본 꺼짐. 실제 전송, 실제 엔진은 돌리지 않았습니다 (Main 실행).

## 1. 원인 (L1 층 감사 ②, check-27mw)
`startTurnMemoryWrite`(기록 판단)는 엔진 답이 끝난 뒤에 돕니다. 그래서 own-confirm 2턴에서 엔진은 기록이 판단되기도 전에 "신제품 리뷰 회의는 다음 주 화요일로 확정됐군요."라고 말했고, 같은 사실이 기록에는 확인 전 읽기(pending)로만 남았습니다. 엔진의 말이 기록을 앞질렀고, `RECORDING_RULE`은 "답 뒤에 EG-Desk가 정한다, 기록했다고 말하지 마라"까지만 말해 줍니다. 두 상태(기록은 미정, 말은 확정)의 충돌도 아무도 판단하지 않고 엔진이 문장 속에서 처리했습니다.

## 2. 만든 것
- **턴 시작에 같은 판단을 앞당김** (`helper/codex-chat-runtime.mjs`: `startWriteFirst`, `awaitWriteFirst`): 메모리 루프가 끝난 바로 뒤, 같은 코드와 같은 질문(`judgeWrite`: 분류, 대상, 문장별 라벨)으로 기록 판단이 돌고, 기존 기록의 상태 변경이면 그 자리에서 **pending 읽기로 저장**합니다 (같은 writer, 같은 operationId, 같은 canWrite 검사. 상태는 절대 바뀌지 않음, promote는 사람의 다음 확인 말로만). 답 뒤 경로(`runTurnMemoryWrite`)는 그 결과를 쓰고 다시 묻지도 저장하지도 않습니다 (판단 1회, 저장 1회).
- **엔진에게 확정된 기억 상태를 줌** (`helper/egdesk-record-settled.mjs`): `egdesk_recording` 키가 "답 뒤에 정한다" 규칙 대신 이미 정해진 상태를 전합니다: 무엇이 어떤 상태로 남았는지(확인 전 보고, 정정, 새 확인 전 기록, 기록 안 함), 이번 턴 시작에 사람이 확인/거절한 것(기존 `confirmNotedRecords` 결과), 기록 상태는 그대로라는 것. 끝에 "이 상태를 따라 말하라, 사람에게 확인을 묻지 마라, 보고를 확정이라 부르지 마라"가 붙습니다 (엔진용 상태 문장이고 사람에게 보이는 새 문구가 아닙니다: 사람이 보는 말은 엔진이 사람의 언어로 씁니다). 이번 턴에 이미 말한 보고는 `offered`로 등록되어 다음 말 "응 맞아"가 바로 확인이 됩니다 (기존: 상태를 말하는 턴이 하나 더 필요했음).
- **충돌 쌍 판단** (`judgeRecordConflict`): 판단이 기존 기록을 겨냥할 때만, (기록 문장, 말) 한 쌍에 yes/no 한 질문(`cf_differs`: 말이 기록과 다른 상태나 다른 날짜를 말하는가). yes면 `conflict`로 표시: 엔진에게는 "기록은 이렇고 사람은 이렇게 보고함, 둘 다 둔다: 기록은 그대로, 말은 확인 전 보고"로 전하고, 사람에게 새로 묻는 문구는 없습니다. 정정(superseded)은 정의상 충돌이라 따로 묻지 않습니다. 호출 실패는 `unknown`(충돌 표시 안 함).
- **지연 예산 (엄수)**: 쓰기 판단을 기다리는 시간은 루프의 상한 안(따뜻한 턴 2.5초, 차가운 첫 턴 4초)까지만이고, 그 안에 못 끝나면 **오늘과 똑같이** 진행합니다 (엔진은 `RECORDING_RULE`, 쓰기는 답 뒤, 같은 결과 재사용으로 호출 중복 없음; 시험 있음). 기록할 말이 아닌 턴(분류가 no)은 추가 호출이 없습니다.
- **L1 열린 항목 해소기를 위한 읽기 전용 호출** (중복 판단 없음): `openMemoryItems(conversationId)` (사람에게 말했고 아직 확인을 기다리는 노트: 종류 `memory_confirm`, id와 닫힌 단어만), `memorySettledFor(run|context)` (이번 턴에 정해진 것: 제목/본문 없음). 확인/거절 판단 `rc_*`은 그대로 `confirmNotedRecords`에 있고 promote 권한도 거기(사람 본인의 다음 말)에만 있습니다. L1(DzABESZ2DPhqdzhj)에게 알렸습니다.
- 초안 점검 증거(`turnMemoryDraftEvidence`)에도 같은 확정 상태가 들어가서, 엔진이 "확인 전 보고로 적어 뒀어요"라고 말한 것이 거짓으로 걸리지 않습니다.
- 영수증(`turnMemoryWriteReceipts.writeFirst`): settled, inTime, sent, ms, kind, conflict(yes/no/unknown), conflictP, confirmations (닫힌 단어와 숫자만).

## 4. 실제 엔진 비교 대본 `real-engine-memory-first-v1` (Main 실행)
- 같은 write-v3 픽스처와 플래그(hybrid-ask, own v4, confirm v2)에 `EGDESK_TURN_MEMORY_WRITE_FIRST=on`만 더한 대화:
  - `own-confirm-off`: write-v3 own-confirm 그대로(기준선, 4턴).
  - `own-confirm-first`: 2턴 "아 그거 다음 주 화요일로 확정했어" → pending 읽기(출처 self_reported_observation, 상태 plan/done, 기록 unknown), **`settled: true`**(엔진 시작 전에 정해져 엔진이 받음), **`conflict: true`**(기록은 미정, 말은 확정), 답에 `확정됐/확정되었/확정 완료/확정이군요/확정이네요` 없음(check-27mw의 실패 문장); 3턴 "응 맞아" → accepted, confirmed, 기록 상태 plan/done (v3은 4턴째).
  - `control-first`: 기록에 동의하는 말("…아직 안 정해졌지?") → 읽기 없음, 새 페이지 0, 충돌 표시 없음.
  - `hedged-first`, `relayed-first`: write-v3의 hedged, relayed 기대값 그대로 (느슨하게 하지 않음).
- 새 기대 키(`expect.recording.settled`, `conflict`)는 플래그가 켜진 대화에서만, 엄격한 불리언만 허용됩니다 (검증기 시험 있음). 값은 제품의 영수증에서 코드가 읽고, 모델에게 묻지 않습니다.
- 명령 (write-v3와 같은 구성): `node scripts/egdesk-real-engine-check.mjs --codex-bin <bin> --person-home --decisions --persisted-with-cleanup --run --out <dir> --script scripts/real-engine/scripts/real-engine-memory-first-v1.json`
  비교: `node scripts/egdesk-memory-first-compare.mjs <records dir>` (턴별 엔진 초, 통과 여부, 엔진 시작 전에 정해졌는지와 걸린 ms, 충돌, 답 문장; 2턴 비교와 확인 턴 번호).
- **예상 (추정, 측정 아님)**: 정해진 상태가 오면 엔진 2턴 답은 "확정됐군요" 대신 "확인 전 보고로 적어 뒀어요" 계열이 됩니다(엔진이 지시를 따르는 한; 실패하면 `answerExcludes`가 잡음). 2턴 엔진 초는 같거나 약간 늘 수 있고(입력에 상태 몇 줄 추가), 턴 시작 지연은 기록할 말이 있는 턴에서만 판단 호출 약 2~3번(쓰기 판단 1, 두 번째 라벨 1, 충돌 1; Decision 중앙값 0.30초) 약 0.6~0.9초가 루프 뒤에 더해집니다. 상한(2.5/4초) 안에서만 기다립니다. 확인까지 걸리는 턴 수는 4 → 3.

## 5. 한계와 하지 않은 것
- 새 페이지(new_page) 저장은 기존처럼 답 직후 경로에 둡니다 (발화 라벨을 답 뒤에 설치하는 `at-page` 설계와 얽혀 있어 앞당기면 같은 발화가 두 번 기록될 위험). 엔진에게는 발화 동의와 쓰기 범위가 있을 때만 "새 확인 전 기록으로 둠"을 전하고, 없으면 "기록 없음"을 전합니다.
- 충돌 판단은 변경 대상이 정해진 판단에만 있습니다. 링크가 없는 모순 전반(M4의 두 기록 사이 모순)은 이번에 다루지 않았습니다.
- 지시어("방금 그 내용") 해소(M-e)와 "기록만으로 답이 충분한가"(M-f)는 하지 않았습니다. 병렬화(대상 판단과 충돌 질문을 한 요청으로 묶기)로 0.3초쯤 더 줄일 여지가 있으나 이번에는 기존 판단 코드를 바꾸지 않았습니다.
- hedged 턴 180초 정지는 엔진 쪽 "accepted, then silent"이고 L5가 감시 장치를 만드는 중이라 손대지 않았습니다.
