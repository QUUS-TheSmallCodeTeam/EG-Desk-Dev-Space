## 2. fit 질문 (술어 하나에 조건 하나)

| part | 질문 | 코드 조합 |
|-|-|-|
| compare | `aspect_P#` | 예 → 두 버전 카드가 다 보드에 있으면 `step_pair`, 아니면 `result_compare` |
| sequence | 자료마다 `happened_M#`: "일어났거나 결정된 일을 말하는가" | 예가 2개 이상이면 그 자료들만으로 목록 |
| open items | 계획 자료마다 `todo_M#` | 예가 1개 이상이면 그 자료들로 목록 |
| single | `fact_M#`: "구체적 사실을 하나 이상 말하는가" | 예 → 짧은 텍스트 카드 |
| 이미 카드 있음 | 없음 | 재사용 |

- **버전 판정은 코드다.** `supersedes`/`superseded_by` 링크가 있으면 그것으로, 링크가 없으면 버전 표시(v1/v2, 1차/2차, 버전 1/2)만 다르고 나머지가 같은 제목으로 판정한다.
  - 링크도 제목 근거도 없는 쌍은 비교 후보가 아니다. 그런 쌍마다 "같은 것의 버전인가"를 묻는 술어는 만들지 않았다. 후보가 자료에서 나와야 하고(U2), 아니면 N² 질문이 되기 때문이다. 필요해지면 그 술어를 추가하는 것은 결정 사항이다.
- **"도움이 되는가 / 요청이 필요로 하는가"는 fit에서 뺐다.** 어떤 자료가 답에 속하는지는 상류(L7 관련성 술어, `place`)가 정한다. 이 변경에 따른 행동 변화 두 가지:
  - 상류가 무관한 페이지를 붙이면 그 페이지는 사실을 담고 있는 한 카드가 된다. c14부터 쓰던 mount 테스트에서 L7의 **mock** 판단이 붙인 B사 페이지가 이제 카드 4번째가 된다. 테스트 기대를 그대로 바꾸고 이유를 주석으로 남겼다.
  - 카탈로그가 그릴 수 없는 표 요청을 막는 것은 이제 `place`뿐이다. 그래서 재측정에 넣었다.
- 목록 카드는 1–6줄로 바꿨다(이전 2–6). 열린 단계 하나도 목록이 된다. 순서 part는 코드가 날짜 있는 자료 2개 이상일 때만 만든다.

## 3. 판단 조각의 인용

- **연결 문자열이 생기면 실패하는 테스트를 추가했다.** 판단 대상 조각과 step이 보여주는 내용 어디에도 `제목 본문`이나 `항목 값`이 한 문자열로 나오면 실패한다.
- **날짜 제목은 코드가 대조한다.** `11/06`, `11.6`, `2026-11-06`, `11월 6일` 형식을 자료 날짜 또는 본문의 같은 월·일과 비교한다. 틀린 날짜는 질문 없이 "지원되지 않는 조각"(`P2 line 2`)이 되어 한 번 다시 쓰게 된다.
- **확인하지 않는 것:** 날짜가 아닌 제목은 판단하지 않는다(줄 이름으로만 쓰임). 틀린 제목이 붙을 위험이 남는다.
