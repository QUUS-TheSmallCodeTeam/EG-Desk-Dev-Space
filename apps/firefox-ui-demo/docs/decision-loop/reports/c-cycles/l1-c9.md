# L1 cycle 9: presence를 두 소비자(배치 런타임, 하트비트 청중 규칙)와 통합

브랜치 `lane/c9-presence-integration` (base `int/c12` 2ad24e5), 커밋 `2bfaa37`.
모든 관찰은 **loopback + 합성**이다: 실제 joint store·HTTP 핸들러·presence 허브·joint client·presence 모듈(L1), 실제 `EGDeskWorkPlacement`와 브리지 DTO 검사(L4), 실제 `audienceFacts`와 mock 엔진 위의 실제 chat runtime(L3). 사람·Desk·시계·Decision 모델은 합성이다. 설치 앱과 실제 두 대의 Firefox에서는 확인하지 않았다.

## 1. 호스트 배선 (플래그, 기본 꺼짐)
- **창(surface):** pref `egdesk.presence`가 정확히 `"on"`일 때만 `installDeskPresence()`가 동작한다. 꺼져 있으면 pref 하나를 읽는 것 말고는 아무 일도 없다(`state.presence` 없음, 타이머 없음, 입력 감시 없음). L4의 `workPresence()`는 손대지 않았고 예전처럼 단일 사용자 provider를 돌려준다.
- 켜면: L4의 단일 사용자 provider(이 창의 실제 카메라·viewport·입력)를 그대로 재사용해 본인 행을 만들고, `JointPresence.createDeskPresence`가 **하나의 `state.presence.snapshot()`**을 만든다. 공용 Board 피드에 행이 있으면 그 행(본인 행 먼저), 없으면 단일 사용자 행이다.
- L4 배치 런타임은 이미 `state.presence`가 있으면 그것을 읽으므로 추가 변경 없이 같은 객체를 쓴다.
- L3 청중 규칙은 브리지 프로세스에 있다. 창이 같은 행을 3초마다 `POST /presence/snapshot`으로 보내고, 새 `helper/egdesk-presence-mirror.mjs`가 메모리에 들고 있다가 `conversationFlow.presence.snapshot()`으로 내준다. 브리지 쪽 플래그는 `EGDESK_PRESENCE=on`(기본 꺼짐, 꺼져 있으면 경로는 404). 창이 10초 넘게 보내지 않으면 미러는 `null`을 돌려주고, 청중 규칙은 피드가 없을 때의 기존 동작(존재 여부 unknown)으로 돌아간다.
- 공용 Board 뷰(`createUI`)에는 본인 행(`h.selfPresence`)과 개인 설정 읽기/쓰기 훅을 넘긴다. 본인 행 훅은 플래그가 켜졌을 때만 생긴다.
- 두 소비자의 판단 로직은 수정하지 않았다.

## 2. 필드 불일치와 어댑터 수정
| 항목 | 확인 결과 | 조치 |
|---|---|---|
| `viewport: null`(active만 공유) | L4 `normalizePresence`는 사각형 없는 행을 장면에서 뺀다. L3는 `viewport`를 쓰지 않아 그대로 "있음"으로 센다. | 수정 불필요. 계약 시험으로 고정 |
| **`active`의 의미** | L4 단일 provider는 "입력 후 5분 이내"를 활성으로 본다. 내 피드는 60초였다. 그대로면 61초 동안 읽기만 한 참가자가 비활성이 되어 **그 사람이 보고 있는 화면 안에 배치가 허용**된다. | **피드·클라이언트·미러 모두 5분으로 맞췄다.** 한 스냅숏의 모든 행에서 `active`가 같은 뜻이다. 입력 경과는 5초 단위로 가므로 원격 행은 305초부터 비활성 |
| L4의 idle(20초) | `lastInputAgeMs`에서 계산한다. 원격 값은 5초 단위라 그대로 맞는다. | 시험으로 확인 |
| 별칭 형식 | `m-`+16 hex, 본인 `self`. L4의 별칭 정규식과 최대 8명 제한에 맞는다. | 수정 불필요 |
| 요청자 식별 | L4 `tasks[].requester`와 L3 `audience.requester`는 presence의 member 값을 기대한다. 소유자는 불투명 별칭만 보므로 "누가 물었는지"를 별칭에 묶을 방법이 제품에 없다. | `presence.aliasOn(boardId)` 추가: 각자 자기 별칭을 알 수 있어 요청에 직접 실어 보낼 수 있다. 실제로 싣는 경로는 미구현(5절) |

## 3. 3인 시나리오 (`helper/egdesk-presence-integration.test.mjs`)
소유자 a는 자기 캔버스의 A 영역 (0,0,1280×800)에서 작업. B는 Board 공용 좌표 (2400,200,1200×800)을 본다. C는 다른 곳을 본다.
| 단계 | 스냅숏(소유자 Desk) | 배치 런타임(L4) | 청중 규칙(L3) |
|---|---|---|---|
| 0. 아무도 공유 안 함(기본) | 본인 1행 | 장면 구성원 1 | B·C가 요청자여도 "없음" → 기다리는 사람은 owner |
| 1. B가 `region` 공유 + 파일 점검 요청 | 본인 + B(사각형) | 옵션 `near_requester, quiet, adjacent_area`. **A와 겹치는 옵션 0**, 소유자 카드와 겹침 0. B 화면 바로 오른쪽 (3624,224)에 "B 근처" 옵션, 코드 기본 선택도 그것. 판정기를 거친 `placeSurface`도 같은 자리. 소유자 자신의 다음 표면은 B 화면 밖 | B가 기다리는 사람, 있음 |
| 2. C가 `active`만 공유 | 본인 + B + C(`viewport:null`) | C는 장면에 없음. C의 요청 표면은 소유자 요청과 **똑같이** 배치된다(C 기준 배치 없음, 요청 DTO에 C 별칭조차 없음). B 화면은 계속 보호 | C가 기다리는 사람, 있음(실제 runtime 경로에서도 `waiting_person: requester / present: yes`) |
| 3. B가 발행 중단 | 9초까지 활성, 12초 읽기에서 비활성, 30초 뒤 삭제 | B의 옛 화면 안 배치가 허용으로 바뀜 | B 대신 owner가 기다리는 사람 |
| 4. C가 `off` | 본인 1행 | 구성원 1 | C는 "없음" |
| 5. 창이 미러 전송 중단 | - | - | 10초 뒤 미러 `null` → 피드 없는 기존 동작과 동일 |
- 전 과정에서 공용 원장 파일 해시는 그대로다. 피드 별칭(`m-…`)은 Decision 요청·비트·기록 어디에도 나오지 않는다.
- 경계: 소유자 Desk에서는 10초 안에 비활성이 된다(3초 읽기 주기로 보면 최대 12초 시점에 관찰). 브리지 미러는 여기에 전송 주기 3초가 더해진다.

## 4. 공유 선택의 보관
- 위치: 참가자 자신의 개인 pref `egdesk.jointBoard.presenceShare.v1`(이 프로필). 서비스에는 설정으로 저장되지 않고 공용 원장과 무관하다.
- 형태: `{ [서비스 인스턴스/내 계정]: { [boardId]: { level: 'active'|'region', epoch } } }`. `off`는 값으로 저장하지 않는다(항목 없음 = 꺼짐).
- 좌석(epoch)에 묶인다: Board를 나갔다 다시 들어오면 예전 선택은 이어지지 않고 pref에서도 지운다. 다른 계정, 깨진 pref, 알 수 없는 값은 모두 꺼짐.
- 서비스에서 로그아웃(연결 해제)하면 그 서비스의 선택을 지운다. 연결이 끊긴 동안에는 메모리 선택을 꺼짐으로 두고 재연결 후 다시 읽는다.
- **재시작 시험:** `region`을 고른 뒤 새 세션이 같은 pref를 읽으면 `region`. 읽기만으로는 쓰기 0.
- UI는 만들지 않았다. 지금도 코드(`jointDesk.presence.setShare`)로만 켤 수 있다.

**최소 설정 행에 필요한 문구(제안, 승인 대기):**
| 자리 | 문구 |
|---|---|
| 행 제목 | `내 위치 공유` |
| 선택 1(기본) | `공유 안 함` |
| 선택 2 | `접속 중인 것만` |
| 선택 3 | `보고 있는 영역까지` |
| 선택 1 설명 | `이 Board의 다른 참가자에게 내 접속 여부와 보는 위치를 보내지 않습니다.` |
| 선택 2 설명 | `이 Board에 있다는 것과 마지막 입력 후 지난 시간(5초 단위)만 보냅니다.` |
| 선택 3 설명 | `이 Board를 보는 동안 화면에 보이는 영역의 사각형과 선택한 카드를 함께 보냅니다. 카드 제목·내용, 포인터 위치는 보내지 않습니다.` |
| 범위 안내 | `이 Board의 현재 참가자에게만 보이고 저장되지 않습니다. 보내기를 멈추면 10초 뒤 비활성으로 바뀌고 30초 뒤 사라집니다.` |
| 보관 안내 | `이 선택은 이 기기의 내 설정에만 저장됩니다.` |

## 5. 남은 것 / 다른 레인에 알릴 것
- **요청자와 별칭의 연결 경로가 없다.** 시나리오에서는 B가 자기 별칭을 요청과 함께 넘긴다고 가정했다. 실제 제품에는 (a) 공용 Board 참가자의 요청이 소유자 Agent의 과업이 되는 경로, (b) 그 요청에 별칭을 싣는 자리, (c) L3 `audience` 공급자, (d) L4 `work.requester`를 채우는 곳이 모두 없다. 지금 켜도 요청자는 항상 본인이다.
- L4 동작 참고(수정 안 함): 사각형 없는 참가자의 과업은 요청자를 본인으로 대체해 배치한다.
- L3 참고: `viewport`·`focusCard`는 미러에 그대로 있다(지금은 쓰지 않음).
- 같은 브리지에 창이 둘이면 마지막에 보낸 창의 스냅숏이 남는다.
- `createUI`의 배선은 소스 정규식과 `createShareStore`/`projectionPresence` 단위 시험까지다(전체 호스트를 세워 돌리지는 못했다).
- 사용자 결정 대기 항목(c8의 5개)은 그대로이고 기본값은 계속 꺼짐이다.

## 7. 철학 점검
"어느 과업이 어느 활성 사용자의 어느 화면에 들어가는가"를 세는 두 판단이 이제 같은 사실 하나를 읽는다. 그 사실은 각자가 켠 만큼만 나오고, 켜지 않은 사람은 두 판단 어디에도 없으며, 영역을 주지 않은 사람에 대해서는 아무것도 가정하지 않는다.
