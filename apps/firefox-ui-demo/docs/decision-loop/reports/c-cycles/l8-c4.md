# L8 / C4 분류기 확장 보고

브랜치 `lane/c4-reflex-classifier` (base int/c2 256c816), 커밋 `b88fd49`. 합성 검증만, 실제 Firefox 검증 없음.

## 1. 문제
c3 측정: 위험 same-site 5/30 놓침(/order/place, /grant/allow, /logout, /account/close, /subscriptions/cancel). 원인은 분류기 어휘 공백이다. 확장 측정 세트(href 50 + 50, label 31 + 36)에서 전: href 놓침 16/50(32.0%), label 놓침 12/36(33.3%).
- 어순/복수: "subscriptions cancel", "order place", "account close"는 기존 어휘가 `cancel subscription`/`place order`/`close account` 순서만 가졌다.
- 세션 종료: log out/logout/sign out/로그아웃 어휘 자체가 없었다.
- 권한: 허용 계열이 `allow access`, `권한 허용`뿐이라 "Allow notifications", "알림 허용", "위치 허용", href의 `grant`, `allow`가 none.
- 한국어: `주문 하기`(띄어쓰기), `계정 폐쇄`, `계약 해지`류 일부.

## 2. 패치 (`egdesk-browser-action-classifier.mjs` +21/-9, `egdesk-browser-reflex.mjs` +1/-1)
- 결제(pay): `order place, orders place, order confirm/submit/complete, confirm your order, proceed to payment/checkout, 주문 하기`.
- 권한(grant): `grant, permission grant, allow notifications/location/camera/microphone/permission(s), 알림·위치·카메라·마이크·쓰기 허용, 권한 승인`.
- 삭제/해지(delete 범주; 세션 종료와 계정 폐쇄 포함): `log out, logout, log off, sign out, signout, sign off, close my/your account, account close/closure, 로그아웃, 로그 아웃, 로그오프, 계정 폐쇄, 계정 닫기`.
- 취소(CANCEL_WORDS): 복수형과 역순(`subscriptions cancel, plan cancel, membership cancel, contract cancellation`), `cancel contract/account`, `terminate/end subscription|contract|membership|plan`, `계약·약정·서비스·회원·요금제·정기구독·정기배송·이용권` + 취소/해지/중단/철회/탈퇴.
- href 목적지: 분류기에 `href: true` 사실 추가. 이때만 bare `allow/permit/허용`이 `grant-destination`(링크 목적지는 쿠키 배너 버튼이 아니다). reflex의 href 판정만 이 플래그를 전달한다. 버튼 label의 bare `Allow`/`모두 허용`은 기존 테스트(`Allow` elsewhere = none, 쿠키 배너)가 요구하므로 **그대로 none**이다. 사용자가 요청한 "허용"은 권한 명사와 결합한 형태로 커버했고, bare 허용은 consent 페이지 규칙으로만 grant다.
- 분류기 범주(pay/grant/delete/submit)는 늘리지 않았다. 세션 종료·계정 폐쇄는 기존 범주 `delete`("삭제·해지")에 매핑했고 게이트 정책은 변경 없음(현재 모두 allow 기록용, 추천 프리셋에서 delete=confirm).

## 4. "더 허용적이지 않음" 증거
`classifier-old.mjs`(int/c2)와 새 분류기를 label 15,130 조합(기존 테스트 문자열 전부 + 어휘 36개의 쌍 조합 × role/consent URL/amount/enter 5종)으로 비교: **이전에 none이 아니었는데 none이 된 경우 0건**(`monotonic.json`). 변경 1,643건은 모두 none→위험 범주 또는 위험 범주 간 재분류. 어휘만 더했고 제외 규칙(쿠키 거부, 검색 폼, non-activating role)은 건드리지 않았다.

## 6. 철학 점검
"확률은 실행 권한이 아니다 / 삭제·결제·권한은 사람"(canon §1, §5.2): 모델 확신도와 무관하게 실행 후보 단계에서 분류기가 막고, 판정이 불확실한 쪽(어휘 포함)으로 기울게 했다. 허용 범위는 넓히지 않았고 단방향 검증으로 확인했다.
