### 러너: `productBars` 와 검사 (`b365f2a`)

- 계획에 `productBars: { "<계열 이름(숫자→#)>"|"*predicate"|"*choice"|"*score": { yes?, no?, minConfidence?, minMargin?, source? } }` 를 선언할 수 있다.

  - 점수에 minConfidence 가 막대 미만
  - 막대가 선언되지 않은 계열의 hard 기대
- `diagnostic: true` 로 표시한 기대는 검사에서 빠진다.

- 기존 `choice` 설계(N지 + "그대로 둠")는 실측된 적이 한 번도 없다. v2/v3 표에서 인용 N지 + 기본값 칸은 미결정이 36.5% 였다.

**제안:** 게이트(기본 OFF 유지) 안의 판정 기본 설계를 `predicates` 로 바꾸는 것을 권한다. 다만 아래 두 가지 코드 안전장치를 먼저 붙이는 조건이다:
1. **"아니오"는 다시 읽을 수 있을 때만 줄을 뺀다.** 지금 `predicateAction` 은 스필 저장소가 없을 때 프로세스 출력 블록을 접는다(collapse). 이것을 반복 템플릿(코드 규칙으로 이미 접히는 것)일 때로만 좁히고, 그 밖에는 유지하게 하는 것.
2. **모든 블록이 "불필요"이면 전부 유지한다.** 도구는 목표 때문에 불렀으므로 전부 불필요는 판단 실패로 본다. 정답 없이 볼 수 있는 신호다 (오염 연구의 모임 신호와 같은 종류).

**위험:** 틀린 "불필요"(≤ .2) 는 필요한 줄을 포인터 뒤에 숨긴다. 앵커 줄(오류·경로·목표 단어)은 항상 남지만 산문 문장은 앵커가 아니다. 모델이 포인터를 다시 읽지 않으면 답에서 빠진다 (c9 의 적대 판정 테스트가 이 경우를 고정해 두었다).

**사용 중 탐지 방법** (모두 내용 없이, 숫자만):
- 스필된 블록이 같은 run 안에서 `egdesk_read_source` 로 다시 읽힌 비율. 다시 읽었다는 것은 필요했다는 직접 증거다. 이 카운터는 지금 없어서 새로 기록해야 한다.
- 보정 기록에 이미 남는 블록별 p, 막대, 행동 (c9 advisory).
- 요청당 "전부 아니오 / 전부 예" 비율. 오염 연구가 묶음 분리를 권하면 이 게이트에도 같은 신호를 쓴다.

**판단 근거의 한계:** 실측은 문서 1개, 블록 22개다. 바꿀지는 owner 가 정한다. 바꾸게 되면 advisory 상태에서 위의 다시 읽기 비율을 먼저 모으는 것을 권한다.
