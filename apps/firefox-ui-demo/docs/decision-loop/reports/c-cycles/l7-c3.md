# L7 / cycle 3 / lane/c3-advisory-calibration 보고서

질문: canon §5.3 ("임계값 보정: 먼저 advisory 모드(판단만 기록, 실행은 추론 모델)로 로그를 모은 뒤 라벨로 정한다. 현재 값은 임시", DECISION_MODEL_CONTEXT_SETUP.md:147)가 말하는 기록이 제품에 실제로 있는가. 임계값은 바꾸지 않았다. 모드 동작도 바꾸지 않았다(기록만). 전부 합성/목 관찰이며 실제 호출 0회.

## 1. 측정 (패치 전)

방법: `$EV/measure.mjs`가 실제 `CodexChatRuntime.send` + `prepareDecisionContext` + 챗 SQLite를 임시 HOME에서 advisory 모드로 한 턴 실행(목 Decisions: 후보 2개, 하나는 p=0.91, 하나는 planned 항목 p=0.42, 발화에 사적 문구 포함). 임시 디렉터리 아래 모든 파일, emit된 이벤트를 검사.

| 기능 | 계산하는 값 | 기록되는 곳 (패치 전) | 보정에 쓸 수 있나 |
|---|---|---|---|
| 턴 시작 컨텍스트(자료 선택, answer_type, time_intent) | 후보별 확률, 적용 문턱(일반 0.5 / planned·가정 + 현재형 질문 0.8), choice 확률 | 챗 SQLite의 `activity.completed` 이벤트 안 receipt. 전용 보정 로그 파일 없음 | 아니오 (아래) |
| 발화 라벨 / recall / topic route | 축별 확률, 0.85+margin 0.2, recall 0.5 | receipt에 "라벨 몇 축 채택"(내 c2 패치)뿐. 축별 확률·문턱·recall 확률은 비영속 | 아니오 |
| DM 선택지(chat-choice) | 행별 확률 | 반환값이 `{status,index|reason}`뿐. 확률은 호출 안에서 소멸(egdesk-chat-choice.mjs:60-85) | 아니오 |
| Board 배치(presentation) | board_view confidence/margin | `{status:'advisory-only', suggestion}`뿐(egdesk-board-presentation-plan.mjs:163-165) | 아니오 |
| 브라우저 reflex | next_step confidence/margin, page_state, goal_met | 단계 결과 메모리 안(`decision.next`, egdesk-browser-reflex.mjs:240-241). 영속 보정 기록 없음 | 아니오 |

턴 컨텍스트 측정값(패치 전 실측):
- 영속 파일: 챗 SQLite 3개(`.sqlite`, `-shm`, `-wal`, 모두 0600)뿐. 설정 디렉터리에 보정 로그 없음.
- activity detail에 **Board 항목 제목**(`비공개제목A`)이 들어 있음(`items[].title`). 이는 기존 사용자 화면 기능이지만 보정 로그로 쓰면 내용 유출.
- receipt `selected`에 붙은 항목의 확률(0.91)은 있으나 **붙지 않은 후보(0.42, 문턱 0.8)의 확률은 어디에도 없음**. 정밀도/재현율을 못 구함.
- 문턱이 "무엇을 했을지(would)"는 붙은 행에만 암묵적으로 존재. 거부 행에는 없음.
- 라벨(그 뒤 추론 모델/사용자가 실제 한 일) 없음. 기록은 채팅 기록과 같이 삭제되어 보존 정책도 별개로 정해지지 않음.
결론: canon이 묘사한 기록은 **존재하지 않는다**. 유출(내용)은 보정용이 아니라 기존 activity의 제목 노출이지만, 그것을 보정 데이터원으로 쓰면 안 된다.

## 2. 구현 (턴 컨텍스트만, 최소·내용 없는 로컬 기록)

- 새 모듈 `helper/egdesk-decision-calibration-log.mjs` (+187): 설정 디렉터리(`<dataDir>/settings/egdesk-decision-calibration.json`), 0600, 키·사용량 파일과 같은 관례(원자적 쓰기, 비공개 디렉터리 검사, 손상 시 `.corrupt-*`로 치워 둠, 새 버전 파일은 신뢰하지 않음). 한도: 100건, 192 KiB, 30일, 오래된 것부터 삭제. 시간은 UTC 날짜만(시각 없음).
- 내용 없음 보장 방식: `record()`가 화이트리스트로 항목을 다시 만든다. 필드는 숫자(0..1, 소수 3자리)와 닫힌 어휘(`q`,`would`,`kind`,`slice`,`forced`,`axis`, 스키마 값, 폴백 코드, 실행 상태)뿐. id·제목·본문·URL·메시지·오류 문구를 넣을 필드가 없다. 읽을 때도 같은 규칙으로 걸러 낸다.
- `prepareTurnContext`가 별도 반환값 `calibration`을 만든다(receipt/activity/이벤트에는 넣지 않음): answer_type·time_intent(상위 두 확률, 문턱, would), 후보별 relevance(**거부된 후보 포함**: p, 적용 문턱, 강제 이유, kind, slice, would), 발화 축(축별 상위 두 확률, 0.85/0.20, would), recall(p, 0.5, would), topic_route(상위 두 확률, 라우팅 여부). 후보 id는 저장하지 않고 확률 내림차순으로만 나열.
- 라벨: 런 종료 시 `{run: completed|failed|interrupted|cancelled, toolActivities: n}`을 같은 항목에 붙임. `toolActivities`는 추론 모델이 advisory 턴에서 스스로 실행한 도구 활동 수(약한 라벨: "붙여 줬어야 했나"의 대리 지표). 사용자 행동 라벨(채택/무시)은 이 기능에는 없음.
- 폴백/타임아웃은 닫힌 사유 코드만 가진 항목으로 기록.
- 모드: advisory와 on 둘 다 기록(항목에 `mode`, `attached` 표시). off는 `prepareDecisionContext`가 null이라 기록 없음. topic 비공개 배치가 폐기된 턴과 skipped는 기록하지 않음(기존의 조용함 유지).
- `.egdesk` 내보내기: 설정 디렉터리 파일은 번들에 들어가지 않는다. 추가로 사용자 첨부 파일명 필터(egdesk-portable-extras.mjs SECRET_NAMES)에 `egdesk-decision-calibration*`을 추가해 이름이 같은 첨부도 비밀로 거른다.
- 변경: egdesk-decision-calibration-log.mjs +187(신규), context-setup +38/-3(`buildCalibration`, 후보별 threshold), codex-chat-runtime +27(`recordCalibration`/`completeCalibration`, noteDecisionContext·finish에서 1줄씩 호출; 800ms 예산 구간 미접촉), codex-bridge-server +4, speech-grounding +2(`SPEECH_THRESHOLDS` 읽기 전용 노출; 값 변경 없음), portable-extras +1/-1, 시험 +144.
- 미구현(다른 레인 영역·라벨이 그 레인 소유): DM 선택지(L1/L2), Board 배치(L4: 적용/되돌림이 라벨), reflex(L8: handoff/성공이 라벨). 세 곳 모두 값은 이미 계산되지만 반환 경계에서 버려지거나(choice, board) 단계 메모리에만 있다(reflex). 모듈은 이미 `dm_chooser`/`board_arrangement`/`browser_reflex` 기능 이름과 `choice`/`next_step`/`page_state`/`goal_met` 질문 어휘를 받아들인다. 연결 지점 제안: chooser는 `readRecommendation`이 `{status,index}`와 함께 (상위 2 확률, 문턱 0.8/0.2)를 내부 콜백으로 넘기고 사용자의 채택/기타/무시를 라벨로; board는 `readBoardPresentation`에서 같은 값을 내고 적용·되돌림이 라벨; reflex는 `decideReflexStep`의 `next/goalMet`을 단계 항목으로. 선택지 value는 사용자/페이지 텍스트일 수 있으므로 기록하지 않고 순위 index만.

## 4. 철학 점검

"Decision Model의 동의·높은 점수는 사실 증명이나 쓰기 권한이 아니다": 로그는 점수를 사실이나 권한으로 쓰지 않고 오직 나중에 문턱을 정할 자료로만 남긴다. 어떤 코드 경로도 이 로그를 읽어 동작을 바꾸지 않는다(읽는 곳 없음, 기록 전용). 또 "보기가 모자라면 억지로 분류하지 않는다": 거부·보류 판정(0.42, `reject`)도 그대로 남겨 "분류하지 않은 것"의 분포까지 보정에 쓸 수 있게 했다. 날짜·내용은 저장하지 않는다(UTC 날짜만).

## 5. 열린 결정 / 다음

1. 라벨 정의는 소유자 결정: 현재 turn_context 라벨은 `toolActivities` 수뿐이라 약함. 사용자 신호(자료 칩을 직접 붙임/뗌, 같은 질문 재시도)를 라벨로 쓸지.
2. 로그 사용자 가시성/삭제: 설정 화면에 "보정 기록 N건, 지우기"를 둘지(미구현, UI 카피 승인 필요). 현재는 파일 삭제로 초기화.
3. DM 선택지·Board·reflex 연결은 각 레인 머지 후 위 연결 지점으로 후속(레인 충돌 회피로 미구현).
4. 실제 모델 분포로 문턱을 정하려면 실호출 로그가 필요. 합성 값으로는 문턱 결정 불가.
5. 다음 시뮬레이션: advisory→on 전환 중 한 턴, 재시작 후 라벨 소실(`complete`는 프로세스 로컬 id라 재시작 전 턴은 라벨 없이 남음), 동시 두 DM.
