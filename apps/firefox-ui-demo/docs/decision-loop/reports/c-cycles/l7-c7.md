# L7 / cycle 7 / lane/c7-turn-memory 보고서

사용자 정제(권위): (1) 첫 턴은 위키에서 기억을 **재구성**, 세션 중간은 재구성하지 않고 대화가 살아 있다는 전제에서 **다음 판단에 필요한 자료만** 가져온다(이미 맥락에 있는 것은 다시 보내지 않음). (2) 매 턴 **온톨로지에 이 턴 내용을 넣을지**(새 페이지 / 기존 페이지 상태 갱신 / 넣지 않음, 넣으면 시간 slice·출처)를 시스템이 판정한다. 사용자에게 묻지 않으며 쓰기는 호스트의 권한·리비전 검사를 거친다. 모두 목(mock)만 사용, 실호출 0회. 부모(Main) 메시지에 따라 시간·출처 라벨은 **격리 축(axes-isolated)**만 쓴다(실호출: 격리 축 6개 중 3개 설치·오설치 0, 술어 설계는 불필요).

## 1. 구현 요약 (모두 프로토타입·플래그 뒤, 턴 경로 미연결)

- 턴 위치(`deriveTurnPosition`, egdesk-turn-memory.mjs): 실제 런타임 사실에서만 유도. 네이티브 스레드 없음 / 새 스레드 시작 / 완료된 선행 턴 없음 / 맥락 압축됨 → `first`, 그 외 → `mid`(`live_thread` 또는 `resumed_thread_with_history`). 의심스러우면 first(재구성은 토큰 낭비, 사라진 맥락을 있다고 믿는 것은 오답).
- 런타임 접점(codex-chat-runtime +18): `turnPosition(context)`가 conversationId, 저장소의 완료된 assistant 메시지, `loadedThreads`(재시작 후 resume 여부), `compactedThreads`로 유도. `markContextCompacted(cid)`는 호스트가 압축을 알게 됐을 때 호출하는 표식이며 **현재 엔진에서 압축 신호는 연결돼 있지 않다**(이 경계는 보고서 7장). 실제 런타임 통합 시험: 첫 질문 `first/no_native_thread`, 둘째 `mid/live_thread`, 스레드 재적재(재시작 뒤 resume) `mid/resumed_thread_with_history`, 압축 표시 뒤 `first/context_compacted`.
- 영수증은 같은 네이티브 스레드·mid에서만 유효(`usableReceipts`): first 턴, 다른 스레드, 압축 뒤에는 모든 페이지를 "모델이 안 가짐"으로 본다.
- (b) mid-session 다음 판단용 가져오기(`reconstructMemory({mode:'next'})`): 판정자 규칙은 "MID-CONVERSATION, 재구성하지 말고 다음 판단에 아직 필요한 페이지만"이다. 보기 = 런타임이 열거한 읽기 가능 후보 − 이미 전달된(영수증) 페이지. 가진 페이지는 **제목·시간·상태 헤더로만** 판정자에게 보이고(본문 재전송 없음) packet에도 다시 안 들어가며, 링크 포인터("이미 전달됨, 내용 재전송 안 함")만 붙는다. 호스트가 허용한 최근 대화 텍스트가 있으면 `live`로 함께 준다(없으면 안 줌). 보유 페이지의 링크 이웃은 보기가 된다("다음에 오는 것"에 도달하는 경로).
  - 선택 옵션 `budget.linksFirst`(기본 꺼짐): 보유 페이지의 링크 이웃만 먼저 본문 스캔하고 나머지는 이웃에서 아무것도 못 찾았을 때만 한 번 더 스캔(`widened`). 안 본 것은 `unscanned`로 보고. 구조가 일의 순서를 정할 뿐 관련성은 여전히 판정자가 본문으로 정한다.
  - 사전 분류(`triageTurn`, 본문 없는 작은 호출 1회, 술어 2개): "보유 자료 밖의 저장 자료가 필요한가", "기록할 가치가 있는가". **결정된 no일 때만** 가져오기를 건너뛰고, 미결정·실패는 그대로 가져온다.
- (c) 매 턴 온톨로지 쓰기 판정(`judgeTurnWrite`): 한 번의 무상태 호출. 보기는 런타임이 열거한 후보 페이지(보유 + 가져온 것, 최대 8, 권한 필터를 통과한 것만) + `new` + `none` + `unsure`. 시간·출처는 격리 축 문항(문장 인용)에서 설치된 라벨만 쓰고 설치되지 않은 축은 unknown으로 둔다(강제 분류 없음). 상태 변화는 별도 3지선다(`tw_status`: done/plan/unknown). 결과는 **제안(proposal)**일 뿐 텍스트가 없고 적용되지 않는다.
  - 매핑: form=plan → planned/plan, conditional → hypothetical, assertion + past_* → past/done, at_utterance·ongoing → present, future_* → planned; question → 기록 안 함; attributed_report → provenance reported_by_other, 그 외 utterance(+basis=source 라벨); time이 unknown이면 새 페이지 제안 안 함.
  - 대상 미결정·none·unsure·질문·상태 불명 → `op:none`과 닫힌 사유.
- 호스트 쓰기 경로(`createWikiWriter`, **기본 꺼짐**): 순서대로 플래그 → 제안 재검증(닫힌 어휘, 판정자 모양을 믿지 않음) → 호스트 쓰기 권한 `canWrite` → 판정자가 본 리비전(`baseRevision`) 일치 → `operationId` 멱등(같은 입력 같은 영수증, 다른 입력은 충돌).
  - 상태 변화는 페이지에 **보류 중 판독(statusReadings, state:pending)**으로만 기록되고 저장된 `status`는 그대로다. 호스트 정책 `acceptStatus`가 true일 때만 status로 승격(accepted 표시)한다. 변경 시 리비전 증가 → 영수증 해시가 달라 그 페이지는 다음에 다시 전달된다. 헤더에 `status-reported-pending=done`으로 표시.
  - 새 페이지 본문은 **사용자 원문 그대로**(호스트가 공급, 최대 2000자; 판정자는 텍스트를 쓰지 않음). `time.slice`, provenance(kind+by+basis), `spokenAt`(말한 시각)은 저장하되 사건 시각 `time.at`은 만들지 않는다. 링크는 `same_task`만, 대상이 존재하고 이 범위에서 읽을 수 있을 때만.
- 파일: 신규 `helper/egdesk-turn-memory.mjs`(+217), `…turn-memory.test.mjs`(+247, 17개), reconstruction +179/-65(scan 함수화, `mode:'next'`, `linksFirst`, 호스트 변경 API `add/addLink/patch`, `allowsPage` 단일 권한 규칙), fixture(+49, 합성 위키 32페이지로 증가: `db/pg-followup` 추가, 판정자 stand-in 확장), codex-chat-runtime +18.

## 6. 철학 점검
"Decision Model의 동의·높은 점수는 사실 증명이나 쓰기 권한이 아니다": 쓰기 판정은 제안일 뿐이고, 저장은 호스트의 플래그(기본 꺼짐)·권한·리비전 검사 뒤에만 이루어지며, 상태 변화는 저장된 상태와 분리된 보류 판독으로 남고 호스트 정책이 승격할 때만 status가 된다. "보기가 모자라면 억지로 분류하지 않는다": 미설치 라벨은 unknown, 대상 미결정은 기록하지 않음, 질문·작은 말은 기록하지 않는다. 판정자는 코드가 내놓지 않은 페이지나 텍스트를 만들 수 없다(새 페이지 본문은 사용자 원문 그대로).

3. 쓰기 판정과 발언 라벨을 턴 경로가 아니라 응답 뒤(`judgeWrite`는 thunk)에 돌릴지. packet은 쓰기 판정에 의존하지 않는다.
4. `acceptStatus` 정책(어떤 상태 판독을 status로 승격할지)과 `canWrite` 범위(페이지·방별)는 소유자가 정한다.
5. W1/T1–T3 실호출 승인. 어댑터(온톨로지 edges와 후보를 페이지·링크로 변환)와 비동기 실행 위치는 이전 보고서의 열린 항목 그대로.
