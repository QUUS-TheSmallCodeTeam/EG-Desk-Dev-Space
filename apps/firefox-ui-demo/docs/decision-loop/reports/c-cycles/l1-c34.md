# L1 c34: Claude 로그인을 EG-Desk 안에서 (터미널 카드의 CLI가 연 주소를 EG-Desk 브라우저 카드로)

브랜치 `lane/c34-login-in-desk` (base `int/c14` `f3f3ccd`). 플래그 `EGDESK_TERMINAL_OPEN_URL=on` (브리지 환경, 기본 꺼짐). Claude CLI와 실제 로그인은 실행하지 않았다 (가짜 CLI, 실제 HTTP 핸들러, 합성 DOM). 새 사용자 문구 없음 (제안은 "승인 필요"로 표시). 라이브 QA 체크리스트: `$L/reports/l1-c34-login-qa-checklist.md`.

## 0. 준수 (Anthropic Claude Code 약관, Main이 11-25에 읽은 내용 기준) — 가장 먼저

Main이 전달한 규칙: 제3자 앱은 Claude.ai 로그인을 제공하거나, 사용자 대신 구독 자격으로 요청을 중계하거나, Claude.ai 자격 증명/세션 토큰을 수집·저장·중개할 수 없다. 로그인은 Anthropic 자체 흐름으로 끝나야 한다. 허용: 사용자가 **수정되지 않은** Claude Code 바이너리에 자기 구독으로 로그인하는 것. 약관 원문은 내가 읽지 않았고 Main의 요약을 따른다. 아래는 이 구현이 그 규칙에 어떻게 맞는지의 설명이며 **법적 판단이 아니다**.

1. **사람이 모든 단계를 직접 한다.** 이 기능이 하는 일은 "CLI가 시스템에 열어 달라고 한 http(s) 주소를 시스템 기본 브라우저 대신 EG-Desk 브라우저 카드에 연다"뿐이다. 카드 안의 로그인 페이지에는 EG-Desk의 어떤 코드도 클릭, 입력, 계정 선택, 읽기를 하지 않는다. 코드는 사람이 화면에서 복사해 터미널에 직접 붙여 넣는다. 바이너리는 수정하지 않는다 (`claude auth login --claudeai`를 그대로 실행).
2. **EG-Desk는 코드나 토큰을 읽지, 저장하지, 전달하지 않는다** (`claude-engine-auth.mjs`의 규칙 유지: HOME, 키체인, `~/.claude`, 토큰을 건드리지 않음). 새로 추가된 터미널 환경 변수는 `BROWSER`, `PATH` 앞 디렉터리, `EGDESK_OPEN_URL_ENDPOINT/SESSION/TOKEN` 뿐이다 (HOME 불변, 테스트 `egdesk-terminal-open-url.test.mjs`). 브리지가 받는 것은 **CLI가 연 로그인 주소 하나**이고 (메모리에만, 최대 4개, 60초, 로그에 남기지 않음), 그 주소의 OAuth 매개변수(client id, redirect, PKCE challenge, state)는 공개 값이다. 코드 페이지는 카드에 **표시될 뿐**, 브리지는 그 페이지를 가져오거나 읽지 않는다.
3. **QA 드라이버**는 로그인 페이지를 건드리지 않는다: 클릭 3개(설정 열기, 계정 탭, 로그인 버튼: 모두 EG-Desk 컨트롤), 카드 주소/페이지 글/입력값 읽기 없음 (카드가 "생겼는지"만 EG-Desk 자신의 카드 목록에서 본다), 스크린샷은 EG-Desk 자신의 요소 둘 (설정의 Claude 행, 터미널 카드 제목줄)만이고 **창 전체를 찍지 않으며** 브라우저 카드가 겹치면 건너뛴다. 로그인 버튼을 누른 뒤 "waiting for the person"에서 멈춘다. 사람이 끝났다고 한 뒤 `--resume-after-signin`은 Firefox에 연결조차 하지 않고 브리지의 `POST /engines/claude/refresh` 결과(단어만, 계정 라벨 없음)만 읽는다. 코드 페이지 감지 같은 기능은 두지 않았다. 테스트 `scripts/egdesk-claude-login-live-qa.test.mjs`가 위를 코드 수준으로 고정한다 (페이지 읽기 패턴 금지, 클릭 3개, 전체 창 스크린샷 도구 금지, Firefox 실행/종료 금지, resume은 연결 없음).
4. **로그인 카드는 EG-Desk의 모든 모델에게 불투명하다 (같은 플래그 뒤).** `helper/egdesk-auth-opaque.mjs`: 호스트 `claude.ai`, `claude.com`, `anthropic.com`, `auth.openai.com`, `auth0.openai.com`, `platform.openai.com`, `chatgpt.com` (하위 도메인 포함; **목록은 제안이며 소유자가 고칠 수 있다**).
   - 브라우저 도구 런타임 `requestUi` 입구 (`egdesk-browser-tool-runtime.mjs`): 그 주소를 보는 카드에 대한 관찰, 스크린샷, 클릭, 입력, 이동, 그리고 그런 주소로 가는/여는 요청은 `BROWSER_CARD_OPAQUE`로 거절된다. 도구 호출, 직접 진입(entry), 브라우저 과제의 페이지 읽기가 모두 이 입구를 지난다고 코드로 읽었다 (실제 실행으로 검증 못 함).
   - 대화 요청의 `selectedSources`에서 그런 카드는 `startTurn` 맨 앞에서 제거된다: 에이전트에게 권한 부여, 호스트, 제목(진입 질문의 `page_text`)이 만들어지지 않는다.
   - 테스트: 각 도메인에서 observe와 screenshot 거절 (카드로 요청이 나가지 않음), 플래그 꺼짐 = 오늘과 같음, 다른 사이트 불변, 선택 카드 제거. 변이 모두 잡힘 (아래).
   - **덮지 못한 것 (확인 안 됨)**: 카드 썸네일/미니맵: 코드에서 그런 기능을 찾지 못했다 (`grep thumbnail` 없음). 메모리/온톨로지로의 페이지 캡처: 브라우저 카드 내용을 메모리에 넣는 경로를 찾지 못했다. 사람이 직접 화면을 캡처하는 일은 막지 않는다. 오늘의 에이전트 경로 중 `requestUi`를 거치지 않는 읽기가 있으면 구멍이다 (찾지 못했다).
5. **D-S1 버튼/문구**: 새로 바꾼 것 없음. 현재 문구 (모두 평문, 로고/그림 없음): 버튼 `로그인` (`eg-desk-surface.uc.js` `settings-claude-login`), 툴팁 `이 계정의 터미널에서 Claude 로그인을 시작합니다`, 시작 후 `터미널에서 Anthropic 공식 로그인을 마친 뒤 다시 확인을 눌러 주세요. EG-Desk는 로그인 정보를 보관하지 않습니다.` (`EGDeskAccountSettingsView.sys.mjs`). EG-Desk 자체 로그인처럼 보이는 문구는 없다. **제안 (승인 필요, 적용 안 함)**: 플래그가 켜져 있을 때만 시작 후 문구를 `Anthropic의 로그인 화면이 EG-Desk 브라우저 카드에 열립니다. 직접 로그인을 마치고, 화면에 보이는 코드를 터미널에 붙여 넣은 뒤 다시 확인을 눌러 주세요. EG-Desk는 로그인 정보를 읽거나 보관하지 않습니다.`
6. **남는 판단 거리 (소유자/법무)**: EG-Desk가 CLI의 "주소 열기"를 자기 브라우저 카드로 돌리는 것이 "중개"로 읽힐 여지가 있는지. 이 구현은 주소만 옮기고 자격 증명은 전혀 보지 않지만, 해석은 내가 단정할 수 없다. 그래서 기본 꺼짐이고 QA는 사람이 직접 한다.

## 1. 어떻게 동작하나 (플래그 켬)

| 단계 | 코드 |
|---|---|
| 브리지 시작 | `codex-bridge-server.mjs`: 플래그가 켜지면 `<데이터 폴더>/terminal-opener/`에 opener 스크립트와 `bin/open`, `bin/xdg-open` shim을 쓴다 (소유자만, 0700) |
| 터미널 세션 시작 | `terminal-platform.mjs` `create`: 세션 id를 먼저 정하고 그 세션 전용 환경 (`BROWSER`, 앞에 shim 디렉터리를 붙인 `PATH`, endpoint, 세션 id, 세션 토큰)을 더한다. Windows는 건드리지 않음 |
| CLI가 주소를 연다 | `$BROWSER <url>` 또는 `open <url>`이 opener를 부른다. opener는 첫 http(s) 인자만 `POST /terminal/open-url`로 보낸다. http(s)가 아닌 인자 (`open .`), 전송 실패, 이상한 문자는 **시스템 opener 그대로** 실행한다 (잃는 것 없음) |
| 브리지 | `terminal-http.mjs` 새 경로 (플래그 꺼짐이면 경로 자체가 없음, 404): 세션 토큰을 상수 시간 비교, `normalizeOpenUrl` (http(s), 자격 증명 없음, 공백/제어문자 없음, 2048자), 세션당 4개, 60초 만료. `terminal-sessions.mjs` `read()`가 `openUrls`를 한 번만 돌려준다 |
| 터미널 카드 | `egdesk-terminal-init.js`가 `terminal-open-url` 메시지로 호스트에 알리고, `EGDeskSurfaceTerminal.mjs`가 (인증된 프레임에서만) `spawnBrowserCard(url, { openMode: 'new', opener: 터미널카드, background: true })`. **background**라 카메라 이동과 활성 카드 변경이 없고 배치는 기존 규칙 (`resolveCanvasCardPlacement`). 같은 주소 5초 내 중복 무시, 메시지당 4개 |
| 성공 뒤 | 화면의 기존 `다시 확인`이 `/engines/claude/refresh`로 로그인됨을 보여 준다 (이 변경이 건드리지 않음) |

## 3. 한계와 확인 안 됨

1. **실제 Claude CLI가 `BROWSER` 또는 PATH의 `open`을 쓰는지는 확인하지 못했다** (CLI를 실행하지 않음). macOS에서 Node의 `open` 패키지는 보통 `open`을 PATH로 부르지만 절대 경로 `/usr/bin/open`을 쓰면 shim을 우회한다. 사용자 셸 rc가 `PATH`나 `BROWSER`를 다시 설정하면 값이 덮인다. 그 경우 시스템 브라우저가 열린다 (체크리스트 2단계에 기록). 이것이 이 기능이 실제로 성립하는지에 대한 가장 큰 불확실성이다.
2. 주소는 셸의 curl로 올라온다 (`/usr/bin/curl`, macOS 기본). curl이 없거나 실패하면 시스템 opener로 떨어진다.
3. `$BROWSER`/`open`으로 열린 모든 http(s) 주소는 (로그인뿐 아니라 터미널 안의 `open https://...`도) 이 세션에서 브라우저 카드가 된다. 플래그 범위의 의도된 효과다.
4. 윈도우 세션은 지원하지 않는다 (sh 스크립트).
5. 불투명 도메인 목록, 라이브 QA의 실제 동작 (Marionette 선택자: 설정 버튼은 rail/dock/hud 버튼의 aria-label/title에서 `설정`을 찾는다; 맞지 않으면 드라이버가 본 라벨을 출력하고 멈춘다)은 실제 창에서 실행해 보지 않았다.
6. 드라이버의 요소 스크린샷은 `drawWindow`에 의존한다. 안 되면 건너뛰고 이유를 출력한다 (창 전체 스크린샷으로 대체하지 않는다).

## 4. 명령

- 브리지 환경: `EGDESK_TERMINAL_OPEN_URL=on` (그 프로필의 `run-firefox-mcp-target.sh --automation` 실행 환경에 넣는다).
- QA: `node scripts/egdesk-claude-login-live-qa.mjs --out <dir>` → 사람이 로그인 → `node scripts/egdesk-claude-login-live-qa.mjs --resume-after-signin`. 사전 확인: `--dry-run`.
