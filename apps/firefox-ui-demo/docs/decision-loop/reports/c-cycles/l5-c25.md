### (3) 명령 중단: `pause`에서 중단 뒤에도 명령이 계속 실행된 것 (Main의 결정 반영)
- `cancelRun(run)`을 실행기 제공자에 추가함: 런타임이 중단, 실행 종료, 대화 삭제에서 이미 모든 제공자의 `cancelRun`을 부르므로 한 곳으로 충분함. 실행 중인 명령마다 `AbortController`를 두고, 러너가 시간 제한과 같은 경로로 **프로세스 그룹에 SIGTERM, 유예(2 s) 뒤 SIGKILL**을 보냄. 러너의 abort는 이제 `aborted: true`(시간 초과 `timedOut`과 구분)로 보고되고, 이미 abort된 신호는 아무것도 시작하지 않음.
- 도구 결과는 `status: 'stopped'`(`stopped: true`, `executed`, `exitCode: null`, `signal`, 중단 전까지의 stdout/stderr, 소요 시간): **끝났다고 보고하지 않음**. 중단된 명령의 출력은 성공 여부로 판정하지 않음(`health unknown`, 이유 `stopped`). 사실 행에 `stopped: true`, 하트비트 사실 `stopped`, 메시지 근거 한 줄은 "…was stopped before it finished (the person stopped the run); it did not complete"로 바뀜. 게이트에서 승인을 기다리던 중 중단되면 아무것도 시작하지 않음(`executed: false`).
- 테스트 6+1개(`helper/egdesk-command-stop.test.mjs`, 가짜 spawn만): **파괴적으로 보이는 명령(`rm -rf build dist node_modules/.cache`, 승인된 상태) 실행 중 중단** → SIGTERM, SIGTERM을 무시하는 프로세스에는 SIGKILL, 중단 전 출력 보고; SIGTERM에 따르는 명령은 SIGKILL 없음; 다른 run의 명령은 그대로; 두 번 중단해도 무해; 러너 단위 테스트; 런타임 끝까지 `chat.interrupt` → 프로세스 그룹 신호, 엔진에 `turn/interrupt`, 결과 `stopped`, 근거 한 줄.
