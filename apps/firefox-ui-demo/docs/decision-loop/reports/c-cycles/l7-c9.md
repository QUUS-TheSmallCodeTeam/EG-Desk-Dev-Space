## 2. 어댑터 (`helper/egdesk-wiki-adapter.mjs`)
원칙: 새 원본 사본을 만들지 않는다. 본문은 **이번 턴 메모리에만** 읽고(기존 저장소의 `ref`와 `contentKey`로 안정 참조), 각 페이지는 자기 저장소의 권한(`mayRead`/scope)을 그대로 쓴다. 영속 저장은 쓰기 경로가 받아들인 것뿐이다. 모델 호출 없음.

|---|---|---|---|---|
| 온톨로지 그래프(`readGraph`) | 노드, 스냅샷 (`candidatesFromOntologyGraph`가 이제 **edges를 `links`로 보존**) | edge relation → 타입(`linkTypeForRelation`: supersede/replace→supersedes, decid/approv→decided_in, continu/follow/deriv/next→follows_from, same/part_of/member→same_task, 그 외는 가장 약한 refers_to), 스냅샷 `continuesFrom`→follows_from, 노드→자기 스냅샷 same_task. 없는 대상은 링크 아님 | 후보와 같음(전역) | 내용 해시 12자 |

- 쓰기 저장소(`egdesk-private-json-store.mjs` 신규 + `openWikiWrites`): 설정 디렉터리, 0600, 비공개 디렉터리, 원자적 쓰기, 최대 200페이지·200판독·256 KiB(초과 시 오래된 것부터), 새 버전 파일은 건드리지 않음, 손상은 `.corrupt-*`로 치움, **저장 불가(디렉터리 사용 불가 등)면 쓰기를 거부**(위키 변경 없음). 내보내기에 포함되지 않음(기존 보정 로그와 같은 위치·규약).
- 본문 사본 방지: 사용자 발화에서 만든 새 페이지는 `messageRef: 'chat-message:<id>'`를 받아 **참조만** 저장한다(제목도 원문 접두를 복사하지 않고 자리표시자). 다음 턴에 발화 레코드로 참조가 풀리면 본문·제목이 채팅 저장소에서 읽혀 오고, 동의 철회나 최근 창을 벗어나면 그 페이지는 **사라진다**(권한 철회와 일치). 작업 결과(agent_note)는 새 내용이라 본문(≤2000자)을 저장한다. 시험이 파일에 원문이 없음을 확인.
- 상태 판독: 저장소 기반 페이지(리비전이 해시)에 대한 pending/accepted 판독은 **그 소스 리비전**에 대해 저장되고 다음 턴에 겹쳐 보인다(리비전 `<rev>.rN`). 소스가 바뀌면 그 판독은 버려진다(오래된 판독을 새 내용에 붙이지 않음). accepted면 status를 덮어쓴다.
- 버그 수정: 해시처럼 숫자가 아닌 리비전의 `nextRevision`이 `+1`을 붙여 위키 리비전 문자 집합을 벗어났고, `wiki.patch`가 조용히 거부된 채 성공으로 보고되었다(실제 저장소 기반 페이지에서는 판독이 안 저장됨). 이제 `.r1, .r2…`로 증가하고 patch 실패는 `invalid`로 보고. 시험 추가.
- 쓰기 경로 변경은 L8의 `agent_note` 수정과 합쳐져 있다(`persist`, `messageRef`는 선택 옵션, 시그니처 불변).

## 3. 배선 (`codex-bridge-server.mjs`, 설정 기본 꺼짐)
- 브리지 설정 `turnMemory`: `"off"`(기본) | `"advisory"`, 다른 값은 파일 전체를 손상으로 처리(기존 규약). `on`은 없다. 명시적으로 `bridge-settings.json`에 쓰거나 `bridgeSettings.turnMemory.save('advisory')`를 호출해야 켜진다. 브리지 코드는 스스로 켜지 않는다(시험이 소스를 확인).
- `createTurnMemoryConfig`(`egdesk-turn-memory-wiring.mjs`): `mode()`는 설정을 읽고, 어댑터와 쓰기 저장소는 **지연 생성**한다(꺼진 동안 파일도 열지 않는다). `wiki()`는 온톨로지 그래프 + Board/선택 후보 + (런타임이 동의 하에 넘긴) 발화·대화 쌍을 어댑터로 매핑. 쓰기 판정(`ontologyWrite`)은 아직 꺼짐(호스트 쓰기 정책 전까지 제안을 적용할 곳이 없음).
- 런타임은 advisory 때 `tm.wiki({body, context, sources:{speech, topic}})`로 이미 만든 발화·토픽 접근자를 넘긴다. 이 접근자들은 기존 동의 조건(결정 모드 on, 발언·토픽 허용)을 그대로 따르므로, 해당 동의가 없으면 온톨로지와 Board만으로 위키가 만들어진다. 새 접근자: `speech.records()`(최대 12, 부분 체인 거부), `topic.turns()`.
- 증명(`egdesk-turn-memory-bridge.test.mjs`): ① 소스: 브리지가 `createTurnMemoryConfig({ settings: bridgeSettings, …})`와 `turnMemory: turnMemoryConfig`로만 배선, 어댑터·저장소는 지연 getter 안에서만 생성, 스스로 advisory로 켜지 않음. ② 설정: 기본 off, 'on' 저장은 거부, 'on'이 든 파일은 손상 처리, 저장한 advisory는 재시작 뒤에도 유지. ③ 실제 채팅 런타임: **기본 브리지는 추가 Decisions 요청 0건, 어댑터 생성 0회, 설정 디렉터리에 위키 파일 없음, `turn/start` 입력이 기능이 없는 브리지와 바이트 동일**. 설정을 advisory로 켜면 백그라운드에서 루프가 돌고(요청 2건 이상, 어댑터 1회 생성, 보정 항목 `turn_memory` 1건, 후보 수 = 온톨로지 그래프 페이지), 입력은 여전히 동일하며 `egdesk_decision_context`가 없고 위키 쓰기 파일도 만들어지지 않는다.

## 6. 철학 점검
"Decision Model의 동의·높은 점수는 사실 증명이나 쓰기 권한이 아니다": 어댑터는 읽기 전용 매핑과, 쓰기 경로가 받아들인 것만 저장하는 좁은 저장소로 나뉘며, 판독은 소스 리비전에 묶여 pending으로만 남는다. 저장 불가이면 쓰기 자체를 거부한다. "보기가 모자라면 억지로 분류하지 않는다": 라벨이 설치되지 않은 발화는 unknown으로 두고, 모르는 relation은 가장 약한 refers_to로만 잇는다. 동의 철회는 참조 페이지를 사라지게 한다.
