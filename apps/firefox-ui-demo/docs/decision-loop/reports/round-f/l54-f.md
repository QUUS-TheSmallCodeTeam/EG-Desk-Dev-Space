# L54-f 카드 조작 잠금 (single-writer UI lease)

커밋: 136ceb35 (branch lane/f-card-lease, base a6e70dd0). 플래그: pref `egdesk.cardLease` = "on" (기본 꺼짐, 다른 egdesk.* pref와 같은 readSurfacePref 방식).

## 설계
- 순수 로직 `overlay/resources/EGDeskCardLease.sys.mjs`: lease = {state: agent|person|handoff, owner, generation, startedAt, lastBeatAt, tasks, reason}.
- 이벤트: start(task) → agent (generation+1, 같은 카드의 다른 task는 합류) / stop(task) → 마지막 task면 person / handoff → handoff(사람 권한, 차단 없음) / pause → person / reset(전송로 끊김·run 사망·revoke) → person / beat(에이전트 도구 요청마다) / expire → person.
- 사람이 일시중지(hold)한 동안은 새 lease를 받지 않음.
- 안전 만료: 마지막 heartbeat 후 120초. 이유: decision loop 한 step은 수 초, 느린 모델 step도 1분 미만이라 2배 이상 여유이고, 죽은 run 때문에 카드가 먹통인 시간은 2분 이내로 제한. heartbeat는 카드로 오는 모든 observe/act 요청.
- 차단 대상은 isTrusted 이벤트만(실제 사람 입력). 에이전트는 page actor/디스패치 입력이라 통과. 차단 이벤트: mousedown/up, click, dblclick, auxclick, pointer, wheel, contextmenu, drag*, drop, key*, beforeinput/input, composition*, paste/cut, touchstart.
- UI(overlay/JS, per card, 플래그 on일 때만 생성되는 card._cardLease):
  - 페이지 영역에 shield div (CSS `.egd-card-lease-shield`: cursor not-allowed + 5% 틴트, 새 텍스트 없음).
  - lease 동안만 window capture 리스너를 붙이고 해제 시 제거.
  - 포커스가 페이지에 있으면 blur해서 키가 원격 페이지로 안 가게 함.
  - 휠은 preventDefault만 하고 bubbling 유지(캔버스 팬/줌 가능). 키/IME는 stopPropagation.
  - 일시중지 버튼, 카드 프레임(이동·크기·닫기), 다른 카드는 영역 밖이라 그대로.
- 연결 지점: `_browserTaskActivity`의 start/stop/null, `pauseAgentControl`, `startAgentToolActivity`(beat), `browser.task.step` 중 status/code human_step 또는 op handoff(카드 id가 있으면 즉시 handoff), `clearBrowserToolTransport`(전송로 정리 시 모든 카드 reset), cleanupCard(dispose).
- human_step: task loop는 human_step이면 어차피 종료되어 stop이 오고, 그 전에 step 이벤트가 오면 handoff로 먼저 풀림.

## Main 실창 검증 순서
1. egdesk.cardLease를 "on"으로 (JSON 문자열 값, presence pref와 동일 형식). 기존 Browser steps UI(EGDESK_BROWSER_STEPS_UI=on)도 켜져 있어야 활동 프레임이 옴 (지금 "Agent 작업 중" 배지가 뜨는 조건과 동일).
2. Browser 카드에서 에이전트 task 시작: 카드에 틴트와 not-allowed 커서. 카드 클릭, 스크롤, 우클릭, 텍스트 입력(한글 IME 포함), 파일 드롭이 모두 안 먹혀야 함. 에이전트의 클릭/입력은 계속 동작.
3. 같은 시점에 카드 이동·리사이즈·닫기, 다른 카드 조작은 가능한지, 일시중지 버튼이 눌리는지 확인.
4. 일시중지: 즉시 틴트 사라지고 직접 입력 가능 ("대표님이 직접 조작 중").
5. 정상 종료/실패/중단: 끝나면 풀림.
6. 핸드오프: 로그인/비번/인증코드 단계 task에서 "사용자 차례"로 멈추면 즉시 풀리고 직접 입력 가능한지.
7. 브리지 연결 끊기(재연결 포함) 또는 run 강제 종료 시 풀리는지, 아무 일 없이 120초 지나면 풀리는지.

## 위험
- 실제 Firefox에서 부모 프로세스 window capture preventDefault+stopPropagation이 원격 페이지로의 키 전달을 확실히 막는지는 실창 확인 필요(단위 테스트는 가짜 DOM). 보강으로 blur를 함께 함.
- IME 조합 중에 lease가 시작되면 이미 시작된 조합은 blur로 끊김.
- 전송로 정리(clearBrowserToolTransport)는 재연결 때도 호출될 수 있어 그때 잠금이 풀림(막힘보다 안전한 쪽 선택).
- 대화 모델의 도구 호출 경로는 호출마다 start/stop이라 호출 사이에 잠깐 풀림(loop 경로는 task 전체가 잠김).
- 활동 프레임이 이 플래그와 별개로 browserSteps UI 의존.
- 휠은 캔버스로 bubbling하므로 카드 위에서 캔버스가 팬/줌될 수 있음(페이지는 안 바뀜).
- shield가 카드 body 클릭 활성화(bodyCapture)를 대신 가로채므로 잠금 중 카드 클릭으로는 활성화 안 됨.

## 수정 (실창 측정 반영): run 단위 lease
- 문제: 세그먼트(entry, 채팅 모델 턴, 이어받기)마다 start/stop 프레임이 와서 중간 약 5.6초 동안 풀림.
- 변경: lease 키를 [clientThreadId, taskId] 대신 run의 clientThreadId로. activity stop(핸드오프 아님)은 해제하지 않고 beat(만료 연장)만. 해제는 run 종료 이벤트(chat.event의 run.completed: completed/failed/cancelled/interrupted 상태를 모두 이 이벤트로 옴, 그리고 run.unavailable)에서 모든 Browser 카드의 해당 thread lease만. 다른 thread 종료는 무시. 핸드오프, 일시중지, 전송로 reset, 카드 닫기, 120초 만료는 그대로. Agent 배지(activeBrowserTasks)는 미변경. 플래그 off면 변화 없음.
- 순수 로직: leaseSegmentEnd, leaseEnd 추가. 카드 API: segmentEnd, endRun.
- 테스트: egdesk-card-lease 11개 포함 합계 1331 중 pass (fail 0).
- 위험: run.completed가 유실되면 마지막 beat 후 120초까지 잠김(만료가 안전망). run.unavailable은 RUNTIME_LOST 외에도 해제(안전한 쪽).

## 수정 2 (재측정 반영)
1. 가짜 해제: 핸드오프 step 전부가 아니라 stepIsHumanStep(status/reason/code가 human_step)일 때만 즉시 해제. needs_value, low_confidence, needs_user는 run 종료까지 유지.
2. IME 우회: 잠금 중 window focus/focusin capture 리스너(setListening과 함께 설치/제거)가 페이지 영역(xulBrowser 포함)으로 들어오는 포커스를 즉시 blur(+microtask 재확인). 시작 시 blur는 유지. 잠금 아님이면 blur 안 함.
- 포커스 grep: overlay의 BrowserAgentRuntime Parent/Child에 focus()/setFocus/focusManager 호출 없음. surface에도 toolBrowser/xulBrowser에 .focus()를 부르는 에이전트 경로 없음(사용자 Tab/클릭 경로만). 단, 콘텐츠 프로세스의 element.focus()는 BrowserChild가 부모에 포커스 요청을 보낼 수 있어, 그 경우 가드가 blur함. 값 채우기는 합성 이벤트/DOM 값 설정이라 포커스에 의존하지 않을 것으로 보이나, 실창 7필드 재측정에서 입력이 정상인지 확인 필요(blur로 사이트의 blur 이벤트/검증이 추가로 뜰 수 있음).
