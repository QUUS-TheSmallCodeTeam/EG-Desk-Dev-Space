# 공용 Board 입구 리허설

[단일 HTML 열기](./index.html). 첫 화면은 지우가 초대 수락과 배송 요청서 지정 공개를 **이미 마친 장면**이다. 전표를 당겨 놓고 개인 메모와 통화 수첩을 곁에 둔 예다. 세 물건은 [같은 Desk 캔버스](../../apps/firefox-ui-demo/docs/egdesk-approved-desktop-style.html)에 놓인다. 원본 스타일의 나무 무늬를 축소해 내장하고, 종이색·잉크·창의 재료는 [제품 토큰](../../apps/firefox-ui-demo/overlay/CSS/eg-desk-surface.uc.css)을 따른다. 서버·계정 없이 동작하는 디자인 예시로 제품 스크린샷이나 실제 원격 접근 통제는 아니다. 새로고침하면 초기화된다.

- **놓은 자리가 작업 상태다:** 메모·전표·수첩 제목줄을 각각 끌면 다른 물건은 그대로다. 포개진 물건의 보이는 부분을 누르면 자리 이동 없이 맨 위로 올라온다. 수첩을 펼쳐 통화 내용을 적거나 개인 메모를 고쳐 쓸 수 있다. Dock의 되돌리기는 마지막 위치 이동만 되돌린다. 제목줄을 Tab으로 선택하고 화살표로 옮길 수도 있다.
- **작업:** 전표에서 ‘이 일 맡기 → 상태 기록 → 집하 준비됨/집하 대기’. 여기까지는 개인 초안이다. 회신 쪽지는 전표를 보고 있던 자리 곁에서 처음 펼쳐지며, 따로 옮기고 접었다가 그 자리에서 계속 쓸 수 있다. 대상과 내용을 확인하고 ‘민재에게 회신’을 눌러야 가상 회신이 완료된다. Agent가 자동으로 상태를 가져오는 예가 아니다.
- **초대:** 오른쪽 아래 ‘시안 → 초대받기’로 독립 장면을 시작한다. 알림의 ‘초대 내용 보기 → 수락하고 참여’ 뒤에도 보드는 비어 있다. 오른쪽 아래 ‘민재의 카드 공개 재생’은 **송신자가 별도로 공개한 사건을 재생하는 시연 조작**이지 수신자가 자신에게 권한을 부여하는 버튼이 아니다.
- **재방문:** ‘시안 → 받은 보드 다시 열기’은 유효한 수락과 지정 공개가 남은 예를 처음부터 재구성한다. 목록의 ‘출고 협업 · 공용’을 누른다. **방금 한 작업을 보존하며 왕복**하려면 장면을 바꾸지 말고 보드 제목 ‘⋯ → 보드 닫기’ 후 왼쪽 공용 보드를 다시 누른다.
- **나머지 경로:** 오른쪽 아래 ‘시안’ 안에 공동 개설, 내 보드에 초대, 받은 초대 경로, 첫 열기 실패, 로컬 보드 예가 있다. 보낸 뒤 ‘내 Desk로’를 누르고 시안 설정에서만 상대 시점을 바꾼다. 왼쪽 ‘내 작업’으로 메모에 복귀하거나 빈 곳을 끌어 이동한다. 창 폭을 바꿔도 종이 위치·크기·현재 배율을 다시 계산하지 않는다. 화면 밖의 물건은 Dock에서 찾아가거나 명시적으로 ‘현재 작업물에 맞추기’를 누른다. 다른 장면·새로고침으로 넘어가면 이 합성 세션의 메모와 배치는 사라진다.

| 구분 | 어디서 시작해 어디로 가는가 |
| --- | --- |
| **현재 제품에 있는 로컬 동작을 재현** | 처음에는 `[Desk 시작]` 또는 Browser 도구 모음의 `[Desk]`. Desk 안에서는 왼쪽 `[Desk]` 또는 좌상단 현재 이름 ▾ → `Board` 목록 → 저장된 이름. 왼쪽에 보이는 보드 이름을 바로 눌러도 된다. 새 창이 열리지 않는다. 같은 Canvas의 빈 곳에 저장 배치를 펼치거나, 이미 열려 있으면 그 영역만 선택하고 필요할 때만 카메라를 옮긴다. 모형의 `자료 정리`는 가상이름이다. |
| **기존 설계: 내가 가진 Board에 초대** | 보드 제목의 `⋯ → 공유 → 미리보기 → 보내기`. 상대는 앱 알림(또는 설정한 채널) → `[초대 내용 보기]`에서 사람·대상·역할·기간을 확인 → `[수락하고 참여]`. 성공하면 한 동작으로 자신의 Canvas에 허용된 범위가 열리고 제목에 포커스가 간다. 채팅, ERP 로그인 또는 원격 조작에 들어가는 게 아니다. |
| **이번 UI 제안: 둘이 새로 개설** | `[Desk] → [새 Board] → [함께 만들기]`에서 목적·참여자·자료 범위를 제안. 같은 개설에 둘 다 수락해야 한 공용 Board가 생긴다. 개시자의 Canvas는 상대가 수락했다는 이유로 이동하지 않는다. 상대도 개인 보드를 복제하거나 합치지 않는다. |
| **다시 열기** | 기존 상세 설계: `[설정] → [공유 관리] → [받은 초대] → 항목 → [열기]`. 일상용 바로가기로, 현재 유효한 **Board 전체 참여권**이 있는 경우만 기존 왼쪽 목록에 `출고 협업 · 공용`을 두는 것이 이 모형의 제안이다. 같은 보드를 다시 열며 새 사본을 만들지 않는다. **한 자료만** 허용된 경우 받은 초대에서 그 자료만 열고, 원래 보드 전체의 이름·항목은 보이지 않아야 한다(자료 전용 경로는 이 Board 모형에서 별도 재현하지 않는다). |

- 초대만 받았을 때에는 카드가 없고, 배송 요청서가 따로 공개됐을 때에만 지우에게 SH-42가 보인다. Agent를 사용하는 [배송 업무 인계 시연](../board-collaboration-rehearsal/README.md)은 별도 예제이며 상태를 주고받지 않는다.
- ‘시안’에서 `첫 열기 실패 후 복구` 예를 선택해 수락하면 수락은 유지되고 현재 위치에 안내가 남는다. `[수락 상태 확인] → [공유 대상 다시 열기]`로 복구한다. 접근 회수가 적용된 후 옛 행·바로가기에서는 열 수 없다. 개인 영역에 놓은 자료는 그대로다.
- [공간·카메라 기준](../../apps/firefox-ui-demo/docs/VIEWPORT_LAYOUT_INTERACTION_MODEL.md)과 [공유/개인 범위](../../ideas/confirmed/EGDESK_INTERACTION_AND_ORCHESTRATION_CONTRACT.md#tech-board-entry-doors)를 구분한다. 이 예시에서는 제품의 자동 스냅을 재현하지 않고 개별 배치와 겹침에 집중한다. 여기서 전표를 옮겨도 보드 공유 배치 변경을 송신하지 않는다. 서버 동기화나 다른 기기로의 위치 복원이 아니다. [공간 회귀 테스트](./geometry.test.mjs)와 [입장 검증](./entry.test.mjs)은 별도로 실행할 수 있다.
- 실제 제품의 근거: [Board switcher·openBoardSnapshot·왼쪽 rail](../../apps/firefox-ui-demo/overlay/JS/eg-desk-surface.uc.js), [사용자 안내](../../ideas/confirmed/EGDESK_PRODUCT_INTERACTION_TRACE_ATLAS.md#atlas-local-share). 기존 사람 초대 설계는 [초대·권한 상세](../../docs/references/design-synthesis/egdesk-ux-realization-proposals.md#ux-detail-e24-collaboration-invite), 이번 접근 경로는 [매뉴얼](../../ideas/confirmed/EGDESK_PRODUCT_INTERACTION_TRACE_ATLAS.md#atlas-board-entry-doors)과 [기술 계약](../../ideas/confirmed/EGDESK_INTERACTION_AND_ORCHESTRATION_CONTRACT.md#tech-board-entry-doors)에서 구분한다. 로컬 Board Thread의 `[초대]`는 사람을 초대하는 버튼이 아니라 Agent 멤버 추가다.
