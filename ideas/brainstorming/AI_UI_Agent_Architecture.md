# 차세대 프론트엔드 AI 에이전트 아키텍처: AG-UI + Pretext + Yoga

**문서 목적:** 최근 진행된 대화에서 도출된 "완벽한 자가 수정(Self-healing) 및 알잘딱깔센 기획이 가능한 생성형 UI 아키텍처"에 대한 기술적 브레인스토밍 및 아키텍처 구상을 총정리합니다.

---

## 1. 개요 및 배경
현재 LLM을 활용한 B2B/사무용 앱 구축 시, LLM이 마크다운 표나 HTML을 맘대로 생성하여 레이아웃이 박살나고 일관성이 깨지는 문제(Design Breakage)가 발생합니다. 이를 극복하고 LLM을 **'데이터 기획자'**로만 활용하며, 시각적으로 완벽한 앱을 만들기 위한 혁신적인 프론트엔드-백엔드 구조를 설계해야 합니다.

---

## 2. 핵심 기술 스택
이 아키텍처를 구현하기 위한 3가지 핵심 기술 요소입니다.

### A. AG-UI (Agent-User Interaction Protocol)
*   **역할:** LLM(백엔드)과 사용자 인터페이스(프론트엔드) 사이의 실시간 스트리밍 & 상태 동기화 통신망 (ex. CopilotKit).
*   **특징:**
    *   LLM의 응답(텍스트 스트리밍, 툴 호출, 상태 변화)을 규격화된 JSON 이벤트로 프론트엔드에 전달합니다.
    *   **Generative UI:** 프론트엔드에 미리 만들어둔 '레고 블록(사전 정의 컴포넌트)'에 LLM이 결정한 데이터를 맵핑(Mapping)하여 보여줍니다.
*   **해결하는 문제:** 통신 및 파싱 인프라 개발 시간 단축, Subagent/에이전트 메모리 상태의 실시간 동기화(조용한 실패(Silent Failure) 시각화 등).

### B. CopilotKit & Artifact 기반 대화 (Generative UI)
*   **역할:** AG-UI 프로토콜을 구현하여 프론트엔드에 즉시 적용할 수 있게 해주는 UI 프레임워크 생태계.
*   **Pre-built UI:** `<CopilotChat />`, `<CopilotTextarea />` 등 번거로운 채팅창, 스트리밍 렌더링 로직을 기본 제공.
*   **Artifact 기반 모듈화 (알잘딱깔센 기획):** LLM이 마크다운으로 표나 차트를 텍스트로 그리는(환각, 레이아웃 붕괴) 대신, 개발자가 사전에 완벽하게 스타일링해둔 React 컴포넌트(데이터 그리드, 바 차트 등)에 조립용 데이터만 뽑아서 넘기도록 제어. 결과적으로 매 세션 절대 깨지지 않고 사용자가 데이터 팩트에만 집중할 수 있는 유연한 대시보드(Artifact) 생성이 가능.
*   **💡 [Tip] 특수 목적용 '망치로 나사 박기' 전략 (강제 텍스트 정렬):** 위와 같은 멋진 Artifact 기반 컴포넌트를 띄울 수 없고, 오직 '순수 텍스트 챗봇 공간' 안에서 가변폭(Proportional) 폰트를 다뤄야 하는 제한된 대화 상황(Fallback)에서 쓰이는 강력한 해킹 기법입니다. LLM이 생성한 텍스트의 픽셀 폭을 Pretext로 잰 후, 열 너비를 맞출 때까지 스페이스바(공백) 개수를 수학적으로 역산해 강제 주입합니다. 무식해 보이지만 브라우저 DOM 없이 1ms 안에 칼같이 정렬된 ASCII 형태의 표(Table)를 보장합니다.

### C. Pretext (by Chenglou)
*   **역할:** 무거운 브라우저 DOM 렌더링 없이 순수 JavaScript(Canvas)로 텍스트 크기를 1ms 이하로 측정하는 엔진.
*   **특징:** 스트리밍 시 발생하는 화면 덜컥거림(Layout Shift/Jank)을 렌더링 전 예측하여 방지.
*   **해결하는 문제:** 텍스트 높이 문제로 발생하는 레이아웃 붕괴를 DOM 없이 수학적으로 사전 파악.

### D. Headless Layout Engine (ex. Yoga, Stretch)
*   **역할:** 브라우저 엔진 없이 Flexbox, Grid, Margin 등 박스 모델의 좌표(x, y, w, h)를 계산하는 수학적 레이아웃 엔진.
*   **결합 (Pretext + Yoga):** 폰트 픽셀 폭(Pretext)과 상자 구조(Yoga)를 합쳐 **"브라우저 없이 0.01초 만에 화면 전체 레이아웃 좌표 찾기"**가 가능해집니다.

## 3. 궁극의 아키텍처: 시각적 자가 검열 루프 (Visual Feedback Loop)

LLM이 사전 지식이 없더라도, 눈이 없더라도(Text-only 모델), 스스로 레이아웃을 예쁘게 배치하고 고치게 만드는 미들웨어(Middleware) 파이프라인.

### 👁️ 시각적 피드백 시스템의 3단계 진화 (왜 Pretext+Yoga인가?)
실제 프로덕트 레벨에서 자율 UI 생성 사이클(Visual Feedback Loop)을 돌릴 때, LLM에게 자신이 만든 뷰를 인지시키는 접근법은 3가지로 나뉩니다. 이 아키텍처는 속도와 비용이 최적화된 Level 1, 2를 혼합하여 사용합니다.

*   **[Level 1] 수학적 피드백 (가장 빠름/저비용):** Pretext+Yoga 엔진을 써서 "좌측 표는 높이 500px, 우측 차트는 200px이므로 300px의 여백 오차가 있습니다"라는 공학적 치수를 에러 텍스트로 즉각 전달.
*   **[Level 2] ASCII 와이어프레임 (공간 지각력 극대화):** 연산된 박스 좌표를 바탕으로 `+`, `-`, `|` 기호를 이용해 화면 구조도를 텍스트 도화지에 그려(ASCII 아트) 전달. 고도로 훈련된 LLM의 마크다운/ASCII 이해도를 활용해 스스로 균형을 잡게 함.
*   **[Level 3] Vision 모델 피드백 (느림/고비용):** Playwright 같은 헤드리스 브라우저를 띄워 스크린샷 캡처 후 GPT-4o 등 비전 모델에게 비평을 받음. 구현은 쉽지만 서버 리소스가 무겁고 API 비용이 비싸 빈번하게 루프를 도는 상용 파이프라인엔 부적합.

### 🔄 워크플로우 설계
1.  **AI 기획 (LLM):** LLM이 "좌표 차트와 데이터 표를 나란히 배치해라" 라며 AG-UI용 JSON 명령어를 작성.
2.  **검열 엔진 연산 (Middleware):**
    *   Pretext + Yoga 모듈이 이 JSON을 가상으로 렌더링하여 좌표 데이터를 산출.
3.  **피드백 번역 (Math & ASCII):**
    *   산출된 치수를 위에서 설명한 Level 1(에러 텍스트)과 Level 2(ASCII 와이어프레임) 구조로 결합하여 LLM에게 제공.
4.  **피드백 수렴:** LLM이 ASCII 아트와 에러 텍스트를 보고 화면(공간성)을 인지하여 스스로 레이아웃 JSON을 수정.
5.  **프론트엔드 전송:** 최종 검열을 통과한 완벽한 밸런스의 배열만 AG-UI를 타고 React 화면에 노출됨.

## 4. 프롬프트 및 인프라 설계 (Harness Engineering)

LLM을 높은 비용의 파인튜닝(Fine-tuning) 없이도 "우리 회사 사내 맞춤형 UI 기획 전문가"로 만드는 구조적 엔지니어링 방법론입니다.

*   **UI 카탈로그 RAG (지식 주입):** System Prompt에 프론트엔드의 디자인 가이드라인("Barchart는 항목 7개 이하일 때만 사용")을 런타임에 주입하여, LLM이 남은 컨텍스트 윈도우 안에서 완벽한 UI 기획자로 행동하게 만듭니다.
*   **견고한 JSON Schema (설명서):** LLM에게 툴(Tool)을 쥐여줄 때, 변수 타입만 주는 것이 아니라 `description` 란에 시각적 한계와 규칙을 꼼꼼하게 적어 자연스럽게 제약을 학습시킵니다.
*   **멀티 에이전트 분업화 (Separation of Concerns):** 데이터를 검색/분석하는 에이전트(Data Analyst)와 완성된 데이터를 가이드라인에 맞춰 컴포넌트로 뿌려주는 에이전트(UX Router)를 분리하여 환각을 최소화하고 모델 교체에 완벽히 대비합니다.

---

## 5. 아키텍처의 비즈니스적 기대 효과 (Selling Points)

*   **Robust UI (절대 깨지지 않는 화면):** 텍스트 기반 LLM의 환각이나 랜덤한 CSS 작성을 원천 차단. 미리 준비된 컴포넌트만 조립하므로 사내 인트라넷, 대시보드 퀄리티 유지.
*   **Extreme Low Cost (시각 모델 불필요):** Playwright(무거운 브라우저)를 띄워 스크린샷을 찍고 비싼 Vision 모델 API로 피드백을 받는 구조를 거치지 않음. 순수 텍스트(ASCII & JSON) 모델만으로 최고 수준의 Vision 피드백 루프 달성.
*   **Model Agnostic (모델 교체 저항성):** 파인튜닝에 의존하지 않고, JSON Schema 시그니처와 Middleware 텍스트 피드백(Harness Engineering)으로 룰을 통제하기 때문에 내일 당장 새로운 LLM으로 뇌를 교체해도 똑같이 '알잘딱깔센' UX 기획자로 작동.
*   **완벽한 Subagent 디버깅:** AG-UI의 상태 동기화를 이용, 멀티 에이전트의 내부 실패를 시각 노드 색상 등으로 실시간 표출해 모니터링 한계 극복.
