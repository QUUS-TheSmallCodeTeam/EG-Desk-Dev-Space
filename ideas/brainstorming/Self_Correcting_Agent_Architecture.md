# 범용 자가 교정 에이전트 아키텍처 (General Self-Correcting Agent Architecture)

**문서 목적:** 특정 도메인(UI 등)에 국한되지 않고, 사용자와 상호작용하며 실수를 스스로 고치고(Unlearn) 취향을 영구적으로 기억하는 **'에피소딕 메모리(Episodic Memory) 기반 범용 AI 에이전트 시스템'**의 MLOps 설계 사상을 정리합니다.

---

## 1. 개요: 한계점과 극복 패러다임

기존 LLM 에이전트 서비스는 '무한히 긴 System Prompt'나 'RAG(단순 텍스트 긁어오기)'에 의존하여 토큰 부족 및 환각(Hallucination)의 한계를 겪어왔습니다. 본 아키텍처는 컨텍스트 윈도우에 의존하지 않고, **Test-Time Training (실시간 LoRA 파인튜닝)**과 **궤적 압축(Trajectory Distillation)**을 통해 모델의 '뇌신경 가중치' 자체를 미세 조정하는 엔터프라이즈 레벨의 기억 시스템을 제안합니다.

---

## 2. 아키텍처 핵심 작동 원리 (Core Workflow)

이 시스템은 사용자와 대화하는 `Task 엔진`과, 배경에서 몰래 기억을 조작하는 `Memory Compiler 엔진`으로 역할을 완전히 분할(Decoupling)합니다.

### A. 작업망 (Task Engine) - 프론트엔드/추론
*   **역할:** 고도의 추론 능력으로 사용자의 지시를 이행. (GPT-4o, Claude 3.5 등 상용 API 혹은 로컬 거대 모델 병행 가능)
*   **라우터(Router) 에이전트:** 사용자의 질문 의도를 1차 파악하여 가장 적합한 **특화 LoRA 어댑터**를 선별해 본체에 동적으로 부착(Dynamic Serving).

### B. 기억망 (Memory Compiler) - 백엔드/학습
*   **역할:** 대화를 마친 후, 방치된 원시 로그(Raw Logs)를 정제하고, 에이전트가 앞으로 평생 기억해야 할 **'행동 강령 가중치(LoRA)'**를 구워내는 비동기 백엔드 워커.
*   **비대칭 스펙 구성:** 복잡한 본래 임무와 달리, '요약 및 정답지 추출'이라는 단순 텍스트 처리에 특화된 로컬 경량 모델(예: Llama3 8B, Qwen 14B + 특화 LoRA)을 채택하여 서버 비용 최적화.

---

## 3. 완벽한 메모리를 굽는 4단계 파이프라인 (MLOps)

단순히 지난 대화를 통째로 외우는 것이 아니라, 실수를 도려내고 완벽한 궤적(Trajectory)만을 내재화하는 정교한 학습 백엔드 파이프라인입니다.

### Step 1. RLAIF 및 정답지 자동화 (Automated Labeling)
사람의 개입 없이 모델 스스로 과거 대화의 성패를 가늠합니다.
*   **코드/환경 피드백:** 에러가 발생한 Tool Call은 `[Rejected]`, 성공한 Tool Call은 `[Chosen]`으로 시스템이 자동 태깅.
*   **암묵적 사용자 행동:** 에이전트가 렌더링한 결과물을 사용자가 마우스로 직접 수정했다면, 사용자의 최종 수정 상태를 최우선 `[Chosen]` 정답지로 낙점.

### Step 2. 경로 압축 (Trajectory Distillation)
에이전트가 실패와 재시도를 거듭하며 삽질한 지저분한 다중 턴(Multi-turn) 로그를 정제합니다. Memory Compiler(선생님 모델)가 이 로그를 읽고, **삽질 과정은 전부 삭제한 채 "A 요건 발생 시 단 한 번의 완벽한 툴콜로 B를 반환한다"**는 식의 이상적인 숏컷(Shortcut) 대본을 재작성합니다.

### Step 3. DPO를 통한 Unlearning (자가 교정)
에이전트가 잘못된 버릇이 들었을 때(Catastrophic Forgetting 등), DPO(직접 선호도 최적화) 수식을 통해 이를 쳐냅니다.
*   과거의 나쁜 버릇(Rejected)을 뱉어낼 확률 행렬 값은 수식적으로 찍어 누르고(Penalty).
*   새로 습득한 올바른 지름길(Chosen)의 확률 행렬 값은 대폭 상향시킴.

### Step 4. Semantic Experience Replay (망각 방지 알고리즘)
새로운 규칙 하나를 배우다가 기존의 핵심 능력(예: DB 쿼리 실력)을 잃어버리지 않도록 뇌를 보호합니다.
*   **Batch 구성:** `[새로 고쳐야 할 실수본 1개]` + `[RAG로 찾은 과거의 유사한 성공 대화 2개]` + `[완전 랜덤한 과거 타 도메인 성공 대화 1개]` 등 총 4개를 한 쌍으로 묶어 GPU에 밀어 넣습니다.
*   **효과:** 새로운 것(Unlearning)은 거부감 없이 배우면서도, 기존의 전역적/국소적 뇌내망 안정성은 완벽히 유지되는 닻(Anchor) 역할을 합니다.

---

## 4. 인프라 및 서빙 전략 (Serving & Hosting)

하드웨어 제약을 극복하고 극강의 사용자 경험(UX)을 달성하기 위한 배포 전략입니다.

### ⚡ 자원 타협 및 최적화
*   **Serverless LoRA 활용:** 96GB 급의 거대한 자체 서버 구축을 피하고 싶다면, `Together AI`, `Fireworks AI` 등 다중 LoRA 동적 서빙(LoRAX)을 제공하는 오픈소스 상용 API로 우회합니다.
*   **학습 스펙:** 어댑터(LoRA) 역전파는 Unsloth 등 초경량화 프레임워크를 도입해 단일 RTX 4090/A6000(24GB~48GB) 인스턴스에서 비동기로 쾌적하게 소화합니다.

### 🔗 어댑터 병합 관리 (LoRA Merging & Composability)
*   **단기 스파이크:** 개별/도메인별로 쪼개진 어댑터(단기 기억)들은 추론 시점에만 병렬로 동적 라우팅하여 장착.
*   **장기 융합:** 주/월 단위로 배치 스케줄러가 돌아가며 이 분산된 어댑터들을 검증 모의고사(Evaluation)를 거쳐 테스트하고, 통과 시 메인 유저 프로필 어댑터 하나로 수학적으로 합산(Fusing / Merging)하여 관리 포인트를 줄입니다.

### ⏱️ UX 레이턴시 은닉 (Latency Hiding)
학습(Backprop)에 소요되는 시간(대략 3~10초)을 사용자가 체감하지 않게 설계해야 합니다. 대화 중이 아니라 하나의 세션/업무 단위가 완전히 분리되는 트랜지션 시점(예: "환경을 분석 완료했습니다. 요약본을 정리 중...")에 교묘하게 로딩 바를 노출하여 이 체화 프로세스를 백그라운드 태스크로 은닉합니다.
